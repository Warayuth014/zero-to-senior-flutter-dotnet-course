1. InboundOrder เป็น aggregate read model

InboundOrder มี order ID/no, creator และรายละเอียดลูก แม้ API backendแยก headerกับ detailคนละ endpoint adapterจะ composeเป็น treeก่อนส่งให้ UI ทำให้หน้ารายการคำนวณจำนวน item/qtyและค้นข้ามรายละเอียดได้โดยไม่ยิง requestตอนแตะทุกครั้ง

2. Detail ผสม persisted กับ runtime state

InboundOrderDetail มีข้อมูลจาก view เช่น line, product, open quantity, unit และ keyจริง inboundOrderDetailId พร้อม field mutable palletCode, status, receivedQty สำหรับ flowปัจจุบัน การผสมนี้สะดวกแต่ต้องจำว่า DONE ใน objectไม่ใช่สถานะถาวรจน server commitและ reloadยืนยัน

3. Key สำหรับแสดงกับ key สำหรับ command

lineNo = L{n} ใช้แสดง, productCode ใช้ยืนยันการ scan และ inboundOrderDetailId คือ keyที่ส่งให้ ReceiveItem/mobile endpoint ห้ามใช้ line numberหรือ product codeแทน detail ID เพราะหนึ่ง orderอาจมี productซ้ำหลายบรรทัด

4. Quantity semantic

adapterคำนวณ remaining = open_qty - receive_qty แล้ว modelเก็บเป็น int qty ผ่าน round() UIจึงรองรับ quantityจำนวนเต็มและ partial receiptภายในช่วง 0..qty หาก domainมี kg/metreทศนิยม model/stepperปัจจุบันจะสูญ precision ต้องเปลี่ยนพร้อม contractและ testsทั้งเส้น

5. Barcode convention

barcode ถูกตั้งเท่ากับ product code เพราะ flowยืนยัน Part ID ไม่ใช่ consumer barcode นี่เป็น business conventionที่ต้องเขียนชัด มิฉะนั้นผู้พัฒนาอาจคิดว่าต้อง parse UPC/EAN field และแก้ UIผิดจุด การเทียบใน storeไม่สนตัวพิมพ์ใหญ่เล็ก แต่ exact hitในหน้าค้น orderยังเทียบแบบ case-sensitive

6. ReceivedToday เป็น event projection

InboundReceiveTransaction มาจาก Events/EventDetails/Product มี transaction ID, document, product, qty, pallet, time และ operator แยกจาก open detailsเพื่อไม่เอา transient DONE rowมาปลอมเป็น audit history หาก DateTime parseไม่ได้ adapterใช้เวลาปัจจุบัน ซึ่งช่วยไม่ crashแต่เสี่ยงแสดงรายการผิดเวลา ควรเก็บ null/parse failureชัดกว่า

7. Mutability trade-off

การแก้ l.status และ l.receivedQty in-placeลด object mapping แต่ snapshotย้อนหลัง/test equalityยาก และ callerอาจแก้นอก store Senior refactorอาจแยก immutable server DTO/read modelออกจาก ReceivingRunState แล้วใช้ copyWith/reducerให้ commitแต่ละ transitionชัดเจน

8. Model tests

ทดสอบ orderที่มี detail IDต่างกันแต่ productเดียวกัน, remaining 0ถูกตัดออก, partial quantity, product code case, creator/brandว่าง และ event timestampเสีย จากนั้นตัดสินใจเชิง contractว่า fractional quantityกับ invalid timestampควรถูก reject, preserve หรือ fallbackอย่างไร
