1. Endpoint map

POST /api/inbound/get_inbound_order_active
POST /api/inbound/get_inbound_order_details?order_id=...
POST /api/data/get_event_storein_report?receivedToday=true
POST /api/WMS/mobile_receive              // commit
POST /api/WMS/mobile_receive validateOnly // preflight

สาม endpointแรกใช้ absolute: true เพราะอยู่นอก client prefix ส่วนสอง mobile callsส่ง relative /mobile_receive ให้ clientเติม /api/WMS

2. BootstrapBlazor grid contract

shared gridรับ body PageIndex/PageItems และอาจคืน items หรือ Items helper _rows รองรับ casingทั้งคู่ Adapterร้องขอ 1,000 rowsเพื่อทำ local composition แต่ parameter q/page/pageSize ของ fetchOpen ยังไม่ได้ใช้จริงและ totalที่คืนคือจำนวน orderหลัง filter ไม่ใช่ server total

3. N+1 requests

adapterโหลด headersหนึ่งครั้ง แล้ววนแต่ละ orderเพื่อ awaitรายละเอียดทีละ request หากมี 100 ordersจะเป็น 101 requestsแบบ sequential ทำให้ latencyโตตาม N ทางแก้คือ backend endpointที่คืน header+open lines, batch detail query หรือ concurrencyที่มี limit แต่ต้องระวัง rate/database loadและรักษาลำดับผล

4. Compose และกรอง open lines

แต่ละ detailคำนวณ open_qty - receive_qty และตัดค่าที่ไม่มากกว่า 0 จากนั้นตัด orderที่ไม่มีรายละเอียดเหลือ จึงทำให้ UIเห็นเฉพาะงานรับเข้าที่ยังทำได้ Data projectionนี้ควรมี contract testเพราะ backend grid filterเปลี่ยนเพียงเล็กน้อยอาจทำ badgeผิดทั้งหน้า

5. Validate ก่อน commit

validatePallet เรียก endpointเดียวกับ receiveแต่เติม validateOnly: true เพื่อให้ serverตรวจ detail, pallet และ qtyโดยไม่สร้าง stock/event ส่วน receive ส่ง payloadเดียวกันโดยไม่มี flag การ reuse business validationลดโอกาส preflightผ่านแต่ commitใช้กฎคนละชุด

6. Received-today mapping

report projectionใช้ชื่อ fieldแบบ DB/view เช่น event_event_id, doc_no_display, To_LPN/to_LPN และ typoเดิม band Adapterเป็น anti-corruption layerที่แปลง casing/ชื่อเหล่านี้เป็น Dart model ห้ามปล่อย raw mapถึง widget

7. Parsing risks

  • rowถูก castเป็น mapโดยตรง; shapeผิดจะ throw
  • 1,000-row capอาจตัดงานโดยไม่มี pagination
  • query string order IDควรสร้างด้วย Uri เพื่อ encode
  • round() เปลี่ยน fractional quantity
  • DateTimeเสีย fallbackเป็น nowทำ auditคลาดเคลื่อน
  • ไม่มี cancellation เมื่อออกหน้า; storeต้องกัน stale result

8. Adapter contract test

ใช้ mock HTTP สร้างสอง ordersหลาย lines ยืนยันจำนวน/ลำดับ requests, absolute/prefixed URI, field casing, open-line filter, empty-order removal, receivedToday mapping และ validateOnlyไม่มี commit side effect เพิ่ม test 1,001 rows/decimal/malformed rowเพื่อบังคับตัดสินใจเรื่อง paginationกับ parse policy
