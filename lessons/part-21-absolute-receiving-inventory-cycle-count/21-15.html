1. Test pyramid ของ Part นี้

  • Model: status aliases/labelsและ phase parsing
  • Store: receiving/cycle commands, transitions, race guards
  • Adapter contract: URI/payload/grid parsing/status mapping
  • Widget: scanner layout, filters, Continue, phase panels
  • Integration: fake backend→store→viewsทั้ง flow

2. สิ่งที่ cycle testsพิสูจน์แล้ว

cycle_count_flow_test ยืนยัน scan Part IDสามรูปแบบเพิ่มทีละชิ้นและ undoลดหนึ่ง รวมถึง manual countแยกจาก system qty Testsเร็วเพราะสร้าง storeด้วย fake repositoriesและ dispose timer แต่ยังไม่ทดสอบ lookup/start/confirm, phases, errorsหรือ UI

3. สิ่งที่ inventory testsพิสูจน์แล้ว

inventory_status_test ล็อก PICK/18, PICKCOMPLATE/19 และ translated labels ขณะที่ scanner layout testยืนยัน search panelไม่เลื่อนเมื่อ stock listเลื่อน ยังขาด adapter precedenceทุก status, query/filter behavior, loading/error/retryและ large-list performance

4. Receiving navigation tests

flow_navigation_test แยก X pauseจาก Back/bottom navigation clear และ pda_ui_test ยืนยัน Startเปลี่ยนเป็น Continue ส่วน scanner testยืนยัน list scannerคงที่และ run scan pageไม่มี page-level scroll สิ่งเหล่านี้เป็น UX invariantsที่ refactor route/storeห้ามทำหาย

5. ช่องว่างสำคัญของ Receiving

ยังควรมี testsสำหรับ exact/ambiguous search, item mismatch, qty clamp/zero/partial, pallet preflight, double submit, server errors, generationเมื่อออกหน้าระหว่าง await, commitสำเร็จแต่ responseหาย และ adapter N+1/grid parsing ปัจจุบัน FakeReceivingRepositoryสำเร็จเสมอจึงเข้าถึง branchesเหล่านี้ไม่ได้

6. Stateful fakes

เพิ่ม fakeที่มี completers, call logs, configurable errorsและ transition state: receiveควรลด remaining/เพิ่ม receivedToday, cycle startควร available→waiting→ready และ confirmควร ready→returningพร้อม history แบบนี้ integration testจะตรวจ reconciliationได้ดีกว่า fakeที่คืน objectเดิมทุก method

7. Contract + fault injection

Mock HTTPตอบ camel/Pascal, malformed rows, timeoutและ 200ผิด shape แล้วตรวจ adapter/store/UI แยกกัน สำหรับ mutationจำลอง timeoutหลัง server commitเพื่อทดสอบ idempotency/reload และใช้ controlled futuresสลับ completion orderเพื่อจับ stale responseแทนหวังให้ raceเกิดเอง

8. Part 21 capstone

ทำ integration harnessหนึ่งชุด: โหลด RO → scan item → partial qty → validate/receive pallet → reload history → inventoryเห็น pallet AWAIT_PUTAWAY → cycle lookup/start/ready → นับสองโหมด → confirm/history โดยบันทึก requestsและแทรก failure/raceอย่างน้อยสามจุด ทุก assertionต้องระบุว่า server, storeหรือ widgetเป็น ownerของ truth
