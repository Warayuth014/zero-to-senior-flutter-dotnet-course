1. Runtime ที่ทำให้ resume ได้

storeเก็บ recvOrderRo, detailId, rStep, rQty, rPallet และ flagsใน objectที่อยู่ตลอด shell เมื่อออกจาก runกลับ order listแบบ preserve ข้อมูลเหล่านี้ยังอยู่จึงเสนอ Continue ได้ โดยไม่ persistลง diskหรือ backend

2. เงื่อนไข canResumeLine

detailId == requested line
&& line.status != DONE
&& rStep อยู่ก่อนขั้นสุดท้าย

มีเพียง lineเดียวที่ resumeได้ต่อ session การเปิด lineอื่นจะ reset runtimeเดิมและตั้ง quantityจาก remaining doc qtyใหม่

3. X, Back และ bottom navigation

  • X / exitFlow: nav('recvorder', preserveFlow: true) เก็บ stepไว้
  • Back ใน recvrun: ถ้า stepมากกว่า 0ลดทีละขั้น; ที่ stepแรกกลับ order listตาม navigation policy
  • Back จาก recvorder: ไป RO listและ clear runtime
  • bottom nav: ทิ้ง uncommitted receiving stateเสมอ

4. Resume ไม่ใช่ durable recovery

เพราะ stateอยู่ memory การ kill app, logout หรือสร้าง shellใหม่ทำให้ resumeหาย Serverรู้เฉพาะสิ่งที่ commitแล้ว หากต้องการ recoverข้าม restartต้องมี server-side draft/session IDหรือ local encrypted draftพร้อม reconciliation ห้าม serialize mutable modelอย่างง่ายแล้วคิดว่าปลอดภัยจาก stockเปลี่ยนภายนอก

5. Reset ทำอะไรบ้าง

_resetReceivingRuntime เพิ่ม generation, ล้าง receivedQtyของ lineที่ยังไม่ DONE, optionallyล้าง order, reset detail/step/qty/pallet/validation flag การเพิ่ม generationสำคัญกว่าล้าง fieldเพราะ invalidates async resultที่เริ่มก่อน reset

6. Reload กับ local pause

loadReceiving() clear/addAll ordersจาก server จึงสร้าง model instancesใหม่ หาก reloadเกิดตอน paused detail IDอาจยังอยู่แต่ local status/receivedQtyใน objectเก่าหาย canResumeLine lookupด้วย IDจึงพอรักษา stepได้หาก lineยัง open แต่ข้อมูล remainingอาจเปลี่ยน ต้องตัดสินใจว่าจะ refreshแล้ว revalidateหรือ freeze snapshot

7. UX invariant

ปุ่ม Continueควรมีเฉพาะการพักด้วย intentชัดเจน ไม่ควรปรากฏหลังผู้ใช้เปลี่ยนเมนูหรือกด Backออกจาก order มิฉะนั้น dataเก่าจะตามกลับมา Testsใน flow_navigation_test.dart และ pda_ui_test.dart ล็อกความแตกต่างนี้ไว้

8. Resume tests

ทดสอบ pauseทุก step, resume lineเดิม, เปิด lineอื่น, Backทีละขั้น, bottom navทุกปลายทาง, server reloadที่ lineยังอยู่/หาย/remainingเปลี่ยน และ logout/recreate store ยืนยันว่าไม่มี uncommitted pallet/qtyหลงไป commitกับ lineใหม่
