ไฟล์หลัก: lib/features/warehouse/models/inventory_models.dart — raw view modelsรักษาความหมาย backend ส่วน Pallet เป็น read modelสำหรับหลายหน้าจอ

1. ContainerView คือ boundary model

fieldsสะท้อน Container_Reg, Locations, LocationDetailsและ Product projection: registration, location, product text, unit, available qty, inProcessและ state ชื่อ fieldใน Dartอ่านง่ายขึ้นแต่ commentบอกแหล่งจริงไว้เพื่อ traceกลับ DB/APIได้

2. Derived getters รวม legacy rules

isPicking, isPickCompleted และ isBusy normalize case/aliasที่ model boundary ทำให้ adapterไม่เขียน magic stringsซ้ำหลายจุด Testsยืนยันทั้ง enum-like nameกับ numeric API valueซึ่งเป็นหลักฐานว่า backend contractมีหลาย representationจริง

3. Pallet เป็น UI read modelร่วม

Pallet มี pallet/product/qty/location/statusที่หน้า Inventoryและ outbound pallet pickerใช้ร่วมกัน นี่ทำให้ทั้งสองหน้าเห็น snapshotเดียวจาก WarehouseStore.pallets แต่ก็หมายความว่า statusหรือ filterเปลี่ยนต้องตรวจผลกระทบทั้ง Inventoryและ Withdraw

4. Status value แยกจาก label

modelเก็บ canonical strings เช่น STORED/PICKING/EMPTY ส่วน palletStatusLabel แปลตอน render จึงส่ง/กรองด้วย stable valueโดยไม่ขึ้นกับภาษา Unknown statusคืน raw stringเพื่อไม่ซ่อนข้อมูล แม้ productionอาจเพิ่ม telemetryและ humanized fallback

5. Mapping labels

Canonicalความหมาย UI
STOREDอยู่ใน rackและพร้อมตาม policy
MOVING / ALLOCATEDกำลังเคลื่อนหรือถูกงานจอง
AT_DEST / PICKINGถึงปลายทางหรืออยู่ในงานหยิบ
AWAIT_PUTAWAY / WAIT_RETURNรอจัดเก็บกลับ
EMPTYcontainerไม่มี stock

6. LocationView แยกอีก use case

LocationView.isFree ต้อง enable, process idleและไม่มี container จึงเหมาะกับรายการตำแหน่งว่างสำหรับ putaway ไม่ควร reuse Pallet.locationCode คำนวณ vacancy เพราะ pallet projectionไม่มี location capacity/enableครบ

7. Immutability และ precision

modelsเป็น final fields จึงปลอดภัยกว่ารับเข้า mutable detail แต่ Pallet.qty เป็น intขณะที่ ContainerView.qty เป็น double การแปลงนี้คือ deliberate loss of precisionต้อง documented/tested ถ้ารองรับหน่วยทศนิยมควรเปลี่ยน UI formatterและ quantity commandsพร้อมกัน

8. Model exercise

เพิ่ม canonical enumหรือ sealed statusแทน string โดยมี parserรองรับ aliasesเดิมและ unknown case จากนั้นรัน testsยืนยัน localization, filters, withdraw eligibility และ backend valuesเดิมทั้งหมดโดยไม่เปลี่ยน wire contract
