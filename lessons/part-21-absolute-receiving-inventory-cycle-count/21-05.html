1. Screen hierarchy

ReceiveView / _ReceiveList       screen = receive
  → RecvOrderView               screen = recvorder
      → RecvRunView             screen = recvrun
          detail → scan item → qty → scan pallet → match → done

route stackไม่ได้สร้างใหม่ทุกขั้น; shell render bodyตาม store.screen จึงต้องเก็บ current order/detail/stepใน store

2. Search และ scanner บนรายการ RO

scan panelอยู่คงที่และเลื่อนเฉพาะ result list ค้นจาก order no, creator, product code/description/brand/barcode Exact ROเปิด order, exact itemหรือ filtered resultเหลือหนึ่งรายการเปิด lineโดยตรง วิธีนี้รองรับ scanner Enterกับ manual browseในช่องเดียว

3. Group ก่อน render

_wait() ตัด DONE linesและคืน record (order, details) ส่วน _filtered() ถ้า headerตรงจะแสดงรายละเอียดทั้งหมดของ order แต่ถ้าตรงเฉพาะ itemจะแสดง subset ควรเข้าใจว่าตัวเลข totalบน cardหลังค้นอาจสะท้อนเฉพาะ matched lines ไม่ใช่ orderทั้งหมด

4. Open กับ received history แยกกัน

รายการ openอยู่ด้านบนและ receivedToday เป็น collapsible sectionจาก persisted event report ไม่ใช้ local DONE rows ทำให้ auditยังอยู่หลัง reload แต่หลัง confirmสำเร็จ historyยังไม่ถูก appendทันทีจน loadReceiving() รอบถัดไป จึงมีช่วงที่ server commitแล้วแต่ sectionยัง stale

5. Order detail view

RecvOrderView แสดง RO summaryและ cardต่อ product line ปุ่มเลือก Start Receivingหรือ Continueจาก store.canResumeLine การตัดสิน resumeอยู่ store ไม่ให้ widgetเดาจาก text/stepเอง หาก linesว่างแสดง completion stateแทน listเปล่า

6. Run view แยก layout ตาม interaction

ขั้น scan item/palletใช้ Columnที่ไม่มี page-level scrollเพื่อให้ scanner targetไม่เลื่อน ส่วน detail/qty/match/doneใช้ ListViewสำหรับเนื้อหายาว FlowStepsอ่าน current stepจาก store และ ScanBoxรับ busy stateตอน server validate pallet

7. PDA feedback และ accessibility

quantity hero, color accent, busy label, toast/flash/hapticช่วย operatorเห็นผลเร็ว แต่ต้องมีข้อความเสมอไม่พึ่งสีหรือแรงสั่น การค้น exact barcodeปัจจุบัน case-sensitiveต่างจาก run scanที่ case-insensitive จึงควร normalize conventionเดียวกัน

8. Widget test matrix

ทดสอบ fixed scan panel, exact RO/item, ambiguous filterไม่เปิดผิด line, no-result/all-done/history, Start→Continue, scan pagesไม่เลื่อน, keyboard/scanner submit, long Thai textและ 390px overflow พร้อมตรวจ semanticsของ busy/error/quantity controls
