1. Documentation drift ที่ต้องจับให้ได้

commentต้นไฟล์บอก “นับหน้า rack ไม่มีเบิก/ส่งกลับ” แต่ model/API/storeมี WAITING_FOR_PALLET, station, task documentและ RETURNING พร้อมข้อความรอ pallet/ส่งกลับคลัง หลักฐาน executableชี้ว่า transport phaseมีจริงหรืออย่างน้อย contractรองรับ จึงต้องยืนยัน product requirementแล้วแก้ commentหรือ flow ไม่ควรเชื่อ commentเพียงอย่างเดียว

2. Stage rendering

pallet == null          → scan stage
pallet != null, !ready → header + product summary + action/history
phase == ready          → mode + count tiles + confirm/history

closeใน headerล้าง sessionและกลับ scan stageโดยไม่เปลี่ยน shell route

3. Scroll policy

ListViewถูกล็อกไม่ให้เลื่อนเมื่อเนื้อหาพอดีเพื่อให้ scannerนิ่ง และเปิด scrollเมื่อมี historyกางอยู่ พร้อม RefreshIndicator เรียก server lookupใหม่ ข้อควรระวังคือ NeverScrollableอาจทำ pull-to-refreshไม่ได้ในบางสภาพเนื้อหา/gesture จึงต้องมี widget/integration testจริง

4. Header, product และ history

headerเน้น pallet/location/round, product cardเปรียบเทียบ system-last-diff และ historyเก็บ document/operator/resultsพร้อมสีต่างตาม diff Layoutใช้ IntrinsicHeight/FittedBoxเพื่อไม่แตกบนจอแคบ แต่ hard-coded Thaiจำนวนมากยังไม่ผ่าน tr ต่างจาก shellส่วนอื่น

5. สองโหมด input

Manualใช้ TextFormField initial valueจาก storeและ parseทุก change ส่วน Scan Eachสร้าง controller/focus nodeต่อ product, Enterหนึ่งครั้งเพิ่มหนึ่งแล้ว clear/refocusให้ยิงรัวได้ มี undoป้องกันผิดหนึ่งชิ้น Controllers/focusทั้งหมด disposeใน widget lifecycle

6. Confirm enablement

countedAll ตรวจเพียง mapมี keyทุก product แต่ทั้งสอง modeเติม keyครบตอนเลือก จึงเปิด confirmทันที Manualหมายถึงยอมรับ default, Scanหมายถึงนับศูนย์ทุก itemโดย implicit หากต้องการพิสูจน์ physical actionต้องเก็บ touched/acknowledged setแยกจาก numeric value

7. Phase-specific gap

ทุก phaseที่ไม่ readyใช้ action cardเดียวและอาจแสดงปุ่ม “เริ่มนับ” อีกแม้ waiting/returning/unknown Backendต้อง reject commandผิด phase แต่ UIควร mapแต่ละ phaseเป็น status/actionชัด WarehouseStoreมี timer refreshทุก 5 วินาทีเมื่ออยู่ waiting/returningพร้อม pull-to-refresh; สิ่งที่ยังขาดคือ pauseเมื่อ backgroundและ stale-response guard

8. UI test matrix

ทดสอบทุก phase, empty products, scan lookup busy/error, manual decimal/invalid, scan correct/wrong/undo/focus, explicit zero, history collapsed/overflow, pull refresh, hard-coded language และ closeระหว่าง async พร้อม requirement testที่ตัดสินให้ชัดว่า palletเดินมาที่ PDAหรือคนนับที่ rack
