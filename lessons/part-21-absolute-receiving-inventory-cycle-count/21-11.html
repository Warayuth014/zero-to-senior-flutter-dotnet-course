ไฟล์หลัก: lib/api/cycle_count_api.dart — สาม commandsใช้ response modelเดียวกัน ทำให้ serverเป็น authorityของ phase, round, productsและ historyหลังทุก transition

1. Repository contract

lookup(palletCode, station)
start(palletCode, user, station)
confirm(palletCode, user, station, counts[])
           ↓
ทุก method คืน CycleCountPallet snapshot ใหม่

storeไม่เดา phaseถัดไปเอง หลัง start/confirmจึงใช้ responseจาก serverอัปเดตทั้ง pallet

2. Endpoint map

POST /api/WMS/mobile_cycle_count/lookup
POST /api/WMS/mobile_cycle_count/start
POST /api/WMS/mobile_cycle_count/confirm

callsใช้ absolute: true แม้อยู่ใต้ prefixเดียวกับ client ซึ่งให้ URIชัดแต่ซ้ำ config knowledgeเล็กน้อย ค่า station defaultคือ PDA; หลัง lookup storeส่ง stationจาก responseกลับใน commandsถัดไป

3. Payload semantics

lookupส่ง pallet/station, startเพิ่ม user และ confirmเพิ่ม countsทุก product แต่ละ count serializeเป็น product_code/count_qty ซึ่งต่าง casingจาก fieldsระดับบน นี่คือ wire contractจริงที่ต้องทดสอบกับ .NET DTO ไม่ควร normalizeชื่อโดยเดา

4. Parser รองรับสอง casing

helperอ่านทั้ง camelCaseและ PascalCase สำหรับ pallet/products/history/results ทำให้รองรับ serializer policyต่างกันโดยไม่กระจาย fallbackทั่ว code แต่ listจะเก็บเฉพาะ rowsที่เป็น map ส่วน numeric helperคาดค่า num; numeric stringอาจกลายเป็น 0หรือ errorตาม branch จึงควรมี contractชัด

5. Nested history mapping

parserสร้าง productsพร้อม system/last count/diff และ historyแต่ละ roundพร้อม document/operator/time/results DateTime.tryParse อนุญาต nullแทน crash ต่างจาก received-today adapterที่ fallback now นโยบายนี้เหมาะกับ auditมากกว่าเพราะไม่สร้างเวลาเท็จ

6. Phase จาก server

CycleCountPhase.parse แปลง AVAILABLE, WAITING_FOR_PALLET, READY_TO_COUNT, RETURNING และ unknown APIจึงไม่ hard-codeว่า startแล้ว readyทันที ซึ่งบอกว่า flowอาจมี transport/automationคั่นกลางและ clientต้อง refresh/reconcileกับ server

7. Error/idempotency boundary

clientส่ง ApiException ขึ้น store start/confirmควร idempotentหรือ reject duplicateด้วย task/document stateแบบ atomic เพราะ timeoutอาจเกิดหลัง server transitionแล้ว ถ้า confirmถูก retry countsเดิมต้องไม่สร้าง historyสองรอบ

8. API contract tests

ยืนยันสาม URI/body, default/response station, snake_case counts, camel/Pascal responses, unknown phase, nullable last values/time, malformed nested rowsและ decimal quantities เพิ่ม timeout-after-start/confirm scenarioเพื่อกำหนด reconciliation endpointกับ idempotency behavior
