ไฟล์หลัก: receiving methods ใน WarehouseStore — guided flowนี้มี preflight networkหนึ่งครั้งและ commit networkหนึ่งครั้ง โดยมี local scan/quantity validationคั่นกลาง

1. State machine

detail
→ scanitem (เทียบ Part ID)
→ qty (0..remaining)
→ scanpallet (server validateOnly)
→ match (server commit receive)
→ done

recvSteps กำหนด key/title ส่วน storeเก็บ indexและ commandแต่ละ transition Viewเลือก panelจาก key ไม่ใช่กระจาย booleanหลายตัว

2. Item scan

รับ input trimแล้วเทียบ expected barcodeแบบไม่สนตัวพิมพ์ หากถูก flash/toastและ advance หากผิดคง stepเดิมพร้อม error การ validateฝั่ง clientช่วย operatorทันที แต่ backend commitยังต้องตรวจว่า detail/product/quantityถูกต้องเพราะ clientแก้ได้

3. Quantity clamp และ partial receipt

recvQty กับ setRecvQty clamp 0..line.qty ค่าเริ่มต้นเป็นเต็มจำนวน recvConfirmQty เก็บ receivedQtyและแจ้งเตือนเมื่อ partial ก่อน advance ปัจจุบัน 0ก็ผ่านไปได้และส่ง commitได้ หาก zero receiptไม่มีความหมายควร blockที่ storeและ backend ไม่ใช่แค่ซ่อนปุ่ม

4. Pallet preflight

ถ้ามี prepared palletต้องตรงก่อน network มิฉะนั้นรับ palletว่างใดก็ได้แล้วให้ serverตรวจ recvPalletValidating กัน scanซ้ำระหว่าง await และ call validatePallet(detailId,pallet,qty) จึงตรวจ eligibilityโดยไม่สร้าง stock/event

5. Generation กัน stale response

ก่อน await storeจับ _receiveSession หากผู้ใช้ออกจาก flow resetจะเพิ่ม generation เมื่อ responseเก่ากลับมา codeจะไม่เขียน pallet/step/toastลง sessionใหม่ นี่ดีกว่า mounted checkเพราะ storeยัง mountedอยู่แต่ logical sessionเปลี่ยนแล้ว

6. Commit และ uncertain outcome

confirmMatch มี recvSubmitting กัน duplicate แล้ว await receive หากสำเร็จและ generationยังตรงจึงตั้ง DONE/qty/palletและ advance แต่ถ้าออกหน้าระหว่างรอ backendอาจ commitแล้ว codeไม่ restore UIเก่าและสั่ง reload นี่คือการยอมรับ “server outcomeอาจสำเร็จแม้ clientเลิกสนใจ response”

7. Retry safety

timeoutหลัง server commitทำให้ clientเห็น failureและผู้ใช้อาจกดยืนยันซ้ำ Endpointควรมี idempotency keyหรือ rejectการรับเกิน remainingอย่าง atomic เพียง busy flagกันเฉพาะ concurrent tapใน processเดียว ไม่แก้ network retry/restart

8. Store test matrix

ใช้ spy/completerทดสอบ correct/wrong item, quantity -1/0/max/เกิน, prepared pallet mismatch, validate success/failure/double scan, leaveระหว่าง validate/commit, double confirm, partial receiptและ timeout-after-commit โดยตรวจ calls, step, flags, toast/flashและ reload behavior
