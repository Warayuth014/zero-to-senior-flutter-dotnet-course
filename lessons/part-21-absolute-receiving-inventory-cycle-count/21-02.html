1. Dependency inversion ที่ใช้งานจริง

WarehouseStore รับ ReceivingRepository, InventoryRepository และ CycleCountRepository ผ่าน constructor จึงเรียกความสามารถเชิง domain เช่น fetch/lookup/start/confirm โดยไม่รู้ route, JSON casing หรือ ApiClient ฝั่ง production ใช้ API adapters ส่วน tests ใช้ fakes

2. Interface เล็กตาม capability

PortCommands/queries
ReceivingfetchOpen, fetchReceivedToday, validatePallet, receive
Inventoryfetch
Cycle Countlookup, start, confirm

storeไม่ต้องพึ่ง giant API service และ fakeของหนึ่ง featureไม่ต้องจำลองทุก endpointในระบบ

3. Fake ไม่ใช่ mock

FakeInventoryRepository คืนสำเนา list, fake receivingเก็บ open/today data และ fake cycle countคืน palletที่กำหนดไว้ มันมี implementationเล็กที่ทำงานได้จริงโดยไม่ตรวจทุก call ส่วน mockเหมาะกับการยืนยัน interactionเฉพาะ เช่น endpointถูกเรียกครั้งเดียว ทั้งสองแบบใช้ต่างวัตถุประสงค์

4. สำเนา collection ป้องกัน test coupling

constructors ใช้ List.of และ fetch() คืน List.of อีกชั้น ทำให้ storeล้าง/เพิ่ม listของตัวเองไม่เปลี่ยน fixtureต้นฉบับโดยไม่ตั้งใจ นี่สำคัญเพราะ production adapterก็สร้าง result listใหม่ทุก request

5. Fake ที่เรียบเกินไปให้ความมั่นใจหลอก

fake receiving ปัจจุบันไม่บันทึก args และ receive/validatePallet สำเร็จเสมอ ส่วน fake cycle countคืน objectเดิมทุก phase จึงทดสอบได้เพียง local counting logic ไม่พิสูจน์ payload, phase transition, duplicate submit หรือ error recovery ควรเพิ่ม call log, configurable completer/errors และ stateful responseตามโจทย์ test

6. Error contract ของ port

production adaptersโยน ApiException และ storeแปลเฉพาะประเภทนี้เป็น server message ถ้า fakeไม่เคย throw testsจะไม่ครอบ error branch วิธีที่ชัดคือให้ portคืน typed result/domain failure หรืออย่างน้อยสร้าง fakeที่เลือก throw timeout/business errorได้โดยไม่ผูก testกับ HTTP internals

7. Contract tests เชื่อม fake กับ real adapter

store testsยืนยัน workflowผ่าน interface ส่วน adapter testsต้องยืนยัน HTTP URI/body/JSON mapping แยกกัน และ reusable repository contract testควรรันกับ fakeกับ adapter test doubleเพื่อให้ semanticsตรงกัน เช่น new profile fetchต้องคืน listใหม่, confirmต้องส่งทุก product และ validationต้องไม่มี stock mutation

8. แบบฝึกเพิ่ม SpyReceivingRepository

สร้าง fakeที่เก็บจำนวน callและ argsของ validate/receive, ตั้ง delay/errorได้ แล้วทดสอบว่า scan palletซ้ำระหว่าง validatingไม่เรียกซ้ำ, confirmซ้ำระหว่าง submittingไม่เรียกซ้ำ และ quantity/detailId/palletCodeที่ส่งตรงกับ stateล่าสุดโดยไม่ใช้ network
