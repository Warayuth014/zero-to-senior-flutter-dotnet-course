ระดับ: Beginnerหัวข้อ: Feedback loopลงมือ: แก้แล้วดูผล
เป้าหมาย: แยก Hot Reload, Hot Restart และ Full Restart ให้ได้ เพื่อไม่เสียเวลารอ build หรือสงสัยว่าทำไมค่าบางอย่างไม่เปลี่ยน

1. Feedback Loop

แก้ code → บันทึก → เห็นผล → ตรวจ → แก้อีกครั้ง

วงรอบสั้นทำให้เรียนเร็ว แต่ต้องเลือกวิธี restartตามชนิดการเปลี่ยน

2. Hot Reload

โหลด codeใหม่เข้าแอปและพยายามรักษา stateเดิม เหมาะกับสี, ข้อความ, layout และ method body ใน Terminalกด r หรือใช้ปุ่ม Hot Reloadใน IDE

3. Hot Restart

เริ่ม Dart appใหม่และทิ้ง stateใน memory แต่ไม่ rebuild native appทั้งหมด เหมาะเมื่อแก้ initializationหรืออยากเริ่ม flowใหม่ ใน Terminalกด R ตัวใหญ่

4. Full Restart

หยุดแล้ว flutter runใหม่ ใช้เมื่อเปลี่ยน native configuration, เพิ่ม pluginบางชนิด, แก้ entrypointหรือ buildไม่สะท้อนการเปลี่ยน

การเปลี่ยนเริ่มจาก
Text/สี/PaddingHot Reload
ค่าที่สร้างตอนเริ่ม appHot Restart
AndroidManifest/native pluginFull Restart

5. ทดลองด้วย Counter

  1. กดเพิ่ม counterให้เป็น 3
  2. เปลี่ยนสีหรือข้อความและ Hot Reload
  3. ดูว่า counterยังเป็น 3
  4. Hot Restartแล้วดูว่า counterกลับค่าเริ่มต้น

การทดลองนี้ทำให้เห็นคำว่า “รักษา state” โดยยังไม่ต้องเรียน stateภายใน

6. Hot Reload ไม่ใช่การแก้ Error

หาก code compileไม่ได้ Hot Reloadจะบอก error ต้องแก้ syntax/typeก่อน บางครั้งการเปลี่ยน constructorหรือ global initializationต้อง Restartแม้ codeถูก

7. แบบฝึกหัด

ลองเปลี่ยน title, สี และค่าเริ่มต้นของ counter แล้วจดว่าแต่ละอย่างต้องใช้ reloadแบบใดจึงเห็นผลแน่นอน

แนวคำตอบ

title/สีมัก Hot Reloadได้ ค่าเริ่มต้นของ Stateอาจต้อง Hot Restartเพราะ Hot Reloadรักษา State objectเดิม

8. สรุปจำเร็ว

เริ่มจาก Hot Reload ถ้าการเปลี่ยนเกี่ยวกับ initializationให้ Hot Restart และถ้าเกี่ยวกับ native/build configurationให้ Full Restart
