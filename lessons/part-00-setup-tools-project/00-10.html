ระดับ: Beginnerเครื่องมือ: Gitเป้าหมาย: บันทึกงานแบบย้อนกลับได้
Git คือประวัติการเปลี่ยนแปลง: commitที่ดีช่วยทดลองและย้อนกลับได้ ส่วน GitHubคือที่เก็บ repositoryบน serverและใช้ทำงานร่วมกัน

1. Workflow พื้นฐาน

git status
git add lib/main.dart
git diff --cached
git commit -m "feat: update first screen"
git push

อ่าน status/diffก่อน commitทุกครั้งเพื่อไม่ส่ง secretหรือไฟล์ buildโดยไม่ตั้งใจ

2. .gitignore

Flutterสร้างค่าเริ่มต้นให้แล้ว โดยทั่วไปไม่ commit build, .dart_tool, IDE cache และไฟล์ secret แต่ต้อง commit source, tests, pubspecและ lockfileของ application

3. Commit เล็กและมีความหมาย

หนึ่ง commitควรตอบว่าเปลี่ยน behaviorอะไร ไม่รวม formatทั้ง projectกับ featureใหม่โดยไม่จำเป็น ชื่อเช่น feat: add warehouse counterอ่านง่ายกว่า update

4. Branch

git switch -c feature/warehouse-counter

Branchแยกงานทดลองจาก branchหลัก แต่ไม่แทนการ commitสม่ำเสมอ

5. สิ่งที่ห้าม Commit

  • รหัสผ่าน, token, signing key
  • ไฟล์ environmentที่มี secret
  • build artifactsขนาดใหญ่
  • ไฟล์ของผู้ใช้หรือฐานข้อมูลจริง
ลบ secretจาก commitล่าสุดไม่พอหาก pushแล้ว ต้อง revoke/rotateและจัดการ historyตามขั้นตอนทีม

6. แบบฝึกหัด

สร้าง branch แก้ title รัน test แล้วตรวจ diffก่อน commit

Checklist

statusมีเฉพาะไฟล์ตั้งใจแก้, ไม่มี secret/build, messageอธิบายผลลัพธ์ และ pushไป branchที่ถูกต้อง

7. สรุป

วงรอบที่ปลอดภัยคือ status → diff → test → stage → ตรวจ staged diff → commit → push
