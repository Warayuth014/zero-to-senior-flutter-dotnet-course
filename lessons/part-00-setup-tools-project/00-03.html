ระดับ: เริ่มจากศูนย์เครื่องมือ: flutter doctorผลลัพธ์: รู้ว่าต้องแก้ชั้นใด
อย่ากลัวเครื่องหมายเตือน: flutter doctor เป็นรายการตรวจสุขภาพ ไม่ใช่ข้อสอบที่ทุกบรรทัดต้องเขียว หากคุณไม่ทำ iOS บน Windows คำเตือน Xcode ไม่เกี่ยวกับเป้าหมาย

1. รันคำสั่ง

flutter doctor -v

ใช้ -v เพื่อเห็น version และ path จริง ข้อมูลนี้ช่วยมากเวลาถามทีมงานหรือค้นปัญหา

2. อ่านผลจากเป้าหมายก่อน

ถามก่อนว่าจะรันบนอะไร แล้วสนใจเฉพาะหมวดที่ target นั้นต้องใช้

Targetหมวดที่ต้องพร้อม
Chrome/WebFlutter + Chrome
Android Emulator/มือถือFlutter + Android toolchain + device
Windows desktopFlutter + Visual Studio C++ workload
iOSต้องใช้ macOS + Xcode

3. สัญลักษณ์หมายถึงอะไร

  • ✓ หมวดนี้พร้อมตามที่ doctor ตรวจได้
  • ! มีคำเตือน อ่านรายละเอียดก่อนตัดสินว่าเกี่ยวหรือไม่
  • ✗ ขาดส่วนสำคัญของหมวดนั้น

Doctor ผ่านไม่ได้รับประกันว่า project ทุกตัว build ผ่าน แต่ช่วยแยกปัญหาระดับเครื่องออกจากปัญหาใน project

4. Android Toolchain

หมวดนี้ตรวจ Android SDK, build-tools, Java และ licenses หากยังไม่มี ให้ติดตั้ง Android Studio และ SDK ผ่าน SDK Manager ก่อน

flutter doctor --android-licenses

อ่านและยอมรับ license หลัง Java/SDK path ถูกต้อง หาก command นี้หา Java ไม่เจอ ให้แก้ toolchain ก่อนกดยอมรับซ้ำ

5. Connected Device

flutter devices

ผลลัพธ์ควรมีอย่างน้อยหนึ่ง target เช่น Chrome, Android emulator หรือมือถือจริง แต่ละรายการมี device ID ที่ใช้กับ flutter run -d <id>

6. แยกปัญหาเป็นสี่ชั้น

1. flutter command ไม่ทำงาน       → SDK / PATH
2. doctor บอก toolchain ไม่พร้อม  → Android / Chrome / Windows tools
3. project build ไม่ผ่าน          → dependency / platform config / code
4. app เปิดแต่ API ต่อไม่ได้       → runtime URL / network / server

การรู้ชั้นช่วยไม่ให้ลบ project หรือ reinstall ทุกอย่างโดยไม่เกี่ยวกับสาเหตุ

7. ตัวอย่างการอ่าน

ถ้า Flutter และ Chrome เขียว แต่ Android มีเครื่องหมาย X คุณยังทำบทแรกบน Chrome ได้ จากนั้นค่อยแก้ Android ก่อนบทที่ต้องใช้มือถือจริง

ถ้า where flutter ชี้ SDK A แต่ IDE ใช้ SDK B ผล doctor ใน Terminal กับ build ใน IDE อาจไม่เหมือนกัน ต้องตั้ง path ให้ตรง

8. สิ่งที่ไม่ควรทำ

อย่าลบ Gradle cache, Android SDK หรือ Flutter SDK ทั้งหมดเพราะเห็น error หนึ่งบรรทัด ให้เก็บข้อความ error แรก, command ที่รัน, target และ version ก่อนเสมอ

9. แบบฝึกหัด

สร้างตารางสามคอลัมน์จากผลเครื่องคุณ: หมวด, สถานะ, เกี่ยวกับ target หรือไม่ แล้วเลือกเพียงหนึ่งรายการที่ต้องแก้ก่อน

ตัวอย่าง

เป้าหมาย Chrome: Flutter ✓ เกี่ยว, Chrome ✓ เกี่ยว, Android ! ไม่บล็อกบทแรก, Visual Studio ✗ ไม่เกี่ยว หากเป้าหมายเปลี่ยนเป็น Android ลำดับความสำคัญก็เปลี่ยน

10. Exit Checklist

ผ่านเมื่อ flutter --version ทำงาน, flutter devices พบ target อย่างน้อยหนึ่งตัว และคุณอธิบายได้ว่า warning ใดเกี่ยวหรือไม่เกี่ยวกับ target นั้น
