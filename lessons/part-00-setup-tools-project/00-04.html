Device คือที่ที่แอปทำงาน: ใช้ Emulator เพื่อทดลองสะดวก และใช้มือถือ/PDA จริงเพื่อยืนยันกล้อง, scanner, permission, network และขนาดหน้าจอ

1. Emulator กับมือถือจริง

ข้อดีข้อจำกัด
Emulatorสร้างหลายขนาด, reset ง่าย, debug สะดวกกิน RAM/CPU และไม่เหมือน hardware จริงทั้งหมด
มือถือจริงเห็น performance/network/input จริงต้องตั้ง USB debugging และ driver

2. สร้าง Android Emulator

  1. เปิด Android Studio
  2. เปิด Device Manager
  3. เลือก Create Virtual Device
  4. เลือกโทรศัพท์ขนาดมาตรฐาน
  5. ดาวน์โหลด system image ที่แนะนำ
  6. กด Start และรอหน้า Home ของ Android

ครั้งแรกอาจช้าเพราะดาวน์โหลด image และเปิด virtual machine

3. ตรวจ Virtualization

ถ้า Emulator เปิดไม่ได้หรือช้ามาก ให้ตรวจ virtualization ใน BIOS/Task Manager และ Windows hypervisor ตามเอกสาร Android Emulator ของเวอร์ชันที่ใช้

อย่าสุ่มเปิดปิด Hyper-V จากคำแนะนำเก่าก่อนอ่านข้อความ error เพราะ emulator รุ่นใหม่และ CPU แต่ละเครื่องใช้ acceleration ต่างกัน

4. เชื่อมมือถือจริง

  1. เปิด Developer options บนมือถือ
  2. เปิด USB debugging
  3. เสียบสายที่ส่งข้อมูลได้
  4. เลือกอนุญาต debugging บนหน้าจอมือถือ
  5. รัน flutter devices

สถานะ unauthorized หมายถึงยังไม่ได้กดยืนยันบนมือถือ ไม่ใช่ Dart code ผิด

5. ตรวจด้วย ADB และ Flutter

adb devices
flutter devices

ADB เห็น device แปลว่าชั้น Android เชื่อมแล้ว Flutter จึงควรเห็นต่อ หาก ADB ไม่พบ ให้ตรวจ cable, USB mode, driver และ authorization ก่อน

6. เลือก Device ตอนรัน

flutter run -d chrome
flutter run -d emulator-5554
flutter run -d <device-id-จากเครื่องคุณ>

อย่าคัดลอก device ID จากตัวอย่าง ให้ใช้ค่าจาก flutter devices ของเครื่องตัวเอง

7. เรื่อง localhost ที่ต้องจำไว้

บน Android Emulator คำว่า localhost หมายถึง emulator เอง ไม่ใช่ Windows host โดยทั่วไป Android Emulator ใช้ 10.0.2.2 เพื่อหา service บนเครื่อง host

Windows browser  → http://localhost:5080
Android emulator → http://10.0.2.2:5080
มือถือจริง        → http://<IP-ของ-PCในวง-LAN>:5080

ตอนนี้ยังไม่ต้องเปิด API เพียงเก็บ mental model นี้ไว้สำหรับ Part เชื่อม .NET

8. ปัญหาที่พบบ่อย

อาการตรวจ
Emulator ไม่ขึ้นsystem image, virtualization, RAM
มือถือ unauthorizedหน้าจออนุญาต USB debugging
device offlineสาย, USB mode และ ADB
API เข้าไม่ได้host address, firewall, server bind

9. Mini Exercise

เปิด target หนึ่งตัว รัน flutter devices แล้วจด name, device ID และ platform version

ผ่านเมื่อใด

ผ่านเมื่อ device ปรากฏโดยไม่มี unauthorized/offline และคุณสร้างคำสั่ง flutter run -d ... จาก ID นั้นได้

10. สรุปจำเร็ว

Emulator เหมาะเรียนและ debug มือถือจริงเหมาะยืนยัน production behavior บทถัดไปเราจะสร้าง project แรกแล้วรันบน device ที่เตรียมไว้
