ไม่ต้องอ่านทุกไฟล์: Flutter สร้างไฟล์จำนวนมากเพราะรองรับหลาย platform มือใหม่ควรเริ่มจาก lib, test และ pubspec.yaml

1. แผนที่ Project

hello_flutter/
├─ lib/            โค้ดแอปที่เราเขียน
├─ test/           โค้ดทดสอบ
├─ android/        การตั้งค่า Android
├─ web/            การตั้งค่า Web
├─ pubspec.yaml    ชื่อ, version, packages, assets
└─ analysis_options.yaml  กฎตรวจ code

2. lib คือพื้นที่หลัก

lib/main.dart เป็น entrypoint เริ่มต้น ต่อไปเราจะแยกไฟล์ใต้ lib ตาม feature แต่ยังไม่ควรสร้าง folder architecture ใหญ่ก่อนมีความจำเป็น

3. Platform Folders

android, ios, web, windows เป็น host project ของแต่ละ platform ส่วนใหญ่ไม่ต้องแก้ในบท UI ปกติ แต่ permission, app name, signing และ native integration จะมาใช้ภายหลัง

4. ไฟล์ที่สร้างใหม่ได้

โค้ด Dartใต้ lib และ testsใต้ test คือ sourceของเรา ส่วน build และ .dart_tool เป็นผลลัพธ์/cacheที่เครื่องมือสร้างใหม่ได้และไม่ควรแก้มือ

ควร commitไม่ควร commit
lib, test, pubspec.yaml, platform configbuild, .dart_tool, IDE cache

5. package name กับ app name

ชื่อใน pubspec.yaml ใช้ importภายใน Dart ส่วนชื่อที่ผู้ใช้เห็นบนมือถืออยู่ใน platform configuration อย่าสมมติว่าแก้จุดเดียวแล้วทุก platformเปลี่ยน

6. วิธีหาไฟล์โดยไม่หลง

  1. เริ่มจากสิ่งที่เห็นบนหน้าจอ
  2. ค้นหาข้อความนั้นใน lib
  3. เปิดไฟล์ที่ค้นพบ
  4. ตาม importเฉพาะที่เกี่ยวข้อง

ยังไม่ต้องเปิด generated fileหรืออ่าน platform folderทั้งชุด

7. Mini Exercise

ระบุว่าแต่ละงานควรเริ่มที่ใด: เปลี่ยนข้อความบนจอ, เพิ่มรูป, เขียน test, ตั้ง Android permission และลบ build cache

เฉลย

ข้อความเริ่มที่ lib; รูปประกาศใน pubspec.yaml; testอยู่ test; permissionอยู่ platform folder; build cacheสร้างใหม่ได้และไม่แก้ source

8. สรุปจำเร็ว

ทำงานประจำวันเริ่มจาก lib และ test ใช้ pubspec.yamlจัด dependencies/assets และเข้า platform folderเมื่อ featureนั้นต้องใช้จริง
