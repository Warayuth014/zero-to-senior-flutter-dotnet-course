เครื่องมือช่วยคิด ไม่ได้คิดแทนเรา: Formatterจัดรูป, Analyzerตรวจ codeโดยไม่รัน และ Debuggerหยุดดูค่าระหว่างรัน ทั้งสามแก้ปัญหาคนละชั้น

1. Editor ที่พร้อม

ติดตั้ง Flutter/Dart extensionและตั้ง SDK pathให้ตรงกับ where flutter เปิดทั้งโฟลเดอร์ project ไม่เปิดเฉพาะไฟล์ main.dart เพราะ editorต้องอ่าน pubspecและ package graph

2. Formatter

dart format lib test

Formatterจัดช่องว่างและบรรทัดให้มาตรฐานเดียวกัน มันไม่แก้ logicและไม่รับประกันว่า code compileผ่าน

3. Analyzer

flutter analyze

Analyzerตรวจ type, import, API misuseและ lint โดยไม่ต้องเปิด device อ่านจาก errorก่อน warningและแก้จากบรรทัดแรกที่เป็นสาเหตุ

4. Breakpoint คืออะไร

Breakpointสั่งให้ debuggerหยุดก่อนรันบรรทัดนั้น ทำให้เราดูค่าตัวแปรและ call stackได้ ใส่ breakpointใน callbackของปุ่มแล้วกดปุ่มบนแอป

onPressed: () {
  // วาง breakpoint ที่บรรทัดถัดไป
  setState(() => count++);
}

5. Step Controls

คำสั่งความหมาย
Continueรันต่อจน breakpointถัดไป
Step Overรันบรรทัดนี้โดยไม่เข้า methodภายใน
Step Intoเข้าไปดู methodที่ถูกเรียก
Step Outออกจาก methodปัจจุบัน

6. Print กับ Debugger

debugPrint เหมาะดูเหตุการณ์เร็ว ๆ แต่ logมากทำให้อ่านยากและอาจรั่วข้อมูล ส่วน debuggerเหมาะตรวจ stateเฉพาะจุดโดยไม่เพิ่ม codeถาวร

7. Workflow เมื่อมี Error

  1. Formatเพื่อให้ codeอ่านง่าย
  2. Analyzeเพื่อหา compile/lint issue
  3. Runให้เกิดอาการซ้ำ
  4. วาง breakpointก่อนจุดผิด
  5. ดู inputและค่าตัวแปร
  6. แก้สาเหตุเล็กที่สุดแล้วรันทดสอบใหม่

8. แบบฝึกหัด

วาง breakpointที่ปุ่ม counter กดหนึ่งครั้งและดูค่าก่อน/หลังเพิ่ม จากนั้นรัน formatterกับ analyzer

ผ่านเมื่อใด

ผ่านเมื่อ debuggerหยุดตามจุด คุณบอกค่า countก่อนและหลังได้ และ analyzerจบโดยไม่มี error

9. สรุปจำเร็ว

Formatทำให้อ่านง่าย, Analyzeจับปัญหาก่อนรัน, Debuggerแสดงค่าระหว่างรัน ใช้ร่วมกันแทนการเดาและแก้สุ่ม
