1. เขียนอาการให้ชัด

แทน “มันพัง” ให้เขียน “รัน flutter run -d chrome แล้ว buildหยุดที่ไฟล์ X บรรทัด Y” ข้อมูล command, targetและข้อความแรกทำให้ค้นสาเหตุได้

2. แผนผังตัดสินใจ

commandไม่เจอ → PATH/SDK
doctorไม่ผ่าน → toolchain
pub getไม่ผ่าน → network/version/dependency
analyzeไม่ผ่าน → Dart source/type
buildไม่ผ่าน → sourceหรือ platform build
เปิดได้แต่ทำงานผิด → runtime logic/state/data

3. คำสั่งเก็บหลักฐาน

flutter --version
flutter doctor -v
flutter devices
flutter pub get
flutter analyze
flutter run -v

-vให้ logยาว ใช้เมื่อผลปกติไม่พอและส่งเฉพาะส่วนที่เกี่ยวโดยไม่รั่ว path/secretเกินจำเป็น

4. Clean ใช้เมื่อใด

flutter cleanลบ build outputของ project ใช้เมื่อ artifactเก่ามีหลักฐานว่าไม่ตรง ไม่ใช่คำตอบแรกของทุก error และหลัง cleanต้อง pub get/buildใหม่จึงช้าขึ้น

5. ตารางอาการทั่วไป

อาการตรวจแรก
Packageหาไม่เจอpubspec + pub get
Deviceไม่เจอflutter devices/ADB
Undefined namespelling/import/type
จอไม่เปลี่ยนsave/reloadและ callback

6. ขอความช่วยเหลือให้คนตอบได้

ส่ง expected/actual, ขั้นตอนทำซ้ำ, command, errorข้อความ, versionและสิ่งที่ลองแล้ว ไม่ส่งเพียง screenshotตัดครึ่งหรือ logที่มี token

7. แบบฝึกหัด

ตั้งใจลบ semicolonหนึ่งจุด รัน analyze อ่านไฟล์/บรรทัด แก้กลับแล้วรันซ้ำ

สิ่งที่ต้องสังเกต

Analyzerมักชี้ใกล้จุดผิด แต่ errorถัดไปอาจเป็นผลต่อเนื่อง จึงแก้สาเหตุแรกก่อนอ่านรายการใหม่

8. สรุป

Seniorไม่ได้จำ errorทั้งหมด แต่แยกชั้น สร้างอาการซ้ำและใช้หลักฐานจำกัดพื้นที่ค้นหาได้
