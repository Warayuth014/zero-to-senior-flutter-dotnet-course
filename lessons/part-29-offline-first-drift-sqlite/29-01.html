Offline-first ไม่ใช่แค่ cache: ผู้ใช้ต้องอ่านและสั่งงานสำคัญต่อได้แม้ network หาย โดยระบบเก็บ intent ไว้แล้วปรับสถานะกับ server อย่างตรวจสอบได้ภายหลัง

1. Online-only problem

โกดังมี Wi-Fi ขาดช่วงและ PDA สลับ access point หากทุกปุ่มรอ HTTP งานจริงจะหยุดทั้งที่ผู้ใช้สแกนและยืนยันถูกต้องแล้ว

2. Local-first read

หน้าจออ่านจาก local database เป็นหลัก ส่วน network เติมข้อมูลใหม่เข้า database ทำให้ UI ไม่ต้องสลับ data source และเปิดซ้ำได้ทันที

3. Durable write

คำสั่งปิดงานต้องบันทึกลง outbox ก่อนบอกผู้ใช้ว่าเก็บแล้ว การเก็บเฉพาะ Future/ตัวแปรจะหายเมื่อ OS ปิด process

4. Consistency

offline-first ยอมรับ temporary inconsistency แต่ต้องกำหนด eventual consistency, retry, conflict และข้อความสถานะให้ชัด ไม่แกล้งแสดงว่า server สำเร็จแล้ว

5. State machine

server task → cached task → pending command
→ syncing → acknowledged | retry | conflict

6. Authority

server ยังเป็น authority ของ business rule ส่วน local DB เป็น source of truth ของหน้าจอและ intent ที่ยังส่งไม่สำเร็จ

7. Lab scope

Part นี้ใช้ OfflineTaskRepository, OfflineDatabase และ .NET idempotency endpoint จาก Part 26 เพื่อทำ vertical slice ที่รันและ test ได้

8. Checkpoint

เขียน contract ให้ได้ว่าอะไรทำ offline ได้, UI เรียกสถานะนั้นว่าอะไร และจุดไหนต้องบังคับ online ก่อนเริ่มเขียนฐานข้อมูล
