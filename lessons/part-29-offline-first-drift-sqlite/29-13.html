Conflict ไม่ใช่ network error: server และ device ต่างมีการเปลี่ยนที่ถูกต้องแต่ใช้พร้อมกันไม่ได้ ต้องใช้ business rule ตัดสิน ไม่ใช่ retry อัตโนมัติ

1. Detect

ส่ง base rowVersion/ETag กับ command แล้ว serverตอบ 409/412 พร้อม current representation เมื่อ version ไม่ตรง

2. Last-write-wins

ง่ายแต่เสี่ยงสูญข้อมูล ใช้ได้เฉพาะ fieldความเสี่ยงต่ำและมี server timestamp ที่เชื่อถือได้ ไม่ใช้เวลาบนอุปกรณ์เป็น authority

3. Server-wins

ทิ้ง local changeแล้ว refresh เหมาะเมื่อ action ถูกยกเลิกโดย workflowใหม่ แต่ต้องแจ้งผู้ใช้ว่า intentไม่สำเร็จ

4. Client-wins

ควรใช้เฉพาะ businessอนุญาต override และ APIตรวจ permission/versionอย่างชัด ไม่ใช่ส่ง forceทุก conflict

5. Merge

field-level mergeเหมาะ entityที่แก้คนละ field ส่วน inventory quantityมักต้องเป็น domain command/ledger ไม่ mergeตัวเลขแบบทั่วไป

6. Task example

ถ้า taskถูก operator A ปิดแล้ว B replay complete IDคนละตัว serverอาจตอบ already-completed พร้อม actor/time ให้ B reconcileแทน errorลอย ๆ

7. Conflict queue

เก็บ local payload, server snapshot, reason และ resolution status เพื่อให้ผู้ใช้หรือ supervisorตัดสินและ audit ได้

8. Exercise

กำหนด conflict policy แยกต่อ command: complete task, move stock, cycle count และแก้หมายเหตุ เพราะความเสี่ยงไม่เท่ากัน
