29-10 · State & Lifecycle

Optimistic UI pending state และ undo strategy

Part 29: SQLite, Drift & Offline-first Sync

Optimistic UI ต้องซื่อสัตย์: แยก “บันทึกในเครื่องแล้ว” จาก “server ยืนยันแล้ว” และให้ผู้ใช้เห็น pending/conflict เมื่อมีผลต่อการทำงาน

1. Immediate feedback

เมื่อ outbox commit สำเร็จ task หายจากคิวงานทันที ทำให้ operator ทำงานถัดไปได้โดยไม่รอ latency

2. Pending indicator

lab แสดงจำนวน command รอ sync บนหน้าจอ Production อาจมี badge/queue detail และ last sync เพื่อให้หัวหน้างานตรวจสอบได้

3. Language

ใช้ข้อความ “บันทึกแล้ว รอซิงก์” ไม่ใช้ “ส่งสำเร็จ” ขณะยัง offline คำเล็ก ๆ ป้องกันความเข้าใจผิดทาง operation

4. Undo

undo ก่อนส่งอาจลบ commandและคืน projectionใน transaction; หลัง serverรับแล้วต้องเป็น compensating command ไม่ลบประวัติย้อนหลังเฉย ๆ

5. Duplicate taps

primary key command และ busy guard ลดคำสั่งซ้ำ แต่ command ID ต้องผูกกับ user intent เดียว หากผู้ใช้ตั้งใจทำ action ใหม่จึงสร้าง ID ใหม่

6. Permanent failure

validation/permission failure ต้องเอางานกลับหรือแสดง conflict action พร้อมเหตุผล ไม่ retry ไปเรื่อยและซ่อน task ตลอดกาล

7. Accessibility

pending/success/error ต้องสื่อด้วยข้อความและ semantics ไม่พึ่งสีหรือ icon อย่างเดียว โดยเฉพาะ PDA กลางแจ้งและผู้ใช้สวมถุงมือ

8. Exercise

ออกแบบ UI สำหรับ queued, syncing, synced, retrying และ rejected พร้อม action ที่ผู้ใช้ทำได้ในแต่ละ state
