เลือก storage ตาม shape และ guarantee: ไม่มี package เดียวเหมาะกับ preferences, token, relational data และไฟล์ขนาดใหญ่ทั้งหมด

1. Key-value

ค่าธีม, onboarding flag และ preference เล็ก ๆ เหมาะกับ key-value แต่ไม่เหมาะกับ query task ตาม status/location หรือ update หลาย record แบบ atomic

2. Secure storage

refresh token และ secret ใช้ OS-backed secure storage ไม่ใส่ plaintext ใน SQLite โดยอัตโนมัติ และไม่ใช้ secure storage เป็นฐานข้อมูลรายการจำนวนมาก

3. SQLite

SQLite ให้ table, index, constraint, transaction และ SQL query จึงเหมาะ cached entities, outbox, search และความสัมพันธ์ที่ schema ชัด

4. Files

รูป/PDFขนาดใหญ่ควรเก็บเป็นไฟล์แล้วบันทึก path/checksum/สถานะ upload ใน DB หลีกเลี่ยง BLOB ใหญ่ที่ทำให้ backup และ query หนัก

5. Drift

Drift ครอบ SQLite ด้วย Dart API, type-safe queries, reactive streams และ migration hooks แต่ยังต้องเข้าใจ SQL/index/transaction เพื่อออกแบบถูก

6. Decision table

preference → key-value
secret → secure storage
task/outbox → SQLite + Drift
photo → file + metadata row

7. Avoid duplication

อย่าเก็บ entity เดียวหลาย store โดยไม่มี ownership เพราะจะไม่รู้ว่าค่าใดล่าสุด กำหนด canonical local row และ derived UI state

8. Exercise

จัดหมวดข้อมูลในโปรเจกต์จริงเป็น preference, secret, relational row หรือ file พร้อม retention และผู้มีสิทธิ์อ่าน
