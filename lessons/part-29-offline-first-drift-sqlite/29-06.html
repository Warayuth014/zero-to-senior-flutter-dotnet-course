Database มี lifecycle: เปิดหนึ่ง instance ต่อ scope, ทำงานหนักนอก UI isolate และปิด connection เมื่อ owner จบ

1. Composition root

offline_main.dart สร้าง database → remote repository → offline repository → store แล้วส่งลง widget tree ทำให้ ownership อ่านตามลำดับได้

2. Single instance

อย่าสร้าง database ใหม่ทุก build เพราะเกิดหลาย connection, stream รั่ว และ order ของ write ยากควบคุม ให้ DI/container เป็น owner

3. Executor

Drift แยก database API จาก QueryExecutor จึงใช้ file DB ใน app และ NativeDatabase.memory() ใน tests ได้โดย logic เดิม

4. Isolate

query/serialization ใหญ่ทำให้ frame กระตุกได้ ใช้ executor/isolate ที่ library แนะนำและวัด DevTools ก่อน optimize

5. Transaction

transaction ทำให้หลาย write สำเร็จทั้งหมดหรือ rollback ทั้งหมด และ query ภายในต้อง await ให้เสร็จก่อน callback จบ

6. Do not await network inside

อย่าถือ SQLite transaction ขณะรอ HTTP เพราะ lock นาน ให้ commit intent ก่อน ส่ง network แล้วเปิด transaction สั้นสำหรับ acknowledge

7. Close

OfflineWmsApp.dispose ปิด store และ database เพื่อคืน stream/connection; production app scope อาจอยู่ตลอด process

8. Checkpoint

trace owner ของ database ตั้งแต่ main ถึง dispose และตรวจว่า repository/widget ไม่แอบเปิด connection ของตัวเอง
