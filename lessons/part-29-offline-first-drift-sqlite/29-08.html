Reactive database: UI subscribe query result แล้ว Drift ส่งค่าใหม่เมื่อ table ที่เกี่ยวข้องเปลี่ยน ลดการสั่ง reload หลายจุด

1. watch vs get

get() คืน snapshot หนึ่งครั้ง ส่วน watch() คืน Stream และ rerun query เมื่อ dependency เปลี่ยน เลือกตาม lifecycle ของ consumer

2. Visible query

watchVisibleTasks filter hiddenByCommand = false ทำให้ enqueue command แล้วรายการหายจากทุก subscriber โดยอัตโนมัติ

3. StreamBuilder

lab ใช้ stream แสดงจำนวน outbox; หน้าจอใหญ่ควรแปลง row เป็น domain state ใน repository/controller ก่อนถึง widget

4. Narrow queries

subscribe เฉพาะ column/rows ที่หน้าต้องใช้ ลดงาน rerun และ rebuild เช่น count query สำหรับ badge แทนอ่าน payload ทั้ง outbox

5. Ordering

ใส่ orderBy ทุก query ที่ UI พึ่งลำดับ SQL ไม่รับประกัน insertion order ถ้าไม่ระบุ

6. Lifecycle

StreamBuilder จัด subscription ตาม widget; controller ที่ listen เองต้อง cancel ใน dispose และระวัง duplicate listeners จาก rebuild

7. State ownership

อย่ามีทั้ง mutable list ใน store และ reactive DB โดยไม่กำหนด authority ระบบเต็มควรให้ DB stream drive list ส่วน store เก็บเฉพาะ UI/action state

8. Exercise
