Sync engine เป็น state machine: connectivity เป็นเพียง trigger ให้ลอง ไม่ใช่หลักฐานว่า internet/API ใช้งานได้

1. Triggers

ลอง sync ตอน app start/resume, หลัง enqueue, manual tap และเมื่อ network signalเปลี่ยน แต่ทุก trigger ต้องรวมเข้ากลไก single-flight เดียว

2. Connectivity caveat

มี Wi-Fi ไม่ได้แปลว่า DNS/TLS/APIพร้อม จึงต้องตัดสินจาก request result และ health/auth contract ไม่ใช่ connectivity package อย่างเดียว

3. Single-flight

ป้องกัน sync สองรอบอ่าน command เดียวพร้อมกันด้วย mutex/state flag หรือ database lease มิฉะนั้นเกิด duplicate request แม้ serverควร idempotent

4. Batch

จำกัดจำนวนต่อรอบและ yield เพื่อไม่กิน battery/network ถ้า API รองรับ bulk ให้กำหนด partial-result contract ต่อ command

5. Dependencies

create ก่อน update/delete ต้องรักษาลำดับหรือใช้ local-to-server ID mapping ระบุ dependency เพื่อไม่ส่ง child ก่อน parent

6. Background limits

Android/iOS จำกัด background execution อย่าสัญญา sync ทันทีเมื่อ app ปิด ออกแบบ resume/manual sync และ server reconciliation รองรับ

7. Authentication

401 ควรหยุด queue รอ refresh/login ไม่ mark ทุก command เป็น business failure และ tenant/user change ต้องแยกหรือ purgeข้อมูลตาม policy

8. Lab

syncPending เป็น loopแบบตั้งใจให้อ่านง่าย งานต่อยอดคือเพิ่ม single-flight, classification, scheduling และ status stream โดยรักษา repository tests
