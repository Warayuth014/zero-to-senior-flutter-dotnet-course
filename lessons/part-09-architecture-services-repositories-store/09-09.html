Single source of truth (SSOT): ข้อมูลหนึ่งชนิดมี ownerหลักหนึ่งจุด ส่วนค่าที่เหลือ deriveหรือ snapshotตาม contract ไม่ copy mutable stateหลายที่แล้วหวังว่าจะ syncเอง

1. Choose owner

Authenticated userอยู่ AuthStore, active serverอยู่ ConnectionController, receiving workflowอยู่ ReceivingStore และ server inventoryเป็น authoritative remote stateที่ repositoryโหลดเข้ามา

2. Derived state

List<Task> get openTasks =>
    state.tasks.where((task) => task.status == TaskStatus.open).toList();
int get openCount => openTasks.length;

ไม่เก็บ openCount แยกถ้าคำนวณได้ เพราะ mutationอาจลืมอัปเดต

3. Mutable list trap

ห้าม expose final List tasks ให้ widget add/remove ได้ คืน UnmodifiableListView หรือ immutable stateและเปลี่ยนผ่าน actions

4. Remote refresh

หลัง command success เลือก patch stateจาก typed responseหรือ re-fetch authoritative dataตาม consistency/performance ไม่ patchหนึ่ง storeแต่ลืม dashboardอีก store

5. Cache is not another truth

cacheเป็นสำเนาที่มี freshness/version policy Repositoryเป็นผู้ reconcile remote/local และเปิด metadataเช่น stale/offlineให้ UIรู้

6. Selection by ID

เก็บ selectedTaskIdแทน copy Task object เมื่อ list refresh getterหา current objectจาก SSOT ลดรายละเอียดเก่าค้าง แต่ handle IDหายอย่างชัดเจน

7. แบบฝึกหัด

HomeStoreกับTaskStoreถือ list tasksคนละชุด หลัง completeควรแก้อย่างไร?

แนวคำตอบ

มี task ownerเดียว/shared query cache หรือทั้งสอง invalidate/reloadผ่าน repository policy; อย่า mutateสอง listด้วย codeซ้ำ

8. Review questions

ใครเป็น owner? ใครเปลี่ยนได้? derivedอะไรได้? refreshแล้ว selectionยังถูกไหม? logout/server switchล้าง scopeใด?
