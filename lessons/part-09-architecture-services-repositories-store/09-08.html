Constructor dependency injection: dependencyมองเห็นจาก signature, สร้างที่ composition rootและแทนด้วย fakeได้ ไม่ต้องใช้ global locatorเพื่อค้นหากลาง method

1. Inject graph

final client = ApiClient(config: config, tokenProvider: auth.token);
final receiving = RemoteReceivingRepository(ReceivingApi(client));
final store = ReceivingStore(repository: receiving, clock: systemClock);
runApp(App(receivingStoreFactory: () => store));

2. Required dependencies

ใช้ required constructorสำหรับสิ่งที่ classทำงานไม่ได้ เช่น repository; optional/defaultเฉพาะ convenienceที่ semanticsชัด เช่น Clock production—not silent singleton fallbackใน core logic

3. Inject values too

Clock, UUID generator, retry policy, current userและ feature flagsเป็น nondeterministic/config dependenciesที่ควร injectเมื่อ logicต้องใช้ เพื่อ testเวลา/idempotencyได้

4. Lifetime

ApiClient/authอาจ app-scoped, WarehouseStore shell-scoped, ReceivingFlowStore route-scoped กำหนด owner/disposeตรง composition boundary

5. Avoid service locator

GetIt.I<ApiService>() ใน methodซ่อน dependencyและทำ test order/global stateเสี่ยง ถ้าใช้ DI containerให้ resolveที่ boundaryแล้วส่ง constructorต่อ

6. Circular dependency

Authต้องใช้ clientแต่ clientต้องใช้ token แก้ด้วย TokenProvider callback/interfaceหรือแยก anonymous transport ไม่ให้ AuthRepositoryกับ ApiClientอ้างกันเป็น owner

7. แบบฝึกหัด

Storeใช้ DateTime.now() ตัด “done today” แล้ว testข้ามเที่ยง flaky จะแก้อย่างไร?

เฉลย

inject Clock/Now functionและกำหนด timezone boundary; testส่งเวลาคงที่

8. Checklist

ดู constructorแล้วรู้ dependencyครบ, lifetime/disposeชัด, fakeง่าย, ไม่มี network/storage/clock globalแอบอยู่ใน business method
