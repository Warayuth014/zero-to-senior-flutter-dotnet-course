Error translation ทีละ boundary: low-level causeยังอยู่สำหรับ diagnostics แต่แต่ละชั้นเห็นภาษาที่ตัดสินใจได้ ไม่ส่ง SocketExceptionหรือข้อความ .NETดิบถึง widget

1. Translation chain

SocketException
  → NetworkFailure(cause)
  → ReceivingError.offline(retryAllowed: true)
  → UI: “ติดต่อ WMS ไม่ได้ ตรวจเครือข่าย”

2. Transport layer

แปลง timeout/socket/status/ProblemDetails/contract errorเป็น typed infrastructure failuresพร้อม status/code/trace ID โดย redact payload

3. Repository layer

แปลง 404เป็น OrderNotFound, 409 codeเป็น AlreadyReceived ฯลฯ เมื่อมี domain meaning; unknown server errorคงเป็น BackendFailureไม่เดาจาก message

4. Store layer

ตัดสิน retry, state transitionและ recoverability เช่น conflictอาจ reload authoritative order; unauthorizedส่ง auth effect; contract errorแสดง support trace

5. UI layer

localizeข้อความ/ปุ่มตาม typed error ไม่ parse string และไม่แสดง stack trace ให้ operator; loggingทำก่อน localizationเพื่อ aggregateด้วย code

6. Preserve cause

ใช้ error objectมี cause/stackTrace/traceId สำหรับ telemetry แต่ equality/testsอิง stable kind/code ไม่อิงข้อความ

7. แบบฝึกหัด

API 409 code PALLET_ALREADY_ASSIGNED ควรแปลที่ไหน?

เฉลย

ApiClient parse ProblemDetails; ReceivingRepository map codeเป็น domain conflict; Storeเลือก refresh/transition; UIแสดงคำแนะนำ

8. Anti-pattern

catchทุกอย่างแล้วคืน empty list/nullทำ errorหายและ UIโกหกว่าไม่มีงาน—unknown failureต้องยังเป็น failure
