Remote implementation เป็น adapter: แปลง domain call → request DTO/HTTP และ response DTO → domain พร้อม error translation

1. Implementation

final class RemoteReceivingRepository implements ReceivingRepository {
  RemoteReceivingRepository(this.remote);
  final ReceivingRemoteDataSource remote;

  @override
  Future<Receipt> receive(ReceiveCommand command) async {
    final dto = await remote.receive(ReceiveRequestDto.fromDomain(command));
    return dto.toDomain();
  }
}

2. DTO mapping

request mapperกำหนด casing/optional fields; response mapperตรวจ contractและ domain invariants ทำให้ domainไม่ import JSON annotationsหรือ legacy key fallback

3. Error translation

Socket/timeout/ApiException/ContractExceptionถูกแปลงเป็น repository failuresที่ stable เช่น NetworkUnavailable, Conflict, Unauthorized และ UnexpectedContract โดยรักษา cause/trace IDสำหรับ diagnostics

4. Mapping vs orchestration

repositoryอาจรวม remote+cache policy แต่ workflowหลาย stepเช่น validate→confirm→receiveควรอยู่ application service/Store ไม่ฝัง user interactionใน remote adapter

5. N+1 awareness

ของจริง TasksApi โหลด task listแล้วขอ detailทีละ row การซ่อนหลัง repositoryทำ callerสะอาดแต่ไม่ได้ทำ performanceหาย ต้องมี metricsและพิจารณา backend aggregate/batch endpoint

6. Cancellation/generation

Dart Futureทั่วไป cancelไม่ได้ง่าย Repositoryควรรับ cancellation abstractionเมื่อจำเป็นหรือ Store ignoreผลด้วย generation token; .NETรับ CancellationTokenต่อถึง DB

7. แบบฝึกหัด

APIคืน 404 ตอนค้น order ควร throw ApiExceptionถึง UIหรือไม่?

แนวคำตอบ

Repositoryแปลงเป็น OrderNotFound หรือ nullตาม interface contract; UIไม่ควรรู้ status 404หาก semanticsคือไม่มี order

8. Repository tests

assert endpoint/request DTO, mapping success, legacy casing, each failure translation, trace preservationและไม่รั่ว transport type
