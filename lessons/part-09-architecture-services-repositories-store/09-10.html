Unidirectional data flow: UI ส่ง intentลงไป, actionเรียก dependency, resultเปลี่ยน state, UIอ่าน stateกลับมาเป็นวงเดียวที่ตามและทดสอบได้

1. Flow

User event → Store action → Repository → Result
     UI ← render(state) ← New immutable state

2. Intent not mutation

ใช้ store.confirmQuantity(value) แทน store.qty = value; store.step++ ใน widget เพื่อให้ Storeตรวจ invariantและ transition atomically

3. State machine

sealed class ReceiveState {}
class AwaitingPallet extends ReceiveState {}
class AwaitingPart extends ReceiveState { /* pallet */ }
class Confirming extends ReceiveState { /* draft */ }
class Submitted extends ReceiveState { /* receipt */ }

ลด boolean combinationsที่เป็นไปไม่ได้

4. Async sequence

Actionประกาศ loadingก่อน await แล้ว success/failureหลัง awaitโดยมี generation/idempotency guard UIไม่ต้องเดาว่า requestกำลังวิ่งจาก local variable

5. One-shot effects

navigation/toast/hapticอาจเป็น typed effectที่ UI consumeครั้งเดียว แยกจาก persistent state เพื่อ rebuildไม่ replay effect

6. Debuggability

log action name + previous state type + next state type + elapsedโดยไม่ log secret/payload ทำ timelineว่า flowพังที่ transitionใด

7. แบบฝึกหัด

Scanner callbackเรียก APIแล้ว Navigator.popเองมีปัญหาอะไร?

เฉลย

callbackผูก transport/navigationและ raceง่าย ให้ส่ง scan intent→Store state/effect→UI navigateเมื่อ transitionสำเร็จและ mounted

8. Test style

Given initial state + fake repository, When action, Then assert ordered states/effectsและ exact command—ไม่ต้อง inspect private widgets
