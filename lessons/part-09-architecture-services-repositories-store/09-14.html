1. Inventory ก่อนตัด

ทำ outline fields, lifecycle, controllers, async methods, sections/dialogs, dependenciesและ shared mutable variables พร้อมระบุ behaviorที่ต้องคง

2. Characterization tests

ล็อก happy path, validation, back behavior, loading/errorและ scan transitionsที่มีอยู่ แม้ designไม่สวย Testsเป็น safety netระหว่าง move code

3. Extract pure widgets first

class PalletSummaryCard extends StatelessWidget {
  const PalletSummaryCard({required this.pallet, required this.onConfirm});
  final PalletViewData pallet;
  final VoidCallback onConfirm;
  // render only
}

4. Extract view data

ส่ง typed props/callbackแคบ ๆ ไม่ส่ง State objectทั้งก้อนให้ childแล้วเรียก private methodsกลับ ทำ widget testsง่ายและ couplingต่ำ

5. Move logic to Store

หลัง UI sectionsแยกแล้ว ย้าย async workflow/derived stateทีละ actionไป Storeพร้อม unit tests Controller/FocusNodeยังอยู่ route widgetหรือ dedicated form controllerตาม lifetime

6. Keep commits small

commitหนึ่ง extract/moveอย่างเดียว, formatter/analyze/testทุก step ห้าม renameทุก symbolพร้อมย้าย folderและเปลี่ยน behaviorเพราะ review/rollbackยาก

7. แบบฝึกหัด

sectionหนึ่งอ่าน private fields 12 ตัวควรส่ง 12 paramsไหม?

แนวคำตอบ

สร้าง immutable ViewDataที่มีเฉพาะค่าที่ render และ callbacksตาม intent; ถ้ายังใหญ่แปลว่า boundaryของ sectionอาจผิด

8. Done criteria

root screenเห็น layout/orchestration, widgetsไม่มี API, Store testsครอบ flow, lifecycleยัง disposeครบและ screenshot/interactionไม่เปลี่ยนโดยไม่ตั้งใจ
