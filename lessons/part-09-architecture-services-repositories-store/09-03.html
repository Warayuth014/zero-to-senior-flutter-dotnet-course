ApiService เป็น data source: รู้ HTTP mechanics และ wire format แต่ไม่ควรเป็น global owner ของทุก workflow/state/navigation

1. Transport responsibilities

  • ประกอบ base URL/path/query
  • แนบ headers/token
  • timeout/retry policyพื้นฐาน
  • decode JSON/status/ProblemDetails
  • redacted logging และ correlation

2. ไม่ควรทำ

ApiService ไม่ควรเลือกหน้าถัดไป, ถือ selected pallet, เปิด SnackBar, mutate widget list หรือกำหนดว่า operator ต้อง scan step ใดต่อ

3. Generic core

abstract interface class JsonClient {
  Future<Map<String, dynamic>> get(String path,
      {Map<String, String> query = const {}});
  Future<Map<String, dynamic>> post(
      String path, Map<String, dynamic> body);
}

4. Feature data source

class ReceivingRemoteDataSource {
  ReceivingRemoteDataSource(this.client);
  final JsonClient client;
  Future<ReceiptDto> receive(ReceiveRequestDto request) async =>
    ReceiptDto.fromJson(await client.post('/receiving/scan-part', request.toJson()));
}

5. ของจริง

wmsapp/services/api_service.dart รวม base resolution, GET/POST/upload และ ApiResult แล้ว domain extensionsเรียก private methods เป็นจุดเริ่มต้นที่ดีสำหรับแยก transport จาก endpoint-specific mapping

6. Singleton trade-off

singleton สะดวกแต่ซ่อน dependency/global mutable base URL ทำให้ parallel testsและ multi-serverยาก Constructor injection ทำ lifetime และ fake ชัดกว่า; migrateได้โดยห่อ interface ก่อน
