Inventory slice: read-heavy featureต้องค้นได้เร็ว, paginate, แสดง stale/errorตรงไปตรงมาและไม่โหลด stockทั้งหมดมา filterใน memoryเมื่อข้อมูลโต

1. Query contract

GET /api/WMS/mobile_inventory
?q=entity&status=stored&location=A-01
&page=1&pageSize=50
→ { items, totalCount, page, pageSize, generatedAt }

2. Search fields

serverค้น pallet, product code/name, lot, serialและlocationตาม requirement ระบุ case/diacritic behaviorและ queryขั้นต่ำ หาก scan barcode exactให้ prioritize exact result

3. Debounce/cancellation

typing debounceสั้นและ latest-wins generation; scan submitทันที Queryใหม่ reset pageแต่ responseหน้าเก่าห้าม append Filter state canonicalเพื่อ deep link/restoreได้

4. Pagination

โหลดหน้าถัดไปก่อนถึงท้าย, single-flightต่อ page, dedup stable item IDและหยุดเมื่อ itemsครบ totalCount Errorหน้าแรกกับ load-more errorมี UIต่างกัน

5. Inventory model

แสดง pallet/product/location/status/onHand/reserved/available/unit/updatedAt พร้อม status unknown fail-safe Quantityใช้ decimalตาม domain ไม่ cast intโดยเดา

6. Refresh/invalidation

pull refreshรักษา query/filterและแทน snapshot หลัง receiving/cycle/dispatch mark staleหรือ refreshเมื่อกลับหน้า ไม่ optimisticแก้ stockหาก command outcomeไม่แน่นอน

7. UX states

แยก no inventory, no search results, loading, stale dataและ server error Fixed scan/search barเหนือ scroll list, filtersมี clear countและ long textไม่ดัน quantitiesหาย

8. Tests

query encoding, exact scan, debounce, out-of-order, filter reset, pagination/dedup/load-more fail, decimal/unknown status, large result performanceและ invalidationหลัง mutation
