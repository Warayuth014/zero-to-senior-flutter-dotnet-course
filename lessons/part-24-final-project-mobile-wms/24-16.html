Test pyramidของโปรเจกต์: เน้น domain/store/contractเร็วๆ แล้วใช้ widget/flow/integrationเฉพาะ boundaryสำคัญ ไม่ไล่เปอร์เซ็นต์โดยทดสอบ gettersที่ไม่มีความเสี่ยง

1. Unit tests

models/parsers, URL normalization, failures, state machines, quantities, status mapping, generation/idempotencyและ repositoriesที่เป็น pure mapping ทุก unknown/null/boundary valueมีกรณีชัด

2. Store tests

fakesกับ controllable Completers/fake clockทดสอบ loading/data/error, retry, stale response, duplicate command, polling/reconnect, logout/disposeและ cross-feature invalidation

3. Widget tests

scanner focus/Enter, form validation, disabled action, error retry, dialog/navigation, PDA scroll/keyboard, Thai/English/text scale ใช้ semantics/keyที่สื่อ behaviorไม่หา widgetลำดับที่ N

4. Contract tests

Flutter remote repositoriesยิง fake HTTP responses/fixturesและ .NET integration testsยืนยัน routes, auth, ProblemDetails, JSON casing, multipart/idempotency ไม่จำเป็นต้องมี databaseจริงทุก testแต่ production adapterต้องมี suiteของตน

5. End-to-end smoke

health → login → dashboard
→ receive → inventoryเห็นผล
→ dispatch/manual complete
→ cycle count submit
→ upload image → logout

ใช้ dedicated test tenant/dataและ cleanupที่ปลอดภัย

6. Failure/race suite

offline, slow 5s+, 401พร้อมกัน, 409, malformed JSON, timeout-after-commit, event out-of-order, app backgroundและ double scan หาก test harnessสร้างกรณีเหล่านี้ไม่ได้ production reliabilityยังไม่ถูกพิสูจน์

7. CI gates

format check, analyze, Flutter tests, dotnet build/test, secret scanและ release build smoke Pin SDK/dependencies, cacheอย่างระวังและเก็บ test reports/artifact metadata

8. Exit criteria

critical acceptanceทุก flowมีอย่างน้อยหนึ่ง happy+failure+race test, suite deterministic, no ignored flaky tests, READMEรันได้และ regression starter TaskStoreยังผ่าน
