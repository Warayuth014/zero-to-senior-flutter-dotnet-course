ต่อยอด: starterรับ WMS_API_BASE_URLเพียงค่าเดียว ให้เพิ่ม connection profilesและใช้ GET /api/WMS/mobile_healthเป็น probeเดียวกับ base URLที่ requestsจริงใช้

1. Profile model

เก็บ id, name, baseUrl, environment label, created/updated timeและ activeId ไม่เก็บ tokenใน profile Normalize scheme/host/port, ตัด slashและ reject path/queryที่ไม่อนุญาต

2. Persistence

profilesไม่ใช่ secretจึงใช้ SharedPreferencesได้ Decodeแบบ versionedและ recoverจาก malformed dataด้วย safe seed ไม่ให้แอปค้างที่ startup การลบ active profileต้องเลือก replacementและห้ามลบตัวสุดท้าย

3. Health probe

timeoutสั้น, วัด latency, parse service/status/serverTimeและแยก DNS/socket/timeout/HTTP/contract error อย่าถือว่า TCP portเปิดเท่ากับ WMS APIพร้อม

4. Single source URL

ApiClientอ่าน active base URLต่อ requestหรือ rebuild clientอย่างควบคุม Connection dotต้อง probe URLเดียวกัน ห้าม statusบอก server Aแต่ business callไป Bจาก cached base

5. Switch security

เมื่อเปลี่ยน hostให้ clear JWT/sessionและ scoped storesก่อน requestถัดไป เพราะ tokenของ serverเดิมไม่ควรถูกส่ง serverใหม่ จากนั้น probeและบังคับ loginใหม่

6. Lifecycle/battery

probeตอนเปิด settings, activate, shell entryและ app resume ไม่ poll dotทุกไม่กี่วินาทีตลอดวัน Business task pollingมีเหตุผลคนละอย่างและต้องจัดแยก

7. .NET contract

200 {
  "service":"wms-mobile-lab",
  "status":"ok",
  "serverTime":"...Z"
}

ใน productionเพิ่ม version/capabilitiesเพื่อ clientรู้ว่า endpointsที่ต้องใช้รองรับหรือไม่

8. Acceptance tests

add/edit/activate/remove, invalid URL, malformed persistence, health timeout/wrong JSON, server switch logoutและ app resume probe โดย inject http client/fake clock ไม่ใช้ internetจริงใน unit tests
