Cycle Count slice: workflowมี phaseจาก server ไม่ใช่ formกรอกตัวเลขธรรมดา; รองรับ count/recount/variance/closeและ auditโดยไม่เผย expectedจนธุรกิจอนุญาต

1. Server phases

waiting → ready → counting → submitted
→ recount_required | returning | completed

unknown phaseปิด mutationและให้ refresh/support ไม่ mapเป็น ready

2. Lookup contract

scan pallet/stationแล้ว GET/POST lookupคืน sessionId/version/phase/linesและ permissions Expected quantityซ่อนหรือแสดงตาม blind-count policy ไม่ให้ client inferจาก inventory cacheถ้าต้อง blind

3. Count modes

quantity modeกรอก decimalต่อ product, scan modeเพิ่มหน่วย/serialพร้อม duplicate guardและ explicit zero ใช้ product stable IDไม่ใช้ translated nameเป็น map key

4. Preserve inputs

refresh phaseเดิมต้องเก็บ counts local; transitionเป็น readyใหม่จึง resetตาม session/version เปลี่ยน pallet/close/logout invalidate generationเพื่อ responseเก่าไม่คืน sessionเดิม

5. Submit/close

POST countsพร้อม sessionId/version/idempotency key Backendคำนวณ varianceและตัดสิน recount/returning; closeต้อง permission/confirmationและคืน final audit reference

6. Polling

pollเฉพาะ waiting/returning phase, single-flight, pause backgroundและ stopเมื่อ completed/ออกหน้า Pull refreshยังมีไว้แต่ไม่ใช่เหตุผลให้ phaseรอ staleตลอด

7. Error/reconciliation

version conflict reload phaseแต่เก็บ draftแยกให้ผู้ใช้ตรวจ, timeout submit query sessionก่อน retry, invalid countชี้ line, history failureไม่ block active countแต่แสดง stale indicator

8. Tests

ทุก phase, blind policy, decimal/zero/duplicate scan, preserve/reset, stale generation, overlapping poll, conflict, timeout-after-commit, close permissionและ app backgroundด้วย fake clock
