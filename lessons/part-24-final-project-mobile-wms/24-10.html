Receiving slice: สร้าง workflow scan order/part → validate pallet → quantity/serial → confirm โดย serverเป็น authorityและ UI resume/retryได้

1. State machine

select order → select/scan line → scan pallet
→ enter qty/serials → review → submit
→ success/history หรือ failureคง input

เขียน transitions/guardsก่อน widgetsและแยก instructionจาก evidence scan

2. Contracts

GET open orders/details, POST validate palletและ POST receiveที่รับ lineId, pallet, qty, serials, idempotency key/version Responseคืน receipt/remaining/status ไม่ให้ clientคำนวณ stockใหม่เอง

3. Scan normalization

trim/caseตาม barcode policy, exact matchเมื่อมี expected, debounce duplicate scanและ focusกลับช่องถัดไป Mismatchไม่ล้างค่าทั้ง sessionและบอก expected/actionชัด

4. Quantity/serial invariants

qtyมากกว่า 0ไม่เกิน remaining, serial count/uniquenessตรง qtyเมื่อ serial-controlled Backendตรวจซ้ำภายใต้ transactionเพราะ snapshotอาจ stale

5. Async session guard

เปลี่ยน order/lineหรือออกหน้าเพิ่ม receiving generation Response validate/lookupเก่าห้ามเปิด sessionเดิมกลับ Submit disableต่อ sessionและ timeoutเป็น outcome unknownที่ต้อง query receiptก่อน retry

6. Success effects

clearเฉพาะ committed inputs, refresh line/order, invalidate dashboard/inventory, แสดง receipt referenceและ audit user อย่า navigateออกก่อน store commit snapshotครบ

7. Error UX

validation conflictคง scansให้แก้, unauthorizedออก session, networkให้ retry, palletถูกใช้/lineปิด reload current truthและ parse errorมี support reference ไม่โชว์ raw exception

8. Flow tests

scanผิด/ซ้ำ, qty/serial invalid, pallet validation race, duplicate submit, timeout-after-commit, lineถูกปิดจากอีกเครื่อง, logoutระหว่าง submitและ viewport/focusด้วย fake repositoryและ integration endpoint
