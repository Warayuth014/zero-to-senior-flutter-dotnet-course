1. Use case

Supervisorแนบรูปกับ product/part IDเพื่อ identification/audit กำหนด MIME, max size/dimensions,จำนวน,permissionและ retentionก่อนเขียน picker ไม่อัปโหลด arbitrary fileจาก clientโดย backendไม่ตรวจ

2. Cross-platform file

ใช้ XFile/bytes abstraction; mobileอาจมี pathแต่ webไม่มี ห้าม import dart:ioใน code path webโดยไม่มี conditional implementation Repositoryรับ UploadFile(name,mime,bytes/stream,length)

3. Validation/compression

ตรวจ type/sizeและ decode image, resize/compressนอก UI threadเมื่อหนัก, preserve orientationตาม policyและไม่พึ่ง extensionอย่างเดียว Backendตรวจ MIME magic bytesซ้ำ

4. Multipart contract

POST /api/WMS/mobile_parts/{partId}/image
Authorization: Bearer ...
Idempotency-Key: ...
multipart: file + optional metadata
→ { imageId, url, uploadedAt }

5. Progress/cancel

http MultipartRequestพื้นฐานอาจไม่ให้ progressสะดวก ใช้ streamed request/clientที่ track bytesหาก requirementมี Cancelหยุด client uploadแต่ backendต้อง cleanup partialและ client reconcileว่าบันทึกแล้วหรือยัง

6. Security

backend authorize supervisor, sanitize filename, randomize storage key, limit body, scan content, serveด้วย safe Content-Typeและไม่เก็บ public URLถ้าข้อมูล sensitive Flutterไม่ log bytes/token/local path

7. UX

preview, replace/removeก่อน submit, progress, retryและ success thumbnail Failureคง selectionเมื่อปลอดภัย Permission deniedอธิบายวิธีแก้และ app resumeหลัง settingsต้อง recheck

8. Tests

valid/oversize/wrong MIME/corrupt image, Android path vs web bytes, auth denied, progress/cancel, timeout-after-commit, duplicate keyและ server filename attackด้วย repository/endpoint integration tests
