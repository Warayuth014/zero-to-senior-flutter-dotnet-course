1. พื้นที่ที่แอปวาดได้ ไม่เท่ากับหน้าจอ

┌─────────────────────────┐
│  แถบสถานะ (นาฬิกา แบต)  │ ← ระบบวาด
├─────────────────────────┤
│                         │
│      พื้นที่ของแอป       │
│                         │
├─────────────────────────┤
│  แถบนำทาง (ปุ่มย้อนกลับ) │ ← ระบบวาด
└─────────────────────────┘

Android รุ่นใหม่ใช้โหมด edge-to-edge ซึ่งให้แอปวาดใต้แถบทั้งสองได้ ผลคือถ้าไม่จัดการ เนื้อหาจะไปอยู่ใต้นาฬิกา

2. สามเครื่องมือที่ต้องใช้ร่วมกัน

เครื่องมือทำอะไร
SystemChrome.setSystemUIOverlayStyleตั้งสีและความสว่างของไอคอนบนแถบระบบ
AnnotatedRegionตั้งค่าเดียวกันแบบผูกกับ widget — ค่าจะกลับเมื่อออกจากจอนั้น
SafeAreaดันเนื้อหาให้พ้นแถบระบบ

ของจริงใช้ทั้งสามอย่างพร้อมกัน

const _systemUiStyle = SystemUiOverlayStyle(
  statusBarColor: AppColors.statusBar,
  statusBarIconBrightness: Brightness.light,
  statusBarBrightness: Brightness.dark,
  systemStatusBarContrastEnforced: false,
);

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  ...
  // Match the system status bar to the PDA bar so they read as one strip.
  SystemChrome.setSystemUIOverlayStyle(_systemUiStyle);

  runApp(WmsApp(auth: AuthRepository(ApiClient())));
}

3. สองชื่อที่สับสนที่สุดใน Flutter

ค่าหมายถึงใช้บน
statusBarIconBrightnessความสว่างของไอคอน — light คือไอคอนสีขาวAndroid
statusBarBrightnessความสว่างของพื้นหลัง — dark คือพื้นเข้ม ระบบจึงทำไอคอนให้สว่างiOS
สองค่านี้ตรงข้ามกันเมื่อต้องการผลเดียวกัน — พื้นเข้มไอคอนขาว ต้องตั้ง iconBrightness: light และ brightness: dark ซึ่งเป็นที่มาของบั๊กที่ว่า “ทำไมบน iPhone ไอคอนหายไป”

systemStatusBarContrastEnforced: false บอก Android ว่าอย่าเติมพื้นหลังโปร่งแสงให้เอง เพราะเราจัดการสีเองแล้ว ถ้าไม่ตั้ง จะได้แถบสีที่จางกว่าที่กำหนดบนเครื่องบางรุ่น

4. ทำไมต้องมี AnnotatedRegion ด้วย

// Android edge-to-edge devices draw Flutter behind the native status
// bar. Keep every route below that inset while painting the exposed
// area with the same navy as the branded PDA strip.
builder: (context, child) => AnnotatedRegion<SystemUiOverlayStyle>(
  value: _systemUiStyle,
  child: ColoredBox(
    color: AppColors.statusBar,
    child: SafeArea(
      bottom: false,
      child: child ?? const SizedBox.shrink(),
    ),
  ),
),
ชั้นหน้าที่ถ้าไม่มี
AnnotatedRegionตั้งสไตล์ซ้ำแบบผูกกับ widgetAppBar ของแต่ละจอจะทับค่าที่ตั้งใน main
ColoredBoxทาสีพื้นที่ใต้แถบสถานะเห็นพื้นสีขาวโผล่เหนือแถบสีของแอป
SafeAreaดันเนื้อหาลงมาให้พ้นนาฬิกาหัวข้อของจอไปซ้อนกับนาฬิกา

bottom: false สำคัญ — ไม่ดันเนื้อหาขึ้นจากด้านล่าง เพราะจอนี้ไม่มีอะไรติดขอบล่าง และการดันขึ้นจะทำให้เสียพื้นที่ไปฟรี ๆ บนจอที่เตี้ยอยู่แล้ว

วางไว้ที่ MaterialApp.builder เพราะที่นั่นครอบทุกเส้นทาง — ตั้งครั้งเดียวได้ผลทุกจอ รวมถึงจอที่ยังไม่ได้เขียน

5. MaterialApp.builder ทำงานตอนไหน

MaterialApp(
  builder: (context, child) => ..., // child คือจอที่กำลังแสดงอยู่
  home: LoginScreen(auth: auth),
)
คุณสมบัติรายละเอียด
ถูกเรียกทุกครั้งที่เปลี่ยนจอchild เปลี่ยนไปตามเส้นทางปัจจุบัน
อยู่ใต้ MaterialAppใช้ Theme.of และ Localizations.of ได้
อยู่เหนือ Navigatorสิ่งที่ห่อตรงนี้จะไม่ถูกแทนที่เมื่อ push จอใหม่
child อาจเป็น nullต้องเผื่อไว้ ตามที่โค้ดจริงเขียน child ?? const SizedBox.shrink()

เหมาะกับสิ่งที่ต้องครอบทั้งแอป เช่นแถบแจ้งเตือนสถานะการเชื่อมต่อ (10.12) หรือการจำกัดขนาดตัวอักษรไม่ให้ผู้ใช้ตั้งใหญ่จนหน้าจอพัง

6. ล็อกแนวหน้าจอ

await SystemChrome.setPreferredOrientations([
  DeviceOrientation.portraitUp,
]);
ควรล็อกเมื่อไม่ควรล็อกเมื่อ
ทุกจอออกแบบมาสำหรับแนวตั้งเท่านั้นมีตารางกว้างที่ดูแนวนอนดีกว่า
PDA ที่มีปุ่มสแกนอยู่ตำแหน่งตายตัวแอปที่ใช้บนแท็บเล็ตด้วย
ผู้ใช้ถือเครื่องแนวเดียวตลอด—

บน PDA การล็อกแนวตั้งมักถูกต้อง เพราะเครื่องมีสายคล้องและปุ่มสแกนที่ออกแบบมาให้ถือแนวเดียว การหมุนจอจึงเป็นอุบัติเหตุมากกว่าความตั้งใจ

ต้องเรียกหลัง WidgetsFlutterBinding.ensureInitialized() เสมอ ไม่งั้นจะพัง

7. ลำดับใน main มีความหมาย

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();     // 1
  await AppLanguageController.instance.load();   // 2
  await ConnectionController.instance.load();    // 3
  SystemChrome.setSystemUIOverlayStyle(...);     // 4
  runApp(...);                                   // 5
}
ขั้นทำไมต้องอยู่ตรงนี้
1ต้องมาก่อนทุกอย่างที่คุยกับระบบปฏิบัติการ รวมถึงการอ่านค่าที่บันทึกไว้
2ถ้าโหลดหลัง runApp ผู้ใช้จะเห็นภาษาอังกฤษแวบหนึ่งก่อนเปลี่ยนเป็นไทย
3คอมเมนต์ในโค้ดจริงบอกไว้ว่า “ต้องเสร็จก่อนคำขอแรก” — AppConfig.apiBaseUrl จะตกไปใช้ค่าสำรองจนกว่า profile จะอยู่ในหน่วยความจำ
4ตั้งก่อนวาดเฟรมแรก จะได้ไม่เห็นแถบสีเปลี่ยน
ราคาที่ต้องจ่าย: ทุก await ใน main คือเวลาที่ผู้ใช้เห็นหน้าจอเริ่มต้นนานขึ้น สิ่งที่ควรอยู่ตรงนี้คือสิ่งที่ทำให้หน้าจอแรกผิดถ้าไม่มี ไม่ใช่ทุกอย่างที่ต้องโหลด — ส่วนที่เหลือให้โหลดหลังจากนั้นแบบที่ 8.6 ทำ

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
เนื้อหาไปอยู่ใต้นาฬิกาไม่มี SafeAreaใส่ที่ MaterialApp.builder
ไอคอนแถบสถานะมองไม่เห็นตั้ง brightness ผิดตัวตั้งทั้งสองค่าให้ตรงข้ามกัน
ตั้งใน main แล้วบางจอไม่เป็นไปตามนั้นAppBar ทับค่าใช้ AnnotatedRegion หรือตั้งที่ AppBar.systemOverlayStyle
มีแถบขาวเหนือแอปไม่ได้ทาสีพื้นที่ใต้แถบสถานะห่อด้วย ColoredBox
เสียพื้นที่ด้านล่างไปเปล่า ๆSafeArea ดันขึ้นทั้งที่ไม่จำเป็นbottom: false
setPreferredOrientations พังเรียกก่อน ensureInitializedสลับลำดับ

9. แบบฝึกหัด

ผู้ใช้ตั้งขนาดตัวอักษรของเครื่องเป็นใหญ่สุด แล้วรายงานว่าปุ่มในแอปซ้อนทับกันจนกดไม่ได้

  1. เกิดอะไรขึ้น
  2. ควรแก้อย่างไร
แนวคำตอบ

1. Flutter คูณขนาดตัวอักษรทุกตัวด้วยค่าที่ผู้ใช้ตั้งไว้ในระบบ ซึ่งบน Android ไปได้ถึงราว 2 เท่า ปุ่มที่สูง 54 พร้อมตัวอักษร 15 จะกลายเป็นตัวอักษร 30 ที่ล้นออกนอกปุ่ม

2. มีสามทาง และสองทางแรกผิด

ทางผล
ปิดการปรับขนาดทั้งหมดอย่าทำ — ผู้ใช้ที่ตั้งค่านั้นเพราะมองไม่ชัด จะใช้แอปไม่ได้เลย และเป็นกลุ่มที่ต้องการมันจริง ๆ
ตั้งขนาดตัวอักษรตายตัวทุกที่เหมือนข้อแรกแต่กระจัดกระจายกว่า
จำกัดช่วง แล้วทำให้ layout ยืดได้ถูก
MaterialApp(
  builder: (context, child) {
    final scaler = MediaQuery.textScalerOf(context).clamp(
      minScaleFactor: 1.0,
      maxScaleFactor: 1.3,     // เกินนี้ layout ของ PDA รับไม่ไหว
    );
    return MediaQuery.withNoTextScaling(
      child: MediaQuery(
        data: MediaQuery.of(context).copyWith(textScaler: scaler),
        child: child ?? const SizedBox.shrink(),
      ),
    );
  },
)

แต่การจำกัดเป็นแค่ครึ่งเดียวของคำตอบ อีกครึ่งคือทำให้ layout รับได้จริงถึง 1.3

  • ใช้ minimumSize แทน height ตายตัว เพื่อให้ปุ่มสูงขึ้นได้เมื่อตัวอักษรใหญ่
  • ห่อแถวที่มีข้อความยาวด้วย Flexible เพื่อให้ตัดบรรทัดแทนที่จะล้น
  • ทดสอบทุกจอที่ textScaler: 1.3 ในเทสต์ ไม่ใช่รอผู้ใช้รายงาน
testWidgets('จอหลักใช้งานได้ที่ขนาดตัวอักษร 1.3 เท่า', (tester) async {
  await tester.pumpWidget(MediaQuery(
    data: const MediaQueryData(textScaler: TextScaler.linear(1.3)),
    child: const PdaApp(...),
  ));
  await tester.pumpAndSettle();

  expect(tester.takeException(), isNull);   // ไม่มี overflow
});

เทสต์นี้จับ overflow ได้เพราะ Flutter โยน exception เมื่อ layout ล้นในโหมด debug — เป็นวิธีตรวจที่ถูกที่สุดสำหรับปัญหาที่ไม่มีใครทดสอบด้วยมือ

10. สรุป

  • Android รุ่นใหม่ให้แอปวาดใต้แถบระบบ ต้องจัดการเอง
  • statusBarIconBrightness กับ statusBarBrightness ตั้งตรงข้ามกันเมื่อต้องการผลเดียวกัน
  • ตั้งที่ MaterialApp.builder ได้ผลทุกจอ รวมถึงจอที่ยังไม่ได้เขียน
  • SafeArea(bottom: false) ประหยัดพื้นที่บนจอที่เตี้ย
  • main ควรมีแต่สิ่งที่ทำให้หน้าจอแรกผิดถ้าไม่มี
  • อย่าปิดการปรับขนาดตัวอักษร ให้จำกัดช่วงแล้วทำ layout ให้ยืดได้

บทหน้า: ประกอบทุกอย่างเป็นเปลือกแอปสองภาษาที่ใช้งานได้จริง
