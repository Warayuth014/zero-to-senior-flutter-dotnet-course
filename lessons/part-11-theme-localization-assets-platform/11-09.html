intl formatตาม locale ไม่เปลี่ยน business value: เก็บ DateTime/numแบบ typedและ timezoneถูกก่อน แล้ว formatเฉพาะ presentation boundary

1. NumberFormat

final locale = Localizations.localeOf(context).toLanguageTag();
final qtyText = NumberFormat.decimalPattern(locale).format(quantity);
final moneyText = NumberFormat.currency(
  locale: locale, symbol: '฿', decimalDigits: 2).format(amount);

2. DateFormat

final local = utcTimestamp.toLocal();
final text = DateFormat.yMMMd(locale).add_Hm().format(local);

แปลง timezoneตาม contractก่อน formatและอย่า parse display stringกลับเป็น data

3. Cached formatter

สร้าง formatterซ้ำใน listใหญ่มี costแต่ cacheต้อง keyedด้วย locale/pattern/currencyและ invalidateเมื่อภาษาเปลี่ยน ไม่ใช้ singleton formatterภาษาเดิม

4. Machine values

barcode, pallet ID, location codeและ API numbersใช้ invariant wire format ไม่ format comma/Thai digitก่อนส่ง server การ localizeใช้เฉพาะข้อความแสดง

5. Relative time

“12 วินาทีที่แล้ว” ควรใช้ fake Clockใน testและ update intervalเหมาะสม ไม่ให้ widgetหลายร้อยตัวมี Timerของตัวเอง

6. Calendar expectations

กำหนด product policyเรื่อง Gregorian/Buddhist Eraและ timezoneโรงงานให้ชัด อย่า assumeว่า locale thหมายถึงต้องเปลี่ยน business calendarโดยอัตโนมัติ

7. แบบฝึกหัด

quantity 1234.5ควรส่ง APIหลัง NumberFormatภาษาไทยไหม?

เฉลย

ไม่ ส่ง numeric JSON 1234.5; formatสำหรับ Textเท่านั้น มิฉะนั้น separator/เลข localizedทำ contractพัง

8. Tests

en/th decimal/date, zero/negative/large, UTC→local, locale switch, timezone boundaryและ invariant API serialization
