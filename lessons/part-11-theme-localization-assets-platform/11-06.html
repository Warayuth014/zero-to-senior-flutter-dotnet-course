1. Locale คืออะไร

วัตถุเล็ก ๆ ที่บอกว่า “ภาษาอะไร ในภูมิภาคไหน”
const Locale('th')                   // ภาษาไทย ไม่ระบุประเทศ
const Locale('th', 'TH')              // ภาษาไทย ประเทศไทย
const Locale('en', 'US')              // อังกฤษ อเมริกัน
const Locale('en', 'GB')              // อังกฤษ อังกฤษ
ส่วนมาตรฐานตัวอย่าง
รหัสภาษาISO 639 ตัวพิมพ์เล็กth, en, ja
รหัสประเทศISO 3166 ตัวพิมพ์ใหญ่TH, US

ประเทศมีผลกับสิ่งที่ไม่ใช่ภาษาโดยตรง เช่น en_US เขียนวันที่เป็น 08/21/2026 ส่วน en_GB เขียน 21/08/2026 — ตัวเลขชุดเดียวกันแต่คนละความหมาย

แอปนี้ใช้ Locale('th') ไม่ระบุประเทศ เพราะไม่มีความต่างระหว่างภาษาไทยในแต่ละประเทศที่ต้องรองรับ การเพิ่มประเทศเข้าไปตอนที่ยังไม่ต้องใช้ คือการเดาอนาคต

2. delegate คืออะไร

คือวัตถุที่รับผิดชอบสามอย่าง

เมธอดตอบคำถามว่า
isSupported(locale)ภาษานี้มีข้อความให้ไหม
load(locale)โหลดข้อความของภาษานี้มา
shouldReload(old)ต้องโหลดใหม่เมื่อ delegate ถูกสร้างใหม่ไหม
class AppTextDelegate extends LocalizationsDelegate<AppTexts> {
  const AppTextDelegate();

  @override
  bool isSupported(Locale locale) => ['en', 'th'].contains(locale.languageCode);

  @override
  Future<AppTexts> load(Locale locale) async =>
      AppTexts(AppLanguage.fromCode(locale.languageCode));

  // ข้อความของเราอยู่ในโค้ด ไม่ได้โหลดจากไฟล์ จึงไม่มีอะไรต้องโหลดใหม่
  @override
  bool shouldReload(AppTextDelegate old) => false;
}

สังเกตว่า load คืน Future เพราะบางระบบต้องอ่านไฟล์หรือดาวน์โหลด แต่ของเราอยู่ในโค้ดอยู่แล้ว จึงเสร็จทันที

3. ใช้ผ่าน Localizations.of

class AppTexts {
  const AppTexts(this.language);
  final AppLanguage language;

  String get scanPallet => AppText.scanPallet.of(language);

  static AppTexts of(BuildContext context) =>
      Localizations.of<AppTexts>(context, AppTexts)!;
}

// ในจอ
Text(AppTexts.of(context).scanPallet)

Localizations.of ทำงานเหมือน Theme.of คือไต่ต้นไม้ widget ขึ้นไปหาตัวที่ใกล้ที่สุด

4. แล้วทำไม lab ไม่ใช้วิธีนี้

lab ใช้ InheritedNotifier กับ LanguageController แทน ซึ่งต่างกันที่จุดเดียวแต่สำคัญ

LocalizationsDelegateInheritedNotifier (lab)
เปลี่ยนภาษาอย่างไรเปลี่ยน locale ของ MaterialAppเรียก controller.toggle()
ใครถือสถานะMaterialAppcontroller ที่เราถือเอง
บันทึกลงเครื่องต้องมีที่เก็บแยกอยู่ดีอยู่ใน controller เลย
ทดสอบข้อความโดยไม่มี widgetไม่ได้ ต้องมี BuildContextได้ AppText.signIn.of(AppLanguage.thai)
เข้ากับ widget ของ Flutterเข้ากันเป็นธรรมชาติต้องส่ง locale ให้ MaterialApp เอง

แถวรองสุดท้ายคือเหตุผลหลัก — เทสต์ที่ตรวจว่าข้อความถูกแปลครบ (11.8) ต้องเรียกได้โดยไม่สร้าง widget ถ้าผูกกับ BuildContext จะเขียนเทสต์แบบนั้นไม่ได้

ในทางกลับกัน ถ้าโปรเจกต์ใช้ gen_l10n (11.8) จะได้ delegate มาให้อัตโนมัติ และวิธีแรกก็เป็นทางที่ถูกต้อง

5. InheritedNotifier ทำงานอย่างไร

/// ใช้ InheritedNotifier ซึ่งทำสองอย่างพร้อมกัน คือส่งของลงไปโดยไม่ต้อง
/// ต่อ parameter เป็นทอด ๆ และสั่งให้ widget ที่อ่านค่านี้วาดใหม่เมื่อ
/// controller ประกาศว่ามีอะไรเปลี่ยน
class LanguageScope extends InheritedNotifier<LanguageController> {
  const LanguageScope({
    super.key,
    required LanguageController controller,
    required super.child,
  }) : super(notifier: controller);

  static LanguageController of(BuildContext context) {
    final scope = context.dependOnInheritedWidgetOfExactType<LanguageScope>();
    assert(scope != null, 'ไม่พบ LanguageScope เหนือ widget นี้');
    return scope!.notifier!;
  }
}
ส่วนหน้าที่
InheritedWidgetส่งของลงต้นไม้ widget ให้ลูกหลานอ่านได้โดยไม่ต้องส่งผ่านทุกชั้น
InheritedNotifierเพิ่มความสามารถ คือฟัง Listenable แล้วสั่งให้ผู้ที่พึ่งพาวาดใหม่
dependOnInheritedWidgetOfExactTypeอ่านค่าและลงทะเบียนว่า widget นี้ต้องวาดใหม่เมื่อค่าเปลี่ยน
assertฟ้องตอน dev ถ้าลืมห่อ LanguageScope — ต่างจากการคืน null ที่จะไปพังที่อื่นทีหลัง
คำที่ต้องแยกให้ออก — dependOnInheritedWidgetOfExactType ลงทะเบียนการพึ่งพา ส่วน getInheritedWidgetOfExactType อ่านอย่างเดียวไม่วาดใหม่ ใช้ตอนอ่านใน initState ที่ยังลงทะเบียนไม่ได้

6. ทางลัดที่ทำให้โค้ดในจออ่านง่าย

extension LanguageContext on BuildContext {
  String t(Message message) => LanguageScope.of(this).text(message);
  String t1<T>(Message1<T> message, T value) =>
      LanguageScope.of(this).text1(message, value);
  AppLanguage get language => LanguageScope.of(this).language;
}
ไม่มี extensionมี extension
LanguageScope.of(context).text(AppText.signIn)context.t(AppText.signIn)

สั้นลงมาก และสำคัญเพราะข้อความโผล่ในทุกบรรทัดของ UI ถ้าเขียนยาวทุกครั้ง โครงของ layout จะจมอยู่ใต้โค้ดอ่านข้อความ

ข้อควรระวังคือ extension บน BuildContext จะปรากฏในรายการเติมคำอัตโนมัติของทุก context ในโปรเจกต์ ชื่อจึงควรสั้นแต่ไม่ทั่วไปเกิน — t ใช้ได้เพราะสื่อชัดในบริบทของ UI แต่ชื่ออย่าง get หรือ value จะสร้างความสับสน

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
เปลี่ยนภาษาแล้วจอไม่วาดใหม่ใช้ getInheritedWidgetOfExactTypeใช้ dependOn...
Null check operator used on a null valueลืมห่อ LanguageScopeใส่ assert ที่บอกชัดว่าลืมอะไร
อ่านภาษาใน initState แล้วพังยังลงทะเบียนการพึ่งพาไม่ได้ในจังหวะนั้นย้ายไป didChangeDependencies หรืออ่านใน build
บางส่วนของจอไม่เปลี่ยนภาษาส่วนนั้นเป็น const จึงไม่วาดใหม่เอา const ออกจาก widget ที่มีข้อความ

แถวสุดท้ายเจอบ่อยและงงมาก — const Text('Sign in') จะไม่มีวันเปลี่ยนเป็นไทย เพราะ Flutter ข้ามการวาดใหม่ให้ widget ที่เป็น const ทั้งก้อน ซึ่งปกติเป็นเรื่องดีด้านประสิทธิภาพ แต่กลายเป็นกับดักเมื่อข้อความต้องเปลี่ยนได้

8. แบบฝึกหัด

ทีมจะเพิ่มภาษาที่สาม คือภาษาพม่า สำหรับพนักงานที่อ่านไทยไม่คล่อง

  1. ต้องแก้อะไรบ้างในโครงของ lab
  2. โครงนี้เหมาะกับสามภาษาไหม
แนวคำตอบ

1. จุดที่ต้องแก้

ไฟล์แก้อะไร
app_messages.dartเพิ่ม AppLanguage.burmese และเพิ่มพารามิเตอร์ตัวที่สามให้ Message ทุกก้อน
pda_shell.dartเพิ่มใน supportedLocales
ปุ่มสลับภาษาtoggle() ที่สลับไปมาสองค่า ใช้ไม่ได้แล้ว ต้องเป็นเมนูให้เลือก
ฟอนต์ต้องตรวจว่าฟอนต์ที่ใช้มีอักษรพม่าไหม (11.4)

2. ไม่เหมาะ และนี่คือคำตอบที่สำคัญกว่า

Message(String en, String th) เป็นคลาสที่มีพารามิเตอร์ตายตัวสองตัว การเพิ่มภาษาที่สามแปลว่าต้องแก้ ทุกก้อนข้อความ ในไฟล์ ไม่ใช่แค่เพิ่มภาษา

โครงที่รองรับได้ดีกว่าคือเก็บเป็น map

class Message {
  const Message(this._byLanguage);
  final Map<AppLanguage, String> _byLanguage;

  String of(AppLanguage language) =>
      _byLanguage[language] ?? _byLanguage[AppLanguage.english]!;
}

แต่แลกมาด้วยสิ่งที่เสียไป คือคอมไพเลอร์ไม่บังคับให้ใส่ครบทุกภาษาอีกต่อไป ต้องพึ่งเทสต์แทน ซึ่งเป็นการแลกที่ต้องยอมเมื่อภาษาเกินสองภาษา

ข้อคิดที่สำคัญกว่าตัวโค้ด: โครงสองภาษาของ lab ไม่ใช่ความผิดพลาด — มันคือโครงที่ถูกต้องสำหรับความต้องการที่มีอยู่จริงตอนนี้ ตามหลักใน 9.12 ที่ว่าอย่าเผื่ออนาคตที่ยังไม่มา แต่คนที่เขียนต้องรู้ว่าเส้นแบ่งอยู่ตรงไหน และตรงนี้คือ “ภาษาที่สาม”

และถ้าถึงจุดนั้นจริง gen_l10n ที่ 11.8 จะพูดถึงเป็นคำตอบที่ตรงกว่าการเขียนเอง

9. สรุป

  • Locale คือภาษาบวกภูมิภาค ซึ่งมีผลกับรูปแบบวันที่และตัวเลข
  • delegate ตอบสามคำถาม คือรองรับไหม โหลดอย่างไร และต้องโหลดใหม่ไหม
  • InheritedNotifier ส่งของลงต้นไม้พร้อมสั่งวาดใหม่
  • dependOn... ลงทะเบียนการพึ่งพา ส่วน get... ไม่
  • const Text ที่มีข้อความจะไม่เปลี่ยนภาษา
