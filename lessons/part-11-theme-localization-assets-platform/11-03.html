Design tokens เป็น vocabularyของ UI: spacing, radius, typography, colors, elevationและmotionที่ตั้งชื่อตามความหมาย ช่วยให้ brand/ergonomicsเปลี่ยนจากจุดเดียว

1. Token groups

abstract final class AppSpacing {
  static const xs = 4.0, sm = 8.0, md = 16.0, lg = 24.0;
}
abstract final class AppRadius {
  static const field = 12.0, card = 16.0, dialog = 20.0;
}
abstract final class AppSize { static const touchTarget = 48.0; }

2. Semantic names

surfaceMuted, statusBar, touchTarget สื่อ intentดีกว่า blue100/size48ใน widget แต่ primitive paletteยังใช้ภายใน themeได้

3. Reusable widget

class StatusChip extends StatelessWidget {
  const StatusChip({required this.label, required this.tone});
  final String label; final StatusTone tone;
  // map tone → theme tokens + icon, not raw API status string
}

4. Avoid giant CommonWidgets

shared componentควร cohesiveและ APIแคบ หากไฟล์ commonหลายร้อยบรรทัดรวม dialog/card/toastทุกอย่างให้แยกตาม primitive/pattern/featureและไม่ genericเร็วเกิน

5. PDA ergonomics

มือเปียก/ถุงมือ/สแกนเร็วต้อง targetใหญ่, spacingชัด, primary actionตำแหน่งคงที่, feedbackหลายช่องทาง และไม่ใช้ dense UIจนแตะผิด

6. Theme extensions

semantic tokensที่ต่าง light/darkสามารถใช้ ThemeExtension แทน static context getters ทำให้ interpolateและเข้าถึงผ่าน ThemeDataอย่างเป็นระบบ

7. แบบฝึกหัด

status OPENใช้สี primaryใน 12 screensควรแก้ตรงไหน?

เฉลย

map typed status→StatusToneใน presentation mapperและ StatusChip/theme tokenหนึ่งจุด ไม่ค้น replaceสีทุก screen

8. Review

ไม่มี magic spacing/radiusกระจาย, component statesครบ, token namesสื่อ semantics, accessibilityไม่ถูก wrapperซ่อนและ feature-specific widgetไม่ถูกย้าย commonก่อนเวลา
