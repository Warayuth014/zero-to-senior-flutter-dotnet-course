Unit contract และ widget tests

Part 26: Final Project Implementation I: Production Task Flow

Test pyramid ของ slice: model/repository/store tests ให้ feedback เร็ว ส่วน widget testพิสูจน์ interaction สำคัญ ทั้งหมดไม่แทน integration test ที่ยิง .NET จริง

1. Model tests

wms_task_test.dart ตรวจ valid parse, id ว่าง และ unknown status จุดประสงค์คือ lock schema assumptions ไม่ใช่เพิ่ม coverage ตัวเลขอย่างเดียว

2. Repository tests

RecordingJsonApi ตรวจ path/header/typed completion และ malformed list ทำให้รู้ว่า adapter แปลง transport เป็น domain ถูกโดยไม่เปิด port หรือพึ่งเวลา

3. Store happy path

Fake repository คืน task แล้ว complete ตรวจว่า list ซึ่งเป็น SSOT ถูกลบ, error ว่างและ feedback ถูกสร้าง Test ไม่ต้อง pump widget จึงเร็วและชี้ business state ตรง

4. Store concurrency

Completer ทำให้ request ค้างตามควบคุม จึงเรียก complete ซ้ำใน window ที่ busy และ assert call count เท่ากับหนึ่ง หลีกเลี่ยง Future.delayed ซึ่งทำให้ test ช้า/flaky

5. Store reconciliation

Fake จำลอง server commit แล้ว response timeout จากนั้น fetch คืนว่าง Test พิสูจน์ว่า Store ไม่ส่ง mutation ซ้ำและเปลี่ยน warning เป็นผลตรวจสอบล่าสุด

6. Widget behavior

task_screen_test.dart pump app, เห็น task, แตะ complete, เห็น confirm, ยืนยัน, เห็น empty state และ SnackBar correlation นี่คือ critical user path หนึ่งเส้นที่อ่านง่าย

7. สิ่งที่ยังต้องเพิ่ม

เพิ่ม stale-load ordering, known error banner, cancel dialog, accessibility semantics และ HTTP integration test ใน milestone ต่อไป รวมทั้ง screenshot/golden เฉพาะ UI ที่ design stability สำคัญ

8. Quality gate

flutter analyze --no-pub
flutter test --no-pub
dotnet build --no-restore
อย่าแก้ test ให้ผ่านด้วยการลด assertion เมื่อ behavior พัง ให้ตัดสินก่อนว่า contract เปลี่ยนโดยตั้งใจหรือเป็น regression
