Composition root: จุดประกอบ object ควรอยู่ขอบแอป ส่วน widget, store และ repository รับ dependency ที่ต้องใช้ผ่าน constructor อย่างเปิดเผย

1. Trace จาก main

final repository = RemoteTaskRepository(ApiClient(baseUrl: baseUrl));
runApp(WmsLabApp(store: TaskStore(repository)));

main.dart รู้ concrete classes และ environment แต่ TaskStore รู้เพียง TaskRepository นี่คือ dependency direction ที่ทำให้ logic ทดสอบโดยไม่เปิด server ได้

2. Compile-time environment

String.fromEnvironment('WMS_API_BASE_URL') เหมาะกับ lab และ CI เพราะกำหนดผ่าน --dart-define ได้ แต่ production หลาย server ควรมี connection profile ที่ validate/persist และผูก session กับ server ตาม Part 10

3. ใครเป็นเจ้าของ lifecycle

object ที่สร้าง client ควรรับผิดชอบปิด client ส่วน screen ที่รับ store เฉพาะหน้าอาจ dispose store ได้ ในแอปจริงถ้า store อยู่เหนือ route ต้องย้าย ownership ไป shell อย่า dispose dependency ที่ parent ยังใช้

4. Boundary ที่มองเห็น

  • UI รับ TaskStore
  • Store รับ TaskRepository
  • Remote repository รับ JsonApi
  • ApiClient รับ http.Client

ทุก seam เปลี่ยนเป็น fake ได้โดยไม่ใช้ global singleton หรือ service locator

5. หลีกเลี่ยง new ใน feature

ถ้า TaskScreen สร้าง ApiClient เอง test จะต้องรู้ URL และ network, settings เปลี่ยนแล้ว object เก่ายังถือ URL เดิม และ reconnect ยาก การ inject ทำให้ screen สนใจเพียง interaction

6. Scale ไปหลาย feature

เมื่อมี auth/inventory/receiving ให้สร้าง AppDependencies หรือ provider scope ที่ composition root แทนการส่ง constructor ยาวทุกชั้น แต่หลัก ownership/direction เดิมต้องไม่หาย

7. แบบฝึกหัด

เพิ่ม HealthRepository ที่รับ JsonApi และคืน typed HealthStatus ห้าม import package http ใน repository และห้ามให้ widget decode JSON

8. Review question

ถ้าต้องเปลี่ยนจาก HTTP เป็น fixture offline เพื่อ demo คุณควรเปลี่ยน object ที่ composition root เท่านั้น แล้ว store/screen เดิมยังทำงานได้
