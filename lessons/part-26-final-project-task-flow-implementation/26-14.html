Integration checkpoint: บทนี้ปิด milestone ด้วยการรันสอง process, ทดลอง contract และให้ผู้เรียนต่อยอดหนึ่ง feature โดยใช้มาตรฐานเดียวกัน

1. Verify static/test

cd labs/flutter_wms_companion
flutter analyze --no-pub
flutter test --no-pub

cd ../dotnet/WmsMobileApi
dotnet build --no-restore

ต้องผ่านก่อนเปิด UI เพื่อแยก compile/test defect ออกจาก network configuration

2. Run API

dotnet run --project labs/dotnet/WmsMobileApi --urls http://0.0.0.0:5080

เรียก health และ tasks ด้วย REST client ก่อน หากไม่ได้ค่อยตรวจ firewall/port อย่า debug Flutter ทั้งที่ API ยังไม่ฟัง

3. Run Flutter

flutter run --project-directory labs/flutter_wms_companion --dart-define=WMS_API_BASE_URL=http://localhost:5080

Android emulator ใช้ 10.0.2.2 เครื่องจริงใช้ IP ของเครื่อง dev ที่เข้าถึงจากเครือข่ายเดียวกัน

4. Manual scenarios

  1. โหลดสอง task และ pull refresh
  2. กดยกเลิก confirm แล้ว task ต้องอยู่
  3. ยืนยัน TASK-001 และเห็น correlation
  4. refresh แล้ว task ไม่กลับมา
  5. ปิด API แล้ว refresh ต้องคง snapshot พร้อม error

5. Replay experiment

ใช้ REST client ส่ง Idempotency-Key เดิมสองรอบและอ่าน replayed จาก response เก็บ request/response เป็น evidence ไม่อาศัยการมอง list อย่างเดียว

6. แบบฝึกหัดหลัก

เพิ่ม action “เริ่มงาน” ด้วย status transition waiting→working ใช้ command ID, strict response, per-task guard, timeout reconciliation และ tests ชุดเดียวกับ complete ห้าม copy Store ใหม่ทั้งก้อน

7. Rubric

  • 3 คะแนน: contract และ error taxonomy
  • 2 คะแนน: idempotency/reconciliation
  • 2 คะแนน: state/UX concurrency
  • 2 คะแนน: unit+widget tests
  • 1 คะแนน: runbook และข้อจำกัด

8. ต่อไป

Milestone นี้สร้าง implementation standard แล้ว Part ถัดไปจะเปรียบเทียบ Provider, Riverpod และ BLoC/Cubit โดยย้าย Task flow เดิมเพื่อเห็น trade-off จาก behavior เดียวกัน ไม่เรียน package แบบท่อง API
