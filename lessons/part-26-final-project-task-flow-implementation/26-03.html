JsonApi seam เพื่อทดสอบ network boundary

Part 26: Final Project Implementation I: Production Task Flow

Test seam: JsonApi ไม่ได้สร้างเพื่อซ่อนทุกอย่าง แต่สร้าง boundary เล็กที่สุดที่ repository ต้องใช้และ fake ได้โดยไม่ผูกกับ network

1. Interface ของ boundary

abstract interface class JsonApi {
  Future<Map<String, dynamic>> getJson(String path);
  Future<Map<String, dynamic>> postJson(...);
}

2. ทำไมไม่ mock ApiClient โดยตรง

Dart class concrete ที่ทำ I/O มักต้อง subclass/override รายเมธอดและผูกกับ implementation มากเกินไป interface ทำให้ contract ที่ repository พึ่งพาชัด และ fake เก็บ path/header เพื่อ assert ได้ตรงๆ

3. ไม่ให้ dynamic ไหลเกิน boundary

JsonApi ยังคืน dynamic JSON เพราะเป็น transport boundary แต่ RemoteTaskRepository ต้องแปลงเป็น WmsTask หรือ throw ก่อนคืน Store ห้ามส่ง map ดิบไป widget

4. Header ต่อ command

authorization เป็น header กลางใน ApiClient ส่วน Idempotency-Key เป็น metadata ของ command จึงส่งจาก repository ผ่าน optional headers การ merge ต้องกำหนด policy ว่า caller override header ใดได้ ในระบบจริงควรห้าม override Authorization โดยไม่ตั้งใจ

5. Recording fake

class RecordingJsonApi implements JsonApi {
  String? postedPath;
  Map<String, String>? postedHeaders;
}

test จึงพิสูจน์ได้ว่า repository ส่ง route และ key ถูก โดยไม่ทดสอบ internals ของ http package

6. Interface ไม่ควรกลายเป็น God client

อย่าเพิ่ม upload, websocket, token refresh, cache, toast และ navigation ลง interface เดียวเพียงเพราะเรียกว่า API แยก protocol capability ตามเหตุผลที่เปลี่ยน

7. Contract test อีกชั้น

repository test ใช้ fixture เร็ว แต่ไม่พิสูจน์ว่า .NET serialize casing ตรงจริง ควรมี integration smoke test เรียก server จริงเพิ่มโดยไม่แทนที่ unit test

8. Checkpoint

เปิด task_repository_test.dart แล้วชี้ให้ได้ว่า test ใดพิสูจน์ path, idempotency header และ correlation response ถ้า assert ไม่ครอบ boundary นั้น seam ยังไม่ให้คุณค่า
