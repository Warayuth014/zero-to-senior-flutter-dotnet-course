PDA UX: หน้าจอ operational ต้องลด accidental mutation, สื่อ state ระหว่างรอ และยังใช้งานได้เมื่อข้อมูลเก่า/เครือข่ายไม่สมบูรณ์

1. Confirm intent

กด “เสร็จงาน” เปิด dialog ที่ระบุ task และเส้นทางจาก→ไป ผู้ใช้ต้องเห็นสิ่งที่จะเปลี่ยน ไม่ใช้ dialog ทั่วไปว่า “ยืนยันหรือไม่” เพราะหลาย task หน้าตาคล้ายกัน

2. mounted หลัง await

ทั้งรอ dialog และรอ complete อาจมี navigation/dispose จึงตรวจ mounted ก่อนใช้ context แสดง SnackBar ป้องกัน lifecycle exception

3. Loading หลายระดับ

  • initial: spinner กลางหน้า
  • refresh: linear progress เหนือ list เดิม
  • mutation: spinner ในปุ่ม task นั้น

ภาพที่ต่างกันบอกชนิดงานและลดการเดาของผู้ใช้

4. Pull to refresh

RefreshIndicator ใช้ AlwaysScrollableScrollPhysics เพื่อ pull ได้แม้รายการสั้น แต่ยังมี app bar refresh สำหรับอุปกรณ์/ผู้ใช้ที่ gesture ไม่สะดวก

5. Error with data

เมื่อมี cached snapshot อย่าแทนทั้งหน้าด้วย error แสดง MaterialBanner พร้อม reload และคง list ให้ดู แต่ mutation ที่อันตรายอาจต้อง disable หาก freshness เกิน threshold

6. Semantics และ touch target

Card ใส่ semantics ที่อ่าน task/from/to และปุ่ม Material มี touch target มาตรฐาน บน PDA ถุงมือควรทดสอบขนาดจริง ไม่สรุปจาก desktop browser

7. Stable identity

ValueKey(task.id) ช่วย Flutter reconcile card ถูกตัวเมื่อรายการถูกลบ/เรียงใหม่ โดยเฉพาะเมื่อ card มี focus, animation หรือ local transient state

8. Widget test

Test ต้องพิสูจน์ว่าแตะปุ่มแล้วยังไม่ complete จนกดยืนยัน จากนั้น list ว่างและ SnackBar มี correlation ID นี่ทดสอบ behavior ที่ผู้ใช้เห็น ไม่ผูกกับ widget tree ภายในเกินจำเป็น
