Per-entity busy: งาน TASK-001 กำลัง complete ไม่ควรล็อกปุ่มของ TASK-002 และไม่ควรเปิดให้ TASK-001 ส่ง command ซ้ำ

1. ปัญหา global loading

boolean loading เดียวทำให้ refresh, initial read และทุก mutation ขัดกัน ผู้ใช้ปิดงานคนละรายการพร้อมกันไม่ได้ และ progress ที่ card บอกไม่ได้ว่ารายการใดกำลังทำ

2. Set ของ identity

if (_busyTaskIds.contains(task.id)) return;
_busyTaskIds.add(task.id);
try { ... } finally {
  _busyTaskIds.remove(task.id);
}

Set ทำหน้าที่ทั้ง invariant และ state สำหรับ UI โดย key ต้องเป็น stable domain identity

3. Guard ต้องอยู่ Store

ปุ่ม disabled เป็น UX แต่ event อาจมาจาก scanner, keyboard shortcut หรือสอง widget Guard เชิง correctness จึงต้องอยู่ action method ไม่ใช่แค่ปุ่ม

4. finally สำคัญ

success, known error, unknown outcome หรือ parser error ต้องปลด busy เสมอ มิฉะนั้น task ติด disabled จน restart แต่ห้ามปลดก่อน reconciliation จบเพราะผู้ใช้อาจส่งซ้ำระหว่างตรวจสอบ

5. Parallel commands

lab ยอม complete คนละ task พร้อมกัน Backend/ธุรกิจจริงอาจต้อง serialize ตาม pallet, order หรือ location ให้เปลี่ยน lock key เป็น aggregate identity ไม่จำเป็นต้องเป็น task id เสมอ

6. UI feedback

card ที่ busy แสดง spinner ขนาดคงที่และ disable ปุ่มเฉพาะ card ทำให้ operator รู้ว่า intent ถูกบันทึกแล้ว โดยรายการอื่นไม่ถูกแช่แข็ง

7. Test double action

ใช้ pending Completer ให้ request แรกค้าง เรียก complete ซ้ำ แล้ว assert repository ถูกเรียกหนึ่งครั้ง Test ต้องตรวจระหว่าง request ไม่ใช่หลัง request จบเร็วแล้ว

8. Senior question

ถ้า task สองตัวแตะ pallet เดียวกัน คุณจะใช้ busy key อะไร และ backend ป้องกัน conflict อย่างไร Client guard เป็นเพียงชั้นแรก ไม่แทน concurrency control ฝั่ง server
