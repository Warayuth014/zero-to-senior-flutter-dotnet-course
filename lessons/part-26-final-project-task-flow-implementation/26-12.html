.NET companion: Backend lab บางโดยตั้งใจ แต่ต้องมี semantics มากพอให้ Flutter ฝึก idempotency, correlation และ typed response จริง

1. Endpoint contract

POST /api/WMS/mobile_tasks/{id}/complete
Idempotency-Key: TASK-001-...

{ id, alreadyCompleted, replayed, correlationId }

2. Validate ก่อน mutation

ถ้าไม่มี key คืน 400 ก่อนแตะ task เพื่อบังคับ contract อย่า fallback สร้าง key ฝั่ง server เพราะ retry จาก client จะอ้าง intent เดิมไม่ได้

3. Correlation ID

ใช้ HttpContext.TraceIdentifier และคืนทั้ง response header/body เพื่อให้ client แสดง support code ได้ ระบบจริงควรรับ trace context จาก gateway/OpenTelemetry และไม่เชื่อ arbitrary correlation header โดยไม่ validate

4. Atomic section ใน lab

lock(taskGate) ครอบการตรวจ command, เปลี่ยน task และบันทึก response เพื่อสาธิต atomic intention เพราะ ConcurrentDictionary หลาย operation ต่อกันไม่ได้ atomic ทั้งชุด

5. Replay

key เดิมคืน cached response พร้อม replayed: true ไม่ลอง remove task อีกรอบ ส่วน key ใหม่ของ task ที่ปิดแล้วคืน alreadyCompleted: true เพื่อให้ operation converge

6. ข้อจำกัดหลาย instance

in-memory dictionary และ process lock ใช้ไม่ได้เมื่อ restart หรือ scale หลาย server Production ต้องใช้ durable shared store/unique constraint และ transaction ตามคอร์ส .NET

7. Security boundary

idempotency ไม่ใช่ authorization ผู้ใช้ยังต้องมีสิทธิ์ปิด task, server ต้อง validate current state/warehouse/ownership และ audit actor ห้ามถือว่ามี key แล้วทำได้ทุกอย่าง

8. HTTP experiment

ส่ง complete ด้วย key เดิมสองครั้ง ครั้งสองต้อง 200, id เดิม และ replayed=true จากนั้นใช้ key ใหม่กับ task เดิมต้องได้ alreadyCompleted=true ทั้งสามกรณีไม่มี side effect เพิ่ม
