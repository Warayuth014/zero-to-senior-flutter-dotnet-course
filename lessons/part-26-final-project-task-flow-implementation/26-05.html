Strict model: ค่า default ช่วย UI บางกรณี แต่การเปลี่ยน task id ว่างเป็น '' หรือ status ใหม่เป็น waiting จะซ่อน contract regression และอาจสั่งงานผิดรายการ

1. Required fields

WmsTask.fromJson ใช้ helper requiredText ตรวจ id/from/to/status ว่ามีข้อความหลัง trim ถ้าเสียให้โยน FormatException ที่ boundary

2. Enum ต้อง fail visibly

final status = TaskStatus.values.where((value) => value.name == rawStatus);
if (status.isEmpty) throw FormatException(...);

หาก backend เพิ่ม cancelled client รุ่นเก่าต้องรู้ว่าตนไม่รองรับ ไม่ควรแสดงเป็น waiting แล้วเปิดปุ่ม complete

3. Tolerant reader ใช้เมื่อไร

optional presentation field เช่น description อาจ default เป็น '-' ได้ แต่ identity, quantity, unit และ state ที่กำหนด mutation ต้องเข้ม เลือกตามผลกระทบ ไม่ใช่ใช้กฎเดียวทุก field

4. Error translation

repository จับ FormatException แล้วแปลงเป็น ApiException ที่อธิบายว่า response task ไม่ถูกต้อง Store จึงไม่ต้องรู้รายละเอียด parser

5. List item type

ห้ามใช้ whereType<Map<String,dynamic>>() หากรายการผิดแล้วถูกทิ้งเงียบ เพราะ totalCount กับรายการจะไม่ตรงและ data loss ถูกซ่อน Lab ตรวจทุก item และ fail ทั้ง response

6. Contract fixtures

tests ต้องมีทั้ง valid JSON, required field ว่าง, unknown enum และ item ไม่ใช่ object เพิ่ม fixture จาก response จริงเมื่อพบ production incident เพื่อกัน regression

7. Versioning

ถ้า backend ต้องเพิ่ม state ใหม่ ให้กำหนด rollout: client รองรับ enum ก่อน, backend เริ่มส่งทีหลัง หรือใช้ capability/version contract อย่าหวังว่า default จะทำให้ backward compatible

8. Checkpoint

ลองเปลี่ยน status ใน API เป็น cancelled แอปควรแสดง contract error ที่ชัด ไม่แสดง task เป็น waiting นี่คือ failure ที่ปลอดภัยกว่า data corruption
