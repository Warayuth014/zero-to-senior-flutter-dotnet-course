Navigation test มีสองชั้น: pure Store test พิสูจน์ business step/reset/resume ส่วน widget test พิสูจน์ว่า gesture/button ผูกกับ Navigator และแสดง route ถูกจริง

1. Observer บันทึก route

class RecordingObserver extends NavigatorObserver {
  final pushed = <Route<dynamic>>[];
  void didPush(Route route, Route? previous) {
    pushed.add(route);
    super.didPush(route, previous);
  }
}

2. Assert UI ปลายทาง

โดยมากการ tap แล้ว pumpAndSettle และหา title/key เฉพาะปลายทางแข็งแรงกว่า assert concrete Route class เพราะพิสูจน์ผลที่ผู้ใช้เห็นและยอมให้ refactor routing

3. Result จาก route

await tester.tap(find.text('Choose pallet'));
await tester.pumpAndSettle();
await tester.tap(find.text('PLT-001'));
await tester.pumpAndSettle();
expect(find.text('Selected: PLT-001'), findsOneWidget);

4. Back semantics

ทดสอบ app-bar back, system back/handlePopRoute และ business Back แยกกัน หาก step > 0 ต้องลด stepก่อน pop route ดังที่ flow_navigation_test ตรวจ Store; เมื่อมี unsaved draft ต้องถามตาม policy

5. Replacement และ logout

หลัง login pushReplacement ต้องไม่ย้อนกลับ login; หลัง logout clear stack/session และ back ไม่เข้าหน้า protected ใช้ observer หรือ attempt pop แล้ว assert route ปัจจุบัน

6. Deep link/arguments

test valid/invalid entity ID, missing argument และ unauthorized destination Router ต้องแสดง fallback/error ไม่ force unwrap แล้ว crash และ refresh state ที่จำเป็นก่อน render

7. Bottom navigation

ทดสอบสลับแท็บแล้ว state ที่ควรคงยังอยู่ และ flow ที่ต้อง clear ถูก reset ตัวอย่างจริงวน destinations หลายค่าและยืนยัน receiving draft ถูกล้างเหมือนกันทุกแท็บ

8. Navigation matrix

push, pop, cancel, result, replacement, logout clear-stack, system back, deep link, tab switch และ async callback หลังออกจากหน้า โดยไม่มี duplicate route หรือ context หลัง unmount
