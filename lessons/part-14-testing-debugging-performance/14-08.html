Finder ควรยึด semantic intent: ใช้ text/label/key ที่ผู้ใช้หรือ contract รู้จัก หลีกเลี่ยง find.byType(TextField).at(3) เพราะลำดับ widget เปลี่ยนง่าย

1. Finder ที่พบบ่อย

find.text('Save Changes')
find.byKey(const ValueKey('receiving-scan-input'))
find.byIcon(Icons.close_rounded)
find.widgetWithText(TextField, 'Pallet barcode')

2. จำกัดขอบเขต

final dialog = find.byType(AlertDialog);
final cancel = find.descendant(
  of: dialog,
  matching: find.text('Cancel'),
);
await tester.tap(cancel);

จำเป็นเมื่อ sheet และ dialog มีคำว่า Cancel เหมือนกัน ดังตัวอย่าง settings tests ของโปรเจกต์จริง

3. Input เหมือนผู้ใช้

await tester.enterText(scanInput, 'PLT-0006');
await tester.testTextInput.receiveAction(TextInputAction.done);
await tester.pump();

ถ้า production ใช้ onSubmitted การเรียก controller method ตรง ๆ ไม่พิสูจน์ wiring ของ input

4. Tap ที่มองเห็น

ก่อน tap item ที่อยู่ใต้ fold ใช้ ensureVisible หรือ scrollUntilVisible แล้ว pump; warning ว่า hit test ไม่ได้มักหมายถึง test ไม่ได้ทำ gesture แบบผู้ใช้จริง ไม่ควรปิด warning เพื่อให้ผ่าน

5. Drag และ layout assertion

final top = tester.getTopLeft(scanner).dy;
await tester.drag(results, const Offset(0, -260));
await tester.pump();
expect(tester.getTopLeft(scanner).dy, top);

นี่คือ assertion เชิงพฤติกรรมที่ดีกว่า golden ทั้งหน้าสำหรับข้อกำหนด “scanner ต้อง fixed”

6. Matcher จำนวน

ใช้ findsOneWidget, findsNothing, findsNWidgets ให้ตรง contract ระวัง text ซ้ำใน offstage route หรือ lazy list และใช้ skipOffstage: false เฉพาะเมื่อกำลังทดสอบสิ่งนั้นจริง

7. Keys เป็น public test API

ตั้ง stable ValueKey ตามความหมาย เช่น confirm-receive หรือรวม entity ID สำหรับแถว dynamic ห้ามใช้ index เป็น identity เมื่อ reorder/filter ได้ Keys ยังช่วยรักษา State ถูกแถว

8. Accessibility bonus

Finder ที่ยึด semantic label กระตุ้นให้ UI มี label สำหรับ icon/scanner action ซึ่งช่วยทั้ง test และผู้ใช้ screen reader; เพิ่ม semantics test สำหรับ action สำคัญเมื่อเหมาะสม
