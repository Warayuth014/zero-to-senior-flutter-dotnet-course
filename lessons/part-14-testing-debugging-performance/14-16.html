รายการลื่นมาจากการทำงานเท่าที่มองเห็น: lazy build, stable identity, pagination, thumbnail decode ตามขนาด และไม่คำนวณหนักใน itemBuilder

1. Lazy list

ListView.builder(
  itemCount: items.length,
  itemBuilder: (_, index) => PartRow(
    key: ValueKey(items[index].id),
    part: items[index],
  ),
)

อย่าใช้ Column สร้าง 1,000 แถวพร้อมกัน และ key ต้องเป็น entity ID ไม่ใช่ index เมื่อ filter/reorder

2. itemExtent/prototype

ถ้าแถวสูงคงที่ ระบุ itemExtent/itemExtentBuilder หรือ prototype เพื่อลด layout work แต่ห้ามบังคับเมื่อข้อความไทยหลายบรรทัดทำความสูงเปลี่ยนจนตัดข้อมูล

3. Pagination และ search

debounce query, cancel/ignore stale response และโหลดหน้าถัดไปก่อนถึงท้ายเล็กน้อย กัน request ซ้ำด้วย single-flight; แสดง retry ต่อ page โดยไม่ทิ้งข้อมูลเดิมทั้งหมด

4. Image memory

Image.network(
  url,
  width: 72,
  height: 72,
  cacheWidth: 144,
  cacheHeight: 144,
  fit: BoxFit.cover,
)

decoded RGBA ใหญ่กว่าไฟล์ JPEG มาก จึงต้องลด decode size และใช้ versioned URL/cache policy ตาม Part 13

5. Future ต่อแถว

อย่าสร้าง Future resolve URL ใหม่ใน itemBuilder/build ทุก scroll/rebuild เก็บ resolved URI ใน model/repository cache หรือ State ที่ผูก key และแสดง error/loading เฉพาะ thumbnail

6. งาน CPU

parse JSON ใหญ่, sort/filter ซับซ้อน และ image transform ไม่ควรบล็อก UI isolate ระหว่าง scroll วัดก่อนย้าย isolate เพราะ serialization/copy ก็มีต้นทุน และให้ server paginate/filter เมื่อ dataset ใหญ่จริง

7. Performance test

สร้าง fixture 100/1,000 รายการ, scroll ด้วย gesture เดิมใน profile mode เก็บ missed frames, build/layout/raster time และ peak memory ทดสอบภาพ cache cold/warm และ device RAM ต่ำที่ใช้งานจริง

8. Correctness ระหว่าง optimize

หลังปรับต้องยังรักษา state ต่อ entity เมื่อ reorder, ไม่มีรูปผิดแถว, search ไม่โดน stale result, pagination ไม่ซ้ำ/ขาด และ accessibility/text scale ยังอ่านได้—ความลื่นที่ข้อมูลผิดไม่ใช่ optimization
