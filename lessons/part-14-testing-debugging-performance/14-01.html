1. Pyramid สำหรับ Flutter WMS

ฐานกว้างคือ pure Dart unit tests ของ model, parser, validator และ state transition; ชั้นกลางคือ repository/store/widget tests; ยอดเล็กคือ integration/end-to-end บนอุปกรณ์จริง ยิ่งสูงยิ่งใกล้ผู้ใช้แต่ช้าและวิเคราะห์สาเหตุยากกว่า

2. แบ่งตามคำถาม

ระดับพิสูจน์ตัวอย่าง
Unitlogic ถูกไหมbarcode normalization
Contractคุย API ตรงไหมJSON/multipart
WidgetUI ตอบ state ไหมscan → error
E2Eระบบจริงต่อกันไหมรับสินค้า 1 line

3. จากสอง codebase จริง

wmsapp/test/widget_test.dart ยังเป็น template ที่ comment ไว้ จึงไม่มี safety net ขณะที่ wms_absolute_mobile/test มี fake repositories, flow/navigation, scanner layout และ settings tests แสดงให้เห็นว่าการมี dependency seams ทำให้ทดสอบ workflow จริงได้โดยไม่เปิด server

4. Risk-based coverage

จัดลำดับจากความเสียหาย × โอกาสเกิด: การรับ serial ซ้ำ, qty เกิน, กด submit ซ้ำ, session หมดอายุ, timeout ที่ server ทำสำเร็จแล้ว และ navigation ทำ draft หาย ควรมี test ก่อนสี/animation ที่ผลกระทบต่ำ

5. Test portfolio

test/units/          // model, parser, reducer
test/repositories/   // fake HTTP + error mapping
test/widgets/        // one screen/state
test/flows/          // several widgets + fake repository
integration_test/    // real engine/device/backend sandbox

6. Deterministic by design

inject clock, random/ID generator, HTTP client, repository และ timer scheduler; freeze locale/timezone และสร้าง fixture ใน test เอง ห้ามพึ่ง API production, เวลาปัจจุบัน, network หรือ test order

7. CI gate

flutter analyze
flutter test --coverage
flutter test integration_test -d emulator-5554 // job แยก

unit/widget ต้องเร็วและบังคับทุก commit ส่วน device tests รันตามความเหมาะสม แต่ failure ต้องเก็บ screenshot/log/artifact ที่สืบได้

8. Definition of useful test

ชื่อบอก business behavior, Arrange/Act/Assert อ่านง่าย, ล้มด้วยเหตุผลเดียว, ไม่ sleep, cleanup resource, ไม่ผูก implementation detail และจับ regression ที่มีต้นทุนจริง
