อย่าให้ repository สร้าง HTTP client เองแบบซ่อน: inject http.Client หรือ transport interface เพื่อส่ง response ที่ต้องการและตรวจ request โดยไม่เปิด port/network จริง

1. Constructor injection

class ReceivingApi {
  ReceivingApi({required http.Client client, required Uri baseUri})
      : _client = client, _baseUri = baseUri;
  final http.Client _client;
  final Uri _baseUri;
}

composition root สร้าง client จริงครั้งเดียว ส่วน test ส่ง fake client

2. MockClient

final client = MockClient((request) async {
  expect(request.method, 'GET');
  expect(request.url.path, '/api/receiving/open');
  return http.Response('{"items":[],"total":0}', 200,
      headers: {'content-type': 'application/json'});
});

3. ตรวจ request semantics

assert path/query/headers/body ที่เป็น contract เช่น bearer token, page และ JSON field แต่ไม่ assert header ที่ library จัดให้เองทุกตัวหรือ JSON whitespace/order เพราะทำ test เปราะโดยไม่เพิ่มความมั่นใจ

4. Error matrix

for (final (status, expected) in [
  (400, Failure.validation),
  (401, Failure.sessionExpired),
  (409, Failure.conflict),
  (500, Failure.server),
]) { /* arrange response → assert mapped failure */ }

5. Socket กับ timeout

callback fake สามารถ throw SocketException, TimeoutException หรือคืน malformed body พิสูจน์ว่า adapter แปล error ไม่รั่ว exception รายละเอียด transport ไปถึง UI

6. Streaming/multipart

สำหรับ upload/download ใช้ custom BaseClient จับ BaseRequest และคืน StreamedResponse เพื่อทดสอบ progress/cancel/body stream ระวัง consume stream ได้ครั้งเดียว และไม่ล็อก multipart boundary ที่สุ่ม

7. Ownership

ถ้า repository รับ shared client มาจากภายนอก มันไม่ควร close เอง; composition root เป็นผู้ dispose ระบุ ownership ใน API ชัดเจนเพื่อไม่ให้ test หรือ request อื่นล้มตามกัน

8. ระดับที่ HTTP fake พิสูจน์ไม่ได้

ยังต้องมี .NET integration/contract tests สำหรับ routing, model binding, auth และ serialization จริง พร้อม sandbox end-to-end เล็กน้อย เพราะ MockClient พิสูจน์เพียง Dart adapter ตาม response ที่เราสร้างเอง
