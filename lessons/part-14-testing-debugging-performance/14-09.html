1. เปิดจาก harness

await tester.pumpWidget(MaterialApp(
  home: Builder(builder: (context) => ElevatedButton(
    onPressed: () => showConfirmDialog(context),
    child: const Text('open'),
  )),
));
await tester.tap(find.text('open'));
await tester.pumpAndSettle();

2. ตรวจ confirm/cancel

แยก test cancel แล้วไม่มี repository call, confirm แล้ว call ครั้งเดียว, barrier/back ตาม policy และ error แล้ว dialog ยังอยู่ อย่าทดสอบเฉพาะว่าข้อความแสดง

3. ค่าจาก Navigator.pop

bool? answer;
onPressed: () async {
  answer = await showDialog<bool>(...);
}
// tap Yes → pump → expect(answer, isTrue)

แยก null จาก barrier/back กับ false จากปุ่ม Cancel หาก business semantics ต่างกัน

4. Sheet ไม่ควรบีบ shell

connection_settings_sheet_test.dart เก็บ rect ของ bottom nav ก่อนเปิด sheet แล้ว assert rect เท่าเดิมหลังเปิด พิสูจน์ว่า route-level sheet ลอยทับ ไม่ใช่ panel ใน body ที่ดัน layout

5. Lazy content ใน sheet

await tester.scrollUntilVisible(
  find.byKey(const ValueKey('connection-url-preview')),
  140,
  scrollable: find.byType(Scrollable).first,
);

ListView สร้าง child เมื่อเข้า viewport จึงหา widget ใต้ fold ไม่เจอจน scroll

6. Nested routes

เมื่อ dialog อยู่เหนือ sheet คำว่า Delete/Cancel อาจซ้ำ ใช้ find.descendant(of: find.byType(AlertDialog), ...) และตรวจว่าหลังปิด dialog sheet ยังอยู่ หรือทั้งคู่ปิดตาม contract

7. Unsaved changes

test untouched close ไม่ถาม, edited close ถาม, cancel discard คงค่าที่พิมพ์, confirm discard ปิด และ system back ให้ผลเหมือนปุ่ม X นี่ครอบคลุม state มากกว่าถ่าย golden

8. Cleanup assertion

หลังปิด route ให้ assert dialog/sheet หาย, focus/controller ถูก dispose ไม่มี exception, underlying screen ยังอยู่ และ side effect เกิดจำนวนถูกต้องแม้ผู้ใช้แตะ confirm เร็วสองครั้ง
