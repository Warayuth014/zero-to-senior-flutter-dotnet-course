Fake ไม่ใช่ mock ทุก call: fake repository เป็น implementation ขนาดเล็กที่เก็บ state และจำลอง behavior ของ domain ทำให้ flow test อ่านเหมือนงานจริงและไม่เปราะตามลำดับ method ภายใน

1. ตัวอย่างจากโปรเจกต์จริง

test/fakes/fake_repositories.dart ของ wms_absolute_mobile มี FakeReceivingRepository, FakeTasksRepository และ FakeInventoryRepository คืนสำเนารายการ พร้อมบันทึก dispatchCallCount, pallet ที่ส่ง และเปลี่ยน status เมื่อเริ่ม/จบ pick

2. Interface คือ test seam

abstract interface class ReceivingRepository {
  Future<ReceivingPage> fetchOpen({String? q});
  Future<void> receive(ReceiveCommand command);
}

class FakeReceivingRepository implements ReceivingRepository { ... }

3. Fake ที่ควบคุมผลได้

class FakeReceivingRepository implements ReceivingRepository {
  Object? nextError;
  final received = <ReceiveCommand>[];

  Future<void> receive(ReceiveCommand command) async {
    if (nextError case final error?) throw error;
    received.add(command);
  }
}

test ตั้ง success/error และตรวจ command สุดท้ายโดยไม่รู้ว่า store เรียก helper กี่ชั้น

4. Copy ป้องกัน test หลอก

fake ควรคืน List.of หรือ immutable collection ไม่ให้ production code แก้ fixture เดิมโดยบังเอิญ การจำลอง server state ต้องชัดว่า mutation ใดเป็นผลของ command จริง

5. Fake latency

final response = Completer<ReceivingPage>();
Future<ReceivingPage> fetchOpen(...) => response.future;

// test assert loading ก่อน แล้ว response.complete(...)

Completer ทำให้กำหนดลำดับ race ได้แน่นอน ดีกว่า Future.delayed ที่ทำ test ช้าและ flaky

6. Fake ต้องรักษา contract

ถ้า real repository trim/throw/paginate แต่ fake ไม่ทำ flow test อาจผ่านผิด ๆ ใช้ contract test suite เดียวรันกับ fake และ adapter จริงในระดับเหมาะสม หรือจำลองเฉพาะ semantics ที่ scenario อาศัย

7. เมื่อไรใช้ mock

mock เหมาะกับ interaction ที่เป็นผลลัพธ์เอง เช่น audit event ต้องถูกส่งหนึ่งครั้ง แต่ state/result มักตรวจด้วย fake/stub ง่ายกว่า หลีกเลี่ยง verify ลำดับ call ภายในที่ refactor แล้ว behavior ไม่เปลี่ยน

8. Cleanup

สร้าง fake ใหม่ต่อ test, ใช้ addTearDown(store.dispose), ไม่แชร์ mutable singleton และเพิ่ม failure controls เช่น unauthorized/conflict/timeout เพื่อครอบคลุม error path จริง
