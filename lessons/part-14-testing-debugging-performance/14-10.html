1. เวลาในเทสต์ไม่เดินเอง

ในเทสต์ widget เวลาหยุดนิ่งจนกว่าจะสั่งให้เดิน — นี่คือสิ่งที่ทำให้เทสต์เร็วและทำซ้ำได้ แต่ก็เป็นที่มาของความสับสนทั้งหมดในบทนี้
คำสั่งทำอะไร
pump()วาดหนึ่งเฟรม โดยเวลาเดินไปน้อยที่สุด
pump(Duration(seconds: 1))เดินเวลาไปหนึ่งวินาที แล้ววาดหนึ่งเฟรม
pumpAndSettle()วาดซ้ำจนกว่าจะไม่มีเฟรมที่รออยู่ — สูงสุด 10 วินาที

สิ่งที่ต้องเข้าใจคือ pumpAndSettle ไม่ได้แปลว่า “รอให้ทุกอย่างเสร็จ” แต่แปลว่า “วาดไปเรื่อย ๆ จนกว่าจะไม่มี animation ที่ต้องวาดต่อ”

2. งานที่ pumpAndSettle รอ และไม่รอ

รอไม่รอ
animation ของการเปิด dialogFuture ที่ยังไม่ resolve
animation ของการเปลี่ยนหน้าคำขอ HTTP ที่ยังไม่ตอบ
การเลื่อนที่มีความหน่วงตัวจับเวลาที่ตั้งไว้นานกว่า 10 วินาที
AnimatedContainer, Heroงานที่รอ I/O จริง

คอลัมน์ขวาคือที่มาของความเข้าใจผิดที่พบบ่อยที่สุด — pumpAndSettle ไม่ได้ทำให้ Future เสร็จ มันแค่วาดเฟรมไปเรื่อย ๆ

// Future ใน MockClient เสร็จทันที (เป็น microtask) จึงทำงานได้
await tester.pumpWidget(wrap(MockClient((_) async => http.Response(...))));
await tester.pumpAndSettle();
expect(find.byKey(const Key('pallet-PLT-001')), findsOneWidget);   // ผ่าน

// แต่ Future ที่ค้างอยู่ pumpAndSettle ก็ไม่ช่วย
final gate = Completer<http.Response>();
await tester.pumpWidget(wrap(MockClient((_) => gate.future)));
await tester.pumpAndSettle();
expect(find.byKey(const Key('pallet-PLT-001')), findsNothing);     // ยังไม่มา

3. เมื่อไหร่ใช้ pump() เปล่า ๆ

เมื่อต้องการดูสถานะระหว่างทาง

testWidgets('เปิดแอปที่มี session เดิม ต้องไม่เห็นหน้าเข้าสู่ระบบเลย', (tester) async {
  await storage.write(validSession);

  await tester.pumpWidget(AuthLabApp(dependencies: deps));
  // ยังไม่ settle — ดูเฟรมแรกก่อน
  await tester.pump();

  expect(find.byKey(const Key('splash')), findsOneWidget);
  expect(find.byKey(const Key('login-screen')), findsNothing);

  await tester.pumpAndSettle();
  expect(find.byKey(const Key('home-shell')), findsOneWidget);
});

เทสต์นี้จับอาการ “เห็นหน้าเข้าสู่ระบบแวบหนึ่ง” จาก 8.6 ซึ่ง pumpAndSettle อย่างเดียวมองไม่เห็น เพราะกว่าจะ settle เสร็จ หน้าจอก็เปลี่ยนไปแล้ว

สถานะที่ต้องใช้ pump() ถึงจะเห็น
วงหมุนระหว่างโหลดครั้งแรก
ปุ่มที่จางลงระหว่างส่งคำสั่ง
หน้าจอเริ่มต้นก่อนตัดสินใจว่าจะไปไหน
แถบความคืบหน้าระหว่างอัปโหลด
testWidgets('ระหว่างโหลดครั้งแรกเห็นวงหมุน', (tester) async {
  final gate = Completer<http.Response>();
  await tester.pumpWidget(wrap(MockClient((_) => gate.future)));
  await tester.pump();

  expect(find.byKey(const Key('initial-loading')), findsOneWidget);

  gate.complete(http.Response(zoneBody([palletJson('PLT-001')]), 200, ...));
  await tester.pumpAndSettle();
});

4. เมื่อไหร่ใช้ pump พร้อมเวลา

กรณีทำไม pumpAndSettle ใช้ไม่ได้
SnackBarมันปิดตัวเองใน 4 วินาที — settle จะรอจนปิด (14.9)
ตัวจับเวลาที่วนซ้ำไม่มีวันหยุด — settle จะค้างจนหมดเวลา
animation ที่วนไม่รู้จบCircularProgressIndicator หมุนตลอด
await tester.pump();                                    // เริ่มปรากฏ
await tester.pump(const Duration(milliseconds: 750));    // ให้ animation จบ
expect(find.text('ปิด T-1 สำเร็จ'), findsOneWidget);
ข้อผิดพลาดที่พบบ่อยที่สุด — ใช้ pumpAndSettle ในจอที่มี CircularProgressIndicator แสดงอยู่ แล้วเทสต์ค้างสิบวินาทีก่อนล้มด้วยข้อความ pumpAndSettle timed out

5. fakeAsync เมื่อเวลานานเกิน

เมื่อต้องทดสอบสิ่งที่เกิดในอีกสิบนาที pump ทำไม่ได้เพราะเทสต์ widget รอไม่ไหว

test('หลุดแล้วเริ่มถามซ้ำ ต่อกลับได้แล้วหยุด', () {
  fakeAsync((async) {
    ...
    final callsBefore = repository.fetchCalls;
    async.elapse(const Duration(seconds: 45));
    expect(repository.fetchCalls, callsBefore + 3);
    ...
    // หลังหยุดแล้วต้องไม่มีคำขอเพิ่มจากตัวจับเวลาอีก
    async.elapse(const Duration(minutes: 5));
    expect(repository.fetchCalls, callsAfterReconnect);

    store.dispose();
    async.flushTimers();
  });
});
เมธอดทำอะไร
async.elapse(duration)เดินเวลาไป ตัวจับเวลาที่ถึงกำหนดจะทำงาน
async.flushMicrotasks()ให้ Future ที่พร้อมแล้วทำงาน
async.flushTimers()รันตัวจับเวลาที่เหลือทั้งหมด — ใช้ตอนจบเพื่อไม่ให้ค้าง

fakeAsync ใช้กับ test ธรรมดา ไม่ใช่ testWidgets — ถ้าต้องการทั้งสองอย่างพร้อมกัน ให้ใช้ tester.pump(duration) แทน ซึ่งเดินเวลาในเทสต์ widget ได้เหมือนกัน

// ในเทสต์ widget เดินเวลาแบบนี้
await tester.pump(const Duration(seconds: 30));

6. pumpAndSettle ค้างเพราะอะไร

pumpAndSettle timed out
สาเหตุวิธีตรวจแก้
มี CircularProgressIndicator อยู่ดูว่าจอกำลังโหลดอยู่ไหมให้ Future เสร็จก่อน หรือใช้ pump
มี Timer.periodic ทำงานอยู่ค้นหา Timer.periodic ในโค้ดที่เกี่ยวข้องใช้ pump พร้อมเวลา
animation ที่วนไม่รู้จบดู repeat() ใน AnimationControllerเหมือนกัน
Future ค้างอยู่จริงตรวจว่า Completer ถูก complete หรือยังcomplete ก่อน settle

วิธีหาที่เร็วที่สุดคือดูว่ามีอะไรค้างอยู่

// พิมพ์รายการ timer ที่ยังทำงานอยู่
debugPrint(tester.binding.transientCallbackCount.toString());

7. รูปแบบที่ใช้ได้เสมอ

// 1. สร้างจอ แล้วดูสถานะแรก
await tester.pumpWidget(wrap(screen));
await tester.pump();
expect(find.byKey(const Key('initial-loading')), findsOneWidget);

// 2. ปล่อยให้ข้อมูลมา แล้วดูสถานะสุดท้าย
gate.complete(response);
await tester.pumpAndSettle();
expect(find.byKey(const Key('pallet-list')), findsOneWidget);

// 3. กด แล้วดูผล
await tester.tap(find.byKey(const Key('hold-PLT-001')));
await tester.pumpAndSettle();
expect(find.text('ล็อกแล้ว'), findsOneWidget);

สามขั้นนี้ครอบคลุมเทสต์ widget ส่วนใหญ่ และเป็นโครงที่ lab ใช้ทุกไฟล์

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
หา widget ไม่เจอทั้งที่ควรมียังไม่ได้ pump พอเพิ่ม pumpAndSettle
ทดสอบวงหมุนไม่ได้pumpAndSettle ตั้งแต่แรกใช้ pump() ก่อน
pumpAndSettle timed outมีอะไรวนไม่หยุดใช้ pump พร้อมเวลา
เทสต์ค้างเป็นนาทีfakeAsync มี timer ค้างตอนจบasync.flushTimers()
ผลไม่ตรงเพราะ Future ยังไม่เสร็จลืมให้ microtask ทำงานawait Future<void>.delayed(Duration.zero)
เทสต์ผ่านบ้างไม่ผ่านบ้างpump จำนวนครั้งไม่แน่นอนใช้ Completer คุมจังหวะ

แถวสุดท้ายเป็นอาการที่แย่ที่สุด — เทสต์ที่ผ่านบ้างไม่ผ่านบ้างจะถูกเมินในที่สุด และเมื่อถูกเมิน มันจะไม่จับบั๊กอีกเลย

9. แบบฝึกหัด

เทสต์นี้ล้มด้วย pumpAndSettle timed out

testWidgets('โหลดเสร็จแล้วเห็นรายการ', (tester) async {
  await tester.pumpWidget(wrap(TaskScreen(store: store)));
  await tester.pumpAndSettle();

  expect(find.byKey(const Key('task-list')), findsOneWidget);
});

จอนั้นมี Timer.periodic ที่โหลดข้อมูลใหม่ทุกสิบวินาที หาทางแก้

แนวคำตอบ

สาเหตุชัดเจน — Timer.periodic ทำให้มีงานรออยู่ตลอด pumpAndSettle จึงไม่มีวัน settle

มีสามทางแก้ และคุณภาพต่างกันมาก

ทางผล
เปลี่ยนเป็น pump() หลาย ๆ ครั้งทำงานได้ แต่เปราะ — ต้องเดาว่ากี่ครั้ง
ใช้ pump(Duration)ดีขึ้น แต่ยังผูกกับเวลาที่ต้องรู้
ทำให้ช่วงเวลาส่งเข้ามาได้ดีที่สุด
class TaskStore extends ChangeNotifier {
  TaskStore(this.repository, {this.pollInterval = const Duration(seconds: 10)});

  final Duration pollInterval;
}
// ในเทสต์ ปิดการถามซ้ำไปเลย
final store = TaskStore(repository, pollInterval: Duration.zero);
// หรือให้ยาวมากจนไม่ทำงานระหว่างเทสต์
final store = TaskStore(repository, pollInterval: const Duration(hours: 1));

ทางนี้ดีที่สุดเพราะแก้ที่สาเหตุ ไม่ใช่ที่อาการ และได้ประโยชน์อย่างอื่นตามมาด้วย

ได้อะไรเพิ่ม
ทดสอบเรื่องการถามซ้ำได้ตรง ๆ ด้วย fakeAsync
ปรับความถี่ตามสภาพเครือข่ายได้ในอนาคต
ปิดได้เมื่อผู้ใช้อยู่ในหน้าที่ไม่ต้องการข้อมูลสด

เป็นรูปแบบเดียวกับที่ 9.8 สรุปไว้ — อะไรที่ทำให้เทสต์เดาไม่ได้ ให้เปิดช่องรับเข้ามาพร้อมค่าเริ่มต้น

LiveTaskStore ใน lab ทำแบบนี้อยู่แล้ว ซึ่งเป็นเหตุผลที่เทสต์ 23 ข้อของมันรันจบใน 0.3 วินาที

LiveTaskStore({

10. สรุป

  • เวลาในเทสต์หยุดนิ่งจนกว่าจะสั่งให้เดิน
  • pumpAndSettle รอ animation ไม่ได้รอ Future
  • ใช้ pump() เมื่อต้องการดูสถานะระหว่างทาง
  • ใช้ pump(Duration) กับ SnackBar และตัวจับเวลา
  • ใช้ fakeAsync เมื่อต้องเดินเวลาเป็นนาที
  • ถ้า pumpAndSettle ค้าง ให้แก้ที่สาเหตุด้วยการรับช่วงเวลาเข้ามา
