Scanner test ต้องพิสูจน์ทั้ง input และ ergonomics: barcode scanner อาจทำตัวเป็น keyboard wedge จึงต้องทดสอบ focus, Enter, duplicate guard และ layout บน viewport PDA ไม่ใช่เพียงเรียก submit method ตรง ๆ

1. ส่งข้อมูลผ่าน TextInput

final input = find.byKey(const ValueKey('receiving-scan-input'));
await tester.enterText(input, 'PLT-0001');
await tester.testTextInput.receiveAction(TextInputAction.done);
await tester.pump();

พิสูจน์ว่า onSubmitted wiring ทำงานเหมือน scanner ที่ส่ง Enter

2. Hardware key path

ถ้า screen ฟัง HardwareKeyboard/Focus โดยตรง ให้ส่ง key down/up ตามลำดับและรวม buffer จน Enter; แยก test repeated key, modifier, CR/LF และ event หลัง focus หลุด อย่าพึ่งเฉพาะ enterText

3. Focus contract

หลัง success/error/dialog ปิด ตรวจว่า scanner focus กลับมาตาม workflow ใช้ FocusNode ที่ inject/หา widget แล้ว assert hasFocus หลัง pump ห้าม request focus ทุก build เพราะทำ keyboard/focus แข่งกัน

4. Duplicate และ rapid scan

await scan(tester, 'SER-001');
await scan(tester, 'SER-001');
expect(repo.receives, hasLength(1));
expect(find.textContaining('already scanned'), findsOneWidget);

เพิ่ม case ตัวพิมพ์/ช่องว่าง และ scan ตัวที่สองขณะ request แรก pending

5. Fixed scanner layout

scanner_layout_test.dart เก็บตำแหน่ง input ก่อน drag รายการ แล้ว assert y เท่าเดิม นี่พิสูจน์ข้อกำหนดหน้าปฏิบัติงานว่าช่อง scan ไม่เลื่อนหายบนจอ 390×560

6. Overflow และ keyboard inset

ทดสอบ viewport เตี้ย, text scale ใหญ่ และ viewInsets.bottom จำลอง soft keyboard; assert tester.takeException() เป็น null และ action สำคัญยังเข้าถึงได้โดยไม่ให้ทั้งหน้า scroll ผิดโครง

7. Scan state machine

part → serial → pallet ต้องยอมรับเฉพาะชนิดปัจจุบัน Test scan ผิดขั้น, server reject, back หนึ่ง step, resume draft และ reset เมื่อออก flow โดยแยก pure state tests จาก widget wiring

8. Device test

widget test จำลอง keyboard ได้ แต่ต้อง smoke test กับ scanner รุ่นจริง: suffix Enter/Tab, key timing, IME, screen off/on, Bluetooth disconnect และการสแกนเร็วต่อเนื่องใน build profile/release
