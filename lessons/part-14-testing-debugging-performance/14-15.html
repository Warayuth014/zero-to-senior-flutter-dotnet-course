อย่า optimize จากความรู้สึก: เปิด rebuild tracking ใน profile/debug, ทำ interaction เดิม แล้วลดเฉพาะ subtree ที่ rebuild/paint แพงโดยยังรักษาความถูกต้อง

1. ทำไมทั้งหน้าถูก build

setState rebuild subtree ใต้ State; ChangeNotifier.notifyListeners ทำให้ listener ทุกตัว build ถ้า shell ฟัง Store ก้อนใหญ่ การเปลี่ยน progress จุดเดียวอาจ rebuild menu/list/image ทั้งหน้า

2. วัดก่อน

ใช้ DevTools Track Widget Builds, performance timeline และ debug flags เฉพาะงานพัฒนา นับ build ระหว่างพิมพ์ scan, progress tick และ polling response แล้วดู frame time ไม่ใช่นับอย่างเดียว

3. แยก ownership

ValueListenableBuilder<UploadProgress>(
  valueListenable: upload.progress,
  builder: (_, value, __) => ProgressBar(value),
)

ให้ progress widget ฟังเฉพาะ progress; list ฟัง immutable items; theme/session อยู่ระดับ shell ไม่รวมทุก state ใน notifier เดียวโดยไม่มี selector

4. const และ stable inputs

ใช้ const กับ subtree คงที่, ส่ง immutable value และหลีกเลี่ยงสร้าง list/map/callback ใหม่โดยไม่จำเป็น แต่ const ไม่ช่วยหาก parent logic/selector แจ้งเปลี่ยนค่าจริงทุกครั้ง

5. Selector และ equality

select เฉพาะ taskCount/isLoading แล้ว rebuild เมื่อ value เปลี่ยนด้วย equality ที่ถูกต้อง อย่า mutate list เดิมแล้วหวัง selector เห็น หรือสร้าง wrapper ใหม่ที่ equality เป็น identity ทุก notification

6. แยก widget เพื่ออะไร

แยกเมื่อมี state/lifecycle/rebuild boundary หรือช่วยอ่าน/test ไม่แยกทุก Container เป็น class โดยไม่มีประโยชน์ ตรวจว่าการย้าย method ไม่ได้เปลี่ยน ownership FocusNode/Controller ผิดที่

7. RepaintBoundary

ช่วยแยก paint ของ animation/complex card ที่ส่วนอื่นคงที่ แต่เพิ่ม layer/memory อย่าใส่ทุกแถวโดยไม่วัด ใช้ repaint rainbow/timeline เปรียบเทียบก่อนหลังบน device profile

8. Regression guard

มี widget test ยืนยัน behavior และ performance benchmark/integration trace สำหรับ hotspot ที่สำคัญ เก็บ scenario/device/profile เดิมเพื่อเปรียบเทียบ ไม่ใช้เวลา debug test เป็น production budget
