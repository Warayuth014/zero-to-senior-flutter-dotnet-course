UnloadSessionSheet เป็น stateful workflow: state ไม่ได้มีแค่ loading แต่มี session, line ที่เลือก, serial/qty ที่กรอก, สถานะราย line และการคืน pallet ซึ่งต้องเปลี่ยนอย่างมีลำดับ

1. State inventory

แกนหลักประกอบด้วย _session, _partStatus, selected item, scanned serials, qty controllers, loading/error และ scanner focus การเขียนรายการ state ก่อนแก้โค้ดช่วยเห็น invariant และ cleanup ที่ต้องทำ

2. Open session transition

idle → opening → active
             ↘ error

scan pallet แล้วเรียก open-session; เมื่อสำเร็จสร้าง status map จาก items/confirmedLineIds และ reset input เก่าทั้งหมด ไม่ให้ข้อมูลของ pallet ก่อนหน้ารั่วเข้ามา

3. Per-line state

lineId เป็น key ของ _partStatus ค่า PENDING/CONFIRMED บอกว่างานใดเหลืออยู่ ห้าม key ด้วย partId เพราะ part เดียวกันอาจอยู่หลาย lot และต้องยืนยันแยกกัน

4. Selection state

scan part จะเลือกรายการ pending ที่ตรง หากมีหลาย lot ควรให้ผู้ใช้เลือก เมื่อเปลี่ยน selection ต้อง clear serials และ qty ของ selection เดิมเพื่อป้องกันค่าค้างถูกส่งกับ line ใหม่

5. Confirm transition

selected → validating → confirming → reloading → active
                      ↘ validation/error

ระหว่าง confirming ต้อง lock input/double tap และเก็บ context ที่แน่นอน ไม่อ่าน selected item ที่อาจเปลี่ยนระหว่าง await

6. Authoritative reload

หลัง confirm ต้อง reload session เพราะ partial unload อาจสร้าง remainder line ด้วย lineId ใหม่ การ mark local line ว่า confirmed อย่างเดียวจึงไม่พอและอาจทำให้ progress ผิด

7. Lifecycle safety

controller, timer และ focus node ต้อง dispose; callback หลัง await ตรวจ mounted; scanner keyboard events ต้องไม่ทำงานขณะ dialog/return flow เปิด มิฉะนั้น event ซ้ำอาจเปลี่ยน state ที่ไม่คาดคิด

8. Refactor target

ย้าย workflow ไปเป็น reducer/controller ที่มี event เช่น PalletScanned, PartSelected, SerialAdded, ConfirmRequested, SessionReloaded แล้ว widget มีหน้าที่ render state และส่ง event เท่านั้น
