Unload มีสองช่วงคนละธุรกรรม: นำของออกจาก pallet ให้เป็น unloaded inventory ก่อน แล้วจึง load ของนั้นเข้าบasket อย่ารวมสองขั้นจน retry และ audit แยกไม่ได้

1. Unload menu

UnloadMenuScreen เป็นทางแยกไป UnloadScreen สำหรับถอดของออกจาก pallet และ LoadToBasketScreen สำหรับนำยอดที่ unload แล้วเข้าบasket ชื่อปุ่มและคำอธิบายต้องทำให้ลำดับนี้ชัด

2. Open unload flow

เส้นทาง unload เริ่ม scan pallet แล้วเรียก open session จากนั้นแสดงรายการ part/lot ที่อยู่บน pallet ให้ operator ยืนยันทีละ line session เป็นขอบเขต audit ของงานครั้งนั้น

3. Load-to-basket source

LoadToBasketScreen เรียก GET /basket/unloaded-items เพื่ออ่านของที่พร้อมย้าย ไม่ควรใช้รายการจาก unload screen โดยตรง เพราะ server คือแหล่งจริงและงานอาจถูกทำต่อจากคนละเครื่อง

4. Select part and lot

เมื่อ scan part อาจพบหลาย UnloadedItem ที่ lot ต่างกัน UI ต้องให้เลือก line ที่ต้องการอย่างชัดเจน การเลือกตัวแรกอัตโนมัติเสี่ยงลงยอดผิด lot แม้ partId จะตรง

5. Serial vs quantity

รายการ serial-controlled ให้สะสม serial ที่อยู่ในชุดอนุญาตและห้ามซ้ำ ส่วน non-serial รับจำนวนด้วยตัวเลขที่มากกว่า 0 และไม่เกิน qtyRemaining ก่อนเปิดปุ่มยืนยัน

6. Load request

POST /basket/load
{
  "partId": item.partId,
  "lotNumber": item.lotNumber,
  "basketId": basketId,
  "qty": qty,
  "operatorId": operatorId,
  "serialNumbers": serials
}

part+lot ระบุ inventory bucket ส่วน basketId ระบุปลายทาง

7. Refresh after mutation

เมื่อ load สำเร็จให้ clear selection/controller แล้วโหลด unloaded items ใหม่ เพราะ backend อาจลด qtyRemaining, เติม basketId, รวมรายการ หรือปิดรายการเมื่อยอดเป็นศูนย์

8. Failure boundaries

ทดสอบ basket ไม่พบ, part หลาย lot, serial ไม่อยู่ในรายการ, qty เกินคงเหลือ, double tap, timeout หลัง server commit และผู้ใช้ออกจากหน้าระหว่าง request โดยต้องไม่ทำยอด unload ซ้ำ
