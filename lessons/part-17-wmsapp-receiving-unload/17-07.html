Receipt + pallet เป็น compound operation: UIส่ง palletIdพร้อม scan-part แต่ responseแยกผล receiptกับ palletError จึงต้องรองรับ partial successโดยไม่รับสินค้าซ้ำ

1. Validate qty

qtyต้อง >0และไม่เกิน remaining/ordered; serial itemต้องมี serial countเท่ากับ qtyและเป็น partปัจจุบัน Non-serialใช้ manual qtyที่ clampแล้วแต่ validateซ้ำก่อน request

2. Pick pallet

_pickPallet(defaultPalletId: _lastPalletId)เปิด sheetรับ palletก่อน submitทุกครั้ง ใช้ memoryลดการ scanซ้ำแต่ผู้ใช้ยังยืนยัน/เปลี่ยนได้

3. Payload

POST /receiving/scan-part
{ poId, partId, lineId, qtyReceived,
  operatorId, serialNumbers: [], palletId }

serial non-requiredส่ง empty listตาม backend contract

4. Success

ไม่มี palletError: เก็บ assigned summaryโดย part+pallet, จำ last pallet/type, clear form/serial, reload POและแสดง success หาก lineเดิมรับหลายครั้ง summaryบวก qty

5. Pallet failure

receiptถูกบันทึกแล้วแต่ assignmentล้ม: insert ReceiptLineResponseใน resumed pending listและแจ้ง warning Retryต้องเรียก assignPallet(lineIds) ไม่เรียก scanReceiptPartซ้ำ

6. Auto close/over

poItemStatus == OVERแสดง warning; autoClosed/poStatus/closeMessageบอก documentปิด ต้อง refresh/ออก flowตาม responseและกัน callbackเก่าดำเนินต่อ

7. Atomicity decision

backendตั้งใจให้ partial successหรือควร transaction receipt+assignmentต้องตัดสินตามธุรกิจ หาก partialถูกต้อง responseควร typed explicit เช่น receiptCommitted=true, palletAssignment=failedและมี operation ID

8. Retry tests

normal, receipt reject, timeout ambiguity, pallet partial failure, retry assign success/fail, double tap/idempotency, over receive/conflictและ auto close โดย assertว่า receipt endpointไม่ถูกเรียกซ้ำหลัง partial success
