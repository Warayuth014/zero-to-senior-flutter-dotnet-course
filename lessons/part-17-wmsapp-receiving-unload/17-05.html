ScanPartScreen คือ state machine แม้ยังเขียนเป็น fields: ต้องอ่านเป็น phases—idle → resolving line/lot → scanning serialหรือ qty → choosing pallet → submitting → assigned/pending/auto-closed

1. State clusters

controllers/focus 3 กลุ่ม Part/Serial/Pallet, current PO, scanning item, serial list/manual qty, last pallet memory, assigned lines, resumed pending lines, loadingและ timed scan status หาก fieldใดไม่ resetตาม transitionจะข้ามข้อมูลระหว่าง item

2. Initialize/resume

_currentPo = widget.poและ copy po.pendingLinesเข้า resumed list ทำให้กลับมาแก้ pallet assignmentจาก receiptเดิมได้โดยไม่ submitรับซ้ำ

3. Resolve Part

getPartLines(partId)
→ filter line.poId == currentPo.poId
→ choose condition if many
→ choose lot if many
→ resolve POItem by lot.id

4. Two input branches

ถ้า serialRequire focus serialและ qtyมาจากจำนวน serial; ถ้าไม่ requireแสดง manual qty editorพร้อม +/- และ clamp 0..remaining ทั้งคู่รวมกลับที่ _confirmPart

5. Pallet memory

_lastPalletId/_lastPalletTypeช่วย default palletถัดไปและรวม assigned summary แต่ต้อง clearเมื่อ typeขัด, assignmentล้ม, POเปลี่ยนหรือ userยกเลิก เพื่อไม่ส่ง palletเก่าโดยไม่ตั้งใจ

6. Submit outcomes

ReceiptLineResponseอาจ normal success, OVER warning, palletErrorให้เข้ารายการ pending หรือ autoClosedแสดง dialog/ปิด flow Outcomeเหล่านี้ควรเป็น sealed resultแทน flagsที่ผสมกันได้หลายแบบ

7. Timer/lifecycle

scan statusมี Timer 5sและ ScrollController animateไป serialที่เกี่ยว ต้อง cancel timer/dispose controllers/focus/scrollและ mounted guard post-frame callbacks ป้องกัน leak/setStateหลังออกหน้า

8. Refactor seam

สร้าง ReceivingFlowState + reducer/commands, ScanValidator, PalletAssignmentPolicyและ repository แล้วให้ widgetถือเฉพาะ controllers/focus การแยก phaseชัดจะกำจัด state combinationที่เป็นไปไม่ได้
