PO preview คือ decision context: ผู้ใช้ต้องเห็น supplier, status และยอด ordered/received/remainingต่อ line ก่อนเริ่มรับ แต่ข้อมูลนี้ยังเป็น snapshotและ serverต้อง revalidateตอน command

1. POResponse

เก็บ poId, supplierId/name, status, createdAt, itemsและ pendingLines โดย parser fallbackวันที่ invalidเป็น DateTime.now() ซึ่งทำให้ข้อมูลเสียดูเหมือนปัจจุบัน ควร fail/nullableพร้อม diagnostics

2. POItem

identity idทำหน้าที่ line/lot ID, มี part/owner/brand/description/image, serialRequire, qtyสามค่า, status, condition, lotNumber/expiredDate

3. PoInfoCard

สรุป header document/supplier/status/date ช่วยแยกเอกสารก่อน scan ใช้ status badge/color presentation แต่ไม่ควร encode business transitionจากสี

4. PoItemsList

renderรายการและ quantity progressต่อ item จุดตรวจคือ listยาวต้อง lazy/scrollเหมาะกับ PDA, stable keyด้วย item.idและ thumbnailไม่ resolve futureซ้ำทุก rebuild

5. Step indicator

PoStepIndicatorประกอบ dots/linesเพื่อสื่อขั้น PO → Part → Pallet เป็น static contextในหน้า Scan PO ไม่ใช่ state machine source of truth อย่าใช้ตำแหน่ง visualกำหนด allowed command

6. Status logic

if (po.status != 'RECEIVED') show Start;
else show completed banner;

unknown/lowercase/new statusจะเปิด Startโดย default เสี่ยงกว่า enum/allowed-setแบบ fail closed

7. Snapshot freshness

หลัง ScanPart routeกลับ reload PO แต่ระหว่างเปิดหน้าคนอุปกรณ์อื่นอาจรับ lineเดียวกัน Serverต้อง check remaining/versionและตอบ conflict; UI refresh/แจ้งผู้ใช้แทนถือ snapshotเป็น lock

8. Contract tests

itemsว่าง/หลาย lot, qty partial/complete/over, serial/non-serial, pendingLines, unknown status, invalid date, null image/lotและ Thai text พร้อม snapshotจาก .NETจริง
