Unload/Basket contract เชื่อม inventory สองสถานะ: model ต้องรักษา session line, part+lot, serial และยอด remaining เพื่อให้ทุก mutation ตรวจย้อนหลังและ retry ได้อย่างปลอดภัย

1. UnloadApi

สามคำสั่งคือ open-session, confirm-unload และ return-pallet-to-asis แต่ละคำสั่งควรแปลง non-2xx, timeout และ malformed JSON เป็น error ที่ต่างกันเพื่อให้ UI ตัดสินใจ refresh/retry ถูก

2. UnloadSession

UnloadSession มี sessionId, pallet, status, items และ confirmedLineIds Session ID ต้องถูกส่งคืนทุก mutation เพื่อให้ backend ตรวจ ownership/version ของ workflow

3. UnloadItem

lineId แยก part+lot แต่ละบรรทัด; partId อย่างเดียวไม่พอ โค้ดปัจจุบันอนุมาน serialRequire จาก serialNumbers.isNotEmpty ซึ่งคลุมเครือเมื่อ serial-controlled item มีข้อมูลเสียหรือรายการว่าง ควรส่ง boolean จาก API โดยตรง

4. Confirm contract

serial item ส่ง serialNumbers และอาจไม่ต้องส่ง qty; non-serial ส่ง qtyUnloaded และ empty serial list DTO ฝั่ง .NET ควร validate รูปแบบแบบ mutually exclusive ตาม serialRequire ของ inventory จริง ไม่เชื่อ client

5. BasketApi

GET  /basket/unloaded-items
POST /basket/load

endpoint แรกให้ snapshot ของ staging inventory ส่วน endpoint หลังย้ายจำนวน/serial ไป basket และควรคืนยอด/สถานะใหม่ที่ตรวจสอบได้

6. UnloadedItem

model มี partId, lotNumber, qtyUnloaded, qtyLoaded, qtyRemaining, basketId, unloadLineIds และ serialNumbers ทำให้ตามที่มาจาก unload หลาย line ได้ แต่ key ใน UI ต้องอย่างน้อย part+lot และอาจต้อง condition/site เพิ่มตาม backend

7. Load response

LoadToBasketResponse ควรสื่อผลธุรกรรม, basket ปลายทาง, จำนวน accepted/rejected และ remaining อย่าง explicit หาก API คืนเพียง message UI ต้อง reload เสมอและวิเคราะห์ partial result ได้ยาก

8. Contract checklist

ใช้ enum/status ที่รองรับ unknown, decimal policy เดียวกันทั้ง Dart/.NET, UTC timestamps, correlation/idempotency key, version/concurrency token, typed problem details และ JSON fixtures ที่ทดสอบทั้งสองฝั่ง
