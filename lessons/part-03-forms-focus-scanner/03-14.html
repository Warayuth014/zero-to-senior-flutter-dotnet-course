1. Acceptance criteria

  • Enterและปุ่ม submitใช้ commandเดียว
  • canonical pallet trim+uppercase; serialรักษา caseตาม policy
  • busyป้องกัน requestซ้ำและ fieldถูก disable
  • previewไม่เท่ากับ commit ต้อง confirmก่อน mutation
  • error/duplicate/network uncertainมี stateและ feedbackต่างกัน
  • หลังทุก recoverable outcome focusกลับช่องที่ถูกตาม state
  • backend commitรับ operation ID/idempotency key

2. State model

sealed class ScanState { const ScanState(); }
class AwaitingScan extends ScanState { const AwaitingScan(); }
class Validating extends ScanState {
  const Validating(this.code); final String code;
}
class Review extends ScanState {
  const Review(this.preview); final ScanPreview preview;
}
class Committing extends ScanState {
  const Committing(this.preview); final ScanPreview preview;
}
class Succeeded extends ScanState {
  const Succeeded(this.receipt); final ScanReceipt receipt;
}
class Failed extends ScanState {
  const Failed(this.message, {required this.retryable});
  final String message; final bool retryable;
}

3. Transition map

AwaitingScan --submit valid---> Validating
Validating  --preview ok-----> Review
Validating  --reject/error--> Failed --ack/retry--> AwaitingScan
Review      --cancel--------> AwaitingScan
Review      --confirm------> Committing
Committing  --success------> Succeeded --next--> AwaitingScan
Committing  --conflict-----> Failed/Reconcile

กำหนด eventที่อนุญาตต่อ state ป้องกัน Enterระหว่าง Reviewหรือ commitซ้ำ

4. Controller command

Future<void> submitRaw(String raw) async {
  if (state is! AwaitingScan) return;
  final code = normalizePallet(raw);
  final error = validatePallet(code);
  if (error != null) return emit(Failed(error, retryable: false));

  emit(Validating(code));
  try {
    final preview = await repository.preview(code);
    if (state case Validating(code: final current) when current == code) {
      emit(Review(preview));
    }
  } catch (e) {
    emit(Failed(mapError(e), retryable: true));
  }
}

UIไม่ยิง APIใน build/widget field และ controllerตรวจ current stateกัน stale response

5. UI + focus effects

Awaiting/Failedแสดง ScanBox enabled; Validating/Committingแสดง busy; Reviewแสดง summary+confirm; Succeededแสดง receipt/next ใช้ listenerแยก one-shot effectsจาก render state: accepted haptic, error flash, dialogหรือ focus request post-frame อย่าเล่นเสียงใน build

6. Commit และ idempotency

Future<void> confirm() async {
  final review = state;
  if (review is! Review) return;
  final operationId = uuid.v4();
  emit(Committing(review.preview));
  try {
    final receipt = await repository.commit(
      review.preview, operationId: operationId,
    );
    emit(Succeeded(receipt));
  } on Conflict catch (e) {
    emit(Failed(e.message, retryable: false));
  }
}

Retry requestเดิมต้อง reuse operationId; เริ่ม business operationใหม่จึงสร้าง IDใหม่

test('second submit is ignored while validating', () async {
