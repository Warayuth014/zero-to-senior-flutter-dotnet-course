Keyboard-wedge scanner แปลงบาร์โค้ดเป็นชุด key events เช่น PALLET-001 แล้วต่อ suffix Enter/Tab ดังนั้น TextField ที่ focus อยู่รับค่าเหมือนคนพิมพ์เร็วมาก ไม่ได้คุยกับกล้องหรือ Bluetooth API โดยตรง

1. เส้นทาง event

Barcode → Scanner firmware/profile
        → key events: P A L L E T - 0 0 1 ENTER
        → OS focused control
        → Flutter TextField controller
        → onSubmitted
        → normalize/validate/use case

2. Scanner profile สำคัญ

ตั้ง prefix/suffix, keyboard locale, character delay, symbology และการเปิด soft keyboardที่ตัวอุปกรณ์ บางรุ่นส่ง CR, LF, Enter, Tab หรือไม่มี terminator ต้องบันทึก profile ที่รองรับใน deployment ไม่แก้ Flutter อย่างเดียวแล้วคาดว่าทุกเครื่องเหมือนกัน

3. TextField-first approach

ถ้า wedge ส่งข้อความ + Enter ปกติ TextField/onSubmitted ง่ายที่สุด รองรับ manual fallback, selection และ accessibility Absolute ScanBox ใช้ autofocus, monospace, hint “scan then Enter” และปิด field เมื่อ busy

4. Raw key events ใช้เมื่อจำเป็น

ใช้ KeyboardListener/HardwareKeyboard เมื่อ scanner ไม่ควรลง TextField, ต้องจับ function key หรือประกอบ buffer ตาม timing แต่ต้องจัด key down/up, modifier, IME, focus และ platform differences เอง เริ่มด้วย TextField ก่อนถ้า contract รองรับ

5. Timing ไม่ใช่ identity ที่เชื่อถือได้

การเดาว่า “พิมพ์เร็วกว่า 30ms = scanner” เปราะต่อเครื่อง/โหลด/การตั้ง delay ผู้ใช้ยัง paste ได้ ถ้าต้องแยก source ให้ใช้ SDK ของ vendor, prefixเฉพาะ หรือ scanner profile ที่รับรอง Timing ใช้เป็น heuristic เสริม ไม่ใช่ security

6. Focus และ route transitions

Wedge ส่งไป control ที่ focus ณ ขณะนั้น Dialog/menu อาจขโมย focus จึงต้อง disable scan ระหว่าง overlay, คืน focusหลังปิด และแสดง target ปัจจุบันชัด เช่น “สแกน Location ปลายทาง” เพื่อป้องกัน barcode ถูกตีความเป็นคนละ entity

7. แบบฝึกหัด

Scanner รุ่นหนึ่งเติม Tab แทน Enter ทำให้ focus ไปปุ่มถัดไปแต่ไม่ submit ควรแก้อย่างไร?

แนวคำตอบ

ทางหลักคือกำหนด deployment profile ให้ suffix Enter สม่ำเสมอ หากควบคุมไม่ได้ให้รองรับ Tab/RawKey อย่างมี test และ consume event เฉพาะ scan field พร้อม manual submit fallback อย่าเพิ่ม onChanged auto-submit เพราะไม่รู้ว่าข้อมูลจบเมื่อไร

8. จุดพลาด

อย่าสมมติ barcode ทุกชนิดเป็น uppercase ASCII หรือไม่มี leading zero ต้องตกลง contract กับ backend/label/scanner และเก็บ raw value เพื่อ diagnostics โดยไม่ log ข้อมูลอ่อนไหวเกินจำเป็น
