Quantity เป็นจำนวนเชิงโดเมน ไม่ใช่ข้อความ ขั้นตอนคือรับ String → parseอย่างปลอดภัย → validate min/max/precision → สร้าง numeric value แล้วให้ backendตรวจ invariantล่าสุดอีกครั้ง

1. Integer parsing

int? parseQuantity(String raw) {
  final value = int.tryParse(raw.trim());
  if (value == null || value <= 0) return null;
  return value;
}

ใช้ tryParse ไม่ให้ FormatExceptionหลุดถึง UI และอย่าแปลง invalidเป็น 0 เพราะ 0อาจมีความหมายต่างกัน

2. Input formatter เป็น UX ชั้นแรก

TextFormField(
  keyboardType: TextInputType.number,
  inputFormatters: [FilteringTextInputFormatter.digitsOnly],
  validator: (raw) => validateQty(raw, remaining: remaining),
)

Formatterลดความผิดพลาดแต่ paste/hardware/logicยังต้อง parse+validate และต้อง import package:flutter/services.dart

3. Range และ remaining

Validate min ≤ qty ≤ remaining จาก snapshotปัจจุบัน แต่ serverอาจเปลี่ยน stockพร้อมกันจึงต้องตรวจซ้ำ UIควรแสดง “เหลือ 7” ใกล้ field และเมื่อ Conflictให้ refresh/reconcileไม่กล่าวโทษผู้ใช้

4. Decimal และหน่วย

ถ้าหน่วยอนุญาตทศนิยม อย่าใช้ doubleกับค่าที่ต้องแม่นตรงโดยไม่กำหนด scale ใช้ decimal package/จำนวนหน่วยย่อย integer/contractเดียวกับ .NET ระบุ locale decimal separator และ rounding policy ห้าม parse 1,5 แบบเดาสุ่ม

5. Stepper + manual edit

Absolute quantity selector มีปุ่มลด/เพิ่มพร้อม min/max และ dialogกรอกเลข ปุ่มเหมาะกับปรับเล็กน้อย manualเหมาะกับจำนวนมาก แต่ผลจากทั้งสองทางต้องวิ่งผ่าน validator/commandเดียว ไม่ให้ onSetรับนอกช่วงเพราะ dialog parseได้อย่างเดียว

6. Leading zero และ empty state

Quantity 005 parseเป็น 5ได้ แต่ UIอาจ normalizeแสดง “5” หลัง submit ขณะ fieldว่างไม่ควรเท่ากับ 0 แยก null/not entered จาก zero และกำหนดว่า zeroห้ามหรือใช้ clear operation

7. แบบฝึกหัด

remaining=12 ผู้ใช้ส่ง “ 013 ”, “1.5”, “abc”, “” และ “05” ผลควรเป็นอะไรสำหรับ integer piece?

เฉลย

013→13แต่ rejectเกิน remaining; 1.5→parse fail; abc→parse fail; empty→required; 05→5และผ่าน ทั้งหมดต้องมีข้อความเฉพาะและไม่ยิง APIจน local validationผ่าน

8. จุดพลาด

อย่าใช้ controller text เป็นจำนวนระหว่าง business calculationทุกจุด Parseครั้งเดียวเป็น int/decimal typed value แล้วส่งต่อ มิฉะนั้น trim/invalid/rangeจะกระจายและได้ผลต่างกันระหว่างหน้าจอ
