FocusNode เป็น handle ของ focus tree ไม่ใช่แค่คำสั่งเปิด keyboard Workflow scanner ต้องกำหนดว่า field ใดรับ keystrokes ตอนแต่ละ state และคืน focus หลัง success/error/dialog อย่างตั้งใจ

1. Focus ownership

final _scanFocus = FocusNode(debugLabel: 'pallet-scan');

@override
void dispose() {
  _scanFocus.dispose();
  super.dispose();
}

สร้างหนึ่งครั้งตาม lifetime ของ State และส่งเข้า TextField ห้ามสร้างใน build เพราะ focus attachment เปลี่ยนระหว่างพิมพ์

2. autofocus กับ requestFocus

autofocus: true ขอ focus เมื่อ scope แสดงครั้งแรก เหมาะกับ route/dialog ที่ชัดว่ามี field หลัก ส่วน requestFocus ใช้เมื่อ state transition เลือก field ถัดไป เช่น scan part ผ่านแล้วไป serial ถ้า widget เพิ่ง mount ให้เรียก post-frame เพื่อรอ focus attachment

3. Post-frame เริ่ม workflow

@override
void initState() {
  super.initState();
  WidgetsBinding.instance.addPostFrameCallback((_) {
    if (mounted) _scanFocus.requestFocus();
  });
}

wmsapp ใช้รูปแบบนี้ใน CheckIn และ SerialSelect การตรวจ mounted ป้องกัน callback ที่ค้างหลัง route ถูกปิดก่อน frame

4. Focus ตาม state machine

อย่าให้ทุก field ตั้ง autofocus พร้อมกัน Owner ต้อง map state → focus target: scanPallet → palletFocus, scanPart → partFocus, scanSerial → serialFocus, quantity → qtyFocus แล้วเรียกหลัง transition/post-frame เพื่อให้ field ใหม่อยู่ใน tree

5. Dialog และคืน focus

Dialog สร้าง FocusScope ของตนและแย่ง focus เมื่อปิดให้ await result ก่อน แล้วถ้า context/state ยังอยู่จึงคืน focus ช่อง scanner การ request ก่อน dialog pop อาจถูก focus scope เก่ากินและ keyboard wedge ส่ง Enter ไปผิดที่

6. unfocus และ traversal

FocusScope.of(context).unfocus() ใช้ปิด editing เมื่อแตะพื้น/ก่อน action ที่ไม่ต้องรับ key ส่วน form manual ใช้ nextFocus กับ TextInputAction.next และกำหนด FocusTraversalGroup/order เมื่อลำดับ visual ไม่ตรง tree Scanner flow มัก request เป้าหมายโดยตรงเพื่อคงความเร็ว

7. แบบฝึกหัด

หลัง scan API สำเร็จ UI เปลี่ยนจากช่อง source เป็น destination แต่ requestFocus(destination) ทันทีแล้วไม่ติด เพราะอะไร?

แนวคำตอบ

setState ยังไม่สร้าง destination field/attach FocusNode จน frame ถัดไป ให้เปลี่ยน state แล้ว schedule post-frame ตรวจ mounted และ current state ก่อน requestFocus หาก destination มีอยู่แล้วแต่ dialog ยังเปิด ต้องรอ dialog ปิดก่อน

8. จุดพลาด

การ requestFocus ใน build ทำ side effect ทุก rebuild เกิด keyboard กระพริบ/ขโมย focus จากผู้ใช้ ให้ผูกกับ event/lifecycle/state transition และตรวจว่า current state ยังต้องการ target เดิมเมื่อ callback ทำงาน
