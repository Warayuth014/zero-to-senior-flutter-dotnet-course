กฎ ownership: ใครสร้าง resource คนนั้น dispose และ lifetimeต้องตรงกับสิ่งที่ resourceควบคุม Controller/FocusNode/Timer/Subscription/listenerที่หลุดจะทำให้ memory leak, callbackหลังปิดหน้า หรือใช้ objectที่ถูก disposeแล้ว

1. Lifecycle template

class _ScanState extends State<ScanPage> {
  final _controller = TextEditingController();
  final _focus = FocusNode();
  Timer? _duplicateTimer;

  @override
  void dispose() {
    _duplicateTimer?.cancel();
    _controller.dispose();
    _focus.dispose();
    super.dispose();
  }
}

2. External vs internal resource

ถ้า childรับ controller/focusจาก constructor ห้าม dispose เพราะ ownerอาจใช้กับ sibling/หลัง childหาย หาก optionalและ childสร้าง fallback ให้เก็บ fieldแยกเช่น _ownController แล้ว disposeเฉพาะของตน Absolute ScanBoxทำ patternนี้กับ controller

3. addListener ต้อง remove

สำหรับ controllerที่ตน dispose การ disposeจะล้าง listeners แต่ explicit removeช่วยเมื่อ listenerผูกกับ external objectหรือเปลี่ยน sourceใน didUpdateWidget Patternคือ unsubscribe old → assign new → subscribe new และ unsubscribeใน dispose

4. Dynamic maps

Cycle Count สร้าง controller/focusต่อ product codeใน Map เมื่อ listเปลี่ยนต้อง dispose entriesที่ถูกลบ และ disposeทุก valueตอนหน้าปิด ไม่ใช้ indexเป็น keyเพราะ reorderทำ resourceย้าย item ใช้ stable product/line ID

5. Timer และ async callback

Timer cancelใน disposeและ cancelตัวเก่าก่อน replace เช่น toast/flash ของ Absolute Callbackยังควรตรวจ mountedเพราะ cancelอาจแข่งกับ callbackที่เริ่มแล้ว Futureยกเลิกไม่ได้โดยอัตโนมัติจึงต้อง ignore stale result/cancel requestตาม owner

6. dispose order

หยุด producerก่อน consumer: cancel timer/subscription, remove listeners/observers, dispose controllers/notifiers แล้ว super.dispose() ตาม patternของ framework ห้าม setStateใน dispose และอย่าเรียก requestFocusหลัง nodeถูก dispose

7. แบบฝึกหัด

ScanFieldรับ optional controllerและ optional focusNode ควรจัด ownershipอย่างไร?

แนวคำตอบ

เก็บ _ownController/_ownFocus เฉพาะเมื่อ inputเป็น null, gettersเลือก externalหรือ own, disposeเฉพาะ own หาก widget updateจาก own→external/กลับกันต้องจัด create/disposeใน didUpdateWidget หรือออกแบบ contractไม่เปลี่ยน ownerกลาง lifetimeและ assert/documentไว้

8. จุดพลาด

Disposeสองครั้ง/child dispose resourceของ parentอันตรายพอ ๆ กับไม่ dispose อาการมักเกิดหลัง navigation/rebuildจึงหาได้ยาก เขียน ownershipใน constructor docและทดสอบ mount→replace→unmount
