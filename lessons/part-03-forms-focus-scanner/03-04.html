Keyboard configuration เป็น hint ให้ IME และเป็นส่วนของ flow แต่ไม่ใช่ security/validation Hardware scanner แบบ wedge อาจไม่สน keyboardType และส่งตัวอักษรพร้อม Enter เหมือนแป้นพิมพ์จริง

1. keyboardType

  • TextInputType.number: แนะนำแป้นตัวเลข
  • numberWithOptions(decimal: true): จำนวนทศนิยม
  • text/emailAddress/url: ปรับ IME ตามชนิด
  • visiblePassword: ปิด suggestion บางส่วนสำหรับรหัส

ผู้ใช้ยัง paste/keyboard hardware ค่าอื่นได้ จึงต้อง validate/input formatter เพิ่มตามกฎ

2. TextInputAction

TextField(
  textInputAction: TextInputAction.search,
  onSubmitted: (_) => submitScan(),
)

wmsapp ScanTextField ใช้ search action และ suffix button เรียก callback เดียวกัน Manual form หลายช่องใช้ next/done ตามลำดับ focus

3. onChanged, onSubmitted, onEditingComplete

onChanged ทุกการแก้ข้อความ, onSubmitted ส่งค่าหลัง IME action, onEditingComplete ควบคุม behavior เมื่อ editing จบ ปกติเลือก onSubmitted สำหรับ wedge ที่เติม Enter แล้ว route ทุก trigger (Enter/ปุ่ม) เข้า command เดียว

4. InputFormatters

inputFormatters: [
  FilteringTextInputFormatter.digitsOnly,
  LengthLimitingTextInputFormatter(6),
]

เหมาะกับ quantity integer แต่ barcode อาจมี dash/letter/leading zero อย่าใช้ digitsOnly กับ scanner โดยไม่รู้ symbology/contract Formatter ทำงานระหว่าง editing และต้องระวัง composing text

5. submit source เดียว

Future<void> _submitScan() async {
  if (_busy) return;
  final raw = _controller.text;
  // normalize → validate → execute
}

onSubmitted และปุ่มส่งเรียก method เดียว ไม่คัดลอก logicสองชุด มิฉะนั้น normalization/loading/error อาจต่างกัน

6. Keyboard dismissal

PDA ที่ใช้ wedge อาจต้องคง field focusแต่ไม่ต้องการ soft keyboard ขึ้น ทั้งนี้ขึ้นกับอุปกรณ์/SDK สามารถตั้ง scanner profile ไม่เรียก IME, ใช้ readOnly + hardware event เฉพาะเมื่อออกแบบครบ หรือจัด toggle manual input อย่าปิด keyboard จนผู้ใช้ไม่มี fallback

7. แบบฝึกหัด

ช่อง Quantity รับ Enter จาก scanner และปุ่ม Done จาก IME ต้องทำให้ผลเหมือนกันอย่างไร?

แนวคำตอบ

ใช้ controller + TextInputAction.done + onSubmitted เรียก submitQuantity(); ปุ่ม confirm เรียก command เดียวกัน Command อ่าน snapshot, parse/validate, lock busy และเปลี่ยน state ส่วน UI event ไม่ทำ logicแยก

8. จุดพลาด

อย่าเชื่อว่า numeric keyboard ส่งแต่เลข และอย่าใช้ keyboardType เป็น validation ผู้ใช้ paste, hardware keyboard/scanner หรือ accessibility input ได้ Backend ต้อง validate domain value อีกครั้งเสมอ
