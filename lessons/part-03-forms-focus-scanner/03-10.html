Dialog ยืนยันควรใช้กับ actionที่ย้อนคืนยากหรือมีผลกว้าง ไม่ใช่ทุก scan มิฉะนั้นทำลาย throughput และผู้ใช้จะกดตกลงโดยไม่อ่าน Confirmationต้องสรุปสิ่งที่จะ commit และคืน typed resultให้ owner

1. Typed dialog result

final confirmed = await showDialog<bool>(
  context: context,
  barrierDismissible: false,
  builder: (dialogContext) => AlertDialog(
    title: const Text('ยืนยันการย้ายสินค้า'),
    content: Text('$pallet → $destination\nจำนวน $quantity'),
    actions: [
      TextButton(
        onPressed: () => Navigator.pop(dialogContext, false),
        child: const Text('ยกเลิก'),
      ),
      FilledButton(
        onPressed: () => Navigator.pop(dialogContext, true),
        child: const Text('ยืนยัน'),
      ),
    ],
  ),
);
if (confirmed != true || !mounted) return;

2. Preview before commit

Flow CheckIn ของ wmsapp scan→preview API→destination dialog→pending pack แล้วจึงมี action commit การแยก preview/commitช่วยตรวจ pallet/location/quantityก่อน mutation และ dialogแสดงข้อมูลจาก serverไม่ใช่เดาจาก barcodeอย่างเดียว

3. Context ของ dialog

ใช้ dialogContext pop dialog ไม่ pop routeหลัก หลัง awaitตรวจ mounted/context.mountedก่อนใช้ owner context Dialog builderอาจอยู่คนละ navigatorเมื่อ nested navigator จึงกำหนด useRootNavigator ตาม architectureหากจำเป็น

4. Focus และ scanner ระหว่าง dialog

ปิด/lock scannerก่อนเปิด dialog ไม่ให้ Enterจาก triggerเดิมกดยืนยันโดยไม่ตั้งใจ กำหนด focusเริ่มที่ safe actionสำหรับ destructive command และหลัง dialogปิดคืน focusตาม current workflow state

5. Double confirmation ไม่แทน transaction

ผู้ใช้ยืนยันแล้ว serverยังต้องตรวจ authorization, concurrency, stock และ idempotency หาก network timeoutห้ามเปิด dialogใหม่แล้ว commitซ้ำทันที ต้อง query/retryด้วย operation keyหรือแสดงสถานะไม่แน่ชัดให้ reconcile

6. Dialog ใช้เมื่อไร

  • ควรใช้: delete, close task, moveผิดปลายทางแล้วกระทบ stock, bulk commit
  • อาจไม่ใช้: scan serialทีละชิ้นที่ undoได้และมี feedbackชัด
  • ใช้ review screenแทน: transactionหลายรายการ/ต้องตรวจรายละเอียดมาก

7. แบบฝึกหัด

ผู้ใช้สแกน serial 50 ชิ้น ควรถามยืนยันทุกชิ้นหรือจุดไหน?

แนวคำตอบ

validate/feedbackแต่ละ serialทันทีและให้ undo; ยืนยันครั้งเดียวตอน commit batchโดยสรุป part, expected/scanned count, pallet/destination และรายการผิดปกติ ลด modal fatigueแต่ยังมี controlก่อน mutationสำคัญ

8. จุดพลาด

อย่าให้ปุ่มยืนยันและยกเลิกชื่อกำกวม เช่น “OK/No” ใช้คำกริยาตรง action, แยก destructive style, รองรับ back/barrierตามความเสี่ยง และอย่าปิด dialogพร้อมยิง APIโดยไม่มี loading/duplicate guard
