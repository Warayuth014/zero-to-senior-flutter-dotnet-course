Record และ destructuring

Part -1: Dart Foundation for Flutter

Record รวมค่าหลายตัวเป็น value เดียวแบบมี static type โดยไม่ต้องสร้าง class เต็ม เหมาะกับผลลัพธ์ชั่วคราวที่มีความหมายเฉพาะจุด แต่ไม่แทน domain model ที่ต้องมี validation/behavior

1. Positional และ named record

(String, int) scanSummary(String raw) => (raw.trim(), raw.length);
({String palletId, bool continued}) suggestion() =>
    (palletId: 'PAL-001', continued: true);

final positional = scanSummary(' A ');
print(positional.$1);

final named = suggestion();
print(named.palletId);

ชื่อ field ของ named record เป็นส่วนของ type ส่วนชื่อ field positional ไม่ใช่ ระวังลำดับของ positional เมื่อมีหลายค่าชนิดเดียวกัน

2. Destructuring

final (barcode, length) = scanSummary(input);
final (:palletId, :continued) = suggestion();

for (final MapEntry(:key, :value) in quantities.entries) {
  print('$key = $value');
}

pattern ด้านซ้ายตรวจรูปและ bind ตัวแปรในครั้งเดียว ทำให้ไม่ต้องใช้ result.$1 กระจายไกลจากจุดคืนค่า

3. ตัวอย่างจริงสองแบบ

  • wmsapp/services/api/picking_api.dart คืน ({String palletId, bool continued})? จาก endpoint แนะนำ pallet เพราะมีเพียงสองค่าที่ใช้ร่วมกันเฉพาะ operation นี้
  • wms_absolute_mobile/.../warehouse_shell.dart มี (String, String) _titleSub() เพื่อคืน title/subtitle ของ screen พร้อมกัน

4. Record equality และ type

Record เปรียบเทียบเชิงโครงสร้าง: shape และค่าตรงกันถือว่าเท่ากัน Named field order ไม่สำคัญ แต่ชื่อสำคัญ

final a = (id: 'T1', done: false);
final b = (done: false, id: 'T1');
assert(a == b);

5. เมื่อควรสร้าง class แทน

  • ค่าข้ามหลาย layer หรือเป็น public API ระยะยาว
  • ต้อง validate, parse JSON, copyWith หรือมี behavior
  • ชื่อชนิดมีความหมายต่อโดเมน เช่น AuthSession
  • ต้องเพิ่ม field โดยไม่ทำลาย call site จำนวนมาก

Record เหมาะกับ local aggregate/return หลายค่า ส่วน ConnectionProfile, Task, Pallet ควรเป็น class

6. แบบฝึกหัด

ออกแบบผลการ normalize barcode ที่ต้องคืน normalized value และเหตุผลที่ reject แบบใดควรเป็น record และแบบใดควรเป็น class?

แนวคำตอบ

({String value, String? warning}) ใช้ได้ถ้าอยู่ helper เดียวและไม่มี behavior ถ้าผลมีหลาย status, error code, metadata และไหลข้าม layer ให้สร้าง BarcodeValidationResult หรือ sealed result เพื่อไม่ให้ record โตแบบไร้ชื่อ

7. จุดพลาด

อย่าคืน record positional 4–5 ค่า โดยเฉพาะชนิดซ้ำ เพราะ call site จะกลายเป็นการจำตำแหน่ง ใช้ named record หรือ class ที่สื่อโดเมน

8. สรุป

Record คือ typed tuple ที่ดีสำหรับ “ค่ากลุ่มเล็กและชั่วคราว”; destructuring ช่วยแกะค่าใกล้จุดใช้; domain object ที่มีอายุและกติกายังต้องเป็น class
