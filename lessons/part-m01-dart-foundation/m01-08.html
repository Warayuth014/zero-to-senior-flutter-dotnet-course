Generic เก็บความสัมพันธ์ของ type ระหว่าง input และ output เช่น Future<Task>, List<Task>, ApiResult<Task> ดีกว่าคืน Object/dynamic แล้วให้ caller เดา

1. Type parameter สื่ออะไร

class ApiResult<T> {
  const ApiResult.success(this.data) : error = null;
  const ApiResult.failure(this.error) : data = null;
  final T? data;
  final String? error;
}

Future<ApiResult<List<WmsTask>>> loadTasks() async { /* ... */ }

จาก signature คนอ่านรู้ทันทีว่า async, อาจสำเร็จ/ล้มเหลว และ success data เป็นรายการ Task โดยไม่เปิด body

2. Generic function

T? firstWhereOrNull<T>(Iterable<T> items, bool Function(T) test) {
  for (final item in items) {
    if (test(item)) return item;
  }
  return null;
}

นี่ใกล้กับ helper _firstOrNull<T> ใน warehouse_store.dart ความสัมพันธ์สำคัญคือชนิดที่รับเข้าและคืนออกเป็น T เดียวกัน

3. Constraint

abstract interface class Entity { String get id; }

T? byId<T extends Entity>(Iterable<T> items, String id) =>
    firstWhereOrNull(items, (item) => item.id == id);

extends Entity ทำให้ body เรียก item.id ได้โดยไม่ cast และยังรักษา subtype จริงไว้ในค่าที่คืน

4. Variance ที่ต้องรู้พอใช้งาน

List<Dog> ไม่ควรถูกใช้เป็น list ที่เพิ่ม Animal ใดก็ได้ มิฉะนั้นอาจใส่ Cat ลง list ของ Dog Dart มี runtime checks บางกรณี แต่หลักปฏิบัติคืออย่า cast collection เพื่อฝืน type ให้ map/copy ไปชนิดเป้าหมายอย่างชัดเจน

5. Generic ใน Flutter

  • State<WarehouseShell> ทำให้ widget มีชนิด WarehouseShell
  • ValueNotifier<ThemeMode> จำกัด value เป็น ThemeMode
  • FutureBuilder<Task> ทำให้ snapshot data เป็น Task?
  • helper _segmented<T> ใน connection settings รับ Map<T,String> และ ValueChanged<T> โดยรักษาชนิด choice

6. เมื่อ generic มากเกินไป

ถ้า type parameter ไม่สร้างความสัมพันธ์ที่มีประโยชน์ หรือมี parameter 4–5 ตัวจน call site อ่านไม่ออก อาจเหมาะกับ class/domain type เฉพาะมากกว่า Generic เป็นเครื่องมือรักษา type ไม่ใช่เป้าหมายของ abstraction

7. แบบฝึกหัด

เขียน cache ที่เก็บ model ตาม id โดยไม่เสีย type และกำหนด constraint ว่าทุก model ต้องมี id

แนวคำตอบ
class EntityCache<T extends Entity> {
  final Map<String, T> _items = {};
  T? get(String id) => _items[id];
  void put(T item) => _items[item.id] = item;
}
