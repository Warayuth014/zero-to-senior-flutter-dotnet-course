Pattern matching และ switch expression

Part -1: Dart Foundation for Flutter

Pattern matching ไม่ใช่ switch syntax สวยขึ้นอย่างเดียว มันตรวจ shape, type และค่าพร้อม bind ตัวแปร จึงมีประโยชน์มากตรง JSON boundary และ workflow state

1. Switch expression กับ exhaustive cases

String taskTypeLabel(TaskType type) => switch (type) {
  TaskType.putaway => 'Putaway',
  TaskType.retrieve => 'Retrieve',
  TaskType.returning => 'Putaway',
};

expression คืนค่าโดยตรงและ compiler ตรวจ enum ครบ เหมาะกับ mapping ที่ไม่มี side effect ถ้าต้องทำหลาย statement ใช้ switch statement

2. OR pattern, wildcard และ guard

String statusLabel(Object? raw) => switch (raw) {
  'PENDING' || 0 => 'รอมอบหมาย',
  final String s when s.trim().isEmpty => 'ไม่ระบุสถานะ',
  final String s => s,
  _ => 'UNKNOWN',
};

|| จับทางเลือก, _ จับค่าใดก็ได้โดยไม่ bind และ when เพิ่มเงื่อนไขหลัง pattern match แล้ว ลำดับ case สำคัญ: case กว้างอยู่ก่อนจะบังกรณีแคบ

3. Object/List/Map pattern

String parseLogin(Object? json) => switch (json) {
  {'token': final String token} when token.isNotEmpty => token,
  {'error': final String message} => throw ApiException(message),
  _ => throw const FormatException('Invalid login payload'),
};

final [first, ...rest] = tasks;

Map pattern ไม่ได้บังคับว่าห้ามมี key อื่น แต่บังคับ key ที่ระบุต้อง match Shape validation แบบนี้ลด cast ต่อกันหลายชั้น

4. if-case สำหรับทางเดียว

if (payload case {'items': final List<Object?> rows}) {
  // rows ถูก promotion แล้ว
} else {
  throw const FormatException('items is required');
}

5. ตัวอย่างจริง

workflow_definitions.dart ใช้ OR pattern รองรับ status ใหม่/legacy เช่น 'PENDING' || '0'; connection_profile.dart ใช้ switch parse environment; warehouse_shell.dart ใช้ switch expression เลือก widget/title จาก state ปัจจุบัน

6. Pattern ไม่แทน validation ทั้งหมด

Pattern ตรวจ shape/type ได้ แต่ rule อย่าง port 1–65535, quantity ไม่เกินคงเหลือ หรือ transition ถูกลำดับยังต้องตรวจ domain invariant อย่าให้ parser ที่ดูสวยผ่านค่าที่ semantic ผิด

7. แบบฝึกหัด

เขียน parser ที่ยอมรับ quantity เป็น int หรือ numeric String แต่ปฏิเสธค่าติดลบ

เฉลยตัวอย่าง
int parseQuantity(Object? raw) => switch (raw) {
  final int n when n >= 0 => n,
  final String s when int.tryParse(s) case final int n when n >= 0 => n,
  _ => throw const FormatException('Invalid quantity'),
};

8. จุดพลาด

อย่าใส่ wildcard เพื่อให้ analyzer เงียบใน switch ของ enum/sealed state ถ้าค่าใหม่ควรบังคับให้ทุก UI ตัดสินใจ ให้รักษา exhaustive checking
