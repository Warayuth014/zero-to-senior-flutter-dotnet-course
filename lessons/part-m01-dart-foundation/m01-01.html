Dart, Flutter และ .NET อยู่ตรงไหนในระบบ

Part -1: Dart Foundation for Flutter

ภาพใหญ่ก่อนเขียนโค้ด: Dart คือภาษา, Flutter คือ UI framework/runtime ฝั่ง client และ .NET คือ backend คนละ process กัน การเชื่อมกันเกิดผ่าน contract เช่น HTTP/JSON และ SignalR ไม่ใช่การเรียก method ข้ามโปรเจกต์โดยตรง

1. เมื่อจบบทนี้

  • แยกหน้าที่ Dart, Flutter และ .NET ได้
  • วาดเส้นทางหนึ่ง action จาก PDA ถึงฐานข้อมูลและย้อนกลับได้
  • รู้ว่าควรเริ่ม debug ที่ชั้นใดเมื่ออาการเกิดบนหน้าจอ

2. Mental model: สามโลกที่มีสัญญากลาง

Dart ให้ type system, class, async และ collection ที่ใช้เขียนแอป ส่วน Flutter ใช้ Dart สร้าง widget tree, รับ input, render frame และคุยกับ platform Android/iOS ขณะที่ .NET รับ request, ตรวจสิทธิ์, รัน business logic และอ่านเขียนฐานข้อมูล

ผู้ใช้/Scanner
  ↓ event
Flutter Widget → State/Store → Repository/ApiClient
                                  ↓ HTTP + JSON / SignalR
                              .NET Endpoint → Service → Database
                                  ↓ response/event
Flutter Model  ← State/Store ← Repository/ApiClient → rebuild UI

สิ่งที่ข้ามเส้น network มีเพียงข้อมูล ไม่ใช่ Dart object หรือ C# object จริง ๆ ทั้งสองฝั่งจึงต้องตกลงชื่อ field, type, nullable, status code และรูปแบบ error

3. Trace จากโปรเจกต์จริง

  • wms_absolute_mobile/lib/features/auth/login_screen.dart รับ event กด Login
  • features/auth/auth_repository.dart แปลง intent เป็น request
  • core/api_client.dart สร้าง HTTP request และ decode JSON
  • .NET ตรวจ credential แล้วคืน token; Flutter เก็บเป็น AuthSession และเปิด WarehouseShell

อีกแนวทางอยู่ใน wmsapp: screen เรียก singleton ApiService ผ่าน extension ตามโดเมน เช่น ReceivingApi แล้วรับ ApiResult<T> กลับมา ทั้งสองแบบต่อ backend ได้เหมือนกัน แต่ตำแหน่ง owner และความง่ายในการ test ต่างกัน

4. แยกอาการก่อน debug

  1. กดแล้วไม่มีอะไรเกิด: ตรวจ callback, validation และ state guard ฝั่ง Flutter
  2. โหลดค้าง/ต่อไม่ได้: ตรวจ base URL, network, timeout และ server health
  3. ได้ 400/401/500: เปิด status code กับ response body แล้วเทียบ API contract
  4. ข้อมูลมาถูกแต่จอไม่เปลี่ยน: ตรวจ state mutation, notify/setState และ widget ที่กำลังฟัง
  5. ข้อมูลผิดในฐาน: trace ต่อจาก .NET endpoint ไป service/transaction ในคอร์ส backend

5. ขอบเขตคอร์สนี้

คอร์สนี้ลงลึก Dart/Flutter, mobile workflow และรอยต่อ .NET: URL, HTTP verb, header, JSON, JWT, SignalR, upload และ error contract ส่วน Controller → Service → EF Core/SQL มีคอร์ส zero-to-senior-dotnet8-course อธิบายเต็มอยู่แล้ว เราจะเปิดฝั่ง .NET เท่าที่จำเป็นเพื่อพิสูจน์การเชื่อมต่อ

6. แบบฝึกหัด

เลือก action “Login” หรือ “สแกนรับสินค้า” แล้วเขียน 6 ช่อง: Event → Widget → State owner → Client/Repository → Endpoint → UI result พร้อมระบุข้อมูลที่ข้าม network

แนวคำตอบ: Login

กดปุ่ม → LoginScreen._submit → local submitting/error state → AuthRepository.login → ApiClient.post ส่ง employeeId/password → endpoint คืน token/user → สร้าง session และ navigate; กรณีผิดแสดงข้อความโดยไม่เปลี่ยน route

7. จุดพลาดที่ต้องจำ

อย่าแก้ backend เมื่อ callback ไม่ยิง และอย่าแก้ widget เมื่อ server คืน contract ผิด ให้หาหลักฐานที่ boundary ทีละชั้น: input, log/request, response, state และ rendered output

8. เช็กความเข้าใจ

  • Flutter ไม่ใช่ภาษา; Dart ไม่ใช่ backend
  • client กับ server แยก process และอาจแยกเครื่อง
  • JSON คือ wire format ที่ต้อง parse/validate
  • หนึ่ง action ต้อง trace ไป-กลับได้ครบก่อนถือว่าอ่าน flow ออก
