1. ปัญหาที่บทนี้แก้

ในบทที่แล้วเราเก็บชื่อคลังและจำนวนสินค้าไว้ในตัวแปร โดยยังไม่ได้ถามว่า “ตัวแปรนี้เก็บอะไรได้บ้าง” คำถามนี้สำคัญมาก เพราะ Dart จะปฏิเสธโค้ดที่ใส่ค่าผิดชนิด ตั้งแต่ก่อนโปรแกรมจะรัน ซึ่งเป็นข้อดี ไม่ใช่ความจุกจิก — bug ที่ควรเจอตอนพิมพ์โค้ด ดีกว่าเจอตอนพนักงานยืนสแกนของอยู่หน้าแร็ค

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมายแบบสั้นที่สุดตัวอย่าง
ตัวแปร (variable)กล่องที่มีชื่อ ใช้เก็บค่าหนึ่งค่าquantity
ชนิด (type)ป้ายบอกว่ากล่องนี้รับค่าแบบไหนint, String
ประกาศ (declare)สร้างตัวแปรขึ้นมาครั้งแรกint quantity = 0;
กำหนดค่า (assign)ใส่ค่าใหม่ลงกล่องเดิมquantity = 5;
อนุมานชนิด (type inference)Dart เดาชนิดให้จากค่าที่เราใส่var code = 'PAL-1';
compile-time errorผิดตั้งแต่ยังไม่รันใส่ตัวเลขลงกล่อง String
runtime errorผิดตอนโปรแกรมกำลังทำงานแปลงคำว่า “มาก” เป็นตัวเลข

3. Mental model: กล่องที่มีป้ายกำกับ

ให้คิดว่าตัวแปรคือกล่องพลาสติกในคลัง แต่ละกล่องมี ชื่อ (ใช้เรียก) และมี ป้ายกำกับ ติดอยู่บอกว่ากล่องนี้ใส่อะไรได้

  • กล่องชื่อ quantity ป้ายเขียนว่า int → ใส่ได้เฉพาะจำนวนเต็ม
  • กล่องชื่อ barcode ป้ายเขียนว่า String → ใส่ได้เฉพาะข้อความ
  • ป้ายกำกับ ติดตายตั้งแต่วันประกาศ เปลี่ยนของข้างในได้ แต่เปลี่ยนชนิดไม่ได้
ประโยคเดียวที่ต้องจำ: ค่าในกล่องเปลี่ยนได้ ป้ายชนิดของกล่องเปลี่ยนไม่ได้

4. ชนิดพื้นฐานที่ใช้จริง 90% ของเวลา

ชนิดเก็บอะไรตัวอย่างค่าใช้ตอนไหนในงานคลัง
Stringข้อความ'PAL-1001'บาร์โค้ด, ชื่อช่องเก็บ
intจำนวนเต็ม12จำนวนชิ้น, จำนวนกล่อง
doubleทศนิยม3.5น้ำหนัก, ปริมาตร
boolจริง/เท็จtrueตรวจแล้วหรือยัง
numตัวเลขแบบใดก็ได้7 หรือ 7.5เมื่อรับได้ทั้งสองแบบ

num คือชนิดแม่ของ int และ double — ใช้เมื่อ “ยังไม่แน่ว่าจะเป็นจำนวนเต็มหรือทศนิยม” แต่ถ้ารู้แน่ให้เลือกชนิดที่แคบกว่าเสมอ

5. รันดูของจริง

เปิด Terminal ที่โฟลเดอร์ lab แล้วรัน:

Set-Location .\labs\flutter_wms_companion
dart run tool/dart_foundation/d1_02_variables.dart

ผลลัพธ์สี่บรรทัดแรกจะเป็นแบบนี้ สังเกตวงเล็บท้ายบรรทัด นั่นคือชนิดจริงที่ Dart มองเห็น

barcode  = PAL-1001  (String)
quantity = 12  (int)
weightKg = 3.5  (double)
isChecked= false  (bool)

runtimeType คือวิธีถาม Dart ตรง ๆ ว่า “ค่านี้ชนิดอะไร” มีไว้เรียนรู้และ debug ไม่ใช่สิ่งที่ควรใช้ตัดสินใจในโค้ดจริง

6. เขียนชนิดเอง หรือให้ Dart เดาด้วย var

String barcode = 'PAL-1001';  // เขียนชนิดเอง
var location = 'A-01-02';     // ให้ Dart เดา -> ได้ String เหมือนกัน

location = 'A-01-03';  // เปลี่ยนค่าได้ เพราะยังเป็นข้อความ
// location = 5;       // ผิดตั้งแต่ยังไม่รัน เพราะกล่องนี้ป้ายว่า String
เข้าใจผิดที่พบบ่อยที่สุดของบทนี้: var ไม่ได้แปลว่า “ไม่มีชนิด” และไม่ได้แปลว่า “ใส่อะไรก็ได้” — มันแปลว่า “ชนิดชัดอยู่แล้วจากค่าด้านขวา ไม่ต้องพิมพ์ซ้ำ” ผลลัพธ์เข้มงวดเท่าการเขียนชนิดเองทุกประการ

กฎง่าย ๆ ที่ทีมส่วนใหญ่ใช้: ถ้าอ่านบรรทัดเดียวแล้วเดาชนิดออก ใช้ var; ถ้าเดาไม่ออกหรือเป็นค่าสำคัญ ให้เขียนชนิดกำกับไว้ให้คนอ่านสบายใจ

7. แปลงข้อความให้เป็นตัวเลข

เครื่องสแกนและ API ส่งค่ามาเป็น ข้อความ เสมอ ถ้าจะเอาไปบวกลบต้องแปลงก่อน และการแปลงมีสองแบบที่ต่างกันมาก

วิธีเจอค่าที่แปลงไม่ได้ใช้เมื่อ
int.parse('25')โยน error โปรแกรมหยุดมั่นใจว่าข้อมูลถูกแน่นอน
int.tryParse('ยี่สิบห้า')คืน null อย่างสงบรับค่าจากผู้ใช้หรือเครือข่าย
final scannedQty = int.parse('25');        // ได้ 25
final maybeQty = int.tryParse('ยี่สิบห้า');  // ได้ null
final safeQty = int.tryParse('abc') ?? 0;  // ถ้าแปลงไม่ได้ให้ใช้ 0

เครื่องหมาย ?? อ่านว่า “ถ้าฝั่งซ้ายเป็น null ให้ใช้ฝั่งขวาแทน” เราจะเจอมันบ่อยมากตั้งแต่บทนี้เป็นต้นไป

8. String interpolation: ประกอบข้อความ

print('$barcode มี $quantity ชิ้น');
print('น้ำหนักรวม ${weightKg * quantity} kg');
เขียนแบบใช้เมื่อ
$ชื่อตัวแปรแทรกค่าตัวแปรตรง ๆ
${นิพจน์}ต้องคำนวณหรือเรียก method ก่อน

9. Object? ปลอดภัยกว่า dynamic

บางครั้งเราได้ค่าที่ยังไม่รู้ชนิด เช่นข้อมูลที่เพิ่งมาจาก server มีสองทางเลือก และทางที่ถูกมีแค่ทางเดียว

Object? fromServer = 42;
if (fromServer is int) {
  print(fromServer + 1);  // ผ่าน if แล้ว Dart รู้ว่าเป็น int
}

dynamic unchecked = 42;
unchecked.methodThatDoesNotExist();  // ผ่านการ compile แต่พังตอนรัน
Object?dynamic
รับค่าได้กว้างได้ได้
บังคับให้ตรวจชนิดก่อนใช้บังคับไม่บังคับ
พิมพ์ชื่อ method ผิดรู้ทันทีตอน compileรู้ตอนโปรแกรมพัง
ตอนนี้ยังไม่ต้องใช้ทั้งสองตัว แค่จำไว้ว่าถ้าจำเป็นต้องเลือก ให้เลือก Object? เพราะมันบังคับให้เราตรวจก่อน ส่วน dynamic เก็บไว้ใช้เฉพาะจุดที่แกะ JSON เท่านั้น (D1.19)

10. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
A value of type 'int' can't be assigned to a variable of type 'String'ใส่ค่าผิดชนิดลงกล่องแปลงชนิดก่อน หรือแก้ชนิดของตัวแปร
FormatException: Invalid radix-10 numberใช้ int.parse กับข้อความที่ไม่ใช่ตัวเลขเปลี่ยนไปใช้ int.tryParse แล้วรองรับ null
บวกเลขแล้วได้ข้อความต่อกัน เช่น '12' + '1' → 121ลืมแปลงข้อความเป็นตัวเลขแปลงด้วย int.tryParse ก่อนบวก
ผลหารได้ทศนิยมทั้งที่อยากได้จำนวนเต็ม/ คืน double เสมอใช้ ~/ เมื่อต้องการหารแบบปัดลง

11. แบบฝึกหัด

เขียนไฟล์ใหม่ชื่อ my_scan.dart ที่ทำสามอย่างนี้

  1. รับค่าจำลองจากเครื่องสแกนเป็นข้อความ 'PAL-2001' และ '8'
  2. แปลงจำนวนเป็น int โดยถ้าแปลงไม่ได้ให้ใช้ 0 แทน
  3. แสดงผลว่า PAL-2001 จำนวน 8 ชิ้น น้ำหนักรวม 20.0 kg เมื่อของหนักชิ้นละ 2.5 kg โดยต้องคำนวณจริง ห้ามพิมพ์เลข 20.0 ลงไปตรง ๆ
ดูแนวคำตอบหลังจากลองเองแล้ว
void main() {
  final scannedCode = 'PAL-2001';
  final scannedQtyText = '8';
  const weightPerItem = 2.5;

  final quantity = int.tryParse(scannedQtyText) ?? 0;
  final totalWeight = quantity * weightPerItem;

  print('$scannedCode จำนวน $quantity ชิ้น น้ำหนักรวม $totalWeight kg');
}

ทำไมต้องเขียนแบบนี้: ใช้ tryParse เพราะค่าที่มาจากเครื่องสแกนไม่รับประกันว่าถูกเสมอ; ใช้ const กับน้ำหนักต่อชิ้นเพราะเป็นค่าคงที่ที่รู้ตั้งแต่เขียนโค้ด; และคำนวณ totalWeight จริงเพื่อให้แก้จำนวนแล้วผลลัพธ์เปลี่ยนตาม

ลองต่อ: เปลี่ยน '8' เป็น 'แปด' แล้วรันใหม่ ควรได้ 0 ชิ้นและ 0.0 kg โดยโปรแกรมไม่พัง

12. สรุปท้ายบท

  • ตัวแปรทุกตัวใน Dart มีชนิดเสมอ แม้เราจะเขียน var
  • ชนิดพื้นฐานที่ใช้บ่อยคือ String, int, double, bool
  • int.tryParse ปลอดภัยกว่า int.parse เมื่อค่ามาจากผู้ใช้หรือเครือข่าย
  • ?? ใช้ใส่ค่าสำรองเมื่อฝั่งซ้ายเป็น null
  • ถ้าจำเป็นต้องรับค่าที่ยังไม่รู้ชนิด ให้ใช้ Object? ไม่ใช่ dynamic

บทถัดไป: D1.3 จะตอบคำถามที่ค้างจากบทนี้ว่า ควรใช้ var, final หรือ const ตอนไหน และทำไม Flutter ถึงชอบ const เป็นพิเศษ
