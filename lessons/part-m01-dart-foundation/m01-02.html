หัวใจของ Dart: ตัวแปรทุกตัวมี static type แม้เขียนด้วย var ก็ตาม Type inference ช่วยลดคำซ้ำ แต่ไม่ได้ปิด type checking แบบ dynamic

1. ชนิดข้อมูลที่ต้องอ่านออกทันที

  • int, double, num: จำนวนเต็ม ทศนิยม และชนิดแม่ของทั้งคู่
  • String, bool: ข้อความและจริง/เท็จ
  • Object/Object?: รับค่าได้กว้างแต่ยังต้องตรวจ type ก่อนใช้
  • dynamic: เลื่อนการตรวจสมาชิกไป runtime—ใช้เฉพาะ boundary ที่หลีกเลี่ยงไม่ได้
  • Never: function ไม่มีวันคืนค่าปกติ เช่น throw เสมอ

2. Inference ไม่เท่ากับ dynamic

var palletId = 'PAL-001'; // inferred เป็น String
palletId = 'PAL-002';     // ได้
// palletId = 42;          // compile-time error

Object? raw = response['count'];
if (raw is int) {
  print(raw + 1);          // promotion เป็น int ใน branch นี้
}

dynamic unchecked = response['count'];
unchecked.missingMethod(); // compile ผ่าน แต่พังตอน runtime

เลือก var เมื่อ type ด้านขวาชัด เลือกเขียน type เมื่อเป็น public API, ค่าเริ่มต้นไม่บอก intent หรืออยากรับ interface ที่กว้างกว่าคลาสจริง

3. Assignment กับ object identity

ตัวแปรเก็บ reference ไปยัง object ไม่ได้คัดลอก object ทุกครั้ง การ assign list ให้ตัวแปรใหม่จึงยังชี้ list เดิม:

final first = <String>['A'];
final second = first;
second.add('B');
print(first); // [A, B]

final copied = [...first]; // list คนละตัว

เรื่องนี้สำคัญต่อ state: mutate list เดิมอาจทำให้ listener ที่เทียบ identity ไม่รู้ว่าค่าเปลี่ยน การสร้าง collection/object ใหม่ทำให้ flow ชัดและ test ง่ายกว่า

4. ตัวอย่างใน WMS

เปิด wms_absolute_mobile/lib/core/api_client.dart จะเห็น JSON เริ่มเป็น Map<String, dynamic> เพราะข้อมูลเพิ่งข้าม network จากนั้นไฟล์ model/API แปลงเป็น String, int, enum หรือ class ที่แน่นอน ส่วน PdaMetrics.minTapTarget เป็น double ที่มีความหมายด้าน UI ชัดเจน

5. กฎเลือก type สำหรับโค้ดงานจริง

  1. ใช้ type ที่แคบที่สุดซึ่งรองรับค่าที่ถูกต้อง
  2. ถ้า “ไม่มีค่า” เป็นสถานะจริง ใช้ T? ไม่ใช้ค่าวิเศษอย่าง '' หรือ -1
  3. กัก dynamic ไว้ใน parser แล้วคืน typed model
  4. อย่า cast เพียงเพื่อให้ analyzer เงียบ ต้อง validate รูป payload ด้วย

6. แบบฝึกหัด

กำหนด type ให้ข้อมูลสแกน: barcode, quantity, optional serial, loading flag และ raw JSON จาก server แล้วอธิบายว่าทำไม

เฉลย
String barcode = '';
int quantity = 0;
String? serial;
bool isLoading = false;
Map<String, dynamic> rawJson = <String, dynamic>{};

หลัง parse แล้วไม่ควรส่ง rawJson เข้า widget แต่สร้าง model ที่มีชนิดแทน

7. จุดพลาด

var ไม่ได้ทำให้ตัวแปรเปลี่ยนชนิดได้ และ Object? ปลอดภัยกว่า dynamic เพราะ compiler บังคับให้ตรวจ type ก่อนเรียกสมาชิก

8. สรุป

อ่าน declaration แล้วตอบให้ได้สามข้อ: ค่าชนิดใดถูกต้อง, null ได้ไหม, และใครมีสิทธิ์เปลี่ยน object นั้น จากสามคำตอบนี้ bug ของ model/state จำนวนมากจะเห็นก่อนรันแอป
