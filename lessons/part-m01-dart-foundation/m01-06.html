Class, constructor, getter และ encapsulation

Part -1: Dart Foundation for Flutter

Class ที่ดีไม่ได้เป็นแค่ถุงใส่ field แต่บังคับให้ object อยู่ในสถานะที่ถูกต้องตั้งแต่ constructor และเปิดเฉพาะ operation ที่รักษากติกาของโดเมน

1. Anatomy ของ class

class ScanItem {
  const ScanItem({
    required this.barcode,
    required this.quantity,
  }) : assert(quantity > 0);

  final String barcode;
  final int quantity;

  bool get isPallet => barcode.startsWith('PAL-');

  ScanItem copyWith({String? barcode, int? quantity}) => ScanItem(
    barcode: barcode ?? this.barcode,
    quantity: quantity ?? this.quantity,
  );
}

constructor สร้าง invariant, field เก็บ state, getter คำนวณค่าที่ derive ได้ และ method เปลี่ยน/คืนผลตาม behavior ไม่ควรเก็บ isPallet ซ้ำเพราะคำนวณจาก barcode ได้

2. Constructor แบบต่าง ๆ

  • Generative: สร้าง instance ใหม่ตามปกติ
  • Named: เช่น ApiResult.success/ApiResult.error สื่อ intent ต่างกัน
  • Factory: คืน subtype, cache/singleton หรือ parse ก่อนเลือก object ได้ แต่ไม่มี this สำหรับกำหนด field โดยตรง
  • Const: สร้าง compile-time instance เมื่อ field และ argument รองรับ

wmsapp/lib/services/api_service.dart ใช้ factory constructor คืน singleton เดิม ส่วน model ConnectionProfile ใช้ const constructor และ static fromJson ที่คืน null เมื่อข้อมูลไม่น่าเชื่อถือ

3. Encapsulation และ privacy

class Session {
  String? _token;
  bool get isSignedIn => _token != null;

  void start(String token) {
    if (token.isEmpty) throw ArgumentError.value(token, 'token');
    _token = token;
  }

  void clear() => _token = null;
}

underscore ทำให้ชื่อ private ต่อ library ไม่ใช่ private ต่อ class อย่าง C# ดังนั้นไฟล์ที่เป็น part ของ library เดียวกันยังเห็นสมาชิก private กันได้

4. Getter ไม่ใช่ function ที่ควรมี side effect

Getter ควรเร็วและคืน derived value เช่น ConnectionProfile.baseUrl ไม่ควรยิง HTTP, mutate state หรือ throw แบบคาดไม่ถึง เพราะ call site อ่านเหมือนการเข้าถึงข้อมูลธรรมดา งาน async ต้องเป็น method ที่คืน Future

5. Composition ก่อน inheritance

WarehouseStore มี receiving/tasks repositories เป็น field นี่คือ composition: store ใช้ capability โดยไม่ “เป็น” repository การสืบทอดเหมาะเมื่อ subtype เป็นชนิดเดียวกันจริงและต้องรักษาสัญญาของ base type

6. แบบฝึกหัด

ออกแบบ ConnectionProfile ย่อส่วนที่ห้าม port นอก 1–65535 และคืน baseUrl โดยไม่ให้ caller ต่อ string เอง

แนวคำตอบ

validate ใน factory/named constructor แล้วเก็บ protocol, host, port เป็น final; ใช้ getter คำนวณ ${protocol.name}://$host:$port; ไม่ expose setter เพื่อกัน object เข้าสถานะครึ่งถูกครึ่งผิด

7. จุดพลาด

อย่าสร้าง model ที่ field ทุกตัว nullable เพียงเพราะ JSON อาจเสีย ให้ parser ปฏิเสธ payload ที่ขาดข้อมูลบังคับ แล้วคง domain object ให้ใช้งานง่ายและปลอดภัย

8. สรุป

constructor กำหนด “เข้าได้อย่างไร”, private field กำหนด “ใครแตะได้”, method กำหนด “เปลี่ยนได้อย่างไร” และ getter อธิบายค่าที่ derive—นี่คือกำแพงกัน invalid state ชั้นแรก
