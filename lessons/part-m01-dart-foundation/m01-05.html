List เก็บลำดับและค่าซ้ำ, Set เก็บสมาชิกไม่ซ้ำ, Map จับคู่ key-value การเลือกผิดทำให้ทั้ง intent และ complexity ของ workflow อ่านยาก

1. เลือก collection จากคำถาม

ต้องการใช้ตัวอย่าง WMS
รายการเรียงลำดับ/ซ้ำได้List<T>รายการ part ใน pallet
ตรวจสมาชิกไม่ซ้ำSet<T>serial ที่สแกนแล้ว
หา value ด้วย keyMap<K,V>task ตาม taskId, step ตาม TaskType

2. Typed collection และ operators

final scannedSerials = <String>{'SN-001'};
final quantities = <String, int>{'PART-A': 2};
final pending = tasks.where((t) => !t.done).toList();
final ids = tasks.map((t) => t.id).toSet();

final menu = <String>[
  'Home',
  if (canReceive) 'Receiving',
  for (final role in extraRoles) role.label,
  ...customMenus,
];

where/map คืน lazy Iterable; ใช้ toList() เมื่ออยาก snapshot หรือ API ต้องการ List จริง ระวัง enumerate ซ้ำถ้าข้างในแพงหรือ source เปลี่ยนได้

3. Mutation กับ state

// mutation เดิม: listener บางแบบอาจไม่เห็น identity ใหม่
items.add(newItem);

// immutable-style update: intent ชัดและ rollback ง่าย
items = [...items, newItem];
items = [for (final x in items) if (x.id == id) x.complete() else x];

final List ยังแก้สมาชิกได้ ถ้า expose list จาก store ให้ใช้ unmodifiable view/copy เพื่อไม่ให้ UI ข้าม command แล้วแก้ state โดยตรง

4. Equality และ uniqueness

Set/Map ใช้ == กับ hashCode ของ key ถ้า model ไม่ override equality วัตถุสองตัวที่ข้อมูลเหมือนกันอาจยังเป็นคนละสมาชิก สำหรับ barcode มัก normalize เป็น String ก่อนใส่ Set ง่ายและชัดกว่าใช้ object ดิบ

5. ตัวอย่างจริง

  • wms_absolute_mobile/lib/features/warehouse/workflow_definitions.dart ใช้ Map<TaskType, List<StepDef>> เพราะต้อง lookup flow จากชนิดงาน
  • wmsapp/lib/services/signalr_service.dart ใช้ List<SignalRCallback> เพราะ event หนึ่งมีผู้ฟังหลายราย
  • parser ใน API ใช้ whereType<Map<String,dynamic>>() กรอง element ก่อนสร้าง model

6. Collection pitfalls

firstWhere จะ throw ถ้าไม่พบ, single จะ throw ถ้าจำนวนไม่ใช่หนึ่ง, และแก้ list ระหว่าง iterate อาจพัง ใช้ helper ที่คืน nullable, ตรวจ invariant หรือสร้าง list ใหม่ตามความหมายของงาน

7. แบบฝึกหัด

รับ serial ต่อเนื่อง ต้องไม่ยิง API เมื่อซ้ำ และต้องรักษาลำดับแสดงผล ควรใช้โครงสร้างใด?

เฉลย

ใช้ทั้ง List<String> สำหรับลำดับ UI และ Set<String> สำหรับ membership O(1) โดย normalize ก่อนตรวจ เพิ่มทั้งสองภายใต้ command เดียวเพื่อรักษา invariant; หรือใช้ LinkedHashSet หากไม่ต้องเก็บข้อมูลอื่นและยอมให้ Set เป็น source เดียว

8. สรุป

ก่อนเขียน loop ให้ตอบว่า ordering, duplicate และ lookup สำคัญอย่างไร แล้วเลือก collection จาก invariant ไม่ใช่เลือก List เพราะคุ้นมือ
