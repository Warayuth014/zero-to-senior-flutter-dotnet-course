Analyzer, lints, formatter และ tests เป็น feedback loop ไม่ใช่งานเก็บกวาดท้ายโปรเจกต์ เป้าหมายคือทำให้ความผิดที่ตรวจอัตโนมัติได้ไม่ต้องรอ code review หรือ production

1. คำสั่งประจำวัน

dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test

ระหว่างพัฒนาใช้ dart format . เพื่อแก้รูปแบบ ก่อน commit ให้ analyze/test ผ่าน ถ้า repo มี generated code หรือ target เพิ่มให้ยึด script/CI ของ repo เป็นหลัก

2. analysis_options.yaml

ไฟล์นี้ include rule set และปรับ lint/error severity ให้ทีม Lint ควรสะท้อน bug/maintainability ที่ทีมยอมทำตาม ไม่ใช่เปิดทุก rule แล้วกระจาย ignore ทั้ง repo เมื่อจำเป็นต้อง ignore ให้เล็กที่สุดและใส่เหตุผล

include: package:flutter_lints/flutter.yaml

linter:
  rules:
    avoid_print: true
    unawaited_futures: true

3. Checklist ระดับ declaration

  • public function มี type ชัด; ไม่ใช้ dynamic/Function กว้างโดยไม่จำเป็น
  • nullability สื่อ domain; ไม่มี ! จากการเดา
  • final/const ใช้ตาม ownership และ immutability จริง
  • collection มี type และไม่ expose mutable state ข้าม owner
  • ชื่อบอก intent/domain ไม่ใช่ data, temp2, doIt

4. Checklist async/resource

  • Future ถูก await หรือประกาศ unawaited พร้อม error policy
  • Timer, StreamSubscription, controller, FocusNode และ observer ถูก dispose/cancel
  • ตรวจ mounted/context หลัง await เมื่อ owner คือ widget
  • กัน duplicate action และ stale response
  • ไม่ log password/token/PII

5. Checklist boundary

  • HTTP timeout/non-2xx/malformed JSON แยกจาก empty success
  • dynamic ถูกกักใน parser และมี contract test
  • URI/query ใช้ API ของ Uri ไม่ต่อ string ที่ไม่ encode
  • status/date/timezone/null มีข้อตกลงกับ .NET
  • ข้อความ UI actionable ส่วน technical detail อยู่ log ที่ sanitize

6. อ่าน warning เป็นหลักฐาน

ตัวอย่าง use_build_context_synchronously ไม่ได้บอกให้ใส่ ignore แต่บอกว่ามี async gap และ context อาจหมดอายุ ต้องย้าย navigation ก่อน await, ตรวจ context.mounted หรือย้าย side effect ไป owner ที่อายุเหมาะสม

7. แบบฝึกหัดปิด Part

เลือกไฟล์ Dart จริงหนึ่งไฟล์แล้ว review ด้วย checklist 5 มิติ: type/null, ownership/mutation, async/lifecycle, boundary/error, testability จากนั้นจัด finding เป็น Bug risk / Design debt / Style

เกณฑ์ผ่าน

ต้องชี้ symbol/บรรทัดและอธิบาย failure scenario ได้ ไม่ผ่านถ้ามีเพียง “ควร clean code”; เสนอ fix ที่เล็กและ test ที่พิสูจน์ behavior เดิมอย่างน้อยหนึ่งข้อ

8. Part -1 Exit Test

พร้อมไป Part 0 เมื่อคุณทำได้ครบ:

  • อ่าน signature ที่มี nullable/generic/Future ได้โดยไม่เดา
  • อธิบาย final/const/late และ collection mutation ได้
  • อ่าน class/interface/extension/record/switch จากสอง codebase ออก
  • trace JSON dynamic เข้าสู่ typed model และ failure ออกสู่ UI ได้
  • รัน format/analyze/test และแก้ต้นเหตุของ warning ได้
