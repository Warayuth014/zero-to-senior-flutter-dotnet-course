Abstract class, interface, inheritance และ mixin

Part -1: Dart Foundation for Flutter

Abstract/interface กำหนดสัญญา, inheritance reuse ความเป็นชนิดเดียวกัน และ mixin เติมพฤติกรรมหลาย class ได้ ทั้งสามอย่างหน้าตาคล้ายแต่แก้คนละปัญหา

1. Interface เพื่อสลับ implementation

abstract interface class TasksRepository {
  Future<List<WmsTask>> fetchOpen();
  Future<void> complete(String id);
}

class TasksApi implements TasksRepository { /* เรียก .NET */ }
class FakeTasksRepository implements TasksRepository { /* ใช้ใน test */ }

implements รับเฉพาะ contract ต้อง implement สมาชิกเอง ไม่รับ implementation เดิม เหมาะกับ boundary ที่ production ใช้ network แต่ test ต้องควบคุมผล

2. Abstract class กับ extends

abstract class มีทั้ง abstract member และ implementation/shared state ได้ ส่วน extends รับ implementation และมี superclass เดียว ตัวอย่างสำคัญใน Flutter คือ StatefulWidget/State<T>: framework กำหนด lifecycle และ subclass เติม build, initState, dispose

ใช้ inheritance เพื่อความสัมพันธ์ “is-a” และรักษา Liskov contract ไม่ใช้เพียงเพราะอยากยืม method สองตัว

3. Mixin เติม capability

class _WarehouseShellState extends State<WarehouseShell>
    with WidgetsBindingObserver {
  @override
  void didChangeAppLifecycleState(AppLifecycleState state) { /* ... */ }
}

ตัวอย่างนี้อยู่ใน wms_absolute_mobile/.../warehouse_shell.dart State ยังเป็น State เหมือนเดิม แต่รับ capability สังเกต lifecycle ของแอป ต้อง add/remove observer ตาม lifecycle ด้วย—mixin ไม่ได้จัด ownership ให้อัตโนมัติ

4. Dart class มี implicit interface

ทุก class สามารถถูก implements ได้ แม้ไม่ได้ประกาศ interface แยก แต่การสร้าง interface เฉพาะ use case มักชัดกว่า implement class ใหญ่ เพราะ consumer ไม่ควรผูกกับสมาชิกที่ไม่ใช้

5. ตัวอย่างจากสอง codebase

  • absolute/api/receiving_api.dart, inventory_api.dart, tasks_api.dart แยก repository interface ทำ fake ได้
  • wmsapp ใช้ singleton ApiService โดยตรงมากกว่า จึงสลับ dependency ใน unit test ยากกว่า
  • State class จำนวนมาก extends State<Screen> เพราะ framework contract ไม่ใช่ business inheritance

6. Decision guide

  1. ต้องสลับ API/fake → interface
  2. ต้องแชร์ invariant/implementation และ subtype จริง → abstract base + extends
  3. หลาย hierarchy ต้องมี capability เดียวกัน → mixin
  4. แค่ต้องใช้ object อีกตัว → composition/injection

7. แบบฝึกหัด

ออกแบบ scanner ที่ production อ่าน hardware แต่ test คืนค่ากำหนดเอง

เฉลย
abstract interface class BarcodeSource {
  Stream<String> get scans;
}

class HardwareBarcodeSource implements BarcodeSource { /* platform */ }
class FakeBarcodeSource implements BarcodeSource { /* StreamController */ }

8. เช็กความเข้าใจ

เมื่อเห็น extends, implements, with ให้ถามตามลำดับ: รับ state/implementation อะไร, สัญญาอะไรที่ต้องทำให้ครบ และ lifecycle/resource ใหม่ใครเป็นเจ้าของ
