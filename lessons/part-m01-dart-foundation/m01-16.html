Stream และ event-driven code

Part -1: Dart Foundation for Flutter

Future ให้ผลครั้งเดียว ส่วน Stream ให้เหตุการณ์ 0..หลายครั้งตามเวลา ทุก stream listener จึงต้องมีคำตอบเรื่อง subscribe, error, done และ cancel

1. สร้างและฟัง Stream

Stream<String> normalizedScans(Stream<String> raw) async* {
  await for (final value in raw) {
    final code = value.trim().toUpperCase();
    if (code.isNotEmpty) yield code;
  }
}

late final StreamSubscription<String> subscription;
subscription = normalizedScans(scanner.scans).listen(
  onScan,
  onError: onScannerError,
);
// await subscription.cancel(); เมื่อ owner จบ

2. Single-subscription กับ broadcast

single-subscription เหมาะกับลำดับข้อมูลที่ควรมี consumer เดียวและฟังย้อนหลังไม่ได้ ส่วน broadcast เหมาะกับ event ที่ผู้ฟังหลายรายเข้าร่วม/ออกได้ แต่คนมาทีหลังไม่เห็น event เก่า อย่าเปลี่ยนเป็น broadcast เพียงเพื่อแก้ “ถูกฟังสองครั้ง” โดยไม่เข้าใจ semantics

3. Controller และ ownership

class FakeBarcodeSource implements BarcodeSource {
  final _controller = StreamController<String>.broadcast();
  @override Stream<String> get scans => _controller.stream;
  void emit(String code) => _controller.add(code);
  Future<void> dispose() => _controller.close();
}

ผู้สร้าง controller เป็นเจ้าของ close ส่วน subscriber เป็นเจ้าของ subscription/cancel การสลับหน้าจอโดยไม่ cancel ทำ callback ซ้ำและอาจแตะ State ที่ dispose แล้ว

4. Operators และ backpressure เชิงงาน

map, where, distinct, asyncMap ช่วยสร้าง pipeline แต่ scanner อาจส่งเร็วกว่าการเรียก API การใช้ asyncMap ไม่ได้แทน policy เสมอไป ต้องตัดสินใจว่าจะ queue, drop duplicate, ignore ระหว่าง busy หรือ cancel request เก่า

5. SignalR ใน wmsapp

signalr_service.dart ไม่ expose Dart Stream แต่เก็บ List<SignalRCallback> และ add/remove listener เอง Mental model ยังเหมือน stream: connection เป็น producer, screen subscribe ใน init, unsubscribe ใน dispose, event อาจซ้ำ/มาผิดลำดับ และ reconnect อาจทำ event หาย

6. StreamBuilder ใช้เมื่อใด

ใช้เมื่อ UI derive จาก snapshot ของ stream โดยตรงและ lifecycle ผูกกับ widget ได้ แต่ business workflow ที่ต้อง merge event กับ command/state หลายชนิดควรให้ store/service subscribe แล้ว expose state ที่ตีความแล้ว ไม่ควรย้าย business rule ทั้งหมดเข้า builder

7. แบบฝึกหัด

ออกแบบ stream scan ให้ trim, ตัดค่าว่าง, กัน serial ซ้ำติดกัน และหยุดฟังเมื่อหน้าออก

แนวคำตอบ
subscription = scanner.scans
    .map((x) => x.trim().toUpperCase())
    .where((x) => x.isNotEmpty)
    .distinct()
    .listen(_submitScan);

@override
void dispose() {
  subscription.cancel();
  super.dispose();
}

distinct กันเฉพาะค่าซ้ำติดกัน ถ้าต้องกันทั้ง session ต้องใช้ Set/domain rule
