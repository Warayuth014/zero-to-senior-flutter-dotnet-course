Library, import, part และ privacy

Part -1: Dart Foundation for Flutter

Library คือหน่วย visibility ของ Dart; file มักเป็น library หนึ่งหน่วย, import ใช้ library อื่น, part รวมหลายไฟล์เป็น library เดียว จึงมีผลต่อ underscore privacy โดยตรง

1. Import ที่อ่านง่าย

import 'dart:async';
import 'package:flutter/material.dart';
import '../../core/connection_profile.dart' show ConnectionStatus;
import 'package:http/http.dart' as http;

ใช้ relative import ภายใน feature ตาม convention ของ repo, package import สำหรับ package, alias เมื่อชื่อชนหรือช่วยสื่อ namespace และ show/hide เมื่อต้องจำกัด surface ที่มองเห็น

2. Underscore private ต่อ library

class ApiClient {
  Map<String, dynamic> _decode(Response response) { /* ... */ }
}

ไฟล์ library อื่นเรียก _decode ไม่ได้ แต่ทุก part ของ library เดียวกันเห็นได้ นี่ต่างจาก C# private ซึ่งผูกกับ type

3. part/part of ใน wmsapp

// services/api_service.dart
part 'api/receiving_api.dart';
part 'api/picking_api.dart';

// services/api/picking_api.dart
part of '../api_service.dart';
extension PickingApi on ApiService { /* เรียก _get ได้ */ }

ข้อดีคือแบ่งไฟล์แต่แชร์ private transport ข้อเสียคือ part ไม่ได้เป็น library อิสระ, import ของ part มาจาก parent และ coupling สูง เวลาย้ายไฟล์/ทดสอบแยกต้องเข้าใจหน่วย library นี้

4. Export และ public API

package สามารถมี barrel library ที่ export model/interface ที่ต้องการเปิด แต่การ export ทุกไฟล์ทำให้ dependency มองไม่เห็นและชื่อชนง่าย สำหรับแอป feature-first มัก import interface/model ที่ใช้ตรง ๆ ชัดกว่า barrel ใหญ่

5. Dependency direction

ถ้า core import feature UI กลับขึ้นมา หรือ model import screen แสดงว่าทิศทางผิด Library/import graph ควรไหลจาก presentation → domain/data abstraction และ implementation → abstraction ตาม architecture ที่เลือก โดยไม่เกิด cycle

6. Generated files

แพ็กเกจ codegen มักใช้ part 'model.g.dart' เพื่อให้ generated code เข้าถึง private member ตาม convention ห้ามแก้ generated part ตรง ๆ ให้แก้ source/annotation แล้ว generate ใหม่

7. แบบฝึกหัด

ทำไม PickingApi เรียก ApiService._get ได้ แต่ repository ใน absolute เรียก private method ของ ApiClient คนละไฟล์ไม่ได้?

เฉลย

PickingApi เป็น part ของ library api_service.dart เดียวกัน จึงแชร์ privacy ส่วนไฟล์ปกติใน absolute เป็นคนละ library และต้องเรียก public method ของ ApiClient นี่เป็น design boundary ที่ compiler บังคับ

8. จุดพลาด

อย่าใช้ part เพียงเพื่อหลบ private แล้วเข้าถึงทุกอย่าง มันขยายขอบเขต coupling; หากอีกไฟล์เป็น component จริงควรออกแบบ public/interface API ที่เล็กและชัด
