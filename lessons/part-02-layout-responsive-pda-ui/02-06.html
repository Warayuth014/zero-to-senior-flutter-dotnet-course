ScrollView vs ListView

เลือก scroll widget จากจำนวนข้อมูลและ ownership ของ viewport: SingleChildScrollView เหมาะกับ child ก้อนเดียวขนาดไม่ใหญ่มาก ส่วน ListView เป็น lazy multi-child scrollable สำหรับรายการที่เติบโต

1. SingleChildScrollView ใช้เมื่อไร

เหมาะกับ form, settings หรือ dialog content ที่ปกติพอดีแต่ต้องเลื่อนเมื่อจอเตี้ย/keyboard ขึ้น มันสร้าง child subtree ทั้งหมด จึงไม่เหมาะกับรายการคลังหลายร้อยหรือหลายพันแถว

2. ListView คือ viewport + sliver list

ListView.builder(
  itemCount: tasks.length,
  itemBuilder: (context, index) => TaskTile(tasks[index]),
)

Builder สร้างเฉพาะ items ใกล้ viewport และ recycle element/render work ตามการเลื่อน จึงลด initial build/memory แต่ child state ต้องมี identity ที่ถูกเมื่อ reorder/filter

3. Scrollable ซ้อนกัน

ปัญหาคลาสสิกคือ SingleChildScrollView → Column → ListView แต่ทั้งคู่เลื่อนแกนเดียวกัน ให้รวมเป็น ListView/CustomScrollView เดียว หาก list เล็กและจำเป็นจริงใช้ shrinkWrap: true กับ NeverScrollableScrollPhysics แต่ต้องยอมรับว่ารายการทั้งหมดถูกวัด

4. wmsapp Home

Home ใช้ SafeArea → Column → Expanded → SingleChildScrollView → Column ถูกกับเมนูจำนวนจำกัดและต้องเลื่อนทั้งหน้า Expanded ให้ scroll view มี viewport bounded แต่คู่การ์ดสร้างทั้งหมดทันที ซึ่งยอมรับได้เพราะจำนวนคงที่ หากเมนูมาจาก server และเพิ่มมากควรเปลี่ยนเป็น lazy grid/list

5. Keyboard และ form

Scaffold โดยปกติ resize body ตาม viewInsets เมื่อ keyboard ขึ้น SingleChildScrollView ทำให้ focused field เลื่อนเข้า view ได้ ใช้ keyboardDismissBehavior, FocusTraversal และ padding bottom ตาม viewInsets เฉพาะ sheet/custom layout ที่ Scaffold ไม่จัดให้

6. Controller และตำแหน่งเลื่อน

สร้าง ScrollController ใน State เมื่อ owner ต้องอ่าน/สั่ง offset และ dispose เมื่อ State ตาย ใช้ PageStorageKey/Restoration เมื่อควรรักษาตำแหน่งตาม route/tab อย่าสร้าง controller ใหม่ใน build เพราะตำแหน่งและ listeners จะหาย

7. แบบฝึกหัด

หน้า receiving มี header, scan form 4 ช่อง, รายการ item 800 แถว และปุ่ม confirm ตรึงล่าง ควรจัด scroll อย่างไร?

แนวคำตอบ

ใช้ Column: header/form ตาม UX, Expanded(ListView.builder) สำหรับ 800 แถว, action bar ด้านล่าง หากทั้ง header/form ต้องเลื่อนไปด้วยใช้ CustomScrollView ที่รวม SliverToBoxAdapter + SliverList แล้ววางปุ่มนอก scroll ไม่ใช้ SingleChildScrollView ครอบ ListView 800 แถว

8. จุดพลาด

shrinkWrap: true ไม่ใช่ยารักษา unbounded ทุกกรณี มันทำให้ scrollable ต้องคำนวณขนาดจากลูกทั้งหมดและเสีย lazy advantage ใช้เมื่อรายการเล็กและ bounded ทางธุรกิจ พร้อม test performance ด้วยข้อมูลสูงสุดจริง
