LayoutBuilder ทำให้ widget เลือก layout จาก constraints ณ ตำแหน่งนั้น Adaptive UI ที่ดีเปลี่ยนโครง/ความหนาแน่นตามพื้นที่และงาน ไม่ผูกกับชื่ออุปกรณ์ว่า “มือถือ” หรือ “tablet” อย่างเดียว

1. Breakpoint จากความต้องการเนื้อหา

LayoutBuilder(builder: (_, c) {
  final columns = switch (c.maxWidth) {
    < 420 => 2,
    < 840 => 3,
    _ => 4,
  };
  return WarehouseGrid(columns: columns);
})

ตัวเลขต้องมาจาก minimum usable tile width + gaps + text scale และทดสอบ boundary ไม่ใช่คัด breakpoint เว็บมาใช้โดยไม่มีเหตุผล

2. Absolute ใช้สองมิติ

Home ใช้ maxHeight < 650 เลือก compact spacing และ maxWidth <= 400 เลือก narrow text/layout จากนั้น tile แต่ละใบใช้ maxHeight ของตนสลับ Row เมื่อเตี้ยกว่า 92 นี่คือ container-level adaptation หลายชั้น ไม่ใช่ media query เดียวทั้งแอป

3. เปลี่ยนโครง ไม่ใช่ย่อทุกอย่าง

  • narrow: ซ่อน secondary status แต่รักษา label/value
  • short: tile เปลี่ยน icon บน→icon ซ้าย
  • wide: เพิ่ม pane/details ไม่ขยายบรรทัดข้อความไม่สิ้นสุด
  • high text scale: ลด columns ก่อนลด font

ลำดับนี้รักษาความสามารถใช้งานดีกว่าบีบ font จนอ่านไม่ได้

4. Orientation เป็นข้อมูลรอง

OrientationBuilder บอก portrait/landscape แต่เครื่องพับ, split screen และ desktop resize ทำให้ orientation ไม่พอบอกพื้นที่ ใช้ constraints เป็นหลัก หาก logic ต้องรู้ orientation เพื่อกล้อง/หมุนปุ่มจริงจึงอ่าน orientation เพิ่ม

5. ป้องกัน breakpoint กระจาย

รวม policy เป็นชื่อเชิงความหมาย เช่น WarehouseLayout.fromConstraints(c) ที่คืน density/columns/showSecondary ไม่ให้ทุก widgetมีเลข 400/650 คนละชุด แต่ child ที่มี local content constraint ยังควรตัดสินใจใกล้ตนเอง

6. Testing matrix

Widget test ด้วย tester.view.physicalSize/devicePixelRatio หรือครอบ SizedBox หลายขนาด ตรวจ 319/320, 399/400/401, ความสูง 649/650/651, text scale 1.0/1.3/2.0 และภาษาไทย/อังกฤษ Assertions ควรตรวจโครง/จำนวน columns/visibility ไม่อิง screenshot อย่างเดียว

7. แบบฝึกหัด

Dashboard กว้าง 700 แต่ถูกวางใน master-detail pane กว้าง 340 หากใช้ MediaQuery จะแสดง 3 columns แล้วล้น จะแก้อย่างไร?

เฉลย

ครอบ Dashboard ด้วย LayoutBuilder และคำนวณจาก constraints.maxWidth ของ pane ให้ 2 columns ที่ 340 ส่วน page-level ใช้ MediaQuery ได้สำหรับ safe area/keyboard หาก breakpoint ซ้ำให้ส่ง layout policy/value object ลงมาโดยยัง validate local constraint

8. จุดพลาด

Breakpoint ที่ดีไม่ควรทำให้ state หรือ API request เปลี่ยนเพียงเพราะ resize เปลี่ยนเฉพาะ presentation/composition รักษา controller/store/key เดิม หรือย้าย state ขึ้นเหนือ adaptive branch เพื่อไม่ให้ข้อมูลที่กรอกหายเมื่อหมุนจอ
