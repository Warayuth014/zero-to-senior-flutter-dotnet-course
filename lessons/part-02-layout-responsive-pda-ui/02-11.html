1. ปัญหาที่บทนี้แก้

ข้อความในแอปจริงยาวไม่เท่ากันและควบคุมไม่ได้ เพราะมาจากฐานข้อมูลที่คนอื่นกรอก จากหลายภาษา และจากขนาดตัวอักษรที่ผู้ใช้ตั้งเอง

บทนี้ไม่ได้เกี่ยวกับความสวยงามอย่างเดียว แต่เกี่ยวกับความถูกต้องของงาน — การตัดข้อความผิดที่ทำให้พนักงานหยิบของผิดพาเลทได้จริง

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
overflowจะทำอย่างไรกับส่วนที่ยาวเกิน
maxLinesจำนวนบรรทัดสูงสุด
ellipsisจุดไข่ปลาที่บอกว่ามีข้อความต่อ
softWrapยอมขึ้นบรรทัดใหม่เมื่อจบคำหรือไม่
identifierข้อมูลที่ใช้ระบุตัวตน เช่นรหัสพาเลท

3. Mental model: ตัดได้ กับ ห้ามตัด

ก่อนจะเลือกวิธีจัดการข้อความยาว ต้องตอบคำถามเดียวก่อน — ถ้าผู้ใช้อ่านไม่ครบ เขายังทำงานถูกไหม

ประเภทข้อมูลตัวอย่างตัดได้ไหมเหตุผล
คำอธิบายชื่อสินค้าเต็ม ๆตัดได้เห็นบางส่วนก็พอให้จำได้
ตัวระบุตัวตนรหัสพาเลท ซีเรียล ล็อตห้ามตัดตัดแล้วแยกไม่ออกว่าใบไหน
จำนวน12 ชิ้นห้ามตัดตัดแล้วอาจอ่านเป็นคนละจำนวน
ตำแหน่งจัดเก็บA-01-02ห้ามตัดเดินไปผิดที่
อันตรายที่เห็นภาพชัดที่สุด: รหัส PAL-100123 กับ PAL-100189 ถ้าถูกตัดเป็น PAL-1001… ทั้งคู่ จะแยกไม่ออกเลย พนักงานอาจยืนยันผิดใบโดยที่หน้าจอ “ดูปกติ” — บั๊กแบบนี้ไม่มี error ให้เห็น มีแต่ของหายจากคลัง

4. ต้องมีขอบเขตก่อน ellipsis ถึงทำงาน

// ไม่ทำงาน — Text ไม่มีขอบเขต จึงไม่มีจุดที่จะตัด
Row(
  children: [
    const Icon(Icons.inventory_2_outlined),
    Text(productName, overflow: TextOverflow.ellipsis),   // ยังล้น
  ],
)

// ทำงาน — Expanded ให้ขอบเขตก่อน
Row(
  children: [
    const Icon(Icons.inventory_2_outlined),
    const SizedBox(width: 12),
    Expanded(
      child: Text(
        productName,
        maxLines: 1,
        overflow: TextOverflow.ellipsis,
      ),
    ),
  ],
)

นี่คือเหตุผลที่ 2.3 บอกว่า Expanded อย่างเดียวยังไม่พอ ต้องบอกด้วยว่าจะตัดอย่างไร — ทั้งสองอย่างต้องมาคู่กันเสมอ

5. ดูของจริงใน lab

Text(
  line.productName,
  maxLines: compact ? 1 : 2,        // จอแคบ 1 บรรทัด จอกว้าง 2 บรรทัด
  overflow: TextOverflow.ellipsis,
  style: theme.textTheme.bodySmall,
)

และเทสต์ยืนยันทั้งสองกรณี

expect(longName.overflow, TextOverflow.ellipsis);
expect(longName.maxLines, 1);      // ที่ความกว้าง 360
expect(longName.maxLines, 2);      // ที่ความกว้าง 900

สังเกตว่าใน lab เดียวกัน line.palletCode และ line.quantity ไม่มี overflow เลย เพราะทั้งคู่เป็นข้อมูลที่ห้ามตัดตามตารางในหัวข้อ 3 — และเนื่องจากรหัสพาเลทมีความยาวคงที่ เราจึงรู้ว่ามันจะไม่ล้นแน่นอน

6. ตัวเลือกของ overflow

ค่าผลเหมาะกับ
ellipsisตัดแล้วใส่จุดไข่ปลาคำอธิบาย ที่มีทางดูฉบับเต็ม
fadeจางหายไปข้อความประกอบที่ไม่สำคัญ
clipตัดตรง ๆ ไม่มีสัญญาณแทบไม่ควรใช้ — ผู้ใช้ไม่รู้ว่ามีต่อ
visibleปล่อยล้นออกไปไม่ควรใช้ จะไปทับ widget อื่น

clip อันตรายเพราะไม่มีสัญญาณอะไรบอกว่าข้อความถูกตัด ผู้ใช้จะเชื่อว่าที่เห็นคือทั้งหมด — ต่างจาก ellipsis ที่จุดไข่ปลาบอกชัดว่ายังมีต่อ

7. ลำดับที่ควรทำเมื่อข้อความยาวเกิน

  1. ให้ขอบเขตที่ถูกต้อง ด้วย Expanded — แก้ที่ต้นเหตุก่อน
  2. ยอมให้เพิ่มบรรทัด — maxLines: 2
  3. ซ่อนข้อมูลรอง เมื่อจอแคบ — เอาคำอธิบายออก เก็บรหัสไว้
  4. ลดขนาดตัวอักษร ในช่วงที่ยังอ่านออก
  5. ตัดด้วยจุดไข่ปลา พร้อมมีทางดูฉบับเต็ม
อย่าเริ่มจากข้อ 4 ซึ่งเป็นสิ่งที่คนใหม่ทำบ่อยที่สุด — การลดขนาดตัวอักษรแก้ภาพที่เห็นได้ทันที แต่ทำให้พนักงานที่อ่านหน้าจอกลางแดดในคลังอ่านไม่ออก ซึ่งแย่กว่าการเห็นข้อความไม่ครบ

8. ต้องมีทางดูฉบับเต็มเสมอ

เมื่อตัดข้อความด้วยจุดไข่ปลา ต้องมีทางให้ผู้ใช้ดูฉบับเต็มได้

วิธีใช้ได้บน PDA ไหม
แตะที่แถวเพื่อเปิดหน้ารายละเอียดได้ — วิธีที่แนะนำ
กดค้างแล้วแสดงข้อความเต็มได้ แต่ผู้ใช้ต้องรู้ว่าทำได้
เอาเมาส์ไปชี้แล้วขึ้นคำอธิบายไม่ได้ — PDA เป็นจอสัมผัส ไม่มีเมาส์

ข้อสุดท้ายเป็นกับดักที่พบบ่อยเมื่อพัฒนาบนเดสก์ท็อป — ทดสอบแล้วเห็นคำอธิบายโผล่มาตอนเอาเมาส์ไปชี้ จึงคิดว่าแก้ปัญหาแล้ว แต่บนอุปกรณ์จริงไม่มีทางเรียกดูได้เลย

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ใส่ ellipsis แล้วยังล้นข้อความไม่มีขอบเขตห่อด้วย Expanded ก่อน
ข้อความหายไปเฉย ๆ ไม่มีจุดไข่ปลาใช้ clipเปลี่ยนเป็น ellipsis
พนักงานยืนยันผิดพาเลทตัดรหัสด้วยจุดไข่ปลาห้ามตัดตัวระบุตัวตน — ให้ขึ้นบรรทัดใหม่หรือย่อส่วนอื่นแทน
ข้อความล้นเมื่อผู้ใช้ตั้งตัวอักษรใหญ่ล็อกความสูงไว้ปล่อยให้สูงตามเนื้อหา (2.9)
คำอธิบายดูได้เฉพาะตอนเอาเมาส์ชี้ออกแบบบนเดสก์ท็อปทำให้แตะแล้วเปิดรายละเอียดได้
ลดขนาดตัวอักษรจนอ่านไม่ออกเริ่มจากทางแก้ที่ผิดลำดับทำตามลำดับในหัวข้อ 7
ภาษาอังกฤษพอดี แต่ภาษาไทยล้นทดสอบภาษาเดียวทดสอบด้วยข้อความจริงที่ยาวที่สุด

10. แบบฝึกหัด

แถวหนึ่งในรายการต้องแสดงสี่อย่างบนจอ PDA กว้าง 320

  • รหัสพาเลท PAL-100189
  • ชื่อสินค้า อาจยาวถึง 80 ตัวอักษร
  • ตำแหน่งจัดเก็บ A-01-02
  • จำนวน 1,250
  1. จัดวางอย่างไรให้ครบโดยไม่ล้น
  2. ระบุว่าอะไรตัดได้และอะไรห้ามตัด พร้อมเหตุผล
  3. ถ้าจอแคบกว่านี้อีกจนใส่ไม่ครบจริง ๆ จะทำอย่างไร
ดูแนวคำตอบและเหตุผล
Column(
  crossAxisAlignment: CrossAxisAlignment.start,
  children: [
    // บรรทัดบน — ข้อมูลที่ห้ามตัด อยู่ครบเสมอ
    Row(
      children: [
        Text(
          line.palletCode,
          style: theme.textTheme.titleMedium,   // ไม่ใส่ overflow เลย
        ),
        const Spacer(),
        Text(
          '${line.quantity}',
          style: theme.textTheme.titleMedium,
        ),
      ],
    ),
    const SizedBox(height: 4),

    // บรรทัดล่าง — ตำแหน่งห้ามตัด ชื่อสินค้าตัดได้
    Row(
      children: [
        Chip(
          label: Text(line.location),          // ห้ามตัด
          visualDensity: VisualDensity.compact,
        ),
        const SizedBox(width: 8),
        Expanded(                              // ตัวเดียวที่ยอมเสียพื้นที่
          child: Text(
            line.productName,
            maxLines: 1,
            overflow: TextOverflow.ellipsis,
            style: theme.textTheme.bodySmall,
          ),
        ),
      ],
    ),
  ],
)

ข้อ 1 — หลักการจัดวาง

แยกเป็นสองบรรทัด โดยจัดกลุ่มตาม “ตัดได้” กับ “ห้ามตัด” — บรรทัดบนมีแต่ข้อมูลที่ห้ามตัดสองตัว ซึ่งทั้งคู่สั้นและความยาวคาดเดาได้ จึงใส่ในบรรทัดเดียวได้อย่างปลอดภัย ส่วนบรรทัดล่างมีตัวที่ห้ามตัดหนึ่งตัวและตัวที่ยอมเสียพื้นที่หนึ่งตัว

ข้อ 2 — อะไรตัดได้

ข้อมูลตัดได้เหตุผล
รหัสพาเลทไม่PAL-100189 กับ PAL-100123 ตัดแล้วเหมือนกัน
จำนวนไม่1,250 ตัดเป็น 1,2… อาจอ่านเป็น 12
ตำแหน่งไม่เดินไปผิดช่อง
ชื่อสินค้าได้เห็นครึ่งเดียวก็รู้ว่าคืออะไร และมีรหัสยืนยันอยู่แล้ว

ข้อ 3 — ถ้าใส่ไม่ครบจริง ๆ

ทำตามลำดับในหัวข้อ 7 โดยไล่จากบนลงล่าง

  1. ซ่อนชื่อสินค้าไปเลย เมื่อแคบมาก แล้วให้แตะดูรายละเอียดแทน — ดีกว่าแสดงจุดไข่ปลาที่ไม่ให้ข้อมูลอะไร
  2. ย้ายตำแหน่งจัดเก็บขึ้นไปบรรทัดบน ต่อจากรหัส เพราะทั้งคู่สั้น
  3. ลดขนาดตัวอักษรของชื่อสินค้า เท่านั้น ไม่ลดของรหัสหรือจำนวน

สิ่งที่ห้ามทำเด็ดขาด: ย่อขนาดตัวอักษรทั้งแถวลงจนใส่ครบ เพราะรหัสพาเลทกับจำนวนคือสองสิ่งที่พนักงานต้องอ่านให้แม่นที่สุด การทำให้มันเล็กลงเพื่อให้ชื่อสินค้าที่ไม่สำคัญเท่าใส่ครบ คือการสลับลำดับความสำคัญกลับด้าน

ข้อสังเกตเรื่อง Spacer(): ใช้ในบรรทัดบนเพื่อดันจำนวนไปขวาสุด ซึ่งได้ผลดีตรงนี้เพราะทั้งสองฝั่งมีความยาวคาดเดาได้ ต่างจากกรณีในแบบฝึกหัด 2.3 ที่มีข้อความยาวไม่จำกัดปนอยู่ด้วย

ลองต่อ: ใน lab ให้เปลี่ยนชื่อสินค้าของ PAL-1001 เป็นข้อความยาว 200 ตัวอักษร แล้วรันเทสต์ — ควรผ่านทั้งหมด เพราะ Expanded กับ ellipsis จัดการให้แล้ว จากนั้นลองเปลี่ยนรหัสพาเลทเป็นข้อความยาวแทน จะเห็นแถบสีเหลืองดำทันที ซึ่งเป็นสัญญาณที่ถูกต้อง เพราะมันบอกว่าข้อมูลที่ห้ามตัดกำลังจะถูกตัด

11. สรุปท้ายบท

  • ถามก่อนเสมอว่า “อ่านไม่ครบแล้วยังทำงานถูกไหม”
  • ตัวระบุตัวตน จำนวน และตำแหน่ง ห้ามตัดเด็ดขาด
  • ellipsis ต้องมาคู่กับขอบเขตจาก Expanded เสมอ
  • อย่าใช้ clip เพราะไม่มีสัญญาณบอกว่าข้อความถูกตัด
  • แก้ที่ขอบเขตก่อน ลดขนาดตัวอักษรเป็นทางท้าย ๆ
  • ต้องมีทางดูข้อความเต็มที่ใช้ได้บนจอสัมผัส
  • ทดสอบด้วยข้อความจริงที่ยาวที่สุดและภาษาที่ยาวที่สุด
