แถบเหลืองดำ RenderFlex overflow คือหลักฐานว่า child ต้องการ main-axis มากกว่าที่ Flex มี การแก้อย่างเป็นระบบคือหา constraint owner และ content priority ไม่ใช่สุ่มเพิ่ม Expanded/scroll/font เล็ก

1. อ่าน error ให้ครบ

จด Flex direction, จำนวน pixels ที่ล้น, constraints และ nearest ancestor เปิด Inspector เลือก RenderFlex แล้วดู size ของลูก จุดที่เห็นแถบ overflow เป็นปลายเหตุ; root cause อาจอยู่ parent ที่บังคับ height/width ต่ำเกิน

2. Classification

  • Row + text ยาว: child ไม่มี bounded width
  • Column + content สูง: viewport ไม่มี scroll/flex policy
  • Fixed-height card + text scale: height assumption ผิด
  • Nested scroll + Expanded: main axis unbounded
  • Keyboard: available height ลดลงแต่หน้าไม่เลื่อน
  • Localization/data: fixture สั้นกว่าข้อมูลจริง

3. Decision tree

  1. เนื้อหาควรยืดหยุ่น? ใช้ Expanded/Flexible
  2. ควรขึ้นบรรทัด? กำหนด maxLines/softWrap
  3. ควรเลื่อน? ให้ scrollable เป็น owner ของ overflow
  4. ข้อมูลรองซ่อนได้? adaptive composition
  5. ขนาดตายตัวไม่มีเหตุผล? เอาออก/ใช้ min constraint
  6. จำเป็นต้อง scale เชิงภาพ? FittedBox/AutoSize ในขอบเขตจำกัด

4. ตัวอย่าง Row

// ผิด: Text วัดตัวเองตามความยาว
Row(children: [Icon(Icons.place), Text(location), Text(qty)])

// ถูก: กำหนดผู้รับพื้นที่ที่เหลือ
Row(children: [
  const Icon(Icons.place),
  const SizedBox(width: 8),
  Expanded(child: Text(location, maxLines: 2)),
  const SizedBox(width: 8),
  Text(qty),
])

5. ตัวอย่าง Column

ถ้ารายการต้องเลื่อนและ action ตรึง ให้ Expanded(ListView) ถ้าทั้งหน้าควรเลื่อนและ child น้อย ให้ SingleChildScrollView ถ้าหลาย section + list ใหญ่ ให้ CustomScrollView ห้ามแก้ด้วย Column(mainAxisSize:min) เมื่อ parent ยังส่ง height tight และเนื้อหายังเกิน

6. Regression matrix

หลังแก้ทดสอบ width/height ก่อน-ตรง-หลัง breakpoint, landscape, keyboard เปิด, text scale 2.0, ภาษาไทย/อังกฤษ, long identifier, empty/error/loading และจำนวนสูงสุด เพิ่ม widget/golden test เฉพาะ layout contract สำคัญเพื่อกันกลับมา

7. แบบฝึกหัด

Home tile สูง 80 มี icon, title 2 บรรทัด, subtitle 2 บรรทัด และ chevron แล้วล้นล่าง แก้ตาม product priority อย่างไร?

แนวคำตอบ

ตรวจว่าความสูงถูกคำนวณจาก viewportจริง; ที่ tight breakpoint เปลี่ยน Column เป็น Row, รักษา icon/title/action, ลด/ซ่อน subtitle หรือให้ 1 บรรทัด, ลด decorative gaps และใช้ AutoSizeText ภายใน min อ่านได้ ไม่ครอบ tile ด้วย scroll view และไม่ลด touch target

8. จุดพลาด

ถ้าใส่ ClipRect แล้วแถบเหลืองหาย layout ยังผิด เพียงซ่อนภาพล้น ข้อมูล/ปุ่มอาจถูกตัดและ hit target ผิด ต้องแก้ constraint/content policy ก่อน clipping
