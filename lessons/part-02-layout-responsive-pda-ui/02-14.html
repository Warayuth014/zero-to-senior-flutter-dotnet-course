1. ปัญหาที่บทนี้แก้

แถบสีเหลืองดำคือ error ที่เจอบ่อยที่สุดใน Flutter และเป็นตัวที่คนใหม่แก้แบบสุ่มมากที่สุด — ลองใส่ Expanded ดู ไม่ได้ก็ลอง SingleChildScrollView ไม่ได้ก็ลดขนาดตัวอักษร

ความจริงคือมันเป็น error ที่วิเคราะห์ได้ตรงไปตรงมาที่สุดตัวหนึ่ง เพราะ Flutter บอกข้อมูลมาครบแล้ว เราแค่ต้องอ่านให้เป็น

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
RenderFlexตัวจัดวางที่อยู่เบื้องหลัง Row และ Column
overflowลูกต้องการพื้นที่มากกว่าที่มี
constraint ownerwidget ที่เป็นคนตัดสินขนาดจริง ๆ
root causeต้นเหตุจริง ซึ่งอาจอยู่คนละที่กับจุดที่เห็นแถบ

3. Mental model: แถบที่เห็นคือปลายเหตุ

ทบทวนกฎสามข้อจาก 2.1 — เมื่อเกิดเนื้อหาล้น แปลว่ามีคนใดคนหนึ่งในสองคนนี้ผิด

ใครผิดอาการแก้ที่ไหน
ลูกขอมากเกินไปข้อความยาวไม่มีขอบเขตให้ขอบเขตกับลูก
แม่ให้น้อยเกินไปล็อกความสูงไว้ตายตัวปลดล็อกหรือเพิ่มพื้นที่
ประโยคเดียวที่ต้องจำ: จุดที่เห็นแถบสีเหลืองดำคือจุดที่ พื้นที่ไม่พอ แต่ต้นเหตุอาจอยู่ที่แม่ซึ่งอยู่สูงขึ้นไปหลายชั้น — ต้องไล่ขึ้นไปดูเสมอ

4. อ่าน error ให้ครบ

The relevant error-causing widget was:
    Row Row:file:///lib/features/inbound/line_card.dart:38:14
ข้อมูลที่ได้บอกอะไร
42 pixels on the rightล้นเท่าไร — ถ้าล้นน้อยมากอาจเป็นเรื่องระยะขอบ ถ้าล้นเป็นร้อยคือมีตัวที่ไม่ยืดหยุ่นตัวใหญ่
Axis.horizontalเป็น Row ไม่ใช่ Column
ชื่อไฟล์และบรรทัดจุดเริ่มไล่ — ไม่ใช่จุดที่ต้องแก้เสมอไป

Flutter ยังพิมพ์ต่ออีกหลายบรรทัดพร้อมคำแนะนำ ซึ่งคนส่วนใหญ่ข้ามไป — การอ่านให้จบมักบอกคำตอบมาแล้ว

5. จำแนกสาเหตุ

รูปแบบสาเหตุบทที่แก้
Row + ข้อความยาวข้อความไม่มีขอบเขต2.3 + 2.11
Column + เนื้อหาสูงเกินจอไม่มีใครรับหน้าที่เลื่อน2.6
การ์ดที่ล็อกความสูง + ตัวอักษรใหญ่สมมติความสูงผิด2.9
พื้นที่เลื่อนซ้อนกันไม่มีขอบเขตในแกนที่เลื่อน2.1 + 2.6
แป้นพิมพ์ขึ้นแล้วล้นพื้นที่ลดลงแต่เนื้อหาเลื่อนไม่ได้2.9
ล้นเฉพาะบางรายการข้อมูลจริงยาวกว่าข้อมูลทดสอบ2.11

6. ลำดับการตัดสินใจ

ถามตามลำดับนี้ แล้วหยุดที่ข้อแรกที่ตอบว่าใช่

  1. เนื้อหาชิ้นนี้ควรยืดหดได้ไหม → ห่อด้วย Expanded หรือ Flexible (2.3)
  2. ควรขึ้นบรรทัดใหม่หรือตัดข้อความไหม → ตั้ง maxLines และ overflow (2.11)
  3. ทั้งส่วนนี้ควรเลื่อนได้ไหม → ใช้พื้นที่เลื่อน (2.6)
  4. มีข้อมูลรองที่ซ่อนได้ไหม → ซ่อนเมื่อจอแคบ (2.10)
  5. มีขนาดตายตัวที่ไม่มีเหตุผลไหม → เอาออก
  6. จำเป็นต้องย่อขนาดจริง ๆ ไหม → ย่อเฉพาะข้อความรอง ในช่วงที่ยังอ่านออก
ถ้าตอบว่า “ใช่” ตั้งแต่ข้อ 1 หรือ 2 แต่ข้ามไปแก้ข้อ 6 คุณจะได้หน้าจอที่ไม่มีแถบเหลืองแต่ใช้งานยากขึ้น — ซึ่งแย่กว่าเดิม เพราะแถบเหลืองอย่างน้อยก็บอกว่ามีปัญหา

7. ทางแก้ที่เป็นการซ่อนปัญหา

วิธีแถบหายไหมปัญหาที่ยังอยู่
ClipRect ครอบไว้หายเนื้อหายังถูกตัด และปุ่มที่ถูกตัดกดไม่ได้
ห่อทุกอย่างด้วยพื้นที่เลื่อนหายเกิดพื้นที่เลื่อนซ้อนกัน และปุ่มสำคัญเลื่อนหาย
ห่อทุกตัวด้วย Expandedหายไอคอนและปุ่มถูกยืดผิดสัดส่วน (2.3)
FittedBox ครอบทั้งแถวหายทุกอย่างเล็กลงรวมถึงปุ่ม จนกดไม่โดน (2.4)
ปิดการปรับขนาดตัวอักษรหายผู้ใช้ที่ต้องการตัวอักษรใหญ่ใช้ไม่ได้ (2.9)

ClipRect อันตรายที่สุดในตาราง เพราะแถบเตือนหายไปสนิทและหน้าจอดูปกติ แต่ข้อมูลบางส่วนหายไปเงียบ ๆ — ตรงกับเหตุผลที่ 2.11 บอกว่าอย่าใช้ clip กับข้อความ

8. ทดสอบไม่ให้กลับมาอีก

เมื่อแก้แล้ว ให้เขียนเทสต์ที่จับปัญหานี้ได้ ไม่งั้นอีกสามเดือนจะกลับมา

testWidgets('ชื่อสินค้ายาวไม่ทำให้ layout ล้น', (tester) async {
  await pumpAtWidth(tester, 360);

  // ถ้าเกิด RenderFlex overflow เฟรมเวิร์กจะบันทึกเป็น exception
  expect(tester.takeException(), isNull);
});

tester.takeException() คือกุญแจ — เมื่อเกิดเนื้อหาล้น Flutter บันทึกเป็นข้อผิดพลาดไว้ เทสต์จึงจับได้แม้ไม่ได้ดูหน้าจอ

ชุดขนาดที่ควรทดสอบ

ทดสอบอะไรค่าที่ควรใช้
ความกว้างแคบสุดที่รองรับ320
ค่าใกล้จุดตัดทั้งสองฝั่ง479 และ 481
ความสูงเมื่อแป้นพิมพ์ขึ้นประมาณครึ่งหนึ่งของจอ
ข้อมูลที่ยาวที่สุดที่เป็นไปได้ชื่อสินค้า 200 ตัวอักษร
ขนาดตัวอักษรใหญ่สุดที่รองรับตัวคูณ 2.0

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ใส่ Expanded แล้วยังล้นใส่ผิดตัว — ตัวที่กินพื้นที่จริงยังไม่ยืดหยุ่นดูว่าใครในขั้นที่ 1 ของ 2.3 กินเยอะ
แก้แล้วบนจอกว้าง แต่ยังล้นบนจอแคบทดสอบขนาดเดียวทดสอบที่ 320 เสมอ
ล้นเฉพาะข้อมูลบางรายการข้อมูลทดสอบสั้นกว่าข้อมูลจริงทดสอบด้วยค่าที่ยาวที่สุดที่เป็นไปได้
แถบหายแต่ปุ่มกดไม่ได้ใช้ ClipRect ซ่อนย้อนกลับไปแก้ที่ขอบเขต
ล้นหลังปล่อยแอปไปแล้วผู้ใช้ตั้งตัวอักษรใหญ่ทดสอบตัวคูณ 2.0
แก้ตรงที่เห็นแถบแล้วไม่หายต้นเหตุอยู่ที่แม่ไล่ขึ้นไปดูว่าใครล็อกขนาดไว้

10. แบบฝึกหัด

ช่องเมนูบนหน้าแรกล็อกความสูงไว้ 80 และมีไอคอน หัวข้อ 2 บรรทัด คำอธิบาย 2 บรรทัด และลูกศรด้านขวา ผู้ใช้บางคนรายงานว่าเห็นแถบสีเหลืองดำที่ทุกช่อง

  1. ไล่หาสาเหตุอย่างเป็นระบบ ต้องดูอะไรบ้าง
  2. แก้ตามลำดับความสำคัญของข้อมูล
  3. เขียนเทสต์กันไม่ให้กลับมา
ดูแนวคำตอบและเหตุผล

ข้อ 1 — ไล่หาสาเหตุ

ตรวจอะไรเพราะอะไร
ทิศทางที่ล้นล้นด้านล่างแปลว่าเป็น Column ในช่อง ไม่ใช่ Row
ผู้ใช้ที่รายงานตั้งขนาดตัวอักษรเท่าไรคำว่า “ผู้ใช้บางคน” เป็นเบาะแสสำคัญ — ถ้าล้นทุกคนจะเจอตั้งแต่ตอนพัฒนา
ความสูง 80 มาจากไหนถ้าเป็นเลขที่ใครสักคนใส่ไว้เฉย ๆ แปลว่าไม่มีเหตุผลรองรับ
ข้อมูลจริงยาวแค่ไหนคำอธิบายที่มาจากฐานข้อมูลอาจยาวกว่าที่ทดสอบ

คำว่า “ผู้ใช้บางคน” ชี้ไปที่สาเหตุเกือบแน่นอนคือ ขนาดตัวอักษรที่ผู้ใช้ตั้งเอง ตามที่เตือนไว้ใน 2.7 และ 2.9 — ข้อความสี่บรรทัดที่พอดีในความสูง 80 ที่ตัวคูณ 1.0 จะต้องการประมาณ 104 ที่ตัวคูณ 1.3

ข้อ 2 — แก้ตามลำดับ

ไล่ตามลำดับในหัวข้อ 6 จะได้คำตอบตั้งแต่ข้อ 4 และ 5

// เดิม — ล็อกความสูงตายตัว
SizedBox(
  height: 80,
  child: Column(
    children: [
      Row(children: [Icon(...), Expanded(child: Text(title, maxLines: 2)), Icon(Icons.chevron_right)]),
      Text(subtitle, maxLines: 2),
    ],
  ),
)

// แก้ — กำหนดขั้นต่ำแทนความสูงตายตัว และลดข้อมูลรอง
ConstrainedBox(
  constraints: const BoxConstraints(
    minHeight: 80,                    // ขั้นต่ำเพื่อรักษาพื้นที่กด
  ),
  child: Padding(
    padding: const EdgeInsets.all(8),
    child: Row(
      children: [
        Icon(menu.icon, size: 28),
        const SizedBox(width: 12),
        Expanded(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            crossAxisAlignment: CrossAxisAlignment.start,
            children: [
              Text(menu.title, maxLines: 2, overflow: TextOverflow.ellipsis),
              if (!compact)                       // ซ่อนข้อมูลรองเมื่อพื้นที่น้อย
                Text(
                  menu.subtitle,
                  maxLines: 1,                    // ลดจาก 2 เหลือ 1
                  overflow: TextOverflow.ellipsis,
                  style: Theme.of(context).textTheme.bodySmall,
                ),
            ],
          ),
        ),
        const Icon(Icons.chevron_right),
      ],
    ),
  ),
)

เหตุผลของแต่ละการเปลี่ยน

  • เปลี่ยน SizedBox(height: 80) เป็น minHeight: 80 — ยังรักษาพื้นที่กดขั้นต่ำตาม 2.13 แต่ยอมให้สูงขึ้นได้เมื่อตัวอักษรใหญ่ นี่คือการแก้ต้นเหตุ
  • ซ่อนคำอธิบายเมื่อแคบ — เป็นข้อมูลรอง ส่วนหัวข้อคือสิ่งที่ผู้ใช้ใช้ตัดสินใจ (2.11)
  • ลดคำอธิบายเหลือ 1 บรรทัด — ลดความต้องการพื้นที่ลงครึ่งหนึ่ง
  • ไม่ลดขนาดไอคอนหรือลูกศร — เพราะเป็นสิ่งที่บอกว่ากดได้

ข้อ 3 — เทสต์กันไม่ให้กลับมา

testWidgets('ช่องเมนูไม่ล้นแม้ผู้ใช้ตั้งตัวอักษรใหญ่', (tester) async {
  tester.view.physicalSize = const Size(320, 640);
  tester.view.devicePixelRatio = 1.0;
  addTearDown(tester.view.reset);

  await tester.pumpWidget(
    MediaQuery(
      // จำลองผู้ใช้ที่ตั้งขนาดตัวอักษร 200%
      data: const MediaQueryData(textScaler: TextScaler.linear(2.0)),
      child: const MaterialApp(home: MenuScreen()),
    ),
  );
  await tester.pumpAndSettle();

  expect(tester.takeException(), isNull);
});

ทำไมเทสต์นี้มีค่ามาก: เพราะปัญหานี้ ไม่มีทางเจอ ตอนพัฒนา นักพัฒนาไม่มีใครตั้งตัวอักษร 200% บนเครื่องตัวเอง เทสต์จึงเป็นทางเดียวที่จะจับได้ก่อนถึงมือผู้ใช้ — และเป็นตัวอย่างของสิ่งที่ 2.14 หัวข้อ 8 หมายถึงเมื่อบอกให้ทดสอบตัวคูณ 2.0

ลองต่อ: ย้อนโค้ดกลับไปเป็น SizedBox(height: 80) แล้วรันเทสต์นี้ — ควรเห็นมันล้มเหลว ซึ่งยืนยันว่าเทสต์จับปัญหาได้จริง ไม่ใช่ผ่านเพราะบังเอิญ

11. สรุปท้ายบท

  • แถบสีเหลืองดำวิเคราะห์ได้ ไม่ต้องลองสุ่ม
  • อ่าน error ให้ครบ — มันบอกทิศทาง จำนวนพิกเซล และไฟล์
  • จุดที่เห็นแถบอาจไม่ใช่จุดที่ต้องแก้ ต้องไล่ขึ้นไปหาแม่
  • ไล่ตามลำดับ: ให้ขอบเขต → ตัดข้อความ → ให้เลื่อน → ซ่อนข้อมูลรอง → เอาขนาดตายตัวออก → ย่อเป็นทางสุดท้าย
  • ClipRect ทำให้แถบหายแต่ข้อมูลยังถูกตัด
  • ใช้ tester.takeException() จับปัญหานี้ในเทสต์
  • ทดสอบที่ 320, ค่าใกล้จุดตัด, ข้อมูลยาวสุด และตัวคูณตัวอักษร 2.0
