กฎแกนกลางของ Flutter layout: parent ส่ง constraints ลงไป, child เลือกขนาดภายในกรอบนั้น, แล้ว parent เลือกตำแหน่งให้ child หากเข้าใจกฎนี้จะวิเคราะห์ overflow, unbounded size และหน้าจอ PDA ที่ผิดสัดส่วนได้โดยไม่เดาสุ่ม

1. BoxConstraints บอกช่วง ไม่ใช่ขนาดตายตัว

BoxConstraints(
  minWidth: 0,
  maxWidth: 360,
  minHeight: 0,
  maxHeight: 640,
)

Child เลือกได้เฉพาะขนาดที่อยู่ในช่วง min–max ถ้า min เท่ากับ max เรียกว่า tight constraint; ถ้ายังมีช่วงให้เลือกเรียกว่า loose constraint ค่า double.infinity ใน child ไม่ได้แปลว่าใหญ่ไม่สิ้นสุด แต่แปลว่าเอา max ที่ parent อนุญาต

2. Constraints go down, sizes go up, parents set positions

  1. Scaffold/viewport กำหนดพื้นที่ให้ body
  2. Column ส่ง constraint ให้ลูกแต่ละตัว
  3. ลูกคำนวณและส่ง size กลับ
  4. Column รวม size แล้วจัดตำแหน่งตาม main/cross axis

Layout เป็นคนละ phase กับ build: build สร้าง configuration tree ส่วน layout เจรจาขนาดบน render tree จึงแก้ layout bug ด้วยการดู parent chain ไม่ใช่เพิ่ม Container แบบสุ่ม

3. ตัวอย่างจาก HomeView

LayoutBuilder(
  builder: (context, page) {
    final compact = page.maxHeight < 650;
    final narrow = page.maxWidth <= 400;
    return WarehouseHome(compact: compact, narrow: narrow);
  },
)

Absolute ใช้พื้นที่ที่ parent ส่งให้จริง ไม่ใช่ขนาดจอทั้งเครื่อง จากนั้น LayoutBuilder ชั้นในคำนวณ extent = (maxHeight - gaps) / 3 ทำให้กริดพอดีสามแถวในพื้นที่ที่เหลือหลัง banner

4. Tight กับ loose ที่พบบ่อย

  • SizedBox(width: 48) ส่ง tight width ให้ลูก
  • Center คลาย constraint ให้ลูกเลือกขนาด แล้วจัดกลาง
  • Expanded ส่ง tight constraint ตามพื้นที่ flex ที่ได้รับ
  • Flexible(fit: FlexFit.loose) ให้พื้นที่สูงสุดแต่ child ไม่จำเป็นต้องใช้หมด
  • ConstrainedBox เพิ่ม/ผสานข้อจำกัดกับของ parent

5. Unbounded ไม่ใช่ infinity ทุกทิศ

Scrollable มักส่ง main-axis แบบไม่จำกัดให้ลูก เช่น Column ใน vertical SingleChildScrollView ไม่มี maxHeight ที่ใช้ได้ จึงห้ามวาง Expanded ในนั้นโดยตรง เพราะ Expanded ต้องแบ่ง “พื้นที่ที่เหลือ” แต่พื้นที่เลื่อนไม่มีปลายทาง ส่วน cross-axis ยังอาจถูกบังคับเต็มความกว้างตาม viewport

6. วิธี debug constraints

เริ่มจากข้อความ exception และ widget ที่เป็น nearest relevant ancestor เปิด Flutter Inspector ดู constraints/size แล้วไล่ขึ้นจนพบจุดที่ constraint เปลี่ยน ใช้ debugPrintConstraints ผ่าน LayoutBuilder ชั่วคราวหรือ DevTools Layout Explorer และทดสอบอย่างน้อยจอ 320×568, PDA เป้าหมาย, tablet และ text scale สูง

7. แบบฝึกหัด

Column สูงเต็มจอมี header 72, action 56 และ list ที่ต้องกินพื้นที่ที่เหลือ ควรประกอบอย่างไร?

แนวคำตอบ
Column(children: [
  const Header(),
  const SizedBox(height: 8),
  Expanded(child: ListView.builder(/* ... */)),
  const ActionBar(),
])

Expanded ทำให้ list ได้ bounded height ที่เหลือและเลื่อนภายในตัวเอง ไม่ต้องคำนวณ MediaQuery height ลบเลข magic หลายชุด

8. จุดพลาด

อย่าแก้ overflow ด้วย SingleChildScrollView ครอบทุกอย่างทันที มันอาจซ่อนปัญหา ownership ของพื้นที่, ทำ list ซ้อน scroll และสร้าง child ทั้งหมด ให้ระบุว่าอะไรต้องตรึง อะไรต้องยืด และอะไรต้องเลื่อนก่อนเลือก widget
