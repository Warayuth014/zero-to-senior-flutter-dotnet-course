1. ปัญหาที่บทนี้แก้

ใน 2.2 เราพบว่า spaceBetween ไม่ช่วยเมื่อเนื้อหาล้น และบอกว่าทางแก้คือทำให้ลูกที่ยืดได้ “ได้รับขอบเขต” บทนี้คือเครื่องมือสามตัวที่ทำหน้าที่นั้น

สิ่งสำคัญที่ต้องเข้าใจตั้งแต่ต้น: ทั้งสามตัวใช้ได้เฉพาะเมื่อเป็น ลูกโดยตรง ของ Row หรือ Column เท่านั้น ไม่ใช่เครื่องมือกำหนดขนาดที่ใช้ได้ทั่วไป

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
flex childลูกที่ยอมยืดหดตามพื้นที่ที่เหลือ
non-flex childลูกที่ขอขนาดตามเนื้อหาของตัวเอง
flexตัวเลขสัดส่วนว่าจะได้ส่วนแบ่งเท่าไร
FlexFit.tightต้องใช้ส่วนแบ่งให้เต็ม
FlexFit.looseใช้ไม่เกินส่วนแบ่ง แต่จะน้อยกว่าก็ได้

3. Mental model: วัดของที่ตายตัวก่อน แล้วค่อยแบ่งที่เหลือ

Row และ Column ทำงานตามลำดับนี้เสมอ

1. วัดลูกที่ไม่ยืดหยุ่นทั้งหมดก่อน   (ไอคอน ปุ่ม ช่องว่างคงที่)
2. เอาพื้นที่ทั้งหมด ลบด้วยผลรวมข้างบน  → ได้ "พื้นที่ที่เหลือ"
3. แบ่งพื้นที่ที่เหลือให้ลูกที่ยืดหยุ่น ตามค่า flex
4. วางทุกคนตามตำแหน่ง
ประโยคเดียวที่ต้องจำ: เนื้อหาล้นเกิดขึ้นเมื่อ ขั้นที่ 1 กินพื้นที่หมดตั้งแต่ยังไม่ถึงขั้นที่ 3 — จึงต้องหาให้เจอว่าใครในขั้นที่ 1 กินเยอะเกิน แล้วย้ายมันมาเป็นลูกที่ยืดหยุ่น

4. Expanded: ต้องใช้ส่วนแบ่งให้เต็ม

Row(
  children: [
    Expanded(flex: 2, child: LeftPane()),    // ได้ 2 ส่วน
    const SizedBox(width: 8),
    Expanded(child: RightPane()),            // ได้ 1 ส่วน (flex เริ่มต้น = 1)
  ],
)

พื้นที่ที่เหลือหลังหักช่องว่าง 8 จะถูกแบ่ง 2:1 และทั้งคู่ ต้อง ใช้ส่วนแบ่งเต็ม แม้เนื้อหาจะสั้นกว่านั้น

ดูของจริงใน lab — แถบสรุปเมื่อจอกว้าง

Row(
  children: [
    Expanded(child: cells[0]),
    const SizedBox(width: 8),
    Expanded(child: cells[1]),
  ],
)

ผลคือการ์ดสองใบกว้างเท่ากันเสมอ ไม่ว่าข้อความข้างในจะสั้นยาวต่างกันแค่ไหน ซึ่งเป็นสิ่งที่ต้องการสำหรับแถบสรุป

5. Flexible: ไม่เกินส่วนแบ่ง แต่ไม่ต้องเต็ม

Row(
  children: [
    const Icon(Icons.warehouse),
    const SizedBox(width: 8),
    Flexible(child: Text(label, maxLines: 2)),
  ],
)
ExpandedFlexible
ใช้ส่วนแบ่งเต็มเสมอไม่เกิน แต่น้อยกว่าได้
เนื้อหาสั้นยังกว้างเต็มส่วนแบ่งหดตามเนื้อหา
เนื้อหายาวจำกัดที่ส่วนแบ่งจำกัดที่ส่วนแบ่ง
เหมาะกับแผงหรือการ์ดที่ต้องกว้างเท่ากันข้อความหรือป้ายที่ควรพอดีเนื้อหา

วิธีจำ: Expanded คือ Flexible ที่ตั้ง fit: FlexFit.tight ไว้ให้แล้ว — ทั้งคู่ทำหน้าที่ “ป้องกันการล้น” ได้เหมือนกัน ต่างกันแค่ตอนที่เนื้อหาสั้นกว่าพื้นที่

6. Spacer: ช่องว่างที่ยืดได้

Row(
  children: [
    Chip(label: Text(line.location)),
    const Spacer(),          // ดันทุกอย่างหลังจากนี้ไปขวาสุด
    FilledButton(onPressed: () {}, child: const Text('ยืนยัน')),
  ],
)

Spacer() คือ Expanded ที่ไม่มีเนื้อหา ใช้ดันของไปคนละฝั่งโดยไม่ต้องคำนวณระยะเอง

ถ้าใช้ Spacer พร้อมกับ mainAxisAlignment: MainAxisAlignment.spaceBetween ค่า alignment จะแทบไม่มีผล เพราะ Spacer กินพื้นที่ที่เหลือไปหมดแล้วตั้งแต่ขั้นที่ 3 ไม่เหลืออะไรให้ alignment แจก — เลือกใช้อย่างใดอย่างหนึ่ง

7. กฎที่ทำให้พังบ่อยที่สุด: ต้องเป็นลูกโดยตรง

// ผิด — มี Padding คั่นอยู่
Row(
  children: [
    Padding(
      padding: const EdgeInsets.all(8),
      child: Expanded(child: Text(name)),    // error!
    ),
  ],
)

// ถูก — สลับลำดับ ให้ Expanded อยู่นอกสุด
Row(
  children: [
    Expanded(
      child: Padding(
        padding: const EdgeInsets.all(8),
        child: Text(name),
      ),
    ),
  ],
)

เหตุผล: Expanded ไม่ได้กำหนดขนาดด้วยตัวเอง มันเพียง ติดป้ายบอก Row ว่า “ลูกคนนี้ยืดได้” ป้ายนั้นจะสื่อสารได้ก็ต่อเมื่อ Row เห็นมันโดยตรง ถ้ามีอะไรคั่นอยู่ ป้ายก็ไปไม่ถึง

ข้อความ error ที่จะเจอคือ Incorrect use of ParentDataWidget ซึ่งอ่านแล้วไม่รู้เรื่อง แต่ทุกครั้งที่เจอ ให้ตรวจข้อเดียวนี้ก่อน — มีอะไรคั่นระหว่าง Expanded กับ Row/Column หรือเปล่า

ข้อยกเว้นที่คั่นได้คือ widget ที่เราเขียนเองแบบ StatelessWidget ที่คืน Expanded ออกมาโดยตรง เพราะมันไม่ได้สร้างชั้นในการจัดวางจริง

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
Incorrect use of ParentDataWidgetมี widget คั่นระหว่าง Expanded กับ Rowสลับให้ Expanded อยู่นอกสุด
RenderFlex overflowed ทั้งที่ใส่ Expanded แล้วใส่ผิดตัว — ตัวที่กินพื้นที่จริงยังไม่ยืดหยุ่นหาว่าใครในขั้นที่ 1 กินเยอะแล้วห่อตัวนั้น
ครอบ Expanded ทุกตัวแล้วไอคอนยืดผิดรูปบังคับให้ทุกคนกว้างเท่ากันห่อเฉพาะตัวที่ควรยืดจริง
non-zero flex but incoming height constraints are unboundedใช้ Expanded ในที่ที่เลื่อนได้ดู 2.1 หัวข้อ 5
ใช้ Spacer แล้ว spaceBetween ไม่ทำงานทั้งคู่แย่งพื้นที่ที่เหลือกันเลือกใช้อย่างใดอย่างหนึ่ง
สองการ์ดกว้างไม่เท่ากันทั้งที่อยากให้เท่าใช้ Flexible แทน Expandedเปลี่ยนเป็น Expanded

9. แบบฝึกหัด

โค้ดนี้เกิดแถบสีเหลืองดำบนจอกว้าง 320 จงหาสาเหตุและแก้

Row(
  mainAxisAlignment: MainAxisAlignment.spaceBetween,
  children: [
    const Icon(Icons.inventory_2_outlined, size: 32),
    Text('กล่องกระดาษลูกฟูก ขนาดใหญ่พิเศษ สำหรับงานส่งออก'),
    Text('12'),
    FilledButton(onPressed: () {}, child: const Text('ยืนยัน')),
  ],
)
  1. อธิบายว่าทำไมถึงล้น โดยอ้างขั้นตอนทั้งสี่ในหัวข้อ 3
  2. แก้โดยให้ชื่อสินค้าเป็นตัวที่ยอมเสียพื้นที่
  3. อธิบายว่าทำไมไม่ควรห่อทุกตัวด้วย Expanded
ดูแนวคำตอบและเหตุผล

ข้อ 1 — ทำไมล้น

ในขั้นที่ 1 Row วัดลูกทั้งสี่ตัว และไม่มีตัวไหนเป็นลูกที่ยืดหยุ่นเลย ข้อความชื่อสินค้าจึงขอความกว้างตามเนื้อหาเต็ม ๆ ซึ่งอาจเป็น 400 พิกเซล เมื่อรวมกับไอคอน 32 จำนวน และปุ่ม ผลรวมเกิน 320 ไปแล้วตั้งแต่ขั้นที่ 1

พอถึงขั้นที่ 2 “พื้นที่ที่เหลือ” จึงติดลบ ขั้นที่ 3 ไม่มีอะไรให้แบ่ง และ spaceBetween ในขั้นที่ 4 ก็ไม่มีพื้นที่ให้จัดการ — จบด้วยแถบสีเหลืองดำ

ข้อ 2 — วิธีแก้

Row(
  children: [
    const Icon(Icons.inventory_2_outlined, size: 32),
    const SizedBox(width: 12),
    Expanded(                                   // ตัวเดียวที่ยอมเสียพื้นที่
      child: Text(
        'กล่องกระดาษลูกฟูก ขนาดใหญ่พิเศษ สำหรับงานส่งออก',
        maxLines: 1,
        overflow: TextOverflow.ellipsis,
      ),
    ),
    const SizedBox(width: 8),
    const Text('12'),
    const SizedBox(width: 8),
    FilledButton(onPressed: () {}, child: const Text('ยืนยัน')),
  ],
)

สังเกตสามอย่างที่เปลี่ยนไป

  • เอา spaceBetween ออก เพราะเราคุมช่องว่างเองด้วย SizedBox ซึ่งคาดเดาได้กว่า
  • ห่อชื่อสินค้าด้วย Expanded ทำให้มันได้ขอบเขตที่แคบลงจริง
  • เพิ่ม overflow: TextOverflow.ellipsis เพราะแค่ Expanded อย่างเดียวจะได้แถบเหลืองที่ตัว Text แทน — ต้องบอกด้วยว่าให้ตัดข้อความอย่างไร (รายละเอียดใน 2.11)

ข้อ 3 — ทำไมไม่ห่อทุกตัว

ถ้าห่อทุกตัวด้วย Expanded พื้นที่จะถูกแบ่งเท่า ๆ กันสี่ส่วน ผลคือ

ตัวผลที่เกิด
ไอคอน 32 พิกเซลถูกยืดให้กว้าง 80 พิกเซล เหลือช่องว่างรอบตัวเยอะผิดปกติ
จำนวน “12”ได้พื้นที่ 80 ทั้งที่ต้องการแค่ 20
ปุ่มยืนยันถูกบีบเหลือ 80 ซึ่งอาจแคบเกินไปจนข้อความถูกตัด
ชื่อสินค้าได้แค่ 80 ทั้งที่เป็นตัวที่ควรได้มากที่สุด

แถบเหลืองหายไปจริง แต่หน้าตาผิดหมด — นี่คือความหมายของประโยคใน 2.2 ที่ว่า การตัดสินใจว่าใครยอมเสียพื้นที่เป็นหน้าที่ของเรา ไม่ใช่ของเฟรมเวิร์ก

ลองต่อ: ในไฟล์ lab ให้ลบ Expanded ที่ห่อ Column ของชื่อสินค้าออก แล้วรันเทสต์ flutter test --no-pub test/layout_basics_test.dart — เทสต์ “ชื่อสินค้ายาวไม่ทำให้ layout ล้น” จะล้มเหลวทันที นั่นคือตัวอย่างของเทสต์ที่จับปัญหา layout ได้จริง

10. สรุปท้ายบท

  • Flex วัดลูกที่ไม่ยืดหยุ่นก่อน แล้วค่อยแบ่งพื้นที่ที่เหลือ
  • เนื้อหาล้นเกิดเมื่อลูกที่ไม่ยืดหยุ่นกินพื้นที่หมดตั้งแต่ต้น
  • Expanded ใช้ส่วนแบ่งเต็มเสมอ
  • Flexible ใช้ไม่เกินส่วนแบ่ง แต่หดตามเนื้อหาได้
  • Spacer คือช่องว่างที่ยืดได้ ใช้ดันของไปคนละฝั่ง
  • ทั้งสามตัวต้องเป็นลูกโดยตรงของ Row/Column
  • ห่อเฉพาะตัวที่ควรยืดจริง อย่าห่อทุกตัว

บทถัดไป: 2.4 จะดูเครื่องมือจัดระยะและตำแหน่งที่ใช้บ่อยที่สุด — Padding, Align และ SizedBox รวมถึงข้อควรระวังเรื่องระยะขอบที่ซ้อนกัน
