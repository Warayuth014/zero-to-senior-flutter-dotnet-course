Card, Chip และ Badge ไม่ใช่เพียง decoration แต่เป็นภาษา visual hierarchy/status ที่ต้องใช้สม่ำเสมอ สีต้องเสริมข้อความและ icon ไม่เป็นช่องทางเดียวในการสื่อความหมาย

1. Card เป็น grouping boundary

ใช้ Card/PdaCard รวมข้อมูลและ action ที่เกี่ยวข้องหนึ่งหน่วย มี padding, radius, border/elevation ตาม design token อย่าใส่ Card ซ้อน Card โดยไม่มี hierarchy เพราะเพิ่ม noise และกินพื้นที่ PDA

2. Chip ใช้กับ metadata/action เล็ก

  • Chip: label/status แบบอ่านอย่างเดียว
  • FilterChip/ChoiceChip: เลือกตัวกรอง/ตัวเลือก
  • ActionChip: action รองสั้น ๆ
  • InputChip: entity ที่เพิ่ม/ลบได้

อย่าเลียนแบบ chip ด้วย Container หากต้องการ semantics/interaction ของ Material แต่ custom PdaChip ใช้ได้เมื่อเป็น read-only status และมี contrast/semantics ครบ

3. Badge คือข้อมูลรองขนาดสั้น

จำนวนงานค้างบน menu tile เป็น badge ที่ดี: ซ่อนได้เมื่อศูนย์, จำกัดรูปแบบเช่น 99+, มี semantic label “งานค้าง 120” และไม่บัง icon/title Absolute ส่ง count และ badgeColor ตามโดเมนให้ tile

4. Status color mapping

sealed class TaskStatusStyle {
  static (Color, IconData, String) of(TaskStatus s) => switch (s) {
    TaskStatus.ready => (Colors.blue, Icons.play_arrow, 'พร้อมทำ'),
    TaskStatus.done  => (Colors.green, Icons.check, 'เสร็จแล้ว'),
    TaskStatus.error => (Colors.red, Icons.error, 'ผิดพลาด'),
  };
}

Map จาก domain status ที่เดียว ไม่กระจาย if/color ในหลาย screen และส่ง label/icon คู่สีเสมอ

5. Contrast และ dark mode

ตรวจ contrast ของ foreground/background ใน light/dark, disabled และ pressed state สีที่ใช้ alpha ต่ำบนพื้นต่างกันอาจอ่านไม่ได้ ใช้ ColorScheme semantic roles หรือ design tokens และทดสอบเครื่อง PDA จริงที่ความสว่างต่ำ/กลางแจ้ง

6. ตัวอย่าง PdaCard

Absolute PdaCard ใช้ surface ขาว, border, shadow เบา, radius กลาง และ optional left accent 4px เพื่อแยกสถานะโดยไม่เปลี่ยนโครง SecTitle ใช้แถบสี + text และ PdaChip ใช้พื้นโปร่ง/ขอบจากสีเดียวกัน นี่คือ component vocabulary ที่ reuse ได้

7. แบบฝึกหัด

ออกแบบสถานะ task 4 ค่า: waiting, active, done, failed ให้ผู้ใช้ตาบอดสีแยกได้

แนวคำตอบ

ใช้ label ชัด + icon ต่างรูป + สี semantic + optional border/pattern: waiting=นาฬิกา, active=ลูกศร/กำลังทำ, done=check, failed=error พร้อม semantic value และอย่าใช้เขียว/แดงเป็นสัญญาณเดียว ทดสอบ grayscale/high contrast

8. จุดพลาด

อย่าใช้สี accent คนละความหมายระหว่างหน้า เช่นส้มหมายถึง warning ในหน้า A แต่ done ในหน้า B สร้าง status policy กลางและแยกสี brand/navigation ออกจากสีสถานะธุรกิจ
