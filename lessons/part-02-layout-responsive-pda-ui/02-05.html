1. ปัญหาที่บทนี้แก้

Row และ Column วางของเรียงกันโดยไม่ทับกัน แต่บาง UI ต้องซ้อนจริง ๆ

  • จุดสีแดงแจ้งเตือนมุมบนขวาของไอคอน
  • ป้าย “ด่วน” ทับมุมการ์ด
  • แผ่นบังทั้งหน้าจอพร้อมวงกลมหมุนระหว่างบันทึกข้อมูล

ทั้งสามอย่างมีลักษณะร่วมกันคือ ตัวที่ซ้อนอยู่ไม่ได้เบียดพื้นที่ของตัวอื่น ซึ่งเป็นเกณฑ์ตัดสินว่าควรใช้ Stack หรือไม่

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
non-positioned childลูกที่ไม่ได้ระบุตำแหน่ง — เป็นตัวกำหนดขนาดของ Stack
Positionedตัวห่อที่ระบุว่าลูกอยู่ห่างจากขอบเท่าไร
clipBehaviorจะตัดส่วนที่ล้นออกนอกขอบหรือไม่
hit testการตัดสินว่าการแตะจอโดน widget ตัวไหน
overlayชั้นที่ลอยอยู่เหนือหน้าจอทั้งหมด

3. Mental model: กระดาษวางซ้อนกัน

Stack คือกองกระดาษ — ตัวแรกในรายการอยู่ล่างสุด ตัวสุดท้ายอยู่บนสุด

Stack(
  children: [
    A,   // ล่างสุด
    B,
    C,   // บนสุด ทับ A และ B
  ],
)

ขั้นตอนการทำงานมีสองรอบ

  1. วัด ลูกที่ไม่ได้ระบุตำแหน่ง ทั้งหมดก่อน → ตัวที่ใหญ่ที่สุดกำหนดขนาดของ Stack
  2. วาง ลูกที่ระบุตำแหน่ง ลงไปทีหลัง โดยอ้างขนาดที่ได้จากขั้นที่ 1
ประโยคเดียวที่ต้องจำ: Stack ต้องมีลูกที่ไม่ได้ระบุตำแหน่งอย่างน้อยหนึ่งตัวเป็น “เจ้าของขนาด” เสมอ — ถ้าทุกตัวเป็น Positioned หมด Stack จะไม่รู้ว่าตัวเองใหญ่แค่ไหน

4. ดูของจริงใน lab

เปิด lib/layout_basics/layout_basics_app.dart ที่ส่วนไอคอนกับจุดแจ้งเตือน

Stack(
  clipBehavior: Clip.none,
  children: [
    const Icon(Icons.inventory_2_outlined, size: 32),   // เจ้าของขนาด
    if (line.urgent)
      Positioned(
        right: -2,
        top: -2,
        child: Container(
          width: 12,
          height: 12,
          decoration: BoxDecoration(
            color: theme.colorScheme.error,
            shape: BoxShape.circle,
          ),
        ),
      ),
  ],
)

สังเกตสามอย่าง

สิ่งที่เห็นความหมาย
Icon ไม่มี Positionedมันเป็นเจ้าของขนาด — Stack จึงเป็น 32×32
right: -2, top: -2ค่าติดลบ = ล้นออกนอกขอบไปเล็กน้อย
clipBehavior: Clip.noneอนุญาตให้วาดล้นออกนอกขอบได้

ถ้าไม่ใส่ Clip.none จุดสีแดงจะถูกตัดครึ่งตรงขอบไอคอน เพราะค่าเริ่มต้นของ Stack คือตัดส่วนที่ล้นทิ้ง

และสังเกตว่าเราใช้ if (line.urgent) ใน children โดยตรง — นั่นคือ collection if จาก D1.5 ที่ใช้จริง

5. Positioned: กำหนดกี่ด้านก็มีความหมายต่างกัน

ระบุผล
top อย่างเดียวลูกเลือกความสูงเอง วางห่างจากบนตามที่ระบุ
top และ bottomความสูงถูกบังคับตามพื้นที่ที่เหลือ
left และ rightความกว้างถูกบังคับ
Positioned.fillเต็มทั้งสี่ด้าน ใช้กับแผ่นบัง
Stack(
  children: [
    const WorkflowBody(),                 // เจ้าของขนาด
    if (busy)
      const Positioned.fill(
        child: ColoredBox(
          color: Color(0x55000000),
          child: Center(child: CircularProgressIndicator()),
        ),
      ),
  ],
)
แผ่นบังที่ทำครึ่ง ๆ กลาง ๆ อันตราย — แผ่นสีเทาโปร่งแสงบังตาได้ แต่ ไม่ได้กันการแตะ ผู้ใช้ยังกดปุ่มที่อยู่ข้างล่างได้ทะลุผ่านไป ทำให้เกิดรายการซ้ำทั้งที่หน้าจอดูเหมือนกำลังโหลดอยู่ ถ้าต้องกันการแตะจริงต้องใช้ AbsorbPointer หรือ ModalBarrier ครอบ

6. การแตะกับส่วนที่วาดล้น

เมื่อใช้ Clip.none ส่วนที่วาดล้นออกนอกขอบ จะมองเห็นแต่กดไม่โดน เพราะการตัดสินว่าแตะโดนอะไรยังใช้ขอบเขตจริงของ Stack

นี่ไม่ใช่ปัญหาสำหรับจุดแจ้งเตือนใน lab เพราะมันเป็นแค่การตกแต่ง ไม่ต้องกด แต่ถ้าวันหนึ่งอยากให้กดจุดนั้นแล้วเปิดรายละเอียด จะพบว่ากดไม่ได้ และหาสาเหตุยากมากเพราะตาเห็นอยู่ชัด ๆ

ทางแก้คือขยายขอบเขตของเจ้าของขนาดให้ครอบคลุมสิ่งที่ต้องกดได้ แทนที่จะพึ่งการวาดล้น

SizedBox(
  width: 48, height: 48,          // ขอบเขตที่กดได้จริง
  child: Stack(
    alignment: Alignment.center,
    children: [
      const Icon(Icons.inventory_2_outlined, size: 32),
      Positioned(top: 4, right: 4, child: badge),   // อยู่ในขอบเขต
    ],
  ),
)

7. เมื่อไหร่ที่ไม่ควรใช้ Stack

สถานการณ์ใช้ Stack ไหมควรใช้อะไรแทน
จุดแจ้งเตือนบนไอคอนใช่—
ป้ายทับมุมการ์ดใช่—
แผ่นบังระหว่างโหลดในหน้าจอเดียวใช่—
จัดวางฟอร์มทั้งหน้าด้วยพิกัดคงที่ไม่Column + Expanded
กล่องโต้ตอบหรือเมนูที่ต้องลอยเหนือทั้งแอปไม่showDialog, showMenu (Part 5)
ข้อความแจ้งเตือนชั่วคราวด้านล่างไม่ScaffoldMessenger (5.10)
การจัดหน้าจอด้วย Positioned(top: 120, left: 16) ดูเหมือนควบคุมได้แม่นยำ แต่จะพังทันทีเมื่อแป้นพิมพ์ขึ้น เมื่อหมุนจอ เมื่อเปิดบนแท็บเล็ต หรือเมื่อผู้ใช้ตั้งขนาดตัวอักษรใหญ่ขึ้น — ใช้ระบบ constraint ตาม 2.1 สำหรับการจัดวางปกติเสมอ และเก็บ Stack ไว้ใช้เฉพาะเมื่อของซ้อนกันจริง

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
จุดแจ้งเตือนถูกตัดครึ่งค่าเริ่มต้นตัดส่วนที่ล้นใส่ clipBehavior: Clip.none
Stack มีขนาดเป็นศูนย์ลูกทุกตัวเป็น Positionedต้องมีลูกที่ไม่ระบุตำแหน่งอย่างน้อยหนึ่ง หรือกำหนดขนาดให้ Stack
เห็นอยู่แต่กดไม่โดนส่วนนั้นอยู่นอกขอบเขตจริงขยายขอบเขตของเจ้าของขนาด
กดทะลุแผ่นบังได้ระหว่างโหลดแผ่นบังไม่ได้กันการแตะครอบด้วย AbsorbPointer หรือ ModalBarrier
เมนูถูกตัดโดยขอบการ์ดใช้ Stack กับสิ่งที่ต้องลอยเหนือทั้งแอปใช้ showMenu หรือ Overlay
หน้าจอเพี้ยนเมื่อแป้นพิมพ์ขึ้นจัดวางด้วยพิกัดคงที่เปลี่ยนไปใช้ Column และ Expanded

9. แบบฝึกหัด

สร้าง OperatorAvatar ที่แสดงรูปพนักงานพร้อมจุดสถานะออนไลน์มุมล่างขวา โดย

  1. พื้นที่กดได้ต้องเป็น 48×48 เต็ม
  2. จุดสถานะต้องอยู่ในขอบเขตที่กดได้ ไม่ล้นออกไป
  3. กดที่ไหนก็ได้ในพื้นที่ 48×48 ต้องเรียก callback ตัวเดียวกัน
  4. จุดสถานะไม่ใช่ปุ่มแยก

แล้วอธิบายว่าทำไมข้อ 4 ถึงสำคัญ

ดูแนวคำตอบและเหตุผล
class OperatorAvatar extends StatelessWidget {
  const OperatorAvatar({
    super.key,
    required this.initial,
    required this.online,
    required this.onTap,
  });

  final String initial;
  final bool online;
  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;

    return SizedBox(
      width: 48,
      height: 48,                        // 1) ขอบเขตที่กดได้
      child: InkWell(
        onTap: onTap,                    // 3) ตัวเดียวคุมทั้งพื้นที่
        customBorder: const CircleBorder(),
        child: Stack(
          children: [
            // เจ้าของขนาด — เต็ม 48x48
            Center(
              child: CircleAvatar(radius: 20, child: Text(initial)),
            ),
            // 2) อยู่ในขอบเขต ไม่ใช้ค่าติดลบ
            Positioned(
              right: 2,
              bottom: 2,
              // 4) เป็นการตกแต่ง ไม่รับการแตะ
              child: IgnorePointer(
                child: Container(
                  width: 12,
                  height: 12,
                  decoration: BoxDecoration(
                    color: online ? Colors.green : scheme.outline,
                    shape: BoxShape.circle,
                    border: Border.all(color: scheme.surface, width: 2),
                  ),
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

ทำไมข้อ 4 สำคัญ

ถ้าจุดสถานะรับการแตะเอง จะเกิดปัญหาสามอย่าง

  1. มีพื้นที่ตายเล็ก ๆ — เมื่อผู้ใช้กดโดนจุด 12×12 พอดี การแตะจะถูกจุดนั้นรับไว้และไม่ส่งต่อไปที่ InkWell ผลคือกดแล้วไม่มีอะไรเกิดขึ้น ซึ่งดูเหมือนแอปค้าง
  2. เกิดเฉพาะบางครั้ง — พื้นที่นั้นเล็กมาก จึงเกิดสุ่ม ๆ ทำให้ทั้งผู้ใช้และผู้ทดสอบอธิบายอาการไม่ได้ ยิ่งบน PDA ที่ผู้ใช้ใส่ถุงมือและกดไม่แม่น โอกาสโดนยิ่งสูง
  3. เสียความหมายทางความหมาย — จุดสถานะเป็นข้อมูล ไม่ใช่ปุ่ม ถ้าให้มันรับการแตะ โปรแกรมอ่านหน้าจอจะประกาศว่ามีปุ่มเพิ่มอีกหนึ่งปุ่มโดยไม่มีชื่อ

IgnorePointer แก้ทั้งสามข้อในบรรทัดเดียว โดยบอกว่า “ตัวนี้มีไว้ดู ไม่ต้องส่งการแตะมาที่ฉัน”

ทำไมไม่ใช้ค่าติดลบเหมือนใน lab: เพราะ lab เป็นจุดแจ้งเตือนที่แค่ตกแต่งและอยู่บนไอคอนที่ไม่ต้องกด แต่ข้อนี้พื้นที่ทั้งหมดต้องกดได้ ถ้าให้จุดล้นออกไปนอก 48×48 ส่วนที่ล้นจะมองเห็นแต่กดไม่โดนตามที่อธิบายในหัวข้อ 6

ทำไมมีเส้นขอบสีพื้นหลังรอบจุด: เพื่อให้จุดแยกออกจากรูปด้านหลังได้ชัดแม้สีใกล้กัน — รายละเอียดเล็ก ๆ แบบนี้สำคัญมากบนหน้าจอ PDA ที่ใช้กลางแดดในคลัง

ลองต่อ: เขียนเทสต์ที่แตะตรงตำแหน่งของจุดสถานะพอดี แล้วตรวจว่า onTap ยังถูกเรียก — ถ้าลบ IgnorePointer ออก เทสต์นี้จะล้มเหลว

10. สรุปท้ายบท

  • Stack ใช้เมื่อของซ้อนกันจริงและตัวที่ซ้อนไม่เบียดพื้นที่ใคร
  • ตัวแรกในรายการอยู่ล่างสุด ตัวสุดท้ายอยู่บนสุด
  • ต้องมีลูกที่ไม่ระบุตำแหน่งเป็นเจ้าของขนาดเสมอ
  • Clip.none ให้วาดล้นได้ แต่ส่วนที่ล้นกดไม่โดน
  • แผ่นบังต้องกันการแตะด้วย ไม่ใช่แค่บังตา
  • อย่าจัดหน้าจอทั้งหน้าด้วยพิกัดคงที่
  • ใช้ IgnorePointer กับสิ่งที่เป็นการตกแต่ง
