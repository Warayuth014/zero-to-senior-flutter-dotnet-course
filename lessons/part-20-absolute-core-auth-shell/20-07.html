1. Local UI state

หน้า login ถือ controllers ของ employee/password, focus node ของ password, flag _submitting, password visibility และข้อความ error ทั้งหมดเป็น state อายุสั้นที่ควรตายเมื่อออกจากหน้า ส่วน token/session อยู่ repository เพราะต้องอยู่ต่อถึง shell

2. Submit pipeline

guard duplicate submit
→ validate form
→ unfocus keyboard
→ set loading + clear old error
→ await auth.login(...)
→ if mounted: pushReplacement(WarehouseShell)
→ ApiException: show inline message
→ finally if mounted: stop loading

ลำดับ clear error ก่อน request ทำให้ผู้ใช้ไม่เห็น error เก่าระหว่าง retry และ mounted checks ป้องกัน setState/navigation หลัง widget ถูกถอด

3. Duplicate guard

_submitting ถูกตรวจตั้งแต่ต้นและปิด action ระหว่างรอ ป้องกัน operator กดปุ่มหรือกด Enterซ้ำแล้วสร้าง request สองชุด Guard ที่ UI ช่วย UX แต่ backend login และ mutation สำคัญยังต้องรับมือ request ซ้ำเอง

4. Focus และ scanner/PDA ergonomics

employee field ส่ง focus ไป password, password submit เรียก login และ loading stateลดการกดซ้ำ การ unfocus ก่อน network ทำให้ keyboard ไม่บัง error/dialog บนจอเล็ก Controllers กับ focus node ถูก dispose ครบเพื่อไม่รั่ว listener/native resources

5. ทำไมต้องเปิด Connection Settings ก่อน login

ถ้า IP/port ผิด ผู้ใช้ย่อม login ไม่ได้ ดังนั้น settings เป็น recovery path ที่ต้องเข้าถึงได้ก่อนมี session การซ่อน settings ไว้ใน shell เท่านั้นสร้าง deadlock เชิง UX อย่างไรก็ตาม build ที่ pin URL ควรอธิบายชัดว่า runtime profile ถูก override ไม่ให้ผู้ใช้ลองแก้แล้วไม่เกิดผล

6. Navigation semantics

pushReplacement แทน push ทำให้ Back จาก shell ไม่กลับไปหน้าที่มี password form และ login success เก่า ตอน logout shell ก็ replacement กลับ login ทำให้หนึ่ง session มี root route เดียว หากใช้ named/router ในอนาคตยังต้องรักษา invariant นี้

7. Error taxonomy ใน UI

inline error เหมาะกับ credential/business failure ที่ผู้ใช้แก้ input ได้ ส่วน connection/certificate/server configuration ควรมีข้อความและ action เปิด settings ได้ อย่าแสดง stack trace หรือ response body ดิบ และอย่าแปลงทุก failure เป็น “username/password ผิด” เพราะจะพาผู้ใช้แก้จุดผิด

8. Widget tests

ทดสอบ validation, focus/submit จาก keyboard, loading disables controls, double tap ส่ง requestเดียว, success replacement, failure แสดง inline และ retry ได้, dispose ระหว่าง requestไม่ throw, toggle password, language rebuild และเปิด connection settings ได้โดยยังไม่ login
