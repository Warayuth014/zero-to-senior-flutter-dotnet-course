ไฟล์หลัก: lib/features/warehouse/warehouse_shell.dart และ screens/home_view.dart — shell เป็น composition/lifecycle boundary ของ session หลัง login ไม่ใช่เพียงกรอบ navigation

1. สร้าง store และ adapters

ใน initState shell สร้าง WarehouseStore ด้วย username จาก session และ repositories ReceivingApi, TasksApi, InventoryApi, CycleCountApi ที่ใช้ auth clientตัวเดียว แล้วต่อ callbacksสำหรับ toast/flash นี่ทำให้ screenไม่ต้องรู้ tokenหรือสร้าง network dependencyเอง

2. Fire-and-forget อย่างตั้งใจ

unawaited(store.loadAll()) เริ่มโหลดข้อมูล/badgesโดยไม่ blockเฟรมแรก และ unawaited(ConnectionController.instance.refreshStatus()) probeตอนเข้า shell UIต้องรองรับ loading/errorภายใน store/controller เพราะ exceptionจาก fire-and-forgetห้ามหลุดเงียบ การใช้ unawaited เป็นการประกาศ lifecycle intent ไม่ใช่การละเลย error

3. App lifecycle กับวิทยุ/network

shell implement WidgetsBindingObserver และ probeใหม่เมื่อ AppLifecycleState.resumed เพราะเครื่องอาจออก Wi-Fiหรือ server restartขณะ background ไม่มี repeating timerตลอดวัน จึงลด radio/battery cost แต่ให้ข้อมูลสดในจังหวะที่ผู้ใช้กำลังมอง

4. Cleanup symmetry

initState: addObserver + create store + timersเมื่อใช้งาน
dispose:   removeObserver + cancel toast/flash timers + store.dispose

ทุก register/startต้องมี unregister/stopคู่กัน มิฉะนั้น logout/loginหลายรอบจะมี observer, polling หรือ callbackซ้ำและ setStateบน widgetที่ตายแล้ว

5. Screen state และ rendering

store.screen เลือก title/subtitle, body และ active bottom-nav mapping จาก source of truthเดียว ListenableBuilder rebuild shellเมื่อ store notify และ AnimatedSwitcher ใช้ ValueKey(store.screen) แยก identityของหน้าจอ child flows เช่น recvorder/recvrun mapกลับ Receivingใน nav

6. Operational feedback

storeเรียก onToast และ onFlash; shellแสดง overlayชั่วคราวพร้อม haptic medium/heavyตาม success/error และ cancel timerเก่าก่อนเริ่มใหม่ ทำให้ scanติดกันไม่ปล่อย timerเก่ามาล้าง feedbackใหม่ ต้อง guard mountedใน callback timerและไม่ใช้สี/แรงสั่นเป็นข้อมูลช่องทางเดียว

7. Exit flow กับ logout คนละเรื่อง

เมื่ออยู่ใน workflow headerมี Pause actionพร้อม confirm แล้วเรียก store.exitFlow() เพื่อกลับ listโดยรักษางานตาม domain ส่วน logoutล้าง authแล้ว replacementกลับ login ทั้งคู่ต้องไม่ใช้ navigator backแบบเดียวกัน เพราะ pauseยังอยู่ sessionเดิม แต่ logoutต้องทำลาย session scope

8. Lifecycle test

ฉีด fake store/repositories/probe แล้วทดสอบ loadครั้งเดียว, resume probe, paused/inactiveไม่ probe, disposeยกเลิก timers/observer/store, logout-loginไม่เพิ่ม listenerซ้ำ, child screen mapping/nav badges และ stale async resultไม่อัปเดต shellหลัง logout
