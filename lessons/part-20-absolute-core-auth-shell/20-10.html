ไฟล์หลัก: lib/core/connection_profile.dart คู่กับ test/connection_profile_test.dart — model นี้เป็น anti-corruption layer ระหว่างข้อความที่ผู้ใช้กรอกกับ URL ที่ transport ใช้จริง

1. Profile เป็น typed configuration

หนึ่ง profile มี id, name, environment, protocol, host, port, basePath, created/updated timestamps และคำนวณ baseUrl จากค่าที่ validate แล้ว การเก็บ URL stringก้อนเดียวจะจัดการแก้ port/protocol, duplicate, migration และแสดง field errorได้ยากกว่า

2. Normalize base path

normalizer trim ช่องว่าง, ยุบ slash ซ้ำ, ให้ค่าว่างหรือ path ที่ขึ้นต้น slashและไม่มี slashท้าย ตัวอย่าง ///gateway//wms/ กลายเป็น /gateway/wms ก่อนต่อ route ทำให้ URL deterministic และ snapshotเทียบกันได้

3. Field validation

  • name และ host ต้องไม่ว่าง
  • host ห้ามมี scheme, slash, space หรือ colon/port
  • port ต้องเป็นเลข 1–65535
  • base path ห้ามเป็น URL เต็ม
  • base path ที่เริ่ม /api ถูกปฏิเสธ เพราะ app เติม API route เองและต้องกัน /api/api

error อยู่ระดับ field ทำให้ settings sheetชี้จุดแก้ได้ตรงกว่าปล่อยให้ Uri.parse หรือ socket failภายหลัง

4. JSON decode แบบ defensive

fromJson ทิ้ง row ที่ไม่ใช่ map, id/host ว่าง หรือ portนอกช่วง ใช้ defaultกับ enum/status/timestamp บางค่าแทน crashทั้งแอป หลักสำคัญคือข้อมูล persistedเป็น untrusted input: app versionเก่า, manual edit หรือ storage corruptionเกิดได้

5. Snapshot invariant

profiles และ active selection ถูกเก็บใน JSON snapshot เดียว แต่ละ row มี flag isActive decoder เลือก true ตัวแรก ถ้าไม่มีใช้ profileแรก และ rawเสียคืน collectionว่าง จากนั้น controller seed default profile จึงรักษา invariant “เมื่อใช้งานได้ต้องมี active profileหนึ่งตัว”

6. Build override

resolveBaseUrl ให้ WMS_API_BASE_URL จาก dart-defineชนะ active profile และ built-in fallback พร้อม flag isBaseUrlPinnedByBuild UI ควรใช้ flag นี้อธิบายว่า profileไม่ใช่ effective URL ห้ามปล่อย previewบอกอย่างหนึ่งแต่ requestไปอีกอย่าง

7. Tests บอก design intention

connection_profile_test.dart ครอบคลุม normalization, validation, corrupt snapshot, active fallback, config precedence, controller save/edit/delete/activate และ probe payload จึงทำหน้าที่เป็น executable specification เมื่อ refactor ให้รักษา behaviorตาม testsก่อนเปลี่ยน implementation

8. Property-oriented exercise

เพิ่มชุด input หลายรูปแบบแล้วพิสูจน์ว่า normalizeสองครั้งได้ผลเดิม, baseUrlไม่มี double slashหลัง scheme, portไม่หลุดช่วง, decodeข้อมูลเสียไม่ throw และ encode→decodeรักษา active profileหนึ่งเดียว จากนั้นเพิ่ม migration testสำหรับ snapshot versionถัดไป
