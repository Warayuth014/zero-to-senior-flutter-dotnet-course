2. การออกจากระบบ

void _logout() {
  widget.auth.logout();
  Navigator.of(context).pushReplacement(
    MaterialPageRoute(builder: (_) => LoginScreen(auth: widget.auth)),
  );
}

เดินตามผลของสองบรรทัด

auth.logout()
  ├─ _api.authToken = null      → ทุก repository หมดสิทธิ์พร้อมกัน
  └─ _session = null            → ข้อมูลผู้ใช้หายจากหน่วยความจำ

pushReplacement(LoginScreen)
  └─ WarehouseShell ถูก dispose
       ├─ removeObserver
       ├─ ตัวจับเวลาสองตัวถูกยกเลิก
       └─ store.dispose() → ตัวจับเวลา 5 วินาทีถูกยกเลิก
สี่บรรทัดที่สะอาดเพราะการตัดสินใจในบทก่อน ๆ
สิ่งที่ไม่ต้องทำเพราะ
ล้าง token ในแต่ละ repositoryทั้งสี่ใช้ ApiClient ตัวเดียว (20.5)
ลบข้อมูลผู้ใช้จากดิสก์ไม่เคยเก็บลงดิสก์ (20.5)
รีเซ็ต store ทีละฟิลด์store ถูกทิ้งทั้งตัวพร้อมเปลือก
ล้างกอง routeมีจอเดียวเสมอ (20.7)
เมื่อไล่ดูว่า “ทำไมโค้ดนี้ถึงสั้น” จะเจอว่าความสั้นมาจากโครงสร้าง ไม่ใช่จากการละเลย

5. คำตอบของคำถามจาก 19.15

“โปรเจกต์ที่มี store, มี repository และมีเทสต์ — ปัญหา 15 แถวหายไปกี่แถว และเหลืออะไร”

ไล่ทีละแถวจากสิ่งที่อ่านมาใน Part นี้

#กฎที่ wmsapp เขียนสองแบบที่นี่หลักฐาน
1ส่ง statusCode ต่อจากชั้นเครือข่ายหายApiException ตัวเดียวพก int? (20.4)
2สถานะของ flow เก็บที่ไหนหายอยู่ใน store.screen ที่เดียว (20.14)
3เมนู/แถบบนของแต่ละจอหายเปลือกวาดที่เดียว (บทที่ 1)
4เครื่องมือทดสอบที่หลุดไปกับรุ่นจริงหายไม่มีจอทดสอบเลย
5สถานะที่กดไม่ได้บางส่วน_headerAction ทำถูก แต่ PdaButton รับ null ไม่ได้ (20.13)
6สีของประเภท/สถานะบางส่วนสถานะการเชื่อมต่อมีฟังก์ชันเดียว แต่ green/success ยังซ้ำ (20.9)
7การจับข้อยกเว้นตอนอ่านค่าที่เก็บไว้ยังมีon StateError กับ catch (_) (20.11)
8กล่องยืนยันสำหรับการกระทำเดียวกันยังไม่เกิดมี _ask และ _confirmExit ที่รวมไว้แล้ว

อีกเจ็ดแถวที่เหลือ (เลือกล็อต, จำพาเลทล่าสุด, S/N ครบ, ตรวจสภาพ, ล้างช่องสแกน, แจ้งความสำเร็จ, รูปย่อ) เป็นเรื่องของโดเมนที่ Part 21 และ 22 จะไปดู

สรุปคำตอบเท่าที่หลักฐานถึง

สี่แถวหายชัดเจน สองแถวหายบางส่วน หนึ่งแถวยังมีเหมือนเดิม
และทั้งสี่แถวที่หาย หายด้วยเหตุผลเดียวกัน: มีที่กลางที่ทุกคนต้องผ่าน
  • ApiException ตัวเดียว → ทุกจอได้ statusCode โดยไม่ต้องทำอะไร
  • store.screen ตัวเดียว → ไม่มีจอไหนเก็บสถานะเอง
  • _header ที่เดียว → ไม่มีจอไหนวาดเมนูเอง
ไม่ใช่เพราะคนเขียนขยันกว่า แต่เพราะทางที่ผิดถูกทำให้เดินไม่ได้
แต่คำทำนายจาก 20.1 ก็เป็นจริงด้วย
20.1 ทำนายว่าปัญหาที่เกิดที่ชั้นการแสดงผล จะไม่หายไปแม้จะมี store
แถวที่ 5 และ 6 ยืนยันคำทำนายนั้น — WarehouseStore ไม่ได้เกี่ยวอะไรกับการที่ปุ่มไม่เป็นสีเทา หรือการที่สีมีสองชื่อ
และแถวที่ 7 แสดงว่าแม้แต่ในชั้น core/ ที่สะอาดที่สุด ก็ยังมีของเดียวที่เขียนสองแบบได้ ถ้าไม่มีอะไรบังคับ
ข้อสรุป: มีที่กลางแก้ปัญหาได้เฉพาะเรื่องที่ถูกบังคับให้ผ่านที่กลางนั้น เรื่องที่ยังปล่อยให้แต่ละที่ตัดสินใจเอง จะยังไม่ตรงกันเหมือนเดิม
