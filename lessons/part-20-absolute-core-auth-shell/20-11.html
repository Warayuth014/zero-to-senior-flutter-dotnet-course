ไฟล์หลัก: lib/core/connection_controller.dart — singleton ChangeNotifier เป็น source of truth ของ profile list, active profile และผล probe ล่าสุด

1. State ที่ controller เป็นเจ้าของ

controller ถือ profiles, active ID, connection status, last test result และ flag loaded โดยเปิด list แบบ immutable view ลดโอกาส callerแก้ collectionข้าม validation ทุก mutationผ่าน methodแล้ว persist/notify จึงตรวจ invariantได้จากจุดเดียว

2. Load และ self-healing

read connection_profiles_v1
→ decode snapshot
→ ถ้าว่าง/เสีย: seed Default localhost:6191
→ เลือก active profile
→ persist snapshot ที่ valid
→ loaded = true; notifyListeners()

preferences failureถูกจับเพื่อให้ sessionยังเปิดได้ แต่ productionควร record diagnostic มิฉะนั้น profileหายซ้ำโดยไม่มีหลักฐาน

3. Save ไม่เท่ากับ Activate

saveAsNew เพิ่ม profileแต่ไม่แย่ง active profileเดิม ช่วยให้ผู้ใช้เตรียม serverใหม่โดยไม่กระทบงาน ส่วน saveEdits รักษา createdAt ของ rowเดิม และ activate ตรวจว่า idมีอยู่ก่อนสลับ การแยก commandทำให้ UIเสนอ “Save” กับ “Save & Use” อย่างมีความหมาย

4. Delete invariant

ห้ามลบ profileสุดท้าย หากลบ active profileต้องเลือก replacementหรือ fallbackเป็นรายการที่เหลือ แล้ว reset statusเป็น unknown ก่อน persist/notify เพราะผล probeเดิมเป็นของ URLเดิม การลบ inactive profileไม่ควรเปลี่ยนปลายทาง request

5. Status state machine

unknown
  → refreshStatus() → connecting
  → probe ok        → connected + lastResult
  → probe fail      → disconnected + lastResult

การ notifyตอน connectingทำให้ dot/spinnerตอบสนองทันที และ notifyตอนจบทำให้ dialog/shell rebuildจาก stateเดียวกัน

6. Persistence policy

mutation เปลี่ยน memoryก่อนแล้วเขียน preferences โดย swallow storage exception เพื่อไม่ทำให้แอปหยุด นี่คือ availability-first policy: sessionปัจจุบันใช้ค่าใหม่ได้ แต่ restartอาจย้อนกลับ หากต้องการรับประกันการตั้งค่า ควรคืน typed save resultให้ UIและเลือก rollbackหรือเตือนอย่างชัดเจน

7. Async race ที่ยังต้องระวัง

refreshStatus ยังไม่มี request generation/cancellation ถ้า probe A ช้าแล้วผู้ใช้ activate profile B จากนั้น probe Bจบก่อน A ผล Aที่มาช้าสามารถเขียน statusของ Bผิดได้ วิธีแก้คือจับ profile ID/base URLกับ generation ตอนเริ่ม และ commitผลเฉพาะเมื่อยังตรงกับ active generationล่าสุด

8. Controller tests

ทดสอบ load corrupt/empty, immutable list, add/edit/activate/delete, ห้ามลบตัวสุดท้าย, active replacement, persistence failure policy และ race A→B ด้วย completersที่ควบคุมลำดับผล ยืนยันจำนวน notifyและว่า stale resultไม่ทับ statusปัจจุบัน
