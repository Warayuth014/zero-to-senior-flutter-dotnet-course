1. Session เก็บอะไร

AuthSession ประกอบด้วย token, username, roles และ expiration ที่อาจไม่มีค่า มันเป็น snapshot จากผล login ไม่ใช่ผู้ตัดสินว่าผู้ใช้ยัง authenticated อยู่ เพราะ validity ต้องพิจารณาเวลา, issuer/audience, server profile และผลตอบกลับ 401 ด้วย

2. Owner สองชั้น

AuthRepository.session เก็บข้อมูลสำหรับ UI ส่วน ApiClient.authToken เก็บค่าเพื่อสร้าง Authorization header ทั้งสองต้องสอดคล้องกันเสมอ หากเขียน token ก่อน parse session สำเร็จ หรือ logout ล้างเพียงจุดเดียว จะเกิด authenticated transport กับ unauthenticated UI หรือกลับกัน

3. Lifecycle ปัจจุบัน

app start → session = null
login success → session + client token
enter WarehouseShell → read username/expiration
logout → clear session + token
process killed → session lost → login again

ไม่มี restore จาก disk ใน code นี้ การอ่านชื่อ class แล้วสรุปว่าจำ login ได้จึงผิด

4. Expiration มีแต่ยังไม่ enforce

expiration ถูก parse และแสดงใน User Info แต่ยังไม่มี startup guard, pre-request check หรือ scheduler logout ดังนั้น token หมดอายุจริงจะถูกค้นพบเมื่อ server ตอบ 401 แนวทางที่ถูกต้องคือใช้ UTC, เผื่อ clock skew, ป้องกัน refresh พร้อมกันหลาย request และให้ server เป็น authority สุดท้าย

5. Roles ว่างหมายความว่าอะไร

repository สร้าง roles เป็น list ว่าง จึงยังไม่ควรซ่อน/แสดงเมนูตาม role จาก model นี้ หาก backend ส่ง claims ใน JWT ต้องเลือกว่าจะ parse ฝั่ง clientเพื่อ UX หรือให้ endpoint /me คืน permission ที่ normalize แล้ว แต่ backend ต้องตรวจ authorization ซ้ำเสมอ UI guard ไม่ใช่ security boundary

6. Secure persistence ทางเลือก

ถ้าต้องการจำ login อย่าใส่ token ใน SharedPreferences ใช้ platform secure storage, เก็บ refresh token ตาม policy, ผูก session กับ profile/issuer และ restore ก่อนเลือก home route การอ่าน storage ควร fail closed: decrypt/parse ไม่ได้ให้ล้างและกลับ login ไม่ใช้ token ที่ไม่ทราบที่มา

7. Server switch invariant

session ควรบันทึก server identity หรือ profile ID ที่ออก token เมื่อ active profile เปลี่ยน ให้ล้าง sessionและ warehouse state ก่อนยิง request ไป host ใหม่ เว้นแต่มี explicit trust rule นี่แก้ทั้ง credential leakage และข้อมูลหน้าจอจากคลัง A ปะปนกับคลัง B

8. Session tests

สร้าง fake clock แล้วทดสอบ valid/near-expiry/expired, logout idempotent, restore ที่ corrupt, 401 พร้อมกันหลาย request, profile switch และ role parsing ยืนยันด้วยว่า token/password ไม่ปรากฏใน toString, logs หรือ error UI
