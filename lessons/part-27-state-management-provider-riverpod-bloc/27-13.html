Testing Cubit: Cubitเป็น Dart objectที่รับ repository จึง testโดยตรงได้ ไม่ต้อง pump widgetหรือใช้ packageเสริมเพื่อเริ่มต้น

1. Arrange

สร้าง fake repositoryและ inject deterministic command id จากนั้นสร้าง TaskCubitและลงทะเบียน close ใน tearDown

2. State assertions

await load ตรวจ loaded tasks เก็บ snapshot แล้ว await complete ตรวจ tasksว่าง/message correlation อย่าตรวจเฉพาะ call countเพราะ output stateคือ contractกับ UI

3. Emission sequence

เมื่อ transitionสำคัญให้ subscribe cubit.stream หรือใช้ bloc_test ตรวจ sequence busy→success/error Labไม่เพิ่ม dependencyเพิ่มเพราะ testsปัจจุบันพอ แต่รู้เครื่องมือเมื่อ sequenceโต

4. Concurrency

ใช้ Completerค้าง repository completeแล้วเรียก Cubitสองครั้ง ตรวจ callเดียวและ busy stateระหว่างรอ เช่นเดียวกับ TaskStore behaviorต้องไม่หายเมื่อเปลี่ยน package

5. Observer

BlocObserverช่วย log transitions/errorsทั้งแอปแต่ต้อง redactข้อมูลและไม่แทน domain audit อย่า log token/barcode/serialโดยไม่ policy

6. เมื่อใช้ Bloc events

test event→stateและ concurrency transformer เช่น droppableสำหรับ submitซ้ำ, restartableสำหรับ searchล่าสุด แต่ server idempotencyยังต้องมี

7. Widget binding test

override BlocProviderด้วย fake Cubitหรือ real Cubit+fake repositoryเพื่อทดสอบ Builder/Listener แยกจาก controller tests ไม่จำเป็นต้องยิง .NETทุก widget test

8. Exercise

เพิ่ม test unknown outcomeให้ Cubit: fakeลบ taskแล้วโยน ApiException unknown จาก complete จากนั้น fetchว่าง ผลสุดท้ายต้องไม่มี errorและ messageบอก reconcileสำเร็จ
