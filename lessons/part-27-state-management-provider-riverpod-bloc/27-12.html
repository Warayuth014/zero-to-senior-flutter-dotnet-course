BlocProvider Builder Selector Listener

Part 27: State Management: Provider, Riverpod & BLoC/Cubit

flutter_bloc widgets: Providerสร้าง/ปิด Cubit, Builderวาด state, Selectorลด rebuild และ Listenerทำ one-off side effect แต่ละตัวมีหน้าที่ต่างกัน

1. BlocProvider

BlocProvider(
  create: (_) => TaskCubit(repository)..load(),
  child: const BlocTaskBody(),
)

scope own Cubitและ closeเมื่อถอดจาก tree

2. BlocBuilder

builderต้อง pure วาด tasks/loading/errorจาก snapshot ไม่ยิง APIหรือแสดง dialog การ buildอาจเกิดหลายครั้งและไม่เท่ากับ eventครั้งเดียว

3. BlocSelector

Labเลือก state.tasks.length สำหรับ header จึง rebuildเมื่อ countเปลี่ยน คล้าย Provider Selector/Riverpod select แนวคิด projectionเหมือนกัน

4. BlocListener

ฟัง transition messageใหม่แล้วแสดง SnackBarด้วย listenWhen Side effectจึงไม่อยู่ builderและลดการแสดงซ้ำจาก unrelated state

5. BlocConsumer

รวม Builder+Listenerได้แต่แยกสอง widgetมักอ่านหน้าที่ชัดกว่า ใช้ Consumerเมื่ออยู่จุดเดียวและ conditionsไม่ซับซ้อน

6. context.read/watch/select

flutter_blocมี extensionsคล้าย Provider: readสำหรับ callback, watchทั้ง state, select projection แต่ BlocBuilder/Selectorทำ dependencyใน treeเห็นชัดกว่าใน widgetใหญ่

7. Nested scopes

MultiBlocProviderลด nestingแต่ไม่เปลี่ยน ownership ถ้า reuse Cubitเดิมใช้ BlocProvider.value และเจ้าของเดิมต้อง closeเอง

8. Checkpoint

ชี้ใน bloc_task_panel.dart ให้ได้ว่าบรรทัดใดสร้าง lifecycle, render list, render countและแสดง one-off feedback ถ้าทั้งหมดอยู่ Builderเดียว refactorก่อนเพิ่ม flow
