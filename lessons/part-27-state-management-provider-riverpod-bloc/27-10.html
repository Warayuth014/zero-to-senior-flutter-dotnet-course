Cubit vs Bloc: ทั้งคู่ emit immutable states และใช้ flutter_bloc widgetsเหมือนกัน Cubitรับ method callตรง ส่วน Blocแปลง eventsผ่าน handlers/transformers

1. Cubit

class TaskCubit extends Cubit<TaskPatternState> {
  Future<void> complete(WmsTask task) async { ... emit(next); }
}

เหมาะเมื่อ intentsเป็น methodชัดและไม่ต้อง model event pipelineซับซ้อน

2. Bloc

Blocรับ TaskRefreshed, TaskCompleted แล้ว on<Event> จัดการ เหมาะเมื่อ event ordering, debounce/restartable/droppableและ audit eventมีคุณค่ามากกว่า boilerplate

3. ไม่ใช่ระดับ seniorตามชื่อ

การใช้ Blocเต็มรูปไม่อัตโนมัติว่าดีกว่า Cubit เลือก abstractionต่ำสุดที่แสดง concurrency semanticsได้ชัด หาก method callsเพียงพอ Cubitอ่านง่ายกว่า

4. State stream

emit ส่ง snapshotใหม่ตามลำดับ Consumersฟัง streamและ Cubitมี state ล่าสุด ต่างจาก ChangeNotifierที่ notifyโดยไม่ส่งค่าผ่าน callback

5. Error

Business errorควรอยู่ typed state/result ส่วน unexpected exceptionอาจผ่าน onError/BlocObserverเพื่อ telemetry อย่ากลืน exceptionทุกชนิดเป็นข้อความเดียว

6. close

BlocProviderที่ create Cubitจะ closeให้อัตโนมัติ ใน unit testที่สร้างตรงต้อง addTearDown(cubit.close) Ownershipกฎเดียวกับ Providerแม้ชื่อ methodต่าง

7. Migration

ย้ายจาก ChangeNotifierโดยสร้าง immutable stateและ map gettersก่อน แล้วเปลี่ยน notifyListenersเป็น emitทีละ action Repository/UI contractควรคงเดิม

8. Decision

Task flow labใช้ Cubitเพราะ intentsน้อย หากเพิ่ม scanner event burst, search debounceและ concurrent refresh policy ให้ทดลอง Bloc event transformersแล้ววัดความชัดที่เพิ่ม
