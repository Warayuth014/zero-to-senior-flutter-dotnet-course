Baseline: TaskStore extends ChangeNotifier จาก Part 26 คือ business behavior ที่ผ่าน test แล้ว Provider จะเปลี่ยนวิธีจัด scope/consume ไม่จำเป็นต้องเขียน Store ใหม่

1. ChangeNotifier contract

fields private, getters read-only, public intent methods และ notifyListeners หลัง invariant เปลี่ยนคือขอบเขตสำคัญ หาก widget แก้ list ตรง Provider ก็ช่วยไม่ได้

2. Mutable controller

Store object เดิมเปลี่ยน fields ภายใน Listener รู้เพียง “มีบางอย่างเปลี่ยน” จึงต้องใช้ selector/แยก store เพื่อจำกัด rebuild ต่างจาก immutable state ที่แต่ละ emission เป็น snapshot ใหม่

3. Package boundary

UI → Provider lookup → TaskStore
TaskStore → TaskRepository → JsonApi

เฉพาะ UI binding import provider Store และ repository ยังเป็น Dart/Flutter foundation จึงย้าย package ในอนาคตง่าย

4. Existing tests ยังใช้ได้

task_store_test.dart สร้าง Store ตรงโดยไม่ต้อง pump Provider นี่เป็นข้อดีของการไม่เอา BuildContext เข้า controller Widget test เพิ่มเฉพาะ scope/consumer behavior

5. notify granularity

Store เดียว notify เมื่อ busy task ใดเปลี่ยน Consumer ที่ watch ทั้ง Store rebuild หมด Selector ช่วยได้แต่ถ้า state dimensions โตมาก การแยก notifier อาจชัดกว่า selector จำนวนมาก

6. Disposal

ChangeNotifier มี lifecycle จริงเพราะอาจถือ timer/listener Provider ที่สร้าง Store ต้อง dispose ให้ แต่ repository/client ownership อาจอยู่ scope สูงกว่า อย่าปิด shared dependency จาก Store โดยไม่ตกลง

7. Migration seam

เริ่มครอบ Store เดิมด้วย Provider ได้โดยไม่ rewrite feature จากนั้นค่อยปรับ widget ใช้ read/watch/select ทีละ route นี่เป็น migration ที่ reversible

8. Checkpoint

ถ้าลบ import provider ทั้งหมด Controller tests ต้องยังผ่าน ถ้าไม่ผ่านแสดงว่า package concern รั่วเข้า business controller มากเกินไป
