Provider consumption: เลือก read สำหรับ event, watch/Consumer สำหรับ UI ที่ตาม state และ select/Selector เมื่อสนใจ projection เล็ก

1. read

context.read<TaskStore>().complete(task) ใช้ใน callback ไม่ subscribe rebuild ห้ามใช้ read เพื่อวาดค่าที่ต้องเปลี่ยน เพราะ UI จะค้าง snapshot เก่า

2. watch

context.watch<TaskStore>() ทำให้ widget build ใหม่เมื่อ notify เหมาะกับ widget ที่ใช้ state ส่วนใหญ่ แต่ placement กว้างอาจ rebuild subtree ใหญ่

3. Consumer

Consumer<TaskStore> จำกัด listener ไว้ใต้ widget ปัจจุบันและมี child สำหรับ subtree คงที่ Lab ใช้ Consumer ครอบ list behavior

4. Selector

final count = context.select<TaskStore, int>(
  (store) => store.tasks.length,
);

header rebuild เมื่อ count เปลี่ยน ไม่ใช่ทุก progress/error แต่ selected value ต้องมี equality ที่เหมาะสม

5. Mutable collection trap

ถ้า selector คืน list instance เดิมแล้ว mutate ภายใน equality อาจไม่เห็นการเปลี่ยน ใช้ immutable snapshot/projection เช่น length/id tuple แทน expose mutable collection

6. Measure

อย่าใส่ Selector ทุกจุดก่อน profile ใช้ DevTools/rebuild logging หาจุดแพง บาง widget build เล็กๆ เร็วกว่าความซับซ้อนของ optimization

7. Side effect

ไม่แสดง dialog/snackbar ใน build จาก error ทุกครั้งเพราะ rebuild ทำซ้ำ ควรมีกลไก event/consume message หรือ listener แยก Provider พื้นฐานต้องออกแบบเอง

8. Exercise

เพิ่ม widget แสดง busy count ด้วย Selector แล้ว instrument build counter พิสูจน์ว่า refresh ที่ไม่เปลี่ยน busy count ไม่ rebuild widget นี้
