Riverpod mental model: provider เป็น immutable declaration ของ node ส่วน state จริงอยู่ใน ProviderContainer/ProviderScope และ Ref ใช้อ่าน graph/lifecycle

1. ProviderScope

Flutter app ต้องมี ProviderScope เพื่อถือ container และ dispose nodes ตาม scope Lab วาง scopeเฉพาะแท็บ Riverpod พร้อม override repository ทำให้ stateไม่รั่วไปแท็บอื่น

2. Provider declaration

final taskRepositoryProvider = Provider<TaskRepository>(
  (ref) => throw StateError('ต้อง override'),
);

top-level variable เป็น recipe/type-safe key ไม่ใช่ mutable global singleton ค่าเกิดภายใน container

3. Ref operations

  • ref.watch สร้าง reactive dependency
  • ref.read อ่านครั้งเดียวสำหรับ action/dependency
  • ref.listen ทำ side effect ตาม transition
  • ref.invalidate ทิ้ง cacheเพื่อ buildใหม่

4. WidgetRef

ConsumerWidget รับ WidgetRef แยกจาก BuildContext จึงอ่าน provider graph โดยไม่ lookup typeจาก ancestorแบบ Provider แต่ scope ใน widget tree ยังเป็นตัวกำหนด container

5. Dependency tracking

ถ้า controller build ใช้ ref.watch(profileProvider) เมื่อ profile เปลี่ยน provider rebuildตาม graph ต้องวาง policy ว่า in-flight stateถูกยกเลิก/รักษาหรือไม่

6. autoDispose/family

autoDispose ล้าง stateเมื่อไม่มี listener เหมาะ detail/search บางชนิด ส่วน family parameterize provider เช่น task detail by id แต่ parameter ต้องมี equality คงที่

7. Version awareness

Lab pin flutter_riverpod 3.3.2 ตาม SDK/lockfile แม้ registryมีรุ่นใหม่กว่า ให้อ่าน changelogก่อนอัปเดต major/minorและรัน tests ไม่ copy syntaxจากบทความเก่าโดยไม่ตรวจ

8. Exercise

สร้าง ProviderContainer สองตัว override repository คนละ fake แล้วพิสูจน์ว่า stateแยกกัน นี่แสดงว่า provider declaration global แต่ runtime stateไม่ global
