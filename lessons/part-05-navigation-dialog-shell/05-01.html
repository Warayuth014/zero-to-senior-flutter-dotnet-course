Navigator จัดการ stack ของ Route: push วาง routeใหม่ด้านบน, pop เอาด้านบนออกและคืน result ผู้ใช้ Backคือการขอ pop ไม่ใช่การสร้างหน้าเดิมใหม่

1. Stack mental model

Login → Home → PickingOrders → PickItems
                                  ↑ top/current
pop()       กลับ PickingOrders
popUntil()  กลับ Home ตาม predicate

2. Push และ await

final result = await Navigator.of(context).push<PickResult>(
  MaterialPageRoute(builder: (_) => PickScreen(taskId: task.id)),
);
if (!context.mounted) return;
if (result != null) refreshTask(result.taskId);

3. Pop อย่างถูก navigator

Navigator.pop(dialogContext, value) ปิด routeของ contextนั้น Nested navigator/root navigatorอาจต่างกัน จึงอย่าใช้ contextสุ่มจาก global ใช้ contextใน builderหรือระบุ rootNavigatorตาม architecture

4. maybePop/canPop

maybePop เคารพ route pop disposition/PopScopeและคืน bool; canPop บอกว่ามี routeก่อนหน้าแต่ไม่แทน unsaved guard ใช้สำหรับปุ่ม back customโดยไม่ pop rootผิด

5. Stack ownership

wmsappใช้ route stackหลาย workflowจาก Home ส่วน Absoluteเก็บ screensภายใน shell/storeมากกว่า ทั้งสองใช้ได้ แต่ห้ามผสมจน backบางครั้ง pop routeและบางครั้งเปลี่ยน storeโดยไม่มี policy

6. Context หลัง await

Routeอาจปิดระหว่าง await ตรวจ context.mountedและ current workflowก่อน navigationต่อ ไม่ pushจาก async responseเก่าที่ไม่เกี่ยวกับหน้าปัจจุบัน

7. แบบฝึกหัด

จาก listเปิด detailและต้อง refreshเมื่อ detailแก้สำเร็จ ทำอย่างไร?

เฉลย

await push<bool>; detail pop(true)เมื่อ commitสำเร็จ; listตรวจ mounted/resultแล้ว refresh ไม่ใช้ global flagหรือ refreshทุก popโดยไม่จำเป็น

8. จุดพลาด

อย่าเรียก pushใน build และอย่า popสองครั้งจาก callbackเดียวโดยไม่รู้ stack Dialog/bottom sheetก็เป็น routes; popผิด contextอาจปิดหน้าหลักแทน modal
