PopScope ควบคุม back gestureเชิงคาดการณ์ได้: canPop ต้องสะท้อนว่าปัจจุบัน popได้หรือไม่ และ callbackจัดการกรณีที่ไม่ได้ popโดยไม่เรียก popซ้ำเป็นวง

1. Guard draft

PopScope(
  canPop: !isDirty,
  onPopInvokedWithResult: (didPop, _) async {
    if (didPop) return;
    final discard = await confirmDiscard(context);
    if (!context.mounted || !discard) return;
    Navigator.of(context).pop();
  },
  child: const EditorBody(),
)

2. didPop สำคัญ

ถ้า route popไปแล้ว callbackยังถูกเรียก ห้าม popอีก ตรวจ didPopก่อนเสมอ wmsappใช้ PopScopeใน CheckIn/Packing/Pickingเพื่อ backภายใน stepก่อนออก route

3. Internal back

Workflow state machineอาจย้อน stepแทน pop route: canPop falseเมื่อไม่อยู่ initial; callbackสั่ง store.previous/cancel dialog เมื่อกลับ initialจึงให้ route popได้

4. Unsaved settings

Absolute settings sheetใช้ isDirtyควบคุม canPopแล้วถาม discard ก่อนปิด ทำให้ drag/back/close buttonใช้ policyเดียวกัน Close buttonควรเรียก maybePopไม่ bypass guard

5. Predictive back

Androidต้องรู้ canPopล่วงหน้าเพื่อ animation หลีกเลี่ยง async decisionใน canPop; set canPop=falseแล้วถามใน callback จากนั้น popด้วย flag/commandที่ไม่ถามซ้ำ

6. Transaction in flight

ระหว่าง commitอาจ canPop=falseและแสดงเหตุผล หรืออนุญาตออกแต่ operationอยู่ store/idempotent ห้ามปล่อยหน้าแล้ว responseเก่าคืน state obsolete

7. แบบฝึกหัด

Packingอยู่ state scanPartและ Backควรกลับ scanPallet ไม่ออกหน้า ทำอย่างไร?

เฉลย

canPopเฉพาะ initial scanPallet; เมื่อ false callbackตรวจ didPopแล้ว dispatch back eventให้ FSMกลับ stateก่อนหน้า คืน focusตาม state เมื่อ initialรอบถัดไปจึง pop route

8. จุดพลาด

อย่าใช้ canPop:false ถาวรโดยไม่มีทางออก/accessibility และอย่าเรียก Navigator.popทันทีใน callbackจน dialog guardไม่ได้ผล
