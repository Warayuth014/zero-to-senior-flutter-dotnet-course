5. เกณฑ์ที่ต้องผ่าน

#เกณฑ์บท
1เข้าสู่ระบบแล้วย้อนกลับเข้าหน้าเดิมไม่ได้5.4
2ออกจากระบบตอนอยู่ลึกสามหน้า แล้วไม่เหลืออะไรใน stack5.4
3ทุกหน้ารับของที่ต้องใช้ผ่าน constructor5.2
4ผลลัพธ์เป็น sealed class และจัดการ null แยกจาก “ยกเลิก”5.3
5กดย้อนกลับที่หน้าเลือกช่องเก็บ ต้องกลับไปหน้าสแกนพาเลท ไม่ใช่ออกจากงาน5.5
6สแกนพาเลทแล้วกดย้อนกลับ ต้องถามก่อน5.5
7สลับแท็บแล้วกลับมา รายการยังอยู่ที่เดิม5.6
8แผ่นเลือกช่องเก็บคืนค่าแบบ typed และคืน null เมื่อปิด5.9
9ข้อความแจ้งผลไม่ต่อคิว และเรียกได้หลัง await5.10
10ยืนยันไม่สำเร็จเพราะช่องเต็ม ต้องกลับไปเลือกช่องใหม่โดยไม่เสียรหัสพาเลท4.15, 5.3
11ไม่มี Navigator ใน store หรือ repository5.4
12ทุกงานที่สร้างเองถูกทำลาย และของที่รับมาไม่ถูกทำลาย4.12, 5.2

เกณฑ์ข้อ 5 กับ 10 เป็นสองข้อที่ยากที่สุด และทั้งคู่เป็นเรื่องเดียวกัน — ล้มเหลวหรือย้อนกลับ ต้องไปให้ใกล้จุดที่ผิดที่สุด ไม่ใช่กลับไปเริ่มใหม่

6. สองทางเลือกของโครง

งานหลายขั้นตอนทำได้สองแบบ และต้องเลือกก่อนเขียน

หลายหน้าจอ (หลาย route)หน้าเดียวที่เปลี่ยนสถานะ
ปุ่มย้อนกลับทำงานเองตามธรรมชาติต้องเขียน PopScope ให้ถอยขั้น (5.5)
ร่างอยู่ที่ไหนต้องส่งต่อกันทุกหน้าอยู่ที่เดียว
ล้มเหลวแล้วย้อนไปขั้นก่อนต้อง pop หลายชั้นให้ถูกเปลี่ยนสถานะเดียว (4.15)
ทดสอบต้องเดินผ่านทุกหน้าทดสอบตรรกะแยกได้

สำหรับโจทย์นี้แนะนำแบบที่สอง — หน้าเดียวที่เปลี่ยนสถานะตาม 4.15 เพราะงาน putaway เป็นงานชิ้นเดียวที่มีสามขั้น ไม่ใช่สามงานแยกกัน

รายการงาน
  └─ push PutawayScreen(task)          ← route เดียว
       │
       ScanPallet → ScanLocation → ReadyToConfirm → Submitting
       │                                              │
       └─ pop(PutawayOutcome) ─────────────────────────┘

แต่ถ้าเลือกแบบแรกก็ทำได้ ขอให้เกณฑ์ข้อ 5 กับ 10 ยังผ่าน — ซึ่งจะยากกว่าเพราะต้องจัดการการ pop หลายชั้น

7. เกณฑ์ข้อ 5: ย้อนกลับภายในงาน

PopScope(
  // ออกจากหน้าได้เฉพาะตอนอยู่ขั้นแรกและยังไม่ได้สแกนอะไร
  canPop: _state is ScanPallet,
  onPopInvokedWithResult: (didPop, result) async {
    if (didPop) return;

    // ยังส่งอยู่ — ห้ามออก
    if (_state is Submitting) {
      showResultBanner(_messenger, 'กำลังบันทึก กรุณารอสักครู่');
      return;
    }

    // ไม่ใช่ขั้นแรก — ถอยหนึ่งขั้น ไม่ใช่ออกจากงาน
    _goToPreviousStep();
  },
  child: ...,
)

ผลที่ผู้ใช้ได้รับ

ScanLocation   → กดย้อนกลับ → ScanPallet
ScanPallet     → กดย้อนกลับ → ออกจากหน้า (ถ้ายังไม่ได้สแกน)
ScanPallet + มีรหัสแล้ว → กดย้อนกลับ → ถามก่อน (เกณฑ์ข้อ 6)

สังเกตว่าไม่ต้องเขียนเงื่อนไขพิเศษให้ขั้นสุดท้าย — พอถอยมาถึงขั้นแรก canPop กลายเป็น true เอง

8. เกณฑ์ข้อ 10: ล้มเหลวแล้วไปไหน

ผู้ใช้ยืนยันแล้วเซิร์ฟเวอร์ตอบว่าช่องเก็บเต็ม

ข้อมูลยังถูกต้องไหม
รหัสพาเลทถูก — ของยังอยู่บนรถยกคันเดิม
รหัสช่องเก็บผิดแล้ว — ช่องเต็ม
} on LocationFullException {
  if (!_isStillSubmitting(commandId)) return;      // 4.15
  _errorMessage = 'ช่องเก็บนี้เต็มแล้ว กรุณาสแกนช่องอื่น';
  _transitionTo(ScanLocation(current.palletCode));  // เก็บรหัสพาเลทไว้
}

ทดสอบข้อนี้ได้โดยไม่ต้องมี widget เลย ถ้าแยกตรรกะออกมาตาม 4.15 หัวข้อ 9

test('ช่องเต็มต้องกลับไปสแกนช่องใหม่ โดยไม่เสียรหัสพาเลท', () async {
  repository.failWith = const LocationFullException();
  await store.confirm();

  final state = store.state;
  expect(state, isA<ScanLocation>());
  expect((state as ScanLocation).palletCode, 'PAL-0101');
});

อย่างน้อย 12 ข้อ ข้อละหนึ่งเกณฑ์ ตัวอย่างสามข้อที่เขียนยากที่สุด

testWidgets('ออกจากระบบตอนอยู่ลึกสามหน้า ต้องไม่เหลืออะไรใน stack', (tester) async {
  await pumpLoggedIn(tester);
  await tester.tap(find.byKey(const ValueKey<String>('PUT-001')));
  await tester.pumpAndSettle();
  // ... เดินไปจนถึงขั้นสุดท้าย

  await tester.pageBack();                    // กลับมาหน้ารายการก่อน
  await tester.pumpAndSettle();
  await tester.tap(find.byKey(const Key('settings-button')));
  await tester.pumpAndSettle();
  await tester.tap(find.byKey(const Key('sign-out-button')));
  await tester.pumpAndSettle();

  expect(find.byKey(const Key('sign-in-button')), findsOneWidget);
  expect(
    tester.state<NavigatorState>(find.byType(Navigator)).canPop(),
    isFalse,
  );

10. ข้อผิดพลาดที่พบบ่อยตอนทำ lab นี้

อาการสาเหตุวิธีแก้
เทสต์ค้างที่ pumpAndSettleมี animation ที่ไม่จบ เช่นตัวหมุนที่ไม่หยุดใช้ pump(Duration(...)) แทน
กดย้อนกลับแล้วถอยสองขั้นลืม if (didPop) return;ใส่บรรทัดแรกเสมอ (5.5)
canPop ไม่อัปเดตเปลี่ยนสถานะแล้วไม่ได้วาดใหม่setState หรือ notifyListeners
หา widget ในแท็บอื่นไม่เจอตัวค้นหาข้าม offstageskipOffstage: false
Navigator ไม่พบใน contextใช้ context ที่อยู่เหนือ MaterialAppห่อด้วย Builder
ล้มเหลวแล้วกลับไปเริ่มใหม่ทั้งหมดย้อนไปสถานะแรกสุดย้อนไปให้ใกล้จุดที่ผิด
ทดสอบตรรกะต้องสร้าง widgetตรรกะอยู่ใน Stateย้ายไป store (4.5)

11. แบบทดสอบตัวเองก่อนจบ Part 5

ตอบให้ได้โดยไม่เปิดเฉลย ถ้าข้อไหนตอบไม่ได้ ให้กลับไปอ่านบทที่วงเล็บไว้

  1. กดย้อนกลับแล้วหน้าเดิมถูกสร้างใหม่หรือไม่ เพราะอะไร (5.1)
  2. push คืนอะไร และทำไมมันสำคัญ (5.1)
  3. ควรส่ง id หรือส่งข้อมูลทั้งก้อนให้หน้าใหม่ ตัดสินจากอะไร (5.2)
  4. ทำไมผลลัพธ์เป็น bool ถึงไม่พอ (5.3)
  5. null ที่ได้จาก push มาจากไหน และควรแปลว่าอะไร (5.3)
  6. ทำไม pushReplacement ใช้ตอนออกจากระบบไม่ได้ (5.4)
  7. การเปลี่ยน home ทำอะไรได้และทำอะไรไม่ได้ (5.4)
  8. ล้าง stack แล้วยังต้องล้างอะไรอีก (5.4)
  9. ทำไม onPopInvokedWithResult ต้องขึ้นต้นด้วย if (didPop) return; (5.5)
  10. ทำไม canPop ต้องคำนวณ ไม่ใช่เก็บเป็น field (5.5)
  11. IndexedStack ให้อะไร และแลกอะไร (5.6)
  12. ข้อมูลสี่ชั้นตามอายุมีอะไรบ้าง และแต่ละชั้นหายเมื่อไหร่ (5.7)
  13. ย่อแอปกับระบบปิดแอปต่างกันอย่างไร (5.7)
  14. เมื่อไหร่ควรถามยืนยัน เมื่อไหร่ควรทำเลยแล้วมีปุ่มเลิกทำ (5.8)
  15. ทำไมแผ่นที่มีช่องกรอกต้องตั้ง isScrollControlled (5.9)
  16. ทำไมต้องล้างคิวก่อนแสดงข้อความใหม่ (5.10)
  17. ทำไมงานสแกนใช้ข้อความเลื่อนขึ้นมาอย่างเดียวไม่ได้ (5.10)
  18. ทำไมแผ่นตั้งค่าต้องมีร่างของตัวเอง (5.11)

12. สรุปท้าย Part 5

สิ่งที่ทำได้แล้ว

  • เปิดและปิดหน้าจอ พร้อมรับผลกลับมาอย่างมีความหมาย
  • ส่งของให้หน้าใหม่โดยที่ compiler ตรวจให้ และไม่ให้สองหน้าแก้ข้อมูลชุดเดียวกัน
  • จัดเส้นทางเข้าและออกจากระบบโดยไม่เหลือหน้าเก่าค้าง
  • กันงานที่ทำค้างไว้ไม่ให้หายเพราะกดปุ่มย้อนกลับ
  • ทำโครงหลักที่สลับส่วนงานได้โดยไม่เสียของเดิม
  • แยกข้อมูลเป็นชั้นตามอายุ และตัดสินได้ว่าอะไรควรอยู่รอด
  • เลือกใช้กล่อง แผ่น และข้อความให้ตรงกับงาน
  • ทำแผ่นตั้งค่าที่มีร่างของตัวเองและไม่แตะค่าจริงจนกว่าจะบันทึก

สิ่งที่ยังไม่ได้ทำและจะทำที่ไหน
