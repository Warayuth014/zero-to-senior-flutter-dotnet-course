Transient flow stateควรถูกทิ้งเมื่อผู้ใช้ยืนยันยกเลิก/จบ session แต่รักษาเมื่อเพียงเปิด dialog, สลับ presentation หรือ pause workflow กำหนด boundaryเป็น product policy ไม่ปล่อยตาม widgetบังเอิญ dispose

1. State categories

  • editing: controller/focus/expanded
  • workflow draft: scanned pallet, quantity, step
  • server state: task/status/receipt
  • session/app: user/config

แต่ละชนิดมี reset/persistต่างกัน

2. Pause vs cancel

Absolute confirm exitถาม “กลับ listและทำต่อภายหลัง” แล้ว store.exitFlowตาม policy หาก backend taskยัง activeต้องรักษา authoritative stateและ reloadเมื่อกลับ ไม่เก็บเพียง widget fieldsที่หาย

3. Route result

Child workflow pop Saved/Cancelled/Pausedให้ caller refreshต่างกัน Cancel draftล้าง local; pauseเก็บ store/server; saved refresh list/badge อย่าใช้ nullแทนทุกความหมายถ้าต้องตัดสินต่างกัน

4. Process death

Stateที่ต้องรอด appถูก killต้อง persist localอย่าง versionedหรืออยู่ backend พร้อม operation ID ไม่ใช่คาดว่า route stack/Stateค้าง ระวังเก็บข้อมูลอ่อนไหว

5. Reset atomic

ล้าง step, selected IDs, controllers, pending errorsและ increment generationก่อน notifyหนึ่งครั้ง เพื่อไม่ให้ async responseเก่าคืน draftที่ทิ้งแล้ว

6. Navigationไม่ใช่ reset

การ pop widgetอาจ dispose local resourcesแต่ shared storeยังอยู่ ต้องเรียก cancel/complete command explicitเมื่อ domainต้อง reset และไม่ resetเพียงเพราะ rebuild/switch orientation

7. แบบฝึกหัด

ผู้ใช้เปิด quantity dialogแล้ว cancel ควรล้าง palletที่สแกนแล้วไหม?

เฉลย

ไม่ควรโดยอัตโนมัติ Dialogเป็น editing substep; cancelคืน quantityเดิมและ focus workflow หากผู้ใช้ cancelทั้ง workflowจึงใช้ policyยืนยันและ reset draft/session generation

8. จุดพลาด

อย่าเก็บ transient draftใน static/globalเพื่อ “กันหาย” โดยไม่มี user/session keyและ reset เพราะ logout/userใหม่อาจเห็นงานเก่า
