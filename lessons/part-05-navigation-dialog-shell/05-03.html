ทุก Routeมี Future result แบบ typed Navigator.push<T> รอ และ Navigator.pop(context, T) คืน นี่เหมาะกับ selection/editor/modal โดยไม่สร้าง callbackย้อนหลายชั้น

1. Typed selection

final selected = await Navigator.push<Location>(
  context,
  MaterialPageRoute(builder: (_) => LocationPicker(items: locations)),
);
if (!context.mounted || selected == null) return;
store.selectLocation(selected.id);

2. Cancel คือ null

Back/barrierมักคืน null แยกจาก valid false/empty list ให้ typeมีความหมาย เช่น bool resultควรเช็ค == true ไม่ใช้ result!

3. Result object

เมื่อมีหลายค่าใช้ record/sealed result เช่น ({String id, bool changed}) หรือ Saved/Deleted/Cancelled อย่าใช้ Map string keysที่ runtimeพัง

4. ตัวอย่างจริง

wmsapp SerialSelect pop Listของ serials, image source sheetคืน enum, part/lot sheetsคืน typed model ส่วน Absolute dialog scannerคืน custom scan object/string/int ตามงาน

5. Result vs shared state

Resultเหมาะ one-shot outcome Shared storeเหมาะข้อมูลที่หลาย routes observeต่อเนื่อง ใช้ resultบอก “changed”แล้ว source route refresh authoritative dataได้

6. Async safety

หลัง await route sourceอาจ unmountedหรือ selectionไม่ relevant ตรวจ context/current entityก่อน apply และอย่าเก็บ resultใน controllerของ routeที่ disposeแล้ว

7. แบบฝึกหัด

Editorมี Save/Delete/Back จะออกแบบ resultอย่างไร?

เฉลย

sealed EditorResult: Saved(entity), Deleted(id); Backคืน null จากนั้น caller switchเฉพาะ non-nullและ refresh/เอา rowออกตาม authoritative policy

8. จุดพลาด

อย่า pop resultก่อน API saveสำเร็จ มิฉะนั้น callerแสดงข้อมูลที่ยังไม่ commit ระหว่าง submit lock modal/pageและคืน resultหลัง authoritative success
