pushReplacement แทน routeบนสุด เหมาะ Login→Shellและ Logout→Loginเพื่อไม่ให้ Backกลับเข้า sessionเก่า แต่การล้าง authต้องเกิดใน repositoryก่อน/ร่วมกับ navigationอย่างถูกลำดับ

1. Login success

await auth.login(employeeId, password);
if (!mounted) return;
Navigator.of(context).pushReplacement(
  MaterialPageRoute(builder: (_) => WarehouseShell(auth: auth)),
);

Absoluteใช้รูปแบบนี้ทำให้ Loginไม่ค้างใต้ shell

2. Logout

await auth.logout();
if (!context.mounted) return;
Navigator.of(context).pushAndRemoveUntil(
  MaterialPageRoute(builder: (_) => LoginScreen(auth: auth)),
  (_) => false,
);

ถ้ามี nested workflow routes การล้างทั้ง stackปลอดภัยกว่า replacement routeบนสุดอย่างเดียว

3. Session source of truth

Navigationไม่ใช่ auth security Token/sessionต้อง clearใน repository/storage และ APIต้องปฏิเสธ tokenหมดอายุ Shell routeที่ยังค้างไม่ควรเข้าถึง secretหลัง logout

4. Deep stack policy

pushReplacementแทนแค่ top หาก logoutเกิดจาก detailใต้ shell อาจเหลือ shellใน stack ใช้ pushAndRemoveUntil/root auth gateตาม architecture และทดสอบ hardware Back

5. Expired session

API 401ควรส่ง eventไป auth ownerครั้งเดียว ป้องกันหลาย requestเปิด Loginซ้อนกัน แล้ว clear stack/draftตาม policy อาจเก็บ unsynced workแบบปลอดภัยแต่ห้ามเก็บ tokenเก่า

6. Navigation ownership

Repositoryไม่ควรเรียก Navigator ให้ return auth outcome/event; UI/app coordinatorตัดสิน route ทำให้ testได้และไม่ผูก data layerกับ BuildContext

7. แบบฝึกหัด

Logoutจาก workflowลึกสาม routeใช้ replacementพอไหม?

เฉลย

ไม่พอเสมอ แทนเฉพาะ workflow topแล้ว Backอาจกลับ shell ใช้ root navigator + pushAndRemoveUntil falseหรือ declarative auth gate และ clear store/timers/sessionก่อนเผย Login

8. จุดพลาด

อย่า navigateก่อน awaited logout/secure storage cleanupโดยไม่มี policy และอย่าให้ double logoutสร้าง Loginหลาย route ใช้ auth transition guard
