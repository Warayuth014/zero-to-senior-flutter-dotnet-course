Route-level settings sheet เป็น mini application: มี draft, validation, async test/save, dirty guardและ typed decisions แต่ shared ConnectionControllerยังเป็น source of truthหลัง commit

1. Open from shell

Future<void> openConnectionSettings(BuildContext context) =>
  showModalBottomSheet<void>(
    context: context,
    useSafeArea: true,
    isScrollControlled: true,
    builder: (_) => ConnectionSettingsSheet(controller: connection),
  );

2. Draft isolation

Controllersแก้ draft copy ไม่เปลี่ยน active profileทันที Test connectionใช้ draft URL; Save validates duplicate nameและ persist; Applyจึง activate/refresh status

3. Dirty state

คำนวณ dirtyจาก normalized draftเทียบ original ไม่ set boolจากทุก keystrokeอย่างเดียว PopScopeถาม discardและ closeทุกทางผ่านเดียวกัน

4. Async commands

busy guardปิด test/save/deleteซ้ำ, try/finally, mountedหลัง await และ stale draft guardถ้าผู้ใช้แก้ระหว่าง probe ผลต้องผูก URL snapshot

5. Duplicate decisions

Dialogคืน typed enum/string rename/overwrite/cancel ดีกว่า business logicใน dialog ConnectionControllerรักษา invariant active profileและ persistence atomic

6. Route-level benefit

Sheetอยู่เหนือ workflowแต่ไม่ต้องออกจาก shell; root/shared controllerทำ header dotอัปเดตผ่าน ListenableBuilderหลัง apply และ app lifecycle refresh serverเดียวกับ API

7. แบบฝึกหัด

Probe URL Aกำลังวิ่ง ผู้ใช้แก้เป็น Bก่อนผลกลับ ควรแสดงผล Aเป็นของ Bไหม?

เฉลย

ไม่ Capture normalized URL/generationตอนเริ่ม Apply resultเฉพาะ draftยังตรงหรือ labelชัดว่าเป็น A; cancel/ignore staleและปลด busyตาม token

8. จุดพลาด

อย่าแก้ singleton active URLทุก onChanged เพราะ requestอื่นอาจสลับ serverกลางงาน Commit draftผ่าน explicit Save/Applyเท่านั้น
