MaterialPageRoute สร้าง route transitionแบบ Materialและ builderสร้าง pageเมื่อ routeต้องใช้ Dependencyควรถูกส่งแบบ typed constructorจาก composition owner ไม่ให้ screenค้น global singletonเองทุกอย่าง

1. Constructor injection

Navigator.push(
  context,
  MaterialPageRoute(
    builder: (_) => PickItemsScreen(
      taskId: task.id,
      repository: taskRepository,
      session: session,
    ),
  ),
);

2. ส่ง ID หรือ object

ส่ง immutable snapshotเมื่อ pageใช้ข้อมูล ณ จุดเปิดและไม่ต้องสด; ส่ง IDแล้วให้ feature owner/repositoryโหลดเมื่อ authorityอาจเปลี่ยน อย่าส่ง mutable entityแล้วทั้งสองหน้าแก้คนละทาง

3. Builder context

underscore contextใน builderอยู่ใต้ routeใหม่ ใช้สร้าง pageได้ แต่ callbackก่อน pushยังใช้ source context อย่า capture dialog contextไปใช้หลัง modalปิด

4. Dependency lifetime

ถ้า routeสร้าง controller/store ให้ route/page dispose; shared auth/repositoryมาจาก app ownerไม่ disposeใน page Absolute Loginส่ง AuthRepositoryเข้า WarehouseShellและ shellสร้าง WarehouseStoreจาก repositories

5. RouteSettings

กำหนด name/argumentsสำหรับ analytics/debug/restorationได้ แต่ typed constructorยังปลอดภัยกว่า Map dynamic เมื่อ appโตใช้ Router/declarative routesภายหลังโดยรักษา dependency boundaryเดิม

6. Testability

Screenรับ interfaceทำ widget testด้วย fake repository ไม่ต้องตั้ง global HTTP client Navigation testใช้ NavigatorObserverหรือ pump routeแล้ว assert UI/result

7. แบบฝึกหัด

Settingsต้องใช้ ConnectionController sharedและ draft local ควรส่งอะไร?

เฉลย

ส่ง controller interface/shared ownerเข้า route; sheetสร้าง immutable draft/controllers localและ disposeตน เมื่อ saveจึงเรียก controller command ไม่แก้ shared profilesระหว่างพิมพ์

8. จุดพลาด

อย่าส่ง BuildContextเป็น dependencyให้ repository/store และอย่าสร้าง ApiClientใหม่ทุก routeจน config/session/cacheต่างกัน ให้ composition rootกำหนด lifetime
