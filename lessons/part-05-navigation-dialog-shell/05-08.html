AlertDialog เป็น modal decisionสั้นที่คืน typed result ควรใช้กับ actionเสี่ยง ไม่ใช้ทุก scan และต้อง lock scanner/background actionเพื่อไม่ให้ Enterกดยืนยันโดยบังเอิญ

1. Confirm result

final ok = await showDialog<bool>(
  context: context,
  barrierDismissible: false,
  builder: (ctx) => AlertDialog(
    title: const Text('ยืนยันออกจากงาน'),
    content: const Text('บันทึกขั้นตอนแล้วกลับรายการ?'),
    actions: [
      TextButton(onPressed: () => Navigator.pop(ctx, false), child: const Text('ทำต่อ')),
      FilledButton(onPressed: () => Navigator.pop(ctx, true), child: const Text('พักงาน')),
    ],
  ),
);
if (ok == true && context.mounted) store.pause();

2. barrier policy

falseเมื่อ decisionต้อง explicit/transactionกำลังทำ; trueได้สำหรับข้อมูลไม่เสี่ยง Backยังต้องมี policyและ null resultเสมอ

3. Dialog context

ใช้ ctx pop dialog หลัง awaitใช้ page contextที่ตรวจ mounted ไม่เก็บ ctxหลัง pop Absolute/wmsappใช้ patternนี้สม่ำเสมอ

4. Content

สรุป entity/action/ผลกระทบ เช่น pallet→location/quantity ปุ่มใช้คำกริยา ไม่ใช้ Yes/No และ destructive actionมี styleชัด

5. Async confirm

ปิด dialogแล้ว owner submitหรือทำ stateful dialog loading หาก submitใน dialogต้อง guard duplicateและไม่ให้ closeกลาง commitโดยไม่มี policy

6. Accessibility/focus

Title/contentอ่านได้, focus safe action, large touch targets, scanner disabledระหว่าง modal และคืน focusหลังปิด

7. แบบฝึกหัด

Delete connection profileที่ activeควรถามอะไร?

เฉลย

บอกชื่อ profile/ผลต่อ connectionและเลือก profileถัดไปก่อน delete ปุ่ม “ลบโปรไฟล์”/“ยกเลิก”; controller validateห้ามเหลือ config invalidและ persist atomically

8. จุดพลาด

Modal fatigueทำให้ผู้ใช้กดโดยไม่อ่าน ใช้ dialogเฉพาะ irreversible/high-impact ส่วน scanที่ undoได้ใช้ feedback+undoดีกว่า
