Sorting dashboard เป็น state machine 10 stations: tap behavior เปลี่ยนตาม AVAILABLE/BUSY/DISABLED และ server events เปลี่ยน counters, capacity, queue และ assignment แบบ realtime

1. Dashboard state

state มี stations list, completedCount, queuedCount และ loading โดย getSortingDashboard เป็น snapshot เริ่มต้น/refresh ส่วน SignalR เร่งการอัปเดตระหว่างเปิดหน้า

2. Station transitions

AVAILABLE → BUSY → FULL/BUSY → clear → AVAILABLE
AVAILABLE ↔ DISABLED
queued batch → assigned เมื่อ station ว่าง

FULL แสดงผ่าน isFull บน BUSY ไม่ใช่ status แยกใน model

3. Tap dispatch

DISABLED เปิดเมนู enable; AVAILABLE เปิดเมนู disable; BUSY เปิด detail sheet กฎอยู่ใน _openStation จึงควรมี unknown status fallbackแทนให้ทุกค่าอื่นกลายเป็น BUSY โดยปริยาย

4. Toggle

confirm dialog ส่ง stationId, enable, operatorId และ optional reason หลัง success reload dashboard Server ต้องห้าม disable station ที่ยัง BUSY ตาม policy หรือบอกผลที่ explicit

5. Busy detail

sheet โหลด SortingStationDetail ที่มี pallet, cartons, capacity, pendingCount และ carton sequence พร้อมฟัง counter/full event เฉพาะ station เดียวแล้ว reload

6. Clear

clear station ยืนยันส่ง pallet ออกจาก station แล้ว POST clear เมื่อสำเร็จแจ้ง parent reloadและปิด sheet ต้องตรวจ station full/ready และ concurrent assignment ใน backend

7. Realtime reconciliation

CounterUpdated patch station ใน listทันที; full/cleared/toggled/batchAssigned reloadทั้ง dashboard หาก responseเก่ากลับหลัง eventใหม่อาจทับ state จึงต้องมี generation/version guard

8. FSM tests

ทดสอบทุก status/tap, full capacity, toggle/clear conflict, eventผิดลำดับ/ซ้ำ, stationไม่พบ, queued→assigned และ REST stale response โดย stateสุดท้ายต้องตรง server versionล่าสุด
