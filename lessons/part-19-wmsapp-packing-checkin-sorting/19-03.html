Packing มีลำดับชั้น 4 ระดับ: scan pallet เพื่อเลือก pack, เลือก order ใน pack แล้วจึงยืนยัน part การ refresh ต้องกลับไปยังระดับที่เหมาะกับผลของ server

1. Scan pallet

trim+uppercase แล้วเรียก scanPalletForPacking หากสำเร็จเก็บ PackingPalletResponse และเปลี่ยนเป็น packList หาก fail ล้างช่องและคืน scanner focus

2. Pallet response

มี pallet status/location และ packs แต่ละ PackingSummary มี packingId, status, เวลา และ order done count จึงแสดงทั้งงานที่กำลังทำและงานเสร็จบน pallet เดียวกัน

3. Open pack

getPack(packingId) คืน orders หากมีหนึ่ง order โค้ดเรียก _openOrder ทันที มิฉะนั้นเข้าสู่ orderList ระวังการเรียก async method ภายใน setState callback ควรแยก decision หลัง setState เพื่อ flow ชัด

4. Open order

GET /packing/pack/{packingId}/order/{pickOrderId}

response เป็น working snapshot ของ parts พร้อม scannedQty/remaining/availableSerials

5. Reset order draft

เมื่อเปิด order ต้องล้าง selectedPart, serial/qty maps, expanded rows และ scanner text แล้วเปลี่ยน orderParts ก่อน request focus หลัง frame

6. Back navigation

orderParts ย้อน orderList เมื่อ pack มีหลาย order มิฉะนั้นกลับ packList; success/reset กลับ scan pallet ทุก transition ล้าง context ที่ต่ำกว่าระดับปลายทาง

7. Refresh after success

_refreshPackList scan pallet เดิมใหม่ หาก pallet ถูก release/shipped endpoint อาจ fail แล้ว reset all; ถ้ายังมี pack อื่นจะกลับ packList ด้วย authoritative snapshot

8. Hierarchy tests

ทดสอบ pallet ไม่พบ, pack 0/1/หลาย orders, order load fail, back ทุก state, pallet released หลัง finalize และ request A/B สลับผล โดย ID/state ต้องไม่ผสมข้าม snapshot
