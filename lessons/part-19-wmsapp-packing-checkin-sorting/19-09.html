Check-in contract มีทั้ง carton และ pipeline: slot assignment อิง owner/customer order ขณะที่ counters สะท้อนความคืบหน้าข้าม Picking, Packing, Sorting และ Check-in

1. API surface

POST /checkin/preview
POST /checkin/scan
GET  /checkin/slot/{slotId}
POST /checkin/complete
POST /checkin/dispatch

2. Preview model

PreviewCheckInResponse รวม pack identity/content, slot decision, duplicate flag, destination และ counters ค่า skuCount derive จาก items.length ไม่ควรเก็บซ้ำ

3. Preview items

PreviewCheckInItem มี partId, description, brand, imageUrl และ qty เหมาะกับ visual verification แต่ไม่มี lot/serial เพราะขั้นนี้ยืนยัน carton รวม ไม่ใช่แก้ inventory line

4. Scan result

ScanCheckInResponse คืน slotId กับ isReadyToComplete ขนาดเล็กและชัด แต่ timeout หลัง commit ต้องมี operation/query status เพื่อค้นผล ไม่ควรยิง scan ซ้ำโดยเดา

5. Slot model

CheckInSlotDetail มี status, cartons และ pipeline counters ส่วน carton มี packing/tracking/status/time/counts ทำให้ refresh หนึ่งครั้ง rebuild ทั้งหน้าได้

6. Date/status parsing

scannedAt invalid fallback เป็น now และ status เป็น String ควรใช้ UTC timestamp ที่ parse failure สังเกตได้กับ enum ที่รองรับ unknown เพื่อไม่ทำ carton เสียดูเหมือนเพิ่งสแกน

7. Command responses

complete/dispatch คืน void ทำให้ clientรู้เพียง success HTTP หากต้องแสดงสถานะ/version/dispatch destination ควรคืน typed result หรือตามด้วย GET slot อย่างบังคับ

8. Contract lab

fixture preview new/existing/duplicate, slot OPEN/READY/SHIPPED, malformed dates/status และ problem details 409 จาก concurrent scan/complete/dispatch แล้วทดสอบ Dart/.NET contract คู่กัน
