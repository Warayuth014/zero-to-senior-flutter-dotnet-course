Ready-to-complete เปิด command chain: scan carton สุดท้ายแล้ว UI เรียก complete ต่อ dispatch อัตโนมัติ แต่แต่ละขั้นอาจ fail แยกกันและต้องหยุด chain อย่างถูกต้อง

1. Slot detail

GET /checkin/slot/{slotId} คืน status, cartons, customerOrderId และ pipeline progress Slot detail เป็น authoritative snapshot หลัง commit

2. Carton records

CheckInCartonItem มี packingId, trackingId, status, scannedAt, item/order counts รายการถูกแสดงซ้อนกันเพื่อเห็นสิ่งที่ check-in แล้วและเปิด delivery note mock

3. Ready flag

ScanCheckInResponse.isReadyToComplete บอกว่าครบทุก carton ตาม business rule ไม่ควรคำนวณจากจำนวน card ใน client เพราะ pipeline อาจเปลี่ยนจาก process อื่น

4. Complete command

POST /checkin/complete
{ slotId, operatorId }

เปลี่ยน slot เป็น READY และควร reject เมื่อยังไม่ครบหรือ version stale

5. Dispatch command

POST /checkin/dispatch
{ slotId, operatorId }

ย้ายขึ้นรถ/SHIPPED จึงต้องทำได้เฉพาะ READY และควรบันทึกปลายทาง/เวลา/actor

6. Current chain bug

_autoCompleteSlot แสดง error แต่ไม่คืน success/failure จากนั้น caller ยังเรียก dispatch ต่อ แม้ complete fail เช่นเดียวกับ dispatch failที่ workflow ยัง clear pending ควรให้แต่ละ commandคืน typed resultและหยุด chainเมื่อไม่สำเร็จ

7. Orchestration options

ถ้า complete+dispatch ต้องสำเร็จร่วมกันให้ backend มี endpoint orchestration เดียว; ถ้าเป็นสองสถานะธุรกิจจริง UI ต้องแสดง READY ที่ retry dispatch ได้โดยไม่ complete ซ้ำ

8. Chain tests

ทดสอบ scan not-ready, complete fail, dispatch failหลัง complete, timeoutแต่ละขั้น, retryจาก READY และ duplicate commands โดย stateสุดท้ายห้าม SHIPPED เมื่อ completeไม่สำเร็จ
