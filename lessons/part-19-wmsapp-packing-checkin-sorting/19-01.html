Outbound ปลายทางเป็น pipeline: Picking ย้ายของเข้า destination pallet, Packing ยืนยันของใน carton, Sorting จัดเข้า station และ Check-in รวม carton ลง slot ก่อน dispatch ทุกช่วงมี identity/status ของตนเอง

1. End-to-end map

picked pallet → Packing → carton/packingId
→ Sorting station/batch → Check-in slot
→ complete → dispatch/shipped

แต่ละลูกศรเป็น server transaction ไม่ใช่แค่เปลี่ยนหน้าจอ

2. Packing identities

palletId ครอบหลาย pack, packingId ครอบหลาย pick orders และ pickOrderId ครอบ parts การเปิดหน้าจอจึงไล่ pallet → pack → order → part ตามลำดับ ห้ามสลับ identity ระหว่างระดับ

3. Packing state machine

scanPallet → packList → orderList → orderParts
                    ↘ one order ────────┘
orderParts → success

เมื่อ pack มี order เดียว UI ข้าม orderList ได้

4. Check-in state

ไม่มี enum แต่ state เกิดจาก _pendingPack, _slotDetail และ _deliveryNotePack ทำให้หลาย combination เป็นไปได้ ควรนิยาม Previewing/ReadyToCommit/Committed เป็น typed state

5. Sorting station states

แต่ละ station เป็น AVAILABLE, BUSY หรือ DISABLED และ BUSY อาจ full Dashboard มี completed/queued counters แยกจาก station list จึงต้อง reconcile ทั้งระดับ global และราย station

6. Sources of truth

Packing/Check-in refresh ผ่าน REST หลัง mutation ส่วน Sorting รับ SignalR เพื่อ update เร็วแล้ว reload REST ในหลาย event Snapshot ล่าสุดจาก backend ต้องชนะ local animation/derived state

7. Cross-stage invariants

  • Pack ก่อน sorting/check-in
  • serial อยู่ได้หนึ่ง location
  • slot complete ก่อน dispatch
  • station disabled ไม่รับ batch ใหม่
  • retry ห้ามเพิ่ม qty/carton ซ้ำ

8. Trace exercise

เลือก packingId หนึ่งค่าแล้วจด pallet, orders, parts/serials, sorting station, slot และ final status ทุกช่วง พร้อม endpoint, operator และ idempotency boundary ของแต่ละ mutation
