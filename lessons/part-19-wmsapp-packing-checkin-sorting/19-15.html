บทสรุป outbound: ความถูกต้องไม่ได้วัดแค่ว่าหน้าสำเร็จขึ้น แต่ packingId ต้องเคลื่อนผ่านทุกสถานะครั้งเดียว พร้อมยอด/serial/location ที่ตรวจย้อนหลังได้

1. Packing trace

pallet → pack → order → part/serial
→ scan-part(s) → packFinalized
→ trackingId + palletReleased

partial requestที่ commitแล้วต้องไม่ถูกส่งซ้ำเมื่อ batchถัดไป fail

2. Sorting trace

DONE pack(s) → batch ASSIGNED/QUEUED
→ station BUSY → counters/FULL
→ clear → station AVAILABLE

SignalRทำให้เร็ว แต่ REST/versionทำให้ถูก

3. Check-in trace

preview packingId → slot decision
→ scan commit → slot detail
→ ready → complete → dispatch/SHIPPED

complete failต้องหยุด dispatch และคง stateให้ retryได้

4. Image trace

search part → pick/compress image
→ multipart upload → server validate/store
→ versioned URL → reload/cache refresh

5. Invariants checklist

  • qty/serialไม่เกิน remaining
  • packingIdไม่อยู่สอง station/slotพร้อมกัน
  • disabled stationไม่รับ batch
  • SHIPPED ต้องผ่าน READY
  • mutation retryไม่เพิ่มผลซ้ำ

6. Observability

ใช้ correlation/operation ID เชื่อม pack scan, batch, station events, check-in และ dispatch พร้อม operator/device/server timestamp Log identifiers/countsได้แต่ไม่ log tokenหรือไฟล์ภาพดิบ

7. End-to-end tests

รัน happy pathและ fault injection: network timeoutหลัง commit, duplicate scan, stationเต็ม/disabled, queue assignment, complete/dispatch conflict, reconnect eventหลุด และ image reject แล้วตรวจ DB stateกับ UI recovery

8. Capstone

ทำหนึ่ง outbound order ตั้งแต่ destination palletถึง SHIPPED พร้อม sequence diagram, state snapshots และ idempotency keys จากนั้นแก้ chain bug complete→dispatchด้วย typed resultและ testsพิสูจน์ว่า dispatchไม่เกิดเมื่อ complete fail
