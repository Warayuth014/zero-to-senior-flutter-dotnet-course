Preview แยก read decision จาก commit: scan Packing ID ครั้งแรกยังไม่เขียน DB แต่คืน slot/destination/items/progress เพื่อให้ operator ตรวจ ก่อนกด Check-IN จริง

1. Preview request

POST /checkin/preview
{ "packingId": packingId }

แม้ใช้ POST endpoint นี้ประกาศว่าไม่มี side effect จึงสามารถเรียกซ้ำเพื่อ refresh decision ได้

2. Preview response

มี owner/customer order, pack status, items/orders, pickOrderIds, slotId, isNewSlot, isAlreadyCheckedIn, dispatchDestination และ pipeline counters

3. Destination dialog

dialog barrierDismissible=false แสดง destination/slot หรือคำเตือนสแกนซ้ำ ผู้ใช้กดรับทราบแล้ว UI จึงตั้ง pending pack แต่ยังไม่ commit

4. Existing vs new slot

slot เดิมเรียก GET detail; slot ใหม่สร้าง synthetic CheckInSlotDetail status OPEN จาก counters ใน preview เพื่อแสดง pipeline ก่อนมี row จริงใน DB

5. Commit request

POST /checkin/scan
{ "packingId": packingId,
  "operatorId": operatorId }

response คืน slotId และ isReadyToComplete เท่านั้น จากนั้น UI refresh slot

6. Preview race

ระหว่าง preview กับ commit pack อาจถูกอีกเครื่อง check-in หรือ slot เปลี่ยน Backend ต้อง validate/assign atomically และตอบผล authoritative; client มี local duplicate guardแต่ห้ามพึ่ง guard นี้

7. Pending state

_pendingPack คือ draft พร้อมปุ่มยืนยัน; isAlreadyCheckedIn ปิดปุ่ม การสแกน carton ใหม่ขณะมี pending อาจแทน draft เดิม จึงควร confirm discard หรือ serialize workflow

8. Preview/commit tests

ทดสอบ new/existing slot, already checked-in, destination null, preview stale, two-device race, timeout after commit และ scan ใหม่ทับ pending โดย carton ต้องถูกบันทึกไม่เกินหนึ่งครั้ง
