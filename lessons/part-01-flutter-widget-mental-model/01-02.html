MaterialApp ไม่ใช่แค่ theme wrapper แต่ประกอบ Navigator, localization, inherited configuration, title และ material behavior ระดับแอป Root configuration ที่เปลี่ยนจะกระทบ subtree กว้าง

1. หน้าที่หลัก

MaterialApp(
  title: 'WMS',
  theme: lightTheme,
  darkTheme: darkTheme,
  themeMode: themeMode,
  locale: locale,
  supportedLocales: const [Locale('th'), Locale('en')],
  localizationsDelegates: delegates,
  home: const LoginScreen(),
)

นอกจากนี้ยังกำหนด routes/router, navigator observers, builder, debug banner และ restoration ได้ อย่าซ้อน MaterialApp ใหม่ทุก feature เพราะจะได้ Navigator/Theme/Localizations tree แยกโดยไม่ตั้งใจ

2. home กับ navigation

home เป็น route แรก ไม่ใช่ widget ที่ต้องเปลี่ยนด้วย setState ทุกหน้า หลัง login ใช้ Navigator replacement หรือ declarative Router ตาม architecture แอป ถ้าสร้าง MaterialApp ใหม่เพื่อไปหน้า shell back stack/dialog/theme อาจแปลก

3. builder ของ MaterialApp

absolute ใช้ builder ครอบ child ทุก route ด้วย AnnotatedRegion/ColoredBox/SafeArea เพื่อทำ system status bar เป็น policy เดียว จุดนี้เหมาะกับ app-wide wrapper เช่น text scaling boundary หรือ overlay แต่ต้องคืน child ไม่เช่นนั้น Navigator content หาย

4. Root rebuild ในสองโปรเจกต์

  • wmsapp: ValueListenableBuilder<ThemeMode> rebuild MaterialApp เมื่อ theme mode เปลี่ยน
  • absolute: ListenableBuilder rebuild MaterialApp เมื่อภาษาเปลี่ยน

Root rebuild ไม่ได้สร้าง native app ใหม่ แต่ inherited config เปลี่ยนจึงทำ descendants ที่ depend on Theme/Localizations rebuild เป็นวงกว้าง—เหมาะเพราะความหมายเปลี่ยนทั้งแอป

5. Inject dependency ที่ root

absolute รับ AuthRepository ผ่าน constructor ของ WmsApp แล้วส่งต่อ LoginScreen ทำ dependency ชัดและ test root ได้ง่ายกว่าเรียก global จากทุกหน้า สำหรับ dependency หลายชุดอาจใช้ inherited/provider/DI container แต่หลักคือ lifetime ต้องตรง app/session/feature

6. Theme/locale ต้องมี source เดียว

อย่าเก็บ themeMode ใน root พร้อม shared preference และ screen แยกคนละค่า ให้ controller/listenable เป็น source of truth โหลด persistence แล้ว MaterialApp consume ค่า ส่วน widgets ใช้ Theme.of(context)

7. แบบฝึกหัด

อธิบายผลถ้า SettingsScreen สร้าง MaterialApp ใหม่เพื่อใช้ theme อีกสี และเสนอวิธีถูก

เฉลย

จะเกิด nested Navigator/Theme/MediaQuery/Localizations boundary dialog/back behavior อาจไป navigator ผิด ให้เปลี่ยน Theme controller ระดับ root หรือใช้ Theme(data: ..., child: ...) ครอบ subtree เฉพาะจุดโดยไม่สร้าง app ใหม่

8. จุดพลาด

MaterialApp ควรมีหนึ่งตัวต่อ application/navigation root โดยทั่วไป ถ้าต้องมีหลายตัวใน test/embedded flow ต้องรู้ว่ากำลังสร้าง boundary อะไรใหม่บ้าง
