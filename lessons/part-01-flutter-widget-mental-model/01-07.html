1. ปัญหาที่บทนี้แก้

เราพิมพ์คำว่า context มาตั้งแต่ 1.2 โดยไม่รู้ว่ามันคืออะไร — ทั้ง Theme.of(context) และ parameter ของ build

ความไม่เข้าใจตรงนี้ทำให้เกิด error สองแบบที่คนใหม่เจอกันทุกคน และแก้ไม่ถูกจนกว่าจะเข้าใจว่า context คืออะไรจริง ๆ

  • No Scaffold widget found ทั้งที่มี Scaffold อยู่ในไฟล์ชัด ๆ
  • Don't use BuildContext across async gaps ที่ analyzer เตือน

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
BuildContextตัวชี้ตำแหน่งของ widget นี้ใน tree
ancestorwidget ที่อยู่ เหนือ เราขึ้นไป
descendantwidget ที่อยู่ ใต้ เราลงไป
.of(context)รูปแบบการค้นหาของจาก ancestor
Builderwidget ที่สร้าง context ใหม่ที่ต่ำลงไปหนึ่งชั้น
async gapช่วงเวลาที่โค้ดหยุดรอ await

3. Mental model: หมุดปักตำแหน่งบนต้นไม้

ทบทวนจาก 1.3: Element คือตัวจริงที่รู้ว่าตัวเองอยู่ตำแหน่งไหนใน tree — BuildContext ก็คือหมุดที่ปักอยู่ที่ Element ตัวนั้นเอง

เมื่อเราเขียน Theme.of(context) Flutter จะ เดินขึ้นไปตามต้นไม้จากหมุดนั้น จนกว่าจะเจอธีมตัวแรก

MaterialApp          ← มีธีมอยู่ตรงนี้
└── Scaffold
    └── Center
        └── Text     ← เราอยู่ตรงนี้ เดินขึ้นไปหาธีมเจอ
ประโยคเดียวที่ต้องจำ: .of(context) หาได้เฉพาะของที่อยู่ เหนือ ตำแหน่งของ context นั้น — มันมองลงล่างไม่ได้ และมองข้างไม่ได้

4. ปัญหาคลาสสิก: หา Scaffold ไม่เจอ

class MyScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: ElevatedButton(
        onPressed: () {
          // พังตรงนี้ — หา ScaffoldMessenger ไม่เจอ
          ScaffoldMessenger.of(context).showSnackBar(
            const SnackBar(content: Text('บันทึกแล้ว')),
          );
        },
        child: const Text('บันทึก'),
      ),
    );
  }
}

เหตุผล: context ตัวนี้เป็นของ MyScreen ซึ่งอยู่ เหนือ Scaffold ที่เพิ่งสร้าง เมื่อเดินขึ้นไปจึงไม่มีทางเจอ

MyScreen        ← context ที่เราใช้ อยู่ตรงนี้
└── Scaffold    ← สิ่งที่เราตามหา อยู่ข้างล่าง — หาไม่เจอ
    └── Button

ทางแก้ที่ 1 — ใช้ Builder เพื่อสร้าง context ที่ต่ำลงไป

Scaffold(
  body: Builder(
    builder: (innerContext) => ElevatedButton(
      onPressed: () => ScaffoldMessenger.of(innerContext).showSnackBar(...),
      child: const Text('บันทึก'),
    ),
  ),
)

ทางแก้ที่ 2 — แยกเป็น widget ของตัวเอง ซึ่งมักดีกว่าเพราะได้ประโยชน์ตาม 1.4 ไปด้วย

class SaveButton extends StatelessWidget {
  const SaveButton({super.key});

  @override
  Widget build(BuildContext context) {   // context นี้อยู่ใต้ Scaffold แล้ว
    return ElevatedButton(
      onPressed: () => ScaffoldMessenger.of(context).showSnackBar(...),
      child: const Text('บันทึก'),
    );
  }
}

5. context คนละตัวใน method เดียวกัน

เรื่องนี้สำคัญมากเมื่อเปิดกล่องโต้ตอบ

void _confirm(BuildContext context) {
  showDialog<void>(
    context: context,
    builder: (dialogContext) => AlertDialog(
      content: const Text('ยืนยันการบันทึก?'),
      actions: [
        TextButton(
          // ต้องใช้ dialogContext เพื่อปิดกล่อง ไม่ใช่ context ข้างนอก
          onPressed: () => Navigator.pop(dialogContext),
          child: const Text('ยกเลิก'),
        ),
      ],
    ),
  );
}
ตัวแปรชี้ไปที่ใช้ทำอะไร
contextหน้าจอที่เปิดกล่องบอกว่าจะเปิดกล่องบน Navigator ไหน
dialogContextตัวกล่องเองปิดกล่องนั้น

ถ้าใช้ context ตัวนอกไปปิด อาจปิดทั้งหน้าจอแทนที่จะปิดแค่กล่อง — ซึ่งเป็นบั๊กที่ผู้ใช้เจอแล้วงงมาก

6. context มีวันหมดอายุ

เชื่อมกับ 1.6 โดยตรง: context ผูกกับ Element ถ้า Element ถูกทิ้ง context ก็ใช้ไม่ได้อีก

Future<void> _save() async {
  await api.save(data);              // ระหว่างนี้ผู้ใช้อาจกดย้อนกลับ
  if (!context.mounted) return;      // ต้องตรวจก่อนใช้ต่อ
  Navigator.of(context).pop();
}
ใช้ตัวไหนเมื่อ
mountedอยู่ใน State และกำลังจะเรียก setState
context.mountedกำลังจะใช้ context ตัวนั้นโดยเฉพาะ
เมื่อมี context หลายตัวในฟังก์ชันเดียว ให้ตรวจ ตัวที่กำลังจะใช้ ไม่ใช่ใส่ mounted ไปเรื่อย ๆ เพื่อให้ analyzer เงียบ — เพราะ State อาจยังอยู่ ในขณะที่กล่องโต้ตอบถูกปิดไปแล้ว

7. อย่าเก็บ context ไว้ใช้ทีหลัง

ทำแบบนี้ผลที่ตามมา
เก็บ context ไว้ใน field ของ serviceservice อยู่ยาวกว่าหน้าจอ จึงถือ context ที่ตายแล้ว
ส่ง context เข้าไปใน class ที่จัดการข้อมูลทดสอบไม่ได้เพราะต้องมีหน้าจอจริง
ใช้ context ใน callback ที่ยิงหลังหลายวินาทีอาจใช้ตอนที่หน้าจอไปแล้ว

วิธีที่ถูกคือให้ส่วนที่จัดการข้อมูล คืนผลลัพธ์กลับมา แล้วให้หน้าจอเป็นคนตัดสินใจว่าจะแสดงอะไร — ซึ่งเป็นรูปแบบ callback จาก D1.11 ที่เราจะใช้เต็มรูปแบบใน 1.12

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
No Scaffold widget foundใช้ context ที่อยู่เหนือ Scaffoldใช้ Builder หรือแยกเป็น widget ย่อย
No MaterialLocalizations foundไม่มี MaterialApp อยู่เหนือขึ้นไปครอบด้วย MaterialApp (เจอบ่อยในเทสต์)
Don't use BuildContext across async gapsใช้ context หลัง await โดยไม่ตรวจใส่ if (!context.mounted) return;
กดปิดกล่องแล้วออกจากหน้าจอไปเลยใช้ context ตัวนอกไปปิดกล่องใช้ context ที่ builder ให้มา
เปลี่ยนธีมแล้ว widget บางตัวไม่เปลี่ยนสีไม่ได้อ่านสีผ่าน Theme.of(context)เลิกเขียนสีตรง ๆ
ทดสอบ class ที่จัดการข้อมูลไม่ได้มันรับ context เข้าไปให้มันคืนผลลัพธ์ แล้วหน้าจอจัดการ UI

9. แบบฝึกหัด

โค้ดนี้พังตอนกดปุ่ม จงบอกสาเหตุและแก้สองวิธี

class ScanScreen extends StatelessWidget {
  const ScanScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('สแกน')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            ScaffoldMessenger.of(context).showSnackBar(
              const SnackBar(content: Text('สแกนสำเร็จ')),
            );
          },
          child: const Text('สแกน'),
        ),
      ),
    );
  }
}
ดูแนวคำตอบและเหตุผล

สาเหตุ

context ที่ใช้เป็น parameter ของ build ใน ScanScreen ซึ่งอยู่ เหนือ Scaffold ที่บรรทัดถัดไปเพิ่งสร้างขึ้น เมื่อ ScaffoldMessenger.of เดินขึ้นไปตามต้นไม้ มันจึงไม่มีทางเจอ Scaffold ที่อยู่ข้างล่าง

วิธีที่ 1 — Builder

body: Builder(
  builder: (innerContext) => Center(
    child: ElevatedButton(
      onPressed: () => ScaffoldMessenger.of(innerContext).showSnackBar(
        const SnackBar(content: Text('สแกนสำเร็จ')),
      ),
      child: const Text('สแกน'),
    ),
  ),
),

วิธีที่ 2 — แยกเป็น widget ย่อย (แนะนำ)

class _ScanButton extends StatelessWidget {
  const _ScanButton();

  @override
  Widget build(BuildContext context) {
    return ElevatedButton(
      onPressed: () => ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('สแกนสำเร็จ')),
      ),
      child: const Text('สแกน'),
    );
  }
}

// ใน ScanScreen
body: const Center(child: _ScanButton()),

ทำไมวิธีที่ 2 ดีกว่า: เพราะได้ประโยชน์สามอย่างพร้อมกัน — แก้ปัญหา context, ปุ่มกลายเป็น const ได้จึงไม่ถูกสร้างใหม่ทุกรอบ (1.10) และทดสอบปุ่มแยกได้โดยไม่ต้องเปิดทั้งหน้าจอ (1.4) ส่วน Builder เหมาะเมื่อโค้ดสั้นมากจนไม่คุ้มที่จะตั้งชื่อให้

จุดที่คนมักเข้าใจผิด: หลายคนคิดว่า “ก็ Scaffold อยู่ในไฟล์เดียวกัน มองเห็นชัด ๆ ทำไมหาไม่เจอ” — เพราะ Flutter ไม่ได้ค้นหาจากไฟล์ แต่ค้นจาก ตำแหน่งใน tree ตอนรัน ซึ่งเป็นคนละเรื่องกับที่ตาเราเห็นในโค้ด

ลองต่อ: เพิ่มการรอด้วย await Future.delayed(const Duration(seconds: 3)) ก่อนแสดงข้อความ แล้วกดปุ่มและรีบกดย้อนกลับ — จะเห็น error เรื่อง context หมดอายุ จากนั้นแก้ด้วย if (!context.mounted) return;

10. สรุปท้ายบท

  • BuildContext คือตำแหน่งของ widget ใน tree ไม่ใช่ตัวแปรกลางของแอป
  • .of(context) หาได้เฉพาะของที่อยู่เหนือขึ้นไปเท่านั้น
  • ใช้ Builder หรือแยก widget ย่อย เมื่อต้องการ context ที่ต่ำลงไป
  • กล่องโต้ตอบมี context ของตัวเอง ใช้ตัวนั้นในการปิด
  • context หมดอายุได้ — ตรวจ context.mounted หลัง await
  • อย่าเก็บ context ไว้ในส่วนที่จัดการข้อมูล

บทถัดไป: 1.8 จะอธิบาย key ที่เราเลื่อนไว้ตั้งแต่ 1.3 — เครื่องมือที่บอก Flutter ว่า “ถึงจะย้ายที่ ก็ยังเป็นตัวเดิม” และแก้บั๊กข้อมูลสลับกันในรายการ
