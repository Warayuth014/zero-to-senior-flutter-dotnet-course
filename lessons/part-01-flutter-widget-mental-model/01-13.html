ListenableBuilder rebuild subtreeเมื่อ Listenable notify; ValueListenableBuilder<T> ส่ง current valueเข้า builderและรองรับ childคงที่ ทั้งสองเป็นสะพานจาก mutable notifierสู่ declarative widget tree

1. ValueListenableBuilder

ValueListenableBuilder<ThemeMode>(
  valueListenable: themeProvider,
  builder: (context, mode, child) => MaterialApp(
    themeMode: mode,
    home: child,
  ),
  child: const HomeScreen(),
)

wmsapp rootใช้ ThemeProviderที่ extends ValueNotifier ทำให้ builderได้ typed valueโดยไม่อ่าน globalซ้ำ

2. ListenableBuilder

ListenableBuilder(
  listenable: store,
  builder: (context, child) => WarehouseBody(store: store),
)

เหมาะ ChangeNotifier/หลาย fields Builderอ่าน snapshotจาก object Absoluteใช้กับ language controller, WarehouseStore, ConnectionController

3. Rebuild scope

วาง builderต่ำสุดที่ครอบทุก consumerแต่ไม่ครอบของคงที่ Absolute shellแยก bodyกับ bottom navigation listeners แม้ฟัง storeเดียวกัน เพื่อชัดว่าแต่ละ subtree renderอะไร ส่วน app-wide languageอยู่เหนือ MaterialAppเพราะ localeกระทบทั้งแอป

4. child optimization

ถ้า subtreeไม่ขึ้นกับ listenableให้สร้างครั้งเดียวใน child แล้วส่งเข้า builder ลดการ rebuild config แต่ต้องแน่ใจว่า childไม่อ่าน stateนั้นทาง context/global มิฉะนั้น optimizationผิดความหมาย

5. Notify เป็น contract

Mutationใน ChangeNotifierต้องรักษา invariantแล้วเรียก notifyListenersหนึ่งครั้งที่เหมาะ Public mutable fieldsที่ UIแก้เองอาจลืม notify ให้ expose getters/commands และ batch updateก่อน notify

6. Ownership/dispose

Builderเพิ่ม/ถอด listenerตาม element lifecycle แต่ไม่ได้ dispose listenableให้ Listenables singleton/app ownerอยู่ต่อ ส่วน storeที่ shellสร้างต้อง shell.dispose ดังโค้ดจริง ห้ามคิดว่า builderจัดการ resourceทั้งหมด

7. แบบฝึกหัด

Connection statusเปลี่ยนเฉพาะจุดสีบน header ควรวาง builderตรงไหน?

เฉลย

ครอบ status indicator/ส่วน headerที่ dependเท่านั้น ไม่ครอบ MaterialAppหรือทั้ง workflow screen หาก language/themeไม่เกี่ยว ใช้ Listenable/ValueListenableเฉพาะ connection controllerและ childคงที่รอบข้าง

8. จุดพลาด

Nested buildersจำนวนมากไม่จำเป็นอาจ rebuildซ้ำและซ่อน dependency ให้รวม listenablesหรือสร้าง view model snapshotเมื่อหลายค่าต้องเปลี่ยน atomically แต่อย่า notifyทั้ง God Storeทุก eventแล้วหวัง constช่วย
