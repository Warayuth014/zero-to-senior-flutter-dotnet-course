main() คือ Dart entry point, WidgetsFlutterBinding เชื่อม framework กับ engine/platform services และ runApp นำ root widget เข้า Flutter tree นี่คือลำดับ bootstrap ก่อนมีหน้าจอแรก

1. เส้นทางเริ่มต้น

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await loadRequiredConfiguration();
  runApp(const WmsApp());
}

Dart runtime เรียก main → binding พร้อม → bootstrap ที่จำเป็นเสร็จ → runApp attach root widget และ schedule frame แรก ถ้า config ไม่จำเป็นต่อ request/frame แรก อาจเริ่มภายหลังเพื่อไม่ยืด startup

2. Binding ทำอะไรใน mental model

Binding เป็นจุดประสาน widget/rendering/scheduler/services กับ engine เช่น lifecycle, platform channels, SystemChrome และ frame scheduling ปกติ runApp สร้าง binding ให้เอง แต่ต้อง ensureInitialized ก่อนเมื่อ main เรียก plugin/platform service หรือใช้งาน binding ก่อน runApp

3. เปรียบเทียบสองแอป

  • wmsapp/main.dart: ensure binding แล้ว runApp; root สร้าง theme/listenable ต่อ
  • wms_absolute_mobile/main.dart: await ภาษาและ connection profiles, ตั้ง system UI แล้ว inject AuthRepository(ApiClient()) เข้า WmsApp ก่อน runApp

คอมเมนต์ใน absolute ระบุ invariant สำคัญ: connection ต้อง load ก่อน request แรก มิฉะนั้น client ใช้ fallback server ผิด

4. Bootstrap failure ต้องมี UX

ถ้า initialization อาจ fail/ช้า เช่น secure storage หรือ remote config อย่าปล่อยหน้าจอดำโดยไม่มีขอบเขต ออกแบบ bootstrap widget/state ที่แสดง loading/retry หรือ catch ก่อน runApp แล้วเปิด recovery app ทั้งนี้ config ที่ backend ต้องใช้ควรมี owner และ timeout ชัด

5. runApp ไม่ควรถูกเรียกเพื่อเปลี่ยนหน้า

Navigation/state update ทำภายใน tree เดิม การเรียก runApp ซ้ำแทน logout/theme change ทำให้ root configuration ถูกแทนและ lifecycle ซับซ้อน ใช้ Navigator/Listenable/state owner ตามโจทย์

6. Zone/error boundary ระดับเริ่มแอป

Framework, platform dispatcher และ async errors มีจุดดักต่างกัน บท production จะจัด logging/crash reportingเต็มรูปแบบ ตอนนี้จำว่า try/catch รอบ runApp ไม่ได้จับ async/widget errors ทุกชนิด ต้องวาง boundary ตามแหล่ง error

7. แบบฝึกหัด

จัดลำดับ: load connection profile, runApp, create ApiClient, SystemChrome style และยิง request แรก พร้อมระบุสิ่งใดต้อง await

แนวคำตอบ

ensure binding → await connection profile ที่กำหนด base URL → set system UI → สร้าง client/repository ด้วย config ที่พร้อม → runApp → request แรกจาก screen/store หาก language/profile โหลดไม่สำเร็จต้องมี recovery policy ไม่ปล่อย request ใช้ค่าเดา

8. จุดพลาด

main() async ไม่ได้แปลว่าควร await ทุกอย่างก่อน runApp งานที่ไม่บังคับต่อ frame/request แรกควรเลื่อน แต่ dependency ที่กำหนด contract แรกห้ามเกิด race
