Data/config ไหล parent → child ผ่าน constructor ส่วน event ไหล child → owner ผ่าน typed callback นี่คือ unidirectional UIพื้นฐานที่ทำให้ child reusableและ business mutationมีจุดเดียว

1. Typed callback

class QuantityEditor extends StatelessWidget {
  const QuantityEditor({
    super.key,
    required this.value,
    required this.onChanged,
    required this.onConfirm,
  });
  final int value;
  final ValueChanged<int> onChanged;
  final Future<void> Function() onConfirm;
}

อย่าใช้ Function กว้างเพราะ compilerตรวจ argument/returnไม่ได้ Signatureบอก async/error ownershipให้เห็น

2. Child แจ้ง intent ไม่แก้ parent state

QuantityEditor(
  value: store.quantity,
  onChanged: store.setQuantity,
  onConfirm: store.confirmPick,
)

Childไม่ต้องรู้ setState/ChangeNotifier/API Parent/storeตรวจ invariantและ notifyกลับลงมาเป็น valueใหม่

3. Closure เพิ่ม argument

_Tile(
  title: 'Receiving',
  onTap: () => store.nav('receive'),
)

HomeViewใช้ patternนี้ Closureเหมาะ adapterสั้น ๆ แต่ถ้าจับ stateหลายตัว/logicยาวให้ใช้ named methodเพื่อ stack trace/test/อ่านง่าย

4. Async callback และ duplicate tap

Widget button APIรับ void callbackจึงไม่ await Futureอัตโนมัติ Ownerต้องกัน busy, catch errorและแสดง loading Childอาจ disableด้วย onPressed: busy ? null : onConfirm อย่าให้ทั้ง childและparentมี busyคนละค่า

5. Result จาก dialog/route

บาง eventเหมาะ request-responseผ่าน Future เช่น showDialog<bool> หรือ Navigator.pushคืน result Parent awaitแล้วตรวจ mountedก่อน commit state ทำให้ dialogเป็น presentation componentไม่เรียก repositoryเอง

6. Callback identity/performance

closureใหม่ทุก buildปกติไม่ใช่ปัญหาหลัก อย่า optimizeด้วย cache callbackก่อนวัด ให้สนใจ side effectและ rebuild scopeก่อน แต่ listener APIที่ removeต้องใช้ callback instanceเดียวกับตอน add จึงเก็บ method/fieldตาม lifecycle

7. แบบฝึกหัด

ออกแบบ ScanBoxที่แจ้ง barcode submitและไม่รู้ API/store

เฉลย
class ScanBox extends StatelessWidget {
  const ScanBox({super.key, required this.busy, required this.onSubmitted});
  final bool busy;
  final Future<void> Function(String barcode) onSubmitted;
  // normalizeขั้น presentationขั้นต่ำ; owner validate/domain/API
}

Ownerส่ง (code) => store.submitScan(code) และ busyจาก sourceเดียว

8. จุดพลาด

Callback chainผ่าน 5ชั้นอาจบอกว่า state ownerอยู่ไกลเกิน ควรย้าย feature container/storeใกล้ consumersหรือใช้ inherited/providerอย่างมีขอบเขต ไม่แก้ด้วย global singletonทันที
