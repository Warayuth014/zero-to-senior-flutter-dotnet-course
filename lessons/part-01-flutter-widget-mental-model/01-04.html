StatelessWidget ไม่มี State object ของตัวเอง แต่ rebuild ได้เมื่อ parent update หรือ inherited dependency ที่มันใช้เปลี่ยน คำว่า stateless ไม่ได้แปลว่า “build ครั้งเดียว”

1. Configuration จาก constructor

class TaskTile extends StatelessWidget {
  const TaskTile({
    super.key,
    required this.task,
    required this.onTap,
  });
  final WmsTask task;
  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) => ListTile(
    title: Text(task.id),
    onTap: onTap,
  );
}

fields เป็น final และ widget แสดงผลจาก input/context Parent เป็น owner ของ mutable state แล้วส่ง snapshot/callback ลงมา

2. เหตุที่ Stateless rebuild

  • parent build คืน instance/config ใหม่
  • Theme.of, MediaQuery, Localizations ที่ depend เปลี่ยน
  • Element ถูก reinsert/update ตาม identity

จึงห้าม cacheค่าจาก context ใน global หรือทำ API ใน build เพราะ build ถูกเรียกได้บ่อย

3. ตัวอย่างจริง

HomeView, _Tile, _HomeIcon เป็น StatelessWidget รับ WarehouseStore/snapshot properties/callback แล้วประกอบ UI ส่วน WmsApp ก็ stateless แม้แอปรองรับภาษา/theme เปลี่ยน เพราะ mutable owner อยู่ Listenable ภายนอก

4. ส่ง store เข้า Stateless ได้ แต่ต้องฟังให้ถูก

การมี field WarehouseStore store ไม่ทำ widget rebuildเองเมื่อ store mutate ต้องมี ListenableBuilder เหนือ HomeView หรือ builder ภายใน ถ้า parent shell กำลังฟัง store และ rebuild body ก็พอ แต่ dependency scope ต้องอ่านจาก tree จริง

5. Derived UI ไม่ต้องเก็บ state

ค่าพวก hasBadge = count > 0, label จาก enum, color จาก status ควรคำนวณใน build/helper pure ไม่ย้ายเป็น mutable state ที่ต้อง sync สองจุด

6. เมื่อควร Stateful

เมื่อ widget เป็น owner ของ lifecycle state เช่น controller, focus, animation, subscription หรือ local selection ที่ต้องอยู่ข้าม rebuild หาก state เป็นของ workflow/shared ให้ย้ายไป store ไม่ใช่เปลี่ยนทุกอย่างเป็น StatefulWidget

7. แบบฝึกหัด

Card แสดง status จาก task และกดแล้วเรียก parent ต้องเป็น Stateful ไหม?

เฉลย

ไม่จำเป็น ใช้ Stateless รับ task/status และ callback ถ้า hover/animation/local expand ต้องอยู่ข้าม buildจึงค่อย Stateful หรือ widget animationสำเร็จรูป แต่ business status ยังเป็นของ parent/store

8. จุดพลาด

อย่าใส่ mutable collection/controller ใน Stateless แล้วแก้เงียบ ๆ เพราะไม่มี lifecycle/dispose และไม่มี signal rebuild ให้ state owner ชัดหรือสร้างค่าชั่วคราวใน buildเท่านั้น
