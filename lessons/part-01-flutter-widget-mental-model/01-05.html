StatefulWidget เองยัง immutable; mutable data อยู่ใน State<T> ที่ framework ผูกกับตำแหน่ง/type/key ใน tree การแยก config กับ state ทำให้ parent เปลี่ยน input โดยรักษา lifecycle เดิมได้

1. คู่ widget/state

class SummaryCard extends StatefulWidget {
  const SummaryCard({super.key, required this.store});
  final WarehouseStore store;

  @override
  State<SummaryCard> createState() => _SummaryCardState();
}

class _SummaryCardState extends State<SummaryCard> {
  DashboardMode mode = DashboardMode.list;

  @override
  Widget build(BuildContext context) { /* widget.store + mode */ }
}

2. ใครเปลี่ยนอะไร

Parent เปลี่ยน configuration ผ่าน constructor → State อ่านจาก widget; State เปลี่ยน local value ผ่าน setState; shared/business state เปลี่ยนผ่าน store command แล้ว listener rebuild อย่าคัดลอก widget.store.value มา field local โดยไม่มี sync policy

3. setState มีความหมาย

setState รัน callback ทันทีแล้ว mark Element นี้ dirty เพื่อ build รอบถัดไป มันไม่ได้ทำ mutationให้เองและไม่ได้ rerender synchronous ทุกบรรทัด

setState(() => mode = DashboardMode.chart);

เก็บเฉพาะ mutation synchronous สั้น ๆ ใน callback งาน async ทำก่อน/หลังแล้วเรียก setState เมื่อมี snapshot ใหม่

4. ตัวอย่างจริง

_SummaryCardState ใน absolute ถือ list/chart mode ซึ่งเป็น local presentation state เหมาะสม ส่วน WarehouseShellState สร้าง WarehouseStore และถือ timers/flash/toast lifecycle ส่วน LoginScreen ถือ controllers/focus/submitting/error

5. Identity กำหนด State อยู่ต่อ

ถ้า parent สร้าง widget type/key เดิมใน slot เดิม State อยู่ต่อ แม้ constructor instance ใหม่ หาก key/typeเปลี่ยน State เดิม dispose และสร้างใหม่ ดังนั้นอย่าใช้ UniqueKey ทุก build เพื่อ “แก้ refresh” เพราะทำลาย state/lifecycle

6. Local vs lifted state

mode ของ card ไม่มีใครนอก cardใช้ → local State; current warehouse screen/badges/tasks หลาย widgetsใช้ → WarehouseStore; auth sessionอยู่ระดับ session repository การวาง owner ตามผู้ใช้ข้อมูลช่วยลด callback/global ซ้ำซ้อน

7. แบบฝึกหัด

จำแนก owner ของ password visibility, JWT session, dashboard list/chart และ current warehouse task

เฉลย
  • password visibility: Login State
  • JWT session: Auth/session repository ระดับกว้าง
  • list/chart: SummaryCard State
  • current task: WarehouseStore/feature workflow state

8. จุดพลาด

ถ้า State มีทั้ง controllers, API calls, parsing, business transitions และ widget codeจำนวนมาก แปลว่า StatefulWidget กลายเป็น architecture ทั้งระบบ ต้องแยก store/repository/model ไม่ใช่แค่แตก helper methods
