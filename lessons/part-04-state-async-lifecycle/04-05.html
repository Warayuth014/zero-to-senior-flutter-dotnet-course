ChangeNotifier เป็น observable mutable owner: commandsรักษา invariantsแล้ว notifyListeners() เพื่อให้ consumersอ่าน snapshotใหม่ ความง่ายนี้แลกกับความรับผิดชอบเรื่อง encapsulation, notification granularity และ async race

1. Store ขั้นต่ำ

class TaskStore extends ChangeNotifier {
  TaskStore(this.repository);
  final TaskRepository repository;
  final List<Task> _tasks = [];
  List<Task> get tasks => List.unmodifiable(_tasks);

  void select(String id) {
    if (_selectedId == id) return;
    _selectedId = id;
    notifyListeners();
  }
  String? _selectedId;
}

2. Encapsulate mutation

อย่า expose mutable list/public fieldsให้ UIแก้โดยไม่ notify ConnectionControllerเก็บ profiles privateและคืน List.unmodifiable ส่วน WarehouseStoreจริงยังมี public mutable fieldsมากเพื่อความตรงไปตรงมา ซึ่งต้องมีวินัยให้ทุก mutationผ่าน methods

3. Notify หลัง consistent snapshot

อัปเดตหลาย fieldที่เป็น transactionเดียวกันก่อน notifyหนึ่งครั้ง เช่น replace tasks → clear invalid selection → set loaded ถ้า notifyกลางทาง UIอาจเห็น selectionที่ไม่มีใน list อย่า notifyทุก assignmentโดยอัตโนมัติ

4. Loading pattern

Future<void> load() async {
  if (_loading) return;
  _loading = true; _error = null; notifyListeners();
  try {
    _tasks..clear()..addAll(await repository.fetch());
  } catch (e) {
    _error = mapError(e);
  } finally {
    _loading = false; notifyListeners();
  }
}

WarehouseStore loadPalletsใช้รูปแบบนี้ตรง ๆ

5. Repository injection

Storeรับ interfaces/repositoriesผ่าน constructor ไม่สร้าง HTTP clientเอง ทำ fake repository, deterministic Future/errorและ test transitionsได้ Absolute WarehouseStoreรับ receiving/tasks/inventory/cycle-count repositoriesครบ

6. Dispose

ChangeNotifier disposeหยุดการใช้งานและ assertถ้า notifyภายหลัง Storeต้อง cancel timers/subscriptionsก่อน super.dispose Shellที่สร้าง WarehouseStoreเป็นคน dispose อย่า dispose singleton controllerจาก widgetชั่วคราว

7. แบบฝึกหัด

Commandเพิ่ม taskลง listแล้ว notify แต่ callerยังถือ listจาก getterและแก้ได้ จะแก้อย่างไร?

เฉลย

เก็บ list private คืน UnmodifiableListView/List.unmodifiableหรือ immutable snapshot; expose add/remove/update commandsที่ validateและ notify ทำ model immutableเพื่อไม่ให้ callerแก้ fieldภายในโดยไม่ผ่าน store

8. จุดพลาด

ChangeNotifierไม่ทำ thread safety, cancellation, equality หรือ error handlingให้อัตโนมัติ มันแค่ส่ง notification ต้องออกแบบ state/commands/raceเหมือนเดิม และ God Storeที่ notifyทุกเรื่องจะ scaleยาก
