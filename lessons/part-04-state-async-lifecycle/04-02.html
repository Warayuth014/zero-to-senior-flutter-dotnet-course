Derived state คือค่าที่คำนวณได้จาก source of truth อื่น หากเก็บซ้ำจะต้อง syncหลายจุดและเกิด impossible state ให้เก็บข้อมูลขั้นต่ำแล้วคำนวณ getter/selector เว้นแต่มีเหตุผลด้าน snapshot/performanceที่พิสูจน์ได้

1. ตัวอย่างไม่เก็บซ้ำ

final List<Task> tasks = [];

int get pendingCount => tasks.where((t) => t.isPending).length;
bool get isEmpty => tasks.isEmpty;
Task? taskById(String id) => tasks.where((t) => t.id == id).firstOrNull;

ไม่ต้องมี fields pendingCount, hasTasks ที่ลืมอัปเดตตอน replace/filter

2. WarehouseStore จริง

Store เก็บ picks/destination/selected IDs แล้วคำนวณ activePicksForCurrentDestination, activePickCount, selectedPickingConveyor เป็น getters การใช้ IDแทน duplicate selected objectช่วย reconcileหลัง reload list

3. Normalize state shape

เก็บ entityตาม ID + selection ID เมื่อข้อมูล refresh object instanceเปลี่ยน getterยังหา entityล่าสุดได้ ถ้าเก็บทั้ง selectedTask objectและ task list อาจ selectedอ้าง objectเก่าที่ statusไม่ตรง list

4. เมื่อ cache derived valueได้

การคำนวณหนักบน listใหญ่มากและเรียกบ่อยอาจ memoizeตาม immutable input/version แต่ต้อง invalidateจาก sourceเดียว ใช้ profileก่อน optimize ส่วน filter/sortที่เป็น user intentอาจเก็บ query/sort mode แล้ว derive visible list

5. Async derived state

ค่าจาก serverไม่ถือว่า derived localแม้คำนวณได้เชิงแนวคิด หากต้อง authority/current snapshotให้เก็บ responseหรือ fetchผ่าน repository เช่น doneTodayCount/locationCountมาจาก DBและอยู่รอด restart จึงเป็น server state ไม่คำนวณจาก listที่โหลดบางส่วน

6. Invariants

กำหนดว่า selectionต้อง nullหรือมีใน list หลัง refresh WarehouseStoreตรวจ selected IDแล้ว clearถ้าหาไม่พบ ทำ mutation batchก่อน notifyหนึ่งครั้ง ป้องกัน UIเห็นช่วง listใหม่แต่ selectedเก่า

7. แบบฝึกหัด

มี requiredQty, set serials และ scannedQty ควรเก็บอะไร?

เฉลย

เก็บ requiredQtyและ Setของ accepted serial IDs; derive scannedQtyจาก set.length, remainingจาก clamp(required-scanned), completeจาก equality/range ไม่เก็บทั้งสามตัวเลขซ้ำ เว้น backendส่ง authoritative countsที่ไม่เท่ากับ local pending ต้องตั้งชื่อแยกชัด

8. จุดพลาด

อย่าใช้ getterที่ mutate, ยิง API หรือ notifyListeners Getterควรอ่าน snapshotอย่าง predictable มิฉะนั้น buildที่อ่านซ้ำทำ side effectและ debugยาก
