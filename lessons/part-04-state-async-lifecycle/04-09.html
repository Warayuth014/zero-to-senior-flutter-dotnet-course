Part 4: State, Async & Lifecycle

จัดการ local/app state, asynchronous workflow, timer และ race condition ที่เกิดจริงในแอป

1. เป้าหมายของบทนี้

  • อธิบาย mounted และ context หลัง await ด้วยภาษาของตัวเองได้
  • ชี้ได้ว่าแนวคิดนี้อยู่ตรงไหนใน flow Flutter → .NET
  • ทดลองและตรวจผลได้ ไม่ใช่จำโค้ดอย่างเดียว

2. Mental model

Future<T> แทนผลลัพธ์ที่จะมาในอนาคต await พักเฉพาะ async function ไม่ได้ block UI thread จุดสำคัญคือ error จะเดินทางผ่าน Future และ widget อาจถูก dispose ระหว่างรอ

หัวข้อนี้อยู่ในกลุ่ม State, Async & Lifecycle เมื่อเปิดโค้ดจริงให้ถามว่าใครเป็นเจ้าของข้อมูล ใครเปลี่ยนข้อมูล และ widget ใดต้อง rebuild หลังการเปลี่ยนนั้น

มุม Flutter: จับหลักให้ได้ก่อน แล้วค่อยเทียบการใช้งานสองแบบในโปรเจกต์จริง

3. หาในโปรเจกต์จริง

บทพื้นฐานนี้เตรียมแนวคิดสำหรับอ่านทั้ง wmsapp และ wms_absolute_mobile โดยบท Codebase Deep Dive จะระบุไฟล์จริงแบบรายไฟล์

4. วิธีไล่ทีละขั้น

  1. เริ่มจาก event ของผู้ใช้ เช่น tap, submit หรือ scan
  2. ตาม method ที่เปลี่ยน state หรือเรียก dependency
  3. ถ้ามี I/O ให้เปิด request DTO, endpoint และ response model คู่กัน
  4. กลับมาดูว่า state ใหม่ทำให้ widget ส่วนใด rebuild
  5. เขียน test หรือ checklist เพื่อพิสูจน์ happy path และ error path

5. ตัวอย่างโค้ด

class ScanStore extends ChangeNotifier {
  bool loading = false;

  Future<void> submit(String code) async {
    if (loading) return;
    loading = true;
    notifyListeners();
    try {
      await repository.submit(code.trim());
    } finally {
      loading = false;
      notifyListeners();
    }
  }
}

6. จุดที่พบบ่อยในงานจริง

อย่าเรียก setState/notifyListeners หลัง dispose และอย่าให้ response เก่าทับ state ของ request ใหม่

7. Mini Exercise

  1. ค้นหา mounted และ context หลัง await หรือ symbol ที่เกี่ยวข้องในสอง reference apps
  2. วาด flow สั้น ๆ จาก UI ไป data source แล้วกลับมา UI
  3. เพิ่ม error case หนึ่งกรณีและอธิบายว่าผู้ใช้ควรเห็นอะไร

8. Checklist

  • บอก owner ของ state ได้
  • แยก synchronous code กับ asynchronous side effect ได้
  • รู้ว่า dispose/cancel ตรงไหน
  • อธิบาย contract กับ .NET โดยไม่ต้องเดาจาก UI

9. สรุปจำเร็ว

mounted และ context หลัง await ต้องตอบได้ทั้ง “มันคืออะไร”, “อยู่ตรงไหนในโค้ด”, “พังแบบไหน” และ “ทดสอบอย่างไร”
