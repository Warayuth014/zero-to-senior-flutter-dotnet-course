Finite state machine (FSM) ระบุ finite states, events, guards และ transitions ทำให้ workflowหลายขั้นไม่มี boolean combinationsที่เป็นไปไม่ได้ และบังคับ async resultกลับเข้าทาง eventที่ตรวจ current state

1. Boolean explosion

loading, hasPallet, confirmed, error, done ห้าตัวมี 32 combinationsแต่ถูกจริงไม่กี่แบบ เช่น done+loading+errorพร้อมกันอาจไม่มีความหมาย FSMแทนด้วย stateเดียวที่ encodeข้อมูลจำเป็น

2. State types

sealed class ReceiveState { const ReceiveState(); }
class ScanItem extends ReceiveState { const ScanItem(); }
class EnterQuantity extends ReceiveState {
  const EnterQuantity(this.item); final Item item;
}
class ScanPallet extends ReceiveState {
  const ScanPallet(this.draft); final ReceiveDraft draft;
}
class Submitting extends ReceiveState {
  const Submitting(this.draft, this.operationId);
  final ReceiveDraft draft; final String operationId;
}
class Completed extends ReceiveState {
  const Completed(this.receipt); final Receipt receipt;
}

3. Event + guard

scanBarcode ใช้ได้เฉพาะ ScanItem/ScanPalletตาม target; setQuantity เฉพาะ EnterQuantityและ range; confirmเฉพาะ ready state Guard reject eventโดยไม่ mutate และ feedbackบอก targetปัจจุบัน

5. Absolute flow

WarehouseStoreปัจจุบันใช้ screen, step indicesและ transient fields เช่น rStep/tStep ซึ่งเป็น FSMแบบ implicitและ workflow definitions map step การเปลี่ยนเป็น typed stateช่วย compile-time exhaustiveness แต่ migrationต้องรักษา API/UI behaviorและแบ่ง feature storeไม่ให้ไฟล์เดียวโต

6. Entry/exit effects

Focus, polling, fetchและfeedbackเป็น effectsของ transition ไม่อยู่ build เช่นเข้า ScanPallet→focus pallet; เข้า Submitting→call repositoryครั้งเดียว; exit workflow→increment session/cancel request Testsแยก pure reducerจาก effect runnerได้

8. จุดพลาด

Enumอย่างเดียวไม่พอถ้า dataของแต่ละ stateยังเป็น nullable fieldsสิบตัว ใช้ sealed classes/recordsที่ stateถือ required dataของตน หรืออย่างน้อยรวม immutable snapshot+validated transitions
