ValueNotifier<T> เหมาะกับ stateหนึ่งค่าที่มี equalityชัดและ commandไม่ซับซ้อน มัน notifyเมื่อกำหนด value ใหม่ที่ไม่เท่าค่าเดิม ไม่ตรวจ mutationภายใน mutable object

1. ตัวอย่าง ThemeMode

class ThemeController extends ValueNotifier<ThemeMode> {
  ThemeController() : super(ThemeMode.system);

  void toggle() {
    value = value == ThemeMode.dark ? ThemeMode.light : ThemeMode.dark;
  }
}

wmsapp rootใช้ ValueListenableBuilderกับ ThemeModeทำให้ APIอ่านง่ายกว่า ChangeNotifierที่ต้อง getterเพิ่ม

2. ValueListenableBuilder

ValueListenableBuilder<ThemeMode>(
  valueListenable: themeController,
  builder: (_, mode, child) => MaterialApp(
    themeMode: mode,
    home: child,
  ),
  child: const HomeScreen(),
)

childคงที่ไม่ถูกสร้างซ้ำเพราะไม่ขึ้นกับ mode

3. Immutable value

ValueNotifier<List<Task>> แล้ว value.add(task) จะไม่ notifyเพราะ setterไม่ถูกเรียก ให้ assign listใหม่ value = [...value, task] หรือใช้ storeที่ encapsulate mutationและ notifyชัด

4. เมื่อโตเกิน ValueNotifier

ถ้ามี loading/error/dataหลาย field, async commands/invariantsหรือหลาย slices เปลี่ยนพร้อมกัน ใช้ immutable state objectใน ValueNotifierได้ระยะหนึ่ง หรือ ChangeNotifier/controllerแบบ explicit อย่าสร้าง ValueNotifierสิบตัวโดยไม่มี atomic update policy

5. Ownership/dispose

Notifierที่ widgetสร้างต้อง dispose; singleton/app ownerอยู่ตลอด appไม่ให้ builder dispose แทน Constructorรับ ValueListenableช่วย testด้วย fake notifierและไม่ผูก implementation

6. ValueNotifier vs setState

setStateเหมาะ stateภายใน widgetเดียว ValueNotifierเหมาะเมื่อค่าเดียวแชร์หลาย widgets/แยก ownerหรืออยาก expose listenable contract ทั้งคู่ไม่ใช่ persistence/repository เลือกจาก ownershipไม่ใช่กระแส package

7. แบบฝึกหัด

Connection statusมี unknown/connecting/connected/disconnectedและ last error/profileหลายค่า ใช้ ValueNotifierค่าเดียวดีไหม?

เฉลย

ถ้ารวมเป็น immutable ConnectionState snapshotเดียวและ transitionsไม่ซับซ้อนใช้ได้ แต่โปรเจกต์จริงมี profiles, active ID, persistence, resultและ commandsหลายตัว ChangeNotifier controllerเหมาะกว่า โดย expose gettersไม่ให้แก้ listตรง

8. จุดพลาด

อย่าพึ่ง mutationภายในค่าเดิมแล้วเรียก notifyListeners เพราะ ValueNotifierไม่ได้ exposeให้เรียกจากภายนอกอย่างตั้งใจ ใช้ immutable replacementหรือ subclass/storeที่ contractชัด
