สถานะปัจจุบัน: wmsappมี widget smoke testเพียงไฟล์เดียว ขณะที่ absoluteมี flow/widget/model testsและ fake repositoriesหลายชุด จึงมี safety netสำหรับ refactorมากกว่าแต่ยังขาด failure/raceบางเส้น

1. Characterization test

ก่อนเปลี่ยนโครงสร้าง เขียน testบันทึก behaviorที่ระบบทำจริงแม้ implementationไม่สวย จุดประสงค์คือกัน accidental change ไม่ใช่รับรองว่า behaviorปัจจุบันถูกทุกข้อ; behaviorที่สงสัยต้องระบุ product decisionแยก

2. Contract testsก่อนย้าย API

ล็อก URI, method, JSON casing, optional fields, response mappingและ failuresของ ApiService extensions/Api implementations เพื่อให้เปลี่ยนเป็น repositoryหรือ typed DTOโดยไม่เปลี่ยนรอยต่อ .NET

3. Controller/store tests

ใช้ fake repositoryทดสอบ transitions, loading/error, duplicate guards, generationและ reconciliationโดยไม่ render widgets ทำให้ refactor screen-centricไป controller-centricมีหลักฐานเทียบก่อน/หลัง

4. Widget behavior tests

ล็อก focus, scanner Enter, disabled actions, scroll owner, dialog result, navigation resumeและ textสำคัญ ไม่ assert private fieldsหรือ widget treeละเอียดจน extractionธรรมดาทำ testsพังหมด

5. Golden จำกัดขอบเขต

goldenช่วย visual regressionsของ PDA cards/layoutแต่เปราะกับ font/platform ใช้คู่ behavior testsและกำหนด viewport/text scale ไม่ใช้แทน flow assertions

6. Failure injection

Fakeต้องควบคุม success, typed failure, delay, never-complete, timeout-after-commitและ out-of-order response ไม่ใช่ fakeที่ตอบ successทันทีตลอด เพราะจะยืนยัน architectureแต่ไม่พิสูจน์ reliability

7. Refactor loop

capture behavior → test fails for right reason
→ smallest extraction → tests green
→ review diff/invariants → commit
→ next seam

commitเล็กช่วย bisect/revertและลด review cognitive load

8. Coverage priority

เริ่ม mutation-critical flows: receive, pick, pack, dispatch, cycle count ตามด้วย auth/sessionและ realtime ไม่ไล่เปอร์เซ็นต์ line coverageก่อน business invariants
