วิธี review: ตามหนึ่ง user intentจาก widgetถึง .NETแล้วกลับมา state แทนอ่าน diffจากบนลงล่างเพียงอย่างเดียว

1. Scope และ evidence

PRอธิบายปัญหา, behaviorก่อน/หลัง, files/flowsกระทบ, testsและสิ่งที่ intentionallyไม่แก้ Refactor claimต้องมี diffที่ไม่เปลี่ยน contractหรือระบุ changeชัด

2. State ownership

  • source of truthมีหนึ่งตัวหรือไม่
  • local stateถูกยก globalเกินจำเป็นหรือไม่
  • public mutable collectionหลุดหรือไม่
  • derived stateถูกเก็บซ้ำหรือไม่
  • notify/rebuild scopeเหมาะหรือไม่

3. Async/lifecycle

ตรวจ mounted/dispose, identity generation, overlapping poll, duplicate submit, timeout uncertainty, retry semanticsและ response ordering ทุก awaitที่ commit stateต้องพิสูจน์ว่ายังเป็น operationปัจจุบัน

4. API/domain contract

ตรวจ URI encoding, JSON casing/nullability, unknown enum, pagination, N+1, typed failure, idempotencyและ server authorization ไม่ให้ UI labelกลายเป็น business key

5. Security/session

tokenถูกส่ง hostใด, logsมี secretไหม, 401จัดที่ boundaryไหม, logoutล้าง scoped stateไหม, rolesตรวจ serverไหมและ persistenceเหมาะ platformหรือไม่

6. UI/PDA behavior

scanner focus/Enter, double scan, touch target, fixed action, scroll/keyboard, Thai/English overflow, loading/error/retryและ accessibilityต้องไม่หายจาก architecture cleanup

7. Tests และ observability

testsพิสูจน์ invariantหรือเพียง coverage? มี failure/race caseไหม Logs/metricsใช้ correlation IDและไม่เปิดข้อมูลอ่อนไหวหรือไม่ Productionจะรู้ได้อย่างไรว่า migrationแย่ลง

8. Review outcome

แยก blockerด้าน correctness/security/data lossจาก suggestionด้าน style ให้เหตุผลพร้อม scenarioและ testที่เสนอ ไม่ขอ abstractionเพิ่มเพราะ preferenceส่วนตัวหรือบังคับสอง codebaseเหมือนกันทั้งหมด
