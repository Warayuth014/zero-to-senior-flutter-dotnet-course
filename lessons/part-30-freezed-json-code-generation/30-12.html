build_runner เป็น orchestrator: มันจัด dependency graphและรันหลาย builders ไม่ได้เป็น generatorของ Freezed/JSONเอง

1. Build

dart run build_runner build

เหมาะ one-shot/CIและคืน nonzeroเมื่อ generatorล้ม

2. Watch

dart run build_runner watch สร้างใหม่เมื่อ sourceเปลี่ยน เหมาะ development sessionแต่ต้องหยุด processเก่าหาก cache/lockชน

3. Conflicts

อย่าใช้ flagลบ outputแบบอัตโนมัติโดยไม่อ่าน diff โดยเฉพาะเมื่อ generated fileมีการแก้มือซึ่งควรถูกค้นและแก้ workflow

4. Cache

.dart_tool เป็น disposable build cacheไม่ commit หาก cacheเสียให้ใช้ commandของ build_runner/pubที่เหมาะ ไม่ลบ directoryกว้างผิด workspace

5. Multiple builders

labมี Freezed, JSONและDrift บน graphเดียว Outputจำนวนมากใน logอาจเป็น intermediate assets; gitควรเห็นเฉพาะ declared partsที่เปลี่ยนจริง

6. Determinism

หลัง generateแล้วรันซ้ำโดย source/lockfileไม่เปลี่ยน Git diffต้องว่าง หากไม่ว่างตรวจ version, locale, formatterและgenerator nondeterminism

7. CI drift check

CI generateแล้ว failเมื่อ git diff --exit-code มีผลต่าง เพื่อจับ developerลืม commit outputหรือ source/outputไม่ตรง

8. Checkpoint

แก้ fieldใน branchทดลอง รัน build ตรวจ generated delta แล้ว revertผ่าน patch/commitอย่างปลอดภัย ไม่แก้ .g.dartตรง ๆ
