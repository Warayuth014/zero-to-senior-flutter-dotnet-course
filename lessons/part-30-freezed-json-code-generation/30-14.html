DTO ไม่จำเป็นต้องเป็น domain model: generated JSON classสะท้อน wire ส่วน domainสะท้อนกฎธุรกิจ Mapping seamกัน API evolutionไม่ให้กระจายทั่ว UI

1. Same model trade-off

labใช้ WmsTaskเดียวเพราะ contractเล็กและเน้น generator แต่ระบบใหญ่ควรแยกเมื่อชื่อ/nullability/lifecycleของ wireต่างจาก domain

2. Validation

requiredใน Dartบังคับ caller ไม่ตรวจ non-empty/range/cross-field invariant จึงยังต้อง normalize/validateก่อนสร้าง trusted domain object

3. Mapper

TaskDto.fromJson(raw) → validate/map → WmsTask

repositoryแปลง decode errorsเป็น failure vocabularyของ feature

4. API evolution

รองรับ old/new keyหรือ versionใน DTO mapperชั่วคราว เก็บ deprecation deadlineและ telemetryก่อนลบ fallback

5. Trust boundary

JSONจาก network/local DB/deep linkเป็น untrusted inputเสมอ Codegenลด castมือแต่ไม่ได้ sanitize HTML/path/URLหรือ authorize action

6. Sensitive fields

toString/equality/generated JSONอาจรวม token/PII ห้ามใส่ secretในทั่วไป modelหรือ log objectทั้งก้อน; redact/excludeและแยก secure type

7. Error context

รายงาน endpoint/key/type/correlationโดยไม่เก็บ payloadลับ และแยก malformed contractจาก business rejection

8. Checkpoint

เลือก modelจริงหนึ่งตัวและตัดสินด้วยหลักฐานว่าควรรวม DTO-domainหรือแยก พร้อม testsที่ boundary
