Nested/generic models ต้องกำหนด boundary: generatorตาม fromJson/toJson conventionsได้ แต่ไม่รู้ว่า objectใดควรเป็น entity, value object หรือ pagination envelope

1. Nested models

เมื่อ childมี fromJson/toJson generatorสร้างการ decodeได้ เปิด explicitToJsonเมื่อ encoding nested objectต้องเรียก methodชัด

2. Typed collections

List<TaskDto> ดีกว่า Listแต่ response rootยังต้องตรวจว่า itemsเป็น listและ error envelopeไม่ถูก parseเป็นข้อมูล

3. Pagination

สร้าง Page<T> สำหรับ items/cursor/totalได้ แต่อาจต้อง genericArgumentFactories เพื่อส่ง parserของ Tตอน runtime

4. Generic factory

Page.fromJson(json, (value) => TaskDto.fromJson(value))

call siteบอกวิธีสร้าง generic typeที่ runtime type erasureไม่รู้

5. Maps

JSON object keyเป็น stringเป็นหลัก หากใช้ Map<Enum,Model> ต้องกำหนด converterและ round-trip fixtures

6. Large graphs

อย่าสร้าง model graphตาม responseทั้งหมดโดยอัตโนมัติ เลือก fieldsที่ featureต้องใช้เพื่อลด couplingและ accidental data retention

7. Recursion

tree modelsรองรับได้แต่ตรวจ depth/sizeจาก serverเพื่อป้องกัน memory/stack pressureและ UI recursive buildเกินควบคุม

8. Exercise

ออกแบบ generic pageสำหรับ taskพร้อม nextCursor แล้ว test empty list, null cursor, malformed childและ round trip
