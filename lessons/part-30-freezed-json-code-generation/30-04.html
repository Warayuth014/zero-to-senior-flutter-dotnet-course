Immutability value equality collections และ const

Part 30: Freezed, JSON Serialization & Code Generation

Immutable หมายถึงเปลี่ยน referenceไม่ได้: ถ้า fieldเป็น mutable collection/objectภายในก็ยัง mutateได้ ต้องรู้ระดับของ immutability

1. Value equality

Freezedเทียบค่าของ fields ทำให้ objectจาก JSONสองครั้งที่ข้อมูลเท่ากัน compareเท่ากัน เหมาะ tests/state deduplication

2. hashCode

equalityกับ hashCodeถูกสร้างคู่กัน จึงใช้ modelเป็น Set/Map keyได้ตราบใดที่ค่าภายในไม่เปลี่ยนหลัง insert

3. Collection wrapping

Freezedป้องกันการแก้ List/Map/Setผ่าน getterโดย default แต่ objectสมาชิกอาจยัง mutable เลือก immutable nested modelsด้วย

4. Identity

value equalityไม่เท่ากับ domain identity: task IDเดียวแต่ statusต่างกันเป็น objectไม่เท่ากัน ขณะที่ repositoryยังใช้ idระบุ entity

5. Widget/state

immutable snapshotลด shared mutationและทำให้ state transitionเห็นเป็นค่า old→new แต่ large collection copyอาจมีต้นทุนต้องวัด

6. Dates/maps

DateTime immutableแต่ timezone semanticsยังต้องกำหนด; Map JSONแม้ equalityลึกได้ก็ไม่แทน typed nested model

7. Test

labพิสูจน์ว่า WmsTaskสอง instanceค่าเดียวกันเท่ากัน ซึ่ง manual classเดิมไม่ได้ให้ behaviorนี้

8. Checkpoint

ค้นหา mutable fieldsใน modelsจริงและตัดสินว่าควร copy, wrap, เปลี่ยนเป็น immutable model หรือเก็บอยู่นอก state
