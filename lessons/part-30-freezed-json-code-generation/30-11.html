Generated codeควรอ่านแต่ไม่แก้: review declarationและ generated deltaที่มีความหมายเพื่อจับ config/schemaผิดโดยไม่เสียเวลากับ boilerplateทุกบรรทัด

1. .freezed.dart

มองหา implementation classes, mixin getters, copyWith proxies, equality/hashCodeและ union cases เพื่อเข้าใจ public behavior

2. .g.dart

มองหา JSON key casts, enum map, DateTime conversion, nested callsและ null inclusion ซึ่งเป็น wire behaviorที่ต้องตรง backend

3. Do not edit

การแก้ generated fileหายเมื่อ buildรอบถัดไปและทำให้ source of truthสองชุด หาก outputผิดให้แก้ annotation/configหรือรายงาน generator bug

4. Commit policy

repoนี้ commit generated filesเพื่อเปิดคอร์ส/cloneแล้ว analyzeง่าย ทีมอื่นอาจไม่ commitแต่ CIต้อง generateก่อน compileและ reproducible

5. Diff review

fieldใหม่หนึ่ง fieldควรปรากฏใน constructor, equality, copyWithและ JSONตามคาด Diffที่ลามหลาย modelอาจเกิด global config/version change

6. Coverage

generated linesไม่จำเป็นต้องนับ coverageเท่า handwritten behavior แต่ contract testsต้อง execute public generated API

7. Debugging

stack traceอาจชี้ .g.dart ให้อ่าน cast/keyที่พังแล้วกลับไปแก้ contract translation ไม่ ignore generated framesทั้งหมด

8. Checkpoint

review generated diffของ WmsTaskและบอกได้ว่า status uppercaseถูก normalizeตรงไหน และถูก encode lowercaseตรงไหน
