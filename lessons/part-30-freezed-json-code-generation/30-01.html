Code generation ลด boilerplate ไม่ได้แทนการออกแบบ: generator เขียนโค้ดตาม schema/annotations ที่เราให้ ถ้า contract ผิด generated code จะผิดอย่างสม่ำเสมอ

1. ปัญหาที่แก้

model production ต้องมี constructor, equality, hashCode, copyWith, JSON และ union cases การเขียนมือซ้ำมากทำให้ fieldใหม่หลุดจากบาง method

2. Source of truth

ไฟล์ annotated Dart เป็น source ส่วน .freezed.dart/.g.dart เป็นผล build ตรวจเข้าใจได้แต่ไม่แก้มือ

3. Compile-time feedback

type/nullability/constructor mismatch ถูกจับตอน generate/analyze เร็วกว่ารอ dynamic map พังระหว่าง workflowจริง

4. ต้นทุน

เพิ่ม packages, build time, generated diffs, migrationตาม major version และ onboardingเรื่อง annotations จึงไม่จำเป็นกับ classเล็กทุกตัว

5. Build pipeline

annotated source → builders → generated parts
→ analyzer/compiler → tests → artifact

6. ไม่ใช่ runtime reflection

Freezed/json_serializable สร้าง Dart codeก่อน compile จึง tree-shake/type-checkได้และเปิดอ่าน implementationจริงได้

7. Lab target

Partนี้ refactor WmsTask ตัวจริงโดยรักษา strict API validation และเพิ่ม TaskSyncState unionต่อจาก offline lab

8. Checkpoint

ระบุให้ได้ว่า field/contractใดเป็น inputของ generator และ behaviorใดยังต้องเขียนเอง เช่น trim, business validation และ conflict policy
