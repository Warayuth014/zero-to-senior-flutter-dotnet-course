Multipart ไม่ใช่ JSON: request มี boundary แบ่งแต่ละ part ซึ่ง client library ต้องเป็นผู้สร้าง ห้ามกำหนด Content-Type: multipart/form-data เองโดยไม่มี boundary

1. โครงสร้าง request

multipart/form-data รวม text fields และ binary file ใน HTTP request เดียว แต่ละ part มีชื่อ เช่น partId และ file ชื่อเหล่านี้คือ API contract และต้องตรงกับ parameter ฝั่ง .NET

2. MultipartRequest ใน wmsapp

final request = http.MultipartRequest('POST', uri);
request.fields.addAll(fields);
request.files.add(
  await http.MultipartFile.fromPath('file', file.path),
);
final streamed = await request.send()
    .timeout(const Duration(seconds: 30));

3. Header ที่ควรเพิ่ม

เพิ่ม Authorization: Bearer ..., correlation ID และ accept header ผ่าน request.headers แต่ปล่อยให้ MultipartRequest สร้าง content type/boundary ห้าม log token, raw bytes หรือ path ส่วนตัวของผู้ใช้

4. ระบุ filename และ media type

final part = http.MultipartFile.fromBytes(
  'file',
  bytes,
  filename: safeDisplayName,
  contentType: MediaType('image', 'jpeg'),
);
request.files.add(part);

media type จาก client เป็น hint เท่านั้น server ยังต้องตรวจ signature จริง และไม่ใช้ filename นี้เป็นชื่อไฟล์บน disk

5. send คืน streamed response

final streamed = await request.send();
final response = await http.Response.fromStream(streamed);
if (response.statusCode < 200 || response.statusCode >= 300) {
  throw UploadException.fromResponse(response);
}

ต้อง consume response body เพื่อคืน connection ให้ pool และแปล ProblemDetails เป็น error ที่ UI เข้าใจได้

6. Retry อย่างระวัง

upload POST อาจสำเร็จที่ server แต่ response ขาดระหว่างทาง การ retry แบบทันทีจึงสร้างไฟล์ซ้ำได้ ส่ง Idempotency-Key/uploadId และให้ server คืนผลเดิมเมื่อ key ซ้ำ หรือทำ endpoint แบบ replace ต่อ part ที่ชัดเจน

7. Client lifetime

inject http.Client เพื่อ reuse connection และทดสอบได้ อย่าสร้าง client ใหม่ทุก upload โดยไม่ close ใน production ส่วนการยกเลิกต้องปิด request/subscription เฉพาะงาน ไม่ควรปิด shared client แล้วทำให้ request อื่นล้ม

8. Contract test

ยืนยัน method/path, header auth, field name, file part name, filename, content type, status 2xx, ProblemDetails และ duplicate upload ID โดยไม่ assert boundary string ที่ library สุ่มขึ้นมา
