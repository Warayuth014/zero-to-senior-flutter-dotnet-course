1. State ของ upload

sealed class UploadState {}
class UploadIdle extends UploadState {}
class UploadRunning extends UploadState { final double? progress; }
class UploadSucceeded extends UploadState { final PartImage image; }
class UploadFailed extends UploadState { final UploadFailure failure; }

progress เป็น null ได้เมื่อ content length ไม่ทราบ และ failure ควรแยก cancelled, timeout, offline, rejected, unauthorized และ server error

2. Timeout เป็นหลายช่วง

connect timeout, send timeout และ response timeout มีความหมายต่างกัน request.send().timeout(30s) ครอบเวลารอ future แต่ไม่ได้อธิบายผู้ใช้ว่า byte ถูกส่งไปเท่าไร ตั้งค่าตามขนาดสูงสุดและ network จริงของคลัง ไม่ใช้เลขเดียวกับ GET ทุกชนิด

3. นับ progress จาก stream

Stream<List<int>> countBytes(
  Stream<List<int>> source, int total, void Function(double) onProgress,
) async* {
  var sent = 0;
  await for (final chunk in source) {
    sent += chunk.length;
    onProgress(sent / total);
    yield chunk;
  }
}

HTTP package พื้นฐานอาจต้องสร้าง streamed request/adapter เพื่อเห็น upload progress เลือก library ตามความจำเป็นและห่อไว้หลัง interface

4. Throttle UI update

อย่า notifyListeners() ทุก chunk; อัปเดตเมื่อเพิ่มอย่างน้อย 1% หรือทุก 100–200 ms ลด rebuild และให้ screen subscribe เฉพาะ upload item นั้น progress 100% หมายถึงส่ง bytes ครบ ยังต้องรอ server validate/save

5. Cancellation

ปุ่ม Cancel ต้องยกเลิก stream/request จริง ไม่ใช่แค่ซ่อน spinner หลัง cancel ห้ามแสดง success จาก future เก่า ใช้ operation token/generation และให้ .NET รับ CancellationToken แต่ยังต้อง cleanup temp file เมื่อ client disconnect

6. Retry policy

retry อัตโนมัติเฉพาะ error ชั่วคราวและเมื่อมี upload ID ที่ server dedupe ได้; 400/401/403/413/415 ไม่ retry แบบเดิม ส่วน timeout หลังส่งครบให้ query สถานะด้วย upload ID ก่อนส่งไฟล์ใหม่

7. UX บน network แย่

แสดงชื่อ part, thumbnail, bytes/เปอร์เซ็นต์, ปุ่ม cancel/retry และเก็บหน้าจอใช้งานส่วนอื่นได้ตาม business rule หากออกจากหน้า ให้ store/repository เป็น owner งาน ไม่ให้ widget dispose แล้วงานกลายเป็น zombie

8. Tests

จำลอง progress chunks, timeout ก่อนส่ง/หลังส่งครบ, cancel กลางทาง, offline, 413, token หมดอายุ, response เสียรูป, retry key ซ้ำ และ widget ถูก dispose โดยต้องไม่มี setState-after-dispose หรือ success หลอก
