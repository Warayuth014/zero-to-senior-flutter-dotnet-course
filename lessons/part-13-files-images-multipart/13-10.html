3. เส้นทางทั้งหมดในภาพเดียว

ผู้ใช้กดปุ่มถ่ายรูป
  └─ เลือกที่มา (กล้อง / แกลเลอรี)                    ← 13.1
       └─ picker.pick(source)
            ├─ ไม่ได้สิทธิ์   → บอกให้ไปหน้าตั้งค่า      ← 13.1
            ├─ กดยกเลิก      → เงียบ ไม่ใช่ความผิดพลาด
            └─ ได้รูป (ย่อแล้ว 1024, คุณภาพ 85)
                 └─ checkImage()                       ← 13.9
                      ├─ ผิดแน่นอน → ปฏิเสธ พร้อมทางแก้
                      ├─ น่าสงสัย  → เตือน แต่ส่งได้
                      └─ ผ่าน      → สร้างรหัสคำสั่ง     ← 13.4

ผู้ใช้กดส่ง
  └─ MultipartRequest                                  ← 13.3
       ├─ fields: partId, station, capturedAt          ← 13.4
       ├─ headers: token, Idempotency-Key              ← 13.4
       ├─ file: ไบต์ + ชื่อที่ทำให้ปลอดภัยแล้ว           ← 13.9
       └─ นับไบต์ระหว่างส่ง → onProgress                ← 13.8
            ├─ สำเร็จ  → เก็บเส้นทางสัมพัทธ์             ← 13.5
            ├─ ปฏิเสธ  → ล้างรูป ให้เลือกใหม่            ← 13.8
            ├─ ล้มเหลว → เก็บรูปไว้ ส่งซ้ำด้วยรหัสเดิม
            └─ ยกเลิก  → กลับไปพร้อมส่ง

แสดงรูป
  └─ Uri.resolve(baseUrl, relativePath)                ← 13.5
       └─ Image.network(url, cacheWidth: ...)          ← 13.7

4. โจทย์

ทำหน้าจอ “ถ่ายรูปหลักฐานการรับของ” ในโฟลเดอร์ lib/upload_lab/ui/

ส่วนต้องมี

ตัวอย่างรูปพร้อมขนาดไฟล์ และปุ่มถ่ายใหม่

ปุ่มยกเลิกระหว่างที่กำลังส่ง

5. เกณฑ์ที่ต้องผ่าน

#เกณฑ์บท
1ย่อรูปตั้งแต่ตอนเลือก ไม่ใช่ตอนส่ง13.1
2ผู้ใช้กดยกเลิกแล้วไม่เห็นข้อความผิดพลาด13.1
3ไม่ได้สิทธิ์แล้วมีปุ่มพาไปหน้าตั้งค่า13.1
4ไม่มี import 'dart:io' ในโค้ดที่ใช้ร่วม13.2
5ไม่ตั้ง Content-Type เอง พร้อมเทสต์ที่ตรวจ boundary13.3
6เทสต์อ่าน body แล้วยืนยันว่ามีทุกช่องที่ตกลงไว้13.3
7ส่งเวลาที่ถ่ายไปด้วย ไม่ใช่ให้เซิร์ฟเวอร์ใช้เวลาที่ได้รับ13.4
8รหัสคำสั่งเดิมตอนลองใหม่ และใหม่เมื่อเลือกรูปใหม่13.4
9เก็บเส้นทางสัมพัทธ์ และประกอบ URL ด้วย Uri.resolve13.5
10ไม่มี FutureBuilder ที่สร้าง Future ใน build13.6
11รูปย่อทุกใบมี cacheWidth ที่คูณ devicePixelRatio แล้ว13.7
12ความคืบหน้าไม่ถอยหลัง และเปลี่ยนข้อความที่ 100%13.8
13กดส่งซ้ำระหว่างส่งต้องไม่ยิงซ้ำ13.8
14ถูกปฏิเสธแล้วล้างรูป ส่วนล้มเหลวชั่วคราวเก็บรูปไว้13.8
15เน็ตขาดแล้วบอกว่าไม่รู้ผล13.8
16ตรวจชนิด ขนาด และลายเซ็นในไฟล์13.9
17ห้ามกับเตือนแยกกัน13.9
18ชื่อไฟล์ถูกทำให้ปลอดภัยก่อนส่ง13.9
19ออกจากจอระหว่างส่ง ต้องไม่เกิด ChangeNotifier used after disposed13.8, 12.8
20ล้างแคชรูปตอนออกจากระบบ13.7, 8.8

เกณฑ์ 10, 11 และ 19 เป็นสามข้อที่ทดสอบด้วยมือแล้วไม่มีทางเจอ

final ratio = MediaQuery.devicePixelRatioOf(context);

Image.network(
  imageUrl(item.path),
  width: 56,
  height: 56,
  cacheWidth: (56 * ratio).round(),
  fit: BoxFit.cover,
  errorBuilder: (_, _, _) => const Icon(Icons.broken_image),

7. ข้อผิดพลาดที่พบบ่อยตอนทำ lab นี้

อาการสาเหตุวิธีแก้
เทสต์โยน Invalid UTF-8 byteอ่าน request.bodylatin1.decode(request.bodyBytes)
400 บอกว่าไม่พบไฟล์ตั้ง Content-Type เองอย่าตั้ง
Can't finalize a finalized Requestส่งคำขอตัวเดิมซ้ำสร้างใหม่ทุกครั้ง
วงหมุนกะพริบตอนเลื่อนลิสต์Future ใน buildทำให้ base URL เป็น sync
แอปปิดเองตอนเลื่อนลิสต์รูปไม่มี cacheWidthใส่ทุกที่ที่แสดงรูป
ได้รูปซ้ำในระบบรหัสคำสั่งเปลี่ยนตอนลองใหม่สร้างตอนเลือกรูป
ทดสอบการไม่ได้สิทธิ์ไม่ได้เรียก ImagePicker ตรง ๆห่อด้วย interface

8. แบบทดสอบตัวเองก่อนจบ Part 13

  1. ทำไมต้องย่อรูปตั้งแต่ตอนเลือก ไม่ใช่ตอนส่ง (13.1)
  2. การปฏิเสธสิทธิ์สองแบบต่างกันอย่างไร (13.1)
  3. ทำไมเก็บไบต์ดีกว่าเก็บที่อยู่ไฟล์ และเมื่อไหร่ที่ไม่ใช่ (13.2)
  4. ทำไม dart:io ใช้บนเว็บไม่ได้ และเลี่ยงอย่างไร (13.2)
  5. ทำไม base64 ไม่เหมาะกับรูปถ่าย (13.3)
  6. ทำไมห้ามตั้ง Content-Type เอง (13.3)
  7. ทำไมต้องใช้ send() ไม่ใช่ post() (13.3)
  8. อะไรควรอยู่ใน header อะไรควรอยู่ในช่อง (13.4)
  9. รหัสคำสั่งควรสร้างตอนไหน (13.4)
  10. ทำไมต้องส่งเวลาที่ถ่ายไปด้วย (13.4)
  11. ทำไมเก็บเส้นทางสัมพัทธ์ ไม่ใช่ URL เต็ม (13.5)
  12. Uri.resolve ดีกว่าต่อสตริงอย่างไร (13.5)
  13. 200 ที่ไม่บอกที่อยู่ไฟล์ ควรถือว่าอะไร (13.5)
  14. ทำไม FutureBuilder ถึงกะพริบ (13.6)
  15. เก็บ Future ไว้แล้วยังต้องทำอะไรอีก (13.6)
  16. หน่วยความจำที่รูปกิน คำนวณอย่างไร (13.7)
  17. ทำไมต้องคูณ devicePixelRatio ใน cacheWidth (13.7)
  18. แคชรูปของ Flutter อยู่ที่ไหนและนานแค่ไหน (13.7)
  19. ทำไม 100% ไม่ได้แปลว่าเสร็จ (13.8)
  20. การถูกปฏิเสธต่างจากความล้มเหลวชั่วคราวอย่างไร (13.8)
  21. ทำไมการยกเลิกไม่รับประกันว่าเซิร์ฟเวอร์ไม่ได้รับ (13.8)
  22. ฝั่งแอปตรวจเพื่ออะไร ฝั่งเซิร์ฟเวอร์ตรวจเพื่ออะไร (13.9)
  23. ทำไมต้องตรวจลายเซ็นในไฟล์ (13.9)
  24. เมื่อไหร่ควรห้าม เมื่อไหร่ควรเตือน (13.9)

9. สรุปท้าย Part 13

สิ่งที่ทำได้แล้ว

  • ขอรูปจากผู้ใช้และย่อตั้งแต่ต้นทาง
  • จัดการการยกเลิกและการปฏิเสธสิทธิ์ให้ต่างกัน
  • เก็บไฟล์ในรูปแบบที่ทำงานได้ทุกแพลตฟอร์มและทดสอบง่าย
  • ส่ง multipart ไป .NET พร้อมช่องข้อมูลและ header ที่ถูกที่
  • กันไฟล์ซ้ำด้วยรหัสคำสั่งที่ผูกกับรอบ ไม่ใช่กับครั้ง
  • เก็บที่อยู่ไฟล์ให้รอดตอนสลับเซิร์ฟเวอร์
  • มองออกว่า FutureBuilder ถูกใช้ผิดตรงไหน
  • แสดงรูปหลายใบโดยแอปไม่ถูกระบบปิด
  • รายงานความคืบหน้าและยกเลิกได้ระหว่างส่ง
  • ตรวจไฟล์ก่อนส่งโดยรู้ว่าอะไรคือความสะดวก อะไรคือความปลอดภัย

สิ่งที่ยังไม่ได้ทำและจะทำที่ไหน
