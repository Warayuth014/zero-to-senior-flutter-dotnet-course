1. Flow ใน wmsapp

part_image_screen.dart เปิด bottom sheet ให้เลือก ImageSource.camera หรือ gallery แล้วเรียก ImagePicker.pickImage พร้อมลดรูปเป็น 1024×1024 และ quality 85 ก่อนอัปโหลด นี่เป็นจุดเริ่มที่ดีเพราะลด bandwidth ตั้งแต่ต้นทาง

2. XFile และการยกเลิก

final XFile? picked = await picker.pickImage(
  source: source,
  maxWidth: 1024,
  maxHeight: 1024,
  imageQuality: 85,
);
if (picked == null) return; // ผู้ใช้กดยกเลิก ไม่ใช่ error

3. Permission ตาม platform

Android/iOS มีรายละเอียดต่างกันตามเวอร์ชันและ source ที่ใช้ กำหนดข้อความ usage description ใน iOS และ permission ที่จำเป็นใน Android manifest ตามเอกสารของ plugin เวอร์ชันที่ล็อกไว้ อย่าขอ permission ทั้งหมดตอนเปิดแอป—ขอเมื่อผู้ใช้กดฟีเจอร์นั้นเพื่อให้เหตุผลชัดเจน

4. Denied ไม่เท่ากับ permanently denied

เมื่อถูกปฏิเสธครั้งแรกให้บอกว่าฟีเจอร์ใดใช้ไม่ได้และอนุญาตให้ลองใหม่ แต่หากระบบไม่แสดง prompt อีกแล้ว ให้เสนอปุ่มเปิด Settings พร้อมทางเลือกกลับหน้าก่อนหน้า ห้ามวนเรียก permission dialog อัตโนมัติ

5. Android activity ถูกทำลาย

ระหว่างเปิด camera ระบบอาจ kill activity เพราะหน่วยความจำต่ำ เมื่อกลับมา future เดิมอาจหาย แอป production ควรเรียก ImagePicker.retrieveLostData() ตอนเริ่ม screen/app และนำ XFile ที่กู้ได้กลับเข้าสู่ preview โดยไม่อัปโหลดเองทันที

6. State ที่อ่านง่าย

sealed class PickState {}
class PickIdle extends PickState {}
class PickPreview extends PickState { final XFile file; }
class PickFailure extends PickState { final String message; }

// picking และ uploading ควรเป็นคนละ state/operation

แยกการเลือกออกจากการอัปโหลด ผู้ใช้จึงเปลี่ยนรูป ตรวจ preview หรือยกเลิกได้ก่อนใช้ network

7. UX และ lifecycle

กันการกดซ้ำระหว่าง picker เปิดอยู่, ตรวจ mounted ก่อนใช้ context หลัง await, และอย่าบล็อกทั้งหน้าขณะเพียงเลือกรูป ปุ่มอัปโหลดควร disabled เฉพาะ operation ที่ชนกัน

8. Checklist

ทดสอบ camera, gallery, cancel, deny, deny ถาวร, activity recreation, รูปใหญ่มาก, หมุนจอ และการกลับจาก background บนอุปกรณ์จริงอย่างน้อย Android รุ่นที่ใช้งานในคลัง
