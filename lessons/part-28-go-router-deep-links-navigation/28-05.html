Named routes และ centralized navigation intent

Part 28: go_router, Router & Deep Links

Named intent: ชื่อ routeช่วยรวมความหมายและให้ packageประกอบ URLจาก path/query parameters ลด string interpolationกระจายทั่ว widget

1. goNamed

context.goNamed('taskDetail',
  pathParameters: {'taskId': task.id},
  queryParameters: {'source': 'task-list'});

2. Unique names

ชื่อ routeต้อง uniqueทั้ง tree ใช้ชื่อเชิง intent/resourceไม่ผูกชื่อ widgetและ refactorด้วย IDE/searchได้

3. Central helpers

เมื่อ parametersซ้ำสร้าง navigation command/helper typed เช่น openTaskDetail(context,id,source) แทน map stringทุกจุด

4. ไม่ซ่อน operation

Helperควรแยก go กับ push ชัด ไม่สร้าง functionชื่อ openที่บาง callแทน stackบาง callซ้อนโดย callerไม่รู้

5. Route constants

การรวม string constantsช่วย typoแต่ไม่ให้ compile-time parameter safety Type-safe routesด้วย go_router_builderช่วยได้เมื่อ Part code generationมาถึง

6. Analytics name

route nameเหมาะเป็น screen semantic label แต่อย่าส่ง raw taskId/queryทั้งหมดไป analyticsโดยไม่ data policy

7. Migration

ครอบ Navigator.pushเดิมด้วย intent functionsก่อน จากนั้นเปลี่ยน implementationเป็น go_routerทีละ flowและตรึง back behaviorด้วย tests

8. Checkpoint

ค้นหา '/tasks/' ใน widgetsควรมีน้อย Intentส่วนใหญ่ประกอบผ่าน named routeเพื่อกัน URL contractกระจาย
