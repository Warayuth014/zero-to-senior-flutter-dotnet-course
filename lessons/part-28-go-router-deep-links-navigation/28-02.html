MaterialApp.router และ GoRouter lifecycle

Part 28: go_router, Router & Deep Links

Composition: MaterialApp.router รับ routerConfig ส่วน GoRouterเป็น resourceที่มี listener/lifecycle จึงสร้างครั้งเดียวและ disposeเมื่อ app scopeจบ

1. Router constructor

createRoutingLabRouter รับ session, repositoryและ initialLocationอย่างเปิดเผย Route buildersจึงใช้ dependenciesจาก compositionแทน singleton

2. Stateful app owner

RoutingLabApp สร้าง GoRouterใน initState ไม่สร้างใน build มิฉะนั้น navigation stackอาจ resetทุก rebuild

3. Dispose

Stateเรียก router.dispose() เพื่อลบ listeners โดยเฉพาะ refreshListenableและ browser/platform route information

4. MaterialApp.router

MaterialApp.router(
  routerConfig: router,
  theme: theme,
)

ไม่กำหนด home/routes/onGenerateRouteซ้ำเพราะ routerConfigเป็น source of truth

5. initialLocation

ใช้สำหรับ lab/test/cold startปกติ แต่ incoming platform deep linkอาจมีสิทธิ์เหนือค่าเริ่มต้น อย่า hard-code homeจนกลืน deep link

6. Version pin

Lab resolve go_router 17.5.0 และ commit lockfile APIนี้เปลี่ยน majorหลายครั้งจึงอ่าน migration guideก่อน upgrade

7. Diagnostics

เปิด debugLogDiagnostics ชั่วคราวเมื่อ debug route matching แต่ไม่พึ่ง log verboseใน productionและไม่ log queryที่มี secret

8. Review

Routerควรสร้างที่ composition rootและ route buildersควรบาง หาก builderยิง API/ประกอบ business stateมากให้แยก page/controllerออก
