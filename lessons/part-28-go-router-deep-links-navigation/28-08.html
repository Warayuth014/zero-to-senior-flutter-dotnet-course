extra เทียบกับ URL-serializable state

Part 28: go_router, Router & Deep Links

extra เป็น convenience ไม่ใช่ deep-link contract: objectใน memoryเร็วต่อการส่งหน้าแต่หายเมื่อเปิด URLตรง, refresh webหรือprocessถูก kill

1. ใช้ extraได้เมื่อไร

animation hint, transient draftที่มี persistent idหรือ optimizationส่ง snapshotชั่วคราวได้ หาก extraหายหน้าต้อง recoverจาก path/queryหรือ repository

2. ห้ามใช้เป็น identityเดียว

context.push('/detail', extra: task) โดย URLไม่มี taskIdทำให้ share/restoreไม่ได้และ test deep linkต้องสร้าง objectลับ

3. Browser serialization

go_routerอาจต้อง codecสำหรับ complex extraในบาง restoration/historyกรณี แต่การ serializeได้ไม่แปลว่าควรเผยข้อมูลทั้งหมดใน URL/history

4. Stale object

task objectจาก listอาจเก่ากว่า server Detailควรใช้ idโหลด latestและแสดง snapshot extraเพียง optimistic placeholderถ้าจำเป็น

5. Draft workflow

unsaved formใหญ่ควรเก็บใน feature state/persistence keyedด้วย draft id ไม่ยัด JSONทั้งก้อนใน queryหรือ extraโดยไม่มี recovery

6. Test matrix

ทดสอบ navigationจากในแอปพร้อม extra, เปิด URLตรงไม่มี extra, refresh/restartและversionเก่าของ link ทุกกรณีต้องมี behaviorชัด

7. Lab choice

task detailรับ taskId/sourceจาก URLและ scannerคืน resultผ่าน popเพราะ resultเป็น transientของ stack ไม่จำเป็นต้อง bookmark

8. Rule

ถ้าหน้าต้องเปิดจาก notification/email/QR ให้ถือว่า extraเป็น nullเสมอแล้วออกแบบให้ทำงานได้ก่อน
