Platform deep links: Route treeทำให้แอป parse URLได้ แต่ Android/iOSยังต้องพิสูจน์ความเป็นเจ้าของ domainและ OS configuration ส่วน web serverต้อง fallbackไป index.html

1. Web

browserส่ง pathไป serverโดยตรง Production hostingต้อง rewrite unknown app pathsไป Flutter index.html แต่ asset/API pathsต้องไม่ถูก rewriteผิด

2. Android App Links

กำหนด intent-filter scheme/host/pathและ host assetlinks.json ที่จับ package name/signing certificate fingerprint ทดสอบ release signatureด้วย adb

3. iOS Universal Links

เพิ่ม Associated Domains entitlementและ host apple-app-site-associationที่ผูก Team/App ID ทดสอบบน deviceจริงเพราะ simulator/cacheต่างได้

4. Custom scheme

เหมาะ fallback/internal integrationแต่ domain ownership/UX/securityด้อยกว่า verified HTTPS linksและอาจชนแอปอื่น

5. Cold vs warm

ทดสอบ appปิดสนิท, backgroundและforegroundอยู่คนละ route Incoming linkต้องสร้าง/แทน stackตาม product contractโดยไม่ duplicate screen

6. Version/install

asset associationถูก cacheและ certificateต่าง debug/release วาง runbookตรวจ domainไฟล์, signingและOS logs ไม่ debug Flutterอย่างเดียว

7. Security

validate parameters, auth/authorizationและ one-time actions Deep linkเป็น untrusted external inputเหมือน request URL

8. Evidence

เก็บ adb/xcrun/browser commandsและผล cold/warm linksใน release checklist Screenshotหน้าเดียวไม่พิสูจน์ associationหรือ history behavior
