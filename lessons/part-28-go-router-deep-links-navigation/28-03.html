Route tree คือ product contract: ออกแบบจาก resources/workflowsและความสามารถในการเปิดตรง ไม่ใช่คัดลอกชื่อตัวแปร widgetทั้งหมดลง URL

1. Lab URLs

/login?from=...
/home
/tasks?status=waiting
/tasks/:taskId
/tasks/:taskId/scan
/settings

2. Stable nouns

ใช้ tasks และ task identityที่คงกว่าชื่อ screen เช่น TaskListV2 URLไม่ควรเปลี่ยนเพราะ refactor class

3. Hierarchy

scannerอยู่ใต้ taskเพราะต้องมี taskId แต่เปิดบน root navigatorได้ Route hierarchyและ visual navigator hierarchyเป็นคนละมิติ

4. Canonical URL

กำหนด casing/trailing slash/query defaultsเพียงรูปแบบเดียวแล้ว redirect legacy URLเข้ารูป canonical เพื่อ analytics/cache/shareสม่ำเสมอ

5. Route order

dynamic pathเช่น :taskId อาจชน static path new ออกแบบ tree/constraintsและ testsไม่ให้คำ reservedถูกตีความเป็น id

6. Permissions

มี routeไม่ได้แปลว่ามีสิทธิ์ Pageและ APIยังต้อง authorization Route redirectเป็น UX gateไม่ใช่ security boundary

7. Versioning links

ลิงก์จาก email/QRอาจอยู่นานกว่า app release รักษา backward compatibilityหรือมี migration redirect อย่าลบ routeทันทีโดยไม่มี telemetry

8. Exercise

ออกแบบ URL receiving order/run/palletโดยแยก identity, filterและtransient step พร้อมเหตุผลว่า linkใดเปิดหลัง restartได้
