1. Baseline environment

git status --short
flutter --version
flutter doctor -v
flutter pub get
flutter analyze
flutter test

อ่าน SDK constraintใน pubspecก่อน upgrade; wmsappและ absoluteผูก Dartคนละ baselineจึงไม่ควรใช้ lockfile/assumptionร่วมกัน

2. อ่าน rootก่อน lib

เปิด README, pubspec, analysis_options, assets, Android manifests/build configและ test tree เพื่อรู้ platforms/dependencies/fonts/permissions/version จากนั้นจึงเข้า lib/main.dart ไม่เริ่มที่ไฟล์ใหญ่สุดโดยไร้บริบท

3. Entry/composition map

wmsapp mainประกอบ theme+HomeScreenและหลาย screensสร้าง ApiService singletonเอง ส่วน absolute mainโหลด language/connectionก่อน runApp, สร้าง ApiClient→AuthRepositoryและ WarehouseShellประกอบ repositories/store นี่กำหนดว่าจะหา dependency ownerตรงไหน

4. Feature inventory

ใช้ rg --files lib testแล้วจัดกลุ่ม auth, receiving, putaway, picking, packing, sorting, inventory, tasksและshared core จดไฟล์ top 10ตามขนาดเป็น hotspots ไม่ตีตราว่า badก่อนอ่าน responsibilities

5. เลือกหนึ่ง vertical slice

เริ่ม flowเล็กที่มี query+mutation เช่น lab Tasksหรือ absolute Inventory→Task แล้ว trace Widget→state owner→repository/API→model→test ก่อนข้าม feature การอ่านตาม flowสร้าง mental linksเร็วกว่าตาม alphabet

6. State ownership sheet

จด state, owner, lifetime, source of truth, consumers, mutation methodsและdisposal แยก local UIจาก domain/server state หากหา ownerไม่ได้หรือมีสองสำเนาให้ mark risk ไม่รีบ refactorวันแรก

7. Run before change

เปิด backend/base URLที่ถูก, capture happy/error screenshots/logsและทดสอบ hardware scannerถ้ามี Baselineที่รันไม่ได้ต้องบันทึก exact command/environment/error ไม่แก้หลายอย่างพร้อมจนรู้ไม่ได้ว่าอะไรช่วย

8. Day-one artifact

ส่ง architecture sketch, feature map, startup steps, one traced flow, known environment blockersและคำถามธุรกิจ 5ข้อ โดยยังไม่เสนอ rewriteจาก impressionแรก
