อาการ contract mismatch: HTTP 200แต่ parseพัง, fieldว่าง, statusผิด action, 400/415, endpoint not foundหรือ appแสดง zeroทั้งที่ serverมีข้อมูล

1. Capture raw facts

เก็บ method+URL+status+headersที่ไม่ sensitive+request/response bodyจาก dev environmentและ traceId เปรียบเทียบ curl/.httpกับ Flutter request อย่าเริ่มแก้ parserจากข้อความ UIที่แปลแล้ว

2. URL mismatch

ตรวจ scheme/host/port/base path/API prefix, slashซ้ำ, query encodingและ Android emulator 10.0.2.2 404ชี้ routeผิด, connection refusedไม่ใช่ JSON bug, CORSมักกระทบ webไม่ใช่ native

3. Request mismatch

เทียบ JSON property casing/type/nullability, Content-Type, multipart field name, auth headerและ enum numeric/stringกับ .NET request DTO/model binding 400 ProblemDetails errorsควรชี้ field ไม่ hard-code retry

4. Response mismatch

ตรวจ object vs list/envelope, items casing, number int/double/string, null/missing, timestamp zoneและ pagination total Absolute shared endpointsมี casingหลายแบบ; normalizeใน adapterพร้อม testsไม่กระจาย fallbackตาม widgets

5. Status semantics

wire enumใหม่อาจถูก client mapเป็น executing/availableผิด คง Unknown(raw)และปิด mutationจนเข้าใจ contract Labelแปลไม่ใช่ keyสำหรับ logic

6. Minimal contract test

final json = fixture('captured-response.json');
final model = Dto.fromJson(json);
expect(model.id, '...');
expect(model.status, UnknownStatus('NEW'));

เพิ่ม request serialization testคู่กัน

7. Decide owner of fix

backendผิด published contractให้แก้ serverแบบ backward compatible; client assumptionผิดให้แก้ parser; contractกำกวมให้ version/documentก่อน อย่าเพิ่ม dynamic/catch-allเพื่อทำให้ errorหาย

8. Done criteria

มี captured fixtureที่ redactแล้ว, root causeระดับ field/route/status, regression contract test, compatibility impactต่อ clientเก่าและ deploy orderที่ชัดเจน
