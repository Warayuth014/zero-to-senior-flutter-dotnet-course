Coverage ของคอร์ส: coverage-manifest.jsonผูก source/config/test 166 ไฟล์กับบท deep/reference แต่ structural coverageไม่เท่ากับเข้าใจ business flow

1. Refresh source inventory

.\scripts\build-coverage.ps1
.\scripts\build-course.ps1
.\scripts\build-search-index.ps1
.\scripts\verify-course.ps1

รันตามลำดับและอ่าน failure ไม่แก้ generated lessonsโดยตรง

2. New file gate

ไฟล์ Dart/config/testใหม่ต้องมี lesson mappingระดับ deep/referenceที่เหมาะ ถ้า featureใหม่ไม่มีบท ให้เพิ่ม/ปรับ content+blueprintอย่างตั้งใจ ไม่ mapสุ่มไปบทใกล้เคียงเพียงให้ verifierเขียว

3. Deep coverage evidence

สำหรับ lib fileตอบ entry/callers, state owner, dependencies, data contract, side effects, failure/raceและ testsได้ ส่วน reference filesตอบ build/permission/config/test roleและเมื่อใดต้องแก้

4. Flow matrix

ทำตาราง receiving/putaway/picking/packing/sorting/inventory/task/cycle countเทียบ UI→state→API→.NET→realtime→tests Coverageรายไฟล์ครบแต่ flow linkขาดยังไม่ถึง 90%++ understanding

5. Search proof

full-text indexต้องมี lesson countตรง manifestและค้นชื่อ symbol/endpoint/เนื้อหาได้ เช่น entity, ApiClient, mobile_dispatch ไม่ตรวจเพียง title search

6. Generated/authored boundary

content/เป็น sourceของ authored HTML; lessons/, manifest, search indexเป็น generated การแก้ generatedอย่างเดียวจะหายใน buildและ verifyควรจับ authored partที่ยัง scaffold

7. Source drift review

เมื่อ reference appsเปลี่ยน ให้ดู new/removed/renamed filesและ contract behavior ไม่อัปเดต timestamp/hashอย่างเดียว บทที่กล่าวข้อเท็จจริง polling/auth/statusต้อง revalidateกับ code/testปัจจุบัน

8. Completion checklist

verifierผ่าน, mappingsมีเหตุผล, flows traceครบ, searchพบเนื้อหา, authored countตรง, generated diff reviewแล้วและ reference worktreesไม่ถูก course buildแก้ไข
