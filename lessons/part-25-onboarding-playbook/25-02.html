Trace rule: เริ่มจาก user intentหนึ่งเหตุการณ์แล้วตามทั้งไปและกลับ: UI event → state command → HTTP → .NET → response/event → state commit → rebuild

1. ตั้ง trace question

ใช้คำถามเฉพาะ เช่น “กด Complete TASK-001แล้วอะไรลบ card?” ไม่ใช้ “ระบบ taskทำงานอย่างไร” ระบุ input, expected server mutationและ observable UI outcome

2. หา UI event

rg -n "เสร็จงาน|onPressed|onSubmitted|complete\(" lib

จาก widgetอ่าน callback closureและ guard busy/validation อย่าหยุดที่ navigationหรือ helperแรก

3. หา state owner

wmsappมักเข้า private async methodแล้ว setState; absolute/labเรียก WarehouseStore/TaskStore จด fieldsที่อ่านก่อน await, flags/generationและ fieldsที่ commitหลัง await

4. Repository/API path

เปิด interfaceก่อน implementation ตาม methodถึง ApiClient/ApiService extension จด verb, final URL, query/body/headers/timeout/idempotencyและ failure translation ระวัง relative prefixกับ absolute endpoint

5. จับคู่ .NET

rg -n "Map(Post|Get)|HttpPost|HttpGet|mobile_tasks" backend

อ่าน route template, auth policy, request DTO, service transaction, response/status ไม่เดา backendจาก Dart modelเพียงฝั่งเดียว

6. Trace responseกลับ

JSON→DTO/domain parser→repository result/exception→store state→notify/setState→widget branch หาก SignalR/pollingแก้ snapshotภายหลังให้รวมใน diagramด้วย

7. Prove with evidence

เพิ่ม breakpoint/log correlation IDหรือ fake testที่ assert request+state transition ห้าม log token/password เขียน sequenceสั้นพร้อม failure path 401/409/timeoutและใคร reconcile

8. Trace template

Intent / UI symbol / State owner / Repository / HTTP contract / .NET handler / Transaction authority / Response mapping / UI rebuild / Failure+race / Tests ให้กรอกครบก่อนแก้ behavior
