Diagnostic layers: config → device route → transport/TLS → server binding/firewall → HTTP route/auth → JSON contract แยกทีละชั้นแทนเปลี่ยน IP/portสุ่ม

1. Identify topology

Runtimehost machine
Android emulator10.0.2.2
Windows/Webบนเครื่องเดียวlocalhost
Physical PDALAN IP/DNSที่ deviceเข้าถึงได้

2. Confirm effective URL

ดู active connection profileและ final URLจาก ApiClientแบบ redact query ไม่เชื่อค่าที่กรอกอย่างเดียว ตรวจ scheme/port/prefix/slashและ logoutเมื่อ switch server

3. Test from device network

เปิด health URLจาก browser/curlบน deviceหรือเครื่อง networkเดียวกัน หาก hostเข้าถึงแต่ PDAไม่ได้ให้ตรวจ Wi-Fi VLAN/VPN/client isolation ไม่แก้ Flutter parser

4. Server binding/firewall

.NETต้อง bind 0.0.0.0/LAN interfaceไม่ใช่ localhostเท่านั้นและ OS firewallเปิด portเฉพาะ profile/networkที่ต้องใช้ ตรวจ process listenกับ exact portก่อน

5. HTTP vs HTTPS

Android releaseอาจ block cleartext, self-signed/private CAอาจไม่ trustedและ hostname/certificateต้องตรง ห้าม disable certificate validationหรือเปิด cleartext globalเป็น production fix

6. Interpret errors

  • DNS/Socket: route/host/firewall
  • Timeout: path/server load/drop
  • TLS handshake: certificate/protocol
  • 404: route/prefix
  • 401/403: session/policy
  • CORS: browser origin policy

7. Compare health vs business

healthผ่านแต่ endpoint failแปล transportถึง serverแล้ว ให้ตรวจ auth/route/contract Backend productionควร healthแยก liveness/readinessและไม่เปิดข้อมูลระบบ sensitive

8. Incident evidence

device model/OS/app version, network SSID/IP, timestamp/timezone, effective host, health result/latency, HTTP status/traceIdและ server logsที่ correlationตรงกัน โดยไม่ส่ง token/password
