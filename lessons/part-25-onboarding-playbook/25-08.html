Workflow ไม่ใช่หน้า form: เริ่ม state machine/invariantsและ failure recovery จากนั้นค่อยออกแบบ screen/steps/navigation

1. Write workflow table

แต่ละ stateระบุ visible UI, allowed events, guards, side effects, next stateและ recovery เช่น waiting→scan→validating→ready→submitting→done/error รวม server external transitions

2. Ownership split

Widgetถือ focus/controller/search/expanded; feature storeถือ current domain step, scanned evidence, submit stateและ server snapshot; repositoryถือ HTTP mapping; serverถือ inventory/task authority

3. Declarative steps

ใช้ StepDef metadataเมื่อหลาย task typesแชร์ shell แต่ endpoint/transitionต่างกันยังต้อง explicit command strategy อย่าใช้ step indexเป็น business identityโดยไม่มี key

4. Navigation policy

กำหนด back/home/tab/dialogว่า pause, discard local draftหรือ cancel server taskอย่างไร Resumeข้าม route/app restartต้องมี checkpoint/versionตาม requirement ไม่ปล่อยให้ Navigator behaviorตัดสินธุรกิจเอง

5. Scanner UX

exact normalization, hardware Enter, duplicate debounce, expected feedback, focus next/return, fixed actionและ keyboard viewport Scanเป็น proof of presenceจึงห้าม Next bypassใน evidence steps

6. Async/race policy

lookup latest-wins generation, submit exhaust+idempotency, poll single-flight, external event versionedและ logout/dispose invalidate ทั้งหมด วาดสอง operator scenarioก่อน implement

7. Tests before screen polish

state-machine tableเป็น parameterized store tests แล้วเพิ่ม widget tests scan/focus/navigation/overflowและ integration command/reconciliation Testทุก dead-endที่ userอาจไม่มีปุ่ม retry

8. Definition of done

ทุก state/eventมี ownerและ recovery, server/client authorityชัด, pause/resume/cancelอธิบายได้, duplicate/out-of-orderพิสูจน์ด้วย testsและ PDAจริงจบ flowได้โดยไม่ใช้ debug shortcut
