Connection flow มีสามไฟล์: SettingsScreenดูแล form/UX, ApiConfigServiceเก็บ host/port/protocol และ connection_probe.dartยิง /api/healthเพื่อยืนยันว่าเป็น WMS API

1. Stored record

({String? host, int port, String protocol})
defaultPort = 5000
defaultProtocol = 'http'

ใช้ SharedPreferencesสาม key ไม่มี base path/profileหลายชุด

2. Form validation

validateHostห้าม scheme, space, colon, slash เพราะ protocol/portแยกช่อง; validatePortรับ 1–65535 Validationเป็น pure functionsจึง unit testง่าย

3. Load sequence

load config → fill controllers
→ ApiService.resolveServerUrl()
→ render active URL → _probeActive()

มี mounted guardหลัง awaitและแยก loading/testing/saving/probing flags

4. Test before save

_testConnectionประกอบ URLจากค่าร่างแล้วยิง probeโดยไม่เปลี่ยน active config แสดง success/warning snackbar ช่วยป้องกัน saveค่าที่พิมพ์ผิดแต่ผู้ใช้ยังเลือก saveได้ตาม flow

5. Save invalidates cache

await config.save(...);
ApiService.resetBaseUrl();
final active = await ApiService.resolveServerUrl();
_probeActive();

ถ้าลืม reset singletonยังใช้ serverเก่า นี่คือ couplingสำคัญที่ต้องจำ

6. Clear behavior

clearสาม config keys → reset cache → resolverกลับ emulator/localhost → probeใหม่ ต่างจาก AuthSessionService.clearSession() ที่ clear prefsทั้งก้อนและอาจทำผลเดียวกันโดยไม่ตั้งใจ

7. Probe semantics

validate URI, GET healthพร้อม timeout, ตรวจ status 2xxและ payload signature แยก timeout, TLS handshake, socketและ client error Probe successหมายถึง endpointตอบเป็น WMS ไม่ได้พิสูจน์ login/permissionทุกโดเมน

8. Refactor seam

ใช้ typed ConnectionProfile + repository, inject HTTP client/resolver, commit profileแบบ atomicหลัง probe, production policyบังคับ HTTPS และให้ endpoint switchหยุด session/SignalR/in-flight requestsอย่างชัดเจน
