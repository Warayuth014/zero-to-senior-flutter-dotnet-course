1. สิ่งที่อยู่นอก lib/

โฟลเดอร์คืออะไรใช้จริงไหม

สิทธิ์เข้าถึงอินเทอร์เน็ตมีเฉพาะใน debug และ profile ตามที่ 15.3 อธิบาย

โหมดmanifest ที่รวมกันต่อเน็ตได้ไหม

flutter run --profilemain + profileได้

ผลที่ตามมา: APK ที่ build ออกไปแจกจะเปิดได้ ล็อกอินได้ (เพราะล็อกอินเป็น mock ตาม 16.4) แล้วกดเมนูปุ๊บขึ้น “ไม่สามารถเชื่อมต่อ server ได้” ทุกครั้ง
และปัญหานี้มองไม่เห็นเลยระหว่างพัฒนา เพราะทุกคนรันด้วย flutter run

แก้โดยย้ายไปที่ main manifest

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET"/>
    <application ...

และยังต้องเพิ่มอีกอย่างหนึ่ง — เซิร์ฟเวอร์ WMS ใช้ http ซึ่ง Android บล็อกตั้งแต่ API 28

พร้อมไฟล์ android/app/src/main/res/xml/network_security_config.xml ที่อนุญาตเฉพาะวงที่ใช้จริง ตามที่ 15.4 สอน

สอง TODO นี้เป็นของที่ flutter create ใส่มาให้ และยังไม่มีใครแก้

เรื่องผลบท
com.example.wmsappขึ้น Play Store ไม่ได้ และเปลี่ยนทีหลังไม่ได้ถ้าติดตั้งไปแล้ว15.8
เซ็นด้วยกุญแจ debugกุญแจนี้เหมือนกันทุกเครื่อง ใครก็สร้างแอปที่ติดตั้งทับได้15.5

แถวแรกร้ายแรงกว่าที่คิด — applicationId คือสิ่งที่ Android ใช้ระบุตัวแอป เปลี่ยนแล้วจะกลายเป็นแอปคนละตัว ผู้ใช้ต้องถอนของเก่าแล้วติดตั้งใหม่ และข้อมูลใน SharedPreferences หายทั้งหมด รวมถึงที่อยู่เซิร์ฟเวอร์ที่ตั้งไว้

ยิ่งเลื่อนแก้ ยิ่งมีเครื่องที่ต้องตั้งค่าใหม่มากขึ้น

ส่วนอีกสามค่ามาจาก pubspec.yaml โดยอัตโนมัติ

versionCode = flutter.versionCode      // ← มาจาก 1 ใน "1.0.0+1"
versionName = flutter.versionName      // ← มาจาก 1.0.0
# pubspec.yaml
version: 1.0.0+1

ยังเป็นค่าเริ่มต้น แปลว่ายังไม่เคยปล่อยรุ่นจริง — ถ้าปล่อยแล้วต้องเพิ่มเลขหลัง + ทุกครั้ง ไม่งั้นติดตั้งทับไม่ได้ตามที่ 15.2 อธิบาย

8. รายการที่ต้องแก้ก่อนปล่อยจริง

#ต้องแก้ระดับบท
1ย้าย INTERNET ไป main manifestขวางการปล่อย15.3
2เพิ่ม network security config สำหรับ httpขวางการปล่อย15.4
3เปลี่ยน applicationIdขวางการปล่อย15.8
4สร้างกุญแจของตัวเองแล้วเซ็นด้วยกุญแจนั้นขวางการปล่อย15.5
5ตั้งเลขรุ่นที่ไม่ใช่ค่าเริ่มต้นควรทำ15.2
6ต่อการยืนยันตัวตนจริงควรทำ16.4
7แก้ clearSession() ไม่ให้ลบที่อยู่เซิร์ฟเวอร์ควรทำ16.4
8ใส่ cacheWidth ที่ PartThumbnailควรทำ16.10

สี่ข้อแรกทำให้ APK ที่ปล่อยออกไปใช้งานไม่ได้จริง และทั้งสี่ข้อมองไม่เห็นเลยตอน flutter run — เป็นเหตุผลที่ 15.12 ยืนยันว่าต้องทดสอบบน APK release บนเครื่องจริงก่อนแจก

9. แบบฝึกหัด

หัวหน้าบอกว่า “พรุ่งนี้ต้องเอาแอปไปติดตั้งที่คลังให้ผู้ใช้ 20 เครื่อง” ตอนนี้เป็นเช้าวันนี้

  1. ต้องทำอะไรบ้าง เรียงลำดับ
  2. อะไรที่ต้องตัดสินใจแล้วเปลี่ยนทีหลังไม่ได้
  3. ทดสอบอะไรก่อนออกจากออฟฟิศ
แนวคำตอบ

ข้อ 1 — เรียงลำดับ

ลำดับทำอะไรเวลา
1ตัดสินใจ applicationId ให้จบ15 นาที (แต่ต้องคุยกัน)
2สร้าง keystore แล้วเก็บสำรองไว้สองที่30 นาที
3ย้าย INTERNET + เพิ่ม network security config30 นาที
4ตั้งเลขรุ่นเป็น 1.0.0+1 แล้วตั้ง tag ใน git10 นาที
5build APK release แล้วทดสอบบนเครื่องจริงครึ่งวัน
6เตรียมเอกสารตั้งค่า IP ให้ผู้ติดตั้ง30 นาที

ข้อ 5 กินเวลามากที่สุดและตัดไม่ได้ เพราะเป็นครั้งแรกที่จะได้เห็นว่า APK release ทำงานจริงหรือไม่

ข้อ 6 มักถูกลืม — ผู้ติดตั้ง 20 เครื่องต้องรู้ว่าต้องเข้าหน้า Settings แล้วใส่ IP อะไร ถ้าไม่บอก ทุกเครื่องจะขึ้น “ไม่สามารถเชื่อมต่อ server ได้”

ข้อ 2 — เปลี่ยนทีหลังไม่ได้

สิ่งที่ทำไม
applicationIdเปลี่ยนแล้วกลายเป็นแอปคนละตัว ต้องถอนติดตั้งใหม่ทั้ง 20 เครื่อง และค่าที่ตั้งไว้หายหมด
keystoreหายแล้วอัปเดตแอปเดิมไม่ได้อีกเลย ต้องให้ทุกเครื่องถอนแล้วติดตั้งใหม่

สองอย่างนี้ต้องตัดสินใจให้ถูกตั้งแต่วันแรก และ keystore ต้องสำรองไว้ในที่ที่ไม่หายพร้อมกัน — ไม่ใช่แค่บนเครื่องคนเดียว และไม่ใช่ใน git ตามที่ 15.6 ย้ำ

ข้อ 3 — ทดสอบอะไร

ทั้งหมดนี้ต้องทำบน APK release บนเครื่อง PDA จริง ไม่ใช่ flutter run

ทดสอบจับอะไร
ติดตั้งแล้วเปิดลายเซ็นและไอคอน
ตั้ง IP ในหน้า Settings แล้วกดทดสอบสิทธิ์ INTERNET และ cleartext
ล็อกอินแล้วกดเมนูสักอันยิง API ได้จริง
สแกนและยืนยันหนึ่งรอบเต็มflow ทำงานครบ
ปิด Wi-Fi แล้วกดข้อความบอกอะไร
กดออกจากระบบ แล้วล็อกอินใหม่แล้วกดเมนูบั๊ก prefs.clear() จาก 16.4
เลื่อนรายการยาว ๆ สักสองนาทีหน่วยความจำจากรูป (16.10)

สองแถวล่างเป็นแถวที่ปกติไม่มีใครทดสอบ แต่เป็นสองข้อที่จะทำให้ต้องกลับไปที่คลังอีกรอบถ้าไม่เจอตอนนี้

สิ่งที่ควรบอกหัวหน้า

ถ้าเวลาไม่พอทำครบ ข้อที่ตัดไม่ได้จริง ๆ คือข้อ 1–3 และการทดสอบสองแถวแรกของข้อ 3 — เพราะถ้าไม่มีสามข้อนั้น แอปจะใช้งานไม่ได้เลยสักเครื่อง ไม่ใช่แค่ทำงานได้ไม่ดี

ส่วนบั๊ก prefs.clear() ถ้าแก้ไม่ทัน อย่างน้อยต้องบอกผู้ใช้ว่า “อย่ากดออกจากระบบ” และแจ้งวิธีตั้ง IP ใหม่ถ้าเผลอกด — การรู้ปัญหาแล้วบอกล่วงหน้า ต่างจากปล่อยให้ผู้ใช้เจอเองมาก

  • ฟอนต์ Sarabun สามน้ำหนักถูกฝังมาเพราะ PDA มีฟอนต์ไทยไม่ครบ
  • INTERNET อยู่ใน debug/profile manifest เท่านั้น — APK release ต่อเน็ตไม่ได้
  • ยังไม่มี network security config ทั้งที่เซิร์ฟเวอร์เป็น http
  • สอง TODO ของ flutter create ยังอยู่: com.example.wmsapp และเซ็นด้วยกุญแจ debug
  • ไลบรารีเก้าตัว น้อยมากสำหรับ 22,000 บรรทัด ซึ่งเป็นข้อดี
  • เทสต์ 0 ข้อ แต่มีห้าส่วนที่เขียนเทสต์ได้ทันทีโดยไม่ต้องแก้โค้ดเดิม
  • สี่ข้อที่ขวางการปล่อยจริงมองไม่เห็นเลยตอน flutter run
