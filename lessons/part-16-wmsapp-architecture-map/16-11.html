Part 16: wmsapp Real Codebase Map

อ่านแผนที่โปรเจกต์ wmsapp และเส้นทางจาก main ไป screen/service/model

1. เป้าหมายของบทนี้

  • อธิบาย Platform/pubspec/assets ที่เกี่ยวข้อง ด้วยภาษาของตัวเองได้
  • ชี้ได้ว่าแนวคิดนี้อยู่ตรงไหนใน flow Flutter → .NET
  • ทดลองและตรวจผลได้ ไม่ใช่จำโค้ดอย่างเดียว

2. Mental model

Scanner warehouse ส่วนมากส่งอักขระเหมือน keyboard แล้วปิดด้วย Enter หน้าจอต้องคุม focus, normalize ค่า, ป้องกัน duplicate/submit ซ้ำ และคืน feedback เร็ว Controller กับ FocusNode เป็น resource ที่ต้อง dispose

หัวข้อนี้อยู่ในกลุ่ม wmsapp Real Codebase Map เมื่อเปิดโค้ดจริงให้ถามว่าใครเป็นเจ้าของข้อมูล ใครเปลี่ยนข้อมูล และ widget ใดต้อง rebuild หลังการเปลี่ยนนั้น

รอยต่อ .NET: บทนี้อธิบาย request/response และ endpoint ที่ Flutter ต้องรู้ ส่วน Controller → Service → EF Core/SQL ให้อ่านต่อในคอร์ส zero-to-senior-dotnet8-course

3. หาในโปรเจกต์จริง

บทพื้นฐานนี้เตรียมแนวคิดสำหรับอ่านทั้ง wmsapp และ wms_absolute_mobile โดยบท Codebase Deep Dive จะระบุไฟล์จริงแบบรายไฟล์

4. วิธีไล่ทีละขั้น

  1. เริ่มจาก event ของผู้ใช้ เช่น tap, submit หรือ scan
  2. ตาม method ที่เปลี่ยน state หรือเรียก dependency
  3. ถ้ามี I/O ให้เปิด request DTO, endpoint และ response model คู่กัน
  4. กลับมาดูว่า state ใหม่ทำให้ widget ส่วนใด rebuild
  5. เขียน test หรือ checklist เพื่อพิสูจน์ happy path และ error path

5. ตัวอย่างโค้ด

# เริ่มจากชื่อ action แล้วไล่ลงทีละชั้น
rg -n "ชื่อเมธอด|ชื่อ endpoint|ชื่อ model" lib docs

# เส้นทางที่ต้องตอบให้ได้
Screen → State/Store → Repository/ApiService → JSON → .NET endpoint

6. จุดที่พบบ่อยในงานจริง

อย่าอ่านไฟล์ใหญ่จากบรรทัดแรกถึงท้ายโดยไม่มีคำถาม; เริ่มจาก user action แล้ว trace เฉพาะ state และ dependency ที่เกี่ยวข้อง

7. Mini Exercise

  1. ค้นหา Platform/pubspec/assets ที่เกี่ยวข้อง หรือ symbol ที่เกี่ยวข้องในสอง reference apps
  2. วาด flow สั้น ๆ จาก UI ไป data source แล้วกลับมา UI
  3. เพิ่ม error case หนึ่งกรณีและอธิบายว่าผู้ใช้ควรเห็นอะไร

8. Checklist

  • บอก owner ของ state ได้
  • แยก synchronous code กับ asynchronous side effect ได้
  • รู้ว่า dispose/cancel ตรงไหน
  • อธิบาย contract กับ .NET โดยไม่ต้องเดาจาก UI

9. สรุปจำเร็ว

Platform/pubspec/assets ที่เกี่ยวข้อง ต้องตอบได้ทั้ง “มันคืออะไร”, “อยู่ตรงไหนในโค้ด”, “พังแบบไหน” และ “ทดสอบอย่างไร”
