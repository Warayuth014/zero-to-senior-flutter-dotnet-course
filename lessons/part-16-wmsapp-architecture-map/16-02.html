Composition root ปัจจุบันเล็กมาก: main.dart initialize Flutter แล้วสร้าง MaterialApp ซึ่งฟัง global themeProvider; dependencies อื่นยังถูกสร้างภายใน screens/services

1. Startup

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  runApp(const WmsApp());
}

ยังไม่มี async bootstrap จริง แต่ ensureInitialized เตรียมไว้สำหรับ plugin/config ก่อน runApp

2. Theme rebuild boundary

ValueListenableBuilder<ThemeMode>(
  valueListenable: themeProvider,
  builder: (_, mode, __) => MaterialApp(
    theme: AppTheme.light,
    darkTheme: AppTheme.dark,
    themeMode: mode,
  ),
)

toggle ทำให้ MaterialApp subtree rebuild แต่ Flutterรักษา element/stateที่ key/typeเดิม

3. Global ThemeProvider

ThemeProvider extends ValueNotifier<ThemeMode> อยู่ใน theme.dart และ global instanceเริ่ม light มี toggle/setMode ง่ายแต่ inject/test/resetยาก และยังไม่ persist themeข้าม restart

4. AppTheme

รวม brand colors, light/dark palettes, semantic getters, radius/spacing/touchTarget และ component themes ใช้ Sarabunทั่ว app จุดอ่านสำคัญคือ semantic getterที่รับ contextเทียบกับ legacy static light colorsซึ่งอาจผิดใน dark mode

5. Localization shell

Material/Widgets/Cupertino delegatesรองรับ Thai/English แต่ locale fixเป็น th_TH และข้อความ businessจำนวนมาก hardcodeไทย นี่คือ platform widget localization ไม่ใช่ full app localization

6. Home route

home: const HomeScreen()

ไม่มี named/declarative router; navigationส่วนใหญ่สร้าง MaterialPageRoute ใน callbacks จึงตาม route graphจาก HomeScreenและ domain menus

7. Bootstrap ที่ควรขยาย

อนาคต composition rootควรสร้าง config, HTTP client, session repository, stores/logger แล้ว injectลง tree รวม bootstrap state loading/failure ทำให้ singletonลดลงและ testทั้ง appด้วย fakeได้

8. จุดทดสอบ

pump WmsApp แล้ว assert Thai Material locale, light/dark toggleเปลี่ยน brightness, HomeScreenยังรักษา state และ dispose/recreate providerได้โดยไม่แชร์ globalข้าม test
