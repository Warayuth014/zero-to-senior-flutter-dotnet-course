HomeScreen คือ shell + route catalog + session gate: ไฟล์เดียวโหลด session, เปิด login/settings/dev tools/logout และประกอบ workflow cards จึงเป็นจุดแรกสำหรับเข้าใจเส้นทางผู้ใช้ทั้งหมด

1. Session state

String? _userId;
String? _fullName;
String? _role;

initState() → _loadUser() → AuthSessionService.loadSession()

ระหว่าง async loadไม่มี explicit loading state จึงต้องระวัง UIแสดง guestชั่วคราว

2. Login gate

Future<bool> _requireLogin() async {
  if (_userId != null) return true;
  await _openLogin();
  return _userId != null;
}

card callbackต้องเรียก gateก่อน push route; นี่เป็น UI gate ไม่ใช่ server authorization

3. Workflow cards

HomeFlowCard เป็น gradient cardสำหรับ Receiving, Unload, Putaway, Prework, Picking, Packing, Check-in และ Sorting แต่ละ callbackส่ง userId/fullNameลง screen ผ่าน constructor

4. Action cards

HomeActionCard เป็น cardแนวนอนสำหรับ actionรอง แยกจาก flow cardช่วยลด build code แต่ route definitionsยังอยู่ HomeScreen ทำให้เพิ่ม workflowต้องแก้ imports + UI + callbackที่เดียวกัน

5. Navigation style

Navigator.push(
  context,
  MaterialPageRoute(builder: (_) => ReceivingMenuScreen(
    userId: _userId!, fullName: _fullName!,
  )),
);

เครื่องหมาย !ปลอดภัยได้เพราะ gate แต่ compilerไม่รู้ invariant; session objectแบบ non-nullหลัง authจะชัดกว่า

6. Role และ dev tools

roleแสดงใน badgeและ supervisor flowบางส่วน ส่วน long-press avatarเปิด Test Pick Order/Test Sorting menu ต้องไม่ shipเป็น hidden security boundary Productionควร compile/authorize dev toolsอย่างชัดเจน

7. Logout

confirm → clearSession() → set fields null แต่ต้องตรวจ service singletons, SignalR, cached data และ in-flight requestsในทุกโดเมนด้วย เพราะการล้าง Home fieldsอย่างเดียวไม่เท่ากับ session boundaryสมบูรณ์

8. Refactor seam

สร้าง immutable SessionState + RouteDefinition list (label/icon/permission/builder), inject SessionController และให้ router/guardเป็นเจ้าของ auth จะลด callbacksซ้ำและทำ role/navigation testsได้
