Login ปัจจุบันเป็น prototype: LoginScreen มีผู้ใช้ 3 คน hardcode, passwordทุกคนคือ 1234 และหน่วง 500 ms ไม่มี API/JWT จึงห้ามตีความว่าเป็น authentication production

1. UI state

เก็บ selected user, password controller, obscure/loading/error และ animation controllerใน State พร้อม disposeถูกต้อง Flowคือ validate → loading → delay → compare password → save prefs → callback

2. Mock credentials

final _users = [
  {'userId': 'USR-001', 'role': 'OPERATOR'},
  {'userId': 'USR-003', 'role': 'SUPERVISOR'},
];
if (_passController.text != '1234') ...

ใช้ demoได้แต่ credentialอยู่ใน binaryและ roleเลือกจาก clientเอง

3. Persistence

prefs.setString('userId', ...);
prefs.setString('fullName', ...);
prefs.setString('role', ...);

AuthSessionService.loadSessionอ่านสาม keyนี้และ isLoggedInดูเพียง userId ไม่ตรวจ expiry/token/server

4. Callback handshake

HomeScreen push LoginScreenพร้อม onLoginSuccess ที่ pop route แล้ว reload prefs วิธีนี้มีสอง side effectsข้าม route หาก callbackเกิดหลัง disposeต้อง guard context และ typed route resultจะตามง่ายกว่า

5. clearSession risk

prefs.clear()ล้าง SharedPreferencesทั้งหมด รวม API host/protocol/portและ theme/settingsอื่นที่ใช้ storeเดียวกัน Logoutควร removeเฉพาะ session namespace ไม่ทำให้ endpointเปลี่ยนเงียบ ๆ

6. Production shape

credentials → AuthRepository.login()
→ access/refresh token + claims + expiration
→ secure storage → authenticated ApiClient
→ 401 refresh-or-logout → clear scoped session

7. Authorization

roleใน clientใช้ซ่อนเมนูเพื่อ UXได้ แต่ .NETต้องตรวจ permissionทุก endpointและ derive claimsจาก signed token ห้ามเชื่อ role/userIdที่ request bodyหรือ SharedPreferencesส่งมา

8. Characterization tests

ก่อน refactorล็อก behavior: ไม่เลือก user, passwordว่าง/ผิด, success callbackครั้งเดียว, dispose animation, reload Homeและ logoutไม่ลบ server config จากนั้นแทน delay/mockด้วย repositoryทีละขั้น
