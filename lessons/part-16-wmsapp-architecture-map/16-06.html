1. Singleton

static final ApiService _instance = ApiService._internal();
factory ApiService() => _instance;
ApiService._internal();

เรียกง่ายจากทุก screenแต่ inject fake client/base/authยากและ mutable stateแชร์ทั้ง app/tests

3. Discovery caveat

TCP portเปิดไม่ได้แปลว่าเป็น WMS APIและ sequential probeเพิ่ม startup latency Resolverจับ errorทั้งหมดเงียบแล้ว fallback candidateแรก Requestจริงจึงเป็นผู้แสดง error ส่วน Settings health probeตรวจ identityลึกกว่า

4. Transport methods

_get/_postใช้ top-level http functions, JSON headerและ timeout 10s; _uploadFileใช้ MultipartRequest timeout 30s ไม่มี injected client/auth/cancellation/retry

5. Response normalization

decoded List → {'items': decoded}
decoded Map  → Map<String, dynamic>
2xx          → ApiResult.success(body)
non-2xx      → error/detail/statusCode

cast Mapอาจ throwหาก JSONเป็น scalar/nullและถูก catchใน caller transport

6. ApiResult

เก็บ success/data/error/statusCodeและ helper isNotFound ลด exceptionใน UI แต่ success constructorfix statusCode=200แม้ responseจริงเป็น 201/204 จึงสูญเสีย metadataบางส่วน

7. URL helper risk

resolveServerUrlและ image helperใช้ replaceAll('/api','') ซึ่งเปราะหาก path/hostnameมีคำนี้ ควรเก็บ origin/API base/media baseเป็น Uri typedแทนตัด string

8. Refactor order

1) inject http.Client/base resolver 2) typed failures/status 3) auth/correlation 4) Uri composition 5) repository per domain 6) cancellation/idempotency โดย characterization testsล็อก request/responseเดิมก่อน
