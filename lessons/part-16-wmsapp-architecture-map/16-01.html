เป้าหมาย Part นี้: อ่าน wmsapp แบบมีแผนที่ ไม่เริ่มจาก screen ใหญ่สุ่ม ๆ เราจะตามเส้น main → HomeScreen → domain screen → ApiService extension → model → .NET แล้วรู้ว่า state/side effect อยู่ชั้นใด

1. ภาพรวมขนาดจริง

พื้นที่ไฟล์ Dartประมาณบรรทัด
screens8018,271
models111,507

น้ำหนักอยู่ที่ screens จึงพบ business state และ API orchestration ใน StatefulWidget จำนวนมาก

2. โครงโฟลเดอร์

lib/
├─ main.dart
├─ theme/theme.dart
├─ widgets/
├─ services/          // transport, config, session, SignalR
├─ models/            // DTO แยกโดเมน
└─ screens/           // receiving, unload, putaway, picking...

3. Runtime path

WmsApp
  → HomeScreen
    → require login
      → domain menu/screen
        → ApiService().domainMethod()
          → _get/_post/_uploadFile
            → ApiResult<T> → setState → widget tree

4. Domain boundaries

Receiving/Unload เป็น inbound, Putaway เคลื่อนเข้า storage, Picking/Packing/Check-in/Sorting เป็น outbound, Basket เป็นปลาย unload และ Upload เป็น supervisor image แต่ boundary ปัจจุบันเป็นโฟลเดอร์/extension มากกว่า repository/store ที่บังคับทางสถาปัตยกรรม

5. Shared core

theme.dart, common_widgets.dart, ApiService, ApiConfigService, AuthSessionService และ SignalR singletons ถูกใช้ข้ามโดเมน การเปลี่ยนไฟล์เหล่านี้มี blast radius สูง ต้องหา usages และเพิ่ม regression tests ก่อน

6. State ownership ปัจจุบัน

local controllers/loading/selected entity มักอยู่ใน State ของ screen, sessionอยู่ SharedPreferences + HomeScreen fields, base URLอยู่ prefs + static cache, realtime connectionอยู่ service singleton จึงต้องตาม lifecycleหลายตำแหน่งเมื่อ debug race/logout/switch server

7. Strengths และ risks

ข้อดีคือชื่อโดเมนชัด, API/model แยกไฟล์, widget บาง flow ถูกแยกย่อยแล้ว ข้อเสี่ยงคือ singletonซ่อน dependency, mock login, giant screens, dynamic JSON และ testหลักของ wmsappยังไม่มี safety net

8. วิธีอ่าน

เริ่ม composition → เลือกหนึ่ง user action → จด stateก่อน/หลัง → ตาม methodถึง endpoint → เปิด DTO → ไล่ error/lifecycle → เขียน characterization test แล้วจึง refactor ห้ามอ่านทุกไฟล์เรียง alphabetically
