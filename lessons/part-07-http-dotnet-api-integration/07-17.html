Log เพื่อ debug flow โดยไม่รั่วความลับ: เก็บ method, route template, status, elapsed, attempt และ correlation ID; redact token/PII/business payload

1. Structured event

{
  "event":"http.completed",
  "method":"POST",
  "route":"/api/WMS/tasks/{id}/complete",
  "status":409,
  "elapsedMs":184,
  "traceId":"00-abcd",
  "attempt":1
}

2. อย่า log raw URL เสมอ

query อาจมี barcode, username หรือ search text ให้ log route template และ allowlist query ที่ปลอดภัย หรือ hash identifier เมื่อจำเป็นต้อง correlate

3. Redaction

case-insensitive redact headers เช่น Authorization, Cookie, Set-Cookie, API-Key และ redact JSON fields เช่น password/token ก่อน serialize—ไม่ redact หลังเขียน log แล้ว

4. Request/response body

ปิดเป็นค่าเริ่มต้นใน production; debug เฉพาะ endpoint allowlist, จำกัดขนาด และ scrub field หาก error body เป็น HTML ให้เก็บ content-type/length ไม่เก็บทั้งหน้า

5. Timing

ใช้ stopwatch รอบทุก attempt และแยก logical operation ID จาก retry attempt เพื่อวิเคราะห์ latency/timeout โดยไม่สับสนว่าเป็นหลายคำสั่ง

6. Flutter กับ .NET

ส่ง trace/correlation header แล้วให้ .NET scope log ต่อ ID เดียวกัน ทำให้ตามจาก device → endpoint → service ได้ โดย server เป็นแหล่ง log หลักของ exception ภายใน

7. แบบฝึกหัด

เลือก field จาก request complete-task ว่าอะไร log ได้ตรง ๆ, hash, หรือห้าม log

แนวคำตอบ

method/status/elapsed log ได้; task ID อาจ hash; token/password ห้าม; quantity/barcode พิจารณา classification และ operational need

8. Test

เขียน test ส่ง token/secret marker ผ่าน headers/body/error แล้ว assert ว่า marker ไม่ปรากฏใน log sink แม้ request ล้มเหลว
