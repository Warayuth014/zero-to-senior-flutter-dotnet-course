Method สื่อเจตนา: GET อ่านข้อมูล, POST ส่ง command/สร้าง resource; payload และ side effect ต้องตรงกับ contract ของ endpoint

1. GET

final uri = buildUri('/tasks', {'status': 'open'});
final response = await client.get(uri, headers: headers);

GET ควร safe และไม่มีการเปลี่ยนข้อมูล เพื่อให้ retry/cache มีความหมาย

2. POST JSON

final response = await client.post(
  buildUri('/tasks/complete'),
  headers: {...headers, 'Content-Type': 'application/json'},
  body: jsonEncode(request.toJson()),
);

3. DTO ไม่ใช่ widget state

สร้าง request DTO ที่มีเฉพาะ field ตาม API เช่น taskId, quantity และ idempotencyKey อย่าส่งทั้ง domain object หรือ map จาก controller เพราะจะรั่ว field และเปลี่ยน contract โดยไม่ตั้งใจ

4. Other methods

PUT มักแทน resource เต็ม, PATCH แก้บาง field, DELETE ลบ แต่ความหมายจริงต้องอ่าน API contract ไม่เดาจากชื่อ method อย่างเดียว

5. .NET counterpart

app.MapPost("/api/WMS/tasks/complete",
  async (CompleteTaskRequest request, ITaskService service,
         CancellationToken ct) => {
    var result = await service.CompleteAsync(request, ct);
    return Results.Ok(result);
  });

6. Body edge cases

แยก empty body, JSON null, object และ list ให้ชัด ถ้า success endpoint คืน 204 ต้องไม่บังคับ decode map; ถ้า 200 ต้องกำหนด response shape

7. แบบฝึกหัด

การสแกนยืนยันหยิบสินค้าเป็น GET หรือ POST?

เฉลย

POST เพราะเปลี่ยน state และอาจมี side effect; ต้องออกแบบ duplicate/idempotency ด้วย ไม่ซ่อน command ใน query ของ GET

8. Checklist

method ตรง intent, URI encode แล้ว, request DTO typed, content-type ถูก, .NET bind ได้ และกำหนด success body/empty body ชัดเจน
