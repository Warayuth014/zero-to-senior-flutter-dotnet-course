Headers คือ metadata ของ request: กำหนดชนิด payload, รูปแบบ response, authentication, tracing และ idempotency โดยไม่ปนกับ business body

1. ชุดพื้นฐาน

Map<String, String> headers(String? token) => {
  'Accept': 'application/json',
  'Content-Type': 'application/json; charset=utf-8',
  if (token != null) 'Authorization': 'Bearer $token',
};

2. Content-Type vs Accept

Content-Type บอกชนิด body ที่ส่ง ส่วน Accept บอกชนิด response ที่รับ GET ที่ไม่มี body ไม่จำเป็นต้องใส่ Content-Type แต่ใส่ Accept ได้

3. Bearer token

ApiClient ควรอ่าน token จาก session provider ตอนส่ง request เพื่อไม่ cache token เก่าหลัง refresh/logout และต้องไม่เติมคำว่า Bearer ซ้ำสองครั้ง

4. 401 กับ 403

401 หมายถึงยัง authenticate ไม่สำเร็จหรือ token ใช้ไม่ได้ ส่วน 403 คือรู้ว่าเป็นใครแต่ไม่มีสิทธิ์ UI อาจพา login ใหม่เมื่อ 401 แต่ 403 ควรอธิบายสิทธิ์ ไม่ logout แบบเหมารวม

5. Correlation

ส่ง/รับ correlation หรือ trace ID เพื่อให้ support ตาม request จาก PDA ไป log ฝั่ง .NET ได้ โดยแสดง ID นี้ในหน้ารายละเอียด error แต่ไม่ใช้แทน idempotency key

6. Multipart ต่างจาก JSON

เมื่อใช้ MultipartRequest ให้ library สร้าง boundary ใน Content-Type อย่ากำหนด multipart/form-data เองแบบไม่มี boundary

7. แบบฝึกหัด
