Error ต้องแยกประเภท: timeout, ไม่มี route/network, TLS, HTTP error และ JSON contract error มีสาเหตุและวิธีแก้ต่างกัน อย่ารวมเป็น “เชื่อมต่อไม่ได้” ทั้งหมด

1. Exception map

  • TimeoutException: เกินเวลาที่ client ยอมรอ
  • SocketException: DNS/route/connection ล้มเหลว
  • ClientException: transport/client error อื่น
  • FormatException: URL หรือ response format ผิด
  • ApiException: server ตอบ status ที่ไม่สำเร็จ

2. Timeout รอบ operation

try {
  return await _client.get(uri, headers: headers)
      .timeout(const Duration(seconds: 15));
} on TimeoutException {
  throw const NetworkException.timeout();
} on SocketException catch (e) {
  throw NetworkException.offline(cause: e);
}

3. Connect vs response timeout

Future.timeout ให้ budget รวมแบบง่าย แต่ไม่ได้แปลว่าจะยกเลิก socket ทุก implementation งาน download/upload ยาวควรมี policy แยกและ cancellation strategy

4. User message

ข้อความควร actionable เช่น “ติดต่อ server ไม่ได้ ตรวจ Wi-Fi และ URL” หรือ “server ใช้เวลานาน ลองใหม่” พร้อม technical cause สำหรับ log แต่ไม่โยน stack trace ให้ผู้ใช้

5. Finally และ state

ปิด loading ใน finally หรือเปลี่ยนเป็น terminal state ทุก branch เพื่อไม่ให้ปุ่มค้าง และตรวจ mounted ก่อนใช้ context หลัง await

6. Offline ไม่เท่ากับ internet

Mobile WMS อาจไม่มี internet แต่ยังเข้าถึง intranet API ได้ จึงต้อง probe endpoint เป้าหมาย ไม่ใช้ connectivity package เป็นคำตัดสินสุดท้าย

7. แบบฝึกหัด

server บันทึก command สำเร็จแต่ response timeout ผู้ใช้กดซ้ำได้ไหม?

เฉลย

ยังไม่รู้ผลแน่ชัด จึงต้องใช้ idempotency key หรือ query status ก่อน retry; timeout ไม่ได้พิสูจน์ว่า server ไม่ทำงาน

8. จุดพลาด
