1. ปัญหาที่บทนี้แก้

สถานการณ์ที่ทุกคนเจอในวันแรกที่ต่อ API

เปิดเบราว์เซอร์บนคอมพิวเตอร์ → http://localhost:5000/health → ทำงานได้
รันแอปบน emulator ด้วยที่อยู่เดียวกัน → เชื่อมต่อไม่ได้

ความรู้สึกแรกคือ “โค้ดผิด” แล้วก็ไปนั่งไล่โค้ด ApiClient เป็นชั่วโมง

แต่โค้ดถูกทุกบรรทัด — ปัญหาคือคำว่า localhost แปลว่าคนละเครื่องกัน

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
localhostเครื่องที่โปรแกรมนั้นกำลังรันอยู่ — ไม่ใช่เครื่องใดเครื่องหนึ่งตายตัว
127.0.0.1ที่อยู่ตัวเลขของ localhost
LAN IPที่อยู่ของเครื่องในเครือข่ายเดียวกัน เช่น 192.168.1.50
emulatorโปรแกรมจำลองเครื่อง Android บนคอมพิวเตอร์
bindการที่เซิร์ฟเวอร์เลือกว่าจะรับคำขอจากที่อยู่ไหนบ้าง
firewallตัวกรองที่บล็อกการเชื่อมต่อเข้าเครื่อง

3. Mental model: localhost คือ "ตัวฉันเอง"

เบราว์เซอร์บนคอมพิวเตอร์ พูดว่า localhost  →  หมายถึงคอมพิวเตอร์เครื่องนั้น ✓
แอปบน emulator พูดว่า localhost           →  หมายถึง emulator เอง ✗
แอปบน PDA พูดว่า localhost                →  หมายถึง PDA เอง ✗
ประโยคเดียวที่ต้องจำ: localhost ไม่ใช่ที่อยู่ของเซิร์ฟเวอร์ แต่เป็นคำที่แปลว่า “เครื่องนี้” — ซึ่งเปลี่ยนความหมายไปตามว่าใครเป็นคนพูด

เมื่อ PDA พูดว่า localhost มันกำลังหาเซิร์ฟเวอร์ในตัวเอง ซึ่งไม่มี จึงเชื่อมต่อไม่ได้

4. ตารางที่อยู่ตามอุปกรณ์

รันแอปที่ไหนใช้ที่อยู่อะไรเพราะ
Windows หรือเว็บ บนคอมพิวเตอร์เครื่องเดียวกับเซิร์ฟเวอร์http://localhost:5000เครื่องเดียวกันจริง
Android emulatorhttp://10.0.2.2:5000เป็นที่อยู่พิเศษที่ emulator จองไว้ให้หมายถึงเครื่องแม่
iOS simulatorhttp://localhost:5000ใช้เครือข่ายร่วมกับเครื่องแม่
PDA หรือโทรศัพท์จริงhttp://192.168.1.50:5000ต้องระบุที่อยู่ของคอมพิวเตอร์ในเครือข่าย
ใช้งานจริงhttps://wms.company.comชื่อโดเมนพร้อมการเข้ารหัส

10.0.2.2 ไม่ใช่ตัวเลขที่จำมาลอย ๆ — มันคือกติกาของ Android emulator ที่จองที่อยู่นี้ไว้หมายถึงเครื่องที่รัน emulator อยู่

วิธีหาที่อยู่ของคอมพิวเตอร์ในเครือข่าย

ipconfig          # Windows — ดู IPv4 Address ของการ์ดที่ใช้อยู่
ifconfig          # macOS และ Linux

5. เซิร์ฟเวอร์ต้องยอมรับคำขอจากข้างนอกด้วย

ต่อให้ใช้ที่อยู่ถูกแล้ว ก็ยังเชื่อมต่อไม่ได้ ถ้าเซิร์ฟเวอร์รับเฉพาะคำขอจากตัวเอง

// ฝั่ง server — รับเฉพาะเครื่องตัวเอง
app.Run("http://localhost:5000");

// รับจากทุกที่อยู่ของเครื่องนี้ รวมถึงจากเครื่องอื่นในเครือข่าย
app.Run("http://0.0.0.0:5000");
ที่อยู่ที่ bindใครเข้าถึงได้
localhost หรือ 127.0.0.1เฉพาะโปรแกรมบนเครื่องนั้น
0.0.0.0ทุกเครื่องที่เข้าถึงเครือข่ายได้

และแม้ bind ถูกแล้ว firewall ของ Windows ยังอาจบล็อกอยู่ — ต้องอนุญาต port นั้นเฉพาะเครือข่ายส่วนตัว

อย่าปิด firewall ทั้งเครื่องเพื่อให้ผ่าน — เปิดเฉพาะ port ที่ต้องใช้และเฉพาะเครือข่ายส่วนตัว การปิดทั้งเครื่องเปิดช่องให้ทุกอย่าง และมักลืมเปิดกลับ

6. ไล่หาสาเหตุจากล่างขึ้นบน

เมื่อเชื่อมต่อไม่ได้ อย่าเริ่มที่โค้ด Flutter — เริ่มที่ชั้นล่างสุดตามหลักใน 7.1

ขั้นทำอะไรถ้าไม่ผ่าน แปลว่า
1เปิด URL ในเบราว์เซอร์ บนเครื่อง PDA เองปัญหาอยู่นอกแอป ไม่ต้องแตะโค้ด
2ตรวจว่า PDA กับคอมพิวเตอร์อยู่เครือข่ายเดียวกันคนละ Wi-Fi หรือคนละ VLAN
3ตรวจว่าเซิร์ฟเวอร์ bind ที่ 0.0.0.0รับเฉพาะเครื่องตัวเอง
4ตรวจ firewallถูกบล็อกที่ปลายทาง
5ตรวจว่าเป็น http หรือ httpsดูหัวข้อ 7
6ค่อยดูโค้ด

ขั้นที่ 1 สำคัญที่สุดและคนข้ามบ่อยที่สุด — ถ้าเบราว์เซอร์บน PDA เปิดไม่ได้ แอปก็ไม่มีทางเปิดได้ และการรู้แบบนี้ตัดความเป็นไปได้ทั้งหมดที่เกี่ยวกับโค้ดออกไปในสิบวินาที

7. Android บล็อก HTTP ที่ไม่เข้ารหัส

ปัญหาที่ทำให้งงเป็นพิเศษ เพราะเซิร์ฟเวอร์ทำงานปกติและเบราว์เซอร์เปิดได้ แต่แอปเชื่อมต่อไม่ได้

ClientException: Cleartext HTTP traffic to 192.168.1.50 not permitted

Android รุ่นใหม่ไม่อนุญาตให้แอปเรียก http:// ธรรมดา ต้องเป็น https://

สภาพแวดล้อมควรทำ
ใช้งานจริงใช้ https — ไม่มีข้อยกเว้น
ระหว่างพัฒนาอนุญาต http เฉพาะที่อยู่ที่ต้องใช้ ไม่ใช่อนุญาตทั้งหมด

เหตุผลที่ไม่ควรอนุญาตทั้งหมด — การตั้งค่านั้นจะติดไปกับแอปที่ปล่อยจริง แล้วข้อมูลของคลังทั้งหมดจะวิ่งแบบไม่เข้ารหัสในเครือข่ายที่ใคร ๆ ก็ดักดูได้

8. CORS ไม่ใช่คำตอบของทุกปัญหา

เมื่อค้นหาปัญหาการเชื่อมต่อ มักเจอคำตอบที่บอกให้เปิด CORS ซึ่งถูกเฉพาะบางกรณี

รันแอปแบบถูกบังคับด้วย CORS ไหม
Flutter Webใช่ — เบราว์เซอร์เป็นคนบังคับ
Android, iOS, Windowsไม่ — ไม่มีเบราว์เซอร์มาบังคับ

ถ้าแอปบน PDA เชื่อมต่อไม่ได้ CORS ไม่ใช่สาเหตุแน่นอน และการไปเปิด CORS แบบกว้างที่เซิร์ฟเวอร์คือการเปิดช่องโดยไม่ได้แก้อะไร

วิธีแยกที่ง่ายที่สุด — ถ้าข้อความผิดพลาดมีคำว่า CORS อยู่ในนั้น ก็เกี่ยว ถ้าไม่มี ก็ไม่เกี่ยว

9. ให้ที่อยู่เปลี่ยนได้โดยไม่ต้องแก้โค้ด

เพราะที่อยู่ต่างกันตามอุปกรณ์และสาขา จึงไม่ควรเขียนตายไว้ในโค้ด

// เลี่ยง — ต้องแก้โค้ดและ build ใหม่ทุกครั้งที่เปลี่ยนเครื่อง
const baseUrl = 'http://10.0.2.2:5000';
วิธีเหมาะกับ
ค่าที่ส่งตอน buildแยก dev กับ production
หน้าตั้งค่าในแอปแต่ละสาขาคนละเซิร์ฟเวอร์
ค่าตั้งต้นในโค้ดใช้เมื่อยังไม่เคยตั้งค่า
// ค่าที่ส่งตอน build — เปลี่ยนได้โดยไม่แก้ source
const buildTimeBaseUrl = String.fromEnvironment(
  'WMS_BASE_URL',
  defaultValue: 'http://10.0.2.2:5000',
);
flutter run --dart-define=WMS_BASE_URL=http://192.168.1.50:5000

ในแอปคลังจริงมักใช้ทั้งสองอย่าง — ค่าจากตอน build เป็นค่าตั้งต้น แล้วให้ผู้ใช้แก้ได้ในหน้าตั้งค่าตามที่ทำใน 5.11

10. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
emulator เชื่อมต่อไม่ได้ แต่เบราว์เซอร์บนคอมได้ใช้ localhost บน emulatorเปลี่ยนเป็น 10.0.2.2
PDA เชื่อมต่อไม่ได้ แต่ emulator ได้ใช้ 10.0.2.2 บนเครื่องจริงเปลี่ยนเป็น LAN IP
ใช้ LAN IP แล้วยังไม่ได้เซิร์ฟเวอร์ bind แค่ localhostbind ที่ 0.0.0.0
bind ถูกแล้วยังไม่ได้firewall บล็อกอนุญาต port เฉพาะเครือข่ายส่วนตัว
Cleartext HTTP not permittedAndroid บล็อก httpใช้ https หรืออนุญาตเฉพาะที่อยู่นั้น
ไปเปิด CORS แล้วก็ยังไม่ได้ไม่ได้รันบนเว็บCORS ไม่เกี่ยว หาสาเหตุอื่น
ต้อง build ใหม่ทุกครั้งที่เปลี่ยนเครื่องเขียนที่อยู่ตายในโค้ดให้ตั้งค่าได้
วันก่อนใช้ได้ วันนี้ใช้ไม่ได้คอมพิวเตอร์ได้ IP ใหม่จากเราเตอร์ตั้ง IP คงที่ หรือใช้ชื่อเครื่อง

11. แบบฝึกหัด

ทีมติดตั้งระบบที่สาขาใหม่ และเจออาการนี้

สิ่งที่ทดสอบผล
เปิด http://localhost:5000/health บนคอมพิวเตอร์ที่รันเซิร์ฟเวอร์ได้
เปิด http://192.168.1.50:5000/health บนคอมพิวเตอร์เครื่องเดียวกันได้
เปิด http://192.168.1.50:5000/health บนเบราว์เซอร์ของ PDAไม่ได้
PDA เปิดเว็บทั่วไปได้ได้
  1. ตัดความเป็นไปได้ที่ไม่ใช่ออกไปก่อน โดยใช้ข้อมูลที่มี
  2. เรียงสิ่งที่ต้องตรวจต่อ
  3. ตอบว่าถ้าแก้ได้แล้ว ควรทำอะไรเพิ่มเพื่อไม่ให้สาขาถัดไปเจอปัญหาเดิม
ดูแนวคำตอบและเหตุผล

ข้อ 1 — ตัดสิ่งที่ไม่ใช่ออกไป

ข้อมูลสี่บรรทัดตัดความเป็นไปได้ออกไปได้เยอะมาก

ตัดออกได้เพราะ
โค้ด Flutterทดสอบด้วยเบราว์เซอร์ ไม่ได้ใช้แอป
การประกอบ URLเหตุผลเดียวกัน
เซิร์ฟเวอร์ไม่ทำงานบรรทัดแรกบอกว่าทำงานอยู่
เซิร์ฟเวอร์ bind แค่ localhostบรรทัดที่สองบอกว่า bind กว้างแล้ว
PDA ไม่มีเครือข่ายบรรทัดที่สี่บอกว่าออกเน็ตได้
Android บล็อก httpทดสอบด้วยเบราว์เซอร์ ซึ่งไม่ถูกกฎนั้นบังคับ
CORSไม่ได้รันบนเว็บ และเบราว์เซอร์เปิด URL ตรงไม่ถูก CORS บังคับ

บรรทัดที่สองเป็นข้อมูลที่มีค่าที่สุดและคนมักไม่ทดสอบ — การเปิดด้วย LAN IP บนเครื่องตัวเอง แยก “bind แคบ” ออกจาก “ถูกบล็อกระหว่างทาง” ได้

ข้อ 2 — สิ่งที่ต้องตรวจต่อ

เหลือความเป็นไปได้แค่กลุ่มเดียว คือ มีอะไรบล็อกระหว่าง PDA กับคอมพิวเตอร์

1. firewall บนคอมพิวเตอร์
     ทดสอบ: ปิดชั่วคราวแล้วลองใหม่ ถ้าได้ ให้เปิดกลับแล้วเพิ่มกฎเฉพาะ port

2. PDA กับคอมพิวเตอร์อยู่คนละเครือข่ายย่อย
     ทดสอบ: ดู IP ของ PDA — ถ้าเป็น 192.168.5.x ขณะที่คอมเป็น 192.168.1.x
             แปลว่าคนละวง แม้ชื่อ Wi-Fi จะเหมือนกัน

3. เครือข่ายกันไม่ให้อุปกรณ์คุยกันเอง
     พบบ่อยใน Wi-Fi สำหรับแขก และในองค์กรที่แยกวงอุปกรณ์พกพา
     ทดสอบ: ping จาก PDA ไปที่ IP ของคอมพิวเตอร์

4. คอมพิวเตอร์มีการ์ดเครือข่ายหลายใบ
     192.168.1.50 อาจเป็นของสาย LAN ขณะที่ Wi-Fi เป็นอีก IP หนึ่ง
     ทดสอบ: ดู ipconfig ทุกใบ แล้วลอง IP ของใบที่ต่อ Wi-Fi เดียวกับ PDA

เรียงตามความน่าจะเป็น — ข้อ 1 กับ 3 เจอบ่อยที่สุดในคลังจริง เพราะทีมไอทีมักแยกวงอุปกรณ์พกพาออกจากวงเซิร์ฟเวอร์ด้วยเหตุผลด้านความปลอดภัย

และข้อ 4 เป็นข้อที่หลอกที่สุด เพราะ ipconfig แสดงหลาย IP แล้วคนมักหยิบอันแรก

ข้อ 3 — ป้องกันไม่ให้สาขาถัดไปเจอปัญหาเดิม

สิ่งที่ทำได้แบ่งเป็นสองกลุ่ม

กลุ่มที่หนึ่ง — ทำให้แอปบอกสาเหตุได้เอง

ทำอะไรช่วยอย่างไร
ปุ่มทดสอบการเชื่อมต่อในหน้าตั้งค่ารู้ทันทีตอนติดตั้ง ไม่ใช่ตอนคนหน้างานเริ่มทำงาน (7.16)
แยกข้อความ “ต่อไม่ได้” ออกจาก “ต่อได้แต่ถูกปฏิเสธ”ชี้ว่าเป็นปัญหาเครือข่ายหรือปัญหาสิทธิ์ (7.7)
แสดงที่อยู่ที่กำลังใช้อยู่บนหน้าจอคนติดตั้งเห็นได้เลยว่าพิมพ์ผิดหรือเปล่า

กลุ่มที่สอง — ทำให้ทีมติดตั้งไม่ต้องเดา

รายการตรวจก่อนติดตั้ง

□ เซิร์ฟเวอร์ bind ที่ 0.0.0.0 ไม่ใช่ localhost
□ firewall อนุญาต port 5000 เฉพาะเครือข่ายส่วนตัว
□ คอมพิวเตอร์ตั้ง IP คงที่ ไม่ใช่รับจากเราเตอร์
□ ยืนยันว่า PDA กับเซิร์ฟเวอร์อยู่วงเดียวกัน (สองสามหลักแรกของ IP ตรงกัน)
□ เปิด /health จากเบราว์เซอร์ของ PDA ได้ ก่อนจะติดตั้งแอป
□ บันทึกที่อยู่ที่ใช้จริงไว้ในเอกสารของสาขานั้น

บรรทัดที่สามสำคัญและมักถูกลืม — ถ้าคอมพิวเตอร์รับ IP จากเราเตอร์ วันหนึ่งมันจะได้ IP ใหม่ แล้ว PDA ทุกเครื่องในสาขาจะใช้งานไม่ได้พร้อมกันโดยไม่มีใครแก้อะไร

อาการนั้นจะดูเหมือนแอปพังเอง ทั้งที่ไม่มีใครแตะอะไรเลย

บทเรียนที่ควรจำ: ปัญหาการเชื่อมต่อส่วนใหญ่ไม่ได้อยู่ในโค้ด — และการทดสอบด้วยเบราว์เซอร์บนเครื่องปลายทางก่อนเสมอ ตัดความเป็นไปได้ออกไปได้ครึ่งหนึ่งในสิบวินาที

12. สรุปท้ายบท

  • localhost แปลว่า “เครื่องนี้” ซึ่งเปลี่ยนความหมายตามว่าใครพูด
  • emulator ใช้ 10.0.2.2 ส่วนเครื่องจริงใช้ที่อยู่ในเครือข่าย
  • เซิร์ฟเวอร์ต้อง bind ที่ 0.0.0.0 จึงจะรับจากเครื่องอื่นได้
  • firewall ต้องอนุญาตเฉพาะ port ที่ต้องใช้ ไม่ใช่ปิดทั้งเครื่อง
  • Android บล็อก http ธรรมดา — ใช้ https หรืออนุญาตเฉพาะที่อยู่ที่จำเป็น
  • CORS เกี่ยวเฉพาะเมื่อรันบนเว็บ
  • เปิด URL ในเบราว์เซอร์บนเครื่องปลายทางก่อนเสมอ
  • ให้ที่อยู่ตั้งค่าได้ และตั้ง IP ของเซิร์ฟเวอร์ให้คงที่
