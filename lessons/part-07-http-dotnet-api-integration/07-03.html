localhost คือเครื่องที่รันแอป: บน emulator และโทรศัพท์จริง คำว่า localhost ไม่ได้ชี้ไป PC ที่รัน .NET เสมอไป

1. Address matrix

  • Flutter Windows/Web บน PC: localhost อาจถึง .NET บน PC
  • Android Emulator มาตรฐาน: ใช้ 10.0.2.2 เพื่อย้อนถึง host
  • โทรศัพท์/PDA จริง: ใช้ LAN IP ของ PC/server เช่น 192.168.1.50
  • production: ใช้ DNS/HTTPS ตาม environment

2. .NET ต้อง listen ให้ถึง

ถ้า Kestrel bind เฉพาะ localhost อุปกรณ์อื่นจะเข้าไม่ได้ ต้องกำหนด endpoint ที่เหมาะสมและเปิด firewall เฉพาะ port/network ที่อนุญาต

3. เช็กเป็นชั้น

  1. อุปกรณ์อยู่เครือข่ายเดียวกันหรือมี route
  2. ping/port ถึงหรือไม่
  3. เปิด health URL จาก browser บนอุปกรณ์
  4. ตรวจ HTTP/HTTPS และ certificate
  5. ค่อย debug Flutter parsing

4. Android cleartext

HTTP แบบไม่เข้ารหัสอาจถูก platform policy บล็อก แม้ server ทำงานอยู่ ควรใช้ HTTPS ใน production; หาก dev จำเป็นต้องใช้ HTTP ให้จำกัด network security config เฉพาะ host ที่ต้องใช้

5. CORS ไม่ใช่ทุกกรณี

CORS บังคับโดย browser จึงเกี่ยวกับ Flutter Web แต่ native Android/Windows ไม่ถูก browser CORS policy บล็อก อย่าแก้ native connection error ด้วยการเปิด CORS กว้างโดยไม่มีเหตุผล

6. Connection profile

wms_absolute_mobile/lib/core/connection_profile.dart แยก base URL ที่ผู้ใช้บันทึกกับ build-time override ทำให้ dev/staging/production เปลี่ยนได้โดยไม่แก้ source

7. แบบฝึกหัดวินิจฉัย

API เปิดได้ที่ PC ด้วย localhost แต่ PDA timeout จงเรียงสิ่งที่ตรวจ

เฉลย

เปลี่ยนเป็น LAN IP → ตรวจ Kestrel bind → firewall → Wi-Fi/VLAN → เปิด health จาก PDA → platform HTTP policy

8. ความปลอดภัย

อย่าปิด firewall ทั้งเครื่องหรือ trust certificate แบบถาวรเพื่อให้ dev ผ่าน แก้เฉพาะ port, profile และ certificate chain ที่จำเป็น
