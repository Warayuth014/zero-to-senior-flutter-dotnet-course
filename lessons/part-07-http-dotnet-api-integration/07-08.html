Decode สองชั้น: HTTP success เป็นเพียง transport success; body ยังต้องผ่าน JSON syntax, shape และ domain validation ก่อนเป็นข้อมูลที่ UI เชื่อถือได้

1. Success range

โดยทั่วไป status 200–299 สำเร็จ แต่แต่ละ endpoint ต้องกำหนด expected status เช่น POST create อาจคืน 201 และ command ที่ไม่มี body อาจคืน 204

2. Decode UTF-8

Object? decodeJson(http.Response response) {
  if (response.bodyBytes.isEmpty) return null;
  final text = utf8.decode(response.bodyBytes);
  return jsonDecode(text);
}

ใช้ body bytes ช่วยรักษาภาษาไทยเมื่อ header encoding จาก server/proxy ไม่สมบูรณ์

3. Shape guard

final raw = decodeJson(response);
if (raw is! Map<String, dynamic>) {
  throw ContractException('Expected JSON object');
}
return TaskDto.fromJson(raw);

4. Empty response

204 ต้องไม่เรียก jsonDecode('') สำหรับ 200 empty body ให้ถือเป็น contract error เว้นแต่ endpoint ระบุชัดว่าอนุญาต

5. Parse ที่ API boundary

ApiClient อาจคืน typed decoded object หรือ raw map ให้ feature API parse ต่อ แต่ห้ามส่ง raw dynamic ถึง widget เพราะ cast error จะเกิดไกลจากต้นเหตุ

6. Content-Type guard

ถ้า proxy คืน HTML พร้อม status 200 การเช็ก Content-Type และ shape จะจับได้เร็วกว่า error type 'String' is not a subtype... ที่ไม่บอกสาเหตุ

7. แบบฝึกหัด

response 200 body เป็น [] แต่ endpoint สัญญาว่าคืน grid object ควรทำอะไร?

เฉลย

8. Test matrix

ทดสอบ valid object/list, Thai UTF-8, empty 204, empty 200, malformed JSON, wrong top-level shape และ required field ผิดชนิด
