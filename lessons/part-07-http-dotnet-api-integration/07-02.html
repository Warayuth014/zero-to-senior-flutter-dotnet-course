กติกา URL: แยก scheme, host, port, base path, API prefix และ endpoint path ให้ชัด แล้วประกอบด้วย Uri จุดเดียว

1. Anatomy

http://192.168.1.50:5000/wms/api/WMS/tasks
└─scheme └────authority────┘ └base┘└prefix┘└path┘

baseUrl ไม่ควรเปลี่ยนความหมายไปมาว่ารวม /api แล้วหรือยัง

2. ใช้ Uri แทน string query

final base = Uri.parse(profile.baseUrl);
final uri = base.replace(
  path: '${base.path}/api/WMS/tasks'.replaceAll('//', '/'),
  queryParameters: {'search': barcode, 'page': '$page'},
);

3. Normalize ที่ boundary

ตอนบันทึก connection profile ให้ trim, ตรวจ scheme/host/port และตัด trailing slash ตามกติกากลาง อย่ากระจาย endsWith('/') ทุก API method

4. Prefix คนละระบบ

API บางชุดอาจเป็น /api/WMS ขณะที่ health เป็น /api/health จึงควรให้ API class ระบุ route จาก base URL ไม่ hardcode prefix ซ้ำซ้อนใน UI

5. Encoding

Uri encode ช่องว่าง, ภาษาไทย, #, & และ barcode ที่มีอักขระพิเศษได้ถูกต้อง การต่อ ?search=$value เองเสี่ยง query แตก

6. Validate ก่อนใช้

Uri parseBaseUrl(String raw) {
  final uri = Uri.tryParse(raw.trim());
  if (uri == null || !uri.hasScheme || uri.host.isEmpty) {
    throw const FormatException('กรุณาระบุ URL เช่น http://host:5000');
  }
  return uri;
}

7. แบบฝึกหัด

base URL คือ http://10.0.2.2:5000/wms/ และ search คือ A&B 01 จงสร้าง URI ที่ไม่ทำ base path หาย

เฉลย

ใช้ Uri.replace กับ queryParameters และ normalize slash; ห้ามเอา string search ไปต่อท้ายตรง ๆ

8. จุดพลาด

Uri.resolve('/api/...') ที่ path ขึ้นต้นด้วย slash จะทิ้ง base path เดิม เช่น /wms; ต้องตั้ง contract การประกอบ path และมี unit test
