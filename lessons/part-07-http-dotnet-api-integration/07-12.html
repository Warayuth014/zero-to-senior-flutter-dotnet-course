BootstrapBlazor grid: endpoint รายการมักคืน envelope {items, totalCount} และรับ query สำหรับ page/search/sort/filter ไม่ใช่ JSON list เปล่า

1. Response contract

{
  "items": [{"taskId":"T-1","status":"OPEN"}],
  "totalCount": 137
}

items.length คือจำนวนหน้าปัจจุบัน ส่วน totalCount คือผลทั้งหมดหลัง filter

2. Grid DTO

typedef GridPage<T> = ({List<T> items, int totalCount});

GridPage<TaskDto> parseTaskPage(Map<String, dynamic> json) {
  final rows = requireList(json, 'items');
  return (items: rows.map(TaskDto.fromObject).toList(),
          totalCount: requireInt(json, 'totalCount'));
}

3. Casing compatibility

ของจริงใน api/tasks_api.dart รองรับทั้ง totalCount และ TotalCount ระหว่าง migration แต่ควร normalize จุดเดียวและมีแผนถอด fallback

4. Request shape

ตรวจว่า endpoint รับ page/pageSize, offset/limit หรือ Bootstrap query model เพราะเลข page อาจเริ่มที่ 1 หรือ 0 และ sort expression อาจมีรูปแบบเฉพาะ

5. Load all อย่างระวัง

หาก workflow ต้องโหลดทุกหน้า ให้ loop พร้อม maximum pages, cancellation, stable sort และ dedupe ด้วย ID เพื่อป้องกันข้อมูลเปลี่ยนระหว่าง paging หรือ server totalCount ผิด

6. Empty vs failure

items=[] totalCount=0 คือ success empty; wrong shape, missing items หรือ 500 ไม่ใช่ empty และต้องแสดง error state
