ไฟล์หลัก: lib/features/warehouse/workflow_definitions.dart — รวม vocabulary และ step definitions ที่ store, task views, dispatch และ history ใช้ร่วมกัน

1. สามแกนที่อย่าสับสน

TaskType บอกชนิดการเคลื่อนย้าย: putaway/retrieve/returning, TaskStatus บอกสถานะ UI/runtime และ DispatchMode บอก carrier AGV/manual ทั้งสามแกนประกอบกันได้หลายแบบ เช่น retrieve + manual + inProgress หรือ putaway + AGV + executing

2. Server status กับ UI status

taskStatusLabel รองรับทั้งชื่อและเลข enum จาก backend เช่น PENDING/0, HANDLE/11, AGV/9, COMPLETE/4 และเก็บ unknown stringไว้แสดง ไม่ควรใช้ labelแปลกลับไปตัดสิน flow; logicใช้ canonical enumsหรือ raw server statusที่ normalizeแล้ว

3. Returning แสดงเป็น Putaway

RELOCATEที่มุ่งกลับ storageใช้ execution pathต่างจาก received putaway แต่ผู้ใช้ PDAเห็นเป็น “Putaway/จัดเก็บ” เหมือนกัน taskTypeLabel จึงซ่อนความต่างระดับ implementation ขณะที่ storeยังแยก typeเพื่อเลือก endpoint completeMove แทน putaway

4. StepDef เป็น declarative metadata

แต่ละ stepมี key, English/Thai title, expected barcode fieldและ scanner label runSteps map TaskTypeไป sequence ส่วน view render panelตาม key และ storeใช้ expectเรียก WmsTask.barcodeFor ลดการเขียน step title/expected valueซ้ำสองชั้น

5. Manual state machines

putaway:  detail → scan pallet → suggest → scan location → done
retrieve: detail → scan pallet → deliver → scan destination → done
returning:detail → scan pallet → scan location → done

จำนวน stepต่างกันจึงต้องอ่าน listของ typeปัจจุบัน ไม่ hard-code index 3 ว่าเป็น destinationเสมอ

6. Navigation state อยู่ store

taskId, tStep และ WmsTask.step ทำให้ pauseแล้ว Continue ได้ goBack ลด step, exitFlow preserve, ส่วน bottom navigation reset local progressแต่ไม่ยกเลิก assignmentบน server Navigation จึงเป็น eventของ state machine ไม่ใช่แค่เปลี่ยน widget

7. Location labels เป็น presentation alias

taskLocationLabel แปลค่า logical เช่น Receiving Area/Any Available/Awaiting Storage โดยยังปล่อย rack, pointและ destination codesจริงไว้ ห้ามส่ง labelภาษาไทยกลับ endpoint; commandต้องใช้ barcode/location codeจาก modelหรือ scan

8. Definition tests

ทดสอบ server status aliasesทุกค่า, unknown fallback, type labelsสองภาษา, step keys/expectไม่ซ้ำและ doneอยู่ท้ายเสมอ จากนั้นทำ table testว่า Back/Continue/resetทำงานถูกสำหรับทุก TaskTypeและทุก step index
