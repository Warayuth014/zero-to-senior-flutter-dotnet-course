1. Query endpoint map

  • /api/taskmanage/get_task?includeReceive=true: open transport
  • get_task?includePick=true: open PICK
  • get_task_details?task_id=...: detailแรก
  • /api/data/get_history_event?...Today=true: summary/AGV/Forklift/Picking history
  • /api/data/get_locationreport: count/free locations
  • /api/WMS/mobile_destination_queues: queues + C1/C2/C3

2. Command endpoint map

mobile_dispatch / mobile_validate_robot_point
mobile_withdraw / mobile_complete_move / mobile_putaway
mobile_start_pick / mobile_pick
mobile_stage_store_in / mobile_remove_store_in / mobile_store_in

relative pathsให้ ApiClientเติม /api/WMS; shared web gridsใช้ absolute paths

3. N+1 detail enrichment

fetchOpen และ fetchPickTasks โหลด gridแล้ว await _firstDetail ทีละ event ทำให้ N tasksเป็น N+1 sequential requests Detail failureถูก catchแล้วคืน mapว่างจึงยังเห็น taskแต่ product/qtyอาจว่างโดยไม่มี error ทางแก้คือ batch endpointหรือ bounded concurrencyพร้อม partial-data indicator

4. Event→Task classification

INBOUND/RECEIVEเป็น putaway, OUTBOUNDเป็น retrieve, RELOCATEดู destination: DEST-* คือ retrieve มิฉะนั้น returning Status PENDING→pendingDispatch, HANDLE→dispatched, อื่น→executing และ modeอ่าน HANDLE/AGV/ROBOT/ASRSหรือ robot ID

5. Histories

transport history deduplicateด้วย event IDเพราะ detail joinสร้างหลาย row แล้ว sort newest ส่วน pick history group rowsต่อ task, รวม product names/codes/unitsและ sum quantity finishedToday ขอเพียงหนึ่ง rowแล้วอ่าน TotalCountเพราะ completed tasksไม่อยู่ open cache

6. Location และ destination projections

location countนับ distinct non-DEST codes, free locationsต้อง enable+idle+ไม่มี container ส่วน destination queue parserอ่าน nested queues/conveyorsพร้อม status/product/reserved location ข้อมูล physical laneจึงมาจาก server snapshotเดียว ไม่ประกอบจาก UI memory

7. Contract risks

  • PageItems 1000 ไม่มี pagination
  • row castsและ casingหลายแบบอาจ fail
  • _firstDetail กลืนทุก error
  • task IDใน queryควร URI encode
  • statusอื่นทั้งหมดถูก classify executing
  • command timeoutอาจสำเร็จฝั่ง serverแล้ว

8. Adapter test matrix

ทดสอบ URI/body/optional fieldsของทุก command, task classification aliases, N+1 partial failure, histories dedup/group/sort, location filters, queue nested parsingและ malformed/unknown status ใช้ fault injectionหลัง commitเพื่อกำหนด reconciliation/idempotencyของ dispatch, pickและ Store In
