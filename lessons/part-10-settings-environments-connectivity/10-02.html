AppConfig แยก build-time จาก runtime: --dart-define pinค่าที่ buildกำหนด ส่วน profileคือค่าที่ operatorเลือก ต้องมีกฎ precedenceจุดเดียว

1. Compile-time define

const pinnedBaseUrl = String.fromEnvironment('WMS_API_BASE_URL');
const buildEnvironment = String.fromEnvironment(
  'APP_ENV', defaultValue: 'development');
flutter run --dart-define=WMS_API_BASE_URL=https://wms.example.com

2. Precedence

String resolveBaseUrl(String? activeProfileUrl) {
  if (pinnedBaseUrl.isNotEmpty) return pinnedBaseUrl;
  if (activeProfileUrl?.isNotEmpty == true) return activeProfileUrl!;
  return defaultDevelopmentUrl;
}

3. UI เมื่อ pinned

หาก buildถูก pinควร disable/hideการเลือก serverพร้อมอธิบายค่าที่ใช้ ไม่ให้ผู้ใช้ save profileแล้วคิดว่า requestเปลี่ยนทั้งที่ overrideชนะ

4. ไม่ใช่ secret store

ค่า dart-defineถูกฝังใน artifactและ extractได้ ห้ามใส่ password, JWT signing keyหรือ API secret ใช้สำหรับ URL, flavor, feature flagที่ไม่ลับ

5. Environment labeling

แสดง DEV/UAT/PRODเด่นใน shellและใช้ app name/icon/bannerต่างเพื่อลด operatorทำงานผิดระบบ แต่ labelไม่ใช่ security proofต้องตรวจ server identityด้วย

6. One resolver

ApiClient, health dotและsettings previewต้องเรียก resolverเดียวกัน ของจริงมี commentป้องกันกรณี requestไป serverหนึ่งแต่ status probeอีก server

7. แบบฝึกหัด

build pin productionแต่ preferences active dev; probeควรยิงที่ไหน?

เฉลย

productionตาม resolverเดียวกับ request และ UIต้องบอกว่า build overrideกำลังใช้งาน

8. CI contract

แต่ละ flavor/buildระบุ definesชัด, validate URLตอน build/startup, ไม่ commit secretและมี smoke testว่า request/probe resolve URLเดียวกัน
