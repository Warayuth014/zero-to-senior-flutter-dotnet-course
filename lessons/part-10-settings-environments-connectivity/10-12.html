Shell network status เป็น observed state—not guarantee: แสดงผล probeล่าสุดและเวลา ไม่สรุปว่าทุก requestถัดไปสำเร็จ

1. States

  • unknown: ยังไม่ตรวจ
  • checking: กำลัง probe
  • online: WMS markerถูก ณ เวลาหนึ่ง
  • offline: typed failureพร้อม message
  • stale: ผลเก่าเกิน threshold

2. UI

ใช้ dot+icon+text/tooltip เช่น “WMS online · 12s ago” และ tapเปิดรายละเอียด server resolved URL, environment, latency, versionและปุ่ม retry

3. Refresh triggers

startupหลัง profiles load, app resume, active profile change, user retryและ periodic intervalที่เหมาะสม หยุด timerเมื่อ disposed/backgroundตาม policy

4. Avoid probe storms

single-flight/debounce refreshและไม่ให้ทุก widgetสร้าง timerเอง Shell/controllerเป็น ownerเดียว ใช้ backoffเมื่อ offlineเพื่อไม่เพิ่ม load/battery

5. Request feedback

ApiClient failureอาจ mark status suspect/offlineและ schedule probe แต่ 400/403ไม่ใช่ connectivity failure; success requestอาจ update last-seenโดยไม่แทน identity probeทั้งหมด

6. Active parity

Status cardต้องแสดง resolved URLจริงรวม dart-define override ไม่ใช่ selected profileที่ถูก override และเมื่อ switchให้ phaseกลับ unknown/checkingทันที

7. แบบฝึกหัด

dotเขียวจาก 5 นาทีที่แล้วแต่ requestล่าสุด timeoutควรทำอะไร?

เฉลย

mark stale/suspectหรือ offlineตาม policyและ probeใหม่ แสดง timestampเพื่อไม่ทำให้ operatorเชื่อว่า greenเป็น guaranteeปัจจุบัน

8. Tests

state rendering, stale timeด้วย fake clock, resume, timer dispose, profile switch, overlapping refreshและ non-network API errorไม่ทำ dotแดง
