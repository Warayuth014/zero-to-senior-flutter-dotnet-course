Validate สองระดับ: syntaxก่อนบันทึกและ connectivity/identityด้วย probe การ probeไม่แทน validationและ server offlineไม่จำเป็นต้องห้าม saveเสมอไป

1. Raw form validation

validate name, host, port text, protocolและ base pathก่อนสร้าง model เพราะ portยังอาจเป็น stringที่ parseไม่ได้ จึงแยก ConnectionValidation จาก Profile

2. Host rules

  • ไม่ว่าง/ไม่มี whitespace
  • ถ้า formแยก fieldห้ามมี scheme/path/port
  • รองรับ IP/DNSตาม product
  • reject credentials user@host, queryและfragment

3. Port/path rules

port 1–65535; base pathว่างหรือขึ้นต้น slashหลัง normalizeและห้าม .., query, fragmentหรือ API prefixที่ appเติมเอง

4. Save vs Test

ปุ่ม Testใช้ draft URLโดยไม่เปลี่ยน active/persist ส่วน Saveอาจยอม offline profileพร้อม warningตาม operational need; Save & Useต้อง confirmหาก probeไม่ผ่าน

5. TLS

HTTPS URL syntaxถูกไม่ได้แปล certificate trusted Probeต้องรายงาน TLS/certificateต่างจาก unreachable อย่าเพิ่ม global bypass certificateเพื่อให้ผ่าน

6. Duplicate names

case-insensitive trim compareและเสนอ overwrite/save-copy/cancelโดยรักษา ID semantics ห้าม replace profileผิดตัวด้วย name collisionเงียบ ๆ

7. แบบฝึกหัด

ผู้ใช้ใส่ host http://10.0.0.5:5000/api ในช่อง host ควร auto-splitไหม?

แนวคำตอบ

สำหรับ formแยก fieldควรแจ้ง actionable errorหรือนำเข้าอย่าง explicitพร้อม preview ไม่แก้เงียบจน base path/API prefixผิด

8. Test table

empty, schemeปน, slash/space, IPv4/DNS/IPv6, portขอบเขต, base path traversal, duplicate nameและ offline-but-save policy
