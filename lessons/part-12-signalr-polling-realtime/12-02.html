.NET Hub เป็น realtime transport boundary: endpointทำ business transactionก่อน แล้ว broadcast typed eventหลัง commitให้ group/userที่เกี่ยวข้อง ไม่ให้ clientเรียก hubแทน authorization/domain serviceโดยตรง

1. Hub skeleton

builder.Services.AddSignalR();
app.MapHub<TaskHub>("/hubs/tasks");

public sealed class TaskHub : Hub
{
    public Task JoinWarehouse(string warehouseId) =>
        Groups.AddToGroupAsync(Context.ConnectionId, $"wh:{warehouseId}");
}

2. Typed contract

public record TaskStatusChanged(
    string EventId, string TaskId, string Status,
    long Version, DateTimeOffset OccurredAt);

await hub.Clients.Group($"wh:{warehouseId}")

3. Broadcast after commit

ถ้าส่ง eventก่อน DB commitแล้ว transaction rollback clientจะเห็น stateที่ไม่เคยจริง ใช้ post-commit/outboxเมื่อ reliabilityสำคัญและ eventมาจากหลาย process

4. Groups

ส่งเฉพาะ warehouse/user/taskที่เกี่ยวข้องเพื่อลด data leakและtraffic Group membershipต้องตรวจ claims/policy ไม่เชื่อ warehouseIdจาก clientโดยลำพัง

5. Authentication

Hubใช้ auth/policiesเหมือน API Access tokenต้องถูกแนบตาม client library/transportและ refresh/reconnect policy ห้ามใส่ tokenใน log

6. Scale-out

หลาย .NET instancesต้องมี backplane/serviceเพื่อส่ง eventข้าม instanceและ sticky/transport configตาม hosting architecture ส่วนรายละเอียด backendอ่านต่อในคอร์ส .NET

7. แบบฝึกหัด

client Aเปลี่ยน taskแล้วควร broadcastจาก controllerหรือหลัง service save?

เฉลย

หลัง transaction commitใน application/integration boundary; ใช้ outboxถ้าต้องรับประกันไม่สูญ eventระหว่าง DB commitกับ publish

8. Contract rules

event name stable, payload versioned/typed, eventId/entity version/occurredAt, authorization/groupชัด และไม่มี secret/full entityเกินจำเป็น
