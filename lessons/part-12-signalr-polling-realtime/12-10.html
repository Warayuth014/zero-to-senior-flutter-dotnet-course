1. Race timeline

t1 GET tasks เริ่ม (snapshot version 10)
t2 SignalR task T → COMPLETED version 11
t3 GET v10 กลับมาและเขียน T = OPEN  ← ย้อนเวลา

2. Entity version

void apply(TaskChanged event) {
  final current = tasks[event.taskId];
  if (current != null && event.version <= current.version) return;
  tasks[event.taskId] = current!.apply(event);
}

3. Snapshot version

APIควรคืน asOfVersion/updatedAtหรือ ETag ถ้าไม่มี Storeใช้ request generationและ event queue: eventsที่มาระหว่าง loadถูก replayหลัง snapshot

4. Invalidation pattern

ง่ายและปลอดภัย: eventไม่ patch detailแต่ debounce refresh() หลาย eventsเป็นหนึ่ง GET พร้อม single-flightและ trailing refreshหาก eventมาระหว่าง load

5. Optimistic command

eventอาจ echo commandของเครื่องเอง ใช้ command/event IDและ version dedupe ไม่แสดง successสองครั้งหรือ rollback optimistic stateจาก eventเก่า

6. Multiple devices

serverเป็น authority; conflict eventควรยุติ local flowหรือ refresh entityและแจ้งผู้ใช้ ไม่ assumeว่า event orderจากหลาย producersคงที่ทั่วระบบถ้า contractไม่รับประกัน
