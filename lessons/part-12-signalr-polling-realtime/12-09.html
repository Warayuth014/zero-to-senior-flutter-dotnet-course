Singleton connectionแชร์ transport ไม่แชร์ UI state: service app/session-scopedถือ hubและ subscriptions แต่แต่ละ Storeถือ feature state/filtersของตน

1. Why one connection

ลด sockets/auth/reconnect stormsและรับ eventsร่วม แต่ singleton globalทำ tests/server switchยากถ้าไม่มี interface/reset/lifecycleชัด

2. Lease model

RealtimeLease acquire() {
  final id = ++_nextLease;
  _leases.add(id);
  unawaited(_ensureConnected());
  return Lease(() => _release(id));
}

release idempotentและ stopเมื่อไม่มี leasesตาม keep-alive policy

3. Ref-count pitfalls

เพิ่ม countทุก connect() แม้ callerเดิมเรียกซ้ำ, connect throwแต่ countค้าง, disconnectเกินศูนย์และ nested sheetฟังโดยไม่ acquireทำ connectionหยุดผิดเวลา

4. Session boundary

singletonต้อง resetเมื่อ logout/token/server realmเปลี่ยน: stop, clear handlers/groups/queued events, increment generationและห้าม reconnectด้วย tokenเดิม

5. Per-feature channels

แยก Task/Sorting/Putaway facadeได้แม้ใช้ underlying connectionเดียว เพื่อ typed event contractsและไม่ให้ screenเห็น listenersทุกโดเมน

6. Testing seam

inject RealtimeClient interface/fakeแทนเรียก singleton constructorใน Store; composition rootใช้ shared production instance

7. แบบฝึกหัด

ควรเปิด hubตั้งแต่ loginตลอด sessionหรือเฉพาะ screen?

แนวคำตอบ

ขึ้นกับ events/latency/battery ถ้า badgeทั้ง shellต้องสดอาจ session-scoped; ถ้า featureเฉพาะใช้ leasesและหยุดเมื่อไม่มี consumer

8. Invariants

หนึ่ง active realm/connection, lease/subscription idempotent, UI stateไม่อยู่ singleton, logout resetครบและ fakeทดสอบได้
