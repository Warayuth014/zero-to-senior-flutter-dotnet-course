Disposeต้องยกเลิกทั้ง listenerและทรัพยากร: remove/cancel subscriptionก่อน release connection lease, cancel timer/debounceและ invalidate async generation

1. Correct order

@override
void dispose() {
  _subscription.cancel();
  _debounce?.cancel();
  store.releaseRealtimeLease();
  super.dispose();
}

2. Why unsubscribe first

ระหว่าง async stop connectionอาจยังส่ง event ถ้าปล่อย leaseก่อน remove listener disposed widgetอาจถูก callbackและ setState after dispose

3. Async dispose

Flutter disposeเป็น voidจึงเรียก stopแบบ unawaitedผ่าน owner/serviceที่ idempotentและจับ errorเอง ห้าม async disposeที่ frameworkไม่รอ

4. mounted is last guard

if (!mounted) return ป้องกัน crashแต่ไม่แก้ listener leak เพราะ callbackยังเก็บ Stateใน memoryและทำ parse/networkซ้ำ ต้อง unsubscribeจริง

5. App lifecycle observer

ถ้า add WidgetsBinding.instance.addObserver(this) ต้อง removeObserverใน disposeและหยุด/ลด pollingตอน pausedตาม policy

6. Ref-count balance

connect/releaseทุก consumerต้องสมดุลแม้ connect failหรือ initถูกเรียกซ้ำ Lease objectที่ cancelครั้งเดียวปลอดภัยกว่าตัวเลข refCountที่ callerจัดเอง

7. แบบฝึกหัด

หน้าหลักกับ bottom sheetใช้ connectionเดียวกัน sheetปิดควร stop hubไหม?

เฉลย

ยกเลิก listener/leaseของ sheet; connectionหยุดเฉพาะเมื่อ owner/leaseสุดท้ายหมด ไม่ stopจนหน้าหลักขาด realtime

8. Leak tests

push/popซ้ำ, open/close sheet, connect failure, cancelสองครั้ง, eventระหว่าง stopและตรวจ listener/ref countกลับ baseline
