HubConnectionBuilder: สร้าง URLจาก resolved server/base pathเดียวกับ ApiClient แนบ token provider และ register handlersก่อน startเพื่อไม่พลาด eventแรก

1. Build

final hubUrl = '$resolvedBaseUrl/hubs/tasks';
final connection = HubConnectionBuilder()
    .withUrl(hubUrl /*, options: token transport config */)
    .withAutomaticReconnect()
    .build();

connection.on('TaskStatusChanged', onTaskStatusChanged);
await connection.start();

2. URL parity

ห้ามต่อจาก hardcoded hostที่ต่างจาก connection profile/API Hub routeอาจอยู่หลัง reverse-proxy base pathและ server switchต้อง rebuild connection

3. Token freshness

ถ้า libraryรองรับ access token factoryให้ดึง tokenล่าสุดตอน connect/reconnect ไม่ capture tokenเก่าใน constructor หลัง logoutต้อง stopก่อน clear/rebuild

4. Handler registration

registerชื่อ event exact case/contractก่อน startและเก็บ handler referenceสำหรับ off/removeภายหลัง ห้ามสร้าง anonymous closureใหม่ตอน unsubscribe

5. Connection state

expose disconnected/connecting/connected/reconnectingให้ Store/Shellแสดงสถานะและตัดสิน fallback ไม่ให้ screenเดาว่ามี connectionจาก object != null

6. Error propagation

อย่า catch connect errorแล้ว logอย่างเดียวจน UIคิดว่า realtimeทำงาน ให้ serviceคืน/notify typed stateและเริ่ม fallback pollingตาม policy

7. แบบฝึกหัด

profileเปลี่ยนจาก Aเป็น Bแต่ singleton connectionยัง connectedที่ Aควรทำอะไร?

เฉลย

เพิ่ม realm generation, stop A, clear subscriptions/server-scoped state, build URL B, start+resubscribeและ HTTP reconcile ห้ามส่ง token Aไป B

8. Tests

resolved hub URL/base path, handlerก่อน start, connect failure state, token redaction, server switchและ duplicate startไม่สร้างสอง connections
