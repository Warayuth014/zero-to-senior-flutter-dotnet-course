APK กับ AAB ใช้คนละงาน: APK ติดตั้งตรงบน device ได้ ส่วน App Bundle เป็น publishing artifact ที่ store ใช้สร้าง APK ที่เหมาะกับอุปกรณ์ ต้องทดสอบ artifact/distribution path เดียวกับของจริง

1. Build commands

flutter clean
flutter pub get
flutter analyze
flutter test
flutter build apk --release
flutter build appbundle --release

release pipeline ควร pin Flutter/Dart และ dependencies จาก lockfile ไม่ upgrade ระหว่าง build

2. APK variants

universal APK สะดวก sideload แต่ใหญ่; split-per-abi ลดขนาดต่อ architectureแต่ต้องส่งไฟล์ถูกเครื่อง ในองค์กรใช้ MDM/private distribution และ checksum/version inventory ที่ตรวจสอบได้

3. App Bundle

flutter build appbundle --release \
  --build-name=1.4.0 --build-number=142 \
  --dart-define=APP_ENV=production

AAB ไม่ติดตั้งตรงเหมือน APK ใช้ store/internal testingหรือ bundletool สร้างชุด APK เพื่อทดสอบ delivery behavior

4. Reproducible input

บันทึก commit SHA, Flutter version, lockfile hash, build command, flavor, environment config และ runner image Artifact ต้องมาจาก clean checkout ไม่พึ่ง local.properties หรือไฟล์ลับบนเครื่องนักพัฒนา

5. Size analysis

flutter build appbundle --release --analyze-size

ดู assets/font/native libraries ที่ใหญ่ผิดปกติและ license ไม่ลบ asset โดยเดาจน runtime หาย ทดสอบ tree shaking/icons กับ route ที่ใช้งานจริง

6. Install/upgrade rehearsal

ติดตั้งใหม่, upgrade จากสองเวอร์ชันก่อนหน้า, retain settings/session ตาม policy, local schema migration, permissions ที่เคย deny และ rollback plan ใช้ release-signed buildบน PDA รุ่นจริง

7. Artifact integrity

เก็บ SHA-256, SBOM/dependency inventory, signature verification และ provenance ใน release record จำกัด retention/สิทธิ์ download และไม่ส่ง artifact ผ่าน chat ที่ไม่มี audit

8. Smoke test

เปิดแอป → endpoint/status → login → scan receiving/picking → image/SignalR → background/resume → logout บน network production-like โดยไม่ใช้ debug bridge แล้ว approve artifact เดิมเท่านั้น
