1. หลักข้อเดียว

ทุกอย่างที่อยู่ในแอป ถือว่าคนอื่นอ่านได้ — APK คือไฟล์บีบอัดที่แกะดูได้ในสามคำสั่ง และการทำให้อ่านยากขึ้นไม่ได้ทำให้อ่านไม่ได้
unzip -o app-release.apk -d extracted/
strings extracted/lib/arm64-v8a/libapp.so | grep -i "password\|secret\|key"
สิ่งที่หลายคนคิดว่าปลอดภัยความจริง
ใส่ใน --dart-defineค่าถูกฝังในไฟล์ที่แจกออกไป
เข้ารหัสไว้ในโค้ดกุญแจถอดรหัสก็อยู่ในโค้ดด้วย
เปิด obfuscationชื่อฟังก์ชันหายไป แต่ค่าคงที่ยังอยู่
เก็บใน asset ที่เข้ารหัสเหมือนข้อสอง

2. อะไรเก็บได้ อะไรเก็บไม่ได้

เก็บในแอปได้เพราะ
ที่อยู่เซิร์ฟเวอร์คนที่อยู่ในเครือข่ายก็รู้อยู่แล้ว
ชื่อ endpointดูจากคำขอที่วิ่งก็เห็น
รหัสสาขา ชื่อสถานีไม่ใช่ความลับ
กุญแจสาธารณะสำหรับตรวจลายเซ็นออกแบบมาให้เปิดเผย
เก็บในแอปไม่ได้ควรอยู่ที่ไหน
รหัสผ่านฐานข้อมูลเซิร์ฟเวอร์เท่านั้น
API key ของบริการภายนอกเซิร์ฟเวอร์เป็นตัวกลางเรียกให้
กุญแจเซ็นแอปที่เก็บความลับ (15.5)
รหัสผ่านของผู้ใช้ไม่เก็บที่ไหนเลย (8.1)
token ที่ไม่หมดอายุอย่ามีตั้งแต่แรก

แถวที่สองเป็นรูปแบบที่ใช้ได้กับความลับเกือบทุกชนิด — ถ้าแอปต้องใช้ความลับ ให้เซิร์ฟเวอร์ใช้แทน

// อย่าทำ — API key อยู่ในแอป
final response = await http.get(Uri.parse(
  'https://maps.example.com/geocode?key=$mapsApiKey&q=$address',
));

// ทำ — เซิร์ฟเวอร์ถือ key แล้วเรียกให้
final response = await api.getJson('/api/WMS/geocode?q=$address');

3. --dart-define ไม่ใช่ที่เก็บความลับ

10.2 พูดถึงเรื่องนี้ไปแล้ว และตรงนี้คือหลักฐาน

flutter build apk --release --dart-define=API_KEY=sk_live_abc123
unzip -p app-release.apk lib/arm64-v8a/libapp.so | strings | grep sk_live
sk_live_abc123

ค่าอยู่ในไฟล์ตรง ๆ สิ่งที่ --dart-define ให้คือความสะดวกในการตั้งค่าต่อ build ไม่ใช่ความปลอดภัย

ใช้ --dart-define กับไม่ใช้กับ
ที่อยู่เซิร์ฟเวอร์ของแต่ละลูกค้าAPI key
เปิดปิดฟีเจอร์รหัสผ่าน
ระบุว่าเป็น build ของ dev หรือ prodอะไรก็ตามที่ถ้าหลุดแล้วเสียหาย

4. ความลับที่หลุดเข้า git

เป็นทางที่พบบ่อยที่สุด และแก้ยากที่สุดเพราะประวัติ git เก็บทุกอย่างไว้

# ค้นในประวัติทั้งหมด ไม่ใช่แค่ไฟล์ปัจจุบัน
git log -p --all | grep -iE "password|secret|api[_-]?key|BEGIN.*PRIVATE"

# หาไฟล์ที่ไม่ควรอยู่
git log --all --name-only --format="" | sort -u | grep -iE "\.jks$|\.keystore$|key\.properties|\.env$"
ถ้าพบต้องทำ
รหัสผ่านหรือ key ที่ยังใช้อยู่เปลี่ยนค่านั้นทันที — การลบ commit ไม่ช่วยถ้ามีคน clone ไปแล้ว
ไฟล์ keystoreสร้างกุญแจใหม่ ถ้ายังไม่ได้ปล่อยรุ่นแรก
ค่าที่เลิกใช้แล้วเพิ่มใน .gitignore แล้วบันทึกไว้
ลำดับสำคัญ — เปลี่ยนค่าก่อน แล้วค่อยคิดเรื่องลบประวัติ เพราะการลบประวัติใช้เวลาและอาจทำไม่สำเร็จ ส่วนการเปลี่ยนค่าทำให้สิ่งที่หลุดไปแล้วไร้ประโยชน์ทันที
# .gitignore ที่ควรมีตั้งแต่วันแรก
android/key.properties
*.jks
*.keystore
.env
**/google-services.json
ios/Runner/GoogleService-Info.plist

5. ความลับที่หลุดเข้า log และรายงานข้อผิดพลาด

7.17 จัดการเรื่อง log ไปแล้ว ส่วน 15.10 จะจัดการรายงานข้อผิดพลาด ตรงนี้คือจุดที่ทั้งสองต้องใช้กฎเดียวกัน

/// รายชื่อนี้ต้องตรงกับที่ 7.17 ใช้กับ log — ถ้าสองที่ไม่ตรงกัน จะมีทาง
/// หนึ่งที่ปิดไว้และอีกทางที่เปิดอยู่
const Set<String> sensitiveKeys = {
  'token', 'accesstoken', 'refreshtoken', 'authorization',
  'password', 'pwd', 'secret', 'apikey', 'pin',
};

lab มีเทสต์ที่จับกรณีที่ตัวปิดค่าทำงานไม่จริง ซึ่งเป็นบั๊กที่อันตรายกว่าไม่มีตัวปิดเลย เพราะทุกคนคิดว่าปิดแล้ว

test('Bearer token ต้องถูกปิด', () {
  const text = 'headers: {Authorization: Bearer eyJhbGciOi.J9.abc}';
  expect(redact(text), isNot(contains('eyJhbGciOi')));
});

เทสต์นี้ล้มตอนเขียนครั้งแรก เพราะลูปที่ปิดค่าตามชื่อคีย์เจอ Authorization: Bearer ก่อน แล้วปิดคำว่า Bearer ทิ้ง — ปล่อย token จริงไว้ทั้งอัน

String redact(String text) {
  // Bearer ต้องมาก่อนเสมอ — ถ้าปล่อยให้ลูปข้างล่างเจอ `Authorization: Bearer`
  // ก่อน มันจะปิดคำว่า "Bearer" แล้วปล่อย token จริงไว้ ซึ่งเป็นการปิดที่
  // ดูเหมือนทำงานแต่ไม่ได้ปิดอะไรเลย
  var result = text.replaceAll(
    RegExp(r'Bearer\s+[A-Za-z0-9._\-]+', caseSensitive: false),
    'Bearer $_masked',
  );
  ...
}
บทเรียนที่ใหญ่กว่าโค้ด — ตัวปิดค่าทุกตัวต้องมีเทสต์ที่ยืนยันว่ามันปิดจริง เพราะข้อผิดพลาดที่นี่ไม่มีอาการอะไรให้เห็นเลย จนกว่าจะมีคนไปอ่าน log แล้วเจอ token

6. obfuscation ทำอะไรและไม่ทำอะไร

flutter build apk --release --obfuscate --split-debug-info=build/symbols
ทำไม่ทำ
เปลี่ยนชื่อคลาสและฟังก์ชันเป็นตัวอักษรสั้นซ่อนค่าคงที่ที่เป็นข้อความ
ทำให้อ่านโครงโปรแกรมยากขึ้นทำให้ถอดรหัสไม่ได้
ลดขนาดไฟล์เล็กน้อยป้องกันการแกะ

--split-debug-info จำเป็นคู่กัน เพราะมันเก็บตารางแปลชื่อกลับไว้ให้ — ถ้าไม่มี รายงานข้อผิดพลาดจะอ่านไม่ออกเลย

# แปล stack trace ที่ถูก obfuscate กลับ
flutter symbolize -i crash.txt -d build/symbols/app.android-arm64.symbols
ต้องเก็บไฟล์ symbols ของทุกรุ่นที่ปล่อย — ถ้าหาย รายงานข้อผิดพลาดจากรุ่นนั้นจะกลายเป็นตัวอักษรสุ่มตลอดไป

7. สิ่งที่ทำได้จริงแทนการซ่อน

แทนที่จะให้
ซ่อน API key ในแอปให้เซิร์ฟเวอร์เรียกแทน
ทำให้ token ยาวจนเดายากให้มันหมดอายุสั้น (8.3)
ซ่อนว่ามี endpoint ไหนบ้างให้เซิร์ฟเวอร์ตรวจสิทธิ์ทุกคำขอ (8.9)
ซ่อนตรรกะการตรวจสอบให้เซิร์ฟเวอร์ตรวจซ้ำ (13.9)

ทุกแถวมีรูปแบบเดียวกัน — ย้ายสิ่งที่ต้องเชื่อถือได้ไปอยู่ที่ที่เราควบคุมได้ ซึ่งคือเซิร์ฟเวอร์ ไม่ใช่เครื่องที่อยู่ในมือผู้ใช้

และเมื่อยอมรับว่าแอปเป็นสิ่งที่คนอื่นอ่านได้ การออกแบบจะง่ายขึ้นมาก เพราะไม่ต้องเสียเวลากับการซ่อนที่ไม่ได้ผล

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
API key หลุดใส่ใน --dart-define หรือในโค้ดย้ายไปเซิร์ฟเวอร์ แล้วเปลี่ยน key
keystore อยู่ในประวัติ gitcommit ก่อนใส่ .gitignoreสร้างกุญแจใหม่ถ้ายังไม่ปล่อย
token โผล่ใน logตัวปิดค่าไม่ได้ปิดจริงเขียนเทสต์ยืนยัน
รายงานข้อผิดพลาดอ่านไม่ออกobfuscate โดยไม่เก็บ symbolsเก็บทุกรุ่น
คิดว่า obfuscation ป้องกันการแกะเข้าใจผิดย้ายความลับออกจากแอป
เปลี่ยนค่าที่หลุดช้าเกินไปมัวลบประวัติ git ก่อนเปลี่ยนค่าก่อนเสมอ

9. แบบฝึกหัด

ทีมจะเพิ่มฟีเจอร์ส่งข้อความแจ้งเตือนผ่านบริการภายนอก ซึ่งต้องใช้ API key

  1. เก็บ key ไว้ที่ไหน
  2. ถ้าทีมหลังบ้านบอกว่าทำให้ไม่ได้ในรุ่นนี้ล่ะ
แนวคำตอบ

1. บนเซิร์ฟเวอร์ และแอปเรียกผ่าน endpoint ของเราเอง

// แอปไม่รู้จัก key เลย
await api.postJson('/api/WMS/mobile_notify', {
  'recipient': supervisorId,
  'message': 'จุดคัดแยก ST-01 เต็ม',
});
ได้อะไรเพิ่มนอกจากความปลอดภัย
เปลี่ยนผู้ให้บริการได้โดยไม่ต้องอัปเดตแอปทุกเครื่อง
จำกัดจำนวนการส่งต่อผู้ใช้ได้
บันทึกได้ว่าใครส่งอะไรไปหาใคร
ตรวจสิทธิ์ได้ว่าคนนี้ส่งหาคนนั้นได้ไหม (8.9)

2. ถ้าฝั่งเซิร์ฟเวอร์ทำไม่ทัน มีสามทาง และสองทางแรกผิด

ทางผล
ใส่ key ในแอปไปก่อน แล้วย้ายทีหลังอย่าทำ — key ที่ปล่อยไปแล้วถือว่าหลุด ต้องเปลี่ยนอยู่ดี และ “ทีหลัง” มักไม่มา
ใส่ key แล้ว obfuscateเหมือนข้อแรกแต่หลอกตัวเอง
เลื่อนฟีเจอร์ออกไปถูก

ทางที่สามฟังดูเหมือนไม่ได้แก้อะไร แต่เป็นคำตอบที่ถูก เพราะฟีเจอร์นี้ทำไม่ได้อย่างปลอดภัยถ้าไม่มีฝั่งเซิร์ฟเวอร์ และการทำแบบไม่ปลอดภัยไปก่อนคือการสร้างงานให้ตัวเองสองรอบ

สิ่งที่ควรทำคือหาว่างานฝั่งเซิร์ฟเวอร์เล็กแค่ไหนจริง ๆ

// ฝั่ง server (แนวคิด — รายละเอียดอยู่ในคอร์ส .NET)
[HttpPost("mobile_notify")]
public async Task<IActionResult> Notify([FromBody] NotifyRequest request)
{
    // ตรวจสิทธิ์ แล้วส่งต่อด้วย key ที่เก็บใน configuration
    await _notifier.SendAsync(request.Recipient, request.Message);
    return Ok();
}

สิบบรรทัด — บ่อยครั้งที่ “ทำไม่ทัน” มาจากการที่ยังไม่มีใครประเมินว่างานเล็กแค่ไหน มากกว่ามาจากงานที่ใหญ่จริง

ถ้าประเมินแล้วยังไม่ทันจริง ให้เลื่อนฟีเจอร์ — และบันทึกเหตุผลไว้ เพื่อไม่ให้กลายเป็นการถกเถียงซ้ำในรุ่นถัดไป

10. สรุป

  • ทุกอย่างในแอปถือว่าคนอื่นอ่านได้
  • --dart-define และ obfuscation ไม่ใช่ที่เก็บความลับ
  • ถ้าแอปต้องใช้ความลับ ให้เซิร์ฟเวอร์ใช้แทน
  • ความลับที่หลุดเข้า git ต้องเปลี่ยนค่าก่อน แล้วค่อยคิดเรื่องลบประวัติ
  • ตัวปิดค่าใน log ต้องมีเทสต์ยืนยันว่าปิดจริง
  • เก็บไฟล์ symbols ของทุกรุ่นที่ปล่อย

บทหน้า: รูปแบบไฟล์ที่จะส่งออกไป
