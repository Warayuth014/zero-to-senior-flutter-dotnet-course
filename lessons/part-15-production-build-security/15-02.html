Version มีสองมิติ: build name สำหรับผู้ใช้ เช่น 1.4.0 และ build number ที่ต้องเพิ่มทุก artifact ที่แจก เช่น 142 ทั้งสองโปรเจกต์ปัจจุบันยังเป็น 1.0.0+1

1. pubspec mapping

version: 1.4.0+142

// Android: versionName 1.4.0, versionCode 142
// iOS: CFBundleShortVersionString 1.4.0, CFBundleVersion 142

2. Override ใน CI

flutter build appbundle --release \
  --build-name=1.4.0 \
  --build-number=142

มี source of truth เดียวใน release pipeline อย่าให้ pubspec, Gradle และ Xcode เพิ่มเลขคนละทาง

3. SemVer กับ migration

major/minor/patch สื่อความเข้ากันได้กับผู้ใช้/ทีม แต่ฐานข้อมูล local, queued commands และ API contract ต้องใช้ schema/version ของตนเอง การอัปแอปไม่ควรล้าง draft โดยไม่รู้ตัว

4. Build number monotonic

ทุก upload ไป distribution channel ต้องใช้เลขสูงขึ้น แม้ build name เท่าเดิม ใช้ CI run number ที่ไม่ย้อนเมื่อย้าย branch/pipeline หรือระบบ version service กลาง

5. แสดงในแอป

หน้า About/Settings ควรแสดง 1.4.0 (142), environment แบบไม่ลับ, API host ที่ sanitize และ Git short SHA/support ID ช่วย support ระบุ artifact โดยไม่ขอ screenshot หลายหน้า

6. Compatibility gate

{
  "minimumAppVersion": "1.3.0",
  "recommendedAppVersion": "1.4.0",
  "apiContractVersion": 3
}

server อาจ soft-warn หรือ block เวอร์ชันเก่าอย่างมีข้อความ/ทางอัปเดต ไม่เดาจาก version string ใน client อย่างเดียว

7. Release notes

ผูก tag เช่น v1.4.0+142 กับ commit, artifact checksum, migration, API minimum และ known issues ห้าม tag ก่อน test แล้ว rebuild หลัง tagโดยไม่มี trace

8. Tests

ติดตั้งทับเวอร์ชันก่อนหน้า, upgrade local schema/queued work, downgrade policy, first install, server compatibility และ About screen แสดงเลขตรง artifact จริง
