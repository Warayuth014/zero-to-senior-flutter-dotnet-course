1. การเซ็นแอปคืออะไร

ทุก APK ต้องถูกเซ็นด้วยกุญแจ Android ใช้ลายเซ็นนี้ตอบคำถามเดียว — “แอปที่จะติดตั้งทับ มาจากคนเดียวกับที่ติดตั้งไว้เดิมไหม”
ลายเซ็นตรงกันลายเซ็นไม่ตรง
ติดตั้งทับได้ ข้อมูลในเครื่องยังอยู่ติดตั้งทับไม่ได้เลย
—ต้องถอนแล้วติดตั้งใหม่ ซึ่งลบข้อมูลทั้งหมด

ในคลัง การถอนแล้วติดตั้งใหม่แปลว่า profile เซิร์ฟเวอร์ทุกตัวหาย (Part 10) และช่างต้องพิมพ์ที่อยู่ใหม่ทีละเครื่อง

2. กุญแจ debug ที่แม่แบบตั้งให้

// android/app/build.gradle.kts ที่ Flutter สร้างมา
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        // Signing with the debug keys for now, so `flutter run --release` works.
        signingConfig = signingConfigs.getByName("debug")
    }
}

บรรทัดนี้อยู่ในทั้ง wmsapp และ wms_absolute_mobile ณ ตอนนี้ — เป็นค่าที่แม่แบบตั้งไว้ให้ทดลองได้เลย ไม่ใช่ค่าที่ตั้งใจ

ผลของการเซ็นด้วยกุญแจ debug
ทุกเครื่องที่ติดตั้ง Android SDK มีกุญแจนี้เหมือนกัน — ใครก็สร้าง APK ที่ติดตั้งทับได้
Play Store ปฏิเสธ
กุญแจหมดอายุใน 365 วัน แล้วสร้างใหม่จะได้ลายเซ็นคนละอัน
องค์กรที่ตรวจแอปก่อนติดตั้ง จะเห็นว่าเซ็นด้วยกุญแจ debug

แถวแรกคือความเสี่ยงจริง — คนที่เข้าถึงเครื่อง PDA ได้ สามารถติดตั้งแอปที่หน้าตาเหมือนกันแต่ส่งข้อมูลไปที่อื่นทับได้ โดยที่ผู้ใช้ไม่มีทางสังเกต

test('เซ็นด้วยกุญแจ debug ต้องขวางการปล่อย', () {
  final gradle = goodGradle.replaceAll(
    'signingConfigs.getByName("release")',
    'signingConfigs.getByName("debug")',
  );

  final findings = checkAndroidGradle(gradle);
  expect(findings.single.code, 'debug-signing');
  expect(findings.single.isBlocker, isTrue);
});

3. สร้างกุญแจของตัวเอง

keytool -genkey -v \
  -keystore ~/keys/acetec-wms.jks \
  -keyalg RSA -keysize 2048 \
  -validity 10000 \
  -alias acetec-wms
พารามิเตอร์ความหมาย
-validity 10000อายุเป็นวัน — ราว 27 ปี ควรตั้งยาวเพราะกุญแจหมดอายุแล้วปล่อยรุ่นใหม่ไม่ได้
-aliasชื่อของกุญแจในไฟล์ ซึ่งเก็บได้หลายอัน
-keysize 2048ขนาดกุญแจ — 2048 พอสำหรับการใช้งานทั่วไป
กุญแจนี้ทดแทนไม่ได้ — ถ้าหาย หรือลืมรหัสผ่าน จะปล่อยรุ่นใหม่ที่ติดตั้งทับของเดิมไม่ได้อีกเลย ทางเดียวคือให้ทุกเครื่องถอนแล้วติดตั้งใหม่

4. ต่อกับ Gradle โดยไม่ให้กุญแจเข้า git

# android/key.properties — ไฟล์นี้ต้องอยู่ใน .gitignore
storeFile=/Users/dev/keys/acetec-wms.jks
storePassword=...
keyAlias=acetec-wms
keyPassword=...
// android/app/build.gradle.kts
import java.util.Properties

val keystoreProperties = Properties().apply {
    val file = rootProject.file("key.properties")
    if (file.exists()) load(file.inputStream())
}

android {
    signingConfigs {
        create("release") {
            keyAlias = keystoreProperties["keyAlias"] as String?
            keyPassword = keystoreProperties["keyPassword"] as String?
            storeFile = keystoreProperties["storeFile"]?.let { file(it) }
            storePassword = keystoreProperties["storePassword"] as String?
        }
    }

    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
# .gitignore
android/key.properties
*.jks
*.keystore
if (file.exists()) สำคัญ — ทำให้คนที่ยังไม่มีกุญแจยัง flutter build apk --debug ได้ ไม่ใช่คอมไพล์ไม่ผ่านทั้งโปรเจกต์

5. เก็บกุญแจไว้ที่ไหน

ที่เหมาะไหม
เครื่องของนักพัฒนาคนเดียวไม่ — คนนั้นลาออกหรือเครื่องพังแล้วจบ
ใน gitไม่ — ใครที่โคลนได้ก็เซ็นแอปแทนได้
ที่เก็บความลับขององค์กรใช่
สำรองแบบเข้ารหัสในที่ที่คนสองคนเข้าถึงได้ใช่ — ขั้นต่ำที่ยอมรับได้

สิ่งที่ต้องเก็บคู่กันเสมอ

เก็บเพราะ
ไฟล์ keystoreตัวกุญแจ
รหัสผ่านของ keystore และของ aliasไม่มีรหัสผ่าน กุญแจก็ใช้ไม่ได้
ชื่อ aliasลืมแล้วต้องเดา
ลายนิ้วมือ SHA-256 ของกุญแจใช้ยืนยันว่าไฟล์ที่กู้มาถูกต้อง
# จดลายนิ้วมือไว้ตอนสร้าง
keytool -list -v -keystore ~/keys/acetec-wms.jks -alias acetec-wms | grep SHA256

สำหรับทีมเล็ก สิ่งที่ทำได้ทันทีคือเขียนเอกสารว่ากุญแจอยู่ที่ไหนและใครเข้าถึงได้ — เพราะปัญหาที่พบจริงส่วนใหญ่ไม่ใช่กุญแจถูกขโมย แต่คือไม่มีใครรู้ว่ามันอยู่ที่ไหน

6. ตรวจว่า APK ถูกเซ็นด้วยอะไร

apksigner verify --print-certs build/app/outputs/flutter-apk/app-release.apk
Signer #1 certificate DN: CN=Android Debug, O=Android, C=US   ← กุญแจ debug
Signer #1 certificate SHA-256 digest: a1b2c3...

บรรทัด CN=Android Debug คือสัญญาณว่ายังเซ็นด้วยกุญแจ debug อยู่ — ตรวจได้ในสิบวินาทีและควรทำก่อนปล่อยทุกครั้ง

# ใส่ในสคริปต์ปล่อยรุ่น
if apksigner verify --print-certs "$APK" | grep -q "CN=Android Debug"; then
  echo "APK ถูกเซ็นด้วยกุญแจ debug — หยุด"
  exit 1
fi

7. เปลี่ยนกุญแจทีหลังได้ไหม

สถานการณ์ทำได้ไหม
แจกไฟล์ APK เอง (ไม่ผ่าน store)เปลี่ยนได้ แต่ทุกเครื่องต้องถอนแล้วติดตั้งใหม่
ผ่าน Play Store ที่เปิด Play App Signingขอเปลี่ยนกุญแจ upload ได้ ส่วนกุญแจที่ผู้ใช้เห็น Google ถือไว้
ผ่าน Play Store แบบเดิมเปลี่ยนไม่ได้

สำหรับ PDA ในคลังที่แจก APK เอง การเปลี่ยนกุญแจทำได้แต่แพง — ต้องเดินไปทุกเครื่อง ถอน ติดตั้ง แล้วตั้งค่า profile ใหม่

ซึ่งเป็นเหตุผลที่ควรสร้างกุญแจให้ถูกตั้งแต่ก่อนปล่อยรุ่นแรก — ต้นทุนตอนนี้คือสิบนาที ต้นทุนทีหลังคือหนึ่งวันของช่างคูณจำนวนเครื่อง

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ติดตั้งทับไม่ได้ ขึ้นว่า “ไม่ได้ติดตั้งแอป”ลายเซ็นไม่ตรงกับที่ติดตั้งไว้ใช้กุญแจเดิม หรือถอนก่อน
Play Store ปฏิเสธเซ็นด้วยกุญแจ debugสร้างกุญแจของตัวเอง
กุญแจอยู่ในเครื่องคนเดียวไม่มีกระบวนการเก็บสำรองและเขียนเอกสาร
กุญแจหลุดเข้า gitไม่ได้ใส่ .gitignoreใส่ก่อน แล้วสร้างกุญแจใหม่ถ้าหลุดไปแล้ว
build ไม่ผ่านบนเครื่องคนอื่นบังคับให้ต้องมี key.propertiesif (file.exists())
กุญแจหมดอายุตั้ง validity สั้นตั้งยาวตั้งแต่สร้าง — แก้ทีหลังไม่ได้

9. แบบฝึกหัด

ทีมจะปล่อยแอปให้คลังใช้จริงสัปดาห์หน้า และตอนนี้ยังใช้กุญแจ debug อยู่

  1. ต้องทำอะไรบ้าง
  2. ถ้าปล่อยไปก่อนแล้วค่อยเปลี่ยนกุญแจทีหลัง จะเกิดอะไร
แนวคำตอบ

1. ห้าขั้น ใช้เวลารวมไม่ถึงชั่วโมง

ขั้นทำ
1สร้าง keystore ด้วย -validity 10000
2ใส่ key.properties และ *.jks ใน .gitignore ก่อนสร้างไฟล์
3ต่อกับ Gradle พร้อม if (file.exists())
4สำรองกุญแจและรหัสผ่าน พร้อมจดลายนิ้วมือ SHA-256
5build แล้วยืนยันด้วย apksigner verify --print-certs

ขั้นที่ 2 ต้องมาก่อนขั้นที่ 1 ในทางปฏิบัติ — เพราะถ้าสร้างไฟล์ก่อนแล้ว commit ไปโดยไม่ทันสังเกต กุญแจจะอยู่ในประวัติ git ตลอดไป และการลบ commit ทีหลังไม่ช่วยถ้ามีคน clone ไปแล้ว

2. ต้นทุนที่ต้องจ่ายทีหลัง เรียงตามลำดับเวลา

ต้องทำต้นทุน
เดินไปทุกเครื่อง ถอนแอปเดิมเวลาช่างคูณจำนวนเครื่อง
ติดตั้งรุ่นใหม่—
ตั้งค่า profile เซิร์ฟเวอร์ใหม่ทุกเครื่องข้อมูลใน Part 10 หายหมด
ผู้ใช้ต้องล็อกอินใหม่session ที่เก็บไว้หายด้วย (Part 8)
งานที่เก็บไว้ในเครื่องรอส่งหายถาวร ถ้ามีฟีเจอร์นั้นแล้ว (Part 29)

แถวสุดท้ายอันตรายที่สุดและมักถูกลืมตอนวางแผน — การถอนแอปลบข้อมูลในเครื่องทั้งหมด ไม่มีข้อยกเว้น

ข้อสรุป: การสร้างกุญแจตอนนี้ใช้เวลาสิบนาที ส่วนการเลื่อนไปทำทีหลังมีต้นทุนที่เพิ่มขึ้นตามจำนวนเครื่องที่ติดตั้งไปแล้ว — ซึ่งเป็นรูปแบบเดียวกับหนี้ทางเทคนิคชนิดอื่น ต่างที่อันนี้ตัวเลขคำนวณได้ชัดเจน

และถ้าทีมยังลังเล ให้ถามคำถามเดียว — “ถ้าอีกหกเดือนต้องแก้บั๊กด่วน แล้วพบว่าปล่อยรุ่นใหม่ไม่ได้เพราะกุญแจ debug หมดอายุ จะทำอย่างไร”

10. สรุป

  • ลายเซ็นตอบคำถามว่า “มาจากคนเดียวกันไหม” — ไม่ตรงแล้วติดตั้งทับไม่ได้
  • กุญแจ debug เป็นกุญแจสาธารณะที่ทุกเครื่องมีเหมือนกัน
  • ตั้ง validity ยาว เพราะแก้ทีหลังไม่ได้
  • กุญแจต้องไม่เข้า git และต้องมีคนเข้าถึงได้มากกว่าหนึ่งคน
  • ตรวจ apksigner verify --print-certs ก่อนปล่อยทุกครั้ง
  • เปลี่ยนกุญแจทีหลังแปลว่าทุกเครื่องต้องถอนแล้วติดตั้งใหม่

บทหน้า: ความลับอื่นที่ไม่ควรอยู่ในแอป
