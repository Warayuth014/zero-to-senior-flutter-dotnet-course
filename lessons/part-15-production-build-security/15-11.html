Connectivity บอกเพียงมี network interface ไม่ได้บอกว่า WMS ใช้งานได้: ต้องใช้ request/health probeจริง, แยก offline/timeout/auth/conflict และรักษา intentผู้ใช้โดยไม่ส่ง commandซ้ำ

1. Failure taxonomy

FailureUXRetry
Offline/socketคงข้อมูล/แจ้ง offlineเมื่อกลับ online
Timeoutสถานะไม่แน่ชัดreconcileก่อน
401ต่อ session/loginตาม auth policy
409refresh conflictไม่ยิงซ้ำเดิม

2. Read resilience

แสดง cached snapshotพร้อมเวลา “อัปเดตล่าสุด”, stale badge และ retry; อย่าแสดงข้อมูลเก่าเหมือนสด ถ้า operationเสี่ยงใช้ข้อมูล stale ให้ blockหรือ server revalidateตอน command

3. Write resilience

commandทุกตัวมี idempotency key, payload snapshot, createdAt, retry countและ status pending/sending/confirmed/failed/conflict เก็บ localอย่าง atomic/เข้ารหัสตาม sensitivityและ server dedupe key

4. Backoff

delay = min(maxDelay, base * pow(2, attempt)) + jitter;

retryเฉพาะ transient error, เคารพ Retry-After, หยุดเมื่อ logout/endpointเปลี่ยน และไม่ให้หลาย screensสร้าง retry storm

5. Timeout ambiguity

requestอาจสำเร็จที่ serverแล้ว responseหาย หลัง timeout queryด้วย operation IDหรือ refresh authoritative stateก่อน resend UIใช้คำว่า “กำลังตรวจสอบผล” ไม่รีบประกาศล้ม

6. Lifecycle

pause/backgroundหยุด pollingที่ไม่จำเป็นแต่ writeที่ OSอาจ killต้อง persistก่อนส่ง เมื่อ resume probe/refresh/reconcile ไม่สร้าง timer/subscriptionซ้อน และ mounted/generation guard callbackเก่า

7. Endpoint switching

เมื่อเปลี่ยน server/profile ให้ยืนยันหากมี pending commands เพราะ queueของ server Aห้ามส่งไป B Clear auth/client/cacheตาม scopeและแสดง environmentเด่นป้องกันข้อมูลข้ามระบบ

8. Chaos tests

offlineก่อน submit, disconnectกลาง request, responseหายหลัง commit, latencyสูง, 401/409/500, app killed, clockเปลี่ยน, networkสลับและ server A→B โดยไม่มีข้อมูลหาย/ซ้ำ/ข้าม tenant
