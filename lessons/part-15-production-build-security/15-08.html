1. ชื่อสามชื่อที่ต่างกัน

ชื่ออยู่ที่ใครเห็นเปลี่ยนทีหลังได้ไหม
applicationIdbuild.gradle.ktsระบบปฏิบัติการไม่ได้ — เปลี่ยนแล้วกลายเป็นคนละแอป
android:labelAndroidManifest.xmlใต้ไอคอนได้
MaterialApp.titleโค้ด Dartตัวสลับแอปของระบบได้

แถวแรกเป็นแถวเดียวที่แก้ทีหลังไม่ได้ และเป็นแถวที่แม่แบบตั้งค่าผิดไว้ให้

2. com.example ที่ยังไม่ได้เปลี่ยน

defaultConfig {
    // TODO: Specify your own unique Application ID
    applicationId = "com.example.wms_absolute_mobile"
}

บรรทัดนี้อยู่ในทั้งสองโปรเจกต์ พร้อมคอมเมนต์ TODO ที่แม่แบบใส่ไว้

ผลของการปล่อยด้วย com.example.*
Play Store ปฏิเสธ — com.example เป็นชื่อจองไว้สำหรับตัวอย่าง
ชนกับแอปตัวอย่างอื่นที่ใช้ชื่อเดียวกัน แล้วติดตั้งทับกัน
ดูไม่น่าเชื่อถือเมื่อฝ่ายไอทีตรวจก่อนอนุญาต
test('applicationId ที่ยังเป็น com.example ต้องขวางการปล่อย', () {
  final gradle = goodGradle.replaceAll('com.acetec.wms.pda"', 'com.example.wms_pda"');

  final findings = checkAndroidGradle(gradle);
  final blocker = findings.firstWhere((f) => f.isBlocker);
  expect(blocker.code, 'default-application-id');
});

3. ตั้งชื่ออย่างไร

com.acetec.wms.pda
│    │      │   └── ชื่อแอปในกลุ่มนั้น
│    │      └────── กลุ่มของระบบ
│    └───────────── ชื่อองค์กร
└────────────────── โดเมนกลับด้าน
กฎเหตุผล
ใช้โดเมนที่องค์กรเป็นเจ้าของ กลับด้านรับประกันว่าไม่ชนกับใคร
ตัวพิมพ์เล็กทั้งหมดบางระบบไฟล์ไม่แยกตัวพิมพ์
ไม่มีขีดกลางใช้ไม่ได้ในชื่อแพ็กเกจ Java
สื่อว่าเป็นแอปอะไรฝ่ายไอทีอ่านแล้วเข้าใจ

ถ้ามีหลาย build ที่ต้องอยู่บนเครื่องเดียวกัน ให้ต่อท้าย

buildTypes {
    debug {
        // แอปทดสอบอยู่ร่วมกับแอปจริงบนเครื่องเดียวได้
        applicationIdSuffix = ".dev"
        resValue("string", "app_name", "ABS PDA (dev)")
    }
}

ต่อยอดจาก 11.12 ที่บอกให้ทำไอคอนคนละชุด — ชื่อแพ็กเกจที่ต่างกันทำให้ติดตั้งพร้อมกันได้จริง ส่วนไอคอนกับชื่อทำให้แยกออกด้วยตา

ปัญหาที่แก้ได้จาก
พนักงานเปิดแอปทดสอบแล้วบันทึกลงเซิร์ฟเวอร์ทดสอบทั้งกะ11.12
ต้องถอนแอปจริงก่อนลงตัวทดสอบบทนี้

4. เปลี่ยนชื่อแพ็กเกจต้องแก้กี่ที่

android/app/build.gradle.kts          namespace + applicationId
android/app/src/main/kotlin/...        โครงโฟลเดอร์และ package ใน MainActivity.kt
android/app/src/*/AndroidManifest.xml  ถ้ามีการอ้างชื่อ

ทำมือได้แต่พลาดง่าย ใช้เครื่องมือเร็วกว่า

dart pub global activate rename_app
dart pub global run rename_app:main android --value "com.acetec.wms.pda"
ทำก่อนปล่อยรุ่นแรกเท่านั้น — หลังจากที่มีเครื่องติดตั้งไปแล้ว การเปลี่ยน applicationId ทำให้ระบบมองว่าเป็นคนละแอป ผู้ใช้จะเห็นสองไอคอนและข้อมูลเดิมทั้งหมดอยู่กับแอปเก่า

5. ชื่อที่ผู้ใช้เห็น

<application android:label="ABS PDA V3">
ชื่อที่ดีชื่อที่ไม่ดี
สั้นพอที่จะไม่ถูกตัดใต้ไอคอนยาวจนเห็นแค่ครึ่ง
บอกว่าเป็นแอปอะไรwmsapp
แยกออกจากแอปทดสอบชื่อเดียวกันทั้งสอง build

ใต้ไอคอนบนหน้าจอ Android แสดงได้ราว 12 ตัวอักษรก่อนถูกตัด — ABS PDA V3 พอดี ส่วน ACETEC Warehouse Management จะเห็นเป็น ACETEC War...

test('ชื่อแอปว่าง ต้องเตือน', () {
  final manifest = goodManifest.replaceAll('android:label="ABS PDA V3"', 'android:label=""');

  expect(checkAndroidManifest(manifest).any((f) => f.code == 'empty-label'), isTrue);
});

6. ไอคอนก่อนปล่อย

11.12 อธิบายวิธีสร้างไปแล้ว ตรงนี้คือสิ่งที่ต้องตรวจก่อนปล่อย

ตรวจอย่างไร
ไม่ใช่ไอคอน Flutter ที่แม่แบบให้มาดูบนเครื่องจริง
ไม่ถูกตัดขอบบนเครื่องที่ใช้กรอบวงกลมทดสอบบนเครื่องที่ใช้จริง
ไม่เบลอไฟล์ต้นฉบับ 1024×1024 ขึ้นไป
แอปทดสอบใช้ไอคอนคนละชุดดูสองแอปข้างกัน

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
Play Store ปฏิเสธapplicationId เป็น com.example.*เปลี่ยนก่อนปล่อยรุ่นแรก
เปลี่ยน applicationId แล้วผู้ใช้เห็นสองไอคอนระบบมองว่าเป็นคนละแอปทำก่อนปล่อยเท่านั้น
ติดตั้งแอปทดสอบทับแอปจริงใช้ applicationId เดียวกันใส่ applicationIdSuffix
ชื่อใต้ไอคอนถูกตัดยาวเกิน 12 ตัวอักษรย่อ
ไอคอนไม่เปลี่ยนหลังสร้างใหม่Android จำไอคอนเก่าถอนแล้วติดตั้งใหม่
build ไม่ผ่านหลังเปลี่ยนชื่อโครงโฟลเดอร์ kotlin ไม่ตรงกับ packageใช้เครื่องมือแทนการแก้มือ

8. แบบฝึกหัด

ทีมจะปล่อยแอปให้สามสาขา และอยากให้แต่ละสาขาเห็นชื่อสาขาตัวเองบนไอคอน

  1. ควรทำเป็นสามแอปแยก หรือแอปเดียวที่สลับได้
  2. ถ้าเลือกแอปเดียว จะแสดงชื่อสาขาอย่างไร
แนวคำตอบ

1. เทียบสองทาง

สามแอปแยกแอปเดียว
ปล่อยรุ่นใหม่build สามครั้ง ติดตั้งสามชุดครั้งเดียว
เครื่องที่ย้ายสาขาต้องถอนแล้วลงตัวใหม่สลับ profile (Part 10)
เห็นสาขาก่อนเปิดแอปเห็นไม่เห็น
เปิดผิดสาขาเป็นไปไม่ได้เป็นไปได้

แอปเดียวชนะ สำหรับกรณีนี้ เพราะ Part 10 สร้างระบบ profile ไว้แล้ว และแถวที่สองสำคัญกว่าที่คิด — PDA ที่ย้ายสาขาชั่วคราวเป็นเรื่องปกติในองค์กรที่มีหลายคลัง

สามแอปแยกคุ้มเมื่อสาขาเป็นคนละองค์กรที่ไม่ควรเห็นข้อมูลของกัน ซึ่งตอนนั้นการแยกไม่ใช่แค่เรื่องความสะดวก

2. แสดงชื่อสาขาในที่ที่ผู้ใช้เห็นตลอดเวลา ไม่ใช่แค่ตอนเปิด

ที่จาก
ชื่อ profile บนแถบหัวจอ10.12 — “ต่อผิดเครื่อง” เจอบ่อยกว่า “ต่อไม่ได้”
สีของแถบหัวจอต่างกันตามสาขา11.12 แบบฝึกหัด
ชื่อสาขาในกล่องยืนยันของรายการที่ย้อนยาก11.12

ข้อที่สองมีพลังที่สุด เพราะผู้ใช้จำสีได้เร็วกว่าอ่านชื่อ และรู้ตัวทันทีเมื่อเห็นสีที่ไม่คุ้น

// สีมาจาก profile ที่ใช้อยู่ ไม่ใช่จาก build
Color headerColorFor(ServerProfile profile) => switch (profile.environment) {
  ServerEnvironment.production => PdaColors.brand,
  ServerEnvironment.development => PdaColors.warning,
  ServerEnvironment.custom => PdaColors.subtitle,
};

แต่ต้องระวังกับดักจาก 10.4 — ป้าย environment ที่ผู้ใช้เลือกเอง ไม่ควรเอาไปเปลี่ยนพฤติกรรมของแอป การใช้มันเลือกสีนั้นยอมรับได้เพราะเป็นเรื่องของการแสดงผลล้วน ๆ แต่ต้องไม่เลยไปกว่านั้น

และคำถามที่ควรถามก่อนทั้งหมดนี้ — ทำไมพนักงานถึงเข้าเซิร์ฟเวอร์สาขาอื่นได้ตั้งแต่แรก ถ้าบัญชีผูกกับสาขา เซิร์ฟเวอร์ควรปฏิเสธการเข้าสู่ระบบเลย (11.12) — สีและไอคอนเป็นแค่การช่วยให้รู้ตัวเร็วขึ้น ไม่ใช่การป้องกัน

9. สรุป

  • applicationId เปลี่ยนทีหลังไม่ได้ — ต้องตั้งก่อนปล่อยรุ่นแรก
  • com.example.* เป็นชื่อจองไว้สำหรับตัวอย่าง Play Store ปฏิเสธ
  • applicationIdSuffix ทำให้แอปทดสอบอยู่ร่วมกับแอปจริงได้
  • ชื่อใต้ไอคอนแสดงได้ราว 12 ตัวอักษร
  • เปลี่ยนไอคอนแล้วต้องถอนติดตั้งใหม่ถึงจะเห็น
  • แสดงสาขาที่ใช้อยู่ในแอป ดีกว่าแยกเป็นหลายแอป
