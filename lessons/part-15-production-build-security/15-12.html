Production readiness checklist

Part 15: Production Build, Security & Resilience

เตรียม Android/iOS build, environment, network security และ operational checklist

1. เป้าหมายของบทนี้

  • อธิบาย Production readiness checklist ด้วยภาษาของตัวเองได้
  • ชี้ได้ว่าแนวคิดนี้อยู่ตรงไหนใน flow Flutter → .NET
  • ทดลองและตรวจผลได้ ไม่ใช่จำโค้ดอย่างเดียว

2. Mental model

Production readiness checklist ให้อ่านโดยแยก 4 อย่าง: input ที่เข้ามา, state ที่ถืออยู่, side effect ที่ออกไป และ output ที่ UI แสดง จากนั้นหา owner และ lifecycle ของแต่ละอย่างให้เจอ

หัวข้อนี้อยู่ในกลุ่ม Production Build, Security & Resilience เมื่อเปิดโค้ดจริงให้ถามว่าใครเป็นเจ้าของข้อมูล ใครเปลี่ยนข้อมูล และ widget ใดต้อง rebuild หลังการเปลี่ยนนั้น

มุม Flutter: จับหลักให้ได้ก่อน แล้วค่อยเทียบการใช้งานสองแบบในโปรเจกต์จริง

3. หาในโปรเจกต์จริง

บทพื้นฐานนี้เตรียมแนวคิดสำหรับอ่านทั้ง wmsapp และ wms_absolute_mobile โดยบท Codebase Deep Dive จะระบุไฟล์จริงแบบรายไฟล์

4. วิธีไล่ทีละขั้น

  1. เริ่มจาก event ของผู้ใช้ เช่น tap, submit หรือ scan
  2. ตาม method ที่เปลี่ยน state หรือเรียก dependency
  3. ถ้ามี I/O ให้เปิด request DTO, endpoint และ response model คู่กัน
  4. กลับมาดูว่า state ใหม่ทำให้ widget ส่วนใด rebuild
  5. เขียน test หรือ checklist เพื่อพิสูจน์ happy path และ error path

6. จุดที่พบบ่อยในงานจริง

อย่าแก้ UI จากอาการอย่างเดียว ให้แยกก่อนว่าเป็น constraints, state, lifecycle หรือ data contract

7. Mini Exercise

  1. ค้นหา Production readiness checklist หรือ symbol ที่เกี่ยวข้องในสอง reference apps
  2. วาด flow สั้น ๆ จาก UI ไป data source แล้วกลับมา UI
  3. เพิ่ม error case หนึ่งกรณีและอธิบายว่าผู้ใช้ควรเห็นอะไร

8. Checklist

  • บอก owner ของ state ได้
  • แยก synchronous code กับ asynchronous side effect ได้
  • รู้ว่า dispose/cancel ตรงไหน
  • อธิบาย contract กับ .NET โดยไม่ต้องเดาจาก UI

9. สรุปจำเร็ว

Production readiness checklist ต้องตอบได้ทั้ง “มันคืออะไร”, “อยู่ตรงไหนในโค้ด”, “พังแบบไหน” และ “ทดสอบอย่างไร”
