Part 18 คือการเคลื่อน inventory ผ่าน station: Putaway ส่ง pallet ไป ASRS/Prework/Replenish ส่วน Picking ดึงของจาก source pallet ไป destination pallet ทุกขั้นต้องรักษา pallet, order และ part identity ให้ตรงกัน

1. Putaway flow map

station scan → pallet scan → inspect items
→ choose destination/wrapping → confirm
→ AMR dispatch → SignalR event → REST reconcile

หน้าจอไม่ได้ขยับสินค้าเอง แต่ส่ง intent ให้ .NET แล้วแสดงสถานะงานขนส่งที่ backend ยืนยัน

2. Picking flow map

orders list → order detail → assign source station
→ scan part/serial or qty → choose dest pallet
→ confirm pick → return source / continue / send dest to pack

หนึ่ง order อาจใช้หลาย source pallet และใช้ destination pallet เดิมต่อได้

3. Station families

Putaway ปกติมี STN-1..3 ส่วน Prework มี PW-STN-1..6 โดยสถานีเลขคี่เป็น receive และเลขคู่เป็น send กติกาอยู่ใน StationInfo: allowedType, fixedDestination และ PWRole

4. Identity map

  • stationId ระบุจุดกายภาพ
  • palletId ระบุภาชนะและ inventory ปัจจุบัน
  • pickOrderId ระบุความต้องการรวม
  • partId/lot/serial ระบุสินค้าที่เคลื่อน

ห้ามแทน line หรือ lot ด้วย partId เมื่อหนึ่ง part ปรากฏหลายชุด

5. Two sources of state

REST status เป็น authoritative snapshot ส่วน SignalR เป็นเหตุการณ์เร่ง UI ให้ตอบสนองเร็ว Pattern ในโค้ดคือ merge event บางส่วนแล้วเรียก REST โหลดใหม่ จึงต้องกัน response เก่าทับ state ใหม่และรองรับ event หลุด

6. Command vs event

confirmPutaway, confirmPickV2, returnPallet และ sendToPack เป็น command ที่อาจเปลี่ยนข้อมูล ส่วน StationDispatched/PalletArrived/PalletReturned เป็น notification ห้ามนำ event มา commit inventory ซ้ำใน client

7. Failure boundaries

แยก validation reject, conflict, timeout ที่ไม่รู้ผล, transport failure และ event disconnect เพราะ retry policy ต่างกัน โดยเฉพาะ confirm/return ต้องมี idempotency key หรือ query สถานะก่อน retry

8. วิธีอ่าน Part นี้

ทุกบทให้ trace 5 ช่อง: user scan → local transition → API payload → backend result/event → UI reconciliation แล้วจด invariant อย่างน้อยหนึ่งข้อและ failure case อย่างน้อยสองกรณี
