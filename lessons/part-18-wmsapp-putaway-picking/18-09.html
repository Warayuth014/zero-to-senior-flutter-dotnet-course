Orders list เป็น operational inbox: แสดง WAITING/PICKING และมี pallet routing panel แยกต่างหาก ผู้ใช้ต้องเห็นชัดว่า action ใดเปิด order และ action ใดส่ง pallet

1. Load orders

getPickOrdersList() อ่าน /picking/orders-list แล้วเก็บ List<PickOrderListItem> พร้อม loading overlay หาก fail แสดง dialog แต่รายการเก่าอาจยังอยู่ จึงควรบอกว่า stale

2. Status semantics

PickOrderListItem มี helper isWaiting/isPicking จาก String status รายการ WAITING เปิด dialog “รอ Robot” ส่วน PICKING จึงเปิด detail unknown status ควรมี behavior ที่ explicit

3. Summary and cards

หน้าจอนับ waiting/picking จาก list เดียวกับ card และแสดง partCount, totalRequiredQty, palletCount, owner/customerOrderId/createdAt จึงเป็น derived UI ไม่ควรมี counter state แยก

4. Open and refresh

เมื่อ detail route pop กลับมา _load() ใหม่เพื่อสะท้อนงานที่ pick ไปแล้ว การเรียกแบบไม่ await ทำได้แต่ควรจัด error/loading และ generation เมื่อผู้ใช้ pull refresh ซ้อนกัน

5. Return preview

scan pallet
→ GET return-pallet-preview/{id}
→ canReturn + destination + reason
→ user confirms
→ POST return-pallet

preview ไม่มี side effect และให้ server เป็นผู้ตัดสิน routing

6. Preview is not reservation

ระหว่าง preview กับ execute สถานะ pallet อาจเปลี่ยน จึงต้อง validate ซ้ำตอน POST และตอบ 409 หาก decision ไม่ใช้แล้ว UI ควร refresh preview ไม่ retry destination เก่าอัตโนมัติ

7. WAITING activation

API มี notifyArrival() สำหรับ robot simulator เปลี่ยน WAITING→PICKING และ assign pallets แต่หน้ารายการปัจจุบันเพียงแจ้งให้รอ จึงต้องรู้ว่า activation มาจาก external process ไม่ใช่ tap card

8. List tests

ทดสอบ empty/error/stale, WAITING dialog, PICKING navigation+refresh, unknown status, preview denied, preview/execute conflict, cancel confirmation และ scanner focus คืนหลังทุก path
