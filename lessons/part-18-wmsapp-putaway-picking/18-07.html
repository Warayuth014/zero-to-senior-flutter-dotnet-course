Putaway API มี read models แบบ dynamic มากเกินไป: pallet/confirm มี typed model แต่ station และ prework status ยังเป็น Map จึงเสีย compile-time safety ตรง flow realtime ที่ซับซ้อนที่สุด

1. Endpoint inventory

GET  /putaway/station-status
GET  /putaway/scan-pallet/{palletId}?stationId=...
POST /putaway/confirm
GET  /putaway/prework-station-status
POST /putaway/prework-return-pallet

2. Scan response

PutawayPalletInfo parse items ด้วย UnloadItem และ default suggestedDestination=ASRS, message ว่าง แต่ required fields cast โดยตรงจึง throw หาก payload missing/wrong type

3. Confirm payload

{ stationId, palletId, destination,
  operatorId, wrappingRequired }

PutawayResult คืน success, palletId, stationId, destination และ message เพื่อยืนยัน command ที่ server รับจริง

4. Station status debt

ทั้ง getStationStatus และ getPreworkStationStatus คืน List<Map<String,dynamic>> ทำให้ field palletStatus/cutItems/destination ถูก cast ใน widget ควรสร้าง StationStatus DTO และ enum แยก normal/prework

5. URL construction risk

scanPalletForPutaway ต่อ palletId ใน path และ stationId ใน query ด้วย string โดยตรง ต่างจาก Picking ที่ใช้ Uri.encodeQueryComponent ควรใช้ Uri builder เพื่อ encode ทุก segment/query อย่างสม่ำเสมอ

6. Error propagation

service คืน ApiResult.error แต่บาง method ไม่ส่ง statusCode ต่อ ทำให้ UI แยก 409 conflict, 404 และ timeout ไม่ได้ Contract ควรรักษา code/problem details ถึง domain layer

7. Parsing hardening

ตรวจ list/map shape, number coercion, unknown status/destination, nullable message และ malformed item พร้อมเก็บ raw transport DTO ไว้ที่ boundary ไม่ปล่อย dynamic เข้า widget

8. Contract lab

สร้าง JSON fixtures ของ station empty/busy, PW in-transit/cut-complete, pallet PW/FG และ confirm conflict แล้วทดสอบ Dart parser คู่กับ .NET response serialization รวมถึง ID ที่มีอักขระต้อง encode
