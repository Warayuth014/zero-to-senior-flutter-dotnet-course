08-05 · Auth Integration

จำ session หลังปิดแอป

Part 8: Authentication, Session & JWT

ทำ login กับ .NET, แนบ bearer token และควบคุม session lifecycle บน mobile

1. เป้าหมายของบทนี้

  • อธิบาย จำ session หลังปิดแอป ด้วยภาษาของตัวเองได้
  • ชี้ได้ว่าแนวคิดนี้อยู่ตรงไหนใน flow Flutter → .NET
  • ทดลองและตรวจผลได้ ไม่ใช่จำโค้ดอย่างเดียว

2. Mental model

Login แลก credential กับ token จากนั้น client แนบ Authorization: Bearer ... ทุก request Session ต้องมีจุดเริ่ม/หมดอายุ/logout ชัดเจน และ token production ควรอยู่ secure storage ไม่ใช่ log หรือ plain preference

หัวข้อนี้อยู่ในกลุ่ม Authentication, Session & JWT เมื่อเปิดโค้ดจริงให้ถามว่าใครเป็นเจ้าของข้อมูล ใครเปลี่ยนข้อมูล และ widget ใดต้อง rebuild หลังการเปลี่ยนนั้น

รอยต่อ .NET: บทนี้อธิบาย request/response และ endpoint ที่ Flutter ต้องรู้ ส่วน Controller → Service → EF Core/SQL ให้อ่านต่อในคอร์ส zero-to-senior-dotnet8-course

3. หาในโปรเจกต์จริง

บทพื้นฐานนี้เตรียมแนวคิดสำหรับอ่านทั้ง wmsapp และ wms_absolute_mobile โดยบท Codebase Deep Dive จะระบุไฟล์จริงแบบรายไฟล์

4. วิธีไล่ทีละขั้น

  1. เริ่มจาก event ของผู้ใช้ เช่น tap, submit หรือ scan
  2. ตาม method ที่เปลี่ยน state หรือเรียก dependency
  3. ถ้ามี I/O ให้เปิด request DTO, endpoint และ response model คู่กัน
  4. กลับมาดูว่า state ใหม่ทำให้ widget ส่วนใด rebuild
  5. เขียน test หรือ checklist เพื่อพิสูจน์ happy path และ error path

5. ตัวอย่างโค้ด

final json = await api.post('/api/Authenticate/login', {
  'username': username,
  'password': password,
}, absolute: true);
api.authToken = json['token'] as String?;

6. จุดที่พบบ่อยในงานจริง

อย่าเก็บรหัสผ่าน และอย่า log token; เมื่อเปลี่ยน server หรือได้ 401 ต้องตัดสินใจเรื่อง session อย่างชัดเจน

7. Mini Exercise

  1. ค้นหา จำ session หลังปิดแอป หรือ symbol ที่เกี่ยวข้องในสอง reference apps
  2. วาด flow สั้น ๆ จาก UI ไป data source แล้วกลับมา UI
  3. เพิ่ม error case หนึ่งกรณีและอธิบายว่าผู้ใช้ควรเห็นอะไร

8. Checklist

  • บอก owner ของ state ได้
  • แยก synchronous code กับ asynchronous side effect ได้
  • รู้ว่า dispose/cancel ตรงไหน
  • อธิบาย contract กับ .NET โดยไม่ต้องเดาจาก UI

9. สรุปจำเร็ว

จำ session หลังปิดแอป ต้องตอบได้ทั้ง “มันคืออะไร”, “อยู่ตรงไหนในโค้ด”, “พังแบบไหน” และ “ทดสอบอย่างไร”
