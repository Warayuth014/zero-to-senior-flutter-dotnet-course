1. Authentication vs authorization

Authentication ตอบว่า “คุณคือใคร” ส่วน authorization ตอบว่า “คุณทำอะไรได้” การ login สำเร็จไม่ได้แปลว่าทุก endpoint อนุญาต และการซ่อนปุ่มไม่แทนการตรวจสิทธิ์ฝั่ง server

2. Request contract

POST /api/Authenticate/login
Content-Type: application/json

{"username":"EMP001","password":"••••••••"}

ส่งผ่าน HTTPS เท่านั้นและไม่ log credential

3. Response contract

{
  "token": "eyJ...",
  "expiration": "2026-08-15T10:00:00Z"
}

ตรวจ field/ชนิด/เวลาเหมือน API contract อื่น ไม่ cast dynamic ใน widget

4. State transitions

signedOut → submitting → authenticated
                    ↘ invalidCredentials
                    ↘ networkFailure
authenticated → expired/revoked → signedOut

disable submit ระหว่างส่งและอย่าเปลี่ยน route ก่อนเก็บ session สำเร็จ

5. ไฟล์จริง

wms_absolute_mobile/features/auth/auth_repository.dart เรียก /api/Authenticate/login แล้วตั้ง token ใน shared ApiClient ส่วน wmsapp/screens/login_screen.dart เป็น mock password และ preferences ซึ่งเหมาะ demo แต่ยังไม่ใช่ security boundary

6. Failure ที่ต้องแยก

  • validation local: field ว่าง
  • 401: username/password ไม่ถูก
  • 403: account ไม่มีสิทธิ์หรือ disabled ตาม contract
  • timeout/offline: ยังไม่รู้ว่า credential ถูกหรือไม่
  • invalid JSON: contract/deployment ผิด

7. แบบฝึกหัด

วาด flow ตั้งแต่กด Login จน GET tasks สำเร็จ พร้อมจุดที่ password และ token ปรากฏ

แนวคำตอบ

Password อยู่เฉพาะ form/request ชั่วคราว ไม่ persist; token อยู่ AuthSession/secure storage และ Authorization header แต่ต้องถูก redact จาก log

8. Security checklist

HTTPS, no credential log, typed response, loading guard, generic invalid-login message, server rate limit/lockout และ token ถูกแนบหลัง session พร้อมแล้ว
