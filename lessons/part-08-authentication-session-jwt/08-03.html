JWT คือ signed access credential: header.payload.signature อ่าน payload ได้แต่แก้ไม่ได้โดยไม่ทำลาย signature; ไม่ใช่ encryption และ client ไม่ใช่ผู้ตัดสินความถูกต้องสุดท้าย

1. AuthSession

class AuthSession {
  const AuthSession({required this.accessToken, required this.expiresAt,
    required this.username, required this.roles});
  final String accessToken;
  final DateTime expiresAt;
  final String username;
  final Set<String> roles;
  bool isExpiredAt(DateTime now) => !now.isBefore(expiresAt);
}

2. Claims ที่พบบ่อย

sub คือ subject, exp expiration เป็น Unix seconds, iss issuer, aud audience และ role/name อาจใช้ URI claim type ตาม .NET configuration

3. Server validation

.NET ต้องตรวจ signature, issuer, audience, expiration และ signing key ทุก request ส่วน Flutter อ่าน claimsเพื่อ UX ได้ แต่ server เป็น security authority

4. Response vs decode token

ถ้า login response ส่ง username/roles/expiration แบบ typed จะลดการผูก client กับ claim naming แต่ต้องกำหนด source of truth; ถ้า decode JWT ให้รองรับ claim shape ที่ตกลงและ validate types

5. Clock skew

ถือ token ใกล้หมดอายุเป็น expired ก่อนจริง เช่น 30–60 วินาที เพื่อลด request ที่หมดอายุระหว่างเดินทาง และเวลาใน device อาจคลาดเคลื่อน จึงควรใช้ server expiration/refresh policy อย่างระวัง

6. ห้ามเก็บ secret ใน JWT

Payload decode ได้โดยผู้ถือ token ห้ามใส่ password, connection string หรือข้อมูลลับ; claim มากเกินทำ token ใหญ่และถูกส่งทุก request

7. แบบฝึกหัด

UI decode role ADMIN จาก token แล้วเปิดปุ่มลบได้หรือไม่?

เฉลย

ใช้เพื่อปรับ UI ได้ แต่ DELETE endpoint ยังต้องตรวจ policy/role ฝั่ง .NET และ client ต้อง handle 403 เพราะ role อาจถูกถอนหรือ token ถูก revoke

8. Contract tests

ทดสอบ token/expiration missing, invalid date, exp seconds, roles string/list, expired/near-expiry และ claim names จาก .NET fixture จริง
