2. Anonymous request

login และ health probe ต้องไม่แนบ token เก่าหรือ expired โดยบังเอิญ API client จึงควรรองรับ explicit auth policy เช่น required/optional/none แทน boolean ที่ความหมายกำกวม

3. Shared client

ของจริงตั้ง ApiClient.authToken หลัง login และ feature APIs ใช้ client เดียวกัน การสร้าง ApiClient ใหม่ในแต่ละหน้าอาจทำ token หายและ config ไม่ตรงกัน

4. Header correctness

รูปแบบคือ Authorization: Bearer <token> มีช่องว่างหนึ่งครั้ง ไม่เติม quote และไม่ส่ง token ใน query string เพราะ URL มักถูก log/cache/history

5. Concurrent logout

request ที่เริ่มก่อน logout อาจกลับมาทีหลัง ต้องมี session generation/identity guard ไม่ให้ response เก่าฟื้น state ของผู้ใช้ที่ออกจากระบบแล้ว

6. Redaction

HTTP logger ต้องลบ Authorization แบบ case-insensitive ทั้ง success/error/retry และ tests ต้อง assert ว่า token marker ไม่ปรากฏใน log

7. แบบฝึกหัด

หลัง refresh token สำเร็จ feature API ควรเปลี่ยนอะไร?

เฉลย

อัปเดต SessionStore atomically; request ใหม่อ่าน token ล่าสุดเอง ไม่ต้องวนแก้ repository ทุกตัว ส่วน request เดิมต้องจบตาม generation policy

8. Checklist

token source เดียว, anonymous route ชัด, client lifecycle เดียว, ไม่มี token ใน URL/log และ session generation ป้องกัน stale response
