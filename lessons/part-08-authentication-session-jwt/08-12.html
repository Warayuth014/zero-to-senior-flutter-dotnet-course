3. เส้นทางทั้งหมดในภาพเดียว

เปิดแอป
  └─ restore(currentServerId)                        ← 8.6
       ├─ ไม่มีข้อมูล        → หน้าเข้าสู่ระบบ
       ├─ คนละเซิร์ฟเวอร์    → หน้าเข้าสู่ระบบ + เหตุผล   ← 8.11
       ├─ หมดอายุ           → หน้าเข้าสู่ระบบ + เหตุผล   ← 8.3
       └─ ใช้ได้            → หน้าหลัก

เข้าสู่ระบบ
  └─ signIn(username, password, serverId)            ← 8.1
       ├─ สำเร็จ  → เก็บลงเครื่อง → ตั้ง token → หน้าหลัก  ← 8.4, 8.5
       ├─ 401     → "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง"
       ├─ 403     → บอกว่าบัญชีใช้ไม่ได้
       └─ เน็ตหลุด → ให้ลองใหม่

ระหว่างใช้งาน
  └─ ได้ 401 → handleUnauthorized()                  ← 8.7
       └─ เก็บร่าง → ล้าง token → ล้าง store → หน้าเข้าสู่ระบบ  ← 8.8

ออกจากระบบ
  └─ signOut(reason) → เหมือนข้างบน แต่คนละเหตุผล      ← 8.8

ถ้ามีขั้นไหนที่ตอบไม่ได้ว่าทำไมต้องมี ให้กลับไปอ่านบทที่กำกับไว้ก่อนทำต่อ

6. คำใบ้สำหรับข้อที่ยาก

เกณฑ์ 11 และ 12 — ทำลาย store พร้อม session

class SignedInScope {
  SignedInScope({required this.apiClient, required this.session}) {
    taskStore = TaskStore(RemoteTaskRepository(apiClient))
      ..startPolling(const Duration(seconds: 10));
  }

  final ApiClient apiClient;
  final AuthSession session;
  late final TaskStore taskStore;

  void dispose() {
    taskStore.dispose();     // หยุด polling + เพิ่มเลขรุ่น (4.11)
  }
}

สร้างและทำลายที่เดียวกัน ทำให้เพิ่ม store ใหม่แล้วลืมล้างไม่ได้

7. เทสต์ที่ต้องเขียน

อย่างน้อย 15 ข้อ ตัวอย่างสามข้อที่เขียนยากที่สุด

testWidgets('เปิดแอปที่มี session เดิม ต้องไม่เห็นหน้าเข้าสู่ระบบเลย', (tester) async {
  await storage.write(validSession);

  await tester.pumpWidget(AuthLabApp(dependencies: deps));
  // ยังไม่ settle — ดูเฟรมแรกก่อน
  await tester.pump();

  expect(find.byKey(const Key('splash')), findsOneWidget);
  expect(find.byKey(const Key('login-screen')), findsNothing);

  await tester.pumpAndSettle();
  expect(find.byKey(const Key('home-shell')), findsOneWidget);
});

เทสต์นี้จับอาการเด้งหน้าจอใน 8.6 ได้ตรง ๆ — ถ้าไม่มีสถานะ unknown เฟรมแรกจะเป็นหน้าเข้าสู่ระบบ

test('ออกจากระบบต้องหยุด polling', () async {
  await app.signIn('somchai');
  final callsBefore = repository.fetchCount;

  await app.signOut();
  await Future<void>.delayed(const Duration(seconds: 30));   // ใช้ fakeAsync จริง ๆ

  expect(repository.fetchCount, callsBefore);   // ไม่เพิ่มเลย
});
test('ล็อกอินคนใหม่ต้องไม่เห็นข้อมูลของคนก่อน', () async {
  await app.signIn('somchai');
  await app.scope!.taskStore.load();
  expect(app.scope!.taskStore.tasks, isNotEmpty);

  await app.signOut();
  await app.signIn('somsri');

  // scope ใหม่ ต้องเริ่มจากว่าง
  expect(app.scope!.taskStore.tasks, isEmpty);
});

8. ข้อผิดพลาดที่พบบ่อยตอนทำ lab นี้

อาการสาเหตุวิธีแก้
เห็นหน้าเข้าสู่ระบบแวบหนึ่งค่าเริ่มต้นเป็น signedOutใช้ unknown (8.6)
เทสต์ widget ไม่เห็นหน้ารอใช้ pumpAndSettle ตั้งแต่แรกใช้ pump() ดูเฟรมแรกก่อน
ออกจากระบบแล้วยังมีคำขอไม่หยุด pollingทำลาย store (8.8)
หน้าเข้าสู่ระบบซ้อนกันจัดการ 401 หลายครั้งตรวจสถานะก่อน (8.7)
403 ทำให้ออกจากระบบเหมารวมกับ 401แยกด้วย kind (7.9)
คำตอบผิดสัญญากลายเป็น “รหัสผ่านผิด”try ครอบกว้างเกินอ่านคำตอบนอก try (8.2)

9. แบบทดสอบตัวเองก่อนจบ Part 8

  1. รหัสผ่านกับ token ต่างกันอย่างไรในแง่การเก็บ (8.1)
  2. ทำไม 401 ต้องใช้ข้อความเดียวสำหรับทุกกรณี (8.1)
  3. ทำไมการอ่านคำตอบต้องอยู่นอก try (8.2)
  4. ทำไม AuthRepository ไม่มีเมธอด logout (8.2)
  5. JWT เข้ารหัสหรือไม่ และผลตามมาคืออะไร (8.3)
  6. exp ใน token ต่างจาก expiration ในคำตอบอย่างไร (8.3)
  7. ทำไมต้องเผื่อเวลาก่อนถือว่าหมดอายุ (8.3)
  8. ทำไมใช้ callback แทนการให้ store ถือ ApiClient (8.4)
  9. ทำไมต้องล้าง token ก่อนล้างที่เก็บ (8.4, 8.8)
  10. เก็บลงเครื่องไม่ได้ ควรทำให้เข้าสู่ระบบล้มเหลวไหม (8.5)
  11. ทำไมต้องมีเลขรุ่นของโครงข้อมูลตั้งแต่วันแรก (8.5)
  12. ทำไมค่าเริ่มต้นของสถานะต้องเป็น unknown (8.6)
  13. ทำไมตรวจเซิร์ฟเวอร์ก่อนตรวจอายุ (8.6, 8.11)
  14. 401 สามตัวพร้อมกัน ควรออกจากระบบกี่ครั้ง (8.7)
  15. ทำไมต้องเก็บเหตุผลของการออกจากระบบ (8.7)
  16. อะไรบ้างที่ต้องล้างเมื่อออกจากระบบ (8.8)
  17. การซ่อนปุ่มตาม role เป็นการป้องกันหรือไม่ (8.9)
  18. ทำไมกฎสิทธิ์ต้องเขียนเป็นรายชื่อที่อนุญาต (8.9)
  19. อะไรเก็บในที่เก็บธรรมดาได้บ้าง (8.10)
  20. ทำไมไม่ควรใช้ที่อยู่เป็น serverId (8.11)

10. สรุปท้าย Part 8

สิ่งที่ทำได้แล้ว

  • แลกรหัสผ่านเป็น token โดยที่รหัสผ่านไม่ค้างอยู่ที่ไหน
  • แยกความล้มเหลวของการเข้าสู่ระบบให้ผู้ใช้ทำต่อได้ถูก
  • อ่านข้อมูลใน token โดยรู้ว่าเชื่ออะไรได้แค่ไหน
  • ต่อ token เข้ากับทุกคำขอโดยมีเจ้าของเดียว
  • จำการเข้าสู่ระบบข้ามการปิดแอปอย่างปลอดภัย
  • เปิดแอปแล้วพาไปที่ถูกที่โดยไม่เด้งหน้าจอ
  • รับมือกับ token ที่ใช้ไม่ได้กลางทาง โดยไม่ทำงานซ้ำ
  • ล้างทุกอย่างที่ผูกกับผู้ใช้เมื่อออกจากระบบ
  • ใช้ role ปรับหน้าจอโดยไม่เข้าใจผิดว่าเป็นความปลอดภัย
  • เลือกที่เก็บให้ตรงกับความอ่อนไหวของข้อมูล
  • ผูก session กับเซิร์ฟเวอร์ที่ออกมัน

สิ่งที่ยังไม่ได้ทำและจะทำที่ไหน
