Theme mode เป็น app state: ValueNotifierเหมาะ stateเล็กที่เปลี่ยนทั้ง MaterialApp; persist choiceแยกจาก effective system brightness

1. Controller

class ThemeController extends ValueNotifier<ThemeMode> {
  ThemeController() : super(ThemeMode.system);
  void setMode(ThemeMode mode) => value = mode;
  void toggle(bool systemIsDark) => value =
      (value == ThemeMode.dark || value == ThemeMode.system && systemIsDark)
          ? ThemeMode.light : ThemeMode.dark;
}

2. MaterialApp wiring

ValueListenableBuilder(
  valueListenable: themeController,
  builder: (_, mode, __) => MaterialApp(
    theme: AppTheme.light, darkTheme: AppTheme.dark, themeMode: mode));

3. Persist explicit choice

เก็บ enum string system/light/dark ใน preferences โหลดก่อนหรือระหว่าง bootstrapโดยมี default system อย่าเก็บ boolเพราะเพิ่ม mode systemภายหลัง migrateยาก

4. Effective brightness

เวลาเลือก icon/overlayใช้ Theme.of(context).brightness ไม่อนุมานจาก controller value เพราะ ThemeMode.system ต้องตาม platform

5. No global context

ThemeControllerไม่ควรถือ BuildContextหรือสี เป็นเจ้าของ modeเท่านั้น Widget/theme builderอ่าน contextและ render

6. ของจริง

wmsapp ใช้ ThemeProvider extends ValueNotifier<ThemeMode> และ MaterialAppมี light/dark theme เป็น patternเรียบง่ายที่เหมาะกับ stateนี้
