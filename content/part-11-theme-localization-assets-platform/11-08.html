tr(en, th) เริ่มเร็ว แต่ scaleมีเพดาน: ARB/gen-l10nให้ key, placeholders, plural/select, toolingและตรวจ missing translationเหมาะเมื่อข้อความโตหรือมีนักแปล

1. Inline helper

String tr(String english, String thai) =>
    AppLanguageController.instance.isThai ? thai : english;

Text(tr('Connection failed', 'เชื่อมต่อล้มเหลว'));

อ่านง่ายสำหรับสองภาษาและแอปทีมเล็ก

2. Inline drawbacks

ข้อความซ้ำ/สะกดไม่ตรง, ค้น missingยาก, ไม่มี key/contextสำหรับนักแปล, plural/interpolationยุ่งและ global helperไม่ทำ widget rebuildเองหาก callerไม่ listen

3. ARB example

// app_en.arb
{"tasksRemaining":"{count, plural, =0{No tasks} one{1 task} other{{count} tasks}}"}

// Widget
Text(AppLocalizations.of(context)!.tasksRemaining(count));

4. Migration strategy

เริ่ม new stringsใน generated localization, สร้าง adapterสำหรับ common labels, migrate screenเมื่อแก้ ไม่ big-bang replaceและไม่ใช้ English sentenceเป็น key

5. Placeholders

อย่าต่อ fragmentเช่น tr('Loaded','โหลดแล้ว') + '$n' เพราะลำดับคำต่างภาษา ใช้ข้อความเต็มพร้อม named placeholder

6. Backend messages

อย่าแปล server detailด้วย string matching ให้ map stable error/status codeเป็น localization keyและมี safe fallbackสำหรับ unknown

7. แบบฝึกหัด

ข้อความ “โหลดแล้ว 1/5 รายการ” ควรออกแบบอย่างไร?

เฉลย

หนึ่ง localization messageพร้อม placeholders loaded/totalและ plural/selectเมื่อจำเป็น ไม่ต่อคำแยกสามส่วน

8. Decision

ใช้ tr helperได้เมื่อสองภาษา/ข้อความน้อย/ทีมเดียว; ขยับ ARBเมื่อมี plural, QA translation, reuse, localeเพิ่มหรือ compile-time missing-key checks
