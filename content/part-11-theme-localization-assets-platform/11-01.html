1. ปัญหาที่ธีมแก้

ลองนึกว่าไม่มีธีม ทุกปุ่มในแอปจะเขียนแบบนี้

FilledButton(
  style: FilledButton.styleFrom(
    backgroundColor: const Color(0xFF2E73B9),
    minimumSize: const Size.fromHeight(54),
    shape: RoundedRectangleBorder(borderRadius: BorderRadius.circular(14)),
  ),
  onPressed: ...,
)

เจ็ดบรรทัดต่อปุ่มหนึ่งอัน คูณด้วยปุ่มสองร้อยอันในแอป ผลที่ตามมา

ปัญหารูปธรรม
เปลี่ยนสีแบรนด์ต้องแก้ทุกที่ค้นหาแทนที่ 200 จุด แล้วพลาดสัก 5 จุด
ปุ่มไม่เหมือนกันโดยไม่ตั้งใจคนหนึ่งเขียน 54 อีกคนเขียน 52
อ่านโค้ดหน้าจอยากตรรกะจมอยู่ในโค้ดจัดหน้าตา
ThemeData คือที่รวมค่าหน้าตาทั้งหมดของแอป ส่งลงไปให้ทุก widget ผ่านต้นไม้ widget โดยอัตโนมัติ

2. โครงสามชั้น

PdaColors / PdaMetrics     ← ค่าดิบ ไม่รู้จัก Flutter (11.3)
        ↓
buildPdaTheme()            ← ประกอบเป็น ThemeData
        ↓
Theme.of(context)          ← จออ่านค่า

สามชั้นนี้แยกกันด้วยเหตุผลเดียวกับ Part 9 — ค่าดิบเปลี่ยนตามฝ่ายออกแบบ ส่วนการประกอบเปลี่ยนตามที่ Flutter รองรับ

3. ColorScheme คือหัวใจ

const scheme = ColorScheme.light(
  primary: PdaColors.primary,
  onPrimary: Colors.white,
  primaryContainer: PdaColors.primarySoft,
  onPrimaryContainer: PdaColors.primaryDark,
  error: PdaColors.danger,
  onError: Colors.white,
  surface: PdaColors.surface,
  onSurface: PdaColors.heading,
  outline: PdaColors.border,
  outlineVariant: PdaColors.divider,
);

สิ่งที่ต้องเข้าใจคือรูปแบบ x คู่กับ onX

ชื่อหมายถึง
primaryสีพื้นของสิ่งที่เด่นที่สุด เช่นปุ่มหลัก
onPrimaryสีของสิ่งที่วางอยู่บน primary เช่นตัวอักษรบนปุ่ม
surfaceสีพื้นของการ์ดและแผง
onSurfaceสีตัวอักษรบนการ์ด

การประกาศเป็นคู่ไม่ใช่แค่ความเรียบร้อย — มันบังคับให้ต้องตอบว่า “ตัวอักษรบนสีนี้จะเป็นสีอะไร” ทุกครั้งที่เพิ่มสีพื้น ซึ่งเป็นคำถามที่คนลืมถามบ่อยที่สุด และ 11.2 จะแสดงให้เห็นว่าลืมแล้วเกิดอะไร

4. ตั้งค่าตามชนิดของ widget

filledButtonTheme: FilledButtonThemeData(
  style: FilledButton.styleFrom(
    backgroundColor: PdaColors.primary,
    foregroundColor: Colors.white,
    disabledBackgroundColor: PdaColors.border,
    disabledForegroundColor: PdaColors.subtitle,
    minimumSize: const Size.fromHeight(PdaMetrics.primaryButtonHeight),
    elevation: 0,
    shape: RoundedRectangleBorder(
      borderRadius: BorderRadius.circular(PdaMetrics.controlRadius),
    ),
    textStyle: const TextStyle(fontSize: 15, fontWeight: FontWeight.w800),
  ),
),

เขียนครั้งเดียว ปุ่มทุกอันในแอปได้หน้าตานี้ทันทีโดยไม่ต้องเขียนอะไรเพิ่ม

FilledButton(onPressed: _scan, child: Text(context.t(AppText.scanPallet)))

สังเกตสองบรรทัดที่คนมักลืม

บรรทัดทำไมสำคัญ
disabledBackgroundColorค่าปริยายของ Material ทำให้ปุ่มที่กดไม่ได้จางมากจนดูเหมือนหายไป ผู้ใช้จะหาปุ่มไม่เจอ ไม่ใช่แค่กดไม่ได้
elevation: 0เงาบนจอเล็กกินที่และทำให้ขอบดูเบลอ ในคลังที่แสงจ้า ขอบชัดสำคัญกว่าความสวย

5. สองค่าที่มีเฉพาะบน PDA

materialTapTargetSize: MaterialTapTargetSize.padded,
visualDensity: VisualDensity.standard,
ค่าทำอะไรทำไมต้องตั้ง
MaterialTapTargetSize.paddedขยายพื้นที่กดให้ถึง 48 แม้ widget จะเล็กกว่าค่าอีกตัวคือ shrinkWrap ซึ่งย่อพื้นที่กดให้เท่ากับที่เห็น — ใช้บนเดสก์ท็อปที่มีเมาส์ได้ แต่บน PDA ที่ใช้นิ้วใส่ถุงมือคือหายนะ
VisualDensity.standardไม่ให้ Flutter บีบ widget ตามแพลตฟอร์มค่าปริยาย adaptivePlatformDensity จะบีบให้แน่นขึ้นบนเดสก์ท็อป ซึ่งทำให้ผลตอนทดสอบบนคอมกับบนเครื่องจริงไม่ตรงกัน

เทสต์บันทึกกฎนี้ไว้

test('พื้นที่กดไม่ถูกย่อ', () {
  expect(buildPdaTheme().materialTapTargetSize, MaterialTapTargetSize.padded);
});

6. ธีมเป็นค่าตั้งต้น ไม่ใช่กฎเหล็ก

จอที่ต้องการหน้าตาต่างจากธีมยังทำได้

FilledButton(
  style: FilledButton.styleFrom(backgroundColor: PdaColors.danger),
  onPressed: _delete,
  child: Text(context.t(AppText.confirm)),
)

ค่าที่ระบุจะทับค่าจากธีมเฉพาะที่ระบุ ส่วนที่เหลือ เช่นความสูงและมุมโค้ง ยังมาจากธีม

เกณฑ์: ถ้าเขียนทับซ้ำเกินสองที่ แปลว่าควรย้ายขึ้นไปเป็นค่าในธีม หรือเป็น widget ของตัวเอง — เขียนทับเพราะจอนั้นพิเศษจริง ๆ ได้ แต่ต้องเป็นข้อยกเว้น ไม่ใช่นิสัย

7. อ่านค่าจากธีมในจอ

Text(
  context.t(AppText.pallets),
  style: Theme.of(context).textTheme.titleLarge,
)
อย่าเขียนให้เขียน
style: TextStyle(fontSize: 18, fontWeight: FontWeight.w800)style: Theme.of(context).textTheme.titleLarge
color: const Color(0xFF2E73B9)color: Theme.of(context).colorScheme.primary

Theme.of(context) ไต่ต้นไม้ widget ขึ้นไปหา Theme ที่ใกล้ที่สุด ผลข้างเคียงที่เป็นประโยชน์คือ ห่อส่วนใดส่วนหนึ่งของจอด้วย Theme ตัวใหม่ แล้วเฉพาะส่วนนั้นจะใช้ธีมอื่นได้

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
เปลี่ยนธีมแล้วบางจอไม่เปลี่ยนจอนั้นเขียนสีลงไปตรง ๆอ่านผ่าน Theme.of
ปุ่มที่กดไม่ได้หายไปจากสายตาไม่ได้ตั้ง disabledBackgroundColorตั้งให้เห็นแต่จาง
หน้าตาบนคอมกับบนเครื่องจริงไม่ตรงกันvisualDensity ปรับตามแพลตฟอร์มตั้งเป็น standard
Theme.of(context) ได้ธีมเปล่าเรียกจาก context ที่อยู่เหนือ MaterialAppใช้ Builder คั่น หรือย้ายไป widget ลูก
ปุ่มหลายแบบในจอเดียวเขียนทับกันคนละที่ตกลงว่าปุ่มมีกี่ชนิด แล้วตั้งในธีม

9. แบบฝึกหัด

ฝ่ายออกแบบขอให้ปุ่ม “ยืนยัน” ทุกอันในแอปเปลี่ยนจากสีน้ำเงินเป็นสีเขียว แต่ปุ่มอื่นยังเป็นน้ำเงินเหมือนเดิม

  1. ควรทำอย่างไร
  2. ถ้าใช้วิธีเขียนทับที่ปุ่มยืนยันทุกอัน จะเกิดอะไรในหกเดือน
แนวคำตอบ

1. สร้าง widget ของตัวเอง ไม่ใช่เขียนทับ และไม่ใช่เพิ่มค่าในธีม

class ConfirmButton extends StatelessWidget {
  const ConfirmButton({super.key, required this.onPressed, required this.label});

  final VoidCallback? onPressed;
  final String label;

  @override
  Widget build(BuildContext context) => FilledButton(
    style: FilledButton.styleFrom(
      backgroundColor: PdaColors.success,
      foregroundColor: PdaColors.onSuccess,   // คู่กันเสมอ (11.2)
    ),
    onPressed: onPressed,
    child: Text(label),
  );
}

ทำไมไม่ใส่ในธีม เพราะธีมตั้งค่าตามชนิดของ widget ไม่ใช่ตามความหมาย — Flutter ไม่มีชนิดที่ชื่อ “ปุ่มยืนยัน” การจะแยกได้ต้องสร้างชนิดนั้นขึ้นมาเอง

2. จะได้ปุ่มยืนยันสามเฉด เพราะคนที่มาทีหลังคัดลอกจากจอที่ตัวเองเปิดอยู่ และบางจอถูกเขียนก่อนที่ฝ่ายออกแบบจะเปลี่ยนใจครั้งที่สอง

ปัญหาที่แท้จริงคือ ไม่มีที่เดียวที่ตอบได้ว่า “ปุ่มยืนยันหน้าตาอย่างไร” — และการมี ConfirmButton แก้ทั้งข้อนี้และข้อที่ว่าคนอ่านโค้ดเห็นเจตนาทันที

10. สรุป

  • ธีมทำให้เปลี่ยนหน้าตาทั้งแอปได้ที่จุดเดียว
  • ColorScheme ประกาศสีเป็นคู่ x/onX ซึ่งบังคับให้ตอบว่าตัวอักษรบนสีนั้นเป็นสีอะไร
  • ตั้ง materialTapTargetSize และ visualDensity ให้ตรงกับอุปกรณ์จริง
  • ธีมแยกตามชนิดของ widget ความหมายต้องแยกด้วยการสร้าง widget ของตัวเอง
