1. ปัญหา

Android ต้องการไอคอนแอปหลายขนาด แยกตามความหนาแน่นของจอ

android/app/src/main/res/
  mipmap-mdpi/ic_launcher.png       48×48
  mipmap-hdpi/ic_launcher.png       72×72
  mipmap-xhdpi/ic_launcher.png      96×96
  mipmap-xxhdpi/ic_launcher.png     144×144
  mipmap-xxxhdpi/ic_launcher.png    192×192

ทำมือได้ แต่ต้องทำใหม่ทุกครั้งที่โลโก้เปลี่ยน และพลาดขนาดเดียวก็จะได้ไอคอนเบลอบนเครื่องบางรุ่น

2. ให้เครื่องมือทำ

# pubspec.yaml
dev_dependencies:
  flutter_launcher_icons: ^0.14.4

flutter_launcher_icons:
  android: true
  ios: false
  image_path: "assets/icons/icon-absolute-cut.png"
dart run flutter_launcher_icons

สร้างไฟล์ทุกขนาดให้อัตโนมัติ สั่งใหม่เมื่อโลโก้เปลี่ยน

ค่าความหมาย
android: trueสร้างให้ Android
ios: falseข้าม iOS — โปรเจกต์นี้ลงเฉพาะ PDA Android
image_pathไฟล์ต้นฉบับ ควรเป็น PNG สี่เหลี่ยมจัตุรัสอย่างน้อย 1024×1024
อยู่ใน dev_dependencies เพราะใช้เฉพาะตอน build ไม่ได้ติดไปกับแอป — ถ้าเผลอใส่ใน dependencies แอปจะใหญ่ขึ้นโดยไม่ได้อะไร

3. Adaptive icon ของ Android

Android รุ่นใหม่แสดงไอคอนในกรอบที่รูปทรงต่างกันตามผู้ผลิต — วงกลม สี่เหลี่ยมมน หรือทรงหยดน้ำ ไอคอนจึงถูกแบ่งเป็นสองชั้น

flutter_launcher_icons:
  android: true
  image_path: "assets/icons/icon.png"

  # ชั้นหน้า — โลโก้ ต้องมีพื้นที่ว่างรอบเผื่อถูกตัด
  adaptive_icon_foreground: "assets/icons/icon-foreground.png"
  # ชั้นหลัง — สีพื้นหรือรูป
  adaptive_icon_background: "#062B50"
กฎที่ต้องรู้: ชั้นหน้าขนาด 108×108 หน่วย แต่มีเพียง 66×66 ตรงกลางที่รับประกันว่าจะมองเห็น ที่เหลือถูกตัดหรือใช้ทำเอฟเฟกต์ — โลโก้ที่เต็มกรอบพอดีจะถูกตัดขอบบนเครื่องที่ใช้กรอบวงกลม

วิธีตรวจที่เร็วที่สุดคือวางวงกลมทับตรงกลางไฟล์ต้นฉบับ ถ้าส่วนสำคัญของโลโก้อยู่นอกวงกลม แปลว่าต้องย่อ

4. ทำไมเรื่องนี้สำคัญบน PDA

บนโทรศัพท์ส่วนตัว ผู้ใช้มีแอปเป็นร้อยและจำตำแหน่งได้ แต่บน PDA ของคลัง สถานการณ์ต่างออกไป

สถานการณ์ผลของไอคอนที่แยกไม่ออก
มีแอป WMS สองรุ่นบนเครื่องเดียว — ตัวจริงกับตัวทดสอบพนักงานเปิดตัวทดสอบแล้วบันทึกข้อมูลลงเซิร์ฟเวอร์ทดสอบทั้งกะ
เครื่องเปลี่ยนมือทุกกะคนใหม่หาแอปไม่เจอ ต้องถาม
ใส่ถุงมือ กดพลาดง่ายเปิดแอปผิดแล้วต้องย้อนกลับ

แถวแรกเป็นปัญหาที่เกิดจริงและแพง วิธีแก้ที่ตรงที่สุดคือให้ build ที่ชี้เซิร์ฟเวอร์ทดสอบมีไอคอนและชื่อคนละสี

# สร้างไอคอนคนละชุดตามสภาพแวดล้อม
flutter_launcher_icons:
  android: true
  image_path: "assets/icons/icon-prod.png"

# แล้วสั่งด้วยไฟล์ตั้งค่าอีกไฟล์ตอน build ตัวทดสอบ
dart run flutter_launcher_icons -f flutter_launcher_icons-dev.yaml

ต่อยอดจาก 10.2 ที่ใช้ --dart-define ตรึงเซิร์ฟเวอร์ — ไอคอนที่ต่างกันทำให้ความแตกต่างนั้นมองเห็นได้ก่อนเปิดแอป

5. ชื่อแอปกับหน้าจอเริ่มต้น

<!-- android/app/src/main/AndroidManifest.xml -->
<application
    android:label="ACETEC WMS"
    android:icon="@mipmap/ic_launcher">

ชื่อนี้คือสิ่งที่แสดงใต้ไอคอน ต่างจาก MaterialApp.title ที่ใช้ในตัวสลับแอปของระบบ

ส่วนหน้าจอที่แสดงระหว่างแอปกำลังเริ่ม ตั้งด้วยแพ็กเกจแยกอีกตัว

dev_dependencies:
  flutter_native_splash: ^2.4.0

flutter_native_splash:
  color: "#062B50"
  image: assets/icons/splash.png
  android_12:
    color: "#062B50"
    image: assets/icons/splash-android12.png
Android 12 ขึ้นไปเปลี่ยนวิธีทำหน้าจอเริ่มต้นทั้งหมด และบังคับรูปทรงวงกลม — ต้องตั้งค่าแยกในส่วน android_12 ไม่งั้นจะได้หน้าจอที่ต่างกันระหว่างเครื่องรุ่นเก่ากับรุ่นใหม่

6. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
สั่งสร้างแล้วไอคอนไม่เปลี่ยนAndroid จำไอคอนเก่าไว้ถอนแอปแล้วติดตั้งใหม่
ไอคอนเบลอไฟล์ต้นฉบับเล็กเกินใช้ 1024×1024 ขึ้นไป
โลโก้ถูกตัดขอบบนบางเครื่องไม่เผื่อพื้นที่ปลอดภัยของ adaptive iconให้ส่วนสำคัญอยู่ใน 66×66 ตรงกลาง
ไอคอนมีขอบขาวรอบไฟล์ต้นฉบับมีพื้นหลังทึบใช้ PNG ที่พื้นหลังโปร่งใส
แอปทดสอบกับแอปจริงแยกไม่ออกใช้ไอคอนเดียวกันทำไอคอนคนละชุดต่อสภาพแวดล้อม

7. แบบฝึกหัด

ทีมจะส่ง PDA ให้สามสาขา แต่ละสาขาใช้เซิร์ฟเวอร์ของตัวเอง และเคยมีเหตุการณ์ที่พนักงานเปิดแอปที่ชี้ผิดสาขา

  1. ไอคอนช่วยแก้ปัญหานี้ได้แค่ไหน
  2. ควรทำอะไรเพิ่ม
แนวคำตอบ

1. ช่วยได้ถ้าแต่ละเครื่องมีแอปหลายตัว แต่แก้ไม่ได้ถ้ามีตัวเดียว

ต้องแยกให้ออกก่อนว่าเป็นสถานการณ์ไหน

สถานการณ์ไอคอนช่วยไหม
เครื่องหนึ่งมีแอปหลายตัว ชี้คนละสาขาช่วยมาก — เห็นก่อนกด
เครื่องหนึ่งมีแอปตัวเดียว แต่สลับ profile ได้ (Part 10)ไม่ช่วยเลย เพราะไอคอนเดียวกันตลอด

2. ถ้าเป็นกรณีที่สอง สิ่งที่ช่วยได้จริงคือทำให้เซิร์ฟเวอร์ที่ใช้อยู่เห็นตลอดเวลา ไม่ใช่แค่ตอนเปิดแอป

  • แสดงชื่อ profile บนแถบหัวจอทุกจอ ตามที่ 10.12 สรุปไว้ว่า “ต่อผิดเครื่อง” เจอบ่อยกว่า “ต่อไม่ได้”
  • ให้สีของแถบหัวจอต่างกันตามสาขา — มองเห็นจากมุมตาโดยไม่ต้องอ่าน
  • ยืนยันอีกครั้งตอนทำรายการที่ย้อนกลับยาก โดยแสดงชื่อสาขาในกล่องยืนยัน

ข้อที่สองมีพลังมากในงานคลัง เพราะผู้ใช้จำ “แถบสีเขียว = สาขาเรา” ได้เร็วกว่าอ่านชื่อ และรู้ตัวทันทีเมื่อเห็นแถบสีที่ไม่คุ้น

แต่คำถามที่ควรถามก่อนทั้งหมดนี้: ทำไมพนักงานสาขาหนึ่งถึงเข้าเซิร์ฟเวอร์อีกสาขาได้ตั้งแต่แรก — ถ้าบัญชีผูกกับสาขา เซิร์ฟเวอร์ควรปฏิเสธการเข้าสู่ระบบเลย ซึ่งแก้ปัญหาที่ต้นเหตุ ส่วนไอคอนกับสีเป็นแค่การช่วยให้รู้ตัวเร็วขึ้น

นี่เป็นรูปแบบเดียวกับ 8.9 — การซ่อนปุ่มตาม role ไม่ใช่การป้องกัน เซิร์ฟเวอร์ต้องบังคับ

8. สรุป

  • ใช้ flutter_launcher_icons สร้างทุกขนาด อย่าทำมือ
  • adaptive icon มีพื้นที่ปลอดภัยแค่ 66×66 ตรงกลางจาก 108×108
  • อยู่ใน dev_dependencies เพราะใช้เฉพาะตอน build
  • ไอคอนคนละชุดต่อสภาพแวดล้อม ทำให้เห็นความต่างก่อนเปิดแอป
  • Android 12 ต้องตั้งค่าหน้าจอเริ่มต้นแยก

บทหน้า: แถบสถานะ ปุ่มย้อนกลับ และพื้นที่ที่แอปวาดได้จริง
