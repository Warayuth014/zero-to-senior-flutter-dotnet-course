ต้องผ่านอะไรมาก่อน: 11.1
จบบทนี้แล้วจะทำได้: แยกออกว่าข้อความไหนเป็นของเรา ข้อความไหนเป็นของ Flutter และรู้ว่าแต่ละอย่างแปลอย่างไร

1. ข้อความในแอปมีสองประเภท

ข้อความของเราข้อความของ Flutter
ตัวอย่าง“สแกนพาเลท”, “ไม่มีพาเลทในโซนนี้”ปุ่ม OK/Cancel ในตัวเลือกวันที่, คำว่า “Search”, ข้อความ “Paste” ในเมนูคลิกขวา
ใครเขียนเราทีม Flutter
แปลอย่างไรเราแปลเอง (11.7, 11.8)เปิดใช้ delegate ที่มีมาให้แล้ว
ลืมแล้วเกิดอะไรเห็นภาษาอังกฤษบนหน้าจอที่เหลือเป็นไทยตัวเลือกวันที่ขึ้นภาษาอังกฤษทั้งกล่อง

บทนี้พูดถึงประเภทที่สอง ซึ่งใช้แรงน้อยที่สุดแต่คนลืมบ่อยที่สุด เพราะมันโผล่เฉพาะในหน้าจอที่ไม่ค่อยได้เปิด

2. เปิดใช้งาน

# pubspec.yaml
dependencies:
  flutter_localizations:
    sdk: flutter
  intl: any
sdk: flutter แปลว่าแพ็กเกจนี้มาพร้อม Flutter SDK ไม่ได้โหลดจากอินเทอร์เน็ต ส่วน intl: any ปล่อยให้ Flutter เลือกรุ่นที่เข้ากับ SDK ที่ติดตั้งอยู่ ถ้าตรึงรุ่นเองมักจะชนกัน
MaterialApp(
  locale: controller.locale,
  supportedLocales: const [Locale('en'), Locale('th')],
  localizationsDelegates: const [
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  home: const PdaHomeScreen(),
)

3. สาม delegate ทำอะไรกัน

delegateแปลอะไรถ้าไม่ใส่
GlobalMaterialLocalizationsข้อความใน widget ของ Material — ตัวเลือกวันที่และเวลา, SearchBar, ปุ่มใน AboutDialog, ป้ายกำกับของ Scaffoldขึ้นภาษาอังกฤษหมด
GlobalWidgetsLocalizationsทิศทางการเขียน (ซ้ายไปขวา หรือขวาไปซ้าย)ภาษาอาหรับและฮีบรูจะแสดงผิดทิศ
GlobalCupertinoLocalizationsข้อความใน widget สไตล์ iOSขึ้นภาษาอังกฤษ ถ้าใช้ widget เหล่านั้น

ทั้งสามตัวไม่ได้แปลข้อความของเราแม้แต่คำเดียว — เป็นความเข้าใจผิดที่พบบ่อยที่สุดเรื่องนี้

// สาม delegate นี้ไม่ได้แปลข้อความของเรา แต่แปลข้อความที่ฝังอยู่ใน
// Material, Cupertino และ widget พื้นฐาน ถ้าไม่ใส่ ตัวเลือกวันที่จะขึ้น
// ภาษาอังกฤษแม้ผู้ใช้เลือกไทย
localizationsDelegates: const [
  GlobalMaterialLocalizations.delegate,
  ...
],

4. เห็นผลตรงไหนบ้าง

ลองเรียกตัวเลือกวันที่ดู

final picked = await showDatePicker(
  context: context,
  initialDate: DateTime.now(),
  firstDate: DateTime(2020),
  lastDate: DateTime(2030),
);
ส่วนไม่มี delegateมี delegate + locale th
ชื่อเดือนJanuaryมกราคม
ชื่อวันM T W T Fจ อ พ พฤ ศ
ปุ่มCANCEL / OKยกเลิก / ตกลง
ข้อความช่วยเหลือSelect dateเลือกวันที่

ที่อื่นที่ได้ประโยชน์โดยไม่ต้องทำอะไรเพิ่ม

  • ข้อความสำหรับโปรแกรมอ่านหน้าจอ เช่น “ปุ่ม” “แถบเลื่อน”
  • ข้อความ “แสดง x จาก y” ใน PaginatedDataTable
  • เมนูคัดลอก–วางเมื่อกดค้างในช่องข้อความ
ข้อสุดท้ายมีผลกับ PDA จริง — ผู้ใช้ที่กดค้างในช่องรหัสพาเลทเพื่อวางค่าที่คัดลอกมา จะเห็นเมนูภาษาอังกฤษถ้าไม่ได้ตั้ง

5. supportedLocales สำคัญกว่าที่ดู

supportedLocales: const [Locale('en'), Locale('th')],

รายการนี้บอกสองอย่าง

บอกอะไรผล
ภาษาที่แอปรองรับถ้าเครื่องตั้งเป็นภาษาญี่ปุ่น Flutter จะเลือกตัวแรกในรายการ
ลำดับความสำคัญตัวแรกคือค่าสำรอง ควรเป็นภาษาที่แปลครบที่สุด

วิธีที่ Flutter เลือก locale เมื่อไม่ได้กำหนด locale เอง

1. หา locale ที่ตรงทั้งภาษาและประเทศ  (th_TH ตรงกับ th_TH)
2. หา locale ที่ตรงเฉพาะภาษา          (th_TH ตรงกับ th)
3. ใช้ตัวแรกใน supportedLocales

ในแอปนี้เรากำหนด locale เองจากที่ผู้ใช้เลือก จึงข้ามการเดาไปทั้งหมด ซึ่งเป็นสิ่งที่ถูกต้องสำหรับแอปที่มีปุ่มสลับภาษา — ถ้าผู้ใช้เลือกไว้แล้ว อย่าให้การตั้งค่าของเครื่องมาทับ

6. เทสต์ว่าส่ง locale ลงไปจริง

testWidgets('MaterialApp ได้ locale ตามที่เลือก', (tester) async {
  await pumpApp(tester);

  await tester.tap(find.byKey(const Key('language-button')));
  await tester.pumpAndSettle();

  final app = tester.widget<MaterialApp>(find.byType(MaterialApp));
  // ถ้าไม่ส่ง locale ลงไป widget สำเร็จรูปของ Material จะยังเป็นอังกฤษ
  expect(app.locale, const Locale('th'));
});

เทสต์นี้ตรวจสิ่งที่มองไม่เห็นบนหน้าจอหลัก — ข้อความของเราเปลี่ยนเป็นไทยแล้วดูเหมือนถูกต้อง ทั้งที่ locale อาจยังไม่ถูกส่งลงไป และจะไปพบตอนเปิดตัวเลือกวันที่ในอีกสามเดือน

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ใส่ delegate แล้วข้อความของเรายังไม่แปลเข้าใจผิดว่า delegate แปลให้ทุกอย่างข้อความของเราต้องแปลเอง (11.7)
ตัวเลือกวันที่ยังเป็นอังกฤษไม่ได้ส่ง locale หรือลืม delegateใส่ทั้งสองอย่าง
No MaterialLocalizations foundใช้ widget ของ Material นอก MaterialAppห่อด้วย MaterialApp หรือ Localizations
เทสต์ล้มด้วยข้อความเดียวกันเทสต์สร้าง widget โดยไม่มี MaterialAppห่อด้วย MaterialApp ในเทสต์
ภาษาเปลี่ยนแต่บางส่วนของจอไม่เปลี่ยนส่วนนั้นไม่ได้อยู่ใต้ MaterialApp ที่ rebuildตรวจว่า ListenableBuilder ครอบถูกที่

8. แบบฝึกหัด

แอปรองรับไทยกับอังกฤษ ผู้ใช้คนหนึ่งตั้งเครื่องเป็นภาษาลาว

  1. เขาจะเห็นภาษาอะไร
  2. ถ้าอยากให้เห็นภาษาไทยแทน ควรทำอย่างไร และควรทำไหม
แนวคำตอบ

1. ในแอปนี้เห็นภาษาอังกฤษ เพราะเรากำหนด locale เองจากค่าที่ผู้ใช้เลือก และค่าเริ่มต้นคืออังกฤษ — การตั้งค่าของเครื่องไม่มีผลเลย

ถ้าไม่ได้กำหนด locale เอง Flutter จะไล่ตามขั้นใน §5 หาไม่เจอ แล้วใช้ Locale('en') ซึ่งเป็นตัวแรก ผลเหมือนกัน

2. ทำได้ด้วย localeResolutionCallback

localeResolutionCallback: (deviceLocale, supported) {
  // ลาวอ่านไทยได้มากกว่าอ่านอังกฤษ
  if (deviceLocale?.languageCode == 'lo') return const Locale('th');
  ...
},

แต่ไม่ควรทำในแอปนี้ ด้วยเหตุผลสามข้อ

  • เป็นการเดาแทนผู้ใช้ จากสมมติฐานเรื่องภาษาที่อาจไม่จริงสำหรับคนคนนั้น
  • ผู้ใช้เปลี่ยนเองได้อยู่แล้วด้วยปุ่มเดียว การเดาจึงไม่ได้แก้ปัญหาที่แก้ไม่ได้
  • เมื่อเดาผิด ผู้ใช้จะไม่รู้ว่าทำไมแอปขึ้นภาษาที่ตัวเองไม่ได้เลือก

สิ่งที่ควรทำแทนคือ ทำให้ปุ่มสลับภาษาหาเจอง่ายตั้งแต่หน้าแรก ซึ่งในแอปนี้อยู่บนแถบหัวจอตลอดเวลา ไม่ได้ซ่อนอยู่ในหน้าตั้งค่า

หลักเดียวกับ 10.11 — เมื่อต้องเดาเจตนาของผู้ใช้ ให้ถามหรือทำให้เขาเปลี่ยนเองได้ง่าย แทนที่จะเดา

9. สรุป

  • ข้อความในแอปมีสองประเภท และ delegate แปลให้เฉพาะของ Flutter
  • สาม delegate ใส่ครั้งเดียวได้ผลทั้งแอป
  • supportedLocales ตัวแรกคือค่าสำรอง
  • เมื่อผู้ใช้เลือกภาษาไว้แล้ว อย่าให้การตั้งค่าของเครื่องมาทับ
  • เขียนเทสต์ตรวจว่า locale ถูกส่งลงไปจริง

บทหน้า: Locale คืออะไรกันแน่ และ delegate ทำงานอย่างไรข้างใน
