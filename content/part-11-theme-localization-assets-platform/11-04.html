ระดับ: กลางใช้เวลา: 50–65 นาทีลงมือทำ: เทียบฟอนต์ไทยสองแบบบนเครื่องจริง
ต้องผ่านอะไรมาก่อน: 11.1
จบบทนี้แล้วจะทำได้: เลือกและติดตั้งฟอนต์ไทยได้ถูก และรู้ว่าทำไมข้อความไทยต้องการที่มากกว่าอังกฤษ

1. ปัญหาที่มองไม่เห็นจนกว่าจะเห็น

ภาษาไทยเขียนซ้อนกันได้ถึงสี่ชั้น

       ่           ← วรรณยุกต์ (ชั้นบนสุด)
      ิ            ← สระบน
    ป              ← พยัญชนะ
      ุ            ← สระล่าง

คำว่า “ปุ๋ย” หรือ “กี่” กินความสูงมากกว่าตัวอักษรอังกฤษที่สูงเท่ากันอย่างชัดเจน ผลคือ

ปัญหาเกิดเมื่อ
วรรณยุกต์ถูกตัดหายกล่องข้อความสูงพอดีเกินไป
สระบนของบรรทัดล่างชนสระล่างของบรรทัดบนheight เป็นค่าปริยาย
ข้อความไทยดูอัดแน่นกว่าอังกฤษในกล่องเดียวกันออกแบบโดยดูแต่ข้อความอังกฤษ
อาการทั้งสามไม่โผล่ตอนทดสอบด้วยคำว่า “ทดสอบ” ซึ่งไม่มีสระบนล่างเลย — ต้องทดสอบด้วยคำที่มีวรรณยุกต์บนสระบน เช่น “ปุ๋ย” “กี่” “เดี๋ยว”

2. ทางแก้บรรทัดเดียว

// height 1.4 ไม่ใช่ค่าปริยาย 1.0 เพราะสระบนล่างของไทยต้องการที่
bodyLarge: TextStyle(fontSize: 14.5, color: PdaColors.heading, height: 1.4),
bodyMedium: TextStyle(fontSize: 13.5, color: PdaColors.heading, height: 1.4),
bodySmall: TextStyle(fontSize: 12.5, color: PdaColors.subtitle, height: 1.35),
height ใน Flutter เป็นตัวคูณของ fontSize ไม่ใช่หน่วยพิกเซล — fontSize: 14 กับ height: 1.4 ได้ความสูงบรรทัด 19.6

เทสต์บันทึกกฎนี้ไว้ เพื่อไม่ให้ใครลบทิ้งเพราะคิดว่าเป็นค่าที่ไม่จำเป็น

test('ตัวอักษรเนื้อความมี height เผื่อสระไทย', () {
  final theme = buildPdaTheme();
  // ค่าปริยายคือ null ซึ่งแปลว่า 1.0 และทำให้สระบนล่างชนกัน
  expect(theme.textTheme.bodyMedium!.height, greaterThanOrEqualTo(1.3));
  expect(theme.textTheme.bodyLarge!.height, greaterThanOrEqualTo(1.3));
});

3. ฟอนต์ปริยายรองรับไทยไหม

รองรับ แต่ต้องเข้าใจว่ารองรับอย่างไร

แพลตฟอร์มสิ่งที่เกิดขึ้นกับข้อความไทย
AndroidRoboto ไม่มีอักษรไทย ระบบจึงสลับไปใช้ Noto Sans Thai ที่ติดมากับเครื่องโดยอัตโนมัติ
iOSสลับไป Thonburi
Webขึ้นกับฟอนต์ที่เบราว์เซอร์และระบบปฏิบัติการมี

กลไกนี้เรียกว่า font fallback ทำงานได้ดี แต่มีผลข้างเคียงที่ต้องรู้

ผลข้างเคียงรายละเอียด
หน้าตาต่างกันในแต่ละเครื่องAndroid รุ่นต่างกันมีฟอนต์ไทยคนละรุ่น ความกว้างไม่เท่ากัน
ประโยคที่ปนสองภาษาใช้ฟอนต์คนละตัว“สแกน Pallet PLT-001” — คำไทยเป็นฟอนต์หนึ่ง คำอังกฤษเป็นอีกฟอนต์ ความหนาไม่เท่ากัน
น้ำหนักตัวหนาอาจไม่มีฟอนต์สำรองบางตัวไม่มี w800 ระบบจะเลียนแบบโดยทำให้หนาขึ้นเอง ซึ่งดูไม่เรียบร้อย

wms_absolute_mobile ยอมรับผลข้างเคียงนี้และไม่ได้ฝังฟอนต์ ส่วน wmsapp เลือกอีกทาง

4. ฝังฟอนต์เอง

# wmsapp/pubspec.yaml
flutter:
  fonts:
    - family: Sarabun
      fonts:
        - asset: assets/fonts/Sarabun-Regular.ttf
        - asset: assets/fonts/Sarabun-Medium.ttf
          weight: 500
        - asset: assets/fonts/Sarabun-Bold.ttf
          weight: 700
ส่วนความหมาย
familyชื่อที่ใช้อ้างในโค้ด TextStyle(fontFamily: 'Sarabun')
weightต้องตรงกับ FontWeight ที่ใช้ — w500 คือ 500
ไฟล์ที่ไม่ระบุ weightถือเป็น 400

ตั้งเป็นฟอนต์ปริยายทั้งแอปด้วย

ThemeData(fontFamily: 'Sarabun', ...)
Sarabun เป็นฟอนต์ไทยจากโครงการฟอนต์แห่งชาติ ใช้ฟรีในเชิงพาณิชย์ได้ ออกแบบมาให้อ่านง่ายบนหน้าจอ และมีทั้งอักษรไทยและละตินในไฟล์เดียว ซึ่งแก้ปัญหาประโยคปนสองภาษาได้

5. ราคาของการฝังฟอนต์

ต้นทุนตัวเลขคร่าว ๆ
ขนาดแอปโตขึ้นฟอนต์ไทยหนึ่งน้ำหนักราว 100–300 KB คูณจำนวนน้ำหนักที่ใส่
ต้องตรวจสัญญาอนุญาตฟอนต์เชิงพาณิชย์หลายตัวห้ามฝังในแอป
ต้องดูแลไฟล์ฟอนต์เป็นไฟล์ binary ใน git ที่ diff ไม่ได้

เมื่อไหร่ควรฝัง

ควรฝังไม่ต้องฝัง
หน้าตาต้องเหมือนกันทุกเครื่องแอปภายในที่เครื่องเป็นรุ่นเดียวกันหมด
มีประโยคปนไทย–อังกฤษเยอะข้อความส่วนใหญ่เป็นภาษาเดียว
แบรนด์กำหนดฟอนต์มาไม่มีข้อกำหนดเรื่องฟอนต์
ต้องใช้น้ำหนักที่ฟอนต์ระบบไม่มีใช้แค่ปกติกับหนา

สังเกตว่าทั้งสองโปรเจกต์เลือกไม่เหมือนกัน และทั้งคู่มีเหตุผล — wmsapp มีข้อความไทยเยอะกว่ามาก ส่วน wms_absolute_mobile ใช้อังกฤษเป็นค่าเริ่มต้น (11.7)

6. อีกสองเรื่องที่ต่างจากอังกฤษ

ภาษาไทยไม่มีช่องว่างระหว่างคำ

Flutter ตัดบรรทัดภาษาไทยได้ เพราะเอนจินข้อความรู้จักขอบเขตคำของไทย แต่ผลที่ได้ไม่สมบูรณ์เสมอไป โดยเฉพาะกับชื่อเฉพาะและคำทับศัพท์ ถ้าเจอการตัดที่แปลก ให้ใช้

Text('ข้อความยาว​ที่อยากให้ตัดตรงนี้')   // U+200B = จุดตัดที่มองไม่เห็น

ข้อความไทยยาวกว่าอังกฤษ

อังกฤษไทยยาวขึ้น
Saveบันทึกราว 1.5 เท่า
Cancelยกเลิกราว 1.2 เท่า
Sign outออกจากระบบราว 1.4 เท่า

ปุ่มที่พอดีกับคำอังกฤษจะล้นเมื่อสลับเป็นไทย ทางแก้ที่ใช้ได้จริงคือออกแบบโดยดูภาษาที่ยาวที่สุดก่อน แล้วภาษาอื่นจะพอดีเอง

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
วรรณยุกต์หายบนบางเครื่องกล่องสูงพอดีเกินตั้ง height อย่างน้อย 1.3
ทดสอบแล้วไม่เจอปัญหา แต่ผู้ใช้เจอทดสอบด้วยคำที่ไม่มีสระบนล่างใช้ “ปุ๋ย” “เดี๋ยว” เป็นคำทดสอบมาตรฐาน
ปุ่มล้นเมื่อสลับเป็นไทยออกแบบด้วยข้อความอังกฤษออกแบบด้วยภาษาที่ยาวที่สุด
ตัวหนาดูเบลอระบบเลียนแบบตัวหนาเพราะไม่มีไฟล์น้ำหนักนั้นฝังไฟล์น้ำหนักที่ใช้จริง หรือใช้เฉพาะน้ำหนักที่มี
ฟอนต์ไม่ขึ้นทั้งที่ใส่ใน pubspec แล้วยังไม่ได้รีสตาร์ทแอปhot reload ไม่พอ ต้อง flutter run ใหม่

8. แบบฝึกหัด

ผู้ใช้รายงานว่า “ตัวหนังสือในตารางบางแถวมีขีดข้างบนหายไป” แต่ส่งภาพมาแล้วเห็นแค่บางแถว

  1. สาเหตุน่าจะเป็นอะไร
  2. จะยืนยันอย่างไร
แนวคำตอบ

1. แถวที่มีปัญหาน่าจะเป็นแถวที่มีคำที่มีวรรณยุกต์บนสระบน เช่น “กี่” หรือ “ปุ๋ย” ส่วนแถวอื่นมีแค่พยัญชนะกับสระข้าง จึงไม่เห็นปัญหา

สาเหตุมักเป็นอย่างใดอย่างหนึ่ง

สาเหตุวิธีสังเกต
กล่องมีความสูงตายตัวมี SizedBox(height: ...) หรือ Container(height: ...) ครอบอยู่
height ต่ำเกินทุกแถวโดนเหมือนกัน แต่เห็นชัดเฉพาะแถวที่มีวรรณยุกต์
มี ClipRect หรือ OverflowBoxขีดถูกตัดตรง ๆ ไม่ใช่จางหาย

2. เขียนเทสต์ที่วัดความสูงจริงเทียบกัน

testWidgets('แถวที่มีวรรณยุกต์ต้องสูงไม่น้อยกว่าแถวธรรมดา', (tester) async {
  await tester.pumpWidget(wrap(Column(children: const [
    PalletRow(key: Key('plain'), name: 'พาเลท'),
    PalletRow(key: Key('tonal'), name: 'ปุ๋ยเคมี'),
  ])));

  final plain = tester.getSize(find.byKey(const Key('plain')));
  final tonal = tester.getSize(find.byKey(const Key('tonal')));

  // ถ้ากล่องถูกบังคับความสูงไว้ สองค่านี้จะเท่ากันเป๊ะ ซึ่งคือตัวปัญหา
  expect(tonal.height, greaterThanOrEqualTo(plain.height));
});

วิธีที่เร็วกว่าสำหรับการยืนยันครั้งแรกคือเปิด debugPaintSizeEnabled = true แล้วดูว่าขอบของกล่องตัดผ่านตัวอักษรตรงไหน

สิ่งที่ควรทำต่อ: ตั้งคำทดสอบมาตรฐานของโปรเจกต์ไว้ชุดหนึ่ง เช่น 'ปุ๋ยเคมี เดี๋ยวกี่โมง' แล้วใช้คำนี้ในทุกเทสต์ที่วาดข้อความไทย ปัญหาแบบนี้จะถูกจับตั้งแต่ก่อนถึงมือผู้ใช้

9. สรุป

  • ภาษาไทยซ้อนได้สี่ชั้น ต้องการความสูงบรรทัดมากกว่าอังกฤษ
  • ตั้ง height อย่างน้อย 1.3 กับข้อความเนื้อความ
  • ฟอนต์ปริยายรองรับไทยผ่าน fallback แต่หน้าตาต่างกันในแต่ละเครื่อง
  • ฝังฟอนต์เมื่อต้องการหน้าตาที่แน่นอน หรือมีประโยคปนสองภาษาเยอะ
  • ออกแบบด้วยภาษาที่ยาวที่สุด แล้วภาษาอื่นจะพอดีเอง
  • ทดสอบด้วยคำที่มีวรรณยุกต์บนสระบนเสมอ
