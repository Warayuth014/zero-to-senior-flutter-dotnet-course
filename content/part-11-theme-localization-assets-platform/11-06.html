Locale เป็น dataของแอป: MaterialAppรับ Locale, delegatesและ supported localesร่วมกัน ภาษาเปลี่ยนต้อง rebuildเหนือ Navigatorเพื่อให้ทุก routeเห็นค่าใหม่

1. Locale identity

Locale('th') กว้างกว่า Locale('th','TH') เลือกระดับที่ resourcesรองรับจริงและ normalize preferenceเป็น language code stable

2. Wiring

ListenableBuilder(
  listenable: languageController,
  builder: (_, __) => MaterialApp(
    locale: languageController.locale,
    supportedLocales: const [Locale('en'), Locale('th')],
    localizationsDelegates: appDelegates,
  ),
);

3. System vs explicit

ใช้ Locale? nullเพื่อ follow systemหรือ explicit user choiceและ persist mode/code หาก productต้องมี “ตามเครื่อง” อย่าเก็บเพียง th/enจนแยกไม่ได้

4. Context timing

Localizations.localeOf(context) ต้องใช้ contextใต้ MaterialApp ไม่อ่านใน mainก่อน delegatesพร้อม สำหรับ formatterสร้างตาม localeปัจจุบันไม่ cacheตลอด process

5. Directionality

en/thเป็น LTRแต่ architectureควรใช้ EdgeInsetsDirectional/AlignmentDirectionalเมื่อรองรับ RTLในอนาคต ไม่ hardcode left/rightโดยไม่จำเป็น

6. Backend values

แยก UI labelsที่ translateได้จาก codes/namesที่ serverเป็นเจ้าของ เช่น location codeต้อง verbatim ส่วน typed status mapเป็น localized labelได้

7. แบบฝึกหัด

เปลี่ยนภาษาใน dialogแล้ว dialogเดิมไม่เปลี่ยนเพราะอะไร?

แนวคำตอบ

ตรวจว่า MaterialApp rebuildจาก controllerและ dialog builderอ่าน localizationใน context ไม่จับ translated stringก่อนเปิดหรืออยู่นอก listener

8. Tests

explicit/system/fallback, runtime toggleบน nested routes/dialogs, persistenceและ formatterไม่ใช้ localeเก่า
