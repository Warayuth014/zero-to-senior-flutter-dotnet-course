การกระทำทั่วไป — ค้นหา ลบ แก้ไข ย้อนกลับสิ่งเฉพาะของธุรกิจ — รถ AGV, พาเลท, สายพาน

เกณฑ์: ถ้าต้องมีข้อความกำกับตลอดเวลา แปลว่าไอคอนนั้นสื่อไม่ได้ด้วยตัวเอง — ซึ่งไม่ผิด แต่ต้องรู้ว่าไอคอนกำลังทำหน้าที่แค่ช่วยหาตำแหน่ง ไม่ได้ทำหน้าที่บอกความหมาย

4. ไอคอนบน PDA ต้องใหญ่กว่าที่คิด

ขนาดใช้กับ
16–18ไอคอนประกอบข้อความ ไม่ต้องกด
24ค่าปริยายของ Material ใช้กับไอคอนในลิสต์
28–32ไอคอนของเมนูหลักที่ต้องเห็นชัดขณะเดิน

สิ่งที่แยกจากขนาดไอคอนคือพื้นที่กด — ไอคอนขนาด 24 ที่กดได้ ต้องมีพื้นที่กดอย่างน้อย 48 รอบตัว ซึ่ง IconButton จัดการให้อยู่แล้ว แต่ GestureDetector ที่ครอบ Icon ตรง ๆ ไม่จัดการให้

// พื้นที่กดเท่ากับไอคอน คือ 24×24 — เล็กเกินไปสำหรับนิ้วที่ใส่ถุงมือ
GestureDetector(onTap: _refresh, child: const Icon(Icons.refresh))

// พื้นที่กด 48×48 ตามที่ Material กำหนด
IconButton(onPressed: _refresh, icon: const Icon(Icons.refresh))

5. ไอคอนต้องไม่เป็นสัญญาณเดียว

ต่อจาก 11.2 ที่ว่าสีไม่ควรเป็นสัญญาณเดียว ไอคอนก็เช่นกัน

ไม่พอพอ
ไอคอนถังขยะอย่างเดียวไอคอน + ข้อความ “ลบ”
ไอคอนรถโฟล์คลิฟท์อย่างเดียวในลิสต์ไอคอน + ข้อความ “โฟล์คลิฟท์”

เหตุผลบน PDA ไม่ใช่แค่ความเข้าถึงได้ แต่เป็นเรื่องความเร็ว — ผู้ใช้ที่อ่านคำว่า “โฟล์คลิฟท์” มั่นใจได้ทันที ส่วนคนที่ต้องตีความไอคอนจะลังเลเสี้ยววินาที ซึ่งคูณด้วยห้าร้อยครั้งต่อวันแล้วมีความหมาย

เมื่อที่ไม่พอจริง ๆ ให้ใส่ Semantics อย่างน้อย เพื่อให้โปรแกรมอ่านหน้าจอบอกได้

Semantics(
  label: context.t(AppText.forklift),
  child: SvgPicture.asset('assets/icons/wms/forklift.svg', width: 24),
)

6. ไอคอนที่มีความหมายต่างกันในแต่ละวัฒนธรรม

ไอคอนปัญหา
แผ่นดิสก์สำหรับ “บันทึก”ผู้ใช้อายุน้อยไม่เคยเห็นของจริง แต่ยังใช้ได้เพราะเป็นธรรมเนียมที่แพร่หลาย
นกฮูกสำหรับ “ความรู้”บางวัฒนธรรมมองว่าเป็นลางร้าย
ท่าทางมือความหมายต่างกันมากในแต่ละประเทศ
เครื่องหมายถูกสีเขียวปลอดภัยที่สุด เข้าใจตรงกันเกือบทุกที่

ในแอปคลังที่มีพนักงานหลายสัญชาติ กฎง่าย ๆ คือใช้ไอคอนที่แทนของจริงที่จับต้องได้ — รถโฟล์คลิฟท์หน้าตาเหมือนกันทุกประเทศ

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ไอคอนไม่ขึ้น ขึ้นเป็นกล่องเปล่าลืมประกาศโฟลเดอร์ใน pubspec.yamlเพิ่มใน assets: แล้วรันใหม่
เพิ่มไฟล์ใหม่ในโฟลเดอร์ที่ประกาศแล้ว แต่ไม่ขึ้นต้องรีสตาร์ท ไม่ใช่ hot reloadflutter run ใหม่
SVG ขึ้นเป็นสีดำหมดไฟล์ SVG ใช้ currentColorกำหนด colorFilter
SVG บางไฟล์ไม่แสดงflutter_svg ไม่รองรับทุกฟีเจอร์ของ SVG เช่น filter และ mask ที่ซับซ้อนส่งออกจากโปรแกรมออกแบบแบบ “ทำให้เรียบง่าย” หรือแปลงเป็น path
ขนาดแอปโตขึ้นมากใช้ทั้งชุด font awesome เพื่อไอคอนสามตัวใช้ SVG เฉพาะตัวที่ต้องการ
ไอคอนกดยากครอบด้วย GestureDetectorใช้ IconButton

8. แบบฝึกหัด

ทีมออกแบบส่งไอคอนใหม่มา 40 ตัวเป็น PNG ขนาด 512×512 สำหรับเมนูทั้งหมดในแอป

  1. ควรรับแบบนี้ไหม
  2. จะขออะไรเพิ่ม
แนวคำตอบ

1. ไม่ควรรับตามที่ส่งมา ด้วยเหตุผลที่วัดได้

ปัญหาผล
512×512 ใหญ่เกินความจำเป็นมากไอคอนแสดงที่ 24–32 การเก็บไฟล์ 512 คือเปลืองพื้นที่และหน่วยความจำ 200 เท่า
PNG เปลี่ยนสีไม่ได้ต้องมีไฟล์แยกสำหรับสถานะปกติ เลือกอยู่ และปิดใช้งาน — กลายเป็น 120 ไฟล์
40 ไฟล์ × หลายความละเอียดถ้าทำครบ 1x 2x 3x คือ 120 ไฟล์ และขนาดแอปโตขึ้นหลาย MB

2. ขอ SVG พร้อมข้อกำหนดที่ชัดเจน

  • SVG ที่แปลงเป็น path แล้ว — ไม่มี text ที่ต้องพึ่งฟอนต์ ไม่มี filter หรือ mask ที่ flutter_svg อาจไม่รองรับ
  • สีเดียว ใช้ currentColor — จะได้ย้อมจากโค้ดตามสถานะได้ ไอคอนหนึ่งไฟล์ใช้ได้ทุกสถานะ
  • กรอบ 24×24 เท่ากันทุกไฟล์ — ไม่งั้นไอคอนจะดูขนาดไม่เท่ากันเมื่อวางเรียงกัน แม้จะกำหนด width เท่ากัน
  • เส้นหนาอย่างน้อย 1.5 — เส้นบางหายไปบนจอ PDA ความละเอียดต่ำกลางแดด

ข้อสุดท้ายเป็นข้อที่ฝ่ายออกแบบมักไม่รู้ เพราะเขาดูบนจอ Retina ในห้องที่แสงพอดี ควรส่งภาพถ่ายหน้าจอ PDA จริงกลางแดดให้ดูสักครั้ง — มีพลังกว่าอธิบายด้วยคำพูดมาก

และควรเสนอว่าเริ่มจาก 8 ตัวที่ใช้บ่อยที่สุดก่อน ไม่ใช่ 40 ตัวพร้อมกัน จะได้เห็นว่าข้อกำหนดที่ตกลงกันใช้ได้จริงไหม ก่อนที่อีก 32 ตัวจะถูกทำผิดแบบเดียวกันทั้งหมด

9. สรุป

  • ใช้ของสำเร็จรูปกับการกระทำทั่วไป ทำเองกับสิ่งเฉพาะของธุรกิจ
  • SVG ชนะเกือบทุกกรณีสำหรับไอคอน เพราะย้อมสีได้และคมทุกขนาด
  • ขนาดไอคอนกับพื้นที่กดเป็นคนละเรื่อง
  • ไอคอนไม่ควรเป็นสัญญาณเดียว ใส่ข้อความหรืออย่างน้อย Semantics
  • ขอ SVG ที่แปลงเป็น path สีเดียว กรอบเท่ากัน เส้นไม่บาง
