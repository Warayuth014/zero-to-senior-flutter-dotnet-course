Client validation เพื่อ UX; server validation เพื่อ security: extension และ Content-Type ที่ client ส่งปลอมได้ ต้องตรวจขนาด, signature และ decode ที่ server ก่อนยอมรับ

2. ตรวจขนาดก่อนอ่าน bytes

const maxBytes = 5 * 1024 * 1024;
final length = await picked.length();
if (length == 0 || length > maxBytes) {
  throw const InvalidImage('รูปต้องมีขนาดไม่เกิน 5 MB');
}

ฝั่ง server ตั้ง multipart/body limit ด้วยเพื่อ reject ก่อน buffer ไฟล์ใหญ่ และตรวจ IFormFile.Length ซ้ำ

3. Extension/MIME ไม่พอ

evil.exe เปลี่ยนชื่อเป็น photo.jpg ได้ และ request กำหนด image/jpeg เองได้ อ่าน magic bytes เช่น JPEG FF D8 FF หรือ PNG signature แล้วลอง decode ด้วย image library ที่อัปเดตแพตช์ความปลอดภัย

4. ชื่อไฟล์จากผู้ใช้

var extension = detectedType == ImageType.Jpeg ? ".jpg" : ".png";
var storedName = $"{Guid.NewGuid():N}{extension}";

เก็บ original name เป็น display metadata หลัง normalize/จำกัดความยาวเท่านั้น ห้าม combine original name ลง storage path เพราะ path traversal, reserved names และ collision

5. เก็บที่ไหน

เก็บนอก executable/static web root หรือ object storage แบบ private แล้วเสิร์ฟผ่าน controlled endpoint/CDN ที่ตั้ง content type, X-Content-Type-Options: nosniff และ authorization ถูกต้อง ไม่อนุญาต SVG/HTML หากไม่ sanitize เพราะเป็น active content

6. Resource safety

นอกจาก bytes ให้จำกัด pixel dimensions เพื่อกัน decompression bomb, จำนวน frames ของ animated image, เวลา decode และ concurrency ใช้ streaming scan/temp file ที่มี quota แล้วลบทุก error path พิจารณา malware scan ตาม threat model

7. Authorization และ audit

ตรวจว่าผู้ใช้มีสิทธิ์แก้ partId นี้ ไม่ใช่เพียง authenticated บันทึก uploader, time, part, generated object key, hash และ result โดยไม่ log raw image/token การ replace ควรมี audit/version และ cleanup รูปเก่า

8. Adversarial tests

ไฟล์ว่าง, เกิน limit, extension ปลอม, MIME ปลอม, polyglot/corrupt image, huge dimensions, animated image, filename ../x, Unicode ชนกัน, duplicate upload ID, ไม่มีสิทธิ์ และ disconnect ระหว่าง save
