Destination ไม่ใช่ label: ASRS, PREWORK และ REPLENISH เป็น business command คนละแบบ ส่วน wrapping เป็น option ที่ถูกต้องเฉพาะเส้นทาง ASRS

1. Normalize scans

station/pallet IDs ถูก trim และ uppercase ก่อนใช้ ลดความต่างจาก scanner แต่ API client ต้อง encode path/query และ backend ต้อง normalize/validate ซ้ำเสมอ

2. Station scan guard

ค้น station จาก catalog เพื่อหานโยบาย allowedType/fixedDestination/pwRole การส่งเฉพาะ stationId โดยไม่มี policy object ไปทั่ว widget ช่วยลด branch ที่ซ้ำ

3. Pallet lookup

GET /putaway/scan-pallet/{palletId}?stationId={stationId}

การรวม stationId ทำให้ server ตรวจว่าพา pallet มาที่ station นี้ได้หรือไม่ ไม่ใช่แค่อ่านรายละเอียด pallet

4. Type compatibility

receive/send prework รับเฉพาะ PW หาก response type ไม่ตรง UI reject ก่อน confirm แต่ backend confirm ต้องตรวจซ้ำเพื่อกัน stale response และ forged request

5. Destination choices

PW pallet เลือก ASRS หรือ PREWORK; FG palletเลือก ASRS หรือ REPLENISH ส่วน fixed destination ไม่แสดง selector การ map นี้ควรเป็น enum/decision table แทน String literals กระจายหลายไฟล์

6. Wrapping invariant

เมื่อเปลี่ยน destination ออกจาก ASRS โค้ด reset wrappingRequired=false และ toggle แสดงเฉพาะ ASRS ดังนั้น payload ต้องไม่เกิด PREWORK+wrapping หรือ REPLENISH+wrapping

7. Suggested destination

server ส่ง suggestedDestination และ model fallback เป็น ASRS หาก field หาย ค่า fallback อาจส่งของผิดปลายทางโดยเงียบ ควรใช้ nullable/unknown แล้วบังคับเลือกหรือ fail contract แทน default ที่มี side effect

8. Decision-table test

เขียน table สำหรับ pallet type × station policy × destination × wrapping พร้อม expected allowed/rejected แล้วใช้ชุดเดียวทดสอบ Dart policy และ .NET validator เพื่อลด contract drift
