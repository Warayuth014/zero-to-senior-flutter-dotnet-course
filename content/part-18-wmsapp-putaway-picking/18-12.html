Source pallet กำหนดชุดสินค้าที่หยิบได้: assignment response คือ snapshot ที่ผูก station, source pallet และ order เข้าด้วยกัน ทุก part/serial ที่เลือกต้องอยู่ใน snapshot นี้

1. Source scan UI

PickingScanSourceCard รับ controller/focus/onScan จาก parent จึงเป็น stateless presentation scanner focus กลับมาหลัง transition ด้วย post-frame callback

2. Assign source command

POST /picking/assign-station
{ "palletId": sourcePalletId,
  "pickOrderId": pickOrderId }

response คืน station และรายการบน pallet พร้อมจำนวนแนะนำที่จะ pick

3. Assignment snapshot

PickItemOnPallet มี partId, lotNumber, qtyOnPallet, qtyToPickSuggested, condition, serialRequire และ availableSerials Client ใช้กำหนด input mode และเพดาน local

4. Part activation

scan part ต้องตรง item ใน assignment แล้ว selection เป็น single-select; serial item โฟกัส serial field ส่วน non-serial เติมค่าเริ่มต้นเป็น suggested remaining และโฟกัส qty

5. Non-serial quantity

_addQty รับ int มากกว่า 0 และไม่เกิน qtyToPickSuggested แล้วเก็บใน map Backend ยังต้องตรวจ stock/order remaining ล่าสุด เพราะ local snapshot อาจ stale

6. Serial guard

serial ต้องไม่ซ้ำใน local list, อยู่ใน availableSerials ของ part และ count ไม่เกิน suggested qty ต่างจาก receiving flow ที่ validate server ต่อ scan; ที่นี่ server validation เกิดตอน confirm จึงมี conflict ช้ากว่า

7. Identity collision

selection, _pickedSerials และ _pickedQty key ด้วย partId หาก source มี part เดียวกันหลาย lot/condition record จะชนกัน ควรใช้ lineId หรือ composite part+lot+condition ที่ backendรับรู้

8. Source tests

ทดสอบ wrong pallet/order, empty assignment, part หลาย lot, duplicate/unknown serial, suggested qty ศูนย์/เกิน, scan source ซ้ำ และ network failure โดยห้ามเปลี่ยนไป returnSource เมื่อเป็น transport error
