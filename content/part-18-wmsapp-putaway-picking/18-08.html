SignalR เป็น invalidation channel: event ทำให้หน้าจอรู้ว่าควร refresh ไม่ใช่แหล่งข้อมูลเดียว เพราะ reconnect อาจพลาด event และ event payload อาจมีเพียงบาง field

1. Singleton + ref count

SignalRService เป็น singleton; connect เพิ่ม _refCount และ disconnect ลด เมื่อถึงศูนย์จึง stop connection ทำให้ Putaway กับ Prework ใช้ hub เดียวพร้อมกันได้

2. Hub connection

service resolve server URL แล้วต่อ /hubs/putaway ด้วย automatic reconnect จากนั้น register StationDispatched, PalletArrived, PalletReturned และ LabelingCompleted

3. Listener lifecycle

screen add callbacks ใน initState และ remove ใน dispose การ remove ต้องส่ง function instance เดิม ซึ่ง method tear-off ของ state ทำได้ตามโค้ดปัจจุบัน แต่ duplicate registration ยังควรป้องกัน

4. Safe dispatch

for (final cb in List.of(listeners)) {
  cb(data);
}

copy list ก่อน iterate ทำให้ callback remove listener ระหว่าง dispatch ได้โดยไม่เกิด concurrent modification

5. Parse event args

_parseArgs รับ null/empty/non-map เป็น empty map แล้ว handler screen ตรวจ stationId ต่อ ความทนนี้กัน crash แต่ malformed events ถูกกลืน ควร log metric พร้อม event name/schema version

6. Optimistic merge

StationDispatched merge pallet/destination เพื่อแสดง busy ทันที จากนั้นโหลด REST ใหม่ ส่วน events อื่นใช้ refresh อย่างเดียว Pattern นี้ลด latency แต่ต้องมี request generation guard ไม่ให้ response เก่าทับ event ใหม่

7. Connection gaps

connect catch แล้ว log แต่ไม่ส่ง connection state ให้ UI; automatic reconnect ไม่รับประกัน event replay จึงควร refresh เมื่อ reconnected, ทำ periodic reconciliation และแสดงสถานะ stale/offline

8. Realtime tests

fake stream แล้วทดสอบ event ซ้ำ/ผิดลำดับ/unknown station, disconnect-reconnect, สอง screens ref-count, listener remove, REST response เก่าหลัง event และ event ที่ payload ขาด field โดย state สุดท้ายต้องตรง snapshot ล่าสุด
