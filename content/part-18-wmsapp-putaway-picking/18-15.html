Return pallet มีสอง entry points: orders list ใช้ preview ก่อนส่ง ส่วน PickItemsScreen เสนอ ASRS/ZONE_PACK ทันทีเมื่อ assign source ไม่สำเร็จ ความต่างนี้ต้องอธิบายและทำ policy ให้เป็นหนึ่งเดียว

1. Return API

GET  /picking/return-pallet-preview/{palletId}
POST /picking/return-pallet
{ palletId, destination? }

ถ้าไม่ส่ง destination backend เลือก ZONE_PACK สำหรับ PACKED มิฉะนั้น ASRS

2. Preview model

ReturnPalletPreview มี currentStatus/location, canReturn, destination และ reason จึงเป็น typed decision จาก server ก่อน mutation ไม่ใช่แค่ข้อมูลแสดงผล

3. Orders-list flow

scan → preview → deny หรือ confirm destination ที่ serverแนะนำ → execute → clear/focus เป็น flow ปลอดภัยเพราะ operator เห็นเหตุผลและ routing ก่อน commit

4. Pick-flow fallback

เมื่อ assign source fail โค้ด set returnPalletId และเปิดสองปุ่ม ASRS/ZONE_PACK โดยไม่ preview ทั้งยังตีความทุก error ว่าไม่มีของที่ต้อง pick จึงเสี่ยง routing pallet หลัง network/auth failure

5. Unify decision

สร้าง ReturnPalletCoordinator ที่เรียก preview, แสดง destination ที่อนุญาต และ execute ด้วย version/token จาก preview ใช้ร่วมทั้งสองหน้า ห้ามให้ widget เดา policy จากข้อความ error

6. Source result flags

หลัง confirm response มี sourcePalletEmpty/sourcePickDone ซึ่งควรช่วยตัดสินว่า source ต้อง return หรือใช้ต่อ แต่ UI ปัจจุบันไม่ได้ branch ด้วย flags เหล่านี้ ควรออกแบบ transition ตาม domain outcome

7. Concurrency/idempotency

return ชนกับ pick/robot dispatch ได้ Backend ต้อง lock/version pallet, reject stale preview และทำ retry key ให้ safe Client ต้อง refresh location/status หลัง 409 หรือ timeout

8. Return tests

ทดสอบ AVAILABLE/PICKING/PACKED, canReturn false, auto-route, explicit destination, preview stale, timeout after commit, assign transport error และสองเครื่อง return พร้อมกัน โดยมีเพียงหนึ่ง transition สำเร็จ
