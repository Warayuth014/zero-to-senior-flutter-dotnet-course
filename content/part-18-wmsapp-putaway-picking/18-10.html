2. ตรวจสองชั้นก่อนเข้าจอหยิบ

Future<void> _scanPallet() async {
  final palletId = _scanCtrl.text.trim().toUpperCase();
  if (palletId.isEmpty) return;

  // ── ชั้นที่ 1: ตรวจในเครื่อง ──
  final found = _detail?.pallets.any((p) => p.palletId == palletId) ?? false;
  if (!found) {
    showErrorDialog(context, message: 'Pallet "$palletId" ไม่อยู่ใน Pick Order นี้');
    _scanCtrl.clear();
    _scanFocus.requestFocus();
    return;
  }

  // ── ชั้นที่ 2: ถามเซิร์ฟเวอร์ ──
  setState(() => _loading = true);
  final res = await _api.assignPickStation(palletId: palletId, pickOrderId: widget.pickOrderId);
  if (!mounted) return;
  setState(() => _loading = false);

  if (!res.success) {
    showErrorDialog(context, message: res.error ?? 'Scan pallet ไม่สำเร็จ');
    return;
  }

  _scanCtrl.clear();
  await Navigator.push(
    context,
    MaterialPageRoute(builder: (_) => PickItemsScreen(
      userId: widget.userId,
      fullName: widget.fullName,
      pickOrderId: widget.pickOrderId,
      initialAssignment: res.data!,
    )),
  );
  _load();
}

8. แบบฝึกหัด

ผู้ใช้แจ้งว่า “สแกนพาเลทที่การ์ดขึ้นสีเขียวแล้ว แต่แอปบอกว่าสแกนไม่สำเร็จ”

  1. อธิบายว่าเกิดได้อย่างไร
  2. ผู้ใช้ควรได้ข้อความว่าอย่างไร
  3. ป้องกันไม่ให้เกิดอีกได้ไหม

ข้อ 3 — ป้องกันได้ไหม

ทางได้ผลไหม
โหลดข้อมูลใหม่ก่อนสแกนทุกครั้งลดโอกาสแต่ไม่หมด — ยังมีช่องระหว่างโหลดกับสั่ง
โหลดใหม่เป็นระยะลดโอกาส และการ์ดจะเปลี่ยนสีเองก่อนผู้ใช้สแกน
ฟัง SignalRลดได้มากที่สุด แต่ต้องแตะฝั่งเซิร์ฟเวอร์
ป้องกันให้หมดทำไม่ได้

แถวสุดท้ายคือคำตอบที่แท้จริง — ไม่ว่าจะโหลดใหม่เร็วแค่ไหน ก็มีช่วงเวลาระหว่างที่ผู้ใช้เห็นข้อมูลกับที่กดเสมอ

นี่คือธรรมชาติของระบบที่มีผู้ใช้หลายคน ไม่ใช่ข้อบกพร่องของโค้ด
สิ่งที่ทำได้คือให้เซิร์ฟเวอร์เป็นผู้ตัดสินคนสุดท้ายเสมอ ซึ่งโค้ดนี้ทำถูกแล้ว — ชั้นแรกเป็นแค่การช่วยผู้ใช้ ไม่ใช่การรับประกัน
สิ่งที่ต้องแก้คือข้อความตอนที่ชั้นสองปฏิเสธ ให้บอกว่านี่เป็นเรื่องปกติที่เกิดได้ ไม่ใช่ว่าแอปพัง

วิธีตรวจว่าเข้าใจถูก: ถามว่าถ้าลบชั้นแรกออกทั้งหมด ระบบยังปลอดภัยไหม

คำตอบคือปลอดภัย — ชั้นแรกมีไว้ให้ผู้ใช้รู้เร็ว ไม่ได้มีไว้ป้องกัน และนั่นคือเหตุผลที่มันอยู่ในเครื่องได้โดยไม่เสี่ยง

9. สรุป

  • จอกลางมี state สี่ตัว ทำเรื่องเดียว — แสดงรายละเอียดแล้วรอสแกน
  • addPostFrameCallback ทำให้โฟกัสเข้าช่องทันทีที่จอเปิด
  • ตรวจสองชั้น: ในเครื่องก่อน แล้วค่อยถามเซิร์ฟเวอร์
  • ชั้นแรกใช้ข้อมูลที่โหลดมาแล้ว ไม่ต้องยิงเพิ่ม
  • ล้างช่องสามในสี่ทางออก และคืนโฟกัสสองในสามทาง
  • การ์ดใช้ stationId != null ตัดสินว่าพาเลทพร้อมไหม
  • ไฟล์เดียวใช้ทั้ง Colors.grey[700] และ AppTheme.textGrey(context)
  • fontFamily: 'monospace' ไม่ได้ประกาศใน pubspec
  • โหลดล้มเหลวแล้วจอว่างเปล่า ไม่มีทางลองใหม่
  • ชั้นแรกช่วยให้รู้เร็ว ไม่ได้ป้องกัน — เซิร์ฟเวอร์เป็นผู้ตัดสินคนสุดท้ายเสมอ
