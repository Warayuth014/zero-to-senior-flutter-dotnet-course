ไฟล์หลัก: models/task_models.dart และ models/destination_models.dart — แยก DB/API projections ออกจาก mutable operational models ที่ UIใช้

1. EventView เป็น boundary model

EventView flatten Eventsกับ detailแรก: IDs/class/status/type, from/to location/point/LPN, robot/requestQty และ product/doc fields Adapterอ่าน modelนี้ก่อนแปลงเป็น WmsTask หรือ Pick จึงเก็บ legacy naming/casingไว้ที่ boundary

2. WmsTask ผสม server กับ runtime

immutable identity/type/fromอยู่ร่วมกับ mutable qty, to, loc barcode, scanned destination, mode/status/serverStatus/step/agvName Server refreshสร้าง taskใหม่แล้ว store preserveเฉพาะ runtime fieldsที่ไม่มี server counterpart การรู้ ownerราย fieldป้องกัน pollingเขียนทับ truthผิดฝั่ง

3. barcodeFor ผูก stepกับ model

barcodeFor(expect) คืน pallet/location/destination โดย destination fallbackจาก destBarcode ไป to Storeจึงตรวจ scanตาม metadata แต่ putaway/returning scan locationเป็นกรณีพิเศษ: รับตำแหน่งว่างใดก็ได้แล้วให้ backend validate/commit ไม่เทียบ fixed barcode

4. Pick เป็น task projectionอีกแบบ

Pick เก็บ server/task IDs, pallet, product, requested quantity, destination, started flagและ audit creator/time มันไม่ใช่ stock line; quantityคือจำนวนที่งานขอให้หยิบและ backendคืน remainingหลัง confirm

5. Destination config

Destination แยก internal key, display nameและ barcode DEST-* พร้อม localized label isDestinationCode ใช้แยก outbound hand-offจาก storage rackในการ classify task/location count

6. Queue กับ Conveyor คนละมุม

DestinationQueueItem คือ unfinished RELOCATE eventรอ destination ส่วน DestinationConveyor คือ physical C1/C2/C3 positionพร้อม pallet/status/task/product DestinationQueueSummary รวม occupancy, free incoming count, conveyorsและ persisted queueต่อ destination

7. Conveyor status predicates

isAvailable ดู palletว่าง, isArrived exact ARRIVED, isStaged/isDispatched ใช้ prefixเพื่อรองรับ STAGED_PICKING/STAGED_MANUAL และ DISPATCHED_PUTAWAY UIควรตัดสิน actionจาก predicates ไม่ copy string comparisonsหลายหน้า

8. Model tests

ทดสอบ event alias→task type/status/mode, RELOCATEไป DESTเทียบ rack, barcode fallback, queue/conveyor predicatesทุก prefix, missing task/product fieldsและ duplicate conveyor numbers เพิ่ม unknown status policyเพื่อไม่ให้ action destructiveเปิดโดยบังเอิญ
