ไฟล์หลัก: stageStoreIn, removeStoreIn และ C3 branch ใน PickingView — staging เป็น reversible stateก่อน dispatch

1. C3 มี flowคนละแบบ

C1/C2รับของมาเพื่อ picking แต่ C3รับ palletที่จะ Store In จึงใช้ local selectionแยกและ action Stage/Remove/Store In ไม่ควรยัดทุก conveyorเข้า state machineเดียวโดยมองแค่เลข lane

2. Stage pallet

เมื่อ C3 available ผู้ใช้สแกน palletแล้วเรียก mobile_stage_store_in Backendตรวจ eligibilityและเปลี่ยน conveyor snapshotเป็น STAGED พร้อม product/quantityสำหรับตรวจทาน

3. Remove เป็น compensating action

ก่อน dispatch ผู้ใช้กด Removeเพื่อยกเลิก stagingผ่าน mobile_remove_store_in ไม่ใช่แค่ clear UI เพราะ lane reservationอยู่ฝั่ง server หลัง success reload queuesแล้ว C3กลับ available

4. State predicates

isStagedรองรับ statusขึ้นต้น STAGED และ isDispatchedรองรับ DISPATCHED ทำให้ suffixรายละเอียดจาก backendยัง renderได้ แต่ควรมี unknown-state cardแทนตีความเป็น availableจาก palletว่างเพียงอย่างเดียว

5. Busy และ refresh

stage/removeใช้ pickingSubmittingกัน tapซ้ำ แล้ว reload destination queuesหลัง command ผู้ใช้จึงเห็น server snapshotใหม่ แต่อย่าปล่อย responseเก่าจาก pollมาทับ staged snapshotใหม่

6. Scan validation

clientรับ pallet codeแต่ serverต้องตรวจว่ามี stock, ไม่อยู่ lane/taskอื่นและอนุญาต Store In การ normalizeที่ UIช่วย inputเท่านั้น ไม่ใช่ domain validation

7. Failure recovery

stage timeoutอาจสำเร็จแล้วจึงต้อง refreshก่อน retry Remove conflictอาจหมายถึงถูก dispatchไปแล้ว UIควรเปลี่ยนเป็น waiting ESSแทนเสนอ Removeซ้ำ และทุก errorควรรักษา scan valueที่ช่วยผู้ใช้ตรวจสอบ

8. C3 tests

conveyor testครอบคลุม staged predicatesและ inline scan→details/actions ควรเพิ่ม remove success/fail, duplicate stage, timeout-after-commit, invalid pallet, response orderingและ transition staged→dispatchedจากอีกเครื่อง
