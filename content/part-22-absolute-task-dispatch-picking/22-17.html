2. Timer lifecycle

WarehouseStoreสร้าง periodic timerใน constructorและ cancelใน dispose ป้องกัน memory leak/callbackหลัง storeตาย แต่ควรพิจารณา app lifecycleและ visibilityเพื่อหยุด pollingเมื่อ backgroundหรือ tabซ่อน

3. Guard ไม่เท่ากัน

loadTasksและ historyมี loading guards แต่ picks/queuesบางเส้นไม่มี จึงเกิด overlapping requestsเมื่อ APIช้ากว่า 5 วินาทีและ responseเก่าอาจทับใหม่ ต้องใช้ single-flight, generation tokenหรือ versioned snapshot

4. Dispatch race

pollที่กำลังโหลด PENDINGอาจจบใกล้ manual/AGV dispatch และ loadTasksหลัง commandอาจถูก guardข้าม รอบถัดไปซ่อมได้แต่ UIมีช่วง stale การ invalidate/request-after-currentช่วยให้ command refreshไม่หาย

5. Test coverageปัจจุบัน

  • AGV dialog: pallet/point validation
  • Conveyor: states + C3 stage UI
  • Picking: arrived→start→find→confirm→history
  • Withdraw: fixed scanner + scroll list
  • Navigation: pause/resume/back/tab

Fake repositoryจำลอง stateful flowได้ดีแต่ failure/race pathsยังบาง

6. Integration test ที่ควรเพิ่ม

ใช้ fake clockและ controllable completersสร้าง out-of-order responses, timeout-after-commit, duplicate operatorและ partial refresh จากนั้น assertว่า latest server versionชนะ, actionไม่ซ้ำและผู้ใช้มี retry path

7. Observability

log commandด้วย correlation/task ID, duration, resultและrefresh generation โดยไม่บันทึก tokenหรือข้อมูลอ่อนไหว Metricsควรเห็น timeout, conflict, stale response droppedและpoll latencyเพื่อวิเคราะห์หน้างานจริง
