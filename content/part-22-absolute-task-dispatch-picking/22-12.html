ไฟล์หลัก: findActivePick, confirmPick และ mobile_pick — active taskถูกค้นด้วย palletแล้ว confirmจำนวนที่ backendกำหนด

1. Find Picking Task

active pickไม่ถูกเลือกอัตโนมัติหลัง start ผู้ใช้สแกน palletเพื่อค้น taskที่ activeอยู่ Storeจับ exact palletและตั้ง selectedActivePick ทำให้การยืนยันผูกกับวัตถุจริงตรงหน้า

2. Close detail ไม่ยกเลิก backend

ปิด active pick panelเพียง clear local selection Taskยัง activeฝั่ง server เมื่อสแกน palletเดิมจึงกลับมาได้ นี่แยก UI focusออกจาก domain statusอย่างถูกต้อง

3. Fixed pick quantity

detailแสดง pickQtyจาก taskและ confirmส่งจำนวนนั้น ไม่มี stepperใน active flow จึงเป็นการ execute allocation ไม่ใช่แก้ order หากต้อง partial pickควรเป็น business flowใหม่พร้อม reason/remaining ไม่แอบเปลี่ยน clientอย่างเดียว

4. Confirm transaction

mobile_pick(taskId, pickQty)
→ response.remaining
→ clear selected active pick
→ reload open picks + history + queues
→ show remaining feedback

5. Shared submit flag

confirmใช้ recvSubmittingร่วมกับ receiving/dispatch เป็น accidental coupling ชื่อ stateไม่สื่อ domainและ actionที่ไม่เกี่ยวกันอาจ blockกัน ควรแยก busy/errorด้วย operation key

6. Stale allocation

จำนวนที่เห็นอาจเปลี่ยนจากอีก operatorก่อน confirm Backendต้อง compare task status/versionและ quantity ไม่เชื่อ client UIควร reloadแล้วบอกจำนวนล่าสุดแทน retryค่าเก่าอัตโนมัติ

7. Timeout reconciliation

หาก pick commitแล้วแต่ responseหาย การส่งซ้ำเสี่ยงตัด stockสองครั้ง Commandต้อง idempotentด้วย task state/request key Clientควร fetch task/historyก่อนเสนอ retryและถือ remainingจาก serverเป็น authority

8. Active-pick tests

existing flow testครอบคลุม arrived→start→find→close→find→confirm→historyและ fixed-page behavior ควรเพิ่ม wrong pallet, stale quantity, timeout-after-commit, duplicate confirm, refresh partial failureและ task activeจากอีก destination
