ไฟล์หลัก: CompletedTaskHistory, CompletedPickHistory และ history loaders — projectionสำหรับ audit ไม่ใช่ source of truthของ open work

1. สามมุมของ history

AGV historyกรอง transportที่ robot-driven, Forklift historyกรอง manual/HANDLE และ Picking historyรวมรายการสินค้าต่อ pick task การแยก projectionช่วยแต่ละหน้าตอบคำถาม operationalต่างกัน

2. Transport deduplication

history endpoint join detailหลาย rowต่อ event Adapter deduplicateด้วย event IDก่อนสร้าง CompletedTaskHistory ไม่เช่นนั้น taskเดียวจะปรากฏหลาย cardและ countผิด

3. Pick grouping

completed pick rowsถูก groupตาม task, joinชื่อ/code/unitของสินค้าและ sum quantity แล้ว sort newest นี่เป็น projection logicที่ควร unit testกับ multi-line productและ row orderไม่แน่นอน

4. Today summary

จำนวน finished todayไม่พึ่ง open-task cacheเพราะ completed taskหายจาก open grid Adapterขอ historyเพียงหนึ่ง rowแล้วอ่าน TotalCount เป็น optimizationที่อาศัย contract pagination

5. Independent loading guards

แต่ละ historyมี loading flagของตนจึงไม่ block task fetch และ fail-softเพื่อไม่ทำหน้าปฏิบัติงานพังเมื่อ audit panelล้ม แต่ควรแสดง stale/error timestampแทนเงียบจนผู้ใช้คิดว่าศูนย์รายการ

6. Sort และ timezone

Newest-firstต้อง parse timestampแน่นอน “Today”ควรนิยาม timezoneของ warehouse/server ไม่อิงเครื่อง PDAต่าง timezone และ eventที่มาถึงช้าควรยังเรียงตาม occurred timeหรือมี received timeแยก

7. Audit integrity

historyมีไว้ตรวจย้อนหลังจึงควรรวม stable task/pallet/user/robot/source/destination/quantity/status timestamps อย่าพึ่ง labelที่แปลแล้วเป็น key และไม่ควรให้ clientประกอบข้อเท็จจริงที่ backendไม่ได้ persist

8. History tests

ครอบคลุม duplicate joins, multi-product pick, empty/malformed rows, same timestamp, timezone boundary, partial detail failure, filter AGV/Forkliftและ stale-history indicator โดยเทียบ domain valuesไม่ยึดข้อความ UIอย่างเดียว
