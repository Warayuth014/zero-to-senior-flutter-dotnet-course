ไฟล์หลัก: DestinationConveyor, PickingView และ selectedIncomingPick — C1/C2 เป็น projection ของ laneจริงจาก backend

1. Snapshot เดียวของ destination

DestinationQueueSummaryรวม occupancy, free incoming, conveyorsและ queue items ทำให้ headerกับ lane cardsอ้าง snapshotเดียว ลดการเห็น countกับรายละเอียดคนละเวลา

2. Conveyor predicates

availableดู palletว่าง, arrivedเทียบ statusตรง, staged/dispatchedดู prefix Predicatesรวมความรู้เรื่อง wire statusไว้ใน modelแทนกระจาย string comparisonsทั่ว widget

3. C1/C2 incoming states

Stateความหมายใน UI
Availablelaneว่าง
In transittaskกำลังมาถึง
Arrivedพร้อม start picking

ผู้ใช้เลือกดูได้ทุก state ไม่ใช่เฉพาะ arrivedเพื่อมอง operational contextครบ

4. selectedIncomingPick

storeจับคู่ arrived conveyor palletกับ waiting pick หาก queue snapshotกับ pick snapshotมาคนละจังหวะอาจหาไม่เจอ UIควรบอกว่า dataกำลัง syncและมี refresh ไม่สรุปว่าไม่มี taskอย่างถาวร

5. Selection toggle

แตะ conveyorเดิมอีกครั้งเพื่อปิด selection เมื่อเปลี่ยน destination storeเคลียร์ selectionเดิม ป้องกัน C1ของ destination Aไปใช้กับ taskของ B ซึ่งเป็น contextual-state invariantสำคัญ

6. Selection หลัง start

เมื่อ startสำเร็จ backendปล่อย conveyor แต่ UIคง conveyorที่เลือกไว้เพื่อแสดง Available เป็น feedbackทันที ขณะเดียวกัน active pickยังไม่ถูก auto-select ผู้ใช้ต้อง scan palletผ่าน Find Picking Task

7. Snapshot ordering race

การโหลด picksและqueuesแยก requestอาจได้ snapshotคนละ version Senior APIอาจคืน version/watermarkหรือ aggregate projectionเดียว Clientอย่างน้อยควรป้องกัน responseเก่ามาทับ responseใหม่

8. Conveyor tests

ทดสอบ predicateทุก status, destination switch, toggle selection, arrivedแต่ pickยังไม่มา, startสำเร็จแล้ว laneว่าง, out-of-order refresh และ unknown conveyor code เพื่อให้ UI fail-softโดยไม่ dispatchผิด lane
