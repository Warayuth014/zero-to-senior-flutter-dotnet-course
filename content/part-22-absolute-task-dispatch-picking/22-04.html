ไฟล์หลัก: WarehouseStore.loadTasks() — merge server snapshotใหม่กับ runtime progressเดิมอย่างเลือก field ไม่ copy objectเก่าทั้งตัว

1. Server เป็น ownerของ assignment

mode, persisted status, robotและ task routeมาจาก fetchOpen ทุก pollingรอบ Storeไม่ preserveค่าพวกนี้จาก objectเดิมเพราะ dispatch/ESS/operatorอื่นอาจเปลี่ยนแล้ว การ copyทั้งหมดจะทำให้ PDAแสดงเจ้าของงานเก่า

2. Runtime key

mergeใช้ server IDถ้ามี มิฉะนั้น event ID เพื่อจับ taskเดิมข้าม object instances Keyต้อง stableและ unique; หาก fallback event IDซ้ำหรือ serverเปลี่ยน ID local progressจะหายซึ่งปลอดภัยกว่าผูก progressกับ taskผิด

3. Fields ที่ preserve

  • step
  • manual inProgress ทับ HANDLE/dispatchedเพื่อคง Continue
  • scannedDestinationCode
  • to/locBarcode เมื่อ localเลือกตำแหน่งแล้ว

นี่คือ runtime stateที่ server projectionยังไม่มีหรือยังไม่ควรทับระหว่าง guided flow

4. Replace collection หลัง merge

store clear/addAll open snapshotทำให้ taskที่ completed/cancelledหายจาก live listตาม server หาก selected taskId อ้าง taskที่หาย viewอาจคืน empty widgetจน navigationรอบถัดไป จึงควร reconcile selectionและพาออกจาก detailอย่าง explicit

5. Loading guard

_tasksLoading ป้องกัน requestซ้อนจาก timer/nav แต่ถ้า pollเก่าเริ่มก่อน dispatchแล้ว dispatch successเรียก loadTasks ระหว่าง guardยัง true การ reloadใหม่จะถูก skipและ pollเก่าอาจคืน PENDINGมาทับ optimistic state จนรอบ 5 วินาทีถัดไป ควรใช้ generationหรือ queued refresh-after-current

6. Error policy

failure toastแต่เก็บ tasksเก่าและ notifyหลัง finally ทำให้ใช้งานต่อได้แบบ stale snapshot ควรแสดง last-updated/offline stateเพราะ operatorอาจคิดว่า assignmentยังถูกต้อง และห้ามทำ destructive commandจากข้อมูล staleโดยไม่ให้ backend validate

7. Preserve น้อยอย่างตั้งใจ

หลัก mergeคือเริ่มจาก server objectใหม่แล้ว copyเฉพาะสิ่งที่พิสูจน์ว่า local-owned ห้ามเริ่มจาก old objectแล้ว copy serverบาง field เพราะ fieldใหม่จาก APIจะถูกลืมและ stale stateสะสม นี่เป็น reconciliation patternสำคัญสำหรับ pollingทุกระบบ

8. Controlled-future tests

สร้าง two polls A/Bและ dispatchคั่นกลาง ควบคุม completion order แล้วพิสูจน์ว่า server assignmentล่าสุดชนะ, local manual stepยังอยู่, completed taskถูกลบ, selectionถูก clear และ requestที่ถูก skipทำ queued refreshหนึ่งครั้งแทนรอ timerรอบถัดไป
