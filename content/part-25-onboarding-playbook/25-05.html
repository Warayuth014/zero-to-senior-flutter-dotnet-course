Crash กลุ่มนี้: setState after dispose, unmounted context, deactivated ancestor, controller used after dispose, duplicate listenerและ dialog teardown race

1. อ่าน stackแรกของเรา

หา first application frameและ async boundary ไม่แก้ตามบรรทัด frameworkท้าย stack เก็บ navigation/dialog/action sequenceที่ reproduceและ device/platformเพราะ Flutter Web teardownอาจต่าง Android

2. mountedหลัง await

final result = await operation();
if (!mounted) return;          // State
if (!context.mounted) return;  // BuildContext
setState(() => apply(result));

แต่ mountedไม่กัน stale identity จึงเพิ่ม generation/keyเมื่อต้อง latest-wins

3. Dialog lifecycle

อย่า refresh ancestorระหว่าง descendant dialogกำลัง dispose รอ showDialogคืน resultแล้วค่อย mutate/store reload และตรวจ context ownerที่ยัง mounted

4. Resource ownership

Stateที่สร้าง TextEditingController/FocusNode/Animation/Timer/StreamSubscriptionต้อง dispose/cancel; externally supplied controllerเป็นของ caller ห้าม child disposeซ้ำ ระบุ ownershipใน constructor/docs

5. Listener symmetry

add observer/listener/subscriptionใน initต้อง removeใน dispose หาก dependencyเปลี่ยนใน didUpdateWidgetต้อง unsubscribe old/subscribe new ไม่เช่นนั้น callbackเก่าหรือ duplicate events

6. Store dispose

ChangeNotifier cancel timer/streamและ invalidate in-flight commitsก่อน super.dispose Future cancelไม่ได้เสมอจึงมี disposed/session generation guardด้วย Objectที่สร้าง storeเป็นผู้ dispose ไม่ให้หลาย widgetsแย่ง ownership

7. Navigation race test

ใช้ delayed fake: เปิดหน้า→เริ่ม request→pop/logout/close dialog→complete request แล้ว expectไม่มี exception/notify stale ทำซ้ำกับ rapid tab switchและ app background

8. Fix quality

fixต้องอธิบาย owner/lifetimeและมี reproduction test ไม่ใช้ catchกว้างหรือ delay 100msเพื่อซ่อน timing เพราะเครื่องช้าจะพังอีก
