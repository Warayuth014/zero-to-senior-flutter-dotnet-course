เพิ่ม endpointแบบ vertical slice: เริ่ม contractและconsumer need แล้วเดิน DTO/repository/store/UI/tests ไม่เพิ่ม method raw JSONใน widget

1. Contract first

ระบุ verb/route/auth/request/response/status/ProblemDetails/idempotency/paginationและ exampleจริง ตกลง deploy compatibilityกับ .NETก่อนสร้าง Dart modelจากความเดา

2. Model/DTO

สร้าง typed DTO/domain, required/null/unknown policyและ parser fixture Request serializerใช้ exact server property namesและ URI encode path/query

3. ApiClient capability

reuse GET/POST/multipart primitivesและ central error/auth/correlation ไม่ duplicate http call/timeout/headersใน feature หาก methodใหม่ต้อง streaming/progressให้เพิ่ม abstractionเฉพาะ requirement

4. Repository seam

abstract interface class XRepository { Future<X> load(...); }
class RemoteXRepository implements XRepository {
  RemoteXRepository(this.api);
}

คืน domain result/failureไม่คืน raw map

5. Store command

กำหนด loading/refresh/submit semantics, generation/duplicate guard, state commitและ invalidationของ featureอื่น Mutation timeoutต้องมี reconciliation ไม่เพียง catchแล้วเปิดปุ่ม retry

6. Composition/UI

wire repository/storeใน composition root, render initial/loading/data/empty/errorและ permission/action states Widgetส่ง typed inputและไม่ parse responseเอง

7. Tests

contract request+fixture, repository mapping/failure, store success/error/raceและ widget visible behavior เพิ่ม .NET integration test route/auth/validationพร้อม backward-compatible response

8. PR checklist

link contract, example redact, deploy order, observability, tests, security/data classificationและ rollback ไม่มี direct ApiService()/Map dynamicใหม่ใน leaf widget
