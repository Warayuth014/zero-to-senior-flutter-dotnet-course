Health probe ต้องพิสูจน์ identity: การได้ HTTP 200 ไม่พอ เพราะ proxy, captive portal หรือ service คนละตัวอาจตอบพอร์ตเดียวกัน

1. Endpoint contract

{
  "service": "wms-mobile-api",
  "status": "healthy",
  "version": "1.4.2",
  "serverTime": "2026-08-15T03:00:00Z"
}

2. Probe flow

parse base URL → GET anonymous health route → timeout สั้น → ตรวจ expected status → decode JSON → ตรวจ service marker/status → คืน typed ConnectionProbeResult

3. ของจริงสองแอป

wmsapp/lib/services/connection_probe.dart ยิง /api/health; อีกแอปใช้ /api/WMS/mobile_health และตรวจ payload เพื่อไม่ให้ HTML 200 หลอกว่าเชื่อมสำเร็จ

4. Liveness vs readiness

Liveness บอก process ยังอยู่ ส่วน readiness บอก dependency สำคัญพร้อมรับงาน เช่น DB/queue การตั้งค่าหน้า app ควรรู้ว่าจะเช็กแบบใดและอย่าให้ query หนักเกินไป

5. ก่อน login

route สำหรับตรวจ connection profile ควร anonymous และไม่คืนข้อมูลลับ หาก health ต้อง auth ผู้ใช้จะแยก URL ผิดจาก token ผิดไม่ได้

6. Result สำหรับ UI

แยก invalid URL, timeout, unreachable, wrong service, unhealthy, HTTP error และ success พร้อม latency/version เพื่อช่วย support

7. แบบฝึกหัด

GET health ได้ 200 body เป็นหน้า login HTML ควรแสดง connected ไหม?

เฉลย

ไม่ ต้องตรวจ JSON service marker; รายงานว่า endpoint ไม่ใช่ WMS API หรือ proxy/config ผิด

8. Operational rule

Health endpoint ไม่ควรเปิด stack trace, connection string หรือรายละเอียด infrastructure แก่ anonymous caller
