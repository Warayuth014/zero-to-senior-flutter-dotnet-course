หลัก: JSON dynamicหยุดที่ remote repository/DTO mapper ส่วน storesและwidgetsใช้ typed domain models; starter WmsTask/TaskRepositoryเป็นตัวอย่าง seamแรก

1. Domain models

กำหนด Task, InboundOrder/Line, Pallet/InventoryItem, CycleCountSession, DashboardSummaryและAttachmentResult พร้อม stable IDs, enum/unknown status, quantity typeและ timestampsที่มี timezone

2. DTO vs domain

สร้าง DTOแยกเมื่อ backend casing/null/legacy statusesไม่ตรง invariant domain แล้ว mapที่ repository ถ้ารูปร่างตรงและเสถียรใช้ modelเดียวได้ ไม่เพิ่ม classคู่ทุก endpointโดยอัตโนมัติ

3. Parser policy

required fieldหายเป็น ContractFailure, optionalใช้ documented default, numeric stringแปลงเฉพาะ contractยอมรับ, unknown enumเก็บ raw valueและ mutation UI fail-safe ห้าม whereTypeกลืน rowผิดโดยไม่รายงานถ้ารายการนั้นมีผลต่อ stock

4. Repository contracts

InventoryRepository.search(query, filters, page)
ReceivingRepository.validatePallet / receive
CycleCountRepository.lookup / submit / close
TaskRepository.fetchOpen / dispatch / complete
AttachmentRepository.uploadPartImage

5. Commands vs queries

queryอาจ cache/paginate/retryได้ ส่วน commandต้องรับ identity/version/idempotency keyและคืน server outcome เช่น updated quantity/task status ไม่คืน voidหาก clientต้อง reconcile

6. Immutable snapshots

repositoryคืน unmodifiable lists/modelsและ stores replace snapshotแทนให้ widgetsแก้ collections ลด accidental mutation/notify bugs ใช้ copyWithเฉพาะ domainที่ต้อง optimistic updateและเก็บ rollback snapshot

7. Repository tests

contract fixturesตรวจ request/response, mapping, unknown status, pagination, partial malformed dataและ ProblemDetails Store testsใช้ fake repositoryระดับ domainไม่เลียน HTTP

8. Checkpoint

ไม่มี Map<String,dynamic>หลุดเข้า widgets/stores, ทุก repository methodใช้ภาษาธุรกิจ, parser failuresมี field/pathและ modelsอธิบาย source of truth/versionได้
