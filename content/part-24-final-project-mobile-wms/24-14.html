Realtime role: SignalRลด latencyของ task changes แต่ไม่แทน authoritative REST snapshot; connectหลัง auth, reconcileหลัง reconnectและมี lifecycle-safe polling fallback

1. Hub contract

event TaskChanged {
  taskId, status, version, occurredAt, correlationId
}

eventเล็กใช้เป็น invalidationหรือ typed patchที่มี version ไม่ส่ง widget-ready labels

2. Connection ownership

Session coordinatorสร้างหนึ่ง connectionต่อ authenticated server, แนบ access tokenและกระจาย typed events Dispose/logout/server switchหยุด connectionและยกเลิก listenersทั้งหมด

3. Event handling

ถ้า event versionใหม่กว่า snapshotให้ reload task/listหรือ apply patchที่พิสูจน์ invariantได้ Duplicate/out-of-order eventถูก ignoreด้วย event/task version ไม่เรียก notifyจาก raw payloadก่อน parse

4. Reconnect

exponential backoff+jitter, UIแสดง reconnectingแบบไม่ block manual work และหลัง connectedใหม่ต้อง full reconciliationเพราะ eventsระหว่างหลุดอาจหาย อย่าคิดว่า reconnectสำเร็จแปลว่า stateครบ

5. Polling fallback

เมื่อ hub disconnected poll tasksช้าลงตามหน้าและหยุดเมื่อ background เมื่อ realtimeกลับมา reconcileแล้วหยุด fallback ป้องกันทั้ง no updatesและ double network load

6. .NET boundary

Hubส่ง eventหลัง database transaction commit ไม่ก่อน และใช้ user/warehouse groupsเพื่อไม่ broadcastข้อมูลทุกไซต์ Authorization hub/methodsต้องใช้ policyเดียวกับ REST

7. Observability

วัด connection state, reconnect count/duration, event lag, parse failure, version gapและ reconciliation result Log correlation IDแต่ redact token/payload sensitive

8. Tests

duplicate/out-of-order, disconnect during command, reconnect missed events, logout/server switch cleanup, malformed event, fallback pollและ eventหลัง store disposeด้วย fake event source/fake clock
