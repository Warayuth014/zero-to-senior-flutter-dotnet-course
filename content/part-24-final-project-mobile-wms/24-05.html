ฐานเดิม: starter ApiClientมี GET/POST JSON, 15s timeout, Bearer headerและ ApiException ให้ยกระดับเป็น transport boundaryที่ testได้และแยก failure semantics

1. Request API

เพิ่ม URI-safe query builder, DELETE/multipartตามที่ใช้, correlation/idempotency headersและ injected clock/client อย่าสร้าง generic SDKซับซ้อนเกิน endpointsจริง

2. Structured failure

AppFailure(
  kind: network|timeout|unauthorized|forbidden|
        validation|conflict|server|contract|unknown,
  code, message, statusCode, retryable, outcomeUnknown,
)

3. ProblemDetails

รองรับ RFC-style type,title,status,detail,errors,traceIdและ legacy message แต่ UIไม่ branchจากข้อความ เก็บ traceIdแสดงใน support detailโดยไม่เผย stack

4. Decode discipline

ApiClientตรวจ HTTPและ JSON object envelope ส่วน feature DTO parserตรวจ fields อย่า silentlyคืน mapว่างเมื่อ endpointต้องมี token/items เพราะ success HTTPแต่ contractเสียต้องเป็น contract failure

5. Retry policy

GET health/inventory retryแบบ bounded exponential+jitterได้เฉพาะ transient failures Mutationไม่ auto-retryหากไม่มี idempotency key; timeoutหลัง POSTให้ outcomeUnknownและ reconcile

6. Auth interceptor behavior

แนบ bearerจาก session provider, 401ส่ง eventให้ session coordinatorครั้งเดียว, ไม่ log Authorizationและไม่ refresh tokenพร้อมกันหลาย request หาก labยังไม่มี refresh endpointให้ logoutชัดเจน

7. Observability

บันทึก method, route template, duration, status/failure kind, correlation IDและnetwork stateโดย redact payload/barcodeตาม policy Metricsแยก client timeoutจาก server 5xx

8. Contract tests

ทดสอบ 2xx empty/JSON, ProblemDetails, legacy message, invalid JSON, timeout/socket, query encoding, bearer/redaction, 401 coordinationและ POST outcome unknownด้วย fake http client
