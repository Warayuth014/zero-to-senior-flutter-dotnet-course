ต่อยอดตรงจาก starter: TaskStoreโหลด/complete taskได้แล้ว ให้เพิ่ม dispatchและ guided manual executionโดยรักษา endpointเดิมเป็น regression baseline

1. Task lifecycle

pending → dispatched(manual) → in_progress
→ completed | cancelled/error

เก็บ server statusแยก UI stepและ unknown statusปิด actions

2. Dispatch contract

POST taskId, mode, operator/deviceและ idempotency key Backend compare current pending atomicallyและคืน assignment/version เครื่องที่แพ้ conflictแล้ว reload ไม่สร้าง local assignmentเอง

3. Manual steps

detail→scan source/pallet→instruction→scan destination→complete สร้าง StepDef metadataแต่ endpoint completionเลือกตาม task type หาก businessต่าง อย่า hard-code indexว่า step 3คือ destinationทุก flow

4. Runtime checkpoint

Storeรักษา step/scanned evidenceระหว่าง refresh/navigationด้วย stable server ID หากต้อง resumeหลัง app restartให้ persist checkpoint/versionหรือส่ง server ไม่พึ่ง memoryโดยไม่บอก requirement

5. Poll/reconcile

poll tasksเมื่ออยู่ task/dispatch screen, single-flight+pending refresh และ preserve runtime fieldsเฉพาะ task/versionเดิม Server cancel/reassignต้อง override local flowและแจ้งผู้ใช้

6. Complete semantics

รอ server successก่อน doneหรือมี explicit optimistic rollbackครบ status+step Timeoutหลัง commit query task/historyก่อน retry Endpoint completeต้อง idempotentเมื่อ destinationเดิมและ reject conflictเมื่อข้อมูลต่าง

7. Starter improvement

loadingตัวเดียวใน TaskStore blockทุก card ให้แยก initial/refreshจาก command stateต่อ task ID และ URL encode IDใน path เพิ่ม tests responseเก่ากับ completeพร้อมกัน

8. Acceptance tests

dispatchสองเครื่อง, scanผิด/ซ้ำ, pause/resume, refresh preserve, server cancel, duplicate complete, timeout-after-commit, command cardเดียว busyและ GET/POST integrationกับ .NET starter
