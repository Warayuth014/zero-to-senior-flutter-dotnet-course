เริ่มจากของจริง: starterมี core/api_client.dart และ features/tasks/{model,repository,store,screen} อยู่แล้ว ให้ขยาย feature-first ไม่ทิ้งแล้วสร้างใหม่ทั้งก้อน

1. Bootstrap

flutter pub get
flutter analyze
flutter test
dotnet build .\labs\dotnet\WmsMobileApi
dotnet run --project ... --urls http://0.0.0.0:5080

เก็บ baseline outputก่อนแก้และยืนยัน emulatorใช้ 10.0.2.2 ไม่ใช่ localhostของมือถือ

2. Target folders

lib/
  app/             app.dart, composition_root.dart
  core/            api, config, auth boundary, result
  design/          theme, localization, PDA widgets
  features/
    auth/ dashboard/ receiving/ inventory/
    cycle_count/ tasks/ attachments/

3. Feature anatomy

แต่ละ featureมี model/domain, repository contract, remote implementation, store/controllerและ presentationเท่าที่จำเป็น ไม่บังคับสร้างห้า foldersว่างทุก feature; dependency directionสำคัญกว่าหน้าตา tree

4. Dependency rule

Widgetรู้ Storeและview data, Storeรู้ repository contract, remote repositoryรู้ ApiClient/DTO แต่ ApiClientไม่ import feature ห้าม feature Aแก้ public mutable listของ B; cross-feature eventผ่าน coordinatorหรือ explicit method

5. Composition root

ApiClient → AuthRepository
          → TaskRepository / InventoryRepository / ...
repositories → feature stores
stores → AppShell

สร้าง graphจุดเดียวและกำหนด scope: app-wide config, session-wide client, feature-wide store

6. Environment config

ใช้ --dart-defineเป็น bootstrap fallbackแล้วให้ connection profileเป็น runtime choice ห้าม commit production URL/token signing password และ validate URLก่อนสร้าง request

7. Git milestones

commitต่อ vertical sliceที่ build/testได้ ไม่ commit generated build/bin/obj และไม่ผสม formatterทั้ง repoกับ behavior change ตั้ง branch/PRพร้อม acceptance criteriaและ rollback noteสำหรับ mutation flow

8. Checkpoint

ก่อนบทถัดไป starterยังโหลด/complete taskได้, testsเดิมผ่าน, composition rootสร้าง dependenciesชัดและไม่มี screenใหม่ ApiClient/serviceเองจากภายใน widget
