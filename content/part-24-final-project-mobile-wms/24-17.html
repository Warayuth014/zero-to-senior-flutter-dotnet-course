Release goal: สร้าง Android artifactที่ติดตั้ง/อัปเกรด/ต่อ production-like HTTPSได้ พร้อม version/signing/config/rollback—not เพียง flutter runผ่าน

1. Application identity

เปลี่ยน applicationId/package/display name/icon, กำหนด min/target SDKตาม device fleetและตรวจ permissions INTERNET/camera/mediaเท่าที่ใช้ ห้ามส่ง com.exampleขึ้น production

2. Versioning

version: major.minor.patch+build build numberต้องเพิ่มทุก artifact เก็บ git commit/build time/environmentใน diagnosticsแต่ไม่แสดง secrets Backend capability/version mismatchต้องมี messageชัด

3. Signing

สร้าง upload/release keystoreนอก repo, เก็บ credentialsใน secret manager/CI, backupและจำกัด access ห้าม commit key.properties/keystoreหรือพิมพ์ passwordลง logs ทดสอบ upgradeด้วย keyเดียวกัน

4. Build commands

flutter analyze
flutter test
flutter build apk --release --dart-define=...
# หรือ appbundleสำหรับ managed distribution
Get-FileHash ... -Algorithm SHA256

5. Network security

productionใช้ HTTPSและ valid trust chain ไม่เปิด cleartextกว้างเพียงเพราะ dev serverเป็น HTTP หาก private CAให้ provision certificateตาม fleet policy ไม่ disable TLS verificationใน app

6. Obfuscation/symbols

ถ้าใช้ --obfuscate --split-debug-infoต้องเก็บ symbolsตาม versionเพื่อ symbolicate crash Obfuscationไม่ปกป้อง embedded secrets—อย่า embed secretตั้งแต่แรก

7. Device smoke/rollout

ติดตั้ง clean+upgradeบน PDAจริง, scanner wedge, camera, sleep/resume, Wi-Fi roam, text scale, server switchและ long shift Pilotกลุ่มเล็ก, monitor metrics/crashesแล้ว staged rolloutพร้อม rollback artifact

8. Release evidence

signed artifact, version/commit/SHA256, test outputs, SBOM/dependency notes, configuration matrix, install/rollback instructions, known issuesและผู้อนุมัติ ห้ามส่ง keystore/tokenรวมใน zip
