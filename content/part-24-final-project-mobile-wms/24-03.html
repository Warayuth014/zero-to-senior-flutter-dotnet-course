เป้าหมาย UI: shellเดียวรองรับ PDAเล็ก, tablet, Thai/English, status feedbackและ session navigation โดย business storesไม่รู้สี/BuildContext

1. Design tokens

กำหนด color scheme, spacing, radius, typography, status colorsและminimum touch targetใน ThemeExtension/const tokens ไม่คัดลอก hex/paddingทุกหน้า Statusต้องมีข้อความ/iconร่วมกับสี

2. Localization contract

ใช้ ARB/gen-l10nหรือ typed lookup, ตั้ง locale fallbackและห้ามเก็บ translated labelเป็น domain key Enum/statusใช้ canonical codeแล้วแปลที่ presentation ทดสอบข้อความไทยยาวและ Englishที่กินพื้นที่ต่างกัน

3. PDA shell

Shellเป็น ownerของ tab/navigation, session header, connection indicator, global toast/flashและ app lifecycle ไม่ถือ receiving quantities/task transitions Navigationต้อง clearเฉพาะ transient run stateตาม policy ไม่ logoutโดยบังเอิญ

4. Responsive rule

compact: one pane + fixed primary action
wide: navigation rail + content pane
lists: one scroll owner
scanner: visible above keyboard when possible

5. Shared primitives

สร้าง PdaScaffold, StatusChip, ScanField, PrimaryAction, Empty/Error/Loading statesและConfirmDialog ทุก primitiveประกาศ controller/focus ownershipและรองรับ hardware Enter

6. Feedback

successใช้ visual+hapticแบบไม่รบกวน, mismatchแสดง expected/actionต่อไป, network errorมี retry, destructive/irreversible mutationต้อง confirmตาม risk ไม่ใช้ Snackbarเดียวสำหรับทุกเหตุการณ์

7. Accessibility

ตรวจ semantics labels, text scale 1.3–2.0, contrast, focus order, touch targetและ screen readerของ scanner status PDAใช้งานกับถุงมือ/แสงจ้า จึงให้ actionสำคัญใหญ่และไม่พึ่ง hover

8. Checkpoint tests

widget testsที่ 360×640 และ wide viewport, Thai/English, text scale, keyboard inset, empty/error/loadingและ bottom action visibility พร้อม visual checkบน Androidจริงอย่างน้อยหนึ่งเครื่อง
