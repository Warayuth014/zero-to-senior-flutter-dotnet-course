ระดับ: เริ่มต้นใช้เวลา: 30–40 นาทีลงมือทำ: จัดระยะห่างและตำแหน่งให้อยู่มือ
ต้องผ่านอะไรมาก่อน: 2.1 (tight กับ loose) และ 2.3 (Expanded)
จบบทนี้แล้วจะทำได้: ใช้ Padding, Center, SizedBox, ConstrainedBox ได้ถูกที่ และเข้าใจว่าแต่ละตัวเปลี่ยนข้อจำกัดที่ส่งให้ลูกอย่างไร

1. ปัญหาที่บทนี้แก้

สามบทแรกทำให้เราจัดโครงหน้าจอได้แล้ว แต่ทุกอย่างยังติดกันแน่นและชิดขอบจอ บทนี้คือเครื่องมือจัดระยะ ซึ่งดูเหมือนง่ายแต่มีจุดที่พลาดกันบ่อยสองเรื่อง

  • ระยะขอบซ้อนกันหลายชั้นจนพื้นที่จริงเหลือน้อยกว่าที่คิด
  • ใส่ขนาดให้ widget แล้วไม่มีผล เพราะแม่ส่ง tight constraint มา (จาก 2.1)

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
EdgeInsetsระยะขอบทั้งสี่ด้าน
insetระยะที่หักเข้ามาจากขอบ
alignmentตำแหน่งที่จัดลูกไว้ในพื้นที่ที่มี
intersectการรวมข้อจำกัดสองชุดเข้าด้วยกัน โดยเอาส่วนที่ทับกัน
design tokenค่ามาตรฐานที่ตั้งชื่อไว้ใช้ร่วมกันทั้งแอป

3. Mental model: แต่ละตัวแทรกตรงไหนของกฎสามข้อ

ทบทวน 2.1: ข้อจำกัดไหลลง ขนาดไหลขึ้น แม่วางตำแหน่ง — widget ในบทนี้แทรกอยู่คนละจุดของวงจรนั้น

widgetทำอะไรกับข้อจำกัดที่ส่งลงทำอะไรกับตำแหน่ง
Paddingหักระยะขอบออกก่อนส่งต่อเลื่อนลูกเข้ามาตามระยะนั้น
Center / Alignคลายเป็น loose ให้ลูกเลือกเองจัดลูกตามตำแหน่งที่ระบุ
SizedBoxบังคับเป็น tight ตามค่าที่ใส่ไม่ทำ
ConstrainedBoxรวมข้อจำกัดของตัวเองกับของแม่ไม่ทำ
ประโยคเดียวที่ต้องจำ: เวลาสงสัยว่าทำไมลูกได้ขนาดแบบนั้น ให้ไล่อ่าน wrapper ทีละชั้นจากบนลงล่างแล้วถามว่า “ชั้นนี้แก้ข้อจำกัดอย่างไร” — คำตอบอยู่ในตารางข้างบนทั้งหมด

4. Padding: หักพื้นที่ก่อนส่งต่อ

Padding(
  padding: const EdgeInsets.all(12),
  child: SomeWidget(),
)

ถ้าแม่ให้พื้นที่กว้าง 360 ลูกจะได้รับ 360 − 12 − 12 = 336 จากนั้น Padding บวกระยะกลับเข้าไปตอนรายงานขนาดขึ้นไป

รูปแบบความหมาย
EdgeInsets.all(12)ทั้งสี่ด้าน 12
EdgeInsets.symmetric(horizontal: 16, vertical: 8)ซ้ายขวา 16 บนล่าง 8
EdgeInsets.only(left: 8)เฉพาะซ้าย
EdgeInsets.fromLTRB(12, 8, 12, 16)ระบุทีละด้านตามลำดับ ซ้าย บน ขวา ล่าง
ระยะขอบสะสมจริง — ใน lab มี Padding(all: 12) ที่ระดับหน้าจอ และ Padding(all: 12) อีกชั้นในการ์ดแต่ละใบ รวมแล้วเนื้อหาในการ์ดห่างจากขอบจอ 24 บนจอ PDA กว้าง 320 นั่นแปลว่าเหลือพื้นที่ใช้งานจริงแค่ 272 ซึ่งเป็นเหตุผลที่ต้องทดสอบบนความกว้างจริงเสมอ

5. SizedBox: สามหน้าที่

// 1) บังคับขนาด
SizedBox(width: 48, height: 48, child: IconButton(...))

// 2) สร้างช่องว่าง — ใช้บ่อยที่สุด
const SizedBox(height: 12)

// 3) ขอพื้นที่สูงสุดที่แม่ให้ได้
SizedBox.expand(child: ...)

หน้าที่ที่สองคือที่ใช้บ่อยที่สุด และควรใช้แทน Padding เมื่อต้องการช่องว่าง ระหว่าง ลูกใน Row/Column เพราะอ่านง่ายกว่าและไม่ต้องคิดว่าจะใส่ระยะที่ตัวไหน

Column(
  children: [
    SummaryBar(...),
    const SizedBox(height: 12),   // ชัดเจนว่าเป็นช่องว่างระหว่างสองตัวนี้
    Expanded(child: ListView.builder(...)),
  ],
)

อย่าลืมว่าตาม 2.1 ถ้าแม่ส่ง tight constraint มา SizedBox ก็บังคับขนาดไม่ได้ — เช่นวาง SizedBox(width: 100) ไว้ใน Expanded ความกว้างจะถูกกำหนดโดย Expanded ไม่ใช่ค่า 100

6. ConstrainedBox: จำกัดไม่ให้กว้างเกินไป

Center(
  child: ConstrainedBox(
    constraints: const BoxConstraints(maxWidth: 480),
    child: LoginForm(),
  ),
)

ผลคือฟอร์มกว้างเต็มที่ 480 บนแท็บเล็ต แต่ยังหดตามได้บน PDA กว้าง 320 — เป็นรูปแบบที่ควรใช้กับทุกฟอร์ม เพราะฟอร์มที่กว้าง 1200 พิกเซลอ่านยากมาก

คำว่า รวมข้อจำกัด สำคัญ: ConstrainedBox ไม่ได้เขียนทับของแม่ แต่เอามาตัดกัน

แม่ให้:        maxWidth 320
เราขอ:         maxWidth 480
ผลลัพธ์:       maxWidth 320   ← ตัวที่แคบกว่าชนะ

จึงเป็นไปไม่ได้ที่จะใช้ ConstrainedBox ทำให้ลูกใหญ่เกินที่แม่อนุญาต ซึ่งตรงกับกฎใน 2.1 ที่ว่าลูกไม่มีทางฝ่าฝืนข้อจำกัดของแม่

7. ตัวช่วยเฉพาะทางที่ควรรู้จัก

widgetใช้เมื่อข้อควรระวัง
AspectRatioอัตราส่วนมีความหมาย เช่นภาพถ่ายหรือกล้องต้องมีขอบเขตอย่างน้อยหนึ่งด้าน
FittedBoxย่อ/ขยายให้พอดีช่อง เช่นตัวเลขใหญ่อย่าครอบทั้งหน้าจอ ตัวอักษรจะเล็กจนอ่านไม่ออก
FractionallySizedBoxขนาดเป็นสัดส่วนของแม่ เช่น 80%ต้องมีขอบเขตที่ชัดเจน
IntrinsicHeightให้ลูกใน Row สูงเท่ากันต้องวัดสองรอบ ใช้กับรายการยาวไม่ได้
FittedBox ดูเหมือนเป็นทางแก้ครอบจักรวาลของเนื้อหาล้น แต่มันย่อขนาดจริง ๆ รวมถึงปุ่มและตัวอักษร ผลคือปุ่มอาจเล็กจนกดไม่โดนบน PDA และผู้ใช้ที่ตั้งขนาดตัวอักษรใหญ่จะไม่ได้ประโยชน์เลย เพราะทุกอย่างถูกย่อกลับ

8. รวมค่าที่ใช้ซ้ำไว้ที่เดียว

ใน lab มีการรวมค่าที่ใช้ร่วมกันไว้ในที่เดียว

class Breakpoints {
  const Breakpoints._();

  /// ต่ำกว่านี้ถือว่าเป็นจอ PDA แนวตั้ง
  static const double compact = 480;

  /// ปุ่มบน PDA ต้องกดได้ด้วยมือที่ใส่ถุงมือ
  static const double minTapTarget = 48;
}

ประโยชน์ไม่ใช่แค่ประหยัดการพิมพ์ แต่คือ ตัวเลขมีชื่อและมีเหตุผลกำกับ — เมื่ออ่านเจอ Breakpoints.minTapTarget เรารู้ทันทีว่าทำไมต้องเป็น 48 ต่างจากการเห็นเลข 48 ลอย ๆ กระจายอยู่สิบที่ซึ่งไม่มีใครกล้าแก้

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ใส่ width ให้ SizedBox แล้วไม่มีผลแม่ส่ง tight constraint มาไปแก้ที่แม่ หรือใส่ Align คั่นเพื่อคลายข้อจำกัด
เนื้อหาแคบกว่าที่คิดมากบน PDAระยะขอบซ้อนกันหลายชั้นไล่นับ Padding ทุกชั้นแล้วรวมกัน
ConstrainedBox(maxWidth: 800) แล้วยังไม่กว้างขึ้นข้อจำกัดถูกตัดกับของแม่ต้องแก้ที่แม่ก่อน
Center แล้วลูกยังกว้างเต็มลูกขอขนาดสูงสุดเอง เช่น Container ไม่ระบุขนาดกำหนดขนาดให้ลูก หรือครอบ ConstrainedBox
ปุ่มเล็กลงจนกดไม่โดนใช้ FittedBox ครอบพื้นที่กว้างเกินไปใช้เฉพาะกับข้อความหรือตัวเลขเดี่ยว ๆ
ตัวเลขระยะกระจายทั่วโปรเจกต์และไม่สม่ำเสมอไม่มีที่รวมสร้าง class ค่าคงที่แบบ Breakpoints

10. แบบฝึกหัด

สร้างหน้าล็อกอินที่ต้อง

  1. อยู่กลางจอเมื่อพื้นที่เหลือเยอะ
  2. กว้างไม่เกิน 480 บนแท็บเล็ต แต่หดได้บน PDA
  3. เลื่อนได้เมื่อแป้นพิมพ์ขึ้นมาบัง
  4. ไม่ไปอยู่ใต้รอยบากหรือแถบล่างของระบบ

จงเรียงลำดับ wrapper ให้ถูก และอธิบายว่าทำไมลำดับนั้นสำคัญ

ดูแนวคำตอบและเหตุผล
SafeArea(                                       // 4) หลบรอยบาก
  child: LayoutBuilder(
    builder: (context, constraints) => SingleChildScrollView(   // 3) เลื่อนได้
      padding: const EdgeInsets.all(16),
      child: ConstrainedBox(
        // บังคับให้เนื้อหาสูงอย่างน้อยเท่าพื้นที่ที่มี
        // เพื่อให้ Center ข้างในมีที่ให้จัดกลางจริง
        constraints: BoxConstraints(minHeight: constraints.maxHeight - 32),
        child: Center(                          // 1) อยู่กลาง
          child: ConstrainedBox(
            constraints: const BoxConstraints(maxWidth: 480),   // 2) ไม่กว้างเกิน
            child: const LoginForm(),
          ),
        ),
      ),
    ),
  ),
)

ทำไมลำดับสำคัญ

ถ้าสลับเป็นผลที่เกิด
SingleChildScrollView อยู่นอก SafeAreaเนื้อหาเลื่อนไปอยู่ใต้รอยบากได้
Center อยู่นอก SingleChildScrollViewจัดกลางในพื้นที่ที่ไม่จำกัด ซึ่งไม่มีความหมาย
ไม่มี ConstrainedBox ที่ใส่ minHeightเนื้อหาหดตามฟอร์ม แล้ว Center ไม่มีพื้นที่ให้จัดกลาง ฟอร์มจะไปติดบนสุด

จุดที่ยากที่สุดของข้อนี้ คือชั้น ConstrainedBox(minHeight: ...) ซึ่งดูเกินจำเป็นแต่จำเป็นจริง — ตาม 2.1 พื้นที่ที่เลื่อนได้ส่งขอบเขตแบบไม่จำกัดในทิศแนวตั้ง Center จึงไม่รู้ว่า “กลาง” อยู่ตรงไหน การใส่ minHeight เท่ากับพื้นที่ที่มีจริง ทำให้เนื้อหาสูงอย่างน้อยเท่าจอ Center จึงจัดกลางได้ แต่เมื่อแป้นพิมพ์ขึ้นมาและฟอร์มสูงกว่าพื้นที่ ก็ยังเลื่อนได้ตามปกติ

ทำไมลบ 32: เพราะ padding: EdgeInsets.all(16) กินไป 16 บนและ 16 ล่าง ถ้าไม่หักออก เนื้อหาจะสูงเกินพื้นที่เล็กน้อยและมีแถบเลื่อนโผล่มาทั้งที่ยังไม่มีอะไรล้น

ลองต่อ: เอา SafeArea ออกแล้วรันบนอุปกรณ์ที่มีรอยบาก จะเห็นว่าหัวข้อฟอร์มโดนบัง จากนั้นใส่กลับแล้วเทียบ — เรื่อง SafeArea และ MediaQuery จะลงลึกใน 2.9

11. สรุปท้ายบท

  • Padding หักพื้นที่ก่อนส่งต่อ และสะสมจริงเมื่อซ้อนหลายชั้น
  • Center/Align คลายข้อจำกัดให้ลูกเลือกขนาดเอง
  • SizedBox ใช้บ่อยที่สุดในบทบาทช่องว่างระหว่างลูก
  • ConstrainedBox รวมข้อจำกัดกับแม่ ไม่ได้เขียนทับ — ตัวที่แคบกว่าชนะ
  • FittedBox ย่อทุกอย่างรวมถึงปุ่ม อย่าใช้ครอบพื้นที่กว้าง
  • รวมค่าระยะและขนาดที่ใช้ซ้ำไว้ที่เดียวพร้อมเหตุผล
