ระดับ: เริ่มต้นใช้เวลา: 30–40 นาทีลงมือทำ: เรียง widget เป็นแถวและเป็นคอลัมน์
ต้องผ่านอะไรมาก่อน: 2.1 (กฎสามข้อของ layout)
จบบทนี้แล้วจะทำได้: ใช้ Row และ Column ได้คล่อง จัดตำแหน่งลูกในทั้งสองแกน และรู้ว่าทำไม spaceBetween ไม่ได้ป้องกันเนื้อหาล้น

1. ปัญหาที่บทนี้แก้

Row และ Column คือสอง widget ที่ใช้บ่อยที่สุดในทุกหน้าจอ และก็เป็นต้นเหตุของแถบสีเหลืองดำเกือบทุกครั้งเช่นกัน

ปัญหาหลักคือ property ของทั้งคู่มีชื่อว่า mainAxisAlignment และ crossAxisAlignment ซึ่งไม่ได้บอกตรง ๆ ว่าเป็นแนวตั้งหรือแนวนอน ทำให้เดาผิดกันบ่อย

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
main axisแกนที่ลูกเรียงตาม
cross axisแกนที่ตั้งฉากกับแกนหลัก
flexความสามารถในการยืดหดตามพื้นที่ที่มี
mainAxisSizeตัวเองจะกินพื้นที่เต็มแกนหลักหรือแค่พอดีลูก

3. Mental model: จำแค่ทิศที่ลูกเรียงตาม

RowColumn
ลูกเรียงตามแนวนอน ซ้ายไปขวาแนวตั้ง บนลงล่าง
main axis คือแนวนอนแนวตั้ง
cross axis คือแนวตั้งแนวนอน
mainAxisAlignment จัดซ้าย/กลาง/ขวาบน/กลาง/ล่าง
crossAxisAlignment จัดบน/กลาง/ล่างซ้าย/กลาง/ขวา
ประโยคเดียวที่ต้องจำ: main axis คือทิศที่ลูก เรียงตาม เสมอ — ถ้าจำข้อนี้ได้ ที่เหลืออนุมานเองได้หมด ไม่ต้องท่อง

4. Row: ข้อมูลหนึ่งบรรทัด

ดูตัวอย่างจาก lab layout_basics_app.dart

Row(
  children: [
    Stack(...),                              // ไอคอน ขนาดคงที่
    const SizedBox(width: 12),               // ระยะห่าง
    Expanded(                                // ยอมยืดหด
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text(line.palletCode),
          Text(line.productName, maxLines: 1, overflow: TextOverflow.ellipsis),
        ],
      ),
    ),
    const SizedBox(width: 8),
    Text('${line.quantity}'),                // จำนวน ขนาดตามเนื้อหา
  ],
)

สังเกตว่าเราตัดสินใจเรื่อง ลำดับความสำคัญ ไปแล้วในโค้ดนี้ — ไอคอนกับจำนวนได้ขนาดที่ต้องการเสมอ ส่วนชื่อสินค้าเป็นตัวที่ยอมหดและตัดข้อความเมื่อพื้นที่ไม่พอ

นี่ไม่ใช่แค่การจัดหน้าให้สวย แต่เป็นการตัดสินใจเชิงธุรกิจ: บนหน้าจอรับเข้าสินค้า พนักงานต้องเห็น จำนวน ครบถ้วนเสมอ ส่วนชื่อสินค้าที่ยาวเกินอ่านไม่ครบก็ยังทำงานได้

5. Column: โครงของหน้าจอ

Column(
  crossAxisAlignment: CrossAxisAlignment.stretch,   // ลูกกว้างเต็ม
  children: [
    SummaryBar(...),                 // สูงตามเนื้อหา
    const SizedBox(height: 12),
    Expanded(child: ListView.builder(...)),   // กินที่เหลือ
  ],
)

CrossAxisAlignment.stretch ใน Column แปลว่า “ให้ลูกกว้างเต็มพื้นที่” ซึ่งเป็นสิ่งที่ต้องการเกือบทุกครั้งสำหรับโครงหน้าจอ เพราะไม่ต้องไปห่อ SizedBox(width: double.infinity) ทีละตัว

6. mainAxisAlignment แจกเฉพาะพื้นที่ที่เหลือ

ค่าผล
startชิดต้นแกน (ค่าเริ่มต้น)
centerอยู่กลาง
endชิดท้ายแกน
spaceBetweenตัวแรกชิดต้น ตัวท้ายชิดท้าย ที่เหลือแบ่งช่องว่างเท่ากัน
spaceAroundแบ่งช่องว่างรอบแต่ละตัว
spaceEvenlyช่องว่างทุกช่องเท่ากันหมด
ความเข้าใจผิดที่ทำให้เสียเวลามากที่สุดในบทนี้: spaceBetween ไม่ได้ป้องกันเนื้อหาล้น — มันแจกเฉพาะ “พื้นที่ที่เหลือหลังวัดลูกครบแล้ว” ถ้าผลรวมของลูกใหญ่กว่าพื้นที่ตั้งแต่ต้น ก็ไม่มีอะไรให้แจก และยังล้นเหมือนเดิม

ทางแก้ที่ถูกคือทำให้ลูกที่ยืดได้ ได้รับขอบเขต ผ่าน Expanded หรือ Flexible ซึ่งเป็นเรื่องของบทหน้า

ใน lab มีการใช้ Spacer() ซึ่งคือ Expanded ที่ว่างเปล่า ใช้ดันของไปคนละฝั่ง

Row(
  children: [
    Chip(label: Text(line.location)),
    const Spacer(),                    // ดันปุ่มไปขวาสุด
    FilledButton(onPressed: () {}, child: const Text('ยืนยัน')),
  ],
)

7. mainAxisSize: กินเต็มหรือพอดีลูก

Column(
  mainAxisSize: MainAxisSize.min,   // สูงแค่พอดีลูก
  children: [...],
)
ค่าใช้เมื่อ
max (ค่าเริ่มต้น)เป็นโครงของหน้าจอ ต้องการเต็มพื้นที่
minอยู่ในกล่องโต้ตอบหรือการ์ด ที่ควรหดตามเนื้อหา

ข้อควรจำ: min ไม่ได้ทำให้เล็กลงเสมอ ถ้าแม่ส่ง tight constraint มา (ตาม 2.1) ค่านี้จะไม่มีผลเลย เพราะลูกไม่มีสิทธิ์เลือกขนาด

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ใส่ spaceBetween แล้วยังล้นเข้าใจว่ามันบีบลูกให้เล็กลงห่อลูกที่ยืดได้ด้วย Expanded
ข้อความยาวทำให้ทั้งแถวล้นข้อความไม่มีขอบเขต จึงกว้างตามเนื้อหาห่อ Expanded + overflow: TextOverflow.ellipsis
CrossAxisAlignment.stretch ไม่ยืดแกนขวางไม่มีขอบเขตทำให้แม่มีขอบเขตก่อน (2.1)
ใส่ mainAxisSize: min แล้วไม่หดแม่ส่ง tight constraintไปแก้ที่แม่
ใช้ Row ใน Row แล้วงงว่าแกนไหนคือแกนไหนสับสนระหว่างชั้นอ่านทีละชั้น ถามว่าลูกของชั้นนี้เรียงทิศไหน
ใส่ Expanded ใน Column ที่อยู่ในที่เลื่อนได้ไม่มีขอบเขตให้แบ่งดู 2.1 หัวข้อ 5

9. แบบฝึกหัด

สร้างแถบหัวข้อของหน้าจอ PDA ความกว้าง 320 ที่มีสามส่วนในแถวเดียว

  • ชื่อคลัง ซึ่งอาจยาวมาก เช่น “ศูนย์กระจายสินค้าบางนา อาคาร 3 โซนเย็น”
  • ป้ายสถานะการเชื่อมต่อ
  • ปุ่มออกจากระบบ ที่ต้องกดได้เสมอ
  1. เขียนโค้ด และระบุว่าใครยอมเสียพื้นที่ก่อน
  2. อธิบายว่าทำไมใช้ spaceBetween อย่างเดียวไม่พอ
  3. บอกว่าถ้าจอแคบกว่านี้อีก ควรตัดอะไรออกก่อน
ดูแนวคำตอบและเหตุผล
Row(
  children: [
    // ยอมเสียพื้นที่ก่อน — ตัดข้อความเมื่อไม่พอ
    Expanded(
      child: Text(
        warehouseName,
        maxLines: 1,
        overflow: TextOverflow.ellipsis,
        style: Theme.of(context).textTheme.titleMedium,
      ),
    ),
    const SizedBox(width: 8),

    // ขนาดตามเนื้อหา แต่จำกัดไม่ให้ยาวเกินไป
    ConstrainedBox(
      constraints: const BoxConstraints(maxWidth: 90),
      child: Chip(
        label: Text(online ? 'ออนไลน์' : 'ออฟไลน์', overflow: TextOverflow.ellipsis),
        visualDensity: VisualDensity.compact,
      ),
    ),
    const SizedBox(width: 8),

    // ได้ขนาดที่ต้องการเสมอ กดได้ด้วยมือที่ใส่ถุงมือ
    SizedBox(
      width: 48,
      height: 48,
      child: IconButton(
        onPressed: onLogout,
        icon: const Icon(Icons.logout),
        tooltip: 'ออกจากระบบ',
      ),
    ),
  ],
)

ลำดับการยอมเสียพื้นที่

ลำดับใครเหตุผล
ยอมก่อนชื่อคลังอ่านไม่ครบก็ยังทำงานได้ และผู้ใช้รู้อยู่แล้วว่าตัวเองอยู่คลังไหน
ยอมทีหลังป้ายสถานะมีขนาดจำกัดไว้ ไม่โตเกินควบคุม
ไม่ยอมเลยปุ่มออกจากระบบถ้ากดไม่ได้ ผู้ใช้ติดอยู่ในระบบ

ข้อ 2 — ทำไม spaceBetween ไม่พอ

เพราะชื่อคลังยาว ๆ จะกว้างตามเนื้อหาของมันเอง เมื่อรวมกับป้ายและปุ่มแล้วเกิน 320 ก็ไม่มี “พื้นที่ที่เหลือ” ให้ spaceBetween แจกตั้งแต่ต้น ผลคือได้แถบเหลืองดำเหมือนเดิม — Expanded ต่างออกไปเพราะมันบังคับให้ชื่อคลังรับขอบเขตที่แคบลงจริง ๆ แล้ว ellipsis จึงทำงานได้

ข้อ 3 — ถ้าจอแคบกว่านี้อีก

ตัดตามลำดับความสำคัญที่ต่ำสุดก่อน: เปลี่ยนป้ายสถานะจากข้อความเป็นไอคอนจุดสีเล็ก ๆ ซึ่งสื่อความหมายเดิมแต่กินพื้นที่น้อยกว่ามาก และห้ามตัดปุ่มออกจากระบบหรือย่อให้เล็กกว่า 48 เด็ดขาด เพราะบน PDA ที่ผู้ใช้ใส่ถุงมือ ปุ่มที่เล็กกว่านั้นกดไม่โดน — เรื่องนี้จะลงลึกใน 2.13

จุดที่คนมักพลาด: ใช้ Flexible กับทั้งสามตัวเพื่อ “ให้มันจัดการเอง” ผลคือปุ่มถูกบีบจนเล็กเกินกดบนจอแคบ — การตัดสินใจว่าใครยอมเสียพื้นที่ก่อนเป็นหน้าที่ของเรา ไม่ใช่ของเฟรมเวิร์ก

ลองต่อ: เขียนเทสต์ที่ตั้งความกว้างจอเป็น 320 แล้วตรวจว่าปุ่มยังสูง 48 และไม่มี exception เกิดขึ้น — ดูรูปแบบได้จาก test/layout_basics_test.dart

10. สรุปท้ายบท

  • main axis คือทิศที่ลูกเรียงตาม — จำข้อนี้ข้อเดียวพอ
  • Row เรียงแนวนอน Column เรียงแนวตั้ง
  • mainAxisAlignment แจกเฉพาะพื้นที่ที่เหลือ ไม่ได้บีบลูก
  • spaceBetween ไม่ป้องกันเนื้อหาล้น
  • CrossAxisAlignment.stretch ทำให้ลูกกว้างเต็มใน Column
  • Spacer() คือ Expanded ที่ว่างเปล่า ใช้ดันของไปคนละฝั่ง
  • ตัดสินใจล่วงหน้าว่าใครยอมเสียพื้นที่ก่อนเมื่อจอแคบ
