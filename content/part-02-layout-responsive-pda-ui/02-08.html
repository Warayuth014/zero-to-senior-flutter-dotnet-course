ระดับ: กลางใช้เวลา: 30–40 นาทีลงมือทำ: รวมหลายส่วนไว้ในพื้นที่เลื่อนเดียว
ต้องผ่านอะไรมาก่อน: 2.6 (พื้นที่เลื่อนซ้อนกัน) และ 2.7 (ListView.builder)
จบบทนี้แล้วจะทำได้: ใช้ CustomScrollView เมื่อหลายส่วนต้องเลื่อนไปด้วยกัน และรู้ว่าเมื่อไหร่ที่ยังไม่ต้องใช้

1. ปัญหาที่บทนี้แก้

ใน 2.6 เราแก้ปัญหาพื้นที่เลื่อนซ้อนกันด้วยการทำให้ส่วนหัวตรึงอยู่กับที่ ซึ่งใช้ได้ดีในกรณีส่วนใหญ่ แต่บางหน้าจอต้องการให้ส่วนหัวเลื่อนหายไปด้วยเพื่อให้เห็นรายการมากขึ้น

ปัญหาคือถ้าเอาส่วนหัวใส่ใน Column แล้วครอบด้วยพื้นที่เลื่อน เราจะกลับไปเจอปัญหาเดิม — sliver คือทางออกที่ออกแบบมาเพื่อกรณีนี้โดยเฉพาะ

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
sliverชิ้นส่วนหนึ่งชิ้นของพื้นที่เลื่อน ที่รู้วิธีทำงานแบบ lazy
CustomScrollViewพื้นที่เลื่อนที่รับ sliver หลายชิ้นมาต่อกัน
box widgetwidget ปกติที่เราใช้มาตลอด
pinnedติดอยู่ด้านบนแม้เลื่อนผ่านไปแล้ว
floatingโผล่กลับมาทันทีเมื่อเลื่อนขึ้น

3. Mental model: ต่อรถไฟทีละตู้

ListView ที่เราใช้มาคือรถไฟที่มีตู้เดียว ส่วน CustomScrollView คือการต่อตู้เอง โดยแต่ละตู้ทำหน้าที่ต่างกันแต่เลื่อนไปด้วยกัน

CustomScrollView
├── SliverAppBar          ← ตู้หัวขบวน อาจติดอยู่หรือเลื่อนหาย
├── SliverToBoxAdapter    ← ตู้ที่ใส่ widget ธรรมดาหนึ่งชิ้น
├── SliverList            ← ตู้รายการ ยังคง lazy
└── SliverToBoxAdapter    ← ตู้ท้าย เช่นสถานะกำลังโหลดเพิ่ม
ประโยคเดียวที่ต้องจำ: ทุกอย่างที่อยู่ใน slivers: ต้องเป็น sliver — widget ธรรมดาใส่ตรง ๆ ไม่ได้ ต้องห่อด้วย SliverToBoxAdapter ก่อน

4. sliver ที่ใช้บ่อย

ชื่อใช้ทำอะไรเทียบกับตัวปกติ
SliverList.builderรายการแบบ lazyListView.builder
SliverGrid.builderตารางแบบ lazyGridView.builder
SliverToBoxAdapterใส่ widget ธรรมดาหนึ่งชิ้น—
SliverPaddingระยะขอบที่เข้าใจ sliverPadding
SliverAppBarแถบหัวที่เลื่อนหายหรือติดได้AppBar
SliverFillRemainingเติมพื้นที่ที่เหลือ เช่นข้อความ “ไม่มีข้อมูล”—
CustomScrollView(
  slivers: [
    const SliverAppBar(
      title: Text('งานคลัง'),
      pinned: true,                    // ติดอยู่ด้านบนตลอด
    ),
    const SliverToBoxAdapter(child: DailySummary()),
    SliverPadding(
      padding: const EdgeInsets.all(12),
      sliver: SliverList.builder(
        itemCount: lines.length,
        itemBuilder: (context, index) => InboundLineCard(
          key: ValueKey<String>(lines[index].palletCode),
          line: lines[index],
        ),
      ),
    ),
  ],
)

สังเกตว่า SliverPadding ใช้ property ชื่อ sliver: ไม่ใช่ child: — เป็นสัญญาณว่ามันรับ sliver ไม่ใช่ widget ธรรมดา

5. SliverAppBar: สามพฤติกรรม

ตั้งค่าพฤติกรรมเหมาะกับ
ไม่ตั้งอะไรเลื่อนหายไปแล้วไม่กลับมาจนกว่าจะเลื่อนถึงบนสุดหัวข้อที่ดูครั้งเดียวก็พอ
pinned: trueย่อลงแล้วติดอยู่ด้านบนตลอดชื่อหน้าจอที่ต้องเห็นเสมอ
floating: trueโผล่กลับมาทันทีที่เลื่อนขึ้นนิดเดียวแถบค้นหาที่ต้องเรียกใช้ได้เร็ว

สำหรับแอปคลังบน PDA แนะนำ pinned: true เพราะพนักงานต้องรู้ตลอดว่าตัวเองอยู่หน้าจอไหน — การเลื่อนแล้วหัวข้อหายไปทำให้สับสนได้ง่ายเมื่อทำงานเร็ว ๆ

6. widget ธรรมดากับ sliver ปนกันไม่ได้

// ผิด — Container เป็น widget ธรรมดา
CustomScrollView(
  slivers: [
    Container(height: 100),          // error
  ],
)

// ถูก — ห่อก่อน
CustomScrollView(
  slivers: [
    const SliverToBoxAdapter(child: SizedBox(height: 100)),
  ],
)

// ผิดอีกทาง — เอา sliver ไปใส่ที่รับ widget ธรรมดา
Column(
  children: [
    SliverList.builder(...),         // error
  ],
)

ข้อความ error ที่จะเจอมักพูดถึง RenderSliver กับ RenderBox ซึ่งอ่านแล้วไม่รู้เรื่อง แต่ทุกครั้งที่เห็นสองคำนี้ ให้ตรวจข้อเดียว — เอาของผิดประเภทไปใส่ผิดที่หรือเปล่า

ข้อควรระวังที่กระทบเรื่องอื่น: SliverToBoxAdapter ไม่ lazy — มันสร้างลูกทั้งก้อนทันที ดังนั้นห้ามเอา Column ที่มีพันแถวไปใส่ในนั้น ต้องใช้ SliverList ถึงจะได้ประโยชน์ของ lazy ตามที่คุยกันใน 2.6

7. เมื่อไหร่ที่ยังไม่ต้องใช้

สถานการณ์ใช้อะไร
ฟอร์มสั้น ๆ ที่เลื่อนได้SingleChildScrollView
รายการอย่างเดียวListView.builder
ส่วนหัวตรึง + รายการเลื่อนColumn + Expanded (2.6)
หลายส่วนต้องเลื่อนไปด้วยกัน และมีรายการยาวCustomScrollView
ต้องการหัวข้อที่ย่อหรือติดขณะเลื่อนCustomScrollView

CustomScrollView เพิ่มแนวคิดอีกชุดที่ทีมต้องเข้าใจ จึงไม่ควรใช้เป็นค่าเริ่มต้น ให้เริ่มจากสามแบบแรกก่อน แล้วเปลี่ยนมาใช้เมื่อมีเหตุผลจริง

8. สถานะของแถวที่เลื่อนพ้นจอไป

เชื่อมกับ 1.3 และ 1.5: แถวที่เลื่อนพ้นจอไปอาจถูกทำลาย เมื่อเลื่อนกลับมาจะถูกสร้างใหม่ ผลคือ สถานะที่เก็บไว้ใน State ของแถวนั้นจะหาย

// อันตราย — ติ๊กถูกจะหายเมื่อเลื่อนพ้นจอแล้วเลื่อนกลับมา
class _RowState extends State<Row> {
  bool _checked = false;
}

// ปลอดภัย — สถานะอยู่ที่หน้าจอ อ้างด้วยรหัสจริง
final Set<String> _checkedIds = {};

นี่คือเหตุผลอีกข้อที่ 1.5 บอกให้เก็บข้อมูลไว้ที่แม่ร่วมที่ต่ำที่สุด — และเป็นเหตุผลที่ lab ของ Part 1 เก็บ _doneIds ไว้ที่หน้าจอ ไม่ใช่ในแต่ละแถว

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
error พูดถึง RenderSliver หรือ RenderBoxเอาของผิดประเภทไปใส่ผิดที่ห่อด้วย SliverToBoxAdapter หรือย้ายออกมา
ใส่ Padding ใน slivers: แล้วพังต้องใช้ SliverPaddingเปลี่ยนชื่อและใช้ sliver: แทน child:
เปลี่ยนมาใช้ sliver แล้วยังช้าเหมือนเดิมใส่ Column ยาวใน SliverToBoxAdapterใช้ SliverList.builder
ติ๊กถูกหายเมื่อเลื่อนกลับมาเก็บสถานะไว้ใน State ของแถวย้ายไปเก็บที่หน้าจอ อ้างด้วยรหัส
หัวข้อหายตอนเลื่อน ทั้งที่อยากให้ติดลืม pinned: trueเพิ่มเข้าไป
ใช้ CustomScrollView กับฟอร์มสั้น ๆใช้เครื่องมือเกินความจำเป็นใช้ SingleChildScrollView

10. แบบฝึกหัด

หน้าจอเดิมเขียนแบบนี้ และช้ามากเมื่อมีงาน 1,000 ใบ

SingleChildScrollView(
  child: Column(
    children: [
      const DailySummary(),
      const SizedBox(height: 12),
      for (final task in tasks) TaskCard(task: task),   // สร้างครบ 1,000 ใบ
    ],
  ),
)
  1. แปลงให้เป็น lazy โดยหน้าตายังเหมือนเดิมทุกอย่าง
  2. อธิบายว่าทำไมวิธีของ 2.6 (Column + Expanded) ใช้ไม่ได้กับโจทย์นี้
  3. ถ้าต้องเพิ่มแถวสถานะกำลังโหลดที่ท้ายรายการ จะใส่ตรงไหน
ดูแนวคำตอบและเหตุผล

ข้อ 1

CustomScrollView(
  slivers: [
    const SliverToBoxAdapter(child: DailySummary()),
    const SliverToBoxAdapter(child: SizedBox(height: 12)),
    SliverList.builder(
      itemCount: tasks.length,
      itemBuilder: (context, index) => TaskCard(
        key: ValueKey<String>(tasks[index].id),
        task: tasks[index],
      ),
    ),
  ],
)

หน้าตาเหมือนเดิมทุกประการ เพราะลำดับและเนื้อหาไม่เปลี่ยน สิ่งที่เปลี่ยนคือตอนนี้ TaskCard ถูกสร้างเฉพาะที่มองเห็น

ข้อ 2 — ทำไมวิธีของ 2.6 ใช้ไม่ได้

เพราะโจทย์บอกว่า “หน้าตายังเหมือนเดิมทุกอย่าง” ซึ่งแปลว่ายอดสรุปต้อง เลื่อนหายไปพร้อมรายการ ถ้าใช้ Column + Expanded ยอดสรุปจะกลายเป็นตรึงอยู่กับที่ ซึ่งเปลี่ยนพฤติกรรมของหน้าจอไป

ถ้าโจทย์ไม่ได้บังคับข้อนี้ วิธีของ 2.6 จะง่ายกว่าและควรเลือกก่อน — นี่คือประเด็นในหัวข้อ 7 ว่า CustomScrollView ไม่ใช่ค่าเริ่มต้น แต่เป็นทางเลือกเมื่อมีเหตุผลเฉพาะ

ข้อ 3

CustomScrollView(
  slivers: [
    const SliverToBoxAdapter(child: DailySummary()),
    const SliverToBoxAdapter(child: SizedBox(height: 12)),
    SliverList.builder(
      itemCount: tasks.length,
      itemBuilder: (context, index) => TaskCard(
        key: ValueKey<String>(tasks[index].id),
        task: tasks[index],
      ),
    ),
    if (loadingMore)
      const SliverToBoxAdapter(
        child: Padding(
          padding: EdgeInsets.all(16),
          child: Center(child: CircularProgressIndicator()),
        ),
      ),
  ],
)

ทำไมใส่เป็น sliver แยก แทนที่จะบวก itemCount เหมือนใน 2.7

ทั้งสองวิธีถูก แต่การแยกออกมาชัดกว่าเมื่ออยู่ใน CustomScrollView อยู่แล้ว เพราะไม่ต้องเขียน if (index >= tasks.length) ใน itemBuilder ซึ่งทำให้ตัวสร้างแถวมีสองหน้าที่ปนกัน — ตรงกับหลักใน D1.4 ที่ว่าฟังก์ชันควรทำเรื่องเดียว

สิ่งที่ควรสังเกตที่สุด: if (loadingMore) ใช้ collection if ใน slivers: ได้เหมือนกับ children: ทุกประการ เพราะทั้งคู่เป็น List ธรรมดาของ Dart ตาม D1.5 — sliver ไม่ได้มีไวยากรณ์พิเศษอะไรเลย

ลองต่อ: เพิ่ม SliverAppBar(pinned: true) เป็นตัวแรกสุด แล้วเลื่อนดู จะเห็นว่ายอดสรุปเลื่อนหายไปแต่หัวข้อยังติดอยู่ — เป็นพฤติกรรมที่ทำไม่ได้เลยด้วย Column + Expanded

11. สรุปท้ายบท

  • sliver คือชิ้นส่วนของพื้นที่เลื่อนที่รู้วิธีทำงานแบบ lazy
  • CustomScrollView ต่อ sliver หลายชิ้นให้เลื่อนไปด้วยกัน
  • ทุกอย่างใน slivers: ต้องเป็น sliver — ห่อด้วย SliverToBoxAdapter
  • SliverToBoxAdapter ไม่ lazy อย่าใส่รายการยาวลงไป
  • SliverAppBar มีสามพฤติกรรม — บน PDA แนะนำ pinned
  • แถวที่เลื่อนพ้นจออาจถูกทำลาย สถานะต้องเก็บที่หน้าจอ
  • อย่าใช้เป็นค่าเริ่มต้น — เริ่มจากวิธีที่ง่ายกว่าก่อน

บทถัดไป: 2.9 จะจัดการเรื่องพื้นที่ที่ระบบปฏิบัติการกินไป — รอยบาก แถบล่าง และแป้นพิมพ์ ซึ่งเป็นสาเหตุที่หน้าจอดูดีบนเครื่องหนึ่งแต่ผิดบนอีกเครื่อง
