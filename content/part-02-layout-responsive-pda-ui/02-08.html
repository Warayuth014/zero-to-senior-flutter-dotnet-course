Sliver คือชิ้นส่วนของ scroll viewport ที่รายงาน geometry แบบ lazy ทำให้ header, grid, list และ footer หลายชนิดแชร์การเลื่อนเดียวโดยไม่ต้องซ้อน scrollable

1. ทำไม ListView อย่างเดียวไม่พอ

เมื่อหน้าต้องมี app header ยุบได้, summary box, grid เมนู, list งานหลายร้อยแถว และ loading footer การครอบ Column/ListView หลายชั้นทำให้ unbounded/shrinkWrap แต่ CustomScrollView รวมทุกส่วนเป็น slivers ใน viewport เดียว

2. Sliver vocabulary

  • SliverAppBar: header scroll/pin/floating
  • SliverToBoxAdapter: box widget หนึ่งก้อน
  • SliverList: lazy list
  • SliverGrid: lazy grid
  • SliverPadding: padding ที่เข้าใจ sliver geometry
  • SliverFillRemaining: เติม viewport ที่เหลือ เช่น empty state

3. Warehouse feed ตัวอย่าง

CustomScrollView(slivers: [
  const SliverAppBar(title: Text('งานคลัง'), pinned: true),
  SliverToBoxAdapter(child: DailySummary()),
  SliverPadding(
    padding: const EdgeInsets.all(12),
    sliver: SliverList.builder(
      itemCount: tasks.length,
      itemBuilder: (_, i) => TaskTile(tasks[i]),
    ),
  ),
])

4. Box protocol กับ sliver protocol

Widget ปกติใช้ BoxConstraints/Size ส่วน sliver ใช้ SliverConstraints/SliverGeometry ห้ามวาง Container ตรงใน slivers: ต้องแปลงด้วย SliverToBoxAdapter และห้ามเอา SliverList ไปเป็น child ของ Column โดยตรง

5. Pinned controls และ scanner UX

Filter/search ที่ต้องอยู่ขณะเลื่อนใช้ SliverPersistentHeader pinned หรือวางนอก CustomScrollView ใน Column แล้ว Expanded scroll area การเลือกขึ้นกับว่า header ควรใช้พื้นที่คงที่หรือเข้าร่วม scroll ไม่ควรใช้ Stack ปักพิกัดแล้วบังรายการ

6. KeepAlive และ state ของแถว

Sliver children นอก viewport อาจถูกทำลาย สถานะธุรกิจต้องอยู่ store/model ไม่ฝากไว้ใน State ของ tile หากต้องรักษา UI state เฉพาะแถวใช้ key + AutomaticKeepAliveClientMixin อย่างจำกัด เพราะเก็บทุกแถวทำลายประโยชน์ด้าน memory

7. แบบฝึกหัด

เปลี่ยนหน้า SingleChildScrollView ที่มี summary + Column สร้าง task 1,000 ใบให้ lazy โดยไม่เปลี่ยนหน้าตา

เฉลย

ใช้ CustomScrollView: summary เป็น SliverToBoxAdapter, spacing เป็น adapter เล็กหรือ SliverPadding, task เป็น SliverList.builder, footer/error เป็น SliverToBoxAdapter เก็บ ScrollController เดิมที่ owner และทดสอบ empty/loading/pagination

8. จุดพลาด

Sliver ไม่จำเป็นกับ form สั้นทุกหน้า มันเพิ่ม abstraction และ protocol อีกชุด ใช้เมื่อหลาย section ต้องแชร์ viewport/lazy behavior หรือมี scroll effects จริง ส่วน form จำนวนคงที่ใช้ SingleChildScrollView อ่านง่ายกว่า
