MediaQuery บอกคุณสมบัติของ view เช่น size, padding, viewInsets และ text scaling ส่วน SafeArea แปลง padding ที่หลบ system UI เป็น layout โดยสะดวก ทั้งคู่ไม่แทน constraints ของ parent

1. size ต่างจาก available constraints

MediaQuery.sizeOf(context) คือขนาด view/window แต่ widget อาจอยู่ครึ่งจอ, dialog หรือ split pane จึงควรใช้ LayoutBuilder เมื่อตัดสิน layout จากพื้นที่ที่ได้รับ ใช้ MediaQuery เมื่อสนใจคุณสมบัติทั้ง view เช่น keyboard/system padding

2. padding, viewPadding และ viewInsets

  • padding: ส่วน view ที่ถูก system UI บัง ณ ตอนนั้น
  • viewPadding: safe padding พื้นฐานไม่ลดตาม keyboard
  • viewInsets: ส่วนถูกบังเต็ม เช่น on-screen keyboard

Bottom sheet/form มักต้องสนใจ viewInsets.bottom; content เต็มจอต้องหลบ notch/navigation ด้วย SafeArea

3. SafeArea แบบเลือกด้าน

SafeArea(
  top: false, // AppBar จัดส่วนบนแล้ว
  minimum: const EdgeInsets.symmetric(horizontal: 12),
  child: WarehouseBody(),
)

SafeArea ใช้ MediaQuery padding แล้วแก้ MediaQuery ภายในไม่ให้ descendant บวก safe padding ซ้ำ การซ้อน SafeArea จึงโดยทั่วไปไม่ทบค่าเดิม แต่ padding manual อาจยังซ้ำ

4. จากสองโปรเจกต์

wmsapp Home ใช้ SafeArea(top: false) เพราะ AppBar รับพื้นที่บนแล้ว Absolute ครอบ app-wide SafeArea ใต้ MaterialApp และ shell มี SafeArea ในส่วน navigation การออกแบบระดับ root ช่วย consistency แต่ overlay/dialog ที่อยู่นอกตำแหน่งนั้นยังต้องตรวจเอง

5. Keyboard-aware sheet

final insets = MediaQuery.viewInsetsOf(context);
return AnimatedPadding(
  duration: const Duration(milliseconds: 180),
  padding: EdgeInsets.only(bottom: insets.bottom),
  child: const ConnectionForm(),
);

จำกัด maxHeight และทำ content เลื่อนได้ด้วย เพราะยก sheet อย่างเดียวอาจเหลือความสูงไม่พอเมื่อ PDA เป็น landscape

6. APIs ที่ rebuild แคบกว่า

ใช้ MediaQuery.sizeOf, paddingOf, viewInsetsOf เมื่อสนใจ property เดียว แทน MediaQuery.of ทั้ง object เพื่อให้ dependency ชัดและลด rebuild จาก property อื่น รวมทั้งอ่าน textScaler/platformBrightness/highContrast เพื่อ accessibility ตาม use case

7. แบบฝึกหัด

Bottom action bar ถูก navigation gesture บัง แต่ body มี SafeArea อยู่แล้ว ควรแก้ที่ไหน?

แนวคำตอบ

ตรวจ tree ว่า action bar เป็น descendant ของ SafeArea หรือเป็น bottomNavigationBar/overlay คนละ subtree ถ้าอยู่นอกให้ครอบเฉพาะ action bar ด้วย SafeArea(top: false) หรือเพิ่ม padding จาก MediaQuery.paddingOf(context).bottom ที่ owner อย่าบวกทั้ง body และ bar ซ้ำ

8. จุดพลาด

อย่าใช้ MediaQuery width เป็น breakpoint ภายใน reusable card เพราะมันเห็นทั้งหน้าจอแม้ card อยู่ pane แคบ ใช้ LayoutBuilder ของ card/pane และใช้ MediaQuery เฉพาะ view-level concerns
