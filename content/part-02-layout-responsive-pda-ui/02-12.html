ระดับ: เริ่มต้น–กลางใช้เวลา: 30–40 นาทีลงมือทำ: จัดกลุ่มข้อมูลให้อ่านง่ายด้วย widget สำเร็จรูป
ต้องผ่านอะไรมาก่อน: 1.2 (ธีมและ Theme.of) และ 2.11 (ลำดับความสำคัญของข้อมูล)
จบบทนี้แล้วจะทำได้: ใช้ Card, Chip และตัวเลขแจ้งเตือนอย่างสม่ำเสมอ และออกแบบสีสถานะที่ผู้ใช้ตาบอดสีก็แยกออก

1. ปัญหาที่บทนี้แก้

หน้าจอรายการที่มีแต่ข้อความเรียงกันอ่านยากมาก โดยเฉพาะเมื่อพนักงานต้องกวาดตาหาข้อมูลอย่างรวดเร็วขณะทำงาน

Flutter มี widget สำเร็จรูปที่ช่วยจัดกลุ่มและแสดงสถานะให้อยู่แล้ว บทนี้จะสอนใช้ให้ถูก และที่สำคัญกว่าคือใช้ให้ สม่ำเสมอทั้งแอป เพราะการที่สีส้มหมายถึงคนละอย่างในสองหน้าจอ อันตรายกว่าการไม่มีสีเลย

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
Cardกล่องที่มีเงาและมุมโค้ง ใช้จัดกลุ่มข้อมูลหนึ่งหน่วย
Chipป้ายเล็ก ๆ สำหรับข้อมูลประกอบหรือตัวกรอง
badgeตัวเลขแจ้งเตือนที่ซ้อนบนไอคอน
visual hierarchyการทำให้ตาเห็นสิ่งสำคัญก่อน
contrastความต่างของสีที่ทำให้อ่านออก

3. Mental model: หนึ่งการ์ด หนึ่งหน่วยงาน

ในแอปคลัง หนึ่ง Card ควรตรงกับ หนึ่งสิ่งที่พนักงานทำงานด้วย — หนึ่งพาเลท หนึ่งใบงาน หนึ่งรายการรับเข้า

ประโยชน์ที่ตามมาคือผู้ใช้รู้ทันทีว่าข้อมูลชิ้นไหนเป็นของชิ้นไหน โดยไม่ต้องอ่าน

Card(
  child: Padding(
    padding: const EdgeInsets.all(12),
    child: Column(
      children: [
        // ทุกอย่างในนี้เป็นของพาเลทใบเดียวกัน
      ],
    ),
  ),
)
อย่าใส่ Card ซ้อน Card โดยไม่มีเหตุผล เพราะเงาซ้อนกันทำให้ตาสับสนว่าอะไรอยู่ในอะไร และกินระยะขอบเพิ่มอีกชั้นซึ่งบน PDA แคบ ๆ เสียพื้นที่มาก (ทบทวน 2.4 เรื่องระยะขอบสะสม)

4. ดูของจริงใน lab

Card(

        const SizedBox(height: 8),

สังเกตว่า Card ทำให้เราไม่ต้องใส่ตัวคั่นระหว่างแถวเลย — ตามที่บอกไว้ใน 2.7 ว่าเงาและช่องว่างทำหน้าที่แทนเส้นคั่นได้ดีกว่า

ส่วน visualDensity: VisualDensity.compact ทำให้ป้ายเล็กลงเล็กน้อย ซึ่งเหมาะกับ PDA ที่พื้นที่จำกัด

5. Chip แต่ละแบบใช้ต่างกัน

ชนิดใช้เมื่อตัวอย่างในงานคลัง
Chipแสดงข้อมูลอย่างเดียว กดไม่ได้ตำแหน่งจัดเก็บ
FilterChipเลือกได้หลายตัวเพื่อกรองกรองตามโซน A B C
ChoiceChipเลือกได้ตัวเดียวเลือกกะเช้า/บ่าย/ดึก
ActionChipกดแล้วทำอะไรบางอย่าง“ดูรายละเอียด”
ถ้าจะให้กดได้ ต้องใช้ชนิดที่ออกแบบมาให้กด อย่าเอา Chip ธรรมดาไปห่อ GestureDetector เพราะจะไม่มีเอฟเฟกต์ตอนกด ไม่มีเสียงตอบรับ และโปรแกรมอ่านหน้าจอจะไม่ประกาศว่าเป็นปุ่ม — ผู้ใช้จะไม่รู้ว่ากดได้

6. สีสถานะต้องมาจากที่เดียว

ความผิดพลาดที่พบบ่อยที่สุดคือเขียน if เลือกสีกระจายอยู่ทุกหน้าจอ ผลคือสถานะเดียวกันมีสีต่างกันในแต่ละหน้า

// รวมไว้ที่เดียว พร้อมทั้งสี ไอคอน และข้อความ
enum TaskStatus {
  waiting('รอเริ่ม', Icons.schedule),
  active('กำลังทำ', Icons.play_arrow),
  done('เสร็จแล้ว', Icons.check_circle),
  failed('ผิดพลาด', Icons.error_outline);

  const TaskStatus(this.label, this.icon);

  final String label;
  final IconData icon;

  Color colorOf(ColorScheme scheme) => switch (this) {
    TaskStatus.waiting => scheme.outline,
    TaskStatus.active => scheme.primary,
    TaskStatus.done => scheme.tertiary,
    TaskStatus.failed => scheme.error,
  };
}

นี่คือ enhanced enum จาก D1.10 ที่ใช้จริง — ข้อความ ไอคอน และสี ผูกติดกับสถานะไปตลอด เมื่อเพิ่มสถานะใหม่ analyzer จะชี้จุดที่ต้องแก้ให้ทันที

7. สีอย่างเดียวไม่พอ

ผู้ชายประมาณ 1 ใน 12 คนแยกสีแดงกับเขียวได้ไม่ดี ซึ่งเป็นสองสีที่ใช้บอก “สำเร็จ” กับ “ผิดพลาด” พอดี

ทางแก้ไม่ใช่เลี่ยงสี แต่คือ อย่าให้สีเป็นช่องทางเดียว

ช่องทางตัวอย่างช่วยใคร
สีแดง/เขียวคนทั่วไปที่กวาดตาเร็ว ๆ
ไอคอนเครื่องหมายถูก/เครื่องหมายตกใจผู้ใช้ตาบอดสี
ข้อความ“เสร็จแล้ว” / “ผิดพลาด”ทุกคน รวมถึงโปรแกรมอ่านหน้าจอ

สังเกตว่า enum ในหัวข้อ 6 บังคับให้มีครบทั้งสามอย่างโดยอัตโนมัติ เพราะทุกค่าต้องระบุทั้งข้อความและไอคอนตั้งแต่ตอนประกาศ — เป็นการออกแบบชนิดข้อมูลให้ทำสิ่งที่ถูกต้องได้ง่ายกว่าทำผิด

วิธีทดสอบอย่างเร็ว: ถ่ายภาพหน้าจอแล้วแปลงเป็นขาวดำ ถ้ายังแยกสถานะออกได้แปลว่าผ่าน

8. ตัวเลขแจ้งเตือน

Badge(
  label: Text(count > 99 ? '99+' : '$count'),
  isLabelVisible: count > 0,          // ซ่อนเองเมื่อไม่มีงานค้าง
  child: const Icon(Icons.inbox_outlined),
)

สามข้อที่ต้องทำเสมอ

  1. ซ่อนเมื่อเป็นศูนย์ — “0” ไม่ได้ให้ข้อมูลอะไรและรบกวนสายตา
  2. จำกัดรูปแบบ — 99+ เพราะเลข 4 หลักจะล้นออกนอกไอคอน
  3. มีข้อความสำหรับโปรแกรมอ่านหน้าจอ — “งานค้าง 12 รายการ” ไม่ใช่แค่ “12”

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
สีเดียวกันหมายคนละอย่างในสองหน้าจอเขียน if เลือกสีกระจายรวมไว้ใน enum ที่เดียว
ผู้ใช้แยกสถานะไม่ออกใช้สีเป็นช่องทางเดียวเพิ่มไอคอนและข้อความ
กดป้ายแล้วไม่มีอะไรเกิดขึ้นใช้ Chip ธรรมดาห่อ GestureDetectorใช้ ActionChip หรือ FilterChip
ตัวเลขแจ้งเตือนล้นออกนอกไอคอนไม่ได้จำกัดรูปแบบใช้ 99+
เห็นเลข 0 บนทุกไอคอนไม่ได้ซ่อนเมื่อไม่มีข้อมูลตั้ง isLabelVisible
อ่านไม่ออกในโหมดมืดเขียนสีตายตัวแทนสีจากธีมใช้ค่าจาก ColorScheme (1.2)
การ์ดซ้อนการ์ดจนดูรกใช้ Card เป็นกรอบตกแต่งใช้เมื่อเป็นการจัดกลุ่มจริง

10. แบบฝึกหัด

ออกแบบการแสดงสถานะใบงานสี่ค่า — รอเริ่ม กำลังทำ เสร็จแล้ว ผิดพลาด — โดย

  1. ผู้ใช้ตาบอดสีต้องแยกออกได้
  2. สถานะเดียวกันต้องหน้าตาเหมือนกันทุกหน้าจอ
  3. ใช้ได้ทั้งโหมดสว่างและโหมดมืด
  4. เพิ่มสถานะที่ห้าในอนาคตแล้วต้องรู้ว่าต้องไปแก้ตรงไหนบ้าง
ดูแนวคำตอบและเหตุผล
enum TaskStatus {
  waiting('รอเริ่ม', Icons.schedule),
  active('กำลังทำ', Icons.play_arrow),
  done('เสร็จแล้ว', Icons.check_circle),
  failed('ผิดพลาด', Icons.error_outline);

  const TaskStatus(this.label, this.icon);

  final String label;
  final IconData icon;

  Color colorOf(ColorScheme scheme) => switch (this) {
    TaskStatus.waiting => scheme.outline,
    TaskStatus.active => scheme.primary,
    TaskStatus.done => scheme.tertiary,
    TaskStatus.failed => scheme.error,
  };
}

class StatusChip extends StatelessWidget {
  const StatusChip({super.key, required this.status});

  final TaskStatus status;

  @override
  Widget build(BuildContext context) {
    final color = status.colorOf(Theme.of(context).colorScheme);

    return Chip(
      avatar: Icon(status.icon, size: 18, color: color),   // ช่องทางที่ 2
      label: Text(status.label),                           // ช่องทางที่ 3
      side: BorderSide(color: color),                      // ช่องทางที่ 1
      visualDensity: VisualDensity.compact,
    );
  }
}

ข้อ 1 — ผู้ใช้ตาบอดสีแยกออก

เพราะมีสามช่องทางพร้อมกัน ไอคอนของทั้งสี่สถานะเป็นรูปคนละแบบชัดเจน (นาฬิกา ลูกศร เครื่องหมายถูก เครื่องหมายตกใจ) และมีข้อความกำกับ — ถ้าแปลงเป็นขาวดำก็ยังแยกได้

ข้อ 2 — เหมือนกันทุกหน้าจอ

เพราะทุกหน้าจอใช้ StatusChip ตัวเดียวกัน และมันดึงทุกอย่างจาก enum ไม่มีที่ไหนเขียนสีหรือข้อความเองได้เลย

ข้อ 3 — ใช้ได้ทั้งสองโหมด

เพราะ colorOf รับ ColorScheme เข้ามาแล้วเลือกจากค่าในนั้น ไม่ได้เขียน Colors.red ตายตัว — เมื่อสลับโหมดมืด ธีมจะให้ค่าที่เหมาะกับพื้นหลังใหม่โดยอัตโนมัติ (ทบทวน 1.2)

ข้อ 4 — เพิ่มสถานะที่ห้า

เพิ่มค่าใน enum หนึ่งบรรทัด แล้วรัน flutter analyze — มันจะชี้ว่า switch ใน colorOf ยังไม่ครอบคลุมค่าใหม่ ตามที่เรียนใน D1.10 หัวข้อ 5

paused('พักไว้', Icons.pause_circle_outline);

// analyzer: The type 'TaskStatus' is not exhaustively matched
// → ชี้ให้ไปเติมใน colorOf ทันที

นี่คือจุดที่แสดงว่าการออกแบบชนิดข้อมูลดี ๆ ให้ผลตอบแทนจริง — เราไม่ต้องจำเองว่ามีที่ไหนต้องแก้บ้าง เครื่องมือบอกให้

จุดที่คนมักพลาด: เขียน colorOf โดยมี _ => Colors.grey ปิดท้าย ซึ่งทำให้สถานะใหม่ได้สีเทาเงียบ ๆ โดยไม่มีใครรู้ว่าลืมกำหนด — เป็นสิ่งที่ D1.10 เตือนไว้ตรง ๆ ว่าการเติม _ ทำลายประโยชน์ข้อสำคัญที่สุดของ enum

ลองต่อ: ถ่ายภาพหน้าจอที่มี StatusChip ครบทั้งสี่ค่า แล้วแปลงเป็นขาวดำ ถ้ายังแยกออกได้ทั้งหมดแปลว่าออกแบบผ่าน

11. สรุปท้ายบท

  • หนึ่ง Card ควรตรงกับหนึ่งสิ่งที่ผู้ใช้ทำงานด้วย
  • อย่าใส่ Card ซ้อนกันโดยไม่มีเหตุผล
  • เลือกชนิดของ Chip ตามว่ากดได้หรือไม่
  • รวมสี ไอคอน และข้อความของสถานะไว้ใน enum ที่เดียว
  • สีอย่างเดียวไม่พอ ต้องมีไอคอนและข้อความด้วย
  • ตัวเลขแจ้งเตือนต้องซ่อนเมื่อเป็นศูนย์และจำกัดรูปแบบ
  • ใช้สีจากธีมเสมอ เพื่อให้โหมดมืดทำงานได้เอง
