ยก stateขึ้นถึง ownerร่วมที่ต่ำที่สุด แล้วส่ง immutable dataลงและ event callbackกลับขึ้น วิธีนี้ให้ source of truthเดียวโดยไม่ยกทุก stateถึง app root

1. Data down, events up

class QuantityPanel extends StatelessWidget {
  const QuantityPanel({
    required this.quantity,
    required this.onChanged,
  });
  final int quantity;
  final ValueChanged<int> onChanged;
}

Childไม่แก้ modelเอง Parent/store validate/clampแล้วส่งค่ารอบใหม่ลงมา

2. เมื่อ siblingsต้อง sync

StepperและTextFieldแก้ quantityเดียวกัน ให้ parentถือ int/controller policy แล้ว childrenส่ง delta/valueกลับ หากแต่ละ childมี copyของ quantityจะ driftเมื่ออีกฝั่งเปลี่ยน

3. Lift เท่าที่จำเป็น

Stateโหมด chartใช้เฉพาะ SummaryCardจึงอยู่ใน card แต่ selected taskที่ detail/listใช้ร่วมกันควรอยู่ feature container/store อย่ายก hover/expanded tileทุกใบเข้า God Storeจน notifyหนึ่งครั้ง rebuildทั้งแอป

4. Typed event

ใช้ VoidCallback, ValueChanged<T> หรือ domain callbackเช่น Future<void> Function(TaskId) แทน Functionกว้าง Callbackควรสื่อ user intent “confirmPick” ไม่ใช่ expose setterทุก fieldของ parent

5. Async callback ownership

Childปุ่มสามารถ await callbackเพื่อแสดง local pressed stateได้ แต่ business loading/errorควรอยู่ command ownerและส่ง busy/resultลง Childไม่จับ exceptionแล้วกลืนหาก ownerต้อง rollback/reconcile

6. Alternatives เมื่อ prop drillingลึก

ถ้าส่ง data/callbackผ่าน intermediate widgetsหลายชั้นที่ไม่ใช้ ให้ย้าย feature ownerใกล้ consumersหรือใช้ Inherited/Provider scoped subtree ไม่ใช้ global singletonทันที Constructor injectionยังดีที่สุดเมื่อ dependencyตรงและชั้นน้อย

7. แบบฝึกหัด

TaskListและTaskDetailต้องเห็น selected task; AppBarไม่ใช้มัน Ownerอยู่ไหน?

เฉลย

อยู่ parent/containerที่ครอบ List+Detailต่ำที่สุด ส่ง selected ID/taskลงและ onSelect/onClearกลับ AppBarไม่ต้องรับ หาก selectionต้องคงข้าม routeหรือใช้ command asyncหลายหน้า ค่อยอยู่ feature storeที่มี lifetimeยาวขึ้น

8. จุดพลาด

อย่าส่ง mutable List/storeทั้งก้อนให้ childทุกตัวแล้วปล่อยแก้เอง เพราะ ownershipและ notificationหาย ใช้ unmodifiable view/snapshot + commandsที่รักษา invariants
