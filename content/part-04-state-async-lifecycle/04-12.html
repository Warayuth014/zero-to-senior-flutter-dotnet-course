Listener/subscriptionเป็นทรัพยากรเชื่อม producerกับ consumer ต้อง subscribeเมื่อ ownerพร้อม, unsubscribe sourceเดิมเมื่อ dependencyเปลี่ยน และ unsubscribeตอน dispose มิฉะนั้น callbackซ้ำหรือเรียก objectที่ตายแล้ว

1. ChangeNotifier listener

@override
void initState() {
  super.initState();
  widget.store.addListener(_onStoreChanged);
}

@override
void dispose() {
  widget.store.removeListener(_onStoreChanged);
  super.dispose();
}

ถ้าเพียง renderใช้ ListenableBuilderจัด lifecycle listenerให้ ไม่ต้อง manual

2. didUpdateWidget

@override
void didUpdateWidget(covariant StoreView oldWidget) {
  super.didUpdateWidget(oldWidget);
  if (oldWidget.store == widget.store) return;
  oldWidget.store.removeListener(_onStoreChanged);
  widget.store.addListener(_onStoreChanged);
}

ป้องกันฟัง storeเก่าเมื่อ parentเปลี่ยน instance

3. StreamSubscription

final subscription = stream.listen(...) ต้อง cancel/await cancelตาม API Pause/resumeเมื่อ app lifecycleหรือ tabไม่ activeได้ Error/done handlersต้องกำหนด stateและ reconnect policy ไม่ assume streamอยู่ตลอด

4. WidgetsBindingObserver

Absolute shell addObserverใน initState, refresh connectionเมื่อ resumed และ removeObserverใน dispose Observer globalที่ไม่ถอดทำ shellเก่ารับ lifecycleซ้ำและอาจใช้ disposed store

5. One-shot events

อย่าเก็บ toast/navigationเป็น persistent stateแล้ว listenerใหม่เล่นซ้ำ ใช้ event ID/queue/consume semantics หรือให้ UI callback ownerรับ effect ขณะ mounted WarehouseStoreใช้ onToast/onFlash callbacksจาก shellซึ่งง่ายแต่ couplingสูงและต้อง clear/owner lifetimeให้ชัด

6. Subscribe order

สร้าง state/resourcesก่อน subscribe เพราะ producerอาจ emitทันที Unsubscribeก่อน dispose consumers Timer/subscription callbackตรวจ mounted/current generationเมื่อมี async gap

7. แบบฝึกหัด

Widgetเปลี่ยนจาก store Aเป็น Bแต่ callbackยังมาสองครั้ง สาเหตุและวิธีแก้?

เฉลย

subscribe Aใน initStateแต่ไม่ removeเมื่อ didUpdateWidget ให้ remove A/add Bเมื่อ identityเปลี่ยน และ remove current Bใน dispose ตรวจว่า callbackไม่ได้ add listenerซ้ำทุก build

8. จุดพลาด

Anonymous closureที่ addListenerแล้วสร้าง closureใหม่ตอน removeจะถอดไม่ออก เก็บ callback referenceหรือใช้ named methodเดียวกัน และอย่า subscribeใน build
