Polling คือการแลก freshnessกับ battery, radio, server load และ race Timer.periodicไม่รอ Futureเดิมจบ จึงต้องมี in-flight guard, lifecycle policy, backoff และ disposeที่ชัด

1. Timer.periodic

Timer? _timer;

void startPolling() {
  _timer?.cancel();
  _timer = Timer.periodic(const Duration(seconds: 5), (_) {
    unawaited(_refreshIfIdle());
  });
}

@override
void dispose() {
  _timer?.cancel();
  super.dispose();
}

2. Overlapping request

bool _refreshing = false;
Future<void> _refreshIfIdle() async {
  if (_refreshing) return;
  _refreshing = true;
  try { await repository.refresh(); }
  finally { _refreshing = false; }
}

ถ้า requestใช้ 8sแต่ timer 5s guardจะ skip tickแทนซ้อน request

3. Poll เฉพาะที่ดู

WarehouseStore timer 5sเรียก refreshตาม screen: tasks/history/picks/cycle-countที่เกี่ยวข้อง ลด callหน้าที่ไม่เปิด แต่ storeยังตื่นทุก 5s ควรพิจารณา start/stopตาม route/app lifecycleหรือ realtime SignalRใน Partหลัง

4. Lifecycle

เมื่อ app paused/backgroundหยุดหรือยืด polling; resumedให้ refreshทันทีแล้ว restart schedule Absolute connection dotเลือกไม่ pollตลอดวัน แต่ refreshตอน shell mount/resume/เปลี่ยน profile เป็น policyประหยัดแบตที่เหมาะกับข้อมูลไม่ต้อง realtime

5. Backoff และ jitter

เมื่อ networkล้มไม่ควรยิงทุก 5sตลอด ใช้ exponential backoffมีเพดานและ jitterลด clientพร้อมกัน resetเมื่อ success/foreground/manual retry แยก offline detectionจาก server errorอย่างระวัง

6. Timer test

Inject scheduler/clockหรือใช้ fake_async เพื่อเดินเวลา deterministic ทดสอบ no overlap, stop/dispose, background/resume และ backoff ไม่รอเวลาจริงใน unit test
