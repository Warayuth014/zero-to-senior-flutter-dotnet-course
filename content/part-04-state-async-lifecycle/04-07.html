Loading/Error/Empty/Success เป็นสถานะคนละความหมาย ไม่ควรอนุมานทั้งหมดจาก listว่างและ boolเดียว เพราะ emptyอาจเป็นผลสำเร็จ, errorอาจยังมี stale data และ refreshไม่ควรแทนหน้าเดิมด้วย spinnerเต็มจอ

1. Sealed state

sealed class LoadState<T> { const LoadState(); }
class Initial<T> extends LoadState<T> { const Initial(); }
class Loading<T> extends LoadState<T> { const Loading(); }
class Data<T> extends LoadState<T> {
  const Data(this.value, {this.refreshing = false});
  final T value; final bool refreshing;
}
class Failure<T> extends LoadState<T> {
  const Failure(this.message, {this.previous});
  final String message; final T? previous;
}

2. Empty เป็น Data

โหลดสำเร็จได้ listว่างคือ empty stateที่มีคำอธิบาย/action เช่น “ยังไม่มีงาน” ไม่ใช่ errorหรือ loading Skeleton/spinnerต้องใช้เมื่อ requestยังไม่จบเท่านั้น

3. Initial load vs refresh

Initialไม่มี dataจึงแสดง skeleton/full progress; refreshมี dataเดิมควรรักษารายการและแสดง indicatorเล็ก ป้องกันหน้ากระพริบทุก polling Absoluteหลาย loaderคง listเดิมระหว่าง fetchและ notifyเมื่อผลมา แต่ควรมี per-resource refreshing/errorชัดเมื่อ UXต้องการ

4. Partial failure

Dashboardโหลด tasks, inventory, summaryพร้อมกัน ถ้า summary informational failไม่ควรบล็อก tasks WarehouseStoreจับ error summaryแล้วเงียบเพื่อให้หน้าใช้ได้ แต่ productionควรมี logging/telemetry แยก stateต่อ resourceแทน global errorก้อนเดียว

5. Retry semantics

Error stateบอก retryableหรือไม่ และ retry commandต้องรักษา input/context 401→login, 409→refresh/reconcile, timeout→retryได้, validation→แก้ input อย่าแสดงปุ่ม Retryเดียวทุกชนิด

6. Render exhaustive

return switch (state) {
  Initial() || Loading() => const TaskSkeleton(),
  Data(value: final tasks) when tasks.isEmpty => const EmptyTasks(),
  Data(value: final tasks) => TaskList(tasks: tasks),
  Failure(:final message, previous: null) => ErrorPanel(message),
  Failure(:final previous) => TaskListWithError(previous!),
};
