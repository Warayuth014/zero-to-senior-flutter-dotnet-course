setState บอก framework ว่า local mutable state ของ State object เปลี่ยนและ subtree นี้ต้อง build ใหม่ มันไม่เก็บ stateให้เราและไม่ควรครอบงาน async ทั้งก้อน ใช้เมื่อ owner/consumerอยู่ใกล้และ lifetimeผูกกับหน้าจอ

1. Local UI state

class _SummaryCardState extends State<SummaryCard> {
  DashboardMode _mode = DashboardMode.list;

  void _select(DashboardMode next) {
    if (_mode == next) return;
    setState(() => _mode = next);
  }
}

โหมด list/chart ของ SummaryCard ใน Absolute เป็น local presentation state ที่ไม่ต้องให้ทั้ง WarehouseStoreรู้

2. setState ต้อง synchronous

Callbackของ setStateต้องแก้ค่าแบบ synchronousและคืนทันที ห้าม setState(() async { ... }) ให้ awaitนอกแล้ว setStateเฉพาะ snapshotที่พร้อม เพราะ frameworkต้องรู้ทันทีว่า mutationจบเมื่อไร

3. Scope ของ rebuild

setStateทำให้ State subtree buildใหม่ ไม่ได้ repaintทุกจุดเสมอ Element/render diffจะ reuseส่วนที่ไม่เปลี่ยน แต่ build methodใหญ่ยังมี cost จึงแตก componentตาม responsibilityและวาง stateใกล้ consumer

4. State ที่เหมาะ/ไม่เหมาะ

  • เหมาะ: toggle, selected tab, controller visibility, animation flag
  • ไม่เหมาะ: inventoryที่หลายหน้าต้องใช้, auth session, cache/API workflowข้าม route

ข้อมูลข้าม featureควรมี owner/store/repositoryชัด ไม่ส่ง setState callbackทอดยาวทั้งแอป

5. Equality guard

ถ้าค่าใหม่เท่าเดิมไม่ต้อง setState ลด rebuildและ side effects downstream แต่ห้าม optimizeจนไม่ notifyเมื่อ object mutableภายในเปลี่ยน ทางที่ดีใช้ immutable snapshot/equalityตาม semantic

6. Mutation ก่อน/ใน setState

Frameworkต้องการให้เรียก setStateเมื่อ mutationกระทบ build เขียน mutationใน callbackเพื่ออ่าน intentง่าย หาก mutateก่อนแล้ว setStateเปล่ายังทำงานแต่เสี่ยง return/exceptionจนลืมแจ้ง และอย่าวาง API/file I/Oใน callback

7. แบบฝึกหัด

หน้า scanมี showHelp, current pallet และรายการ inventory อะไรควรอยู่ local?

เฉลย

showHelpเป็น local setState; current palletอาจอยู่ workflow controllerถ้ามีหลาย step/ต้องคงเมื่อ UIสลับ; inventoryอยู่ store/repositoryเพราะโหลด asyncและหลาย consumer หลักคือ ownership/lifetime ไม่ใช่จำนวนตัวแปร

8. จุดพลาด

อย่าเรียก setStateใน build, dispose หรือหลัง State unmounted และอย่าใช้ setStateเพื่อบังคับ refreshเมื่อ source of truthไม่เปลี่ยน ต้องแก้ source/notification contract
