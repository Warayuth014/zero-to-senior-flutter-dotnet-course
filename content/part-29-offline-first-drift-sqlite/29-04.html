Schema คือ sync contract ฝั่งเครื่อง: ออกแบบให้ตอบได้ทั้ง “ผู้ใช้เห็นอะไร” และ “ยังมี intent ใดต้องส่ง”

1. CachedTasks

lab เก็บ id, ต้นทาง, ปลายทาง, status, cachedAt และ hiddenByCommand แยกเวลาที่ cache รับข้อมูลจาก server ออกจาก local projection

2. PendingCommands

outbox เก็บ commandId, taskId, kind, JSON payload, createdAt, attempts และ lastError เพื่อ replay/diagnose ได้หลัง restart

3. Primary keys

task ID ป้องกัน cache ซ้ำ ส่วน command ID เป็น idempotency key เดิมตลอดทุก retry ห้ามสร้างใหม่ตอน sync

4. Constraints

ใช้ NOT NULL/default/check/foreign key เท่าที่ domain รับประกัน Constraint ทำให้ข้อมูลเสียหยุดใกล้จุดเขียนกว่าปล่อยไป crash ใน UI

5. Indexes

สร้าง index จาก query จริง เช่น status + location หรือ outbox createdAt ตรวจ query plan ก่อนเพิ่ม เพราะ index ทำให้ write และพื้นที่เพิ่ม

6. JSON payload

payload ช่วยรองรับหลาย command แต่ควร version schema และ validate ตอนอ่าน ไม่พึ่ง dynamic map โดยไม่ตรวจชนิด

7. Server metadata

ระบบจริงควรเก็บ ETag/rowVersion/server sequence/deleted tombstone เพื่อเปรียบเทียบเวอร์ชันและรับ deletion อย่างถูกต้อง

8. Exercise

วาด unique keys, indexes และ state transition ของ task/outbox ก่อนเพิ่ม column; ทุก column ต้องมีเหตุผลด้าน query, sync หรือ audit
