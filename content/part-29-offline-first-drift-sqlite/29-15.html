Production database checklist: correctness มาก่อน แล้วจึง security, retention, performance และ observability ที่วัดได้

1. Sensitive data

ลด PIIที่ cache, redact log และ purgeตาม logout/tenant policy SQLiteปกติไม่ใช่ encryption guarantee ต้องทำ threat modelก่อนเลือก encryption

2. Keys

ถ้าใช้ encrypted DB กุญแจต้องอยู่ secure keystore/keychain ไม่ hard-codeหรือเก็บข้าง database และต้องวาง key rotation/recovery

3. Retention

กำหนด TTL/cleanupสำหรับ completed cache, acknowledged audit, error payloadและไฟล์แนบ แต่ห้ามลบ pending commandเพียงเพราะเก่าโดยไม่ escalate

4. Performance

วัด query latency, row count, DB size, write transaction และ frame time ใช้ pagination/index/batchตามหลักฐาน ไม่ optimizeจากความรู้สึก

5. Maintenance

เข้าใจ WAL/checkpoint/vacuumตาม executorและplatform ทดสอบพื้นที่เต็มและ disk I/O failure เพื่อให้ errorไม่กลายเป็น data lossเงียบ

6. Observability

เก็บ metric queue depth, oldest command age, sync success/failure class, conflict countและmigration duration โดยไม่ส่ง secret/payloadเกินจำเป็น

7. Diagnostics

support screenควรแสดง schema/app version, last syncและsafe identifiers พร้อม exportแบบ redact ไม่ให้ผู้ใช้ส่ง databaseจริงผ่านแชต

8. Checkpoint

ตั้ง alert เมื่อ oldest pending ageเกิน SLA ไม่ใช่ดูแค่ว่า app crashหรือไม่ เพราะ syncอาจเสียแบบเงียบได้
