At-least-once delivery: client อาจส่งคำสั่งเดิมซ้ำหลัง timeout ดังนั้น correctness ต้องมาจาก stable idempotency key และผล replay ที่ serverจำได้

1. Stable command ID

สร้าง ID ตอน user intent ถูก enqueue และเก็บใน DB ทุก retry ส่งค่าเดิมผ่าน Idempotency-Key ห้ามสร้างใน HTTP methodแต่ละรอบ

2. Outcome unknown

timeout หลัง server commit ทำให้ clientไม่รู้ผล การ retry ID เดิมต้องคืนผลเดิมโดยไม่ทำ side effectซ้ำ ซึ่ง endpoint Part 26 รองรับ

3. Error classes

retry network/408/429/5xx; หยุดหรือขอผู้ใช้แก้สำหรับ 400/403/409 ตาม contract และ refresh auth สำหรับ 401

4. Backoff

delay = min(cap, base × 2^attempt) + random jitter

ใช้ nextAttemptAt แบบ durable เพื่อไม่ยิงทันทีทุก app restart

5. Poison command

หลัง threshold ให้ย้ายเป็น needsAttention/dead-letter พร้อมเหตุผลและ action ไม่ปล่อยรายการแรกบล็อก queue ตลอดไป

6. Rate limits

เคารพ Retry-After และจำกัด concurrency ฝั่ง client การ reconnect ของอุปกรณ์จำนวนมากพร้อมกันอาจสร้าง thundering herd

7. Lab evidence

test บังคับ remote fail แล้วตรวจ attempts = 1, lastError และ commandยังอยู่ อีก testยืนยันว่า replay ใช้ command IDเดิม

8. Checkpoint

สร้างตาราง HTTP/error → retry/auth/conflict/drop/manual action และให้ product/backendรับรองก่อน production
