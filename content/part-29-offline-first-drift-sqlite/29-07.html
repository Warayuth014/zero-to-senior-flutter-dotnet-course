Read-through cache: remote refresh เขียน cache แล้วคืน local projection; ถ้า remote ล้มและ cache มีข้อมูล ผู้ใช้ยังทำงานต่อได้

1. Repository boundary

UI เรียก TaskRepository เหมือนเดิมจึงไม่รู้รายละเอียด SQLite การเพิ่ม offline ไม่ทำให้ widget ผูกกับ query package

2. Refresh path

fetchOpen → remote.fetchOpen
→ database.replaceFromServer
→ database.visibleTasks → UI

3. Failure path

เมื่อ remote throw จะคืน cache ถ้ามี หาก cache ว่างต้องส่ง error ขึ้น UI เพื่อไม่ทำให้ “ไม่มีงาน” ปลอมเป็น success

4. Merge rule

replaceFromServer ไม่ overwrite task ที่มี pending command มิฉะนั้น refresh จะทำงานที่ผู้ใช้เพิ่งปิด offline โผล่กลับมา

5. Snapshot deletion

ถ้า endpoint รับประกันว่า response คือ snapshot เต็มจึงลบ local row ที่ไม่อยู่ remote ได้; pagination/delta feed ต้องใช้ cursor/tombstone rule อื่น

6. Staleness

แสดง last synced/offline banner เมื่อข้อมูลอาจเก่า Business บางอย่างต้องปิดปุ่มหาก stale เกิน threshold ไม่ใช่ทุก action offline ได้

7. Error taxonomy

แยก no network, auth expired, server validation และ corrupt cache เพราะ fallback เหมาะเฉพาะ failure ที่ cache ยังปลอดภัย

8. Test

offline_repository_test.dart โหลด remote หนึ่งครั้ง ปิด network แล้วพิสูจน์ว่า task เดิมยังคืนจาก local DB
