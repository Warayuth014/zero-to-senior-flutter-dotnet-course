Manifest คือ capability declaration: ขอเฉพาะสิทธิ์ที่ feature ใช้จริงและวางใน source set ที่ถูกต้อง ปัจจุบัน main manifest ของ wmsapp ไม่มี INTERNET ขณะที่ permission อยู่ใน debug/profile จึงต้องตรวจ release manifest ก่อนแจก

1. INTERNET ใน main

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
  <uses-permission android:name="android.permission.INTERNET" />
  <application ...>...</application>
</manifest>

network production ต้องประกาศใน src/main; debug/profile overlay มีไว้เพิ่มค่าพัฒนา ไม่ถูก merge เข้า release

2. กล้อง/รูป

Image picker อาจต้อง permission/config ต่างกันตาม Android version และวิธีเลือกภาพ อ่าน merged manifest ของ plugin และเอกสารเวอร์ชันที่ล็อกไว้ อย่าประกาศ storage permission กว้าง “เผื่อไว้” หาก system picker ไม่ต้องใช้

3. Runtime permission

manifest declaration ไม่เท่ากับ runtime grant ขอเมื่อผู้ใช้กด feature, อธิบายเหตุผล, รองรับ deny/deny ถาวร และเปิด Settings อย่างมีทางกลับ Feature ที่ไม่ต้องใช้ permission ต้องยังทำงานได้

4. Exported components

Activity/receiver/service ที่มี intent filter ต้องทบทวน android:exported และ validate input/deep link MainActivity launcher ต้อง exported แต่ component ภายในควร false หากไม่ต้องรับจากแอปอื่น

5. Application ID

ทั้งสองโปรเจกต์ยังใช้ com.example... ต้องกำหนด reverse-domain ที่องค์กรควบคุมก่อนเผยแพร่ เพราะ application ID คือ identity ของแอปและเปลี่ยนภายหลังเท่ากับแอปใหม่

6. Merged manifest

ตรวจผล merge ของ main + flavor + build type + plugins ไม่อ่านไฟล์เดียวแล้วสรุป ใช้ Android Studio Merged Manifest หรือ build report เพื่อตรวจ permission/provider ที่ dependency เพิ่มมา

7. Feature audit

8. Security gate

release manifest ไม่มี debug-only component, broad storage/location permission, test provider หรือ cleartext global โดยไม่อนุมัติ และทุก exported component มีเหตุผล/authorization test
