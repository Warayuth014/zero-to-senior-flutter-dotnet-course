HandshakeException คือสัญญาณให้แก้ trust chain: ห้ามแก้ด้วย badCertificateCallback = (_,__,___) => true เพราะเท่ากับปิดการยืนยันตัวตนของ server และเปิดทาง man-in-the-middle

1. Certificate ต้องตรงอะไร

ยังไม่หมดอายุ/ยังไม่เริ่มก่อนเวลา, chain ถึง CA ที่ device เชื่อถือ, hostname/IP ตรง SAN และ device clock ถูกต้อง Certificate ที่ออกให้ DNS name จะไม่ผ่านเมื่อเรียกด้วย raw IP หาก SAN ไม่มี IP นั้น

2. Endpoint production

ใช้ stable DNS name เช่น wms-api.company.internal แทน IP ที่เปลี่ยนง่าย และให้ reverse proxy/load balancerจัด renewal ทดสอบ health endpoint ผ่าน URL เดียวกับแอป ไม่ใช้ URL คนละชุดสำหรับ probe กับ request

3. Private CA

ในองค์กรอาจใช้ private CA วิธีที่ถูกคือ provision root/intermediate CA ลง managed devices/MDM หรือกำหนด trust อย่างจำกัดตาม platform/build ไม่ bundle private key และไม่ trust certificate ใดก็ได้

4. Pinning trade-off

certificate/public-key pinning ลดความเสี่ยง CA ถูกใช้ผิด แต่เพิ่ม outage risk ตอน rotate ต้องมี backup pins, expiry/rotation runbook และ remote recovery ที่ปลอดภัย สำหรับหลายระบบ standard platform trust + managed CA อาจเหมาะกว่า

5. Connection probe

โค้ดจริงแยก HandshakeException จาก timeout/socket ได้ดี แต่ข้อความที่เสนอ “ลอง HTTP” ไม่ควรแสดงใน production เพราะชักนำ downgrade ให้บอกตรวจ certificate, hostname และเวลาเครื่องแทน

6. Server hardening

ใช้ TLS versions/ciphers ที่รองรับ device fleet, ส่ง full chain, redirect HTTP อย่างระวังช่วง migration, HSTS เมื่อทุก subdomain พร้อม และ monitor certificate expiry ก่อนผู้ใช้เจอ

7. Test matrix

valid chain, expired/not-yet-valid, wrong hostname, missing intermediate, untrusted root, clock skew, rotated cert และ offline ต้องแปลเป็น failure คนละแบบ ไม่ retry handshake errorแบบถี่ ๆ

8. Operational evidence

เก็บ endpoint host, certificate issuer/fingerprint แบบไม่ลับ, expiry alert, owner และ renewal rehearsal แต่ไม่ log token/request bodyหรือ private key
