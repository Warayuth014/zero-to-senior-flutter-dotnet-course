Production readiness คือหลักฐาน ไม่ใช่ความรู้สึก: checklist นี้ต้องมี owner, artifact/build ID, ผลทดสอบและ sign-off ทุก release โดย gaps จากสอง reference apps เป็นรายการแก้ก่อนใช้งานจริง ไม่ใช่เพียงหัวข้ออ่าน

1. Identity & build

  • application/bundle ID ไม่ใช่ com.example
  • version/buildเพิ่มและแสดงในแอป
  • release mode/flavor/endpointถูก
  • artifactสร้างจาก pinned clean CI

2. Signing & supply chain

  • ไม่ใช้ debug signing
  • keysอยู่ secret storeและ recoveryทดสอบแล้ว
  • dependency/lockfile/SBOM review
  • signature/checksum/provenanceบันทึก

3. Platform config

  • Android main manifestมี INTERNETและ permissionเท่าที่ใช้
  • releaseไม่เปิด cleartext global
  • iOS camera/photo/local-network descriptionsตาม feature
  • icons/names/orientation/exported componentsผ่าน

4. Network & backend

  • HTTPS chain/hostname/renewalผ่าน
  • HTTP/WebSocket/mediaไม่ downgrade
  • health/login/SignalR/uploadผ่าน production-like proxy
  • API compatibility/minimum versionและ rollbackพร้อม

5. Data & security

  • ไม่มี embedded master secrets
  • tokenเก็บ/หมดอายุ/logoutอย่างปลอดภัย
  • serverตรวจ authorization/idempotencyทุก command
  • logs/crash reports redactและจำกัด retention

6. Resilience & quality

  • analyze/unit/widget/contract/E2Eผ่าน
  • offline/timeout/duplicate/conflict/lifecycleทดสอบ
  • upgrade migrationและ pending queueผ่าน
  • profileบน PDA ไม่มี critical jank/memory leak

7. Operations

มี staged rollout, canary devices, monitoring dashboards/alerts, support runbook, incident/rollback owner, certificate/signing expiry alerts, inventory device/app versionsและช่องทาง revoke session/buildที่มีปัญหา

8. Go/No-Go

No-Go หากยังใช้ debug key, HTTPพร้อม bearer token, certificate bypass, missing production permission, embedded secret, migrationไม่มี backup/rollback หรือ critical flowไม่ผ่าน release-signed artifact ทุกข้อยกเว้นต้องมี risk ownerและวันหมดอายุ
