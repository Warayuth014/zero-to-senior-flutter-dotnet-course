Build mode ไม่ใช่ environment: debug/profile/release ควบคุม compiler, assertions และเครื่องมือวัด ส่วน dev/staging/prod คือ endpoint/configuration ต้องออกแบบแยกกันและห้ามให้ release ชี้ production โดยอาศัยชื่อ mode อย่างเดียว

1. Debug

มี assertions, service extensions, debugger/hot reload และ optimization ไม่เต็ม เหมาะพัฒนาและ widget tests แต่เวลา frame/ขนาดไฟล์ไม่แทน production อย่าส่ง debug APK ให้ผู้ใช้จริงเพราะเซ็นด้วย debug key และเปิด surface สำหรับพัฒนา

2. Profile

คงเครื่องมือ profiling สำคัญและ optimize ใกล้ release ใช้วัด jank/CPU/memory บนอุปกรณ์จริง ไม่มี hot reload แบบ debug พฤติกรรมบาง platform ต่างกัน จึงต้อง reproduce performance ใน profile ไม่ใช่ debug

3. Release

ปิด assertions/service extensions ส่วนใหญ่และ optimize/AOT ตาม platform ต้องทดสอบ login, scanner, network, image, deep link และ error handling ใน artifact ที่เซ็นจริง เพราะ code ที่อยู่หลัง assert จะไม่ทำงาน

4. เช็ก mode ในโค้ด

if (kDebugMode) { debugPrint('diagnostic only'); }
if (kProfileMode) { /* optional profiling marker */ }
if (kReleaseMode) { /* never use to choose secrets */ }

อย่าใช้ flag นี้ตัด authorization หรือ certificate validation

5. Environment แบบ typed

const environment = String.fromEnvironment('APP_ENV');
const apiBase = String.fromEnvironment('WMS_API_BASE_URL');

// validate scheme/host and fail closed at startup

--dart-define เหมาะกับ public build config ไม่ใช่ความลับ เพราะค่าถูกฝังใน binary และดึงดูได้

6. Flavors

ใช้ flavors/schemes เมื่อ dev/staging/prod ต้องมี application ID, display name, icon, signing หรือ entitlements ต่างกัน ให้เห็นชัดว่าแอปทดสอบไม่ใช่ production และติดตั้งคู่กันได้

8. Gate

CI ต้องบันทึก Flutter/Dart commit, mode, flavor, version, build number, Git SHA และ endpoint class โดยไม่เผย token พร้อม smoke test artifact เดียวกับที่จะส่ง ไม่ rebuild ใหม่หลังอนุมัติ
