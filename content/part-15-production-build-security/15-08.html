Release identity ต้องเตรียมก่อนแจก: ทั้งสองโปรเจกต์ปัจจุบันเซ็น release ด้วย debug key และ application ID ยังเป็น com.example... ซึ่งต้องเปลี่ยนก่อนมีผู้ใช้ production

1. Keystore

สร้าง upload/release key ตาม distribution model เก็บ encryptedใน secret manager/backup ที่มี ownerอย่างน้อยสองคน บันทึก alias, validity และ recovery process ห้าม commit .jks หรือ password

2. Gradle signing

signingConfigs {
  create("release") {
    storeFile = file(secretStoreFile)
    storePassword = secretStorePassword
    keyAlias = secretKeyAlias
    keyPassword = secretKeyPassword
  }
}
buildTypes.release.signingConfig = signingConfigs.getByName("release")

ค่ามาจาก CI environment/protected fileและ fail หากหาย ไม่ fallback ไป debug key

3. Application ID และ namespace

เลือกเช่น com.company.wms และ flavors อาจเป็น .dev/.staging ตรวจ deep link, Firebase/config/provider authority ทั้งหมดที่อิง ID ก่อนเปลี่ยน

4. Verify signature

หลัง build ตรวจ certificate fingerprint/signature ของ APK/AAB เทียบค่าที่อนุมัติ และ install upgrade over production-signed previous build หากเซ็นคนละ key Android จะไม่ยอมอัปเดตทับ

5. Launcher icon

wmsapp มี flutter_launcher_icons ชี้ icon TKS และเปิด Android แต่ปิด iOS ตรวจ adaptive foreground/background, monochrome/theme, contrast และไม่มีข้อความเล็กที่อ่านไม่ได้บน launcher

6. Name/brand per environment

dev/staging ควรมีชื่อ/icon badge ต่างจาก productionเพื่อลด operator ยิงข้อมูลผิด server แต่ไม่เปลี่ยน layoutจน testไม่แทนกัน ตรวจ label ใน Android manifestและ iOS display name

7. Key rotation/recovery

กำหนดว่า store/MDM รองรับ key upgradeอย่างไร ทดลอง recoveryจาก backup และจำกัดผู้มีสิทธิ์ signing การทำ key หายอาจทำให้อัปเดตแอปเดิมไม่ได้

8. Gate

release build ต้อง fail ถ้าใช้ debug certificate, application ID/example, versionซ้ำ, icon placeholder หรือ signing secretsถูก log พร้อมเก็บ verified fingerprintใน release record
