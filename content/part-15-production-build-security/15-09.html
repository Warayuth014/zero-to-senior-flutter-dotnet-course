iOS ต้องอธิบาย permission ก่อนเรียก API: ทั้งสอง Info.plist ปัจจุบันยังไม่มี camera/photo/local-network usage descriptions ขณะที่ wmsapp ใช้ image picker จึงต้องเติมข้อความตาม feature ที่ ship จริงและทดสอบบน device

1. Camera และ Photo Library

<key>NSCameraUsageDescription</key>
<string>ใช้ถ่ายรูปชิ้นส่วนเพื่อแนบกับข้อมูล WMS</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>ใช้เลือกรูปชิ้นส่วนจากคลังภาพเพื่ออัปโหลด</string>

ข้อความต้องเฉพาะเจาะจงและตรงพฤติกรรมจริง ไม่ขอสิทธิ์ที่ไม่ได้ใช้

2. Local Network

หากแอปติดต่อ backendใน LAN และ platform/runtimeต้องขอ local-network access ให้กำหนด NSLocalNetworkUsageDescription พร้อมข้อความธุรกิจ หากใช้ Bonjour discovery ต้องทบทวน service types เพิ่ม ไม่เดาค่าจาก Android

3. App Transport Security

production ใช้ HTTPS ที่ trustได้ ไม่เปิด NSAllowsArbitraryLoads ทั้งแอป หาก devจำเป็นต้อง exception ให้แคบตาม domain/configuration และไม่ปน Release scheme

4. Bundle identity/version

PRODUCT_BUNDLE_IDENTIFIER, team, provisioning profile, capabilities, FLUTTER_BUILD_NAME/NUMBER ต้องตรง distribution channel Application ID ฝั่ง Android ไม่กำหนดค่า iOS อัตโนมัติ

5. Signing/provisioning

ใช้ automatic/manual signing ตามนโยบายทีมแต่ CIต้องเข้าถึง certificate/profileอย่างปลอดภัย Test archive/exportด้วย Release schemeและ device ที่อยู่ใน channel ไม่ใช่เพียง simulator

6. Privacy manifest/data disclosure

ตรวจ SDK ทั้งหมด, collected data, tracking และ required-reason APIs ให้ตรง app privacy submission/manifest การไม่มี adไม่ได้แปลว่าไม่มีข้อมูล เช่น account identifier, diagnostics และรูปที่อัปโหลด

7. Lifecycle/device

ทดสอบ permission deny/limited/settings, backgroundระหว่าง scan/upload, memory pressure, orientationที่ประกาศ, local networkเปลี่ยน และ appถูก terminate iOS simulatorไม่แทน camera/keychain/network permissionจริง

8. iOS gate

Archiveผ่าน, usage descriptionsครบและ localize, ATSไม่มี global bypass, icon/splashถูก, version/signingตรง, privacy disclosureตรง SDK และ TestFlight/internal deviceทำ critical flowได้
