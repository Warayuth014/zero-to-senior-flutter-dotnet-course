หลัง await เวลาและโลกเปลี่ยนได้: routeอาจปิด, Stateอาจ dispose, taskอาจเปลี่ยน และ responseเก่าอาจกลับทีหลัง ต้องตรวจทั้ง lifecycle และความสดของ operationก่อนใช้ context/setState

1. State.mounted

final result = await repository.preview(code);
if (!mounted) return;
setState(() => _preview = result);
ScaffoldMessenger.of(context).showSnackBar(/* ... */);

mounted trueเมื่อ Stateยังผูก Element ใช้ใน State methodก่อน setState/contextหลัง async gap

2. context.mounted

onPressed: () async {
  final ok = await confirm(context);
  if (!context.mounted || ok != true) return;
  Navigator.of(context).pop();
}

เหมาะ callback/local BuildContext ที่ไม่จำเป็นต้องอ้าง State โดย contextที่ตรวจควรเป็นตัวเดียวกับที่จะใช้

3. ตัวอย่างจริง

CheckIn ของ wmsapp ตรวจ if (!mounted) return หลัง preview API และหลัง destination dialogก่อน setState/open slot Absolute ScanBox await onScanแล้วคืน focusเฉพาะ mounted รูปแบบนี้ป้องกัน “setState called after dispose” และ FocusNodeใช้หลังปิดหน้า

4. mounted ไม่รับประกัน resultยัง relevant

หน้าอาจยัง mountedแต่ผู้ใช้เปลี่ยน taskหรือยิง requestใหม่ ใช้ generation ID/current entity check:

final requestId = ++_requestId;
final result = await repository.load(code);
if (!mounted || requestId != _requestId) return;
setState(() => _result = result);

5. finally และ cleanup

ใช้ mountedเพื่อ UI update ไม่ใช่ข้าม cleanupทั้งหมด Busy/resourceใน storeต้องปลดใน finallyแม้ widgetหาย หาก busyอยู่ใน Stateและ Stateตายแล้วไม่ต้อง setState แต่ network/client operationอาจยังต้อง closeตาม owner

6. Async context across dialog/navigation

หลัง await dialogอาจมี navigationอื่นเกิดขึ้น ตรวจ mountedและ current stateก่อน commit/เปิด route อย่าเก็บ dialogContextไปใช้หลัง dialogถูก pop Contextมีความหมายตาม Element lifetimeไม่ใช่ global handle

7. แบบฝึกหัด

Request A สำหรับ pallet Aช้า ผู้ใช้เปลี่ยนเป็น Bและ request Bเสร็จก่อน A หน้าไม่ถูก dispose mountedยัง true จะแก้อย่างไร?

เฉลย

เก็บ request generationหรือ expected pallet ID แล้ว apply responseเมื่อยังตรง current state ยกเลิก Aถ้า clientรองรับ และให้ repository/cacheแยก keyตาม pallet Mountedอย่างเดียวกัน crashแต่ไม่กัน stale data

8. จุดพลาด

การเติม if (!mounted) return ทุกบรรทัดไม่แก้ architecture ถ้างานควรอยู่ต่อหลังหน้าปิดให้ย้ายไป store/service ownerและให้ UI subscribe state ส่วนงานเฉพาะหน้าเท่านั้นที่หยุด applyเมื่อ unmounted
