การป้องกัน submitซ้ำต้องทำที่ command boundary ก่อน await แล้วสะท้อนใน UI พร้อม try/finally ไม่ใช่แค่ทำปุ่มเป็นสีเทา เพราะ Enter/scanner/callbackอื่นยังเรียก methodได้

1. Guard ก่อนงาน async

Future<void> submitScan() async {
  if (_busy) return;
  final code = normalize(controller.text);
  if (code.isEmpty) return;

  setState(() => _busy = true);
  try {
    final result = await repository.validate(code);
    if (!mounted) return;
    apply(result);
  } finally {
    if (mounted) setState(() => _busy = false);
  }
}

2. ปิดทุก trigger

TextField enabled: !busy, ปุ่ม onPressed: busy ? null : submit และ command guardเป็นชั้นสุดท้าย Absolute ScanBox ปิด fieldตอน busy และแสดง progress label แต่ ownerยังต้อง guard callback เพราะ busy propอาจอัปเดตหลัง eventสองอันเข้าคิวใกล้กัน

3. Snapshot ก่อน clear

อ่าน raw/canonicalใส่ local variableก่อน await จากนั้นเลือก clearทันทีเพื่อรับรู้ว่า requestรับแล้ว หรือ clearหลัง successเพื่อให้แก้/retryง่าย Absolute clearก่อน awaitแล้วคืน focusภายหลัง; wmsappบาง flow clearเมื่อ error/success Designต้องบอกผู้ใช้ codeที่กำลัง validateหากช่องถูกล้าง

4. try/catch/finally

Network exceptionต้องไม่ทิ้ง busy=true ใช้ finallyปลด lock และแปลง exceptionเป็น UI state ตรวจ mountedก่อน setState/context แต่ resource/domain storeอาจต้อง completeแม้ widgetหาย จึงวาง async ownershipให้ถูกระดับ

5. Cancel กับ ignore stale result

HTTP Futureทั่วไปอาจยกเลิกไม่ได้ เมื่อเปลี่ยน task/routeให้ใช้ request generation/token เปรียบเทียบก่อน apply result หรือ cancellationที่ clientรองรับ Busy lockกันเฉพาะ concurrent commandของ stateเดียว ไม่กัน responseเก่าทับ taskใหม่

6. Optimistic vs pessimistic

Warehouse commitที่กระทบ stockมัก pessimistic: รอ serverยืนยันก่อนเพิ่ม committed count อาจแสดง pending rowเพื่อความเร็ว แต่ต้อง reconcile/rollbackเมื่อ fail อย่าแสดง “สำเร็จ” จากการกดก่อน HTTP result

7. แบบฝึกหัด

ผู้ใช้ยิง scannerและแตะปุ่มส่งเกือบพร้อมกัน ทำไม disabled buttonอย่างเดียวอาจไม่พอ?

8. จุดพลาด

ถ้า return หลัง await เพราะ !mounted ก่อนปลด busyโดยไม่มี finally state ownerอื่นอาจค้าง งาน cleanupต้องอยู่ finally; UI updateจึงค่อยตรวจ mounted
