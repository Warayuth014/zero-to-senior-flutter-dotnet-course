Normalization แปลง input หลายรูปแบบให้เป็น canonical value ก่อน validate/compare แต่ต้องเป็น policy ตามชนิดรหัส ไม่ใช่เรียก trim().toUpperCase() กับข้อมูลทุกชนิดโดยอัตโนมัติ

1. Pipeline ที่ชัด

String normalizePallet(String raw) => raw.trim().toUpperCase();

final raw = controller.text;
final pallet = normalizePallet(raw);
final error = validatePallet(pallet);
if (error != null) return showError(error);
await repository.previewPallet(pallet);

Normalize หนึ่งครั้งที่ input boundary แล้วส่ง canonical value ต่อ ลดการ compare คนละกฎใน UI/store/API

2. trim แบบไหน

trim() ตัด whitespace หัวท้ายซึ่งมักมาจาก scanner suffix/paste แต่ whitespace ภายในอาจเป็นข้อมูลจริง ห้าม replace ทั้งหมดโดยไม่รู้ contract หาก scanner ส่ง CR/LF แปลกให้ normalize line ending/prefixตาม profileอย่างเจาะจง

3. Case sensitivity

Pallet/location มัก case-insensitiveจึง uppercase ได้; serial, token, password หรือ GS1 data อาจ case-sensitive ห้ามเปลี่ยน case wmsapp ใช้ trim+uppercase กับ packing/pallet ID แต่ SerialSelect ใช้ trim อย่างเดียว สะท้อนว่ารหัสคนละชนิดต้องคนละ policy

4. Leading zeros และ numeric-looking codes

001234 เป็น identifier ไม่ใช่ integer การ parse จะทำศูนย์หาย เก็บ barcode/location/serial เป็น String ส่วน quantity จึง parse เป็น int/decimal แยกชนิดตั้งแต่ model/API contract

5. Prefix/symbology

บาง label มี application identifier, prefix vendor หรือ check digit เช่น GS1 ควรมี parser ที่คืน typed result/error ไม่ใช้ substring magic ใน widget เก็บทั้ง raw/canonical เมื่อ audit ต้องรู้สิ่งที่สแกนจริง และ redact log ตาม policy

6. Equality และ duplicate

Set/List สำหรับ duplicate ต้องเก็บ canonical value ถ้า available set มี rawคนละ case ต้อง normalizeชุด reference ด้วยกฎเดียวกันครั้งเดียว ไม่ normalizeเฉพาะค่าที่สแกนแล้ว compare กับข้อมูลดิบ

7. แบบฝึกหัด

กำหนด normalization สำหรับ pallet " ab-001\r\n", serial "Sn-aB9 " และ quantity " 005 "

เฉลย

Pallet: trim→uppercase = AB-001 หาก contract case-insensitive; serial: trim = Sn-aB9 รักษา case; quantity: trim→int.tryParse = 5 แล้ว validate range อย่าใช้ normalizer เดียวทั้งสามชนิด

8. จุดพลาด

อย่า normalize หลังส่ง API หรือ normalizeซ้ำคนละกฎหลายชั้นจนหา bug ไม่พบ กำหนด canonical contract ที่ boundary และให้ backendบันทึก/ตอบรูปแบบมาตรฐาน แต่ยัง validate server-side
