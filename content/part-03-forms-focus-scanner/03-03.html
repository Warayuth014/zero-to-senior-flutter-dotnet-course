Form รวม field validation/save/reset ภายใต้ FormState แต่ validation ฝั่ง client มีหน้าที่ให้ feedback เร็ว ไม่แทนกฎธุรกิจและ authorization ที่ backend ต้องตรวจซ้ำ

1. Form + GlobalKey

final _formKey = GlobalKey<FormState>();

Form(
  key: _formKey,
  child: TextFormField(
    controller: _locationController,
    validator: validateLocation,
  ),
)

if (!(_formKey.currentState?.validate() ?? false)) return;

Key เป็น identity/handle เข้าถึง FormState ต้องสร้างครั้งเดียวใน State ไม่สร้างใน build

2. Validator contract

คืน null เมื่อผ่าน หรือข้อความ error เมื่อไม่ผ่าน Validator ควร synchronous, deterministic และไม่แก้ controller/state ห้ามยิง API ใน validator เพราะอาจถูกเรียกหลายครั้งและทำ UX ช้า แยก remote validation ไป action/state machine

3. Pure validation

String? validatePallet(String? raw) {
  final value = raw?.trim() ?? '';
  if (value.isEmpty) return 'กรุณาสแกน Pallet';
  if (value.length > 64) return 'รหัสยาวเกินกำหนด';
  return null;
}

แยก function pure ทำ unit test ได้ และใช้ raw/normalized policyเดียวกับ submit เพื่อไม่ให้ validator ผ่านแต่ actionตีความต่างกัน

4. autovalidateMode

หน้าคลังไม่ควรแสดง error ก่อนผู้ใช้เริ่ม ใช้ disabled จนกด submit หรือ onUserInteraction หลัง interaction สำหรับ scanner ที่ submit ด้วย Enter มัก validate ตอน event แล้วแสดง status banner; Form เหมาะเมื่อหลายช่องต้องผ่านพร้อมกัน

5. Validation หลายระดับ

  1. Parsing/shape: ว่าง, ตัวเลข, ความยาว
  2. Local domain: quantity ≤ remaining, serial ไม่ซ้ำใน session
  3. Remote domain: pallet มีจริง, location ว่าง, task ยัง active
  4. Server commit: concurrency/auth/invariant ล่าสุด

UI ต้องแยกข้อความและ retry behavior ของแต่ละระดับ

6. reset และ pending data

FormState.reset reset field state/initialValue แต่ controller ที่กำหนดเองอาจต้อง clear/restore explicit อย่าล้าง pending scan ที่ valid แล้วเมื่อ remote step ถัดไป fail กำหนด transaction boundary ว่า reset input, preview และ committed state ต่างกัน

7. แบบฝึกหัด

Quantity ต้องเป็น 1–remaining และ pallet ต้องมีจริงใน server อะไรอยู่ validator?

เฉลย

parse + range 1–remaining อยู่ pure validator/local domain; การมีอยู่ของ pallet เป็น async validation ใน submit state โดย disable duplicate submit และแสดง loading/error Backend ยังตรวจ quantity/stock/pallet ซ้ำตอน commit

8. จุดพลาด

GlobalKey ไม่ใช่ global variable อย่าแชร์ Form key หนึ่งอันข้ามหลาย Form/route และอย่าใช้เพื่อข้าม architecture ทุกอย่าง ใช้ callback/controller/state owner ตามปกติ; key มีไว้ระบุ FormState เฉพาะ subtree นั้น
