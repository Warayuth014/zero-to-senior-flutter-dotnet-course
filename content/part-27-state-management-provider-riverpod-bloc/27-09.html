Riverpod testing: ProviderContainer คือ runtime graph ที่สร้างใน testได้โดยไม่ pump widget และ overrides ทำให้แทน dependency เป็น fake แบบ type-safe

1. Arrange container

final container = ProviderContainer(overrides: [
  taskRepositoryProvider.overrideWithValue(fake),
]);
addTearDown(container.dispose);

disposeทุก testเพื่อปิด providers/listenersและป้องกัน stateรั่วข้ามเคส

2. Await initial build

await container.read(riverpodTaskProvider.future) รอ AsyncNotifier buildจบอย่าง deterministic ไม่ใช้ delayหรือ poll loading flag

3. Act ผ่าน notifier

เรียก container.read(riverpodTaskProvider.notifier).complete(task) แล้วอ่าน AsyncValueล่าสุด ตรวจ tasks/message/errorตาม behavior

4. Override boundary

override repositoryไม่ใช่ controller เพื่อให้ testยังรัน orchestrationจริง หาก override providerที่กำลังทดสอบด้วยค่าคงที่จะไม่ได้พิสูจน์ logic

5. Container isolation

สร้างสอง containersจาก declarationเดียวกันแล้ว stateแยก นี่ช่วย test tenant/profileหลายชุดและอธิบายว่าตัวแปร provider top-levelไม่ใช่ singleton state

6. Widget test

ครอบ widgetด้วย ProviderScope(overrides: ...) แล้ว pump ConsumerWidget ใช้เฉพาะเมื่อทดสอบ rendering/listening ส่วน controller behaviorใช้ container testเร็วกว่า

7. Lifecycle test

autoDispose providerอาจถูก disposeถ้าไม่มี listenerระหว่าง await ใน test ให้ listenหรืออ่าน futureตามเอกสาร และทดสอบ keepAlive policyเฉพาะจุดที่มีผลจริง

8. Checkpoint

state_patterns_test.dart พิสูจน์ load/completeโดยไม่ BuildContext ถ้า testต้องสร้าง MaterialAppเพื่อทดสอบ Notifier แสดงว่า UI concernรั่วเข้า controller
