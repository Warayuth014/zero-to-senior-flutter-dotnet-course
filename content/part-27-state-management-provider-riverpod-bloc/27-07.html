AsyncNotifier: ใช้เมื่อ node มี async initialization และมี public methods เปลี่ยน stateตาม user intent Riverpod แนะนำแนวนี้แทน legacy ChangeNotifierProvider สำหรับ scalable immutable state

1. Declaration

final riverpodTaskProvider =
  AsyncNotifierProvider<RiverpodTaskController, TaskPatternState>(
    RiverpodTaskController.new,
  );

2. build

build() อ่าน repository แล้วคืน TaskPatternState Riverpod ห่อผลเป็น AsyncLoading/AsyncData/AsyncError ทำให้ initial async lifecycle typed โดยไม่ต้อง boolean แรกเอง

3. Public intents

refresh และ complete อยู่ notifier UI เรียกผ่าน ref.read(provider.notifier) ขณะที่ UI subscribe snapshot ผ่าน ref.watch(provider)

4. state.requireValue

action ใช้เมื่อ provider อยู่ data state หาก action อาจถูกเรียกระหว่าง initial loading ต้อง guard UI/ตรวจ AsyncValue ก่อน ไม่เรียก requireValue แบบสมมติทุกสถานะ

5. Immutable update

ทุก transition assign state = AsyncData(previous.copyWith(...)) Busy idsและ tasks เป็น unmodifiable snapshots ลดปัญหา mutate แล้ว listenerไม่รู้

6. Repository dependency

controller อ่าน taskRepositoryProvider ไม่สร้าง RemoteTaskRepository เอง Test จึง override nodeเดียวและไม่ใช้ BuildContext/network

7. Code generation

Riverpod รองรับ annotations/generator แต่ lab ใช้ manual declarationเพื่อเห็น typesก่อน Part code generation จะอธิบาย trade-off build_runner/generated files ภายหลัง

8. Checkpoint

trace initial load: ProviderScope→AsyncNotifierProvider→build→repository→AsyncData→ConsumerWidget และ trace completeแยกต่างหากให้ได้
