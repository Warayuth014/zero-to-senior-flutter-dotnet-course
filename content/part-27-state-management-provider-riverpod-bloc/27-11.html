Immutable TaskPatternState: snapshotเดียวถูกใช้โดย RiverpodและCubitเพื่อให้การเปรียบเทียบไม่ปนกับ modelคนละแบบ

1. State fields

tasks, refreshing, busyTaskIds, error และ message ครอบ read/action dimensionsโดยไม่เอา repository/clientเข้ามาใน state

2. Unmodifiable collections

constructor/copyWithสร้าง read-only list/set ป้องกัน snapshotเก่าถูกแก้ย้อนหลัง ซึ่งทำให้ time-travel/debug/equalityเสียความหมาย

3. Nullable copyWith

ใช้ sentinelแยก “ไม่เปลี่ยน error” จาก “ตั้ง errorเป็น null” เพราะ parameter String? error อย่างเดียวแยกสอง intentไม่ได้

4. Cubit load

emit refreshing trueก่อน await แล้ว emit tasks/errorหลังจบ UIจึงวาดจาก stateอย่างเดียว ไม่มี hidden mutable booleanนอก stream

5. Cubit complete

เพิ่ม busy id, ส่ง command, ลบ taskและปลด busyด้วย snapshotsใหม่ Known/unknown errorsเดิน pathต่างและ reconcileผ่าน repository

6. Equality

Labไม่เพิ่ม Equatableเพราะ emit instanceใหม่ทุกครั้งและ testsตรวจ fields ระบบใหญ่ควรใช้ value equality/freezedเพื่อ BlocSelector/distinct/testsที่แม่น แต่ต้องเข้าใจ collection equality

7. State explosion

อย่าสร้าง booleanทุก combinationจน invalid statesเกิดง่าย อาจใช้ sealed states/substatesสำหรับ workflowขั้นตอน หรือแยก resource stateจาก command stateตาม aggregate

8. Exercise

เขียน invariant: task idห้ามอยู่ busyถ้าไม่อยู่ tasks ยกเว้นช่วง reconciliation แล้วเพิ่ม assertion/test ตรวจทุก Cubit emission สำคัญ
