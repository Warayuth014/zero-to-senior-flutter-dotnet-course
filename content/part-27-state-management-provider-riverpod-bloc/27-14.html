Trade-off matrix: ไม่มีคำตอบเดียวสำหรับทุกทีม แต่มีคำตอบที่อธิบายด้วย constraintsและ migration costได้

1. Provider

จุดแข็งคือเล็ก, Flutter-native mental model, reuse ChangeNotifierเดิมและ ecosystemกว้าง จุดแลกคือ mutable state/notify granularityและ side-effect patternต้องออกแบบเอง

2. Riverpod

จุดแข็งคือ graphไม่ผูก lookup typeกับ BuildContext, async/cache/override typedและ container tests จุดแลกคือ API surface/version evolutionและทีมต้องเข้าใจ provider lifecycle/invalidation

3. Cubit/Bloc

จุดแข็งคือ explicit immutable transitions, stream tooling, Builder/Listener separationและ conventionทีมใหญ่ จุดแลกคือ types/boilerplateมากขึ้น โดย Bloc eventsไม่คุ้มทุก feature

4. เลือกตาม codebase

แอป ChangeNotifierเดิมไม่ควร rewriteทั้งระบบเพื่อ trend เริ่ม Providerหรือคง injectionเดิมแล้วแก้ painจริง แอปใหม่ async graphหนักอาจเลือก Riverpod ทีมมี Bloc convention/observabilityอาจเลือก Cubit/Bloc

5. ห้ามผสมไร้ boundary

migrationช่วงหนึ่งผสมได้ แต่กำหนด feature boundary/adapter/deadline ไม่ให้ widgetเดียวอ่านสาม containers เพราะ ownershipและdebug pathจะสับสน

6. Migration strategy

  1. ตรึง behaviorด้วย tests
  2. รักษา repository contract
  3. ย้ายหนึ่ง vertical slice
  4. วัด defects/rebuild/onboarding
  5. ตัดสิน ADRก่อนขยาย

7. Exit strategy

Package choiceดีต้องเปลี่ยนออกได้โดย domain/repositoryไม่พัง หลีกเลี่ยง provider refs/BuildContext/Emitใน modelsและ data sources

8. ADR outcome

เขียน Decision, Context, Options, Consequences, Migration/Rollbackและ metrics ไม่ใช้ “นิยมกว่า” เป็นเหตุผลเดียว และทบทวนเมื่อ team/requirementsเปลี่ยน
