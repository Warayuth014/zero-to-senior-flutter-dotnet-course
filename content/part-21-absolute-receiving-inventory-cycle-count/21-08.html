ไฟล์หลัก: lib/api/inventory_api.dart — reuse grid endpointเดียวแล้วแปลง DB-shaped ContainerView เป็น UI-shaped Pallet

1. Shared endpoint

POST /api/data/get_containers?withContents=true
body: { PageIndex: 1, PageItems: 1000 }
response: items/Items → ContainerView → Pallet

withContents=true ทำให้คืน product/qty/unitเพิ่มโดยไม่เปลี่ยน web grid callเดิม จึง reuse queryแต่สร้าง mobile read modelที่เหมาะกับหน้าสต็อก

2. DTO สองชั้น

_toContainer map field 1:1 จาก view columnsก่อน แล้ว _toPallet คำนวณ empty/racked/status/location display การแยกช่วยทดสอบ raw contractกับ business presentation mappingคนละชุดและไม่ฝังชื่อ DBใน widget

3. Quantity และ empty rule

qtyถูกปัดเป็น int และ palletถือว่า emptyเมื่อ product codeว่างหรือ qtyเท่ากับ 0 แม้ APIส่ง product metadataอยู่ สิ่งนี้เหมาะกับ UI container-level แต่ถ้าของเป็นทศนิยมหรือยอดติดลบจาก data error การ round/empty ruleอาจปิดบังปัญหา ควรกำหนด domain precisionชัด

4. Status precedence

EMPTY
→ PICKING
→ AWAIT_PUTAWAY (pick completed)
→ ALLOCATED (inProcess busy)
→ AT_DEST (location is destination)
→ STORED (has rack location)
→ MOVING

ลำดับสำคัญ: palletที่ taskจับแล้วไม่ควรถูกตีเป็น STOREDเพียงเพราะยังมี location และ statusแรกที่ตรงจะชนะ

5. State aliases จาก backend

ContainerView.isPicking รองรับ PICK และเลข 18, completedรองรับ typoเดิม PICKCOMPLATE และ 19, ส่วน busyมองค่า inProcessที่ไม่ว่าง/ไม่ใช่ no/0 นี่คือ anti-corruption mappingที่ยอมรับ legacy representationโดยไม่กระจาย aliasถึง UI

6. Location display กับ domain value

หากไม่มี rack location adapterใส่ '-' ลง Pallet.locationCode เพื่อแสดงผลสะดวก แต่ sentinel stringปะปน domainกับ presentation Senior designควรเก็บ nullable locationแล้วแปลงเป็น dashใน widget เพื่อไม่ให้ search/API logicคิดว่า “-” เป็น locationจริง

7. Scaling และ parse risks

  • จำกัด 1,000 containers ไม่มี loop pagination
  • ทุก row castเป็น mapโดยตรง
  • รองรับ items/Itemsแต่ fieldภายในรองรับ casingเดียว
  • statusใหม่ตกไป MOVING/STOREDตาม precedenceโดยไม่เตือน
  • การโหลดทั้งคลังทุกครั้งอาจหนักสำหรับ PDA/network

8. Mapping tests

ทำ table-driven testsทุก combinationของ product/qty/location/state/inProcess/destination โดยเฉพาะ precedenceชนกัน และ adapter test URI/body/items casing/decimal/มากกว่า 1,000 rows ยืนยันว่า statusใหม่ไม่ถูกจัดหมวดเงียบโดยไม่มี telemetry
