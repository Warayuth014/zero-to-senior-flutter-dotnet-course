หลาย profileเป็น versioned document: เก็บ profiles + activeIdร่วมกันอย่างสอดคล้อง ไม่เขียนหลาย preference keysแล้ว crashกลางทางจน activeชี้ของที่ไม่มี

1. Envelope

{
  "schemaVersion": 1,
  "activeId": "prod-01",
  "profiles": [{"id":"prod-01","name":"Warehouse","host":"10.1.2.3"}]
}

2. Encode/decode

Controller/repository serialize documentจุดเดียวด้วย jsonEncode; decodeเป็น Objectก่อนตรวจ map/listและ skip entryเสียพร้อม telemetry

3. Atomic-ish write

SharedPreferencesไม่มี transactionเต็มรูปแบบ ใช้ JSON string keyเดียวช่วยให้ snapshotสอดคล้อง และ update in-memoryหลัง writeสำเร็จหรือตั้ง policy rollbackชัด

4. Migration

รองรับ legacy host/port keysโดยอ่านเมื่อ documentใหม่ไม่มี สร้าง seed profile, persist schemaใหม่แล้วลบ legacy keysหลังยืนยัน write ไม่ migrateทุก startupซ้ำ

5. Corruption recovery

JSONเสียไม่ควร crash app ให้ backup/log safe metadata, seed defaultและแจ้งผู้ใช้ตามความเหมาะสม ห้ามคืน raw configที่อาจมี internal hostใน crash reportโดยไม่ policy

6. Duplicate profiles

ตรวจ duplicate IDเด็ดขาด; duplicate nameให้ resolve/confirm; duplicate normalized endpointอาจเตือนแต่อนุญาตถ้า environment/labelมีเหตุผล

7. แบบฝึกหัด

profilesโหลดได้ 2 จาก 3 และ activeIdชี้ entryที่เสียควรทำอย่างไร?

เฉลย

เลือก deterministic valid fallbackหรือ seed, persist repaired documentและตั้ง status unknownจน probe ไม่ปล่อย activeเป็น nullแบบ race

8. Tests

round-trip, schemaเก่า/ใหม่, malformed document/entry, duplicate ID, active missing, write failureและ migrationครั้งเดียว
