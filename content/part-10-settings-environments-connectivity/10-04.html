1. profile คืออะไร

Connection profile คือที่อยู่เซิร์ฟเวอร์หนึ่งชุดที่ผู้ใช้บันทึกไว้ พร้อมชื่อที่ตัวเองตั้ง

ผู้ปฏิบัติงานเก็บไว้หลายชุด เช่น

ชื่อที่ตั้งที่อยู่ใช้ตอน
คลังหลักhttp://192.168.1.194:6191ทำงานปกติ
เครื่องทดสอบhttp://192.168.1.50:6191ทดสอบฟีเจอร์ใหม่
สาขาลาดกระบังhttps://wms-lk.company.com:443/wmsไปช่วยงานสาขา

สิ่งที่ต้องสังเกตคือ ชื่อสำคัญพอ ๆ กับที่อยู่ ผู้ใช้จำ 192.168.1.194 กับ 192.168.1.50 สลับกันได้ง่ายมาก แต่จำ “คลังหลัก” กับ “เครื่องทดสอบ” ไม่มีวันสลับ

2. ฟิลด์ทั้งหมดและเหตุผล

class ServerProfile {
  final String id;                     // ตัวระบุที่ไม่เปลี่ยน
  final String name;                   // ชื่อที่ผู้ใช้ตั้ง
  final ServerEnvironment environment; // ป้ายกำกับ
  final ServerProtocol protocol;       // http หรือ https
  final String host;
  final int port;
  final String basePath;               // เก็บดิบตามที่พิมพ์ (10.3)
}
ฟิลด์ทำไมต้องมี
idชื่อกับที่อยู่เปลี่ยนได้ทั้งคู่ ต้องมีอะไรที่ไม่เปลี่ยนไว้อ้างอิงว่า “ตัวที่ใช้อยู่คือตัวนี้”
nameผู้ใช้แยกออกในรายการ
environmentป้ายกำกับล้วน ๆ ไม่มีผลต่อการทำงาน
protocolเป็น enum เพื่อให้มีแค่สองค่า (10.1)
host, portแยกช่องเพื่อตรวจได้ทีละอย่าง
basePathสำหรับเซิร์ฟเวอร์ที่อยู่หลัง reverse proxy

3. ทำไม environment ถึงไม่มีผลอะไรเลย

/// ป้ายกำกับที่ผู้ใช้เลือกเอง ไม่มีผลต่อการทำงาน
///
/// มีไว้ให้แยกออกว่าอันไหนคืออันไหนในรายการ และใช้ตั้งค่าเริ่มต้นของพอร์ต
/// ตอนสร้างใหม่เท่านั้น
enum ServerEnvironment { production, development, custom }

สิ่งที่ยั่วใจคือการเขียนแบบนี้

// อย่าเขียนแบบนี้
if (profile.environment == ServerEnvironment.production) {
  enableStrictValidation();
  disableDebugLogging();
  useShortTimeout();
}

ปัญหาคือมันทำให้ป้ายกำกับที่ผู้ใช้เลือกเล่น ๆ กลายเป็นสวิตช์ที่เปลี่ยนพฤติกรรมของแอป ผู้ใช้ที่ตั้งชื่อ profile ของเครื่องทดสอบว่า production เพราะ “มันคือ production ของแผนกเรา” จะได้พฤติกรรมที่ไม่คาดคิด และไม่มีทางเดาได้เลยว่าทำไม

หลัก: ค่าที่ผู้ใช้เลือกเพื่อความสะดวกของตัวเอง อย่าเอาไปตัดสินใจแทนโปรแกรม ถ้าต้องการโหมดจริง ๆ ให้ตัดสินจาก kReleaseMode หรือ --dart-define ที่ผู้ใช้แตะไม่ได้

4. getter เดียวที่ประกอบทุกอย่าง

String get baseUrl =>
    '${protocol.name}://$host:$port${normalizeBasePath(basePath)}';

ทั้งแอปมีที่เดียวที่ประกอบ URL ผลคือ

  • เปลี่ยนรูปแบบการประกอบ แก้ที่เดียว
  • ไม่มีใครลืมเรียก normalizeBasePath
  • ทดสอบด้วยเทสต์สามบรรทัดครอบคลุมทุกกรณี
expect(profile('p1').baseUrl, 'http://192.168.1.194:6191');
expect(
  profile('p1', protocol: ServerProtocol.https, basePath: 'wms').baseUrl,
  'https://192.168.1.194:6191/wms',
);

5. id ที่ไม่ต้องพึ่ง package

String newProfileId() => 'p${DateTime.now().microsecondsSinceEpoch}';

ไม่ได้ใช้ uuid เพราะ id นี้ต้องไม่ซ้ำเฉพาะในรายการบนเครื่องนี้เท่านั้น ไม่ได้ส่งไปเซิร์ฟเวอร์และไม่ได้เทียบกับเครื่องอื่น เวลาระดับไมโครวินาทีจึงพอ

ใน lab ค่านี้รับเข้ามาทาง constructor พร้อมค่าเริ่มต้น ตามรูปแบบใน 9.8

ProfileStore(this.storage, {String Function()? createId})
  : _createId = createId ?? (() => 'p${DateTime.now().microsecondsSinceEpoch}');

เทสต์จึงส่ง () => 'p${++counter}' เข้าไปแล้วเขียน expect(profile.id, 'p1') ได้ตรง ๆ แทนที่จะต้องเดาเลขเวลา

6. copyWith และกับดักเดิม

ServerProfile copyWith({String? name, String? host, int? port, ...}) =>
    ServerProfile(
      name: name ?? this.name,
      host: host ?? this.host,
      ...
    );

รูปแบบเดียวกับ 6.12 และมีกับดักเดียวกัน คือ ส่ง null เข้าไปเพื่อล้างค่าไม่ได้ — copyWith(basePath: null) จะได้ค่าเดิม ไม่ใช่ค่าว่าง

ที่นี่ไม่เป็นปัญหาเพราะไม่มีฟิลด์ไหนเป็น nullable การล้าง basePath ทำด้วย copyWith(basePath: '') ซึ่งชัดเจนกว่าอยู่แล้ว

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
แก้ที่อยู่แล้วตัวที่ใช้งานอยู่หลุดใช้ที่อยู่หรือชื่อเป็นตัวระบุมี id แยกที่ไม่เปลี่ยน
ผู้ใช้เห็นรายการที่แยกไม่ออกว่าอันไหนคืออันไหนไม่มีชื่อ หรือชื่อว่างบังคับให้ตั้งชื่อ และใช้ host แทนถ้าไม่มี
พฤติกรรมแอปเปลี่ยนตามป้ายที่ผู้ใช้เลือกเอา environment ไปตัดสินใจใช้ kReleaseMode หรือค่าตอน build
URL ประกอบไม่เหมือนกันในแต่ละที่ประกอบเองหลายที่มี getter เดียว

8. แบบฝึกหัด

หัวหน้าขอเพิ่มสองอย่างใน profile

  1. ช่องหมายเหตุให้จดว่าเซิร์ฟเวอร์นี้คือเครื่องไหน ตั้งอยู่ที่ไหน
  2. ชื่อผู้ใช้กับรหัสผ่านที่ผูกกับเซิร์ฟเวอร์นั้น เพื่อจะได้ไม่ต้องพิมพ์ทุกครั้งตอนสลับ
แนวคำตอบ

1. เพิ่มได้ เป็น String note ที่มีค่าเริ่มต้นเป็นค่าว่าง ไม่ต้องตรวจอะไร เพราะเป็นข้อความอิสระที่ไม่มีผลต่อการทำงาน จุดที่ต้องคิดคือถ้าเป็น String? จะได้สองสถานะที่ความหมายเหมือนกัน (null กับ '') ให้เลือกอย่างเดียวคือค่าว่าง

2. ไม่ ด้วยเหตุผลที่ 8.1 และ 8.10 วางไว้แล้ว

  • รหัสผ่านไม่ควรถูกเก็บที่ไหนเลย ไม่ว่าจะเข้ารหัสหรือไม่ — สิ่งที่เก็บได้คือ token ที่หมดอายุได้และเพิกถอนได้
  • ไฟล์ profile นี้ถูกเก็บแบบธรรมดาเพราะเนื้อหาไม่อ่อนไหว การใส่รหัสผ่านเข้าไปทำให้ต้องยกทั้งไฟล์ไปที่เก็บที่ปลอดภัย ซึ่งช้ากว่าและซับซ้อนกว่า
  • PDA เป็นเครื่องที่เปลี่ยนมือ (8.11) รหัสผ่านที่ค้างอยู่แปลว่าคนถัดไปเข้าระบบด้วยชื่อคนก่อนได้

สิ่งที่ตอบความต้องการจริงได้: หัวหน้าไม่ได้อยากเก็บรหัสผ่าน เขาอยากไม่ต้องพิมพ์ซ้ำ ซึ่งแก้ได้ด้วยการเก็บชื่อผู้ใช้ไว้กรอกให้อัตโนมัติ (ไม่ใช่ความลับ) และเก็บ session ต่อ profile ตามที่ 8.11 ออกแบบไว้ — สลับกลับมาที่เครื่องเดิมแล้วยังไม่หมดอายุ ก็ไม่ต้องล็อกอินใหม่

9. สรุป

  • profile ต้องมี id ที่ไม่เปลี่ยน แยกจากชื่อและที่อยู่ที่เปลี่ยนได้
  • ชื่อที่ผู้ใช้ตั้งสำคัญพอ ๆ กับที่อยู่ เพราะเขาใช้ชื่อในการตัดสินใจ
  • ป้ายกำกับที่ผู้ใช้เลือก ห้ามเอาไปเปลี่ยนพฤติกรรมของโปรแกรม
  • ประกอบ URL ที่ getter เดียว

บทหน้า: เก็บหลาย profile ลงเครื่องอย่างไรให้แถวเสียหนึ่งแถวไม่ทำลายที่เหลือ
