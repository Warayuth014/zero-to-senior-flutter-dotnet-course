1. ปัญหา

ให้ผู้ใช้สิบคนพิมพ์เส้นทางเดียวกันลงช่องเดียวกัน จะได้สิบแบบ

wms
/wms
wms/
/wms/
//wms//
  /wms

ทุกแบบผู้ใช้ตั้งใจอย่างเดียวกัน แต่ถ้าเอาไปต่อ URL ตรง ๆ จะได้ผลต่างกัน

พิมพ์URL ที่ได้ผล
/wmshttp://host:6191/wms/api/WMS/...ถูก
wmshttp://host:6191wms/api/WMS/...พอร์ตเพี้ยน
/wms/http://host:6191/wms//api/WMS/...บางเซิร์ฟเวอร์ 404 บางตัวไม่

แถวสุดท้ายอันตรายที่สุดเพราะบางครั้งใช้ได้ ทำให้ทดสอบผ่านแล้วไปพังที่หน้างาน

2. Normalization คืออะไร

Normalization คือการแปลงค่าที่มีหลายรูปแบบให้เหลือรูปแบบเดียว ก่อนที่ส่วนอื่นของระบบจะได้เห็น

หลักคือ ทำที่ขอบ ทำครั้งเดียว — จุดที่ค่าเข้ามาจากโลกภายนอก ไม่ใช่ทุกที่ที่เอาค่าไปใช้

ทำที่ขอบทำทุกที่ที่ใช้
เขียนครั้งเดียว ทดสอบครั้งเดียวต้องจำว่าต้องทำ ทุกครั้ง ทุกที่
ส่วนที่เหลือของระบบเห็นค่ารูปแบบเดียวลืมที่เดียวก็มีบั๊ก
คนอ่านโค้ดรู้ว่าค่านี้สะอาดแล้วต้องเดาว่าค่านี้ผ่านการล้างหรือยัง

3. โค้ด

String normalizeBasePath(String raw) {
  final trimmed = raw.trim();
  if (trimmed.isEmpty) return '';
  final collapsed = trimmed
      .split('/')
      .where((segment) => segment.isNotEmpty)
      .join('/');
  return collapsed.isEmpty ? '' : '/$collapsed';
}

อ่านทีละบรรทัด

บรรทัดจัดการอะไร
trim()ช่องว่างที่ติดมาจากการคัดลอกวาง
split('/')ตัดเป็นชิ้น ทับที่ติดกันจะได้ชิ้นว่างคั่น
where(isNotEmpty)ทิ้งชิ้นว่างทั้งหมด — จัดการทั้งทับนำ ทับปิด และทับซ้อน ในบรรทัดเดียว
join('/')ต่อกลับด้วยทับเดี่ยว
collapsed.isEmpty ? '' : '/$collapsed'เติมทับนำ ยกเว้นตอนไม่มีอะไรเหลือ

4. บรรทัดสุดท้ายสำคัญกว่าที่คิด

ถ้าเขียนแค่ return '/$collapsed'; ค่า / หรือ /// จะได้ผลเป็น '/' ซึ่งพา URL ไปเป็น

http://host:6191//api/WMS/mobile_pallets

ซึ่งกลับไปสู่ปัญหาเดิมที่ตั้งใจจะแก้ เทสต์บังคับข้อนี้ไว้

test('ว่างหรือมีแต่ทับ ต้องได้ข้อความว่าง ไม่ใช่ทับเดี่ยว', () {
  expect(normalizeBasePath(''), '');
  expect(normalizeBasePath('   '), '');
  expect(normalizeBasePath('/'), '');
  expect(normalizeBasePath('///'), '');
});
ฟังก์ชันแปลงค่าทุกตัวควรมีเทสต์ที่ยิงค่าขอบเข้าไป — ค่าว่าง, ช่องว่างล้วน, ตัวคั่นล้วน สามอันนี้เจอบั๊กได้บ่อยที่สุด

5. เก็บดิบ แต่ใช้ที่แปลงแล้ว

/// เก็บตามที่ผู้ใช้พิมพ์ ใช้งานผ่าน [baseUrl] หรือ [normalizeBasePath]
final String basePath;

String get baseUrl =>
    '${protocol.name}://$host:$port${normalizeBasePath(basePath)}';

ทำไมไม่แปลงตั้งแต่ตอนบันทึก คำตอบคือ ผู้ใช้ที่กลับมาแก้ ควรเห็นสิ่งที่ตัวเองพิมพ์ ไม่ใช่สิ่งที่แอปแปลงให้

แปลงตอนบันทึกแปลงตอนใช้
ผู้ใช้พิมพ์ wms/ กลับมาเห็น /wms แล้วสงสัยว่าใครแก้เห็นตามที่พิมพ์
ค่าที่เก็บสะอาดแน่นอนต้องจำว่าต้องเรียกตอนใช้

ข้อเสียของทางขวาถูกปิดด้วยการมี getter เดียวคือ baseUrl — ไม่มีใครประกอบ URL เองอยู่แล้ว

6. สิ่งที่ฟังก์ชันนี้ไม่ทำ

มันไม่แตะ /api/WMS เพราะนั่นไม่ใช่ค่าของผู้ใช้

http://192.168.1.194:6191  /wms      /api/WMS/mobile_pallets
└──────── โปรไฟล์ ────────┘└ ผู้ใช้ ┘└──────── แอปเติมเอง ────────┘

แอปเรียกสามรากที่ต่างกัน คือ /api/WMS สำหรับ PDA, /api/data สำหรับข้อมูลกลาง และ /api/Authenticate สำหรับเข้าสู่ระบบ ผู้ใช้ไม่มีทางรู้ว่าเส้นไหนใช้รากไหน จึงต้องไม่เปิดให้แก้ตามหลักใน 10.1

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
URL มีทับซ้อนต่อสตริงตรง ๆต่อผ่าน getter เดียว
บางเครื่องใช้ได้ บางเครื่องไม่ได้ ทั้งที่ตั้งค่าเหมือนกันค่าดิบต่างกันแต่ตั้งใจเหมือนกันnormalize ที่ขอบ
แปลงค่าซ้ำหลายรอบจนเพี้ยนเรียก normalize ทั้งตอนบันทึกและตอนใช้เลือกที่เดียว
ผู้ใช้บ่นว่าแอปแก้ค่าที่พิมพ์แปลงตอนบันทึกโดยไม่บอกเก็บดิบ แปลงตอนใช้

8. แบบฝึกหัด

ช่อง host ก็มีปัญหาเดียวกัน ผู้ใช้พิมพ์มาได้หลายแบบ

192.168.1.194
 192.168.1.194
http://192.168.1.194
192.168.1.194:6191
192.168.1.194/wms
  1. ควรเขียน normalizeHost ที่แก้ให้ทุกแบบไหม
  2. ถ้าไม่ ควรทำอย่างไร
แนวคำตอบ

1. ไม่ควร และนี่คือความต่างสำคัญระหว่างสองช่อง

wms/ กับ /wms เป็นค่าเดียวกันที่พิมพ์คนละแบบ — แปลงให้ได้โดยไม่มีทางเดาผิด

แต่ 192.168.1.194:6191 ในช่อง host เป็นคนละเรื่อง — ผู้ใช้ใส่พอร์ตผิดช่อง ถ้าแอปแอบตัด :6191 ออกไปใส่ให้ในช่องพอร์ต จะเกิดสองปัญหา คือผู้ใช้ไม่รู้ว่าเกิดอะไรขึ้น และถ้าช่องพอร์ตมีค่าอยู่แล้ว จะต้องเลือกว่าอันไหนชนะ ซึ่งเดายังไงก็มีโอกาสผิด

2. ตรวจแล้วบอก ไม่ใช่แก้ให้

if (host.contains(':')) return 'พอร์ตให้ใส่ที่ช่อง Port';
if (host.contains('/')) return 'เส้นทางให้ใส่ที่ช่อง Base Path';
if (host.startsWith('http')) return 'ใส่เฉพาะที่อยู่ ไม่ต้องมี http://';

เส้นแบ่ง: normalize ได้เมื่อทุกรูปแบบมีความหมายเดียวกันแน่นอน ถ้าต้องเดาเจตนา ให้ถามผู้ใช้แทน — และ 10.7 จะพูดถึงวิธีถามที่ไม่ทำให้ผู้ใช้รำคาญ

9. สรุป

  • แปลงค่าให้เหลือรูปแบบเดียวที่ขอบ ทำครั้งเดียว
  • split + where(isNotEmpty) + join จัดการทับทุกแบบในบรรทัดเดียว
  • อย่าลืมกรณีที่แปลงแล้วไม่เหลืออะไร
  • เก็บค่าดิบ แปลงตอนใช้ ผู้ใช้จะได้เห็นสิ่งที่ตัวเองพิมพ์
  • normalize เมื่อความหมายเดียวกันแน่นอน ถ้าต้องเดาเจตนา ให้ตรวจแล้วบอกแทน
