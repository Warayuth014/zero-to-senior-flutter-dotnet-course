Normalize โดยรักษาความหมาย: protocol, host, port และ reverse-proxy base pathเป็นคนละ field; API prefixไม่ใช่ base path

1. Anatomy

https://wms.example.com:443/warehouse/api/WMS/tasks
scheme └──── host ─────┘ port └base path┘└ API path ─┘

2. Base path

String normalizeBasePath(String raw) {
  final value = raw.trim();
  if (value.isEmpty || value == '/') return '';
  return '/${value.split('/').where((p) => p.isNotEmpty).join('/')}';
}

ห้ามให้ผู้ใช้ใส่ /api ถ้า clientเติม prefixเอง

3. Host field

ถ้า formแยก protocol/host/port ช่อง hostต้องไม่รับ http://, slash, pathหรือ port ปน รองรับ IPv4, DNSและ IPv6ด้วย parser/designที่ชัด

4. Port

ตรวจ 1–65535 และตัดสินว่าจะ omit default 80/443ใน displayหรือเก็บ explicit ทุกครั้ง อย่าใช้ Uri.port โดยไม่เข้าใจ defaultPort behavior

5. Build with Uri

final origin = Uri(
  scheme: protocol.name, host: host, port: port,
  path: normalizeBasePath(basePath),
);
final health = origin.replace(path: '${origin.path}/api/WMS/mobile_health');

6. Idempotent normalization

normalize(normalize(x)) == normalize(x) และ outputเดียวกันสำหรับ wms, /wms, /wms/ เพื่อ comparison/dirty stateไม่สั่น

7. แบบฝึกหัด

ผู้ใช้ใส่ base path //warehouse// ต้องได้อะไรและ health URLเป็นอะไร?

เฉลย

/warehouse และ scheme://host:port/warehouse/api/WMS/mobile_health

8. Edge tests

empty/root/multiple slash, whitespace, invalid scheme, IPv4/DNS/IPv6, default/custom port, Unicode host policyและ pathที่พยายามใส่ query/fragment
