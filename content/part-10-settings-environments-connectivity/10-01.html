Typed preference key: รวมชื่อ key, type, default, migration และ ownershipไว้จุดเดียว ลด typo/collision และป้องกัน prefs.clear() ลบข้อมูลข้าม feature

1. Wrapper

final class PreferenceKey<T> {
  const PreferenceKey(this.name, this.defaultValue);
  final String name;
  final T defaultValue;
}
const localeKey = PreferenceKey<String>('app.v1.locale', 'th');
const serverPortKey = PreferenceKey<int>('connection.v1.port', 5000);

2. Type-safe access

สร้าง SettingsStore/adapter ที่รู้ว่า Stringใช้ getString, intใช้ getInt และแปลง missing/wrong typeเป็น defaultหรือ migration ไม่ให้ทุก widget castเอง

3. Namespace

ใช้ prefixตาม feature/schema เช่น connection.v1.profiles, auth.v1... เพื่อค้นหาและ selective deleteได้ หลีกเลี่ยง keyกว้างอย่าง host/status

4. Defaults

defaultควรอยู่ source of truthเดียวกับ config model ไม่ซ้ำใน form, controllerและApiClient มิฉะนั้น reset/load/first-runให้คนละ port

5. Failure policy

SharedPreferences pluginอาจ unavailableใน widget testหรือ writeล้ม ควรแยก persistence failureจาก in-memory settingและตัดสินว่าใช้ชั่วคราวได้หรือ block save

6. ของจริง

wmsapp/ApiConfigService ใช้ key host/port/protocolและ typed get/setแล้ว ส่วน connection controllerอีกแอปบันทึก JSON envelopeเพื่อรองรับหลาย profile

7. แบบฝึกหัด

เฉลย
