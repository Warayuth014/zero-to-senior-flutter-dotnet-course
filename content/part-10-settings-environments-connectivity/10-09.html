Health probe ที่ดีพิสูจน์ WMS API identity: HTTP 200อย่างเดียวบอกเพียงว่ามีบางอย่างตอบ URL ไม่ได้บอกว่า route/server/payloadถูก

1. Expected payload

{
  "service": "wms-mobile-api",
  "status": "healthy",
  "version": "1.4.2"
}

ตรวจ service markerและ statusแบบ typed ไม่เช็กเพียง bodyไม่ว่าง

2. Probe steps

  1. parse/validate draft base URL
  2. สร้าง health URIด้วย base path
  3. GET anonymousพร้อม timeoutสั้น
  4. ตรวจ status/content-type
  5. decode JSONและ marker
  6. คืน typed result + latency

3. Result taxonomy

invalidAddress, timeout, unreachable, tlsFailure, httpFailure, wrongService, unhealthyและ healthy ช่วย settings UIให้คำแนะนำตรงสาเหตุ

4. Request parity

Probeต้องใช้ resolverและ base pathเดียวกับ ApiClient ของจริงมีสอง health routeต่างกันตาม backend: /api/health และ /api/WMS/mobile_health

5. Anonymous/minimal

connection testก่อน loginควร anonymousและไม่เปิด DB details/secret ใช้ readiness dependencyเท่าที่จำเป็นและไม่ queryหนักทุก shell poll

6. Connectivity ≠ internet

WMS intranetอาจ onlineทั้งที่ไม่มี internet ตรวจ endpointเป้าหมาย ไม่ใช้ connectivity packageหรือ pingเป็นคำตอบสุดท้าย

7. แบบฝึกหัด

ได้ 200 JSON {"status":"ok"} จาก serviceอื่นควรขึ้นเขียวไหม?

เฉลย

ไม่ ถ้าไม่มี expected WMS service marker ให้ wrongServiceและแนะนำตรวจ base path/server

8. Contract tests

healthy/unhealthy marker, HTML 200, wrong JSON 200, 404/500, timeout/socket/TLS, Thai messageและ base path
