Application shellถือองค์ประกอบคงที่ของ session เช่น header, body slot, bottom navigation, feedback overlay และ feature store Navigation itemเปลี่ยน destinationภายใน shellโดยไม่สร้าง session/storeใหม่ทุก tap

1. Shell tree

WarehouseShell (owns session store)
└─ Scaffold
   ├─ AppBar / status / user menu
   ├─ Body destination
   ├─ feedback overlay
   └─ NavigationBar / bottomNavigationBar

2. Single selected destination

เก็บ selected index/screen key sourceเดียว Map index↔destinationอย่างแน่นอน ไม่ให้ highlight tabหนึ่งแต่ bodyอีกหน้า Absolute store.screenกำหนด bodyและ bottom navผ่าน ListenableBuilder

3. Preserve tab state

IndexedStackรักษา subtree/scrollแต่ใช้ memoryและ background listeners; สร้างตาม selectedทิ้ง transient stateแต่เบา เลือก per tabตาม UX และย้าย business stateเข้า storeไม่พึ่ง widgetค้าง

4. Nested Navigator

แต่ละ tabมี nested stackได้เมื่อ backต้องย้อนภายใน tabและสลับ tabแล้วเก็บ stack แต่ complexityเพิ่มเรื่อง root dialog/deep link ใช้เมื่อมี requirementจริง Shellแบบ screen keyง่ายกว่าสำหรับ PDA workflowตื้น

5. Store lifetime

Shellสร้าง WarehouseStoreครั้งเดียวใน initState, loadAllและ disposeพร้อม shell ทำ polling/session stateอยู่ถูกช่วง Logoutต้องหยุด timerผ่าน dispose

6. Responsive navigation

PDAใช้ bottom navจำนวน destinationหลักจำกัด; tabletอาจ NavigationRail แต่เลือก stateเดียวและ callbacksเดียว ไม่สร้าง shellสองชุดที่ behaviorต่างกัน

7. แบบฝึกหัด

Tab Tasksเลื่อน listแล้วไป Home/กลับ Tasksควรรักษา offsetอย่างไร?

เฉลย

ถ้า UXต้องรักษาใช้ IndexedStack/PageStorageKeyหรือ owner ScrollControllerตาม tab; dataอยู่ storeและ refreshตาม policy ไม่เก็บ controllerใน global repository

8. จุดพลาด

อย่า push Shellใหม่ทุกครั้งที่แตะ Home และอย่ามี Navigatorหลายตัวโดยไม่มี back/root modal policy มิฉะนั้น logout/dialogปิดผิด stack
