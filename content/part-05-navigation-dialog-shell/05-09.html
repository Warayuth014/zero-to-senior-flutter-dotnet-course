2. คำศัพท์ที่ต้องรู้ก่อน

6. แป้นพิมพ์บังแผ่น

ปัญหาที่เจอทันทีที่ใส่ช่องกรอกลงในแผ่น

ผู้ใช้แตะช่องค้นหา → แป้นพิมพ์ขึ้นมา → บังแผ่นครึ่งหนึ่ง
                                       ช่องที่กำลังพิมพ์อยู่ใต้แป้นพิมพ์

สองอย่างที่ต้องทำคู่กัน

showModalBottomSheet<String>(
  context: context,
  isScrollControlled: true,        // 1. ให้แผ่นสูงเกินครึ่งจอได้
  builder: (sheetContext) => Padding(
    // 2. ดันเนื้อหาขึ้นเท่าความสูงของแป้นพิมพ์
    padding: EdgeInsets.only(
      bottom: MediaQuery.of(sheetContext).viewInsets.bottom,
    ),
    child: ...,
  ),
);
ถ้าขาดอาการ
isScrollControlledแผ่นสูงได้แค่ครึ่งจอ ใส่อะไรไม่ค่อยได้
viewInsetsช่องกรอกอยู่ใต้แป้นพิมพ์ พิมพ์ไปโดยไม่เห็นสิ่งที่พิมพ์

บน PDA ที่จอสูงไม่มาก ปัญหานี้รุนแรงกว่าบนโทรศัพท์ เพราะแป้นพิมพ์กินสัดส่วนของจอมากกว่า

แต่มีข้อดีอย่างหนึ่ง — งานสแกนส่วนใหญ่ไม่ต้องใช้แป้นพิมพ์เลย เพราะข้อมูลมาจากเครื่องสแกน ถ้าออกแบบให้พิมพ์เฉพาะเมื่อจำเป็นจริง ปัญหานี้ก็แทบไม่เกิด

7. แผ่นที่มีของค้างต้องกันการปิด

แผ่นเลือกรายการปิดทิ้งได้ทุกเมื่อ เพราะยังไม่ได้เลือกอะไร แต่แผ่นที่มีฟอร์มต่างออกไป

PopScope(
  canPop: !_isDirty,
  onPopInvokedWithResult: (didPop, result) async {
    if (didPop) return;
    final discard = await showDiscardDialog(context);
    if (!discard || !context.mounted) return;
    Navigator.of(context).pop();
  },
  child: ...,
)

PopScope ใช้กับแผ่นได้เหมือนกับหน้าจอ เพราะแผ่นก็เป็น route

สิ่งที่ต้องระวังคือมีหลายทางที่ปิดแผ่นได้

ทางปิดPopScope ครอบไหม
แตะนอกแผ่นครอบ
ลากแผ่นลงครอบ
กดปุ่มย้อนกลับครอบ
ปุ่มปิดที่เราทำเองแล้วเรียก pop()ไม่ครอบ — ต้องใช้ maybePop() (5.5)

ตัวอย่างจริงอยู่ใน SettingsSheet ของ lab ซึ่งจะดูเต็ม ๆ ใน 5.11

8. เลือกให้ถูกว่าจะใช้อะไร

ใช้เมื่อตัวอย่าง
กล่องโต้ตอบตัดสินใจสั้น ๆ สองสามทางยืนยันลบ
แผ่นด้านล่างเลือกจากรายการ หรือกรอกฟอร์มสั้นเลือกพาเลท ตั้งค่า
หน้าจอเต็มงานที่มีหลายขั้นตอนรับเข้าทั้งใบ
DraggableScrollableSheetรายการยาวที่ผู้ใช้อาจอยากดูมากขึ้นค้นหาช่องเก็บ

เกณฑ์ที่ใช้ได้ — ถามว่า ผู้ใช้ต้องเห็นสิ่งที่อยู่ข้างหลังหรือไม่

คำตอบใช้
ต้องเห็น เพราะกำลังเลือกให้สิ่งนั้นแผ่น
ไม่ต้อง เพราะเป็นงานใหม่ทั้งชิ้นหน้าจอเต็ม

10. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
แผ่นสูงได้แค่ครึ่งจอไม่ได้ตั้ง isScrollControlledตั้งเป็น true
ช่องกรอกอยู่ใต้แป้นพิมพ์ไม่ได้ดันเนื้อหาขึ้นใส่ padding ตาม viewInsets.bottom
แผ่นล้นออกนอกจอshrinkWrap กับรายการยาวจำกัดความสูง + ListView.builder
เปิดแผ่นแล้วแอปหน่วงสร้างทุกรายการล่วงหน้าListView.builder
ปิดแผ่นแล้วหน้าจอปิดตามไปด้วยใช้ context ผิดตัวใน popใช้ sheetContext
ลากแผ่นลงแล้วของที่กรอกหายไม่มี PopScopeครอบด้วย PopScope
ปุ่มปิดที่ทำเองข้ามการตรวจใช้ pop()ใช้ maybePop()
เนื้อหาชนแถบล่างของระบบไม่ได้ครอบ SafeAreaครอบ หรือใช้ useSafeArea: true

ข้อที่สี่ — แผ่นถูกปิดได้ง่ายกว่าหน้าจอมาก (แตะนอกแผ่น ลากลง) จึงมีโอกาสสูงที่ผู้ใช้จะปิดขณะที่คำขอยังวิ่งอยู่ ถ้า store ไม่ได้เพิ่มเลขรุ่นตอนถูกทำลาย ผลที่กลับมาจะไปแตะ store ที่ตายแล้ว

ข้อที่ห้า — ต้องตัดสินตั้งแต่ออกแบบว่า store ของแผ่นเป็นของใคร

ทางเลือกใครทำลายเหมาะเมื่อ
แผ่นสร้างเองใน initStateแผ่นนั้นผลค้นหาไม่ต้องเก็บไว้
รับมาจากหน้าจอที่เปิดแผ่นหน้าจอนั้นอยากให้เปิดแผ่นครั้งหน้าเจอผลเดิม

โจทย์นี้ควรเลือกแบบแรก — ผลค้นหาไม่ควรค้างข้ามครั้ง เพราะช่องว่างในคลังเปลี่ยนตลอดเวลา และการเห็นผลเก่าจากเมื่อสิบนาทีก่อนอันตรายกว่าการรอโหลดใหม่สองวินาที

ข้อสังเกตสุดท้าย: แผ่นที่มีทั้งการค้นหา สถานะสี่แบบ และ store ของตัวเอง ไม่ใช่ “แค่ตัวเลือก” อีกต่อไป — มันเป็นหน้าจอเล็ก ๆ หนึ่งหน้าที่บังเอิญแสดงเป็นแผ่น จึงต้องได้รับการดูแลเท่ากับหน้าจอทั่วไป ซึ่งเป็นประเด็นหลักของ 5.11

12. สรุปท้ายบท

  • แผ่นด้านล่างคือ route จึงคืนค่าได้เหมือนหน้าจอ
  • ใช้เมื่อผู้ใช้ต้องเห็นบริบทด้านหลังขณะเลือก
  • รายการยาวต้องใช้ ListView.builder พร้อมกำหนดความสูงให้แผ่น
  • มีช่องกรอกต้องตั้ง isScrollControlled และหลบแป้นพิมพ์ด้วย viewInsets
  • อย่าตั้ง autofocus บน PDA — แป้นพิมพ์กินจอมากเกินไป
  • แผ่นที่มีของค้างต้องครอบ PopScope และปุ่มปิดต้องใช้ maybePop()
  • ปิดแผ่นด้วย context ที่ builder ของแผ่นให้มา
  • เมื่อแผ่นมี store ของตัวเอง ต้องตอบให้ได้ว่าใครสร้างและใครทำลาย
