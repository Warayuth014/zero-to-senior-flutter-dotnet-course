Duplicate guard มีสองชั้น: local listตอบผู้ใช้เร็ว แต่ server validationและ uniqueness constraintเท่านั้นที่กัน serialซ้ำข้ามเครื่อง/ข้าม sessionได้

1. Local duplicate

final index = _serialNumbers.indexOf(serialNo);
if (index >= 0) {
  highlight(index, duplicate: true);
  show duplicate status;
  return;
}

normalize trim+uppercaseก่อนเทียบ

2. Quantity guard

maxใช้ qtyRemainingถ้า >0 มิฉะนั้น qtyOrdered และ rejectเมื่อ serial countถึง max ต้องระวัง remaining=0ไม่ควร fallback orderedถ้า item complete; server status/revalidationเป็นตัวตัดสินสุดท้าย

3. Server validation

หน้าจอเรียก validateReceivingSerial() ผ่าน ReceivingApi ก่อนเพิ่มค่าเข้า local state

GET /receiving/validate-serial
  ?partId=P-001&serialNo=SN-01
→ ValidateSerialResponse

queryสร้างด้วย Uriจึง encodeค่าอย่างถูกต้อง

4. Line/lot match

แม้ serialเป็นของ partถูก ต้องมี serialResult.lineId == item.id มิฉะนั้น rejectพร้อมบอก lotจริง ป้องกัน serialของ lotอื่นหลุดเข้า receipt lineปัจจุบัน

5. Add and focus

เมื่อผ่านจึง add list, update qty text, clear input, highlight/scroll row, show status 5sและคืน focusให้ serial field UXเหล่านี้เป็นผลหลัง authoritative validation ไม่ก่อน

6. Remove

ลบ serialต้อง confirm, update list/qty/highlightและคืน focus หาก request submitกำลังทำงานควร disable mutationหรือ snapshot serial listที่ส่งเพื่อไม่ให้ UI/stateต่างจาก command

7. Race/double scan

scannerยิง serialเดิมสองครั้งเร็วระหว่าง validationแรก pending ทั้งคู่ยังไม่อยู่ local listและอาจ addซ้ำ ต้องมี in-flight set/serialize scan และ server enforce unique/idempotent command

8. Tests

local duplicate, concurrent duplicate, case/space, max qty, server reject, wrong line/lot, validation timeout, remove cancel/confirm, focusและ timer dispose พร้อม integration test uniquenessข้ามสอง clients
