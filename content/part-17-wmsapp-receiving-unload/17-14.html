บทสรุป Part 17: Receiving และ Unload เป็น chain ของ inventory transitions ที่ต้องรักษา line identity, เชื่อ server หลัง mutation และออกแบบ partial failure/retry ตั้งแต่ต้น

1. End-to-end receiving

scan PO → choose part/condition/lot
→ validate serial or qty → receive line
→ assign pallet → refresh PO
                  ↘ pending recovery

จุดสำคัญคือ receipt สำเร็จแต่ pallet fail ได้ จึงต้องไป recovery โดยไม่รับซ้ำ

2. End-to-end unload

scan pallet → open session → select line
→ validate serial/qty → confirm unload → reload session
→ all confirmed → return pallet

reload หลังทุก confirm รองรับ line/version ที่ backend เปลี่ยน

3. End-to-end basket

load unloaded inventory → scan part/choose lot
→ validate serial/qtyRemaining → scan basket
→ load → refresh unloaded inventory

นี่คือธุรกรรมใหม่ ไม่ใช่ continuation state ใน widget เดิม

4. Invariants

  • lineId ระบุ lot/receipt/session line; partId ระบุชนิดสินค้า
  • serial ห้ามซ้ำและต้องอยู่ใน line ที่เลือก
  • qty ต้องอยู่ใน remaining ล่าสุด
  • mutation สำเร็จแล้วต้องไม่ถูก submit ซ้ำเพราะ UI retry

5. Refactor priorities

เริ่มจากแยก workflow controller ออกจาก widget, ทำ typed result สำหรับ partial success, เพิ่ม explicit serialRequire, ยกเลิก silent date fallback, ทำ cancellation/latest-request guard และรวม error mapping ไว้ที่ API layer

6. Observability

ทุก request ควรมี correlation ID พร้อม operator, device, session, PO/pallet/line IDs และ result category โดยไม่ log token หรือข้อมูลลับ Metrics ที่ควรมีคือ retry rate, pending age, duplicate rejection และ unload duration

7. Test pyramid

unit test parser/validator/reducer, widget test scanner focus/dialog/progress, API contract test กับ .NET fixture และ end-to-end test ตั้งแต่รับ PO จนเข้า basket เน้น timeout ambiguity, concurrency และ partial success มากกว่า happy path อย่างเดียว

8. Capstone

วาด sequence diagram จากโค้ดจริงหนึ่ง receiving line และหนึ่ง unload line จากนั้น refactor flow ใด flow หนึ่งให้มี immutable state + typed commands เพิ่ม idempotency key ฝั่ง API และเขียน test พิสูจน์ว่า retry หลัง timeout ไม่เพิ่ม inventory ซ้ำ
