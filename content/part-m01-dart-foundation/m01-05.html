1. ปัญหาที่บทนี้แก้

ตัวแปรหนึ่งตัวเก็บได้หนึ่งค่า แต่งานจริงคือ “พาเลททั้งหมดที่สแกนวันนี้” หรือ “จำนวนคงเหลือของสินค้าแต่ละรหัส” เราต้องการกล่องที่เก็บได้หลายค่า และต้องเลือกกล่องให้ตรงกับคำถามที่จะถามข้อมูลนั้นบ่อยที่สุด

5. Map: จับคู่รหัสกับค่า

final stockByCode = <String, int>{
  'PAL-1001': 12,
  'PAL-1002': 4,
};
stockByCode['PAL-1003'] = 9;          // เพิ่มคู่ใหม่

print(stockByCode['PAL-1002']);        // 4
print(stockByCode['PAL-9999']);        // null  <- ไม่มี key นี้
print(stockByCode['PAL-9999'] ?? 0);   // 0     <- ใส่ค่าสำรอง
สิ่งที่ต้องจำให้ขึ้นใจ: การอ่าน Map ด้วย key ที่ไม่มีอยู่จะได้ null ไม่ใช่ error — โปรแกรมจะไม่เตือนอะไรเลย แล้วไปพังทีหลังตอนเอาค่าไปใช้ นี่เป็นสาเหตุอันดับต้น ๆ ของบั๊ก “ข้อมูลหายไปเฉย ๆ” ตอนต่อกับ API (จะเจอเต็ม ๆ ใน D1.19)

วนอ่านทั้ง Map ด้วย entries ซึ่งให้ทั้ง key และ value

for (final entry in stockByCode.entries) {
  print('${entry.key} -> ${entry.value} ชิ้น');
}

6. แปลง กรอง รวม โดยไม่ต้องเขียน for

ตรงนี้คือจุดที่บทที่แล้วออกดอกออกผล — เราส่ง ฟังก์ชัน เข้าไปบอกว่าจะทำอะไรกับสมาชิกแต่ละตัว

คำสั่งแปลว่าได้อะไรกลับ
where(...)เก็บเฉพาะตัวที่เงื่อนไขเป็นจริงIterable
map(...)แปลงทุกตัวเป็นอย่างอื่นIterable
fold(...)ยุบทั้งหมดให้เหลือค่าเดียวค่าเดียว
any(...) / every(...)มีอย่างน้อยหนึ่งตัว / ทุกตัวbool
toList() / toSet()เก็บผลลัพธ์เป็นก้อนจริงList / Set
final lowStock = stockByCode.entries
    .where((entry) => entry.value < 10)   // กรองของใกล้หมด
    .map((entry) => entry.key)            // เอาเฉพาะรหัส
    .toList();

final totalStock = stockByCode.values
    .fold<int>(0, (sum, value) => sum + value);

where และ map เป็น lazy คือยังไม่ทำงานจริงจนกว่าจะมีคนอ่านผล การเติม toList() คือการบอกว่า “คำนวณเดี๋ยวนี้ แล้วเก็บผลไว้” ซึ่งควรทำเมื่อจะใช้ผลลัพธ์ซ้ำหลายครั้ง

7. กับดักที่สำคัญที่สุด: ตัวแปรสองตัวอาจชี้ก้อนเดียวกัน

final a = <String>['A'];
final b = a;        // ไม่ได้คัดลอก แค่ตั้งชื่อเล่นให้ก้อนเดิม
b.add('B');
print(a);           // [A, B]  <- a เปลี่ยนไปด้วย

final copied = [...a];   // spread operator = สร้างก้อนใหม่จริง ๆ
copied.add('C');
print(a);                // [A, B]      ไม่กระทบ
print(copied);           // [A, B, C]

ทบทวนจาก D1.3: ตัวแปรเก็บ “ที่อยู่” ของข้อมูล ไม่ใช่ตัวข้อมูล การกำหนดค่าให้ตัวแปรใหม่จึงเป็นการจดที่อยู่เดียวกันลงกระดาษอีกใบ ไม่ใช่การย้ายของ

เรื่องนี้จะกลายเป็นเรื่องใหญ่ตอนทำ state ในแอปจริง เพราะโค้ดบางแบบตรวจว่าข้อมูลเปลี่ยนโดยดูว่า “เป็นก้อนใหม่หรือเปล่า” ถ้าเราแก้ก้อนเดิมตลอด หน้าจออาจไม่อัปเดต ตอนนี้ยังไม่ต้องแก้อะไร แค่จำอาการนี้ไว้

8. สร้าง collection แบบมีเงื่อนไข

const isSupervisor = true;

final menu = <String>[

  'หยิบสินค้า',

รูปแบบ if และ ... ภายในวงเล็บนี้เรียกว่า collection if และ spread — Flutter ใช้ท่านี้ตลอดเวลาเพื่อประกอบรายการเมนูหรือรายการปุ่มตามสิทธิ์ผู้ใช้ ถ้าคุ้นตั้งแต่วันนี้ ตอนอ่านโค้ดหน้าจอจริงจะไม่สะดุด

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
Bad state: No elementเรียก .first บน collection ว่างตรวจ isEmpty ก่อน หรือใช้ firstWhere พร้อม orElse
Bad state: No element จาก firstWhereไม่มีสมาชิกตรงเงื่อนไขใส่ orElse: () => ... หรือใช้ where(...).firstOrNull
RangeError: Invalid valueอ่าน index เกินขนาดจำไว้ว่า index สุดท้ายคือ length - 1
ConcurrentModificationErrorเพิ่มหรือลบสมาชิกระหว่างที่กำลังวนอ่านสร้าง list ใหม่จากผลลัพธ์ แทนการแก้ของเดิมกลางคัน
แก้ list หนึ่ง แล้วอีกตัวเปลี่ยนตามสองตัวแปรชี้ก้อนเดียวกันคัดลอกด้วย [...list]
ค่าที่คิดว่าซ้ำ กลับไม่ถูกตัดออกจาก Setข้อความมีช่องว่างหรือตัวพิมพ์ต่างกันจัดรูปแบบก่อนใส่ เช่น .trim().toUpperCase()

10. แบบฝึกหัด

พนักงานสแกนซีเรียลต่อเนื่องทั้งกะ ระบบต้องทำสองอย่างพร้อมกัน

  1. แสดงรายการบนหน้าจอ เรียงตามเวลาที่สแกน
  2. ไม่ยิงข้อมูลซ้ำขึ้น server ถ้าซีเรียลนั้นเคยสแกนไปแล้วในกะนี้

จงเขียนฟังก์ชัน addScan ที่รับซีเรียลดิบ แล้วคืน bool ว่ารับเข้าใหม่หรือไม่ พร้อมบอกว่าใช้โครงสร้างข้อมูลอะไรและเพราะอะไร

ดูแนวคำตอบและเหตุผล
final displayOrder = <String>[];   // ลำดับสำหรับหน้าจอ
final seen = <String>{};           // ตรวจซ้ำแบบเร็ว

bool addScan(String raw) {
  final serial = raw.trim().toUpperCase();
  if (serial.isEmpty) return false;
  if (!seen.add(serial)) return false;   // add คืน false ถ้ามีอยู่แล้ว
  displayOrder.add(serial);
  return true;
}

void main() {
  for (final raw in [' sn-001 ', 'SN-002', 'SN-001', '', 'sn-003']) {
    print('$raw -> ${addScan(raw) ? 'รับเข้า' : 'ข้าม'}');
  }
  print(displayOrder);   // [SN-001, SN-002, SN-003]
}

ทำไมต้องใช้ทั้งสองอย่าง: คำถามมีสองข้อที่ขัดกัน — “ลำดับ” ต้องใช้ List ส่วน “ไม่ซ้ำ” ต้องใช้ Set การใช้ List อย่างเดียวแล้วเช็คด้วย contains ก็ได้คำตอบถูก แต่ต้องไล่อ่านทั้งรายการทุกครั้ง พอสแกนหลักพันรายการจะเริ่มหน่วง

เกร็ดที่ควรรู้: seen.add(serial) คืน bool อยู่แล้วว่าเพิ่มสำเร็จหรือไม่ จึงไม่ต้องเรียก contains ก่อนแล้วค่อย add ซึ่งเป็นการอ่านสองรอบโดยไม่จำเป็น

ลองต่อ: เพิ่มการนับว่าซีเรียลไหนถูกยิงซ้ำกี่ครั้ง คำใบ้คือคุณจะต้องใช้ Map<String, int>

11. สรุปท้ายบท

  • เลือก collection จากคำถามที่จะถามข้อมูลบ่อยที่สุด ไม่ใช่จากความคุ้นมือ
  • List = ลำดับ, Set = ไม่ซ้ำ, Map = ค้นด้วย key
  • อ่าน Map ด้วย key ที่ไม่มี จะได้ null เงียบ ๆ ไม่ใช่ error
  • where/map/fold ทำงานร่วมกับฟังก์ชันที่เราส่งเข้าไป และเป็น lazy จนกว่าจะ toList()
  • การกำหนดค่า collection ให้ตัวแปรใหม่ไม่ได้คัดลอก ต้องใช้ [...list]
