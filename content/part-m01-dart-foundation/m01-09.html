จบบทนี้แล้วจะทำได้: อ่านออกว่า <T> ที่เห็นอยู่ทั่วโค้ด Flutter แปลว่าอะไร และเขียนฟังก์ชัน/class ที่ใช้ซ้ำได้กับหลายชนิดโดยไม่เสียการตรวจสอบชนิด

1. ปัญหาที่บทนี้แก้

สมมติเราต้องการฟังก์ชันที่คืนสมาชิกตัวแรกของรายการ หรือคืน null ถ้ารายการว่าง ถ้าไม่มี generic เราจะต้องเขียนซ้ำทุกชนิด

String? firstStringOrNull(List<String> items) { ... }
int? firstIntOrNull(List<int> items) { ... }
Pallet? firstPalletOrNull(List<Pallet> items) { ... }   // ไม่จบสักที

ทางออกที่ผิดคือรับ List<dynamic> แล้วคืน dynamic — เขียนสั้นลงจริง แต่เสียการตรวจสอบชนิดทั้งหมด บั๊กจะย้ายจากตอน compile ไปโผล่ตอนผู้ใช้กำลังใช้งาน

Generic ให้ทั้งสองอย่าง: เขียนครั้งเดียว และยังรู้ชนิดที่แน่นอน

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
genericโค้ดที่เว้น “ช่องว่างของชนิด” ไว้ให้ผู้เรียกเติม
type parameterตัวอักษรที่แทนช่องว่างนั้น เช่น T, K, V, R
type argumentชนิดจริงที่ถูกเติมลงไป เช่น String ใน List<String>
constraintข้อจำกัดว่าชนิดที่เติมได้ต้องเป็นอะไร

T ย่อมาจาก Type เป็นเพียงธรรมเนียมการตั้งชื่อ จะใช้ตัวอักษรอะไรก็ได้ แต่ที่นิยมคือ T สำหรับชนิดทั่วไป, K/V สำหรับ key/value ใน Map และ R สำหรับผลลัพธ์ที่แปลงแล้ว

3. Mental model: แบบฟอร์มที่เว้นช่องไว้

คุณใช้ generic มาตั้งแต่ D1.5 แล้วโดยไม่รู้ตัว

ที่เคยเขียนช่องว่างถูกเติมด้วยผลคือ
List<String>Stringlist ที่ใส่ได้เฉพาะข้อความ
Map<String, int>String และ intkey เป็นข้อความ value เป็นจำนวนเต็ม
Set<String>Stringชุดข้อความที่ไม่ซ้ำ

ทีมที่เขียน Dart ไม่ได้เขียน ListOfString, ListOfInt แยกกัน — เขาเขียน List<T> ครั้งเดียว แล้วเราเป็นคนบอกว่า T คืออะไรตอนใช้ บทนี้คือการเรียนวิธีสร้างแบบฟอร์มแบบนั้นเอง

ประโยคเดียวที่ต้องจำ: generic คือการเลื่อนการตัดสินใจเรื่องชนิดจาก “ตอนเขียน” ไปเป็น “ตอนใช้” โดยไม่ทิ้งการตรวจสอบ

4. Generic function

T? firstOrNull<T>(List<T> items) => items.isEmpty ? null : items.first;

อ่านทีละส่วน: <T> หลังชื่อฟังก์ชันประกาศว่า “ฟังก์ชันนี้มีช่องว่างชื่อ T” จากนั้น List<T> และ T? ใช้ช่องว่างเดียวกัน ซึ่งเป็นการบอก Dart ว่า ชนิดที่รับเข้ากับชนิดที่คืนออกต้องเป็นตัวเดียวกัน

Set-Location .\labs\flutter_wms_companion
dart run tool/dart_foundation/d1_09_generics.dart
firstCode  = PAL-1001  (String)
firstCount = 10  (int)
empty      = null

สังเกตว่าเราไม่ได้บอก Dart เลยว่า T คืออะไร มันดูจาก argument แล้วเติมให้เอง เรียกว่า type inference — ตัวเดียวกับที่ทำให้ var ทำงานใน D1.2

5. Generic class

รูปแบบที่จะใช้บ่อยที่สุดในงานจริงคือ “กล่องผลลัพธ์” ที่บอกได้ทั้งสำเร็จและล้มเหลว

class ApiResult<T> {
  const ApiResult.success(this.data) : error = null, isSuccess = true;
  const ApiResult.failure(this.error) : data = null, isSuccess = false;

  final T? data;
  final String? error;
  final bool isSuccess;
}

final ok = ApiResult<Pallet>.success(Pallet('PAL-1001', 12));
final bad = ApiResult<Pallet>.failure('เชื่อมต่อ server ไม่ได้');

ประโยชน์ที่เห็นได้ทันที: เมื่ออ่านชนิด ApiResult<Pallet> เราตอบได้สามข้อโดยไม่ต้องเปิดโค้ดข้างใน — งานนี้อาจสำเร็จหรือล้มเหลว, ถ้าสำเร็จจะได้ Pallet, และถ้าล้มเหลวจะมีข้อความบอกเหตุผล

ยิ่งไปกว่านั้น ชนิดสามารถเปลี่ยนได้ระหว่างทางโดยไม่เสียสถานะ

ApiResult<R> map<R>(R Function(T value) convert) { ... }

print(ok.map((pallet) => pallet.quantity));    // สำเร็จ: 12
print(bad.map((pallet) => pallet.quantity));   // ล้มเหลว: เชื่อมต่อ server ไม่ได้

map มีช่องว่างของตัวเองชื่อ R เพราะผลลัพธ์ที่แปลงแล้วเป็นคนละชนิดกับของเดิม ส่วนความล้มเหลวถูกส่งต่อไปโดยไม่ต้องเขียน if ที่ทุกจุดเรียก

6. Constraint: จำกัดว่าเติมอะไรลงช่องได้บ้าง

num sumAll<T extends num>(List<T> values) =>
    values.fold<num>(0, (total, value) => total + value);

sumAll(<int>[10, 4, 7]);       // 21
sumAll(<double>[1.5, 2.25]);   // 3.75
// sumAll(<String>['a']);      // error ตั้งแต่ยังไม่รัน

ถ้าไม่ใส่ extends num เราจะบวก value ไม่ได้เลย เพราะ Dart ไม่รู้ว่าชนิดที่จะถูกเติมเข้ามารองรับเครื่องหมาย + หรือเปล่า constraint จึงทำสองหน้าที่พร้อมกัน — ปฏิเสธการใช้ที่ผิด และเปิดให้เราใช้ความสามารถของชนิดนั้นภายในฟังก์ชัน

7. Generic ที่จะเจอใน Flutter

ยังไม่ต้องเข้าใจรายละเอียด แค่ให้ตาคุ้นว่า <T> ที่จะเห็นในบทต่อ ๆ ไปคือเรื่องเดียวกับที่เรียนวันนี้

ที่จะเห็นช่องว่างหมายถึงเรียนใน
Future<String>ค่าที่จะได้ในอนาคตเป็นข้อความD1.15
Stream<String>ค่าที่ทยอยมาเรื่อย ๆ เป็นข้อความD1.16
State<MyScreen>สถานะที่ผูกกับหน้าจอชื่อ MyScreenPart 1
ValueChanged<int>ฟังก์ชันที่รับ int เมื่อค่าเปลี่ยนPart 3
FutureBuilder<Task>ตัวช่วยวาดหน้าจอที่รอ TaskPart 4

8. เมื่อ generic มากเกินพอดี

Generic เป็นเครื่องมือ รักษาชนิด ไม่ใช่เป้าหมายในตัวเอง ถ้าเขียนแล้วมี type parameter สามสี่ตัวจนอ่านไม่ออก หรือช่องว่างนั้นถูกเติมด้วยชนิดเดียวเสมอตลอดทั้งโปรเจกต์ ให้เขียนเป็น class เฉพาะเรื่องไปเลยจะอ่านง่ายกว่า

เกณฑ์ตัดสินง่าย ๆ: “ช่องว่างนี้จะถูกเติมด้วยชนิดที่ต่างกันจริง ๆ อย่างน้อยสองแบบไหม” ถ้าตอบว่าไม่ ก็ยังไม่ต้องใช้ generic

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
The operator '+' isn't defined for the type 'T'ใช้ความสามารถของชนิดที่ยังไม่รู้ว่ามีเพิ่ม constraint เช่น <T extends num>
type 'List<dynamic>' is not a subtype of type 'List<String>'สร้าง collection โดยไม่ระบุชนิด แล้วเอาไปใช้ที่ต้องการชนิดแน่นอนเขียน <String>[] ตั้งแต่ตอนสร้าง
ได้ dynamic ทั้งที่คิดว่าจะได้ชนิดที่ต้องการDart เดาไม่ออกจากบริบทระบุชนิดตอนเรียก เช่น firstOrNull<Pallet>(items)
แก้ error ด้วยการเติม as dynamicปิดปาก analyzer แทนที่จะแก้ต้นเหตุไล่ย้อนกลับไปว่าชนิดเริ่มเพี้ยนตั้งแต่จุดไหน แล้วแก้ตรงนั้น

10. แบบฝึกหัด

เขียน class Cache<T> ที่

  1. เก็บของตามรหัสข้อความ
  2. มี put(String id, T item) และ T? get(String id)
  3. มี getOrAdd(String id, T Function() create) ที่คืนของเดิมถ้ามี และสร้างใหม่เก็บไว้ถ้ายังไม่มี
  4. มี getter count

แล้วทดสอบกับทั้ง Cache<String> และ Cache<int>

ดูแนวคำตอบและเหตุผล
class Cache<T> {
  final Map<String, T> _items = <String, T>{};

  int get count => _items.length;

  T? get(String id) => _items[id];

  void put(String id, T item) => _items[id] = item;

  T getOrAdd(String id, T Function() create) {
    final existing = _items[id];
    if (existing != null) return existing;
    final created = create();
    _items[id] = created;
    return created;
  }
}

void main() {
  final names = Cache<String>();
  names.put('A-01', 'โซนรับเข้า');
  print(names.get('A-01'));            // โซนรับเข้า
  print(names.get('ไม่มี'));            // null

  var built = 0;
  final counts = Cache<int>();
  print(counts.getOrAdd('x', () { built++; return 42; }));   // 42
  print(counts.getOrAdd('x', () { built++; return 99; }));   // 42 (ของเดิม)
  print('สร้างจริง $built ครั้ง');                             // 1
}

จุดที่ generic ทำงานให้: names.get('A-01') คืน String? ส่วน counts.get('x') คืน int? โดยเราเขียน class เดียว ถ้าใช้ Map<String, dynamic> แทน โค้ดจะสั้นเท่ากันแต่ผู้ใช้ต้อง cast เองทุกครั้งและพลาดได้

ข้อควรระวังในคำตอบนี้: getOrAdd ใช้ existing != null ตรวจว่ามีของอยู่แล้วหรือไม่ ซึ่งจะทำงานผิดถ้า T เป็นชนิดที่ยอมให้เก็บ null ได้ (เช่น Cache<String?>) ทางแก้ที่ถูกต้องคือใช้ _items.containsKey(id) — เป็นตัวอย่างที่ดีว่า generic บังคับให้เราคิดถึงกรณีที่กว้างกว่าที่ตั้งใจไว้ตอนแรก

ลองต่อ: เพิ่ม constraint ให้ Cache<T extends Object> แล้วสังเกตว่า Cache<String?> จะถูกปฏิเสธตั้งแต่ตอน compile ซึ่งทำให้โค้ดข้างในปลอดภัยขึ้นทันที

11. สรุปท้ายบท

  • generic คือช่องว่างของชนิดที่ผู้เรียกเป็นคนเติม
  • เขียนครั้งเดียว ใช้ได้หลายชนิด โดยไม่เสียการตรวจสอบตอน compile
  • ช่องว่างเดียวกันที่ใช้ทั้งขาเข้าและขาออก คือการประกาศความสัมพันธ์ระหว่างชนิด
  • extends ในวงเล็บมุมคือ constraint ไม่ใช่การสืบทอด
  • List, Map, Future, Stream ล้วนเป็น generic ที่เราใช้อยู่แล้ว
  • ถ้าช่องว่างจะถูกเติมด้วยชนิดเดียวเสมอ ก็ยังไม่ต้องใช้ generic
