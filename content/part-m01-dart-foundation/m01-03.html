final คุมการ assign reference, const สร้างค่าคงที่ตอน compile time และ late เลื่อนการกำหนดค่า ทั้งสามคำแก้คนละปัญหา

1. เปรียบเทียบให้ชัด

คำกำหนดค่าเมื่อไรกำหนดซ้ำใช้เมื่อ
finalruntime ได้ไม่ได้ค่าที่รู้หลังสร้าง object/เรียก function
constcompile timeไม่ได้literal/config/widget ที่คงที่จริง
lateภายหลัง ก่อนอ่านครั้งแรกขึ้นกับมี final หรือไม่lifecycle รับประกัน initialization แต่ constructor ทำไม่ได้

2. final ไม่ได้ทำให้ object immutable

final scans = <String>[];
scans.add('PAL-001');   // ได้: list ยัง mutable
// scans = [];          // ไม่ได้: reference assign ใหม่ไม่ได้

const statuses = <String>['OPEN', 'DONE'];
// statuses.add('HOLD'); // runtime error: const list แก้ไม่ได้

ถ้าต้องการ immutable state ให้ class/collection ออกแบบไม่เปิด mutation ไม่ใช่ใส่ final ที่ field อย่างเดียว

3. const และ Flutter

const Widget บอกว่า configuration ชุดนี้สร้างได้ตั้งแต่ compile time และ reuse ได้เมื่อ parent rebuild แต่ห้ามไล่ใส่ const แบบไม่เข้าใจ: argument ทุกตัวต้องเป็น compile-time constant

const SizedBox(height: 12);
const Color(0xFF0878F9);

final title = serverResult.title;
Text(title); // const ไม่ได้ เพราะ title รู้ตอน runtime

ตัวอย่างจริงอยู่ใน wms_absolute_mobile/lib/features/warehouse/ui/pda_colors.dart: สีและ metric ที่ไม่เปลี่ยนเป็น static const

4. late: สัญญาที่ compiler ตรวจเวลาไม่ได้

class _WarehouseShellState extends State<WarehouseShell> {
  late final WarehouseStore store;

  @override
  void initState() {
    super.initState();
    store = WarehouseStore(/* dependencies */);
  }
}

แนวนี้ใช้จริงใน warehouse_shell.dart เพราะต้องสร้าง store ใน lifecycle ถ้าอ่านก่อน assign จะเกิด LateInitializationError ถ้าไม่มั่นใจว่าจะมีค่า ใช้ nullable แล้วจัดการ absence ตรง ๆ ดีกว่า

5. late lazy initialization

initializer ของ late final จะรันเมื่อถูกอ่านครั้งแรก จึงใช้เลื่อนงานแพงได้ แต่ต้องระวัง side effect ที่เวลารันไม่ชัด:

late final config = loadConfig(); // loadConfig รันเมื่ออ่าน config ครั้งแรก

6. Decision guide

  1. รู้ค่าคงที่ตั้งแต่ compile time → const
  2. รู้ค่าครั้งเดียวตอน runtime → final
  3. lifecycle รับประกันว่าจะ assign ก่อนใช้ → late final
  4. อาจไม่มีค่าจริง → T?
  5. เปลี่ยนค่าเป็น state ตามเวลา → ตัวแปรปกติพร้อม owner ชัดเจน

7. แบบฝึกหัด

เลือกคำให้ base URL ที่ผู้ใช้แก้ได้, http.Client ที่ inject ใน constructor, สีแบรนด์, และ controller ที่สร้างใน initState

เฉลย

base URL เป็น mutable state; client เป็น final; สีแบรนด์เป็น static const; controller เป็น late final หรือกำหนดที่ declaration แล้ว dispose ตาม lifecycle

8. จุดพลาด

อย่าใช้ late เพื่อหลบ null safety ทุกครั้ง มันย้าย error จาก compile time ไป runtime และทำให้ initialization order เป็นภาระของคนอ่าน
