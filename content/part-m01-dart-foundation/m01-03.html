จบบทนี้แล้วจะทำได้: เลือกได้ทันทีว่าจะใช้ var, final, const หรือ late และอธิบายเหตุผลให้คนอื่นฟังได้

1. ปัญหาที่บทนี้แก้

เมื่อเปิดโค้ด Flutter ของจริง คุณจะเห็นคำสี่คำนี้ปนกันทั้งไฟล์ ถ้าเลือกผิดจะเจอสองอาการ คือโปรแกรมไม่ยอม compile (น่ารำคาญแต่ไม่อันตราย) หรือแอปช้าและพังตอนรัน (อันตราย) บทนี้ทำให้การเลือกกลายเป็นเรื่องอัตโนมัติ

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมาย
compile timeช่วงที่ Dart แปลโค้ดของเรา ยังไม่ได้รันโปรแกรม
runtimeช่วงที่โปรแกรมกำลังทำงานจริง
immutableสร้างแล้วแก้ไม่ได้อีก
reference“ที่อยู่” ที่ตัวแปรชี้ไปหาข้อมูล ไม่ใช่ตัวข้อมูลเอง
lazyยังไม่ทำตอนนี้ รอจนกว่าจะถูกใช้จริง

3. Mental model: เทียบกับกล่องในคลัง

คำเปรียบเทียบเปลี่ยนค่าได้ไหมรู้ค่าเมื่อไหร่
varกล่องธรรมดา หยิบเข้าออกได้เรื่อย ๆได้ตอนรัน
finalกล่องที่ปิดผนึกหลังใส่ของครั้งแรกไม่ได้ตอนรัน
constป้ายที่พิมพ์ติดผนังไว้ตั้งแต่ก่อนเปิดคลังไม่ได้ตอน compile
lateกล่องที่จองที่ไว้ แต่ยังไม่ใส่ของขึ้นกับว่าคู่กับ final หรือไม่ตอนรัน เมื่อถูกใช้ครั้งแรก
ประโยคเดียวที่ต้องจำ: const คือค่าที่รู้ได้โดยไม่ต้องรันโปรแกรม ส่วน final คือค่าที่รู้ตอนรัน แต่รู้แล้วห้ามเปลี่ยน

4. เส้นแบ่งระหว่าง final กับ const

const appName = 'WMS Companion';   // ได้ เพราะเป็นข้อความตายตัว
final startedAt = DateTime.now();  // ต้องเป็น final เพราะเวลาเพิ่งรู้ตอนรัน
// const startedAt = DateTime.now(); // ผิด: compiler ยังไม่รู้ว่าตอนนี้กี่โมง

ทดสอบตัวเองด้วยคำถามเดียว: “ถ้าฉันปิดคอมพิวเตอร์แล้วเปิดใหม่พรุ่งนี้ ค่านี้ยังเท่าเดิมไหม” ถ้าตอบว่าใช่ ใช้ const ได้ ถ้าตอบว่าไม่แน่ ให้ใช้ final

5. กับดักใหญ่: final ล็อกแค่กล่อง ไม่ได้ล็อกของข้างใน

นี่คือจุดที่คนใหม่พลาดมากที่สุดในบทนี้ ลองรันดู

final scanned = <String>['PAL-1001'];
scanned.add('PAL-1002');   // ทำได้! เพราะยังเป็น list ก้อนเดิม
// scanned = <String>[];   // ทำไม่ได้ เพราะเปลี่ยนไปชี้ list ก้อนใหม่

const frozen = <String>['PAL-9001'];
// frozen.add('X');         // พังตอนรัน: const list แก้ข้างในไม่ได้เลย
เปลี่ยนตัวแปรให้ชี้ของใหม่แก้ข้างในของก้อนเดิม
var listได้ได้
final listไม่ได้ได้
const listไม่ได้ไม่ได้

วิธีจำ: final ล็อก “ป้ายชื่อ” ส่วน const ล็อก “ทั้งกล่องและของข้างใน”

6. ทำไม Flutter ถึงชอบ const

เมื่อเราเขียน const Dart จะสร้างวัตถุนั้นเพียงชิ้นเดียวแล้วใช้ซ้ำทุกครั้ง ลองรัน lab เพื่อดูหลักฐาน

Set-Location .\labs\flutter_wms_companion
dart run tool/dart_foundation/d1_03_final_const_late.dart
identical(a, b) = true    // const สองตัว -> เป็นวัตถุชิ้นเดียวกัน
identical(c, d) = false   // final สองตัว -> สร้างใหม่คนละชิ้น

identical ถามว่า “เป็นวัตถุชิ้นเดียวกันจริง ๆ หรือเปล่า” ไม่ได้ถามว่าค่าเท่ากันไหม

ผลกับ Flutter คือ widget ที่ประกาศเป็น const จะไม่ถูกสร้างใหม่ทุกครั้งที่หน้าจอวาดใหม่ ทำให้แอปลื่นขึ้นโดยเราไม่ต้องทำอะไรเพิ่ม ตอนนี้ยังไม่ต้องเข้าใจ widget — แค่รู้ว่านิสัยการเติม const ที่ฝึกวันนี้จะได้ผลตอบแทนใน Part 1 เป็นต้นไป

7. late: สัญญาว่าจะใส่ค่าก่อนใช้

late ใช้เมื่อเรารู้แน่ว่าตัวแปรจะมีค่า แต่ยังใส่ตอนประกาศไม่ได้

class ShiftReport {
  late String shiftName;   // ยังไม่มีค่า แต่สัญญาว่าจะใส่ก่อนอ่าน

  void start(String name) => shiftName = name;
  String describe() => 'รายงานของ $shiftName';
}
สิ่งที่ต้องเข้าใจให้ตรง: late ไม่ได้ทำให้ตัวแปรปลอดภัยขึ้น มันแค่ ย้ายการตรวจสอบจาก compile time ไป runtime ถ้าเราผิดสัญญาคืออ่านก่อนใส่ค่า โปรแกรมจะพังด้วย LateInitializationError ตอนผู้ใช้กำลังใช้งานอยู่

ก่อนใช้ late ให้ลองสามทางนี้ก่อนเสมอ

  1. ใส่ค่าเริ่มต้นไปเลยได้ไหม เช่น String shiftName = '';
  2. รับค่าผ่าน constructor ได้ไหม (จะได้ใช้ final แทน)
  3. ยอมรับว่ามันว่างได้จริง แล้วใช้ String? พร้อมตรวจก่อนใช้ (D1.13)

ถ้าสามทางนี้ไม่ได้จริง ๆ ค่อยใช้ late

8. late final: คำนวณครั้งเดียวตอนถูกใช้ครั้งแรก

รูปแบบนี้มีประโยชน์มากและปลอดภัยกว่า late เปล่า ๆ เพราะยังตั้งค่าได้ครั้งเดียวเหมือน final

class LazyIndex {
  late final List<String> index = _buildIndex();

  List<String> _buildIndex() {
    print('  >> _buildIndex() ทำงานแล้ว');
    return ['A-01', 'A-02', 'B-01'];
  }
}

ผลลัพธ์จาก lab แสดงให้เห็นชัดว่างานหนักถูกเลื่อนออกไปและทำเพียงครั้งเดียว

ยังไม่แตะ index — ยังไม่มีการคำนวณ
  >> _buildIndex() ทำงานแล้ว
อ่านครั้งที่ 1: 3 รายการ
อ่านครั้งที่ 2: 3 รายการ (ไม่คำนวณซ้ำ)

9. ตารางตัดสินใจ

สถานการณ์ใช้
ค่าตายตัวที่รู้ตั้งแต่เขียนโค้ด เช่น ชื่อแอป, ขนาดปุ่ม, สีconst
ค่าที่ได้มาตอนรันแล้วไม่เปลี่ยนอีก เช่น เวลาเริ่มงาน, ผลลัพธ์จาก APIfinal
ค่าที่ต้องเปลี่ยนระหว่างทาง เช่น ตัวนับ, สถานะกำลังโหลดvar
ค่าที่ต้องใส่ทีหลังแน่ ๆ และหลีกเลี่ยงไม่ได้จริงlate
ค่าที่คำนวณแพงและอาจไม่ถูกใช้เลยlate final
ค่าที่อาจไม่มีจริง ๆชนิด nullable เช่น String? (D1.13)
ลำดับการเลือกที่แนะนำ: เริ่มที่ const ก่อนเสมอ ถ้าไม่ได้ค่อยลดไป final ถ้าไม่ได้อีกค่อยใช้ var ส่วน late คือทางเลือกสุดท้าย

10. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
Const variables must be initialized with a constant valueใส่ค่าที่รู้ตอนรันให้ const เช่น DateTime.now()เปลี่ยนเป็น final
Unsupported operation: Cannot add to an unmodifiable listพยายามแก้ข้างใน const collectionถ้าต้องแก้ ให้ใช้ final แทน
LateInitializationError: Field 'x' has not been initializedอ่านตัวแปร late ก่อนใส่ค่าใส่ค่าเริ่มต้น หรือเปลี่ยนเป็นชนิด nullable
เพิ่มสมาชิกใน final list ได้ ทั้งที่คิดว่าห้ามเข้าใจว่า final ล็อกข้างในด้วยใช้ List.unmodifiable หรือ const
ใช้ late ทุกที่เพื่อให้ analyzer เงียบใช้ late เป็นทางหนี null safetyยอมรับว่าค่าอาจว่าง แล้วใช้ชนิด nullable ตรง ๆ

11. แบบฝึกหัด

ตัดสินใจว่าแต่ละบรรทัดควรใช้คำใด แล้วเขียนรวมเป็นไฟล์ที่รันผ่าน

  1. ชื่อบริษัทที่ไม่มีวันเปลี่ยน
  2. เวลาที่พนักงานกดเริ่มกะ
  3. จำนวนพาเลทที่สแกนไปแล้วในกะนี้
  4. รายชื่อช่องเก็บที่ต้องอ่านจากไฟล์ ซึ่งบางหน้าจอไม่เคยเปิดดูเลย
  5. จำนวนสูงสุดต่อกล่องที่กำหนดไว้ในนโยบายบริษัท
ดูแนวคำตอบและเหตุผล
ข้อคำตอบเหตุผล
1const companyName = 'Absolute';รู้ตั้งแต่เขียนโค้ด และไม่มีวันเปลี่ยน
2final shiftStart = DateTime.now();รู้ตอนรัน แต่รู้แล้วไม่เปลี่ยน
3var scannedCount = 0;ต้องเพิ่มค่าเรื่อย ๆ ระหว่างกะ
4late final List<String> locations = loadFromFile();แพง และอาจไม่ถูกเรียกใช้เลย
5const maxPerBox = 50;ค่านโยบายที่ตายตัวในโค้ด

ข้อ 3 มีอีกคำตอบที่ถูก: ถ้าเก็บรายการที่สแกนไว้เป็น final List<String> scanned = [] แล้วนับด้วย scanned.length ก็ถูกเช่นกัน เพราะเราเพิ่มสมาชิกเข้า list เดิม ไม่ได้เปลี่ยนตัว list — นี่คือข้อ 5 ของหัวข้อที่แล้วในทางปฏิบัติ

12. สรุปท้ายบท

  • const = รู้ค่าตั้งแต่ compile และล็อกลึกถึงข้างใน
  • final = รู้ค่าตอนรัน ตั้งได้ครั้งเดียว แต่ข้างในยังแก้ได้
  • var = เปลี่ยนค่าได้ ชนิดยังคงที่
  • late = เลื่อนการตรวจไป runtime ใช้เมื่อไม่มีทางอื่นจริง ๆ
  • เริ่มจาก const เสมอ แล้วค่อยผ่อนลงเท่าที่จำเป็น
