Reconnectคืน transport ไม่คืนข้อมูลที่พลาด: หลัง reconnectต้อง join groupsใหม่ตาม server behaviorและโหลด snapshot/deltaตั้งแต่ last versionเพื่อ reconcile

1. State machine

disconnected → connecting → connected
       ↑            ↓ error      ↓ lost
       └──── reconnecting ←──────┘
connected → stopping → disconnected

2. Single-flight connect

เก็บ Future<void>? _connecting ให้หลาย screensรอ Futureเดียว ไม่เรียก startพร้อมกันและ ref-countเพิ่มซ้ำจาก retry

3. Automatic reconnect

กำหนด delays/backoffตาม libraryและ expose attempt/last error ใช้ jitterเมื่อ devicesจำนวนมาก reconnectหลัง server restart

4. Reconnected hook

  1. ตรวจ session/server generation
  2. join groupsใหม่ถ้าจำเป็น
  3. HTTP refreshหรือขอ eventsหลัง lastVersion
  4. ค่อย mark realtime synchronized

5. Manual disconnect

logout/server switch/dispose ownerต้องตั้ง intent flagเพื่อไม่ให้ automatic reconnectต่อเอง แยก intentional stopจาก network drop

6. App lifecycle

backgroundอาจ suspend socketและ timer เมื่อ resumedอย่าเชื่อ connection stateเก่า ให้ ensureConnected + reconcile และปรับตาม platform/battery policy

7. แบบฝึกหัด

connection reconnectสำเร็จหลังหลุด 30 วินาที ควรแค่เปลี่ยน dotเขียวไหม?

เฉลย

ไม่ ต้อง resubscribe/rejoinและ refresh snapshotหรือ deltaก่อนจึงถือ synchronized เพราะ eventsระหว่างหลุดอาจหาย

8. Chaos tests

server down/up, Wi-Fi toggle, tokenหมดอายุ, app background/resume, logoutระหว่าง reconnectและ devicesพร้อมกันโดยไม่มี reconnect storm
