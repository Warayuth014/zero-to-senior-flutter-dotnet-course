1. Acceptance criteria

  • .NET broadcastหลัง commitไป warehouse group
  • eventมี eventId/taskId/status/version/occurredAt
  • Flutter parse dynamicที่ boundary
  • subscription/lease cancelได้และไม่รั่ว
  • duplicate/out-of-orderถูก ignore
  • reconnectโหลด snapshotก่อน synchronized
  • fallback pollingมี backoffและ lifecycle guard

2. Server event

await hub.Clients.Group($"wh:{warehouseId}").SendAsync(
  "TaskStatusChanged",
  new TaskStatusChanged(eventId, task.Id, task.Status,

3. Flutter reducer

void onRealtime(TaskStatusChanged event) {
  if (event.sessionGeneration != sessionGeneration) return;
  final current = state.byId[event.taskId];
  if (current != null && event.version <= current.version) return;
  state = state.apply(event); notifyListeners();
}

4. Sync algorithm

  1. subscribe/register handlers
  2. connect + join group
  3. GET task snapshot/version
  4. replay newer queued events
  5. mark synchronized/stop fallback
  6. on disconnect mark stale/start fallback

5. Test matrix

valid/malformed event, duplicate/versionย้อน, eventระหว่าง GET, reconnectหลัง 30s, HTTP failขณะ hub connected, logout/server switch, two screens leasesและ dispose event

6. Observability

log connection state, reconnect attempt, event name/version, refresh cause, lagจาก occurredAtและ last syncโดย redact token/task payloadที่อ่อนไหว

7. Device drill

เปิดสองเครื่องเปลี่ยน task, toggle Wi-Fi, background/resume, restart serverและยิง event burst ตรวจ UIสุดท้ายตรง API snapshotโดยไม่มี duplicate toast/request storm
