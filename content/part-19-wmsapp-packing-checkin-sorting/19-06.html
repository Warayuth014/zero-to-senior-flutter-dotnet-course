Packing models คือสาม snapshots: pallet-level เลือก pack, pack-level เลือก order และ order-level ทำ part scan Response จาก mutation ยังบอกผล finalize ของ pack ด้วย

1. API surface

GET  /packing/pallet/{palletId}
GET  /packing/pack/{packingId}
GET  /packing/pack/{packingId}/order/{pickOrderId}
POST /packing/scan-part

2. Pallet models

PackingPalletResponse มี status/location/packs; PackingSummary มี orderCount/orderDoneCount และ isDone ที่ true เมื่อ status DONE หรือ doneCount≥count

3. Pack models

PackingDetailResponse มี tracking/completedAt/orders และถือว่า done จาก status เท่านั้น ส่วน PackingOrderSummary บอก part progress ต่อ pick order

4. Order model

PackingOrderResponse มี parts, status, packFinalized, trackingId, palletReleased ทำให้ response ของ scan เป็นทั้ง updated order snapshot และ domain event summary

5. Part model

PackingPartItem คำนวณ isDone เมื่อ scannedQty≥requiredQty และ remaining ด้วย clamp มี serialRequire/availableSerials แต่ไม่มี lineId/lot/condition จึงจำกัดกรณี part ซ้ำ

6. Parser pitfalls

required lists/fields cast ตรงและ invalid dates fallback now อาจ crash หรือซ่อน contract error ควร validate shape, nullable, unknown status และรายงาน malformed payload แบบสังเกตได้

7. URL and errors

IDs ถูกต่อใน path โดยไม่ encode และทุก endpointรักษา statusCode ผ่าน ApiResult ควรใช้ Uri path segments พร้อม typed ProblemDetails เพื่อแยก conflict/not-found/auth/timeout

8. Contract tests

สร้าง fixtures ทุกระดับ รวม empty/malformed lists, unknown status, invalid dates, serial/nonserial, auto-finalize และ pallet release แล้ว round-trip กับ .NET DTO serialization
