ไม่มีปุ่ม finalize แยก: backend auto-finalize pack เมื่อ scan part สุดท้ายทำให้ทุก detail DONE และ response เดียวบอก tracking กับการ release pallet

1. Batch local confirm

_confirmCollectedPack สร้าง readyParts: serial ต้องครบ remaining, non-serial ต้องมี qty>0 แล้วเรียก _confirmPart ทีละรายการตามลำดับ

2. Sequential partial commit

หาก part แรกสำเร็จแต่ part ที่สอง fail ธุรกรรมแรกถูก commit แล้ว นี่ไม่ใช่ atomic batch UI ต้องเก็บผลใหม่และแจ้งว่าอะไรสำเร็จ ไม่เสนอ retry ทั้งชุดโดยไม่ตรวจ state

3. Auto-finalize signal

PackingOrderResponse.packFinalized เป็น true เมื่อ server ปิด pack แล้ว พร้อม trackingId และ palletReleased ซึ่งบอกว่า pallet ไม่มี pack อื่นค้าง

4. Synthetic success model

UI สร้าง ConfirmPackResponse เองจาก order response และใช้ DateTime.now() เป็น completedAt จึงไม่ใช่เวลา server จริง ควรให้ API คืน typed finalize result/UTC timestamp โดยตรง

5. Success transition

เมื่อ finalized ล้าง draft ของ part แล้วเปลี่ยน state success หาก palletReleased แสดงว่าพร้อมใช้ pallet ใหม่ มิฉะนั้นต้อง refresh pack list เพื่อทำงานที่เหลือ

6. Duplicate finalize

double tap/timeout อาจยิง scan ชิ้นสุดท้ายซ้ำ Endpoint ต้อง idempotent ด้วย operation key และ unique constraint; client ควร disable command และ query pack เมื่อผลไม่แน่นอน

7. Pack vs pallet completion

pack DONE ไม่เท่ากับ pallet released เสมอ เพราะ pallet มีหลาย packs UI/metrics ต้องแยกสอง concept ไม่ใช้ status เดียวตัดสินนำ palletออก

8. Finalize tests

ทดสอบ one/multi-order pack, finalize ที่ part สุดท้าย, sequential second failure, duplicate request, tracking missing, pallet released true/false และ server/client clock ต่างกัน
