Part scan เลือกชนิด input: serial-controlled ต้องยืนยัน serial ทุกชิ้น ส่วน non-serial ระบุ qty ได้บางส่วน แต่ทั้งคู่ยังเป็น draft จนส่ง scanPackPart

1. Activate part

partId ต้องอยู่ใน order และยังไม่ done จากนั้น set selectedPart/ช่อง scan; serial item โฟกัส S/N ส่วน non-serial เติม remaining ลง qty field

2. Quantity draft

qty ต้องเป็น int มากกว่า 0 และไม่เกิน part.remaining แล้วเก็บใน _collectedQty[partId] Non-serial อนุญาต partial packing จึงไม่บังคับเท่ากับ remaining

3. Serial draft

serial ถูก uppercase, ห้ามซ้ำใน local list, ต้องอยู่ใน availableSerials และ count ไม่เกิน remaining จากนั้น clear/focus เพื่อ scan ต่อ

4. Serial completeness

serial part พร้อม submit เมื่อ collected count เท่ากับ remaining เท่านั้น ต่างจาก non-serial ที่มากกว่า 0 ก็พร้อม เหตุผลคือ serial ทุกหน่วยต้องระบุ identity ต่อ request

5. Identity collision

maps และ selection key ด้วย partId เช่นเดียวกับ Picking ถ้า order มี part เดียวกันหลาย lot/condition lines ข้อมูลจะชน และ payloadไม่มี lineId/lot ควรเพิ่ม inventory line identity ตลอด contract

6. Confirm payload

POST /packing/scan-part
{ packingId, pickOrderId, partId, qty,
  operatorId, serialNumbers? }

non-serial ส่ง empty list แต่ API omit field เมื่อ list ว่าง

7. Server validation

backend ต้องตรวจ pack/order membership, remaining ล่าสุด, serial ownership/uniqueness และ status ใน transaction ไม่เชื่อ availableSerials หรือ qty จาก snapshot ฝั่ง client

8. Input tests

ทดสอบ wrong/done part, qty partial/zero/เกิน, duplicate/unknown serial, part หลาย lot, remove serial, double submit และ timeout หลัง commit โดยยอด scanned ต้องเพิ่มเพียงครั้งเดียว
