Refactor giant screen ด้วย characterization tests: เป้าหมายไม่ใช่ทำไฟล์สั้นทันที แต่แยก business transitions ออกจาก rendering โดยรักษาพฤติกรรม scanner, partial commit และ navigation เดิม

1. Freeze behavior

เขียน tests รอบ scan/open/back, serial/qty validation, auto-finalize, preview/commit, complete/dispatch และ SignalR ก่อนย้ายโค้ด บันทึกพฤติกรรมที่เป็น bug แยกจาก behaviorที่ต้องรักษา

2. Extract pure policy

ย้าย readyParts, remaining/allDone, station tap decision, pipeline progress และ validation เป็น pure functions/value objects ก่อน เพราะเสี่ยงต่ำและ unit testง่าย

3. Introduce typed state

sealed class PackingState {}
ScanPallet | PackList | OrderList
| OrderParts | Submitting | Success | Failure

รวม dataที่จำเป็นในแต่ละ stateแทน nullable fieldsหลายตัว

4. Move commands

สร้าง controller/store รับ repository interfaces และคืน typed effects เช่น ShowError/RequestFocus/Navigate อย่าให้ controllerถือ BuildContext หรือ TextEditingController

5. Split widgets

แยก page ต่อ state, scanner card, part list, serial editor, success panel โดยรับ immutable data/callback อย่าย้าย logicซ้ำไปหลาย widgetเพียงเพื่อให้ไฟล์หลักสั้น

6. Fix one boundary at a time

เริ่ม packing hierarchy → part draft → submit จากนั้น check-in orchestration และ sorting realtime แต่ละ PRต้อง build/testและเทียบ payloadเดิม หลีกเลี่ยง rewriteทั้ง 3 screensพร้อมกัน

7. Add concurrency controls

repository/controllerควรมี request generation/cancellation, command lock, idempotency key และ authoritative refreshหลัง mutation UI loadingหนึ่ง booleanไม่พอเมื่อมีหลาย requestชนกัน

8. Definition of done

ไฟล์ widgetไม่มี API parsing/business transition, state combinationsผิดกฎหมายสร้างไม่ได้, all commandsมี typed error/retry policy, scanner focusมี widget tests และ payload/contract testsผ่านเหมือนก่อน refactor
