ไฟล์หลัก: lib/core/api_client.dart — transport layer ที่รวม URL, JSON, timeout, Bearer token และการแปล HTTP error ไว้จุดเดียว

1. หน้าที่และขอบเขต

ApiClient ไม่ควรรู้ receiving หรือ task แต่รู้วิธีส่ง request ไป WMS: สร้าง URI, ตั้ง JSON headers, เติม Authorization, encode body, timeout, decode response และโยน ApiException ส่วน repository เป็นผู้รู้ endpoint กับ shape ของข้อมูล

2. Dependency injection ที่มีอยู่

constructor รับ http.Client ได้ จึงใช้ mock client ใน unit test โดยไม่ยิง network จริง ถ้าไม่ส่งจะสร้าง client มาตรฐาน ข้อควรระวังคือ implementation ยังไม่มี public close/dispose ที่บอก ownership ชัด; เมื่อเพิ่ม streaming/connection pooling ควรกำหนดว่าใครปิด injected client และใครปิด owned client

3. Request pipeline

resolve current base URL
→ choose absolute or /api/WMS prefix
→ Content-Type/Accept: application/json
→ Authorization: Bearer <token> (ถ้ามี)
→ jsonEncode(body)
→ POST timeout 15s
→ decode success or translate failure

4. Success contract

response body ที่ว่างหรือ decode ไม่ได้ตามกรณีที่รองรับจะกลับ map ว่าง แต่ payload ปกติต้องเป็น JSON object การ cast เป็น Map<String,dynamic> ทำให้ JSON array หรือ scalar เป็น contract mismatch ซึ่งควรถูกทดสอบที่ repository ถ้า endpoint คืนหลาย shape ควรมี method/decoder แบบ typed แทนขยาย dynamic ไปทั่วระบบ

5. Error translation

เมื่อ status ไม่สำเร็จ client มองข้อความตามลำดับ Message, message, msg แล้ว fallback เป็นข้อความ HTTP code ก่อนโยน ApiException(message, statusCode) ขณะที่ SocketException และ TimeoutException ถูกแปลเป็นข้อความผู้ใช้ สิ่งนี้แยก transport failure ออกจาก business failure ได้บางส่วน แต่ exception type เดียวยังจำแนก retryability ไม่ละเอียด

6. Token เป็น mutable transport state

authToken ถูกตั้งหลัง login และล้างตอน logout ทำให้ทุก adapter ได้ header โดยอัตโนมัติ ความเรียบง่ายนี้แลกกับ coupling: request ที่กำลังวิ่งอาจใช้ token เก่า, เปลี่ยน server แล้วยังพก token และไม่มีกลไก serialize refresh token การขยาย production ควรใช้ request interceptor/token provider ที่อ่าน session snapshot อย่างมี policy

7. Failure modes ที่ต้องรู้

  • HandshakeException และ certificate error ยังไม่ได้แปลเท่า probe
  • http.ClientException หรือ invalid URI อาจหลุดเป็น raw error
  • JSON malformed/type cast error ไม่กลายเป็น domain-friendly contract error
  • มีเฉพาะ POST ใน client ปัจจุบัน; อย่าจำลอง GET ด้วย body
  • automatic retry ของ mutation อาจทำรายการซ้ำถ้าไม่มี idempotency key

8. Test matrix

ใช้ mock client ยืนยัน URI/header/body สำหรับ absolute และ prefixed request, 2xx body ว่าง/object, 4xx ที่ใช้ key ข้อความทั้งสามแบบ, 500 non-JSON, timeout/socket, malformed success JSON และ token add/remove โดย test ต้องตรวจว่า error ไม่เผย token/password
