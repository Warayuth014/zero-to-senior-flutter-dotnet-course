ไฟล์หลัก: lib/features/auth/auth_repository.dart — repository แปลง login use case ให้เป็น HTTP contract และเก็บ session ปัจจุบันใน memory

1. ทำไมไม่ยิง HTTP จาก LoginScreen

หน้าจอควรดูแล input/loading/navigation ส่วน AuthRepository ดูแล endpoint, request field, response parsing และการผูก token กับ client เมื่อ backend เปลี่ยนชื่อ field หรือ route จึงแก้ที่ data boundary โดยไม่รื้อ widget

2. Contract ที่โค้ดใช้จริง

POST /api/Authenticate/login   // absolute
{
  "Username": "operator",
  "Password": "..."
}

response → token, expiration

ตัวพิมพ์ใหญ่ของ request key และ route นอก /api/WMS เป็นส่วนของ contract ต้องตรงกับ .NET DTO/controller ไม่ควรเปลี่ยนตาม style ของ Dart โดยไม่มี mapping

3. Parse แล้ว commit session

repository รอ response, อ่าน token และ expiration, สร้าง AuthSession โดยใช้ username จาก input และ roles ว่าง แล้วตั้งทั้ง client.authToken กับ field session การ commit สองตำแหน่งนี้ต้องเกิดหลัง validation สำเร็จเท่านั้น ไม่เช่นนั้น UI อาจคิดว่า login fail แต่ transport มี token ครึ่งหนึ่ง

4. Repository เปิด client ให้ shell

client ถูก expose เพื่อให้ WarehouseShell สร้าง ReceivingApi, TasksApi และ adapters อื่นจาก transport เดิม วิธีนี้เหมาะกับ codebase ขนาดปัจจุบัน แต่ senior refactor อาจให้ composition root สร้าง adapters โดยตรง เพื่อลดการที่ auth repository กลายเป็น service locator

5. Logout ที่มีอยู่

logout() ล้าง session และ authToken แบบ synchronous แล้ว shell ใช้ pushReplacement กลับหน้า login สิ่งที่ยังต้องตรวจในระบบจริงคือ store/timer/stream ถูก dispose, cache ข้อมูลผู้ใช้ถูกล้าง และ server-side refresh token/revocation ถูกเรียกหรือไม่

6. Error path

ApiException จาก client ถูกส่งต่อให้ LoginScreen แสดง inline error ส่วน parse error เช่น token หายหรือ expiration ผิดรูปควรถูกแปลงเป็น auth contract error ที่เข้าใจได้ ปัจจุบันต้องอ่าน implementation/test เพื่อยืนยันพฤติกรรม อย่า catch ทุกอย่างแล้วแสดง “รหัสผ่านผิด” เพราะ network และ backend schema error ต้องแก้ต่างกัน

7. Security review

  • password อยู่เฉพาะ request และห้าม log
  • HTTP profile ส่ง credential แบบ cleartext; production ควรบังคับ HTTPS
  • token อยู่ memory จึงหายเมื่อปิดแอป ซึ่งปลอดภัยกว่า plain preferences แต่ UX ต้อง login ใหม่
  • roles ยังว่าง จึงยังใช้ client-side authorization ไม่ได้
  • expiration ถูกเก็บแต่ยังไม่มี enforcement/refresh

8. Contract test ที่ควรเขียน

ฉีด fake ApiClient หรือ mock transport แล้วพิสูจน์ว่า endpoint เป็น absolute, payload casing ถูก, success ตั้ง session/token ครั้งเดียว, failure ไม่แตะ session เดิม, logout ล้างสองแหล่ง และ response ที่ token/expiration หายถูกปฏิเสธอย่างชัดเจน
