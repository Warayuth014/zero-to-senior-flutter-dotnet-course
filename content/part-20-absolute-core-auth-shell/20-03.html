ไฟล์หลัก: lib/core/app_config.dart — config ไม่ได้เก็บ active URL เป็นค่าคงที่ แต่ resolve ใหม่เมื่อ request ขอใช้

1. URL มีหลาย root

โปรเจกต์มี base URL ของ server แล้วต่อ route ตาม contract: business API ส่วนใหญ่ใช้ prefix /api/WMS, login ใช้ absolute path /api/Authenticate/login และบางระบบอาจมี /api/data การรวมทุก endpoint ไว้ใต้ prefix เดียวจะสร้าง URL ผิดโดยเงียบ ๆ จึงต้องให้ call site ระบุชัดว่า path เป็น prefixed หรือ absolute

2. Precedence ของ base URL

--dart-define=WMS_API_BASE_URL=...
             ↓ ถ้าไม่มี
ConnectionController.activeBaseUrl
             ↓ ถ้ายังโหลด/ไม่มี
http://localhost:6191

compile-time override เหมาะกับ managed build/CI และถูก pin ไม่ให้ runtime setting หลอกผู้ใช้ว่าเปลี่ยน server ได้ ส่วน profile เหมาะกับเครื่องภาคสนามหลาย environment

3. Getter แทน cached field

AppConfig.apiBaseUrl เป็น getter ที่เรียก resolver ทุกครั้ง ดังนั้น Save & Use profile ใหม่แล้ว request ถัดไปจะเห็น URL ใหม่ทันที แม้ ApiClient เป็น object เดิม หาก cache URL ตอน constructor ของ client การสลับ profile จะไม่เกิดผลจน restart หรือ recreate dependency graph

4. ประกอบ URL ที่ boundary เดียว

baseUrl + (absolute ? '' : apiPrefix) + path

caller ควรส่ง path ที่เริ่มด้วย slash ตาม convention เดียว และ ConnectionProfile ต้อง normalize base path ไม่ให้มี slash ท้ายซ้ำ การกระจาย string interpolation ไปทุก repository ทำให้เกิด //api, port หาย หรือ prefix ซ้ำได้ง่าย

5. Environment label ไม่ใช่ security policy

production/development/custom ใน profile ช่วยจัดหมวดและค่าเริ่มต้น แต่ protocol/host/port/basePath ต่างหากที่สร้าง URL อย่าใช้ label “production” เป็นหลักฐานว่า HTTPS ถูกบังคับ หรือใช้ label “development” เพื่อปิด certificate validation; validation/security ต้องผูกกับค่าจริงและ build policy

6. เปลี่ยน server กระทบ session

เพราะ token ยังอยู่ใน ApiClient เมื่อ active URL เปลี่ยน request จะส่ง token เดิมไป server ใหม่ นี่อาจได้ 401 หรือร้ายกว่านั้นคือส่ง credential ข้าม environment แนวทางปลอดภัยคือ profile switch สำเร็จแล้ว invalidate session, กลับ login และล้าง feature state เว้นแต่ระบบพิสูจน์ว่า issuer/audience เดียวกัน

7. Contract tests ที่ควรมี

  • override ชนะ active profile และ fallback
  • base path /gateway/wms ต่อกับ prefix ได้ครั้งเดียว
  • login ไม่ถูกเติม /api/WMS
  • business endpoint ถูกเติม prefix
  • สลับ active profile แล้ว client เดิมสร้าง URI ใหม่
  • ค่าที่มี slash/space ผิดรูปถูก reject ก่อนถึง HTTP

8. แบบฝึก .NET boundary

เขียนตาราง endpoint อย่างน้อย 5 รายการ โดยมี Flutter call, URI เต็ม, HTTP method, request DTO และ .NET route จากนั้นเพิ่ม test ที่จับกรณี login ถูกต่อ prefix ผิดและกรณี base path ทำให้ /api/api ซ้ำ
