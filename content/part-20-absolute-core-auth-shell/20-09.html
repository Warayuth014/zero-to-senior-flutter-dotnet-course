3. ค่าที่ถูกตั้งเพราะพีดีเอ

return ThemeData(
  useMaterial3: true,
  colorScheme: scheme,
  scaffoldBackgroundColor: AppColors.pageBg,
  visualDensity: VisualDensity.standard,              // ①
  materialTapTargetSize: MaterialTapTargetSize.padded, // ②
  ...
);

① VisualDensity.standard

ปกติจะเขียน VisualDensity.adaptivePlatformDensity ซึ่งบีบระยะห่างให้แน่นขึ้นบนเดสก์ท็อป

ที่นี่ตรึงเป็น standard — ระยะห่างเท่ากันทุกที่ จอบนพีดีเอกับจอที่รันบนเครื่องพัฒนาจึงหน้าตาเหมือนกัน

② MaterialTapTargetSize.padded

บังคับให้พื้นที่กดของทุกปุ่มมีอย่างน้อย 48×48 พิกเซล แม้ตัวปุ่มจะเล็กกว่านั้น

สอดคล้องกับ PdaMetrics.minTapTarget = 48.0 ในอีกไฟล์

สองบรรทัดนี้คือหัวใจของธีมพีดีเอ
คนงานสวมถุงมือ นิ้วหนากว่าปกติ และมักถือของอยู่มือเดียว
ปุ่มที่กดพลาดในคลังไม่ได้แค่ทำให้รำคาญ — มันแปลว่ายืนยันผิดใบ แล้วต้องมีคนไปตามแก้ในระบบ

ปุ่มที่สูงกว่าปกติ

filledButtonTheme: FilledButtonThemeData(
  style: FilledButton.styleFrom(
    minimumSize: const Size.fromHeight(54),      // ← ปกติ 40
    ...
  ),
),
outlinedButtonTheme: OutlinedButtonThemeData(
  style: OutlinedButton.styleFrom(
    minimumSize: const Size.fromHeight(50),      // ← เตี้ยกว่าปุ่มหลัก
    ...
  ),
),
ปุ่มสูงสื่อว่า
FilledButton54การกระทำหลัก — ยืนยัน, บันทึก
OutlinedButton50ทางเลือกรอง — ยกเลิก, ย้อนกลับ

ความต่าง 4 พิกเซลไม่ได้ตั้งใจให้มองเห็น แต่ทำให้ปุ่มหลักเด่นกว่าเล็กน้อยแม้จะวางเรียงกัน

และ Size.fromHeight แปลว่ากำหนดแค่ความสูง ความกว้างปล่อยให้ยืดตามพื้นที่ — ปุ่มจึงเต็มความกว้างจอโดยอัตโนมัติ ซึ่งเป็นสิ่งที่ต้องการบนจอแคบ

ขนาดที่มีจุดทศนิยม

14.5, 13.5, 12.5 — ไม่ใช่เลขกลม

ในสเกลมาตรฐานของ Material ค่าเหล่านี้คือ 16, 14, 12 — ที่นี่บีบลงเล็กน้อยเพื่อให้ข้อความยาว ๆ (ชื่อสินค้า, รหัสตำแหน่ง) ลงในบรรทัดเดียวบนจอแคบ

การลดขนาดตัวอักษรบนจอเล็กเป็นดาบสองคม — อ่านยากขึ้นในที่แสงน้อย
ครึ่งพิกเซลเป็นการประนีประนอมที่พอดี ต่างจากการลดจาก 16 เหลือ 12 ซึ่งจะเห็นผลชัดกับคนสายตาไม่ดี
โปรเจกต์นี้ยังใช้ auto_size_text ในบางจอสำหรับข้อความที่ยาวเกินคาด (20.1) แทนที่จะลดขนาดฐานลงไปอีก

น้ำหนักตัวอักษรที่หนักกว่าปกติ

w800 สำหรับหัวข้อ และ w700 สำหรับป้าย — มาตรฐานคือ w600/w500

ตัวหนาขึ้นอ่านง่ายกว่าในที่ที่แสงจ้าหรือจอมีรอยขีดข่วน ซึ่งเป็นสภาพของพีดีเอที่ใช้งานมาสักพัก

height ที่ตั้งไว้ทุกตัว

headlineSmall: TextStyle(..., height: 1.2),
bodyLarge:     TextStyle(..., height: 1.4),

height คือระยะระหว่างบรรทัดเทียบกับขนาดตัวอักษร — ตั้งไว้ชัดเจนแทนที่จะปล่อยตามฟอนต์

ผลคือกล่องข้อความมีความสูงที่ทำนายได้ ซึ่งสำคัญเมื่อต้องจัดหลายบรรทัดในการ์ดที่มีที่จำกัด

5. ขอบมนสามระดับ

cardTheme       → 16

เรียงจากใหญ่ไปเล็กตามขนาดของสิ่งที่ครอบ — กล่องใหญ่ขอบมนมาก กล่องเล็กขอบมนน้อย

ค่าเหล่านี้ซ้ำใน PdaMetrics

class PdaMetrics {

  static const cardRadius = 16.0;
  static const controlRadius = 14.0;

ค่าเดียวกันอยู่สองที่ — cardRadius = 16 ใน PdaMetrics และ BorderRadius.circular(16) ใน cardTheme
ถ้าเปลี่ยนที่หนึ่งแล้วลืมอีกที่ การ์ดที่ใช้ Card จะไม่เหมือนการ์ดที่วาดเองด้วย Container
แก้ได้ทันทีโดยให้ธีมอ่านจาก PdaMetrics — แต่จะต้องย้าย PdaMetrics ขึ้นมาที่ core/ ก่อน เพราะตอนนี้มันอยู่ใต้ features/ และ core/ ไม่ควร import จาก features/

28 พิกเซล

สูง
AppBar มาตรฐาน56

ครึ่งเดียว เพราะบนจอสูง 800 พิกเซล ทุก 28 พิกเซลที่ประหยัดได้คือหนึ่งแถวของรายการที่มองเห็นเพิ่ม

ทำได้เพราะแถบนี้ไม่มีปุ่ม — มีแค่ไอคอน ชื่อแอป และคำว่า PDA จึงไม่ต้องเผื่อพื้นที่กด 48 พิกเซล

ต่อเนื่องกับแถบของระบบ

gradient: LinearGradient(
  colors: [AppColors.statusBar, Color(0xFF122D45)],
),

AppColors.statusBar คือสีเดียวกับที่ main.dart ตั้งให้แถบสถานะของ Android (20.2) — สองแถบจึงกลมกลืนเป็นแถบเดียว โดยมีนาฬิกาและแบตเตอรี่ของระบบอยู่ด้านบน

key: const ValueKey('pda-status-bar-surface')

key ที่ใส่ไว้เพื่อให้เทสต์หาเจอ

find.byKey(const ValueKey('pda-status-bar-surface'))
การใส่ key เพื่อเทสต์เป็นการยอมให้เทสต์มีร่องรอยในโค้ดจริง
ทางเลือกคือหาโดย find.byType(PdaStatusBar) ซึ่งไม่ต้องแตะโค้ดเลย
แต่ที่นี่ต้องการหา Container ข้างในเพื่อตรวจสี ไม่ใช่ตัว widget — จึงต้องมี key
ยอมรับได้เมื่อมีน้อยและตั้งชื่อชัด แต่ถ้าเริ่มมี key แบบนี้กระจายทุกไฟล์ แปลว่าเทสต์กำลังผูกกับโครงสร้างภายในมากเกินไป

10. แบบฝึกหัด

  1. ค้นหาทุกที่ที่ใช้ PdaColors.green กับ AppColors.success แล้วเสนอทางรวม
  2. ธีมนี้ตั้ง ColorScheme.light ตายตัว — ถ้าต้องรองรับโหมดมืดสำหรับกะกลางคืน ต้องแก้อะไรบ้าง
แนวคำตอบ

ข้อ 1

rg "PdaColors\.green|AppColors\.success" lib

ทางรวมที่เจ็บน้อยที่สุดคือทำให้ชื่อที่ผิดหายไป โดยไม่ต้องแก้จุดเรียก

// ขั้นที่ 1 — ทำเครื่องหมายว่าเลิกใช้
@Deprecated('Use AppColors.success — colours are named by role, not by hue')
static const green = AppColors.success;

ตัววิเคราะห์จะขีดเส้นใต้ทุกจุดที่ใช้ โดยที่โค้ดยังทำงานได้ปกติ

// ขั้นที่ 2 — ทยอยแก้ตามที่ตัววิเคราะห์ชี้
// ขั้นที่ 3 — ลบบรรทัดนั้นทิ้ง
@Deprecated คือเครื่องมือสำหรับการเปลี่ยนที่ทำไม่จบในครั้งเดียว
ต่างจากการลบทันทีตรงที่โค้ดไม่พังระหว่างทาง และต่างจากการปล่อยไว้ตรงที่มีแรงกดดันให้จบ
ใช้ได้กับทุกกรณีที่ 19.15 เรียกว่า “กฎเดียวเขียนสองแบบ” — เลือกแบบที่ถูก แล้วประกาศให้อีกแบบเป็นของเลิกใช้

ข้อ 2 — โหมดมืด

ต้องแก้รายละเอียด
AppColorsทุกค่าเป็น const ตายตัว ต้องมีชุดที่สอง
buildAppTheme()ต้องรับพารามิเตอร์ว่าสว่างหรือมืด
MaterialAppเพิ่ม darkTheme + themeMode
ทุกที่ที่เขียน AppColors.xxx ตรง ๆงานหนักที่สุด

ข้อสุดท้ายคือปัญหาจริง — โปรเจกต์นี้เรียก AppColors และ PdaColors โดยตรงเกือบทุกที่ ไม่ได้ผ่าน Theme.of(context).colorScheme

// แบบที่ใช้อยู่ — ค่าคงที่ ไม่รู้จักธีมปัจจุบัน
color: AppColors.heading

// แบบที่รองรับโหมดมืด — อ่านจากธีมที่กำลังใช้
color: Theme.of(context).colorScheme.onSurface
แต่ต้องถามก่อนว่าโหมดมืดคือคำตอบที่ถูกจริงหรือไม่
ปัญหาของกะกลางคืนในคลังคือจอสว่างจ้าแสบตา ซึ่งแก้ได้ด้วยการลดความสว่างของหน้าจอ
โหมดมืดแก้คนละปัญหา — มันช่วยเรื่องแบตเตอรี่กับความสบายตาในที่มืดสนิท ซึ่งคลังที่มีไฟส่องสว่างไม่ใช่
