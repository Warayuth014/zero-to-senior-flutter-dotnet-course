ไฟล์หลัก: lib/main.dart — startup ordering เป็นส่วนหนึ่งของ correctness เพราะ request แรกต้องเห็นภาษาและ active server ที่โหลดแล้ว

1. ทำไม main ต้องเป็น async

WidgetsFlutterBinding.ensureInitialized() ต้องมาก่อนเรียก plugin เช่น shared preferences และ system UI จากนั้น code รอ AppLanguageController.instance.load() กับ ConnectionController.instance.load() ก่อน runApp ผลคือเฟรมแรกไม่กระพริบจาก English/default server ไปเป็นค่าที่บันทึก และ request แรกไม่วิ่งไป localhost โดยบังเอิญ

2. Startup pipeline

WidgetsFlutterBinding.ensureInitialized()
await languageController.load()
await connectionController.load()
SystemChrome.setSystemUIOverlayStyle(...)
runApp(WmsApp(auth: AuthRepository(client: ApiClient())))

สอง load ปัจจุบันรันตามลำดับ ซึ่งอ่านง่ายและ deterministic หากจะใช้ Future.wait ต้องพิสูจน์ก่อนว่าไม่มี dependency ระหว่างกัน และยังต้องกำหนด failure policy ของแต่ละ future ให้ชัด

3. Fail-soft ไม่เท่ากับซ่อนทุก error

controller ภายในจับ failure ของ preferences เพื่อให้แอปยังใช้ค่า default ได้ นี่เหมาะกับ PDA ที่ต้องเปิดใช้งานต่อ แต่ควรส่ง diagnostic แบบไม่เปิดเผย secret ไป logger ด้วย มิฉะนั้น storage เสียจะดูเหมือนผู้ใช้ไม่เคยตั้งค่า การ catch ควรอยู่ใกล้ boundary ที่รู้ fallback ไม่ใช่ครอบ main ทั้งก้อนแล้วปล่อย state ครึ่งโหลด

4. Composition ที่รักษา session

WmsApp รับ AuthRepository ที่ประกอบจาก ApiClient เพียงครั้งเดียว ไม่สร้าง client ใน build เพราะ build เรียกซ้ำได้ เมื่อ login เขียน token ลง client แล้ว shell และ API adapters จึงใช้ transport instance เดิม การย้าย object นี้เข้า local variable ของ build จะทำให้ token หายเมื่อ rebuild

5. ภาษาเป็น reactive root

MaterialApp อยู่ใน ListenableBuilder ที่ฟัง language controller เมื่อ toggle ภาษา root จะ rebuild พร้อม locale/delegates ส่วน feature widgets เรียก tr(en, th) จึงได้ข้อความใหม่ใน build รอบเดียวกัน อย่าเก็บข้อความแปลแล้วไว้ใน field ที่ไม่ rebuild เพราะจะเกิดภาษาเก่าปะปน

6. Edge-to-edge และ status area

system status bar ถูกตั้ง transparent/สี icon ที่เหมาะสม และ MaterialApp.builder ห่อ child ด้วย AnnotatedRegion, แถบสีด้านบน และ SafeArea นี่ทำให้ login กับ shell ใช้นโยบาย platform chrome เดียวกัน ส่วน PdaStatusBar เป็น app bar ภายในแอป ไม่ใช่ system status bar—สองชั้นนี้มีหน้าที่คนละอย่าง

7. สิ่งที่ยังไม่มีใน bootstrap

  • restore token จาก secure storage และตรวจ expiration
  • global 401 handler หรือ refresh token
  • dependency container สำหรับสลับ fake/real implementations
  • startup error screen/telemetry เมื่อ initialization สำคัญล้มเหลว

การสังเกตว่า “ยังไม่มี” สำคัญพอ ๆ กับอ่านสิ่งที่มี อย่าอนุมานจากชื่อ AuthSession ว่า session ถูก persist แล้ว

8. ทดสอบ startup อย่างไร

แยกฟังก์ชัน bootstrap ที่ inject preference adapters ได้ แล้วทดสอบว่า (1) connection load เสร็จก่อนสร้าง request (2) storage ล้มเหลวใช้ default ได้ (3) language ที่บันทึกถูกเลือกตั้งแต่เฟรมแรก และ (4) rebuild ภาษาไม่สร้าง AuthRepository/ApiClient ใหม่
