ไฟล์หลัก: lib/features/warehouse/ui/user_chip_menu.dart, lib/widgets/pda_status_bar.dart, test/user_menu_test.dart — ปิด Part 20 ด้วยการ trace state จาก controllerไปสู่ UIและ tests

1. เมนูเดียวทั้ง shell

UserChipMenu ถูกวางใน headerของ WarehouseShell จุดเดียว ทุก operational screenจึงได้ user/connection/language/logout actionsเหมือนกันโดยไม่ copy widgetหรือ callback การรวมไว้ shellยังทำให้ session actionไม่ตกเป็นเจ้าของ feature screenใด screenหนึ่ง

2. Reactive connection chip

widget ใช้ ListenableBuilder ฟัง ConnectionController.instance แล้วอ่าน active profile nameกับ status สี dotมาจาก mapping unknown/connecting/connected/disconnected ไม่ใช่ hard-coded green เมื่อ probe notify chipจึงเปลี่ยนโดยไม่ต้องให้ WarehouseStoreรู้ connection state

3. จำกัดข้อมูลบน header

pillแสดง username, profile nameที่จำกัด 78pxและ ellipsis พร้อม status dot แต่ไม่แสดง IPเพราะจอ 390pxต้องเหลือพื้นที่ title/action ที่อยู่เต็มแสดงใน popup summaryหนึ่ง tapถัดไป นี่คือ progressive disclosure: ข้อมูลสำคัญทันทีสั้น ข้อมูลวินิจฉัยเต็มอยู่ใกล้มือ

4. Popup semantics

PopupMenuButton เปิดใต้ chipและใช้ Flutter barrierปิดเมื่อแตะข้างนอก header summaryเป็น item disabled แล้วมี User Info, Connection Settings, Language และ Sign Out แต่ละ itemสูงอย่างน้อย PdaMetrics.minTapTarget ส่วน logoutใช้สีแดงเพื่อแยก destructive session action

5. Action routing

UserMenuAction.profile    → User Info dialog
UserMenuAction.connection → Connection Settings sheet
UserMenuAction.language   → languageController.toggle()
UserMenuAction.logout     → confirmation → auth.logout → LoginScreen

menuรายงาน enumกลับ shell แทนทำ side effectเอง ทำให้ presentation componentทดสอบได้และ shellเป็นผู้ถือ context/session dependencies

6. User Info เป็น live dialog

dialogแสดง username, expiration และ active connection พร้อมปุ่มตรวจใหม่ เนื้อหาฟัง ConnectionController จึงอัปเดตผล probeใน dialogเดิม ไม่ต้องปิดเปิดใหม่ สิ่งนี้แสดง patternให้ modalที่มี async state: ownerอยู่นอก dialogและ dialog render snapshotล่าสุด

7. Tests ที่ล็อก invariant

user_menu_test.dart ยืนยันชื่อผู้ใช้/profileแสดงแต่ IPไม่กิน header, popupมีสี่ actionsและแสดง addressเต็ม, selectionส่ง enumแล้วปิด, tap outsideไม่เลือก, dotตามทุก controller statusด้วยสีที่ต่างกัน และ no-profileไม่ crash ส่วน settings testsครอบคลุม transactional editorจากบทก่อน

8. Part 20 capstone

Trace จากเปิดแอปจน logoutพร้อมหลักฐานไฟล์: startup load → effective URL → login contract → session/token → shell composition → connection resume probe → user menu/settings → profile switch policy → cleanup เขียนเพิ่มหนึ่ง integration testที่ loginด้วย fake transport, เข้า shell, เปลี่ยน statusทุกค่า, เปิดเมนู และ logoutโดยยืนยันว่า tokenกับ store lifecycleถูกล้างครบ
