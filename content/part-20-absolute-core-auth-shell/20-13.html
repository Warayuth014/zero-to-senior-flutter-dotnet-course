ไฟล์หลัก: lib/features/settings/connection_settings_sheet.dart และ widget tests — bottom sheet นี้เป็น transactional editor ไม่ใช่ form ที่แก้ global stateทุกครั้งที่พิมพ์

1. Route-level bottom sheet

showConnectionSettings(context) เปิด modal bottom sheetเหนือ Scaffold จึงไม่บีบ body/bottom navigation และใช้ scroll/insetsรับ keyboardบนจอ 390×844 ได้ การวาง panelไว้ใน bodyจะเปลี่ยน layoutทั้ง shellและสร้าง overflowตอน keyboardเปิด

2. Draft state แยกจาก controller

TextEditingControllers, editing ID, environment/protocol และ validation stateอยู่ใน sheet ระหว่างพิมพ์ ConnectionController.active ยังไม่เปลี่ยน จนกด save/apply จึง commit ช่วยให้ Cancel/Discardทำงานจริงและ requestปัจจุบันไม่สลับ hostทุก keystroke

3. Live preview ไม่ใช่ effective URL เสมอ

draftถูกประกอบเป็น URL previewทันทีให้เห็น protocol/host/port/basePath แต่ถ้า build pin WMS_API_BASE_URL ต้องแสดงข้อจำกัดว่า requestจริงใช้ override มิฉะนั้นผู้ใช้จะเชื่อ previewผิด การแยก “draft URL”, “saved active URL” และ “effective URL” เป็นสาม labelช่วยลดความสับสน

4. Test ก่อน Save

validate fields
→ build draft profile
→ probeConnection(draft.baseUrl)
→ render result/latency
→ ยังไม่เปลี่ยน active profile

direct probeทำให้ตรวจเครื่องใหม่ได้ปลอดภัย และผลต้องผูกกับ snapshotของ draftตอนกด หากผู้ใช้แก้ fieldหลังผลสำเร็จควรทำให้ผลเก่ากลายเป็น stale/ถูกล้าง

5. Command ต่างความหมาย

  • Save Changes: แก้ profileเดิมในที่เดิม
  • Save as Profile: เพิ่มรายการใหม่โดยไม่แย่ง active
  • Save & Use: validate/save แล้ว activate
  • Duplicate: ทำ draftใหม่จากค่าปัจจุบันและแก้ชื่อซ้ำ
  • Delete: ห้ามตัวสุดท้าย; activeต้องเลือกตัวรับช่วง

6. Unsaved-change guard

sheetเก็บ snapshotหลัง load/reset แล้วเทียบกับค่าปัจจุบัน เมื่อกด close/drag/backพร้อมการแก้ไขจึงถาม Discard หาก untouchedปิดทันที Guardต้องครอบทุก exit path ไม่ใช่เฉพาะปุ่ม X และหลัง saveสำเร็จต้องอัปเดต baseline ไม่ให้ถามทั้งที่ไม่มีงานค้าง

7. Tests ที่ยืนยัน UX contract

connection_settings_sheet_test.dart ตรวจ active profile/preview, live typing, overlayไม่ดัน bottom nav, invalid inline errors, schemeใน hostถูกปฏิเสธ, edit in place, newไม่ activate, discard guard, delete invariants และ keyboard layout นี่คือตัวอย่าง test behaviorแทน test private method

8. Production hardening

เพิ่ม generationกัน stale probe, แสดง persistence failure, invalidate sessionเมื่อ Save & Useข้าม server, block duplicate actionระหว่าง busy, redact credentialใน URLถ้าอนาคตรองรับ และเขียน widget testสำหรับ build-pinned URL, rapid test, storage failureกับ system back gesture
