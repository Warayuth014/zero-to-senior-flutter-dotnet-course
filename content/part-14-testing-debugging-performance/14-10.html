pumpAndSettle ไม่ใช่ยาวิเศษ: มัน pump จนไม่มี scheduled frame ถ้ามี spinner/timer/animation วนไม่สิ้นสุด test จะ timeout และอาจซ่อนจำนวน frame ที่ผิดปกติ

1. pump แบบตั้งใจ

await tester.tap(button);
await tester.pump(); // เริ่ม animation/state
expect(find.byType(CircularProgressIndicator), findsOneWidget);
response.complete(result);
await tester.pump(); // apply future result

ควบคุม frame ทำให้ทดสอบ intermediate state ได้

2. เมื่อไรใช้ pumpAndSettle

เหมาะหลัง Navigator push/pop, dialog/sheet transition หรือ finite animation ที่เราต้องการ final UI ตัวอย่าง flow จริงใช้หลังเปิด scanner dialogและ submit แล้วรอทุก transition จบ

3. Infinite animation

CircularProgressIndicator, repeating controller หรือ polling อาจ schedule frame ต่อเนื่อง ให้ complete fake future ก่อน settle หรือ pump duration ที่ต้องการแล้ว assert loading โดยไม่ settle

4. จำนวน pumps เป็นสัญญาณ

final frames = await tester.pumpAndSettle();
expect(frames, lessThan(10));

ใช้เมื่อจำนวน transition เป็น contract เชิง performance จริง มิฉะนั้น exact count เปราะตาม theme/platform

5. AnimationController lifecycle

test unmount ขณะ animation ทำงานแล้ว pump ต่อ ตรวจไม่มี ticker leak/setState() called after dispose และ controller ถูก dispose ใช้ addTearDown กับ controller ที่ test เป็นผู้สร้าง

6. Reduced motion

ถ้าแอปรองรับ accessibility animation disabled ให้ทดสอบทั้ง normal และ disableAnimations โดย behavior/route result เหมือนกัน ไม่ผูก action กับ animation completion อย่างเดียว

7. Time budget

pump(const Duration(seconds: 5)) ขยับ fake time ไม่ได้ sleep จริง จึงใช้ทดสอบ timeout/debounce ได้เร็ว แต่ async I/O ที่อยู่นอก fake clock ยังต้องควบคุมด้วย Completer/fake scheduler

8. Debug เมื่อ settle timeout

หา ticker/timer ที่ยังทำงาน, future ที่ fake ไม่ complete, animation repeat และ pending route; เปลี่ยนเป็น pump ทีละช่วงพร้อม assert แทนการเพิ่ม timeout แบบเดาสุ่ม
