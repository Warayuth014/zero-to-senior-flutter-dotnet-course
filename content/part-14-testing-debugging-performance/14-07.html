pumpWidget สร้างโลกของ test: ห่อ widget ด้วย MaterialApp, theme, localization และ dependencies เท่าที่ production screen ต้องใช้ แต่ไม่จำเป็นต้องเปิดทั้งแอปทุก test

1. Minimal harness

Future<void> pumpScreen(
  WidgetTester tester, Widget child,
) => tester.pumpWidget(
  MaterialApp(home: Scaffold(body: child)),
);

MaterialApp ให้ Navigator/Theme/MediaQuery ส่วน Scaffold ให้ snackbar/sheet context หาก test ล้มเพราะ provider หาย ให้ inject fake ตาม composition ของ screen

2. pump คือ frame เดียว

pumpWidget attach tree แล้ว schedule frame; pump() เดินอีก frame/microtask; pump(duration) ขยับ fake clock ตามเวลา อย่าสมมติว่า async/animation ทั้งหมดเสร็จหลัง pump ครั้งเดียว

3. กำหนด viewport PDA

tester.view.devicePixelRatio = 1;
tester.view.physicalSize = const Size(390, 560);
addTearDown(tester.view.reset);

scanner_layout_test.dart ใช้วิธีนี้พิสูจน์ scan input อยู่กับที่เมื่อรายการ scroll ต้อง reset view ไม่ให้ test ถัดไปปน

4. Inject fake ก่อน pump

final repo = FakeReceivingRepository(openOrders: [order]);
final store = createTestStore(receivingRepository: repo);
addTearDown(store.dispose);
await tester.pumpWidget(
  MaterialApp(home: ReceiveView(store: store)),
);

5. Async initialization

ถ้า screen load ใน initState ให้ pump ครั้งแรกแล้ว assert loading จากนั้น complete fake future และ pump อีกครั้งเพื่อ assert data การใช้ fake ที่คืนทันทีอย่างเดียวจะไม่พิสูจน์ loading state

6. Exceptions

expect(tester.takeException(), isNull);

ใช้หลัง layout/interaction เพื่อจับ overflow หรือ setState-after-dispose แต่หากคาด exception ให้ดึงและ assert ทันที ไม่ปล่อย exception ค้างไปทำ test framework fail แบบหาเหตุยาก

7. Unmount ก่อน dispose

await tester.pumpWidget(const SizedBox.shrink());
store.dispose();

เหมาะเมื่อ widget ยัง listen store อยู่ ให้ tree ถอด listener ก่อน dispose หรือให้ test harness เป็น owner lifecycle แบบเดียวกับ production

8. Test scope

หนึ่ง widget test ควรพิสูจน์ behavior เด่น 1 เรื่อง ใช้ helper ลด setup แต่เก็บ intent ไว้ใน test และไม่ pump app ทั้งระบบหาก screen เดี่ยวให้คำตอบได้
