ห้ามใช้เวลาจริงเป็น synchronization: Future.delayed และ sleep ทำ suite ช้า/flaky ให้ inject scheduler หรือใช้ fake async/WidgetTester clock เพื่อเดินเวลาอย่าง deterministic

1. Timer ใน codebase

WarehouseStore มี Timer.periodic สำหรับ refresh tasks และ animation บางหน้ามี timer ทุกวินาที ทั้งคู่ต้อง cancel ตอน dispose และไม่ควรเริ่มโดยหลบอยู่ใน constructor หาก test ต้องควบคุม lifecycle

2. Inject periodic scheduler

typedef StartPeriodic = Cancelable Function(
  Duration interval, void Function() tick,
);

class Poller {
  Poller(this.startPeriodic);
  final StartPeriodic startPeriodic;
}

production adapter ใช้ Timer; fake เก็บ callback แล้วให้ test เรียก tick เอง

3. fake_async

fakeAsync((async) {
  var ticks = 0;
  final timer = Timer.periodic(const Duration(seconds: 5), (_) => ticks++);
  async.elapse(const Duration(seconds: 12));
  expect(ticks, 2);
  timer.cancel();
});

4. Widget timer

ใน widget test ใช้ tester.pump(Duration) เดิน test binding clock แล้ว assert countdown/state; unmount ก่อนหมดเวลาและ pump ต่อเพื่อพิสูจน์ callback ไม่แตะ State ที่ dispose แล้ว

5. Debounce

พิมพ์ query A, เดินเวลาไม่ถึง threshold, พิมพ์ B, เดินจนถึง threshold แล้ว assert repository ถูกเรียกครั้งเดียวด้วย B ต้อง cancel timer เก่าและไม่อาศัย wall clock

6. Concurrent async

ใช้ Completer คุมลำดับ response ไม่ใช้ delay จำลอง race: B เสร็จก่อน A, dispose ก่อน response, cancel ระหว่าง operation และ event มาระหว่าง refresh แต่ละ scenario ควรจบโดยไม่มี pending future

7. Microtask กับ timer

await Future.delayed(Duration.zero) ขยับ event queue แต่ไม่ใช่คำตอบทั่วไป แยกว่ารอ notification microtask, timer หรือ frame แล้วใช้ pump/flushMicrotasks/Completer ให้ตรงชนิด

8. Leak test

start → tick → stop/dispose → tick/advance อีกครั้ง แล้ว assert ไม่มี repository call/notification เพิ่ม รวมถึง restart ไม่สร้าง timer ซ้อนและ app lifecycle pause หยุด polling ตาม policy
