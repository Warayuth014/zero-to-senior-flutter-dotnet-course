Store/ViewModel: ownerของ screen/feature stateและ actions ใช้ ChangeNotifier เพื่อประกาศการเปลี่ยน แต่ state transitionต้องถูกต้องแม้ไม่มี widget

1. State object

class ReceivingState {
  const ReceivingState({this.order, this.loading = false, this.error});
  final InboundOrder? order;
  final bool loading;
  final Failure? error;
  ReceivingState copyWith(/* fields */) => /* immutable copy */;
}

2. Action

Future<void> loadOrder(String code) async {
  final request = ++_generation;
  _set(state.copyWith(loading: true, error: null));
  try {
    final order = await repository.findOrder(code);
    if (request != _generation) return;
    _set(ReceivingState(order: order));
  } on Failure catch (e) {
    if (request == _generation) _set(ReceivingState(error: e));
  }
}

3. Notify once per meaningful transition

ใช้ private _set เปลี่ยน state+notify ไม่ expose mutable listให้ widgetแก้ และ batch synchronous mutationsก่อน notifyเพื่อลด intermediate invalid states

4. Lifecycle

Storeที่สร้าง Timer/listenerต้อง dispose/cancel; owner route/shellเป็นผู้ disposeตาม lifetime ห้าม singleton storeถือ transient flowตลอดแอปโดยไม่ reset

5. UI effects

หลีกเลี่ยง callback onToast ฝังใน Storeถ้าทำให้ test/lifetimeซับซ้อน ใช้ typed effect queue/operation resultหรือ UI map stateเป็น feedbackตาม architectureทีม

6. Selective rebuild

แยก storesหรือใช้ selectors/listenableเฉพาะส่วนเมื่อ stateใหญ่ ไม่แก้ performanceด้วยการหยุด notifyจน UI stale

7. แบบฝึกหัด

load Aแล้ว load B, response Aกลับหลัง B ต้องแสดงอะไร?

เฉลย

แสดง B; generation tokenของ Aไม่ตรงจึง ignore และไม่ overwrite loading/errorของ B

8. Store tests

assert state sequence loading→ready/error, duplicate guard, stale response, dispose timer และ repository commandโดยไม่ pump widget
