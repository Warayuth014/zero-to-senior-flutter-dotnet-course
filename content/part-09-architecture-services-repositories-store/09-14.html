4. ลำดับที่ปลอดภัย

กฎเหล็ก: เขียนเทสต์ที่คุมพฤติกรรมปัจจุบันให้ได้ก่อน แล้วค่อยขยับโค้ด ไม่มีเทสต์ = ไม่ใช่ refactor แต่คือการเขียนใหม่แล้วหวังว่าจะเหมือนเดิม
ขั้นทำอะไรเสี่ยงแค่ไหน
1เขียนเทสต์ครอบเส้นทางหลักที่ผู้ใช้ทำจริงไม่แตะโค้ดเดิม
2ย้ายเมธอด Widget _xxx() ที่ไม่ใช้ตัวแปรของ State ออกเป็น StatelessWidgetต่ำมาก คอมไพเลอร์ฟ้องถ้าย้ายผิด
3ย้ายเมธอดที่ใช้ตัวแปร โดยส่งค่าเข้าไปเป็นพารามิเตอร์ต่ำ แต่ต้องดูว่าส่งของถูกตัว
4ยกตรรกะที่ไม่เกี่ยวกับการวาดออกไป storeกลาง
5แยกไฟล์ต่ำ เป็นแค่การย้ายที่อยู่

ขั้นที่ 2 คือขั้นที่ให้ผลมากที่สุดต่อความเสี่ยง เพราะเมธอดวาดส่วนใหญ่ในจอใหญ่ ๆ ไม่ได้แตะสถานะเลย

7. กับดักตอนแยก

กับดักอาการทางแก้
แยกแล้วต้องส่งพารามิเตอร์ 12 ตัวชิ้นนั้นไม่ได้เป็นก้อนเดียวกันจริงแบ่งเส้นใหม่ หรือส่ง store เข้าไปแทนค่าดิบ
widget ลูกเรียก setState ของแม่ผ่าน callback หลายชั้นสถานะอยู่ผิดที่ยกสถานะขึ้นไป store (9.9)
แยกแล้วแต่ยังต้องเปิดสองไฟล์คู่กันเสมอตัดผิดที่รวมกลับ แล้วตัดใหม่
สร้าง widgets/common_widgets.dart รวมทุกอย่างย้ายปัญหา ไม่ได้แก้ไฟล์ละ widget หรือละกลุ่มที่เกี่ยวกันจริง

กับดักที่สี่เกิดขึ้นจริงใน wmsapp — lib/widgets/common_widgets.dart มีขนาด 20KB ซึ่งเป็นไฟล์ที่ทุกจอต้อง import และทุกคนต้องแก้

8. แล้วจอที่ยังไม่มีเทสต์ล่ะ

นี่คือสถานการณ์จริงของทั้งสองโปรเจกต์ ทางออกที่ใช้ได้คือ

  1. เขียนเทสต์ครอบเฉพาะเส้นทางที่จะแตะ ไม่ต้องครอบทั้งจอ
  2. ถ้าจอทดสอบไม่ได้เลยเพราะหยิบ ApiService() เอง ให้ทำขั้นที่เล็กที่สุดก่อน คือเปลี่ยนให้รับเข้ามาทาง constructor พร้อมค่าเริ่มต้น
class PackingScreen extends StatefulWidget {
  const PackingScreen({super.key, ApiService? api}) : _api = api;
  final ApiService? _api;
}

// ใน State
late final _api = widget._api ?? ApiService();

โค้ดที่เรียกใช้จริงทั้งหมดไม่ต้องแก้เลย แต่เทสต์ส่งของปลอมเข้าไปได้ทันที นี่เป็นก้าวเล็กที่สุดที่เปิดทางให้ก้าวถัดไป

ก้าวนี้ยังไม่สวย เพราะจอยังรู้จัก ApiService อยู่ แต่มันปลอดภัยพอที่จะทำในวันที่มีงานอื่นรออยู่ — และปลอดภัยกว่าการรื้อทั้งจอในครั้งเดียว

9. แบบฝึกหัด

เปิด ops_views.dart ดูเมธอด _conveyorTile (บรรทัด 264 เป็นต้นไป ยาวราว 205 บรรทัด) แล้วตอบ

  1. มันใช้ตัวแปรของ State ตัวไหนบ้าง
  2. แยกเป็น StatelessWidget ได้ทันทีไหม ถ้าไม่ ต้องทำอะไรก่อน
แนวคำตอบ

ขั้นตอนที่ควรทำคือไล่หา _ ทุกตัวในเมธอดนั้น ตัวไหนเป็นตัวแปรของ State ตัวไหนเป็นพารามิเตอร์

  • ถ้าใช้แค่พารามิเตอร์ที่ส่งเข้ามา — แยกได้ทันที เป็นการคัดลอกวางแล้วเปลี่ยนพารามิเตอร์เป็นฟิลด์
  • ถ้าใช้ _conveyor3Selected หรือ setState — ต้องตัดสินใจก่อนว่าสถานะนั้นควรอยู่ที่ไหน ถ้ามีแค่จอนี้ใช้และหายได้เมื่อปิดจอ ให้ส่งค่าเข้าไปพร้อม callback ถ้าฟีเจอร์อื่นต้องรู้ด้วย ให้ยกขึ้น WarehouseStore
  • ถ้าใช้ context.watch หรืออ่าน store โดยตรง — แยกได้ เพราะ store เข้าถึงได้จากทุกที่ในต้นไม้

คำตอบที่ถูกที่สุดสำหรับไฟล์นี้: อย่าเพิ่งแยก ให้เขียนเทสต์ของเส้นทาง “เลือกสายพาน → สแกนพาเลท → ยืนยัน” ให้ผ่านก่อน แล้วค่อยขยับ เพราะการรื้อ 205 บรรทัดที่ไม่มีเทสต์คุม แลกความเสี่ยงกับความสวยที่ผู้ใช้ไม่เห็น

10. สรุป
