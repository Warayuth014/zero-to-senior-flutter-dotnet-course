Repository interface ใช้ภาษาของ caller: ซ่อนว่า dataมาจาก HTTP/cacheและคืน domain result ไม่ expose URL, responseหรือ JSON

1. Interface example

abstract interface class ReceivingRepository {
  Future<InboundOrder> findOrder(String orderNo);
  Future<Receipt> receive(ReceiveCommand command);
  Future<List<PendingPalletLine>> pendingPalletLines();
}

2. Naming by intent

receive(command) ดีกว่า postScanPart(map) เพราะ callerไม่ต้องรู้ transportและ interfaceยังคงเดิมเมื่อ endpointเปลี่ยน

3. Contract boundary

กำหนด nullability, ordering, paginationและ failuresใน interface/docs เช่น not-foundเป็น nullหรือ typed exception ต้องเลือกแบบเดียว ไม่คืน nullสำหรับ offlineด้วย

4. Interface ไม่ต้องมีทุก class

สร้างเมื่อมี consumerต้องการ abstraction, fake, remote/local variantsหรือ boundaryทีม ไม่สร้าง IThing ที่มี implementationเดียวและไม่มี test seamเพียงตามพิธี

5. Narrow interfaces

Store รับเฉพาะ repositoryของ feature ไม่รับ GodRepository 50 methods ทำ dependencyชัดและ fakeเล็ก ใช้ Interface Segregationตาม use casesจริง

6. ของจริง

TasksRepository, ReceivingRepository, InventoryRepository และ CycleCountRepository ใน wms_absolute_mobile ทำให้ WarehouseStoreไม่ import package http

7. แบบฝึกหัด

repositoryควรมี method Future<http.Response> getTasks() ไหม?

เฉลย

ไม่ เพราะรั่ว infrastructure type ให้คืน List<WmsTask> หรือ TaskPage และ translate failure

8. Testability

Fake repositoryเก็บ commandsและกำหนด result/failureได้ ทำให้ Store testsพิสูจน์ workflowโดยไม่มี JSON/network
