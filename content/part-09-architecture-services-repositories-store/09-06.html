จบบทนี้แล้วจะทำได้: เขียนตัวจริงที่ทำตามสัญญา และทดสอบมันได้โดยไม่ต้องมีเซิร์ฟเวอร์

1. หน้าที่สามอย่างของตัวจริง

หน้าที่ทำอะไร
เรียก endpointแปลง argument เป็น path และ body
อ่านคำตอบเป็นโมเดลแปลง JSON เป็น Pallet
แปลความล้มเหลวแปลง ApiException เป็น PalletFailure

สามอย่างนี้อยู่ด้วยกันเพราะเปลี่ยนด้วยเหตุผลเดียวกัน คือ “สัญญากับเซิร์ฟเวอร์เปลี่ยน”

2. รับ interface เข้ามา ไม่ใช่คลาสจริง

class RemotePalletRepository implements PalletRepository {
  const RemotePalletRepository(this.api);

  final JsonApi api;      // ← ไม่ใช่ ApiClient
  ...
}

JsonApi เป็น interface เล็ก ๆ ที่มีแค่ getJson กับ postJson ส่วน ApiClient เป็นตัวจริงที่ implement มัน การรับ interface ทำให้เทสต์ระดับนี้ใส่ตัวปลอมได้โดยไม่ต้องมี baseUrl หรือ http.Client

หลัก: รับสิ่งที่แคบที่สุดที่ยังทำงานได้ — ถ้าใช้แค่สองเมธอด อย่ารับทั้งคลาสที่มีสิบเมธอด

3. เส้นทางที่สำเร็จ

@override
Future<List<Pallet>> fetchInZone(String zone) async {
  final Map<String, dynamic> json;
  try {
    json = await api.getJson(
      '/api/WMS/mobile_pallets?zone=${Uri.encodeQueryComponent(zone)}',
    );
  } on ApiException catch (error) {
    throw _translate(error);
  }

  // อ่านคำตอบอยู่นอก try โดยตั้งใจ (8.2)
  final items = requireList(json, 'items');
  return [
    for (var index = 0; index < items.length; index++)
      _readPallet(items[index], 'items[$index]'),
  ];
}
บรรทัดเหตุผล
Uri.encodeQueryComponent(zone)โซนอาจมีช่องว่างหรืออักษรพิเศษ ถ้าไม่ encode จะได้ URL ที่ผิด
final Map json; ประกาศไว้ก่อนเพื่อให้ try ครอบเฉพาะบรรทัดที่ยิงเน็ต ไม่ครอบการอ่านคำตอบ
'items[$index]'ถ้าแถวที่ 7 พัง ข้อความผิดพลาดจะบอกว่าแถวไหน ไม่ใช่แค่ “พัง”

4. ทำไม try ต้องแคบ

นี่คือกฎเดียวกับ 8.2 แต่ครั้งนี้เห็นผลชัดกว่า ลองคิดว่าถ้าเขียนแบบนี้

// อย่าเขียนแบบนี้
try {
  final json = await api.getJson('...');
  final items = requireList(json, 'items');        // ← อยู่ใน try
  return [...];
} on ApiException catch (error) {
  throw _translate(error);
}

ผลคือ ถ้าเซิร์ฟเวอร์ส่ง items ผิดรูป ContractException จะไม่ถูกจับ (เพราะจับแค่ ApiException) — ดูเหมือนไม่มีปัญหา แต่วันที่มีคนเปลี่ยนเป็น catch (error) เพื่อ “กันไว้ก่อน” ข้อผิดพลาดของสัญญาจะกลายเป็นข้อความว่า “เชื่อมต่อไม่ได้ ลองใหม่” แล้วผู้ใช้จะกดลองใหม่ทั้งวัน

เทสต์ในข้อนี้บังคับพฤติกรรมไว้แล้ว

test('ข้อมูลผิดสัญญาต้องโยน ContractException พร้อมตำแหน่ง', () async {
  ... palletJson('PLT-002')..['quantity'] = 1.5,   // 1.5 ชิ้นไม่มีอยู่จริง
  await expectLater(
    repository.fetchInZone('A1'),
    throwsA(isA<ContractException>()
        .having((e) => e.path, 'path', 'items[1].quantity')),
  );
});

5. อ่านโมเดลผ่านตัวอ่านกลาง

Pallet _readPallet(Object? value, String path) {
  final map = requireMap(value, path);
  return Pallet(
    code: requireString(map, 'code', path: path),
    productCode: requireString(map, 'productCode', path: path),
    quantity: requireInt(map, 'quantity', path: path),
    onHold: readBool(map, 'onHold', path: path, orElse: false),
  );
}

ทุกตัวมาจาก json_basics/json_read.dart ที่เขียนไว้ตั้งแต่ Part 6 กฎการแปลงค่าจึงเหมือนกันทั้งแอปโดยอัตโนมัติ

ข้อสังเกต: ตอน Part 6 ไฟล์นั้นยังไม่มี readBool เลย เพราะยังไม่มีใครต้องอ่านค่าจริงเท็จ พอถึงบทนี้ที่ต้องใช้จริงจึงค่อยเพิ่ม — เพิ่มตอนมีคนใช้ ไม่ใช่เพิ่มเผื่อ

readBool บังคับให้ระบุ orElse เสมอ เพื่อให้คนเขียนต้องตอบว่า “ไม่มีค่า” แปลว่าอะไร แทนที่จะได้ false มาโดยไม่ได้ตั้งใจ

6. เทสต์โดยไม่มีเซิร์ฟเวอร์

final repository = RemotePalletRepository(
  ApiClient(
    baseUrl: baseUrl,
    client: MockClient((_) async => http.Response(
      jsonEncode({'detail': 'พาเลทนี้ถูกล็อกโดยสมชายอยู่'}),
      409,
      headers: {'content-type': 'application/json; charset=utf-8'},
    )),
  ),
);

เทสต์ระดับนี้ยังผ่าน ApiClient ตัวจริง เพราะอยากทดสอบด้วยว่ามันแปลง 409 เป็น ApiFailureKind.conflict ถูกไหม ถ้าอยากทดสอบเฉพาะ repository ล้วน ๆ ก็ใส่ JsonApi ปลอมแทนได้ — เลือกได้เพราะรับ interface ไว้

7. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
ผู้ใช้เห็น “เชื่อมต่อไม่ได้” ทั้งที่เน็ตดีtry กว้างเกิน ครอบการอ่านคำตอบด้วยย้ายการอ่านออกนอก try
ข้อความผิดพลาดบอกแค่ว่าพัง ไม่บอกว่าตรงไหนไม่ส่ง path ต่อลงไปส่ง 'items[$index]' ทุกชั้น
repository คืน Map<String, dynamic>เลื่อนการแปลงไปให้ store ทำแปลงให้เสร็จที่นี่ ชั้นบนต้องเห็นแต่โมเดล
repository เก็บผลลัพธ์ล่าสุดไว้ใน fieldสับสนระหว่างหน้าที่ของ repository กับ storeให้ store เป็นคนเก็บ (9.9)

8. แบบฝึกหัด

เซิร์ฟเวอร์เพิ่มฟิลด์ lastCountedAt ในพาเลท เป็นเวลาแบบ ISO และอาจไม่มีถ้ายังไม่เคยนับ

  1. ต้องแก้ไฟล์ไหนบ้าง
  2. ถ้าเซิร์ฟเวอร์ส่ง "2026-08-16T10:00:00" มา (ไม่มี Z) ควรเกิดอะไรขึ้น
แนวคำตอบ

1. สองไฟล์ คือ pallet.dart เพิ่มฟิลด์ DateTime? lastCountedAt และ pallet_repository.dart อ่านค่า ส่วน store ไม่ต้องแก้ และจอแก้เฉพาะถ้าจะแสดงผล

ต้องเพิ่มตัวอ่านด้วย เพราะ requireUtcTime ที่มีอยู่บังคับว่าต้องมีค่า จึงต้องมีคู่แฝดที่ยอมให้ไม่มีได้ ทำนองเดียวกับ requireString/readString

2. ต้องโยน ContractException ตามที่ 6.9 ตัดสินใจไว้ — เวลาที่ไม่บอกเขตเวลาตีความไม่ได้ และการเดาว่าเป็นเวลาไทยจะทำให้รายงานผิดชั่วโมง ไม่ใช่ผิดนิดหน่อย

คำถามที่ควรถามต่อคือ “แล้วผู้ใช้จะเห็นอะไร” คำตอบคือจอพัง ซึ่งฟังดูแย่ แต่ถูกกว่าการแสดงเวลาที่ผิดเงียบ ๆ — และมันบังคับให้ทีมแก้ที่ต้นเหตุ ไม่ใช่ให้ผู้ใช้ทนใช้ข้อมูลผิด

9. สรุป

  • ตัวจริงทำสามอย่าง คือเรียก แปลงเป็นโมเดล และแปลความล้มเหลว
  • รับ interface ที่แคบที่สุดเข้ามา ไม่ใช่คลาสจริง
  • try ครอบเฉพาะบรรทัดที่ยิงเน็ต การอ่านคำตอบต้องอยู่ข้างนอก
  • ส่ง path ลงไปทุกชั้น เพื่อให้ข้อความผิดพลาดบอกตำแหน่งได้
