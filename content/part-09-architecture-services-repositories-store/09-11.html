Feature-first: เก็บ UI, state, domainและ dataของ workflowเดียวกันใกล้กัน เพื่อลดการเดินข้ามโฟลเดอร์ global screens/services/modelsเมื่อแก้ feature

1. Example tree

lib/
  core/                 # api client, auth, config
  features/receiving/
    data/               # DTO, remote source, repository impl
    domain/             # entities, repository contract
    application/        # store/state/effects
    presentation/       # screens/widgets
  features/tasks/...

2. Shared threshold

อย่าย้ายของเข้า commonตั้งแต่ใช้ครั้งแรก รอให้มี reuseจริงและ semanticsเดียวกัน เช่น ErrorPanel genericได้ แต่ ReceivingQuantityCardอาจไม่ควร generic

3. Public surface

แต่ละ featureมี barrel/public exportsเท่าที่ consumerต้องใช้และเก็บ DTO/helpers private ลด accidental couplingข้าม feature

4. Cross-feature coordination

Shell/application coordinatorเรียก narrow interfacesหรือ shared domain events ไม่ให้ ReceivingStore import WarehouseScreen internals

5. ของจริงสองแบบ

wmsapp แยก top-level screens/services/modelsแล้วมี subfoldersตาม flow; wms_absolute_mobile รวม warehouse featureแต่ APIอยู่ top-level ขั้น refactorคือย้ายทีละ vertical sliceโดยคง importsชั่วคราว

6. Tests colocated conceptually

mirror feature treeใน test/features/receiving/... และ fixtureอยู่กับ data tests ทำ ownershipหาได้ง่าย

7. แบบฝึกหัด

StationInfo ใช้เฉพาะ putaway screenควรอยู่ core/modelsไหม?

เฉลย

อยู่ feature putaway presentation/domainตามความหมาย จนมี consumerอื่นที่ใช้ conceptเดียวกันจริง

8. Migration rule

ย้ายตาม featureที่กำลังแก้, ใช้ forwarding exportชั่วคราว, testsผ่านทุก stepและไม่ทำ big-bang folder rewrite
