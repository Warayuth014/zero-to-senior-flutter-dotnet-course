1. Acceptance criteria

  • Screenไม่มี HTTP/JSON/storage
  • repository interfaceใช้ domain language
  • remote implementation map DTO/failure
  • Storeมี immutable stateและ generation guard
  • dependenciesเข้าทาง constructor
  • characterization + repository + store + widget testsผ่าน

3. Repository contract

abstract interface class ReceivingRepository {
  Future<InboundOrder> findOrder(String orderNo);
  Future<Receipt> receive(ReceiveCommand command);

ใช้ fakeตัวนี้เขียน Store testsก่อนย้าย HTTP

4. State sequence tests

  • load: idle→loading→ready
  • not found/network/contract errorแยกกัน
  • scan Aแล้ว B: A responseเก่าถูก ignore
  • submitซ้ำถูก guard
  • successอัปเดต SSOT/typed effectครั้งเดียว

5. Repository tests

ใช้ fake JsonClient assert path/query/body, fixturesสำหรับ casing/null, map domainและ error code PALLET_ALREADY_ASSIGNED โดยไม่มี Flutter binding

6. Widget tests

inject fake Store/repository, submit barcode, verify loading/empty/error/success, focusและ dialog result โดยไม่เปิด server; screenshotเดิมช่วยตรวจว่า refactorไม่เปลี่ยน UI

7. Migration sequence

  1. ล็อก behaviorเดิม
  2. สร้าง interface+fake
  3. ย้าย remote mapping
  4. ย้าย action/state
  5. extract widgets
  6. ลบ codeซ้ำและ forwarding facade
