สามชั้นที่ใช้จริง: UI แสดง state/ส่ง intent, logic คุม workflow, data layer อ่านเขียนข้อมูลและแปลง contract

1. UI layer

Widget อ่าน immutable ViewState, เรียก action เช่น store.scan(code), จัด focus/navigation/dialog ตาม effect และไม่รู้ endpoint/JSON

2. Logic layer

Store/ViewModel ตรวจ transition, loading/duplicate/race, เรียก repository และสร้าง state ใหม่ โดยไม่สร้าง Widget หรือใช้ ScaffoldMessenger โดยตรง

3. Data layer

Repository/DataSource กำหนด URI, request DTO, decode response, cache/remote policy และ translate transport errors ให้ logic layer เข้าใจ

4. Example

// UI
onSubmitted: store.submitBarcode

// Logic
Future<void> submitBarcode(String raw) async {
  state = state.loading();
  final item = await repository.validateBarcode(raw.trim());
  state = state.ready(item);
}

// Data
Future<Item> validateBarcode(String code) async =>
  ItemDto.fromJson(await api.get('/items/$code')).toDomain();

5. Effects ไม่ใช่ state ทุกอย่าง

toast/navigation แบบ one-shot ใช้ effect channel/callbackที่ typed หรือให้ UI ตอบสนองต่อ action result อย่าเก็บ bool showSuccess ค้างจน rebuild ซ้ำ

6. Rule of dependencies

UI import logic/models; logic import repository interface/domain; infrastructure implement interfaceและ import HTTP DTO หลีกเลี่ยง circular importด้วย ownership ที่ชัด

7. แบบฝึกหัด

ปัจจุบัน screen มี try/catch SocketException แล้ว set error string ควรย้ายอะไร?

เฉลย

Data layer แปลง SocketException เป็น NetworkFailure; logic map เป็น error state; UI render message/retry action

8. Review checklist

เปลี่ยน widget testโดย fake store, เปลี่ยน APIโดย repository test, และทดสอบ workflowโดย fake repositoryได้อย่างอิสระ
