ในแบบฝึกหัดของ 1.1 เราลอง ลบ MaterialApp ออกแล้วพบว่าข้อความกลายเป็นฟอนต์ดิบพร้อมขีดสีเหลืองประหลาด นั่นเป็นหลักฐานว่ามันให้อะไรบางอย่างกับเรา บทนี้จะตอบว่ามันให้อะไรบ้าง

3. Mental model: กล่องเครื่องมือประจำแอป

MaterialApp ไม่ได้วาดอะไรบนหน้าจอเลยแม้แต่จุดเดียว หน้าที่ของมันคือ วางของกลางไว้ให้ทุก widget ที่อยู่ข้างใต้หยิบไปใช้

สิ่งที่วางไว้ให้ใครใช้ถ้าไม่มีจะเกิดอะไร
ธีมสีและฟอนต์ปุ่ม ข้อความ การ์ด ทุกตัวทุกอย่างใช้ค่าดิบที่ไม่สวยและไม่สม่ำเสมอ
Navigatorการเปลี่ยนหน้าจอ (Part 5)เปลี่ยนหน้าไม่ได้เลย
ทิศทางข้อความText ทุกตัวขึ้นขีดสีเหลืองเตือน
ข้อความมาตรฐานปุ่ม “ยกเลิก/ตกลง” ในกล่องโต้ตอบerror No MaterialLocalizations found
ประโยคเดียวที่ต้องจำ: MaterialApp คือชั้นที่ตั้ง “ค่ากลางของทั้งแอป” — ไม่ใช่ที่สำหรับใส่เนื้อหา เนื้อหาไปอยู่ใน home:

4. หน้าตาของ MaterialApp ที่ใช้จริง

เปิด lib/beginner_main.dart ใน lab ดูส่วนบนสุด

class WarehouseCounterApp extends StatelessWidget {
  const WarehouseCounterApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      title: 'Warehouse Counter',
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
        useMaterial3: true,
      ),
      home: const WarehouseCounterScreen(),
    );
  }
}
ค่าที่ตั้งทำอะไร
debugShowCheckedModeBannerปิดแถบ DEBUG มุมขวาบน — มีผลตอนพัฒนาเท่านั้น
titleชื่อแอปที่ระบบปฏิบัติการเห็น ไม่ได้แสดงบนหน้าจอ
themeชุดสีและตัวอักษรของทั้งแอป
homeหน้าจอแรกที่ผู้ใช้เห็น
title ไม่ใช่ข้อความบนแถบด้านบนของหน้าจอ — อันนั้นมาจาก AppBar ที่อยู่ใน Scaffold ซึ่งเป็นคนละเรื่องกัน เป็นจุดที่สับสนกันบ่อยมาก

5. ธีมสีจากสีเดียว

theme: ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
  useMaterial3: true,
),

ColorScheme.fromSeed รับสีเดียวแล้วสร้างชุดสีทั้งหมดให้อัตโนมัติ ทั้งสีพื้นหลัง สีตัวอักษร สีปุ่ม และสีที่ใช้ตอนกด — โดยรับประกันว่าอ่านออกทุกคู่

ลองเปลี่ยน Colors.indigo เป็น Colors.teal หรือ Colors.orange แล้วบันทึกไฟล์ ทั้งแอปจะเปลี่ยนสีทันทีโดยที่เราไม่ได้แตะโค้ดหน้าจอเลย

วิธีหยิบสีจากธีมมาใช้ในหน้าจอ

backgroundColor: Theme.of(context).colorScheme.inversePrimary,

Theme.of(context) อ่านว่า “ขอธีมที่ใกล้ตัวฉันที่สุด” — เดี๋ยวจะอธิบายว่า context ทำงานอย่างไรใน 1.7 ตอนนี้แค่จำรูปแบบนี้ไว้

ทำไมถึงควรใช้สีจากธีมแทนการเขียนสีตรง ๆ: เพราะวันที่ลูกค้าขอเปลี่ยนสีแบรนด์ คุณจะแก้ที่เดียว ไม่ใช่ไล่แก้ทุกไฟล์ — และเพราะสีในธีมรับประกันว่าตัวอักษรจะอ่านออกบนพื้นหลังนั้นเสมอ

6. หนึ่งแอป หนึ่ง MaterialApp

คำถามที่คนใหม่มักเจอ: อยากให้หน้าตั้งค่ามีสีต่างจากหน้าอื่น จะสร้าง MaterialApp ใหม่ในหน้านั้นได้ไหม

คำตอบคือไม่ควร เพราะจะได้ Navigator ตัวใหม่และระบบธีมชุดใหม่ซ้อนกันอยู่ ผลคือ

อาการที่จะเจอสาเหตุ
กดย้อนกลับแล้วไม่ไปไหนNavigator ตัวในไม่รู้จักหน้าที่อยู่ข้างนอก
กล่องโต้ตอบเปิดผิดที่ หรือถูกบังเปิดบน Navigator คนละตัว
เปลี่ยนธีมแล้วบางส่วนไม่เปลี่ยนมีแหล่งธีมสองแห่ง

วิธีที่ถูกคือครอบเฉพาะส่วนที่ต้องการด้วย Theme ซึ่งเปลี่ยนแค่ธีม ไม่ได้สร้างแอปใหม่

Theme(
  data: Theme.of(context).copyWith(
    colorScheme: Theme.of(context).colorScheme.copyWith(primary: Colors.red),
  ),
  child: const SettingsPanel(),
)

7. home คือหน้าแรก ไม่ใช่ที่เก็บหน้าจอทั้งหมด

home: รับ widget ตัวเดียว ซึ่งคือหน้าจอที่ผู้ใช้เห็นตอนเปิดแอป

อย่าเปลี่ยนหน้าจอด้วยการสลับค่าใน home: เช่นใช้ if (loggedIn) HomeScreen() else LoginScreen() เป็นวิธีเปลี่ยนหน้าทั้งแอป วิธีนั้นจะทำให้ไม่มีประวัติการย้อนกลับ และเปลี่ยนหน้าแบบไม่มีอนิเมชัน — การเปลี่ยนหน้าที่ถูกต้องใช้ Navigator ซึ่งเรียนใน Part 5

ข้อยกเว้นที่ใช้วิธีนี้ได้จริงคือการสลับระหว่าง “ยังไม่ล็อกอิน” กับ “ล็อกอินแล้ว” ซึ่งเป็นการเปลี่ยนทั้งโลกของแอป ไม่ใช่การเดินหน้าถอยหลังระหว่างหน้าจอ — เรื่องนี้จะกลับมาอีกครั้งใน 5.4

8. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
No MaterialLocalizations foundเปิดกล่องโต้ตอบโดยไม่มี MaterialApp ครอบใส่ MaterialApp ที่ชั้นบนสุด (เจอบ่อยมากในเทสต์)
ตั้ง title แล้วแถบด้านบนไม่เปลี่ยนสับสนกับ AppBarแก้ที่ AppBar(title: ...) ใน Scaffold
เปลี่ยนธีมแล้วบางหน้าไม่เปลี่ยนมี MaterialApp ซ้อนกันเหลือตัวเดียวที่ชั้นบนสุด
ปุ่มย้อนกลับใช้ไม่ได้ในบางหน้าหน้านั้นอยู่ใต้ Navigator คนละตัวลบ MaterialApp ที่สร้างซ้อนออก
สีที่ตั้งไม่ตรงกับที่เห็นColorScheme.fromSeed ปรับสีเพื่อให้อ่านออกถ้าต้องได้สีเป๊ะ ให้กำหนดทีละค่าใน ColorScheme

ข้อ 3 — ปัญหาที่ตามมา

  1. ปุ่มย้อนกลับทำงานผิด — เมื่อกดย้อนจากหน้าตั้งค่า Navigator ตัวในจะหาหน้าก่อนหน้าไม่เจอ เพราะประวัติอยู่กับ Navigator ตัวนอก ผู้ใช้จะติดอยู่ในหน้านั้น
  2. กล่องยืนยันเปิดผิดชั้น — เมื่อเปิดกล่องยืนยันการบันทึก มันอาจแสดงเต็มจอทับทุกอย่าง หรือถูกบังจนกดไม่ได้ เพราะเปิดบน Navigator คนละตัวกับที่คาดไว้
  3. ธีมสองแหล่ง — เมื่อผู้ใช้เปลี่ยนโหมดมืด หน้าอื่นเปลี่ยนแต่หน้าตั้งค่าไม่เปลี่ยน เพราะมันอ่านธีมจาก MaterialApp ตัวในที่ไม่ได้ผูกกับค่าที่ผู้ใช้ตั้ง

สิ่งที่ควรสังเกตที่สุดในข้อ 2: ถ้าคุณเขียน backgroundColor: Colors.teal ตรง ๆ มันก็จะดูถูกต้องตอนนี้ แต่เมื่อทำโหมดมืดในภายหลัง แถบนี้จะยังเป็นสีเดิมบนพื้นดำและอาจอ่านไม่ออก — การใช้ Theme.of(context) ทำให้สีปรับตามบริบทให้เอง

ลองต่อ: เพิ่ม darkTheme: และ themeMode: ThemeMode.dark เข้าไปใน MaterialApp แล้วรันดู จะเห็นว่าโค้ดหน้าจอไม่ต้องแก้เลยแม้แต่บรรทัดเดียว

10. สรุปท้ายบท

  • MaterialApp ไม่วาดอะไร แต่วางค่ากลางไว้ให้ทั้งแอปใช้
  • มันให้ธีม, Navigator, ทิศทางข้อความ และข้อความมาตรฐาน
  • ColorScheme.fromSeed สร้างชุดสีทั้งหมดจากสีเดียว
  • ใช้ Theme.of(context) แทนการเขียนสีตรง ๆ
  • title ของแอป ไม่ใช่ข้อความบน AppBar
  • ทั้งแอปควรมี MaterialApp ตัวเดียว
