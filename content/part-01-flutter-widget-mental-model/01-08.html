Key ช่วย parent จับคู่ widget configuration ใหม่กับ Element เดิมใน sibling list: identity = runtimeType + key เมื่อไม่มี key Flutterจับตาม type/ตำแหน่ง จึงสำคัญตอน reorder/insert/animation/test

1. Key ประเภทใช้งานหลัก

  • ValueKey(id): identity จากค่าธุรกิจที่ stable
  • ObjectKey(object): identity จาก object/equality
  • UniqueKey(): ใหม่เสมอ—บังคับ state ใหม่
  • GlobalKey: unique ทั้ง tree และเข้าถึง State/context เช่น Form

2. List reorder bug

for (final task in tasks)
  TaskRow(key: ValueKey(task.id), task: task)

เมื่อ sort/insert Flutter ย้าย Element/State ตาม task id หากไม่ key state ของ TextField/expandอาจติด index เดิมและไปอยู่ taskอื่น Key ต้อง uniqueเฉพาะ siblings และ stableข้าม rebuild

3. ตัวอย่างสลับ screen

AnimatedSwitcher(
  child: KeyedSubtree(
    key: ValueKey(store.screen),
    child: buildCurrentScreen(),
  ),
)

Absolute shell ใช้แบบนี้เพื่อบอก AnimatedSwitcher ว่า screen nameใหม่เป็น child คนละ identity แม้ wrapper/typeคล้ายกัน จึง transitionถูกและ stateเก่าถูกจัด lifecycleตาม intent

4. ValueKey ใน dashboard/test

HomeView key AutoSizeText ตาม title/mode และ tests หา controls ด้วย ValueKey เช่น connection URL preview/scanner inputs ข้อดีคือ selector stableกว่าหาข้อความที่เปลี่ยนตามภาษา แต่ production identity key กับ test hookควรตั้งชื่อมีความหมาย

5. GlobalKey สำหรับ Form

final formKey = GlobalKey<FormState>();
Form(key: formKey, child: ...);
formKey.currentState?.validate();

LoginScreen absolute ใช้เพื่อสั่ง FormState validate เพราะ operationเกี่ยวกับ subtree stateจริง อย่าสร้าง GlobalKey ใน build—จะใหม่ทุกครั้งและทิ้ง state

6. Key ไม่แก้ state ownership

ถ้าข้อมูลผิดเพราะ list mutation/store race การใส่ UniqueKeyอาจดูเหมือนแก้เพราะ remountทุกอย่าง แต่ซ่อน bugและเสีย focus/scroll/network lifecycle ต้องแก้ identityเฉพาะกรณีที่ Element matchingผิดจริง

7. แบบฝึกหัด

รายการ serial reorderได้และแต่ละ rowมี TextField quantity เลือก keyใดและเพราะอะไร?

เฉลย

ValueKey(serial.id หรือ normalizedSerial) ที่ unique/stable เพื่อให้ field stateตาม entity ไม่ตาม index ไม่ใช้ UniqueKeyเพราะจะ resetทุก rebuild และไม่ใช้ indexเพราะ reorderแล้ว identityผิด

8. จุดพลาด

Key มีผลเฉพาะการจับคู่ใน parent/sibling level ที่วางไว้ ใส่ key ลึกเกินจุด reorderไม่ช่วย และ keyซ้ำใน siblingsทำให้ assertion/error
