Widget คือ immutable configuration, Element คือ instance/ตำแหน่งที่มี identity ใน tree และ RenderObject คือวัตถุ layout/paint/hit-test ของ render widgets การ build ใหม่จึงไม่เท่ากับสร้างทุกอย่างใหม่

1. สาม tree ที่ต้องแยก

ชั้นเก็บอะไรเปลี่ยนเมื่อ
Widgetconfiguration ชั่วคราว immutableparent build คืน config ใหม่
Elementตำแหน่ง, identity, lifecycle, inherited dependenciesmount/update/deactivate/unmount
RenderObjectconstraints, size, paint, hit testproperty/layout/paint ต้องอัปเดต

2. Reconciliation

เมื่อ parent build คืน widget ใหม่ Flutter เทียบ runtimeType และ key กับ widget เดิม ถ้าตรง Element เดิมถูก update และ State/RenderObject ที่เหมาะสมอยู่ต่อ ถ้าไม่ตรง subtree เดิมถูกถอดและ mount ใหม่

Old: Tile(key: ValueKey('receive'), badge: 2)
New: Tile(key: ValueKey('receive'), badge: 3)
     → Element เดิม, configuration ใหม่, render เฉพาะที่จำเป็น

3. Component widget กับ render widget

Stateless/StatefulWidget ประกอบ widgets อื่นและไม่มี RenderObject ของตัวเองโดยตรง ส่วน Container แตกเป็น render-capable widgets หลายชั้น เช่น padding/decoration/constraints การดู Inspector ช่วยเห็น tree จริงที่ shorthand สร้าง

4. Build ≠ layout ≠ paint

Build คำนวณ configuration tree, layout ส่ง constraints/เลือก size, paint วาด การแก้ overflow ต้องดู layout; การ rebuild มากต้องดู state dependency; paint แพงอาจใช้ repaint boundary/caching หลังวัด อย่าเรียกรวมว่า “render ช้า”

5. ตัวอย่าง dashboard

HomeView เป็น StatelessWidget ที่ build LayoutBuilder → Padding → Column → DispatchTile/Grid/SummaryCard Tiles เป็น component widgets; ภายใน Material/Ink/Stack/LayoutBuilder ลงไปถึง render objects ที่ layout/paint จริง

6. State อยู่กับ Element

StatefulWidget object ถูกสร้างใหม่ได้บ่อย แต่ State อยู่กับ StatefulElement ตาม identity นี่คือเหตุผล reorder list โดยไม่มี key อาจทำ state ติดตำแหน่งแทน entity

7. แบบฝึกหัด

Parent เปลี่ยน badge 2 → 3 แต่ Tile type/key เดิม อธิบายแต่ละ tree เกิดอะไร

เฉลย

สร้าง Tile widget config ใหม่; Element เดิม update เพราะ type/key ตรง; child widgets ที่ build คืนถูก reconcile; render object รับ property ใหม่และ mark layout/paint เฉพาะที่เกี่ยว ไม่ mount ทั้งแอปใหม่

8. จุดพลาด

อย่า optimize ด้วยการกลัว “สร้าง Widget object” ก่อนวัด ปกติ widgets เบา ปัญหามักเป็นงาน side effect ใน build, subtree dependency กว้าง, layout/paint แพง หรือ list/image ไม่ lazy
