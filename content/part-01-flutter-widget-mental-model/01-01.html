1. ปัญหาที่บทนี้แก้

ใน Part 0 เราสั่ง flutter create แล้วรัน แอปก็ขึ้นมา แต่ยังไม่รู้ว่าเกิดอะไรขึ้นระหว่างนั้น ไฟล์ lib/main.dart ที่ Flutter สร้างให้มีโค้ดร้อยกว่าบรรทัดที่ยังอ่านไม่ออก

บทนี้จะเริ่มจากแอปที่เล็กที่สุดเท่าที่เป็นไปได้ — เล็กจนอ่านออกทุกบรรทัด — แล้วค่อย ๆ ต่อเติมในบทถัดไป

2. คำศัพท์ที่ต้องรู้ก่อน

คำความหมายแบบสั้นที่สุด
widgetชิ้นส่วนหนึ่งชิ้นของหน้าจอ — ปุ่ม ข้อความ ช่องว่าง ล้วนเป็น widget
runAppคำสั่งที่บอก Flutter ว่า “เอา widget ตัวนี้ไปแสดงเป็นทั้งหน้าจอ”
root widgetwidget ตัวบนสุด ที่ครอบทุกอย่างไว้
widget treeโครงสร้างว่า widget ตัวไหนอยู่ข้างในตัวไหน
frameภาพหนึ่งภาพที่หน้าจอวาด
engineส่วนที่วาดภาพลงหน้าจอจริง ๆ ซึ่งเราไม่ต้องเขียนเอง

3. Mental model: จากคำสั่งเดียวสู่หน้าจอ

โปรแกรม Dart ทุกตัวเริ่มที่ main() — ข้อนี้เรารู้มาตั้งแต่ D1.1 แล้ว สิ่งที่เพิ่มเข้ามาใน Flutter คือคำสั่งเดียวคือ runApp

Dart เริ่มที่ main()
        │
        ├─ runApp(widget ตัวบนสุด)
        │        │
        │        └─ Flutter รับ widget ไปคำนวณว่าต้องวาดอะไรตรงไหน
        │
        └─ engine วาดลงหน้าจอเป็น frame แรก
ประโยคเดียวที่ต้องจำ: หน้าที่ของเราคือ อธิบายว่าหน้าจอควรมีหน้าตาอย่างไร ส่วนการวาดจริงเป็นหน้าที่ของ Flutter — เราไม่เคยสั่งวาดเส้นหรือระบายสีเองเลยตลอดทั้งคอร์ส

4. แอปที่เล็กที่สุดที่รันได้

สร้างไฟล์ใหม่แล้วใส่โค้ดนี้ทั้งหมด — สั้นแค่นี้จริง ๆ

import 'package:flutter/material.dart';

void main() {
  runApp(
    const MaterialApp(
      home: Scaffold(
        body: Center(
          child: Text('สวัสดีคลังสินค้า'),
        ),
      ),
    ),
  );
}

อ่านทีละบรรทัดจากบนลงล่าง

บรรทัดทำอะไร
import 'package:flutter/material.dart';ขอใช้ widget สำเร็จรูปของ Flutter (ตามที่เรียนใน D1.18)
void main()จุดเริ่มของโปรแกรม เหมือน Dart ทั่วไป
runApp(...)ส่ง widget ตัวบนสุดให้ Flutter
MaterialAppตัวห่อระดับแอป ให้ธีมและระบบหน้าจอมาตรฐาน (บทหน้า)
Scaffoldโครงหน้าจอหนึ่งหน้า มีที่สำหรับแถบบน เนื้อหา ปุ่มลอย
Centerจัดสิ่งที่อยู่ข้างในให้อยู่กลาง
Textข้อความหนึ่งชิ้น

สังเกตว่าทุกตัวรับ named parameter อย่าง home:, body:, child: ซึ่งเป็นสิ่งที่เรียนมาแล้วใน D1.4 — Flutter ไม่ได้มีไวยากรณ์พิเศษอะไรเลย มันคือ Dart ธรรมดาที่เราคุ้นอยู่แล้ว

5. widget tree คืออะไร

โค้ดข้างบนสร้างโครงสร้างซ้อนกันแบบนี้

MaterialApp
└── Scaffold
    └── Center
        └── Text('สวัสดีคลังสินค้า')

วงเล็บที่ซ้อนกันในโค้ดคือความสัมพันธ์ “อยู่ข้างใน” ตรง ๆ — ถ้าอ่านโค้ดแล้วนึกภาพต้นไม้นี้ออก คุณจะอ่านโค้ด Flutter ได้ทุกไฟล์

คำที่ใช้ต่อกันหมายถึง
child:มีลูกได้ตัวเดียว
children:มีลูกได้หลายตัว (จะเจอใน Part 2)
home:, body:ชื่อเฉพาะของ widget นั้น ๆ แต่ความหมายคือ “ข้างใน” เหมือนกัน

ในโฟลเดอร์ lab มีแอปนับสินค้าที่เขียนไว้ให้แล้ว ใช้เป็นตัวอย่างตลอด Part 1

เปลี่ยน chrome เป็นชื่ออุปกรณ์อื่นได้ ดูรายชื่อด้วย flutter devices ส่วน -t คือการบอกว่าจะเริ่มจากไฟล์ไหน เพราะ lab นี้มีหลายแอปอยู่ในโปรเจกต์เดียว

เปิดไฟล์ lib/beginner_main.dart แล้วดูสามบรรทัดแรก

void main() {

}

เหมือนกับตัวอย่างในหัวข้อ 4 ทุกประการ ต่างกันแค่ widget ตัวบนสุดถูกแยกออกไปเป็น class ของตัวเอง ซึ่งเป็นสิ่งที่จะอธิบายใน 1.4

7. ทำไมต้องมี const

runApp(const WarehouseCounterApp());

ทบทวนจาก D1.3: const แปลว่าค่านี้รู้ได้ตั้งแต่ยังไม่รันโปรแกรม Flutter ใช้ประโยชน์จากข้อนี้เพื่อไม่สร้าง widget เดิมซ้ำ ๆ ทุกครั้งที่วาดหน้าจอใหม่

ตอนนี้ยังไม่ต้องเข้าใจรายละเอียด แค่ติดนิสัย: ถ้า analyzer แนะนำให้เติม const ให้เติม เหตุผลเต็ม ๆ อยู่ใน 1.10

8. เมื่อต้องเตรียมอะไรก่อนเปิดแอป

แอปจริงมักต้องทำบางอย่างก่อน เช่นอ่านค่าที่ตั้งไว้ หรือโหลดที่อยู่ของ server ซึ่งเป็นงานที่ต้องรอ (D1.15)

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();   // เตรียมสะพานเชื่อมกับอุปกรณ์
  await loadSettings();                        // งานที่ต้องเสร็จก่อนจริง ๆ
  runApp(const WarehouseCounterApp());
}

WidgetsFlutterBinding.ensureInitialized() จำเป็นเมื่อเราต้องคุยกับอุปกรณ์ ก่อน เรียก runApp ถ้าไม่มีบรรทัดนี้จะได้ error ทันที

อย่ารอทุกอย่างก่อนเปิดแอป — ยิ่ง await เยอะก่อน runApp ผู้ใช้ยิ่งเห็นหน้าจอดำนาน ให้ถามทีละอย่างว่า “ถ้าไม่มีค่านี้ หน้าจอแรกยังแสดงได้ไหม” ถ้าได้ ให้ไปโหลดทีหลัง

9. ข้อผิดพลาดที่พบบ่อย

อาการสาเหตุวิธีแก้
หน้าจอขึ้นข้อความสีแดงว่า No MaterialLocalizations foundใช้ widget ที่ต้องการ MaterialApp แต่ไม่มีครอบด้วย MaterialApp ที่ชั้นบนสุด
ข้อความมีขีดเส้นใต้สีเหลืองประหลาดใส่ Text โดยไม่มี MaterialApp/Scaffold ครอบใส่โครงให้ครบตามตัวอย่างหัวข้อ 4
Binding has not yet been initializedเรียกใช้สิ่งที่ต้องคุยกับอุปกรณ์ก่อน runAppเพิ่ม WidgetsFlutterBinding.ensureInitialized()
แก้โค้ดแล้วหน้าจอไม่เปลี่ยนยังไม่ได้บันทึกไฟล์ หรือ hot reload ไม่ทำงานบันทึกไฟล์ แล้วกด r ใน terminal หรือ R เพื่อเริ่มใหม่
รัน lab แล้วขึ้นแอปผิดตัวลืมใส่ -t ระบุไฟล์ใส่ -t lib/beginner_main.dart

10. แบบฝึกหัด

สร้างไฟล์ my_first_app.dart ที่แสดงข้อความสองบรรทัดกลางจอ คือชื่อคลังและจำนวนสินค้า โดย

  1. ต้องใช้ตัวแปรเก็บค่าทั้งสอง ห้ามพิมพ์ข้อความสำเร็จรูปลงใน Text
  2. วาด widget tree ของแอปที่คุณเขียนออกมาบนกระดาษ
  3. ลองลบ MaterialApp ออกแล้วรันดู เพื่อดูว่าเกิดอะไรขึ้น
ดูแนวคำตอบและเหตุผล
import 'package:flutter/material.dart';

void main() {
  const warehouseName = 'Bangkok DC';
  const itemCount = 128;

  runApp(
    MaterialApp(
      home: Scaffold(
        body: Center(
          child: Column(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [
              Text(warehouseName),
              Text('$itemCount รายการ'),
            ],
          ),
        ),
      ),
    ),
  );
}

widget tree ที่ได้

MaterialApp
└── Scaffold
    └── Center
        └── Column
            ├── Text('Bangkok DC')
            └── Text('128 รายการ')

ทำไมต้องมี Column: เพราะ Center รับลูกได้ตัวเดียวผ่าน child: เมื่อต้องการสองบรรทัดจึงต้องใส่ตัวที่รับหลายลูกคั่นไว้ — Column คือตัวที่เรียงลูกจากบนลงล่าง และจะเรียนเต็ม ๆ ใน 2.2

ทำไม MaterialApp ตัวนี้ไม่ใส่ const: เพราะ Text('$itemCount รายการ') ใช้การประกอบข้อความซึ่งคำนวณตอนรัน จึงเป็น const ไม่ได้ ทำให้ตัวที่ครอบมันก็เป็น const ไม่ได้ตามไปด้วย — ตรงกับกฎจาก D1.3 ว่า const ต้องเป็น const ตลอดสาย

ผลของข้อ 3: เมื่อลบ MaterialApp ออก ข้อความจะแสดงด้วยฟอนต์ดิบและมีขีดสีเหลือง เพราะไม่มีใครกำหนดธีมและทิศทางข้อความให้ — เป็นหลักฐานว่า MaterialApp ให้ค่าเริ่มต้นหลายอย่างที่เราไม่เคยสังเกต ซึ่งจะอธิบายในบทหน้า

11. สรุปท้ายบท

  • แอป Flutter เริ่มที่ main() แล้วเรียก runApp ครั้งเดียว
  • เราอธิบายว่าหน้าจอควรมีหน้าตาอย่างไร ส่วน Flutter เป็นคนวาด
  • widget ซ้อนกันเป็น tree — วงเล็บที่ซ้อนในโค้ดคือความสัมพันธ์ “อยู่ข้างใน”
  • child: รับลูกตัวเดียว children: รับหลายตัว
  • ใส่ const ทุกครั้งที่ทำได้
  • งานที่ต้องรอก่อนเปิดแอปควรมีให้น้อยที่สุด

บทถัดไป: 1.2 จะอธิบายว่า MaterialApp ที่เราใส่ไว้เฉย ๆ ในบทนี้ ให้อะไรกับเราบ้าง และทำไมทุกแอปถึงต้องมีมันหนึ่งตัว
