BuildContext คือ handle ของ Element ตำแหน่งหนึ่งใน tree ไม่ใช่ global application context การหา Theme/Navigator/MediaQuery เดินจากตำแหน่งนั้นขึ้น ancestor และ context มีอายุเท่า Element

1. ตำแหน่งเป็นตัวกำหนดผล

final theme = Theme.of(context);
final media = MediaQuery.of(context);
final navigator = Navigator.of(context);

context สองตัวใน methodเดียวกันอาจเห็น ancestors ต่างกัน Dialog builder ให้ ctx ที่อยู่ใต้ dialog route จึงใช้ Navigator.pop(ctx) ปิด dialog ได้ตรงตัว

2. Builder สร้าง context ใต้ widget ใหม่

ถ้าสร้าง Scaffold แล้วใช้ context ของ widget ที่อยู่เหนือ Scaffold เรียก ScaffoldMessenger/Theme ที่เพิ่งสร้าง อาจหาไม่เจอ ใช้ Builder หรือแยก child widget เพื่อได้ context ใต้ ancestor นั้น

3. Async gap

final confirmed = await showDialog<bool>(...);
if (!context.mounted || confirmed != true) return;
Navigator.of(context).pop();

ระหว่าง await Element อาจ unmount จาก back/logout/rebuild route Absolute/wmsapp ตรวจ mounted หรือ context.mounted ก่อน navigation/setState หลายจุด นี่ไม่ใช่ lint cosmetic แต่กัน lookup บน context ที่หมดอายุ

4. context ไม่ควรถูกเก็บใน service

Service/repository มี lifetime ยาวและไม่ควรขึ้นกับ UI tree ส่งข้อมูล/errorกลับให้ owner แล้ว widget แสดง dialog/navigation หากต้อง dispatch app-level navigationจริงให้ใช้ navigation abstraction/key อย่างจำกัดและทดสอบได้

5. Inherited dependency กับ rebuild

การเรียก Theme.of(context) ลงทะเบียน Element เป็น dependent เมื่อ themeเปลี่ยน Element นี้ rebuild ส่วนการเข้าถึง inherited แบบไม่ depend มี API/กรณีพิเศษ แต่ปกติใช้ of ตาม declarative model

6. ตัวอย่างจริง

  • wmsapp ใช้ Theme.of(context) เลือกสี dark/light
  • scan dialogs ใช้ MediaQuery ของ dialog context สำหรับ keyboard inset/bottom safe area
  • connection settings รอ confirm แล้วตรวจ context.mounted ก่อนใช้ contextต่อ

7. แบบฝึกหัด

ทำไม if (!mounted) return กับ if (!context.mounted) return อาจใช้ต่างกัน?

เฉลย

mounted เป็น property ของ State ปัจจุบัน ส่วน context parameter/local อาจเป็นคนละ Element เช่น dialog/child builder จึงตรวจ contextนั้นโดยตรง ใช้ตัวที่คุณกำลังจะเรียก ไม่ใช่ใส่เชิงพิธี

8. จุดพลาด

GlobalKey/currentContext ไม่ใช่ทางลัดแทนการส่ง callback/state มันสร้าง coupling กับตำแหน่ง tree และมี lifecycle null ได้ ใช้เฉพาะ operation ที่ต้องเข้าถึง Element/State จริง
