JsonKey เป็น field-level contract: ใช้เมื่อชื่อ/เงื่อนไขเฉพาะ fieldต่างจาก policyกลาง และเขียน testทุก behaviorที่กระทบ compatibility

1. name

@JsonKey(name: 'from_location') map wire keyกับ Dart naming โดยไม่ทำให้ชื่อ domainตาม backend legacy

2. defaultValue

defaultควรใช้เมื่อ contractบอกว่าหายเท่ากับค่านั้นจริง ไม่ใช้กลบ required fieldที่ backendลืมส่ง

3. required/disallowNull

เปิด strict key/null checksสำหรับ contractสำคัญและดูชนิด exceptionที่ generatorสร้าง จากนั้น translateที่ repository boundary

4. includeIfNull

การ omit nullกับส่ง "field": null มีความหมายต่างกันใน PATCH/บาง API กำหนด per fieldหรือ build policyอย่างชัด

5. include directions

includeFromJson/includeToJson เหมาะ server-only/local-only fields เช่น local UI flagไม่ควรถูกส่งกลับ API

6. checked

checked decodingให้ error contextดีขึ้นแต่มี runtime overheadเล็กน้อย ประเมินจาก diagnosabilityและ boundary risk

7. Precedence

field JsonKeyเหนือ class annotation และ class annotationเหนือ build.yaml ทีมต้องลด configซ้อนเพื่อ reviewง่าย

8. Exercise

สร้าง fixture missing/null/wrong-type/extra-key แล้วบันทึกว่า modelรับหรือ rejectแต่ละกรณีตาม API contract
