Union แทน stateที่เป็นไปได้: แต่ละ caseมี payloadเฉพาะและ sealed typeทำให้ switchตรวจ exhaustivenessเมื่อเพิ่ม caseใหม่

1. Declaration

TaskSyncState มี idle, running(remaining) และ failed(commandId,message) แทน bool flagsที่สร้าง combinationผิดเช่น idleและsyncingพร้อมกัน

2. Generated cases

Freezedสร้าง public case classes SyncIdle, SyncRunning, SyncFailed ให้ Dart patterns narrowชนิดและอ่าน payloadปลอดภัย

3. Exhaustive switch

switch (state) {
 SyncIdle() => ...
 SyncRunning(:final remaining) => ...
 SyncFailed(:final message) => ...
}

4. Case-specific API

ตัวแปรชนิดฐานเรียก field/copyWithเฉพาะ failedไม่ได้ ต้อง pattern-matchก่อน นี่คือ type safetyไม่ใช่ข้อจำกัดที่ควร castหนี

5. when/map

Freezedมี generated helpersตาม version/config แต่ Dart 3 pattern matchingลด package-specific syntaxและทำให้ migrationง่าย

6. JSON unions

tagged union serializeได้ด้วย discriminator เช่น runtimeTypeหรือ custom unionKey/valueCase แต่ wire contractควรเป็นชื่อ stableไม่ผูกชื่อ Dartภายใน

7. UI state

unionเหมาะ loading/data/empty/errorเมื่อ payloadต่าง แต่ data+refreshingพร้อมกันอาจเหมาะ product stateที่ออกแบบเองมากกว่า unionแบบง่าย

8. Test

task_sync_state_test.dart พิสูจน์ exhaustive pattern, case payload, value equalityและ copyWithหลัง type narrowing
