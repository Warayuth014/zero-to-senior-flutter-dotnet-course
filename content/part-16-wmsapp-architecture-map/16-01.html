8. ข้อผิดพลาดที่พบบ่อยตอนเริ่มอ่านโปรเจกต์ใหญ่

ทำแบบนี้ปัญหาทำแทน
เปิดไฟล์เรียงตามตัวอักษรไม่รู้ว่าอันไหนสำคัญตามเส้นทางของหนึ่งการกด
เริ่มที่ไฟล์ใหญ่ที่สุดไม่มีบริบท อ่านไม่รู้เรื่องเริ่มที่ main.dart
อ่านให้จบก่อนแตะโค้ดไม่มีวันจบอ่านเท่าที่ต้องใช้กับงานตรงหน้า
รีบตัดสินว่าเขียนผิดมองไม่เห็นเหตุผลเดิมถามว่า “ทำไมถึงเขียนแบบนี้” ก่อน
แก้ทันทีที่เจอสิ่งที่ไม่ชอบไม่มีเทสต์รับจดไว้ก่อน แก้ทีหลังพร้อมเทสต์

แถวสุดท้ายสำคัญที่สุดในโปรเจกต์นี้ เพราะไม่มีเทสต์เลยแม้แต่ข้อเดียว

9. แบบฝึกหัด

ยังไม่ต้องเปิดไฟล์ไหน ใช้แค่ตัวเลขในบทนี้ตอบ

  1. ถ้าได้รับแจ้งว่า “จอ Packing กดยืนยันแล้วค้าง” จะเปิดไฟล์ไหนก่อน และคาดว่าจะเจออะไร
  2. ถ้าต้องเพิ่มฟิลด์ใหม่จาก API หนึ่งช่องให้แสดงในจอ Picking ต้องแก้กี่ไฟล์ และไฟล์ไหนบ้าง
  3. ทำไมโฟลเดอร์ putaway มี 26 ไฟล์แต่ packing มีไฟล์เดียว ทั้งที่บรรทัดใกล้เคียงกัน
แนวคำตอบ

ข้อ 1

screens/packing/packing_screen.dart — 2,176 บรรทัด และเป็นไฟล์เดียวของโดเมนนั้น

คาดว่าจะเจอ: state ทั้งหมดของ flow อยู่ในไฟล์เดียว, การเรียก API อยู่ปนกับการวาดหน้าจอ, และเมธอดที่ยาวมากหนึ่งหรือสองตัวที่ทำงานตอนกดยืนยัน

วิธีเข้าเร็วที่สุดคือค้นคำว่า ApiService() ในไฟล์นั้นเพื่อหาจุดที่คุยกับเซิร์ฟเวอร์ แล้วไล่ขึ้นไปว่าใครเรียก

ข้อ 2

ไฟล์แก้อะไร
models/picking/picking_models.dartเพิ่มฟิลด์ + อ่านใน fromJson
screens/picking/.../xxx_screen.dartเอาไปแสดง

สองไฟล์ ถ้า endpoint เดิมส่งค่านั้นมาอยู่แล้ว

ถ้า endpoint ยังไม่ส่ง ต้องเพิ่มอีกสองที่ — services/api/picking_api.dart (ถ้าต้องเปลี่ยน path หรือ body) และฝั่ง .NET

สังเกตว่าคำตอบนี้ตอบได้เพราะรู้โครง ไม่ต้องเปิดไฟล์ดูเลย นี่คือประโยชน์ของการทำแผนที่ก่อนอ่าน

ข้อ 3

เพราะทั้งสองถูกเขียนคนละเวลา และ putaway ถูกแตกทีหลัง

สิ่งที่บอกเราคือ ทีมนี้รู้วิธีแตกไฟล์อยู่แล้ว — putaway คือหลักฐาน ดังนั้น packing ที่ยังไม่แตกไม่ใช่เพราะไม่รู้ แต่เพราะยังไม่ได้ทำ

ข้อสรุปนี้เปลี่ยนวิธีคุยกับทีม จาก “ควรแตกไฟล์นะ” (ซึ่งเขารู้อยู่แล้ว) เป็น “จะแตก packing ตามแบบเดียวกับ putaway ไหม” ซึ่งเป็นคำถามที่คุยต่อได้จริง

และเป็นข่าวดีสำหรับเราด้วย — มีตัวอย่างในโปรเจกต์เดียวกันให้เดินตาม ไม่ต้องออกแบบใหม่

10. สรุป

  • wmsapp มี 110 ไฟล์ 22,095 บรรทัด และ 83% อยู่ใน screens/
  • ตรรกะทางธุรกิจอยู่ในจอ ไม่มีชั้น repository/store
  • แบ่งโฟลเดอร์ตามชนิดไฟล์ แล้วแยกโดเมนภายในอีกชั้น
  • ทุกการกดเดินตามเส้นเดียวกัน: จอ → ApiService → extension → model → setState
  • putaway คือตัวอย่างที่แตกไฟล์แล้ว packing คือตัวอย่างที่ยัง
  • ไม่มีเทสต์เลย — ห้ามแก้อะไรโดยไม่เพิ่มตาข่ายก่อน
  • อ่านตามเส้นทางของหนึ่งการกด อย่าอ่านเรียงตามตัวอักษร
