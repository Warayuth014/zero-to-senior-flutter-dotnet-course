2. Simple fromJson

factory Part.fromJson(Map<String, dynamic> json) => Part(
  partId: json['partId'],
  owner: json['owner'],
  imageUrl: json['imageUrl'],
);

อ่านง่ายแต่ required fieldผิดชนิด/nullจะ throw runtime cast ไม่บอก JSON pathชัดเจน

3. Nested collections

response models map listย่อยด้วย .map(...fromJson).toList() ต้องตรวจ root key missing/null/wrong type, elementไม่ใช่ Mapและ empty list จาก fixtureจริง อย่าเชื่อ response.data!โดยไม่มี contract

4. Naming/casing

DTO keysสะท้อน backendหลาย style เช่น partIdกับ business abbreviations ให้ codecชั้นเดียวรับผิดชอบ ห้ามกระจาย json['...']ใน widgets เพราะ renameหนึ่ง keyจะแก้หลายหน้า

5. Nullability

nullableต้องหมายถึง domainจริง ไม่ใช่ใช้ ?/?? ''เพื่อกลบ server bug Required fieldควร failพร้อม field pathใน repositoryและ UIแสดง contract error ไม่ renderข้อมูลผิดเงียบ ๆ

6. Domain vs DTO

ปัจจุบันหลาย classเป็นทั้ง wire DTOและ UI model ใช้ง่ายแต่ status string/date/number semanticsรั่ว Refactorเฉพาะจุดซับซ้อนให้ DTO parseก่อนแล้ว mapเป็น domain type เช่น enum, Quantity, EntityId

7. Immutability/equality

fieldsส่วนใหญ่ finalแต่ constructorsไม่ const/equalityไม่ได้กำหนด Store/testจึงอาจเปรียบเทียบ identity เพิ่ม value equality/copyWithเมื่อ state architectureต้องใช้ ไม่ทำ mechanical rewriteทุก modelโดยไม่มี consumer

8. Contract checklist

happy fixtureจาก .NET, missing/null/wrong type, unknown status, int/double, Thai/Unicode, UTC/offset, extra fields, empty/nested list และ outbound key names พร้อมผูก OpenAPI/integration testกัน drift
