PartThumbnail เป็นตัวอย่าง dependency ไหลเข้า widget: StatelessWidgetสร้าง ApiService(), resolve relative URLผ่าน FutureBuilder แล้วโหลด Image.network จึงรวม config, async, network, cacheและ presentationในจุดเดียว

1. Input/output

รับ String? imageUrlและ size default 40 ถ้า null/emptyแสดง package icon มิฉะนั้น resolve URL → spinner → network imageหรือ error icon

2. Async path

FutureBuilder<String>(
  future: ApiService().getImageFullUrl(imageUrl!),
  builder: (_, snap) => snap.hasData
      ? Image.network(snap.data!)
      : spinner,
)

3. Rebuild issue

สร้าง Futureใหม่ทุก build ทำให้ parent rebuildจาก search/theme/pollingเริ่ม resolveซ้ำแม้ URLเดิม Futureควร cacheใน State/repositoryหรือ resolutionควร synchronousหลัง config bootstrap

4. URL issue

getImageFullUrlนำ API baseไป replaceAll('/api','')แล้วต่อ relative string เสี่ยง slash/path/hostผิด ใช้ Uri.resolveกับ media baseที่ explicitและ allowlist absolute origin

5. Image memory

กำหนด layout width/heightแต่ไม่ได้ส่ง cacheWidth/cacheHeight decoderอาจเก็บ bitmapต้นฉบับใหญ่สำหรับ thumbnail 40px เพิ่ม decode sizeตาม devicePixelRatioและ versioned cache key

6. Error states

resolve Future errorตอนนี้แสดง spinnerต่อเพราะเช็กเพียง hasData ต้องแยก waiting/error/emptyและ retry ส่วน Image.networkมี errorBuilderแล้วแต่ไม่มี loading progressจาก download

7. Better boundary

PartThumbnail(
  imageUri: mediaPolicy.resolve(part.imageUrl),
  cacheKey: part.imageVersion,
)

widgetรับ presentation-ready valueและ ImageProviderที่ fakeได้ ไม่รู้ ApiService

8. Tests

null/empty, resolving, resolve failure, network failure, parent rebuildเรียก resolverครั้งเดียว, URLเปลี่ยน, theme/list reorderและ decode dimensionsเหมาะกับ PDA
