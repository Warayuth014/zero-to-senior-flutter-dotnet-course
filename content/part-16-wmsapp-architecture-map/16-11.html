โค้ด Dart ไม่ใช่ทั้งแอป: pubspec.yaml, assets/fonts/icons, Android/iOS manifests, Gradle/Xcodeและ generated plugin registrationกำหนดว่า feature compile/รันบน deviceได้จริงหรือไม่

1. SDK/dependencies

pubspecกำหนด Dart ^3.9.2 และใช้ http, shared_preferences, intl, image_picker, material icons, signalr_netcore รวม Flutter localization ทุก packageเพิ่ม platform code, permissions, lifecycleและ supply-chain surface

2. Assets/fonts

fonts/Sarabun-Regular.ttf
fonts/Sarabun-Medium.ttf (500)
fonts/Sarabun-Bold.ttf   (700)
icons/icon-tks-square.png

3. Launcher configuration

flutter_launcher_iconsเปิด Android, ปิด iOSและใช้ icon TKS การแก้ YAMLต้องรัน generatorและ review generated mipmaps ไม่ใช่แก้ assetอย่างเดียว

4. Android

android/app/build.gradle.ktsยังใช้ com.example.wmsappและ release debug signing; main manifestกำหนด label/icon/activityแต่ INTERNETอยู่ debug/profile ไม่ใช่ main ประเด็นนี้ Part 15จัดเป็น production blockers

5. iOS

Info.plistกำหนด display/bundle version/orientationsแต่ยังไม่มี camera/photo usage descriptionsที่ image pickerต้องใช้ และ iOS launcher generationปิด ต้องตรวจ signing/capabilities/ATSบน Mac/deviceจริง

6. Web/desktop boundary

ApiServiceimport dart:ioและ uploadรับ File แม้ resolverเช็ก kIsWeb จึงต้องตรวจ compile targetจริง ไม่ใช่เห็น web foldersแล้วสรุปรองรับทุก feature Conditional adapter/XFileช่วยแยก platform

7. Lock/build inputs

pubspec.lock, analysis options, Gradle wrapper, Podfileและ platform projectเป็น review surface Pin toolchainใน CIและ rebuild from clean checkoutเพื่อจับ native configที่เครื่อง devเคย cache

8. Platform checklist

dependency → Dart usage → plugin docs/version → manifest/plist permission → runtime deny path → release build/signing → device test ทุกครั้งที่เพิ่ม packageที่แตะ camera, storage, network, notificationหรือbackground
