pubspec.yaml เป็น contract ของ package: SDK range, dependencies, version, assets/fonts และ tool config ส่วน pubspec.lock บันทึกเวอร์ชันที่ solver เลือกจริงสำหรับ application

1. โครงที่ต้องอ่านออก

name: wms_mobile
publish_to: none
version: 1.0.0+1
environment:
  sdk: ^3.11.5
dependencies:
  flutter:
    sdk: flutter
  http: ^1.2.2
dev_dependencies:
  flutter_test:
    sdk: flutter
flutter:
  uses-material-design: true

YAML ใช้ indentation เป็นโครงสร้าง ห้ามใช้ tab และ key ที่อยู่ผิดระดับอาจถูก ignore หรือ error

2. dependencies กับ dev_dependencies

package ที่ runtime/import จาก lib อยู่ dependencies; test/lint/codegen/build tooling อยู่ dev_dependencies อย่าย้าย package runtime ไป dev เพียงเพราะ “ใช้ตอนพัฒนา” เพราะ release build ยังต้อง resolve/import

3. สองโปรเจกต์บอก capability

  • wmsapp: http, preferences, intl, image picker, icons, SignalR, Sarabun fonts
  • wms_absolute_mobile: http, Font Awesome, auto-size text, SVG, preferences และ asset icon folder

แค่อ่าน pubspec ก็พอเดา boundary ได้: network, persistence, realtime, files และ localization แต่ต้องตามไปดู usage ก่อนสรุป architecture

4. Pub commands โดยไม่ทำ dependency drift

flutter pub get       # resolve ตาม constraints/lock
flutter pub outdated  # รายงาน current/upgradable/resolvable/latest
flutter pub deps      # dependency graph
flutter pub add http  # แก้ pubspec + get อย่างมีเจตนา

pub upgrade เลื่อน versions ภายใน constraint และเปลี่ยน lockfile จึงควรเป็น commit ที่ review/test ได้ ไม่รันก่อน feature แล้วปน diff

5. Lockfile policy

Flutter application ควร commit pubspec.lock เพื่อ build ซ้ำได้ ส่วน reusable package มี policy ต่างได้ตามทีม เมื่อ conflict lockfile อย่าลบอัตโนมัติ ให้ resolve จาก pubspec ที่ถูกต้องแล้วดูว่าชุด dependency เปลี่ยนอะไร

6. Assets และ fonts

flutter:
  assets:
    - assets/icons/wms/
  fonts:
    - family: Sarabun
      fonts:
        - asset: assets/fonts/Sarabun-Regular.ttf

ไฟล์ต้องมีจริง path/case ต้องตรง โดยเฉพาะ CI/Linux ที่ case-sensitive หลังเพิ่ม asset ให้ pub get และ restart หาก bundle ยังไม่อัปเดต

7. แบบฝึกหัด

จะเพิ่ม mocktail สำหรับ test และรูป assets/images/logo.png ต้องแก้ส่วนใดและ commit อะไรบ้าง?

เฉลย

เพิ่ม mocktail ใน dev_dependencies, เพิ่ม asset path ใต้ flutter, วางไฟล์จริง, รัน pub get และ commit pubspec + lockfile + asset จากนั้น analyze/test และเปิด UI ยืนยัน bundle

8. จุดพลาด

อย่าใช้ version any หรือ dependency override ถาวรเพื่อให้ solver ผ่าน เพราะคุณกำลังย้าย incompatibility ไป runtime/คนอื่นแทนการแก้ constraint
