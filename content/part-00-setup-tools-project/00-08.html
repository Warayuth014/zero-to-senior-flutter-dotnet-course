Analyzer ตรวจ syntax, type flow, API misuse และ lint โดยไม่ต้องรันทุก path analysis_options.yaml คือ policy ที่ทำให้ IDE, local CLI และ CI ตัดสินโค้ดด้วยกติกาเดียวกัน

1. รันจาก root ที่ถูกต้อง

flutter pub get
flutter analyze

ต้องรันในโฟลเดอร์ที่มี pubspec ของ app ถ้า monorepo มีหลาย package ให้ analyze แต่ละ packageหรือมี workspace script ไม่รันจาก parent แล้วคิดว่าครบ

2. Severity และความหมาย

  • Error: compile/type resolution ผิด ต้องแก้
  • Warning: มีโอกาส bug/โค้ดผิด intent
  • Info/lint: rule ที่ทีมเปิด อาจบังคับใน CI

อย่าวัดคุณภาพด้วยจำนวนสีอย่างเดียว อ่าน rule และ failure scenario เช่น use_build_context_synchronously ชี้ lifecycle risk หลัง await

3. analysis_options จริง

สองโปรเจกต์ include package:flutter_lints/flutter.yaml แล้วมีพื้นที่เพิ่ม/ปิด rule เฉพาะทีม ความต่างคือ wmsapp ใช้ flutter_lints 5.x ส่วน absolute ใช้ 6.x จึงไม่ควร copy baseline โดยไม่ดู SDK/package compatibility

include: package:flutter_lints/flutter.yaml

linter:
  rules:
    avoid_print: true

4. Ignore อย่างรับผิดชอบ

// ignore: use_build_context_synchronously -- mounted checked by owner
navigate(context);

ตัวอย่างเหตุผลข้างบนยังไม่พอถ้าไม่ได้ตรวจจริง หลักคือแก้ต้นเหตุก่อน; ถ้าจำเป็นต้อง suppress ให้ scope เล็ก, ใส่เหตุผล และมี test/review อย่าใช้ ignore_for_file เพื่อซ่อน debt ทั้งไฟล์

5. Analyze ไม่แทน tests/build

Analyzer ไม่รู้ว่า JSON production เปลี่ยน, API endpoint ถูก, layout overflow บนอุปกรณ์ หรือ native manifest ครบ จึงต้องต่อด้วย unit/widget/contract tests และ build/run target จริง

6. แก้เป็นลำดับ

  1. pub/URI/import errors
  2. syntax/type errors ต้นทาง
  3. null/async/lifecycle warnings
  4. lints และ cleanup
  5. รัน analyze ใหม่ทั้ง package ไม่เฉพาะไฟล์

Error หนึ่งจุดอาจทำให้เกิด cascade หลายสิบรายการ อย่าแก้ปลายทีละบรรทัดก่อนต้นเหตุ

7. แบบฝึกหัด

สมมติ analyzer เตือนใช้ BuildContext หลัง await และ unused import จัดลำดับ/แนวแก้

เฉลย

แก้ lifecycle risk ก่อนโดยตรวจ mounted, restructure navigation หรือย้าย side effect ให้ owner ที่อยู่รอด แล้วลบ unused import/format จากนั้น analyze และ test flow back-navigation เพื่อพิสูจน์ว่าไม่แตะ context หลัง dispose

8. Definition of clean

คำว่า analyze ผ่านต้องระบุ SDK/package, command/root และผล exit code ไม่ใช่เพียง IDE ไม่มีเส้นแดง เพราะ IDE อาจใช้ SDK หรือ scope คนละชุด
