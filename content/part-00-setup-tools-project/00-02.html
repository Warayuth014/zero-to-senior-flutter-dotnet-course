Flutter แต่ละ release ผูก Dart SDK ที่รองรับมาแล้ว ส่วนโปรเจกต์กำหนดช่วง Dart ใน environment.sdk และบันทึก dependency resolution ใน lockfile ทั้งสามชั้นต้องเข้ากัน

1. อ่าน version 4 จุด

  1. flutter --version: SDK global ที่ shell กำลังใช้
  2. pubspec.yaml → environment.sdk: ช่วง Dart ที่ source อนุญาต
  3. pubspec.lock: package versions ที่ resolve จริง
  4. CI/README/version manager config: SDK ที่ทีมตั้งใจใช้

ตัวอย่างจริง wmsapp ใช้ sdk: ^3.9.2 จึงรันกับ Dart 3.11.5 ได้ตามช่วง semver ขณะที่ wms_absolute_mobile ใช้ ^3.11.5 และต้องการ baseline ใหม่กว่า

2. Channel คือระดับความเสถียร

stable เหมาะกับงาน production; channel อื่นเหมาะทดสอบ feature/compatibility ตามนโยบายทีม การเปลี่ยน channel หรือ flutter upgrade เปลี่ยน SDK global และอาจกระทบทุก repo ที่ใช้ path เดียวกัน

flutter channel
flutter --version
# อย่า upgrade กลางงานโดยไม่อ่าน diff/ทดสอบทั้งโปรเจกต์

3. Pinning strategy

  • ขั้นต่ำ: บันทึก Flutter/Dart baseline ใน README และ CI
  • ดีกว่า: ใช้ version manager เช่น FVM แล้ว commit config ของเวอร์ชัน
  • CI: ระบุ Flutter version ไม่ใช้ “latest” แบบลอย
  • ทีม: upgrade เป็นงานแยกพร้อม analyze/test/build ไม่ปน feature change

คอร์สนี้บันทึก source snapshot และ baseline เพื่อให้รู้ว่าคำอธิบายอ้างโค้ด/SDK ชุดใด

4. SemVer และ caret แบบที่ต้องรู้

^3.11.5 โดยทั่วไปยอมรับตั้งแต่ 3.11.5 จนก่อน 4.0.0 แต่ package solver ยังต้องหาชุดที่ทุก dependency ยอมรับพร้อมกัน SDK ใหม่ไม่ได้รับประกันว่า package เก่าทุกตัวรองรับ

5. วินิจฉัย version mismatch

flutter pub get
flutter pub deps
flutter pub outdated
  1. อ่านข้อความ solver ตั้งแต่ package แรกที่ขัด
  2. ตรวจ Dart/Flutter constraint ของ root และ dependency
  3. อย่าแก้ด้วยการลบ constraint หรือใช้ dependency_overrides ถาวรโดยไม่ทดสอบ
  4. ถ้า upgrade SDK ให้ดู breaking changes และรัน checks ทุก target

6. IDE ต้องใช้ SDK เดียวกัน

ถ้า analyzer ใน IDE แดงแต่ CLI ผ่าน ให้ตรวจ Flutter SDK path และ restart analysis server ส่วน terminal ใหม่อาจใช้ PATH ใหม่ต่างจาก terminal เก่า ใช้ where flutter เป็นหลักฐาน ไม่เดาจาก icon ของ IDE

7. แบบฝึกหัด

ตอบว่า Dart 3.10 เปิดสองโปรเจกต์นี้ได้หรือไม่ และถ้าจะเพิ่ม syntax ที่ต้อง Dart 3.11 ลง wmsapp ต้องทำอะไร

แนวคำตอบ

Dart 3.10 อยู่ในช่วงของ wmsapp ^3.9.2 แต่ต่ำกว่า minimum ของ absolute ^3.11.5 ส่วนการเพิ่ม feature 3.11 ใน wmsapp ต้องยก minimum constraint, pin Flutter ที่ bundle Dart รองรับ, อัปเดต CI/docs และทดสอบ consumers ไม่ใช่แค่เขียน syntax แล้ว commit

8. จุดพลาด

“เครื่องผมรันได้” ไม่ใช่ version policy ถ้า repo ไม่บันทึก SDK baseline และ CI ไม่ pin คนถัดไปอาจ resolve dependency คนละชุดและได้ behavior ต่างกัน
