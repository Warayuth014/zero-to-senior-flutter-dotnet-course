อ่าน Flutter repo ให้เริ่มจาก source of truth ไม่หลง generated artifacts: lib/, test/, pubspec.yaml, assets และ platform config ที่ตั้งใจแก้ ส่วน .dart_tool//build/ เป็นผลลัพธ์

1. แผนที่ root

Pathหน้าที่ปกติ commit?
lib/Dart source ของ appใช่
test/unit/widget tests + fixturesใช่
assets/รูป/font/static filesใช่
android/ios/web/windowsrunner/build/permission/platform codeใช่เมื่อ target นั้นรองรับ
.dart_tool/, build/generated/cache/outputไม่

2. เริ่มอ่านจาก main ไม่ใช่เรียงชื่อไฟล์

  1. เปิด lib/main.dart
  2. ดู async bootstrap ก่อน runApp
  3. เปิด root widget/MaterialApp
  4. ตาม initial screen/application shell
  5. จาก user action ตาม state owner → repository/client → model

วิธีนี้ให้ dependency graph และ runtime order แทนการอ่านทุกไฟล์โดยไม่รู้คำถาม

3. โครง wmsapp

มี screens/, services/, models/, widgets/, theme/ แบบ layer-ish และ screen-centric หลาย flow API extensions รวมผ่าน ApiService singleton ตัวอย่างนี้อ่าน UI flow ง่าย แต่บางหน้าถือ state/business logic มาก

4. โครง absolute

มี core/, api/, features/auth, features/settings, features/warehouse ภายใน warehouse แยก model/screen/ui/store/workflow ชัดกว่า และมี repository interfaces/fakes/tests เป็น seam

5. Platform folders ไม่ใช่ boilerplate ทั้งหมด

  • Android manifest: permission, application config, cleartext/network
  • Gradle: application id, SDK, signing, plugins
  • iOS plist/project: permission strings, bundle/build
  • web index/manifest: bootstrap/PWA metadata
  • Windows runner: native host/product metadata

อ่านเฉพาะ target ที่เกี่ยวข้อง แต่ห้ามลบทิ้งเพราะคิดว่า generated ทั้งหมด

6. Test กับ source ต้องเดินคู่กัน

เมื่อพบ repository/store ให้ค้นชื่อ class/method ใน test/ ทันที Tests บอก expected behavior และ edge cases เร็วกว่าคอมเมนต์ ส่วน test screen ที่อยู่ใน lib/screens/test ของ wmsapp เป็น runtime diagnostic UI ไม่ใช่ automated test ต้องแยกให้ออก

7. แบบฝึกหัด

ใช้ rg --files lib test และวาด startup map ของสองแอปถึงหน้าแรก พร้อมระบุ dependency ที่สร้างก่อน runApp

แนวตรวจคำตอบ

wmsapp binding → WmsApp → theme listener → MaterialApp → HomeScreen; absolute binding → load language → load connection → system UI → AuthRepository(ApiClient) → WmsApp → LoginScreen ต้องบอกด้วยว่า absolute ห้ามยิง request ก่อน connection load ตาม comment/invariant

8. จุดพลาด

อย่า review ไฟล์ใน build/ หรือ .dart_tool/ เพื่อเข้าใจ business logic และอย่าแก้ generated file โดยไม่มี source/generator เพราะ regeneration จะลบงาน
