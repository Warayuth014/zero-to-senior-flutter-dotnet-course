flutter create สร้าง Dart package และ platform runners ที่เข้าชุดกัน ให้ตัดสินชื่อ package, organization และ target platforms ก่อนเริ่ม เพราะชื่อเหล่านี้ไหลไป Android applicationId, iOS bundle id และ namespace

1. สร้างโปรเจกต์อย่างมีเจตนา

flutter create \
  --org com.example.wms \
  --platforms=android,web,windows \
  --project-name wms_mobile \
  wms_mobile

ชื่อ Dart package ใช้ lowercase_with_underscores ไม่ใช้ dash ส่วนชื่อโฟลเดอร์และ product display name ปรับภายหลังได้ แต่ application/bundle identity มีผลต่อการติดตั้งและ store

2. ผลลัพธ์สำคัญ

  • lib/main.dart: entry point ตัวอย่าง
  • pubspec.yaml: metadata, SDK, dependencies, assets
  • analysis_options.yaml: analyzer/lints
  • test/: test ตัวอย่าง
  • android/ios/web/windows/...: runner/build config ของแต่ละ platform
  • .gitignore: generated artifacts ที่ไม่ควร commit

3. App, package และ plugin ต่างกัน

flutter create app_name
flutter create --template=package shared_domain
flutter create --template=plugin --platforms=android,ios scanner_plugin

คอร์สนี้สร้าง app เพราะมี UI/runner; package เหมาะ pure Dart/Flutter library; plugin มี platform implementation อย่าเลือก plugin เพียงเพราะแอปใช้ hardware scanner—keyboard wedge scanner อาจไม่ต้อง native plugin

4. จำกัด platform เพื่อลด noise

ถ้า production มีแค่ Android การสร้างทุก platform เพิ่มไฟล์ที่ไม่มีใครทดสอบ แต่การเก็บ web/windows อาจมีค่ากับ dev/debug ต้องตัดสินจาก workflow ทีม ไม่ใช่ลบเพราะ “ดูเยอะ” โดยไม่รู้ target

5. อย่ารัน create ทับแบบไม่ตรวจ diff

flutter create . ใช้เติม platform files ที่หายหรือ migrate template ได้ แต่จะเปลี่ยน generated/runner config หลายไฟล์ ก่อนใช้ใน repo จริงต้อง clean worktree, บันทึก SDK version, ดู diff และทดสอบ build target เพราะ config signing/manifest/custom native code อาจได้รับผล

6. First-run checklist

cd wms_mobile
flutter pub get
flutter analyze
flutter test
flutter run -d windows  # หรือ device id ที่เลือก

commit แรกควรผ่านก่อนเพิ่ม package เพื่อให้รู้ว่า environment/template ทำงาน หากเริ่มด้วย dependency 20 ตัวแล้ว build พังจะหาต้นเหตุยาก

7. แบบฝึกหัด

ออกแบบคำสั่งสร้างแอป PDA ชื่อ warehouse_pda สำหรับ Android และ Windows ภายใต้ organization ของบริษัท พร้อมบอกไฟล์สามจุดที่จะเปลี่ยน product identity ภายหลัง

แนวคำตอบ
flutter create --org com.company.wms \
  --platforms=android,windows \
  --project-name warehouse_pda warehouse_pda

ตรวจ pubspec metadata/version, Android Gradle/manifest application identity และ Windows runner/resource/product settings; ชื่อไฟล์จริงขึ้นกับ template เวอร์ชันจึงดู diff จาก SDK ที่ pin

8. จุดพลาด

อย่าคัดลอกโฟลเดอร์โปรเจกต์เก่าแล้ว rename ทุก string เพื่อเริ่มแอปใหม่ เพราะจะพา application id, signing, generated cache และ dependency debt เดิมติดมาด้วย
