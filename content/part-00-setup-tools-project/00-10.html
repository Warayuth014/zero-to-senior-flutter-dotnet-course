Debug, profile และ release เป็น build/runtime modes คนละวัตถุประสงค์ ผล performance, assertions, service extensions และ optimization ต่างกัน จึงต้องเลือก mode ให้ตรงคำถาม

1. เปรียบเทียบสาม mode

Modeเด่นใช้เมื่อ
Debugassert, debugger, hot reload, diagnosticsพัฒนา/functional debugging
Profileoptimization ใกล้ release + profiling hooksวัด frame/CPU/memory บนอุปกรณ์จริง
Releaseoptimization/deployment, diagnostics จำกัดfinal behavior/build artifact

2. คำสั่ง

flutter run -d <device>                 # debug
flutter run --profile -d <device>
flutter run --release -d <device>
flutter build apk --release
flutter build appbundle --release

target บางชนิด/platform มีข้อจำกัด mode ให้เชื่อ output ของ tooling รุ่นที่ pin และทดสอบบน production target

3. Assertions และค่าที่ไม่ควรพึ่ง

assert เหมาะจับ programmer invariant ระหว่างพัฒนา ไม่ใช้ validate barcode, auth หรือ API payload ที่ production ต้องป้องกัน เพราะ release อาจไม่รัน assertion Business validation ต้องเป็น code path ปกติ

4. Performance measurement

Debug มี JIT/instrumentation และอาจช้ากว่าอย่างมาก อย่า optimize จากความรู้สึกใน debug ให้ reproduce บน physical target ด้วย profile, record timeline และเทียบก่อน/หลังด้วย workload เดิม

5. Environment ไม่ควรผูกกับ mode อัตโนมัติ

Debug ไม่ได้แปลว่าต้องยิง test server และ release ไม่ได้แปลว่า production เสมอ ให้ environment/base URL เป็น config ที่ explicit เช่น dart-define/connection profile และแสดงให้ operator รู้ ป้องกัน release build ชี้ server ผิด

6. Mode-specific code

Flutter มี flags เช่น debug/profile/release แต่ใช้ให้น้อยและกักไว้ใน diagnostics/config อย่ากระจาย branch behavior จน happy path ใน debug ต่างจาก release การ log sensitive data แม้อยู่ debug ก็ยังเสี่ยงเมื่อใช้เครื่องจริง

7. แบบฝึกหัด

อาการ list กระตุกเฉพาะ PDA และ API ชี้ผิด server ใน APK ควรตรวจด้วย mode/config ใด?

เฉลย

วัดกระตุกด้วย profile บน PDA จริงและ workload เดิม ส่วน server ผิดให้ตรวจ build/runtime configuration, dart-define/profile persistence และ URL ที่ resolve จริงใน release ไม่แก้ด้วย assert หรือ hardcodeตาม mode

8. จุดพลาด

“ผ่าน debug” ยังไม่พอสำหรับ permission, minification/tree shaking, signing, network security และ performance ต้องมี release smoke test บนอุปกรณ์เป้าหมายก่อนส่งงาน
