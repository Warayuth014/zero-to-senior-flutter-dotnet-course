Formatter ทำให้ diff อ่าน logic, debugger พิสูจน์ค่าระหว่างทาง และ DevTools พิสูจน์ runtime behavior ทั้งสามอย่างลดการเดาจาก print แต่แก้คนละชั้น

1. Format เป็น deterministic tool

dart format lib test
dart format --output=none --set-exit-if-changed lib test

คำสั่งแรกแก้ไฟล์ คำสั่งหลังเหมาะกับ CI เพื่อตรวจโดยไม่แก้ อย่าจัดบรรทัดด้วยมือแข่ง formatter และควร format เฉพาะ source ที่ทีมตั้งใจ ไม่รวม generated/vendor แบบสุ่ม

2. Breakpoint ดีกว่า print ตอนไหน

  • ต้องดู call stack ว่า callback มาจากใคร
  • ต้อง inspect object/collection โดยไม่แก้ source
  • ต้อง step ผ่าน branch/await
  • ต้องจับ exception ตรงจุด throw ก่อนถูกแปลงเป็นข้อความ

ตั้ง conditional breakpoint เช่นหยุดเฉพาะ barcode ที่ซ้ำ ช่วย debug flow scanner โดยไม่จมกับ event ทุกครั้ง

3. Async debugging

หลัง await stack ทางตรรกะยังสำคัญกว่า thread แบบ synchronous ดู Futures/async call stack และ request generation อย่ากด step อย่างเดียวจนลืมว่า user event ใหม่อาจเข้ามาระหว่างรอ

4. เปิด DevTools

รันแอปแบบ debug/profile แล้วเปิดลิงก์ DevTools จาก CLI/IDE หรือใช้คำสั่งที่ tooling แสดง Panels สำคัญ:

Panelใช้ตอบคำถาม
Inspectorwidget/constraints/layout มาจากไหน
Performanceframe ไหนช้า งาน CPU/build/layout/paint
Memorycontroller/subscription/image/object รั่วไหม
Networkrequest timing/status/payload ตาม platform ที่รองรับ
Debugger/Loggingstack, variables, structured events

5. Debug paint/rebuild อย่างมีสมมติฐาน

เปิด tracking เฉพาะตอนต้องตอบว่า widget ใด rebuild/layout/paint มาก อย่าทิ้ง debug flags ไว้ใน production และอย่าสรุป performance จาก debug mode เพราะ instrumentation/JIT ต่างจาก profile/release

6. Logging ที่ปลอดภัย

ใช้ logger/dev log พร้อม category/correlation id และระดับ severity ไม่ print token/password/request body ทั้งก้อน สำหรับ WMS log ควรบอก action, entity id ที่ไม่ลับ, endpoint/status/duration และ sanitized error เพื่อ trace Flutter ↔ .NET ได้

7. แบบฝึกหัด

Login กดแล้ว loading ค้าง: วาง breakpoint/inspection จุดใดบ้าง?

แนวคำตอบ
  1. callback ก่อน guard/validation
  2. จุดตั้ง loading=true
  3. ก่อน/หลัง repository await
  4. ApiClient ก่อนส่งและหลัง response/exception
  5. finally ที่คืน loading
  6. ตรวจ mounted/notify/setState และ rendered widget

8. จุดพลาด

อย่าแก้ bug ด้วยการใส่ print ทุกบรรทัดแล้วลืมลบ เพราะ log เปลี่ยน timing ของ race, เปิดข้อมูล และยังไม่บอก object ownership/call stack เท่า debugger
