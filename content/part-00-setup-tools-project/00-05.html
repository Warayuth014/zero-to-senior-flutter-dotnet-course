Hot reload, hot restart และ full restart มีผลต่อ state/native process ต่างกัน การเลือกผิดทำให้เสียเวลาหรือหลงเชื่อว่าโค้ดใหม่ทำงานทั้งที่ initialization เดิมยังค้างอยู่

1. Hot reload

inject Dart code ใหม่เข้า VM แล้ว rebuild widget tree โดยพยายามรักษา State object และค่าตัวแปร runtime เดิม เหมาะกับแก้ build, layout, style และ pure method ระหว่าง debug

# ระหว่าง flutter run
r  # hot reload

main() และ initState() ที่รันไปแล้วมักไม่รันใหม่ ถ้าแก้ default field แต่ instance เดิมยังอยู่ อาจเห็นค่าเก่า

2. Hot restart

รีสตาร์ต Dart isolate และรัน main() ใหม่ จึงทิ้ง in-memory app state แต่ไม่ rebuild/reinstall native app ทั้งหมด เหมาะเมื่อแก้ bootstrap, singleton initialization, initial route หรือ state schema

R  # hot restart

3. Full restart/rebuild

หยุด process แล้ว run/build ใหม่ ใช้เมื่อเปลี่ยน native/plugin/Gradle/manifest/Info.plist, asset บางประเภท, generated registration หรืออาการค้างจาก native state

q
flutter run -d <device-id>

flutter clean ไม่ใช่ ritual แรก เพราะลบ build cache และทำให้รอบถัดไปช้า ใช้เมื่อมีหลักฐานว่า artifact/cache ไม่ตรง ไม่ใช้กลบ compile error

4. ตัวอย่างจากสอง main()

wmsapp/main.dart เรียก binding แล้ว runApp เกือบทันที ส่วน absolute ต้อง await language และ connection profile ก่อน request แรก ถ้าแก้ลำดับ bootstrap ใน absolute ต้อง hot restart อย่างน้อย ไม่ใช่ hot reload แล้วสรุปผล

5. การเปลี่ยนที่ reload ไม่รองรับดี

  • เปลี่ยน enum/class shape หรือ generic signature ที่ instance เดิมใช้อยู่
  • เปลี่ยน global/static initializer
  • เปลี่ยน platform channel/plugin/native permission
  • แก้ dependency/pubspec แล้วไม่ได้ pub get/restart

CLI จะแจ้งเมื่อ reload ถูกปฏิเสธ อ่านข้อความก่อน clean ทั้ง repo

6. State illusion

หน้าจอสแกนอาจมี list/controller/loading จากก่อนแก้ code ค้างหลัง reload ให้สร้าง reproduction ใหม่หรือ restart ก่อนยืนยัน bug fix โดยเฉพาะ lifecycle/race/initialization tests

7. แบบฝึกหัด

เลือกวิธีสำหรับ: เปลี่ยนสี Text, เปลี่ยน base URL ที่โหลดใน main, เพิ่ม Android permission, และแก้ method validate ของ object ที่มีอยู่

เฉลย
  • สี Text: hot reload
  • bootstrap base URL: hot restart
  • Android permission: full restart/rebuild และอาจ reinstall
  • method validate: reload ได้ แต่สร้าง flow ใหม่เพื่อไม่ให้ state เดิมบิดผล

8. จุดพลาด

อย่าใช้ผลหลัง hot reload เป็นหลักฐานของ cold start, persisted session, migration หรือ app lifecycle เพราะมันตั้งใจรักษา state ที่ production launch จะไม่มี
