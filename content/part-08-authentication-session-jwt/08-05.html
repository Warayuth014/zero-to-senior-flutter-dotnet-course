Remember session คือ restore credential ไม่ใช่จำหน้า UI: เก็บเฉพาะข้อมูลที่ต้องใช้ยืนยันตัวตน แล้ว rebuild user/session state จาก storage อย่างปลอดภัยตอนเปิดแอป

1. Persistence choices

access/refresh token เป็น secret ควรอยู่ secure storage ของ platform; username, locale หรือ active server profileที่ไม่ลับอาจอยู่ SharedPreferences ตาม data classification

2. Stored envelope

{
  "schemaVersion": 1,
  "serverId": "warehouse-prod",
  "username": "EMP001",
  "expiresAt": "2026-08-15T10:00:00Z"
}

เก็บ token ด้วย secure key แยกหรือตาม abstraction และ bind session กับ server

3. Atomic save

อย่าให้ memory session authenticated ก่อน token persist สำเร็จหาก product ต้อง remember login กำหนด policy เมื่อ secure storage เขียนไม่ได้: session ชั่วคราวหรือ fail login พร้อมข้อความที่ชัด

4. Restore validation

  1. อ่าน storage และ schema
  2. ตรวจ server binding
  3. ตรวจ expiration/required fields
  4. ตั้ง token ใน client
  5. อาจเรียก profile/me เพื่อยืนยันกับ server
  6. ค่อยประกาศ authenticated

5. Corrupt/migrated data

parse failure ไม่ควร crash splash screen ให้ลบเฉพาะ auth keys ที่เสียและกลับ login พร้อม telemetry ไม่ใช้ prefs.clear() เพราะอาจลบ theme/server settings ที่ไม่เกี่ยวข้อง

6. ของจริง

wmsapp/AuthSessionService โหลด userId/fullName/role จาก preferences แต่ไม่มี bearer token นี่คือ remembered demo identity ไม่ใช่ server-authenticated session

7. แบบฝึกหัด

แอปเปิดแล้วพบ token expired แต่ยังมี username ควรเข้า shell ไหม?

เฉลย

ไม่ ให้ล้าง credential/auth state และไป login โดยอาจ prefill username ที่จัดเป็น non-secret ได้

8. Test matrix

ไม่มีข้อมูล, valid, expired, corrupt JSON, schema เก่า, secure storage error, server mismatch และ logout หลัง restore
