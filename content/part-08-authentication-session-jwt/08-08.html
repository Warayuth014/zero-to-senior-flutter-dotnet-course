Logout คือ security transition ทั้งระบบ: หยุดงาน, ล้าง credential และ user-scoped state, invalidate navigation แล้วค่อยกลับ login—not merely pop route

1. ลำดับที่ปลอดภัย

  1. เปลี่ยน auth state เป็น signingOut และเพิ่ม generation
  2. หยุด polling/timer/subscription
  3. cancel หรือ ignore in-flight response
  4. ล้าง feature/user caches
  5. ลบ secure credential และ token ใน memory
  6. แทน route stack ด้วย login

2. API revoke

ถ้ามี refresh token/server session ให้เรียก revoke แบบ best effort ตาม product policy แต่ local logout ต้องสำเร็จแม้ offline; server token อายุสั้นช่วยลดช่วงเสี่ยง

3. Clear เฉพาะ scope

ลบ auth keys, selected task และ user data แต่อาจเก็บ theme/language; connection profile จะเก็บหรือไม่ขึ้นกับ threat model อย่าใช้ SharedPreferences.clear() โดยไม่รู้ ownership

4. Navigation reset

Navigator.of(context).pushAndRemoveUntil(
  MaterialPageRoute(builder: (_) => LoginScreen(auth: auth)),
  (_) => false,
);

กด Back แล้วต้องไม่กลับ authenticated screen

5. Stale response guard

ทุก async store action จับ session generation/user ID ตอนเริ่มและตรวจอีกครั้งก่อน apply state ป้องกันข้อมูลผู้ใช้ A โผล่หลังผู้ใช้ B login

6. ของจริง

AuthRepository.logout() ในแอปจริงล้าง token/session memory ส่วน WarehouseShell reset route; production extension ต้องรวม persistence, timers และ feature storesด้วย

7. แบบฝึกหัด

secure storage ลบ token ไม่สำเร็จควรอยู่ shell ต่อไหม?

เฉลย

ไม่ ให้ล้าง memory/route ทันทีและ retry secure deletion หรือ block restore ด้วย tombstone/version เพื่อไม่ฟื้น token เก่าโดยเงียบ

8. Exit checklist

Back กลับไม่ได้, request เก่าเปลี่ยน state ไม่ได้, token/log/cache ไม่มีข้อมูลผู้ใช้เดิม และเปิดแอปใหม่ไม่ restore session ที่ logout แล้ว
