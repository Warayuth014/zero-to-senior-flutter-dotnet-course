Lab ปิด Part 8: ทำ login/logout กับ fake backend และ in-memory secure store เพื่อพิสูจน์ session lifecycle โดยไม่ใช้ network จริงหรือ secret จริง

1. Acceptance criteria

  • LoginScreen ไม่มี HTTP/storage logic
  • repository parse token/expiration เป็น AuthSession
  • ApiClient แนบ Bearer เฉพาะ authenticated route
  • bootstrap restore ก่อน feature request
  • 401 หลาย request logout ครั้งเดียว
  • logout ล้าง token/cache/routes
  • server switch ไม่รั่ว token

2. Fake backend

final http = MockClient((request) async {
  if (request.url.path == '/api/Authenticate/login') {
    return Response('{"token":"test-token",'
      '"expiration":"2099-01-01T00:00:00Z"}', 200);
  }
  expect(request.headers['Authorization'], 'Bearer test-token');
  return Response('{"items":[],"totalCount":0}', 200);
});

3. Fake token store

class MemoryTokenStore implements TokenStore {
  String? value;
  Future<String?> read() async => value;
  Future<void> write(String token) async => value = token;
  Future<void> delete() async => value = null;
}

4. Core tests

  1. valid login sets session/header
  2. 401 invalid credential ไม่ persist
  3. malformed expiration เป็น contract error
  4. restore valid/expired/corrupt
  5. logout ระหว่าง in-flight request
  6. 403 ไม่ logout
  7. token marker ไม่อยู่ log

5. Widget tests

กรอก form → submit ครั้งเดียว → loading disable → fake success เข้า shell; fake failure แสดงข้อความและ passwordไม่ถูก log/persist; logout reset routeจน Back เข้า shellไม่ได้

6. Integration seam

เมื่อ unit testsผ่าน เปลี่ยน fake backendเป็น Minimal .NET login fixtureใน environmentทดสอบ โดยใช้ test signing key/credentialชั่วคราว ห้าม commit production secret

7. Review questions

  • ใครเป็น owner ของ session?
  • request แรกเกิดหลัง restoreจริงไหม?
  • 401/403 ต่างกันไหม?
  • storage/server bindingครบไหม?
  • responseเก่าข้าม logoutได้ไหม?

8. Exit test

อธิบายและทดสอบได้ครบ Login → Session → Bearer → Expire/401 → Logout/Restore/Server switch โดย passwordไม่ persist, tokenไม่รั่ว และ .NETยังเป็นผู้บังคับสิทธิ์จริง
