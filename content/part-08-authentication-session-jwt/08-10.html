Storage เลือกตามความลับ: SharedPreferences เหมาะ setting ทั่วไป ไม่รับประกัน secrecy; token/password/private key ใช้ platform-backed secure storage และออกแบบ lifecycle เพิ่มเติม

1. SharedPreferences

เหมาะ locale, theme, onboarding และ connection profileที่องค์กรยอมรับให้เก็บแบบ application preferences ข้อมูลอาจอยู่ไฟล์ readable บนอุปกรณ์ที่ compromise/backup

2. Secure storage

plugin secure storage ใช้ Android Keystore/iOS Keychain เพื่อปกป้อง encryption key/secret ตาม platform แต่ไม่ทำให้อุปกรณ์ rooted หรือ app process ที่ถูกยึดปลอดภัยสมบูรณ์

3. Never persist password

เก็บ access/refresh token ตาม policy ไม่เก็บ password เพื่อ auto-login; ถ้าต้อง re-auth ใช้ refresh flow, biometric-gated secret หรือ identity platform ที่ออกแบบมา

4. Data classification table

  • token/refresh token: secure storage
  • username: preferences ได้ถ้า policy อนุญาต
  • roles/profile cache: preferences ได้แต่ไม่เป็น security authority
  • password: ไม่ persist
  • server URL: preferences/managed config ตาม threat model

5. Backup และ reinstall

Android backup/key invalidation, device lock change และ reinstall อาจทำ decrypt ไม่ได้ Storage abstraction ต้องแปลงเป็น recoverable signed-out state ไม่ crash

6. Namespace และ selective delete

ใช้ key prefix/version เช่น auth.v1.accessToken และ delete เฉพาะ auth keys ตอน logout/migration ป้องกันชนกับ setting และคอร์สอื่น

7. แบบฝึกหัด

แอป mock เก็บ userId/role ใน preferences แล้วถือว่า authorize ได้หรือไม่?

เฉลย

ไม่ได้ ผู้ใช้/เครื่องมืออาจแก้ค่าได้ ใช้เพื่อ UI demo/cache เท่านั้น; production serverต้อง validate signed tokenและ policy

8. Security tests

ตรวจ repo/log/crash report/preferences backup ว่าไม่มี password/token marker และทดสอบ storage read/write/delete failure โดยไม่คืน secret ใน error
