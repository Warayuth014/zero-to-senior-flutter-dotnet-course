StatefulShellRoute: แต่ละ branchมี Navigatorของตนเอง จึงรักษา stack/scroll/stateเมื่อตัดสลับ Home, TasksและSettingsเหมือนแอป production

1. indexedStack

constructorสำเร็จรูปเก็บ branch widgetsใน IndexedStackและแสดง branchปัจจุบัน เหมาะ bottom navigationมาตรฐาน

2. Branch keys

GlobalKeyแยก navigatorช่วย debug/parentNavigatorKey/restoration แต่สร้างครั้งเดียว ห้ามสร้างใหม่ใน build

3. navigationShell

Shellวาง objectนี้เป็น bodyและอ่าน currentIndex จากนั้นเรียก goBranch(index) แทน context.go pathแบบ hard-code

4. Tap tabเดิม

navigationShell.goBranch(index,
  initialLocation: index == navigationShell.currentIndex);

แตะแท็บเดิมกลับ root branchตาม patternที่กำหนด

5. Preserve stack

เปิด TASK-001→Home→Tasksแล้วกลับ detailเดิม Routing testพิสูจน์ behaviorนี้ ไม่ใช่แค่คาดจาก IndexedStack

6. Memory trade-off

หลาย branchเก็บ state/widgetมากขึ้น ใช้ preload/lazyอย่างเข้าใจและอย่าเริ่ม pollingทุก branchโดยไม่ดู visibility/lifecycle

7. Realtime subscriptions

routeยัง mountedแต่ไม่ visible อาจยังรับ events Controllerควรมี policy pause/reconcileเมื่อกลับมา ไม่พึ่ง disposeอย่างเดียว

8. Checkpoint

แยก “รักษา navigation stack” จาก “รักษา fresh data” StatefulShellRouteแก้เรื่องแรก ส่วน store/repository lifecycleต้องแก้เรื่องสอง
