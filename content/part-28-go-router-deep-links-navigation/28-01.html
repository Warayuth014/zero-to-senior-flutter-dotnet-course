Navigation mental model: Navigatorจัด stackของ Route ส่วน Routerแปลงข้อมูลตำแหน่ง/URLและ app stateให้เป็น page stack ที่สอดคล้องกัน ทั้งสองทำงานร่วมกัน ไม่ใช่เลือกได้เพียงอย่างเดียว

1. Navigator 1.x

push(MaterialPageRoute) เหมาะ flowเฉพาะจุดและ dialog แต่เส้นทางไม่ได้เป็นข้อมูลกลาง จึง restore/deep link/browser historyยากเมื่อแอปมีหลาย stack

2. Router API

RouterInformationParserอ่าน URL, RouterDelegateสร้าง pagesและ Navigator render stack Package go_router ครอบ plumbingนี้ด้วย route treeและ URL matching

3. Page-backed กับ pageless

GoRouteสร้าง page-backed routesที่ deep-linkได้ ส่วน dialog/bottom sheetจาก imperative APIเป็น pagelessและอาจถูกถอดเมื่อ pageใต้ถูกแทนด้วย deep linkใหม่

4. URL คือ state

/tasks/TASK-001?source=email บอก resourceและ contextที่ serialize/share/restoreได้ ต่างจาก objectใน memoryที่หายเมื่อ processตาย

5. ใช้ Navigator ตอนไหน

modalชั่วคราว, pickerหรือ flowที่ไม่ควร bookmarkยังใช้ push/showDialogได้ ส่วนหน้าหลัก/detail/searchที่ผู้ใช้เปิดตรงควรมี URL contract

6. หลาย Navigator

bottom navigationมักต้อง stackแยกต่อแท็บ StatefulShellRouteสร้าง branch Navigatorsและรักษา stateเมื่อสลับแท็บ

7. Lab trace

incoming URI → GoRouter redirect/match
→ StatefulShellRoute branch → Navigator pages
→ RoutingTaskDetailPage

8. Checkpoint

จำแนกทุกหน้าของโปรเจกต์ว่าเป็น shareable pageหรือ transient modal ถ้าตอบไม่ได้ route treeจะสะท้อน widget treeแบบไร้ product contract
