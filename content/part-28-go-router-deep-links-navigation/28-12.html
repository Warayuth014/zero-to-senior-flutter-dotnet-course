Auth redirect: route guardต้อง reactiveต่อ session, เก็บ intended internal URLอย่างปลอดภัยและไม่แทน authorizationฝั่ง API

1. refreshListenable

GoRouterฟัง RoutingSession เมื่อ signIn/signOut notify routerประเมิน redirectใหม่โดยไม่สร้าง router instance

2. Unauthenticated

ถ้า locationไม่ใช่ loginให้สร้าง /login?from=encoded-current-uri เพื่อรักษา path/queryของ deep link

3. After login

เมื่อ authenticatedและอยู่ login routerคืน intended locationหรือ /home Testเปิด email linkก่อน loginแล้วได้ Task detail/sourceเดิมหลัง signIn

4. Open redirect

safeLocalLocation ปฏิเสธ scheme, authority, //host และ login loop ห้าม redirectไป URLจาก queryโดยไม่ validateเพราะเป็น phishing/open redirect

5. Redirect loop

loginต้อง return nullเมื่อยังไม่ authและ from=/loginต้องถูกตัดออก กำหนด redirectLimit/diagnosticsและ testsกรณี loop

6. Startup unknown

production session bootstrapมี unknown/loading state อย่า redirect loginก่อนอ่าน secure tokenเสร็จเพราะหน้ากระพริบหรือ intended URLหาย ใช้ splash/bootstrap route

7. Permission

route guardแสดง access deniedตาม roleได้แต่ APIยัง enforceทุก endpointและ deep linkที่ไม่มีสิทธิ์ต้องไม่รั่ว resource detail

8. Exercise

เพิ่ม session state unknown/anonymous/authenticatedและ test cold-start protected deep linkโดย secure sessionตอบช้า ต้องไม่แสดง protected contentหรือทิ้ง intended URI
