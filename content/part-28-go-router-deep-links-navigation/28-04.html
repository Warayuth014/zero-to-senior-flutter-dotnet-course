Navigation operations: go เปลี่ยน matched location/stackตาม route tree, push ซ้อน page, replace แทน entry และ pop คืน result ต้องเลือกตาม historyที่ผู้ใช้คาดหวัง

1. go

ใช้สลับ destinationหลัก/filterที่ URLเป็น state เช่น Home→Tasks GoRouterสร้าง stackที่ตรง locationใหม่ ไม่รับประกันเก็บหน้าก่อนเป็น back entryแบบ push

2. push

ใช้ scannerชั่วคราวบน detailเพราะผู้ใช้ต้อง popกลับ detailและคืนผล บน webเข้าใจว่า imperative push/history behaviorขึ้นกับ package version

3. replace

เหมาะแก้ URL stateโดยไม่เพิ่ม history entry เช่น normalize queryหรือ wizard stepที่ย้อนกลับหน้าเดิมไม่ควรเห็น

4. pop result

final result = await context.pushNamed<String>('taskScan', ...);
context.pop('PALLET-DEMO-001');

5. Browser history

Router syncกับ History API ผู้ใช้คาดหวัง back/forwardย้อน locationsตามลำดับ ทดสอบบน browserจริงไม่ใช่เฉพาะ Android back

6. Duplicate navigation

disable actionหรือ guardก่อน pushหน้าซ้ำจาก double scan Route packageไม่ป้องกัน user intentซ้ำทั้งหมด

7. Logout

session changeทำ redirectไป loginและไม่ควรให้ backเปิด protected pageโดยไม่ recheck guard ทุก navigation

8. Rule

เขียน expected back stackของทุก operationก่อนเลือก go/push/replace ถ้าเลือกจากชื่อ methodอย่างเดียว browser/mobile behaviorมักผิด
