Path parameter: ใช้ระบุ resource identityที่จำเป็นต่อการสร้างหน้าและควร validate/authorizeก่อนใช้ ไม่ถือว่า stringใน URLเชื่อถือได้

1. Match

path: ':taskId' จับ segmentและอ่านจาก state.pathParameters['taskId'] ค่า decodeตาม URI rules

2. Required contract

builderใช้ ! ได้เพราะ route patternรับประกัน key แต่ valueยังอาจว่าง/formatผิดตาม domain จึง validate typed idก่อน query API

3. Encode

ให้ goNamed/pathParameters encode segmentแทนต่อ stringเอง IDที่มี slash/spaceต้องมี canonical representation หลีกเลี่ยง raw business textเป็น identity

4. Page loads own resource

deep linkอาจไม่มี list cache Detailต้องโหลดด้วย taskIdผ่าน repository ไม่พึ่ง objectจากหน้าก่อน Labแสดง identityชัดแต่ productionควร fetch/handle 404

5. Authorization

ผู้ใช้แก้ URLได้ APIต้องตรวจ warehouse/tenant/permissionทุกครั้ง Route guardเพียงลดหน้าที่เข้าถึงไม่ได้ใน UI

6. Composite identity

ถ้า task id uniqueเฉพาะ warehouse URLอาจเป็น /warehouses/:warehouseId/tasks/:taskId หรือ server resolveจาก session ต้องกำหนดไม่คลุมเครือ

7. Missing resource

แยก route-not-foundจาก resource-not-found URL matchได้แต่ APIคืน 404 ต้องแสดง page stateพร้อม recoveryคนละแบบ

8. Test

เปิดตรง /tasks/TASK-001 ใน widget testโดยไม่ผ่าน listและตรวจ taskIdบนหน้า นี่พิสูจน์ deep-link independenceขั้นแรก
